## Purpose

**Short**: Evaluation hub service providing REST APIs for managing LLM evaluation jobs, collections, and providers, with an MCP server interface, Kubernetes job orchestration, and S3-backed test data initialization.

**Detailed**: eval-hub is an Application Service composed of 4 architecture components. The EvalHub API Server exposes a REST API for creating and managing evaluation jobs, evaluation collections, and evaluation providers, using Go standard library `net/http.ServeMux` with optional OTel HTTP instrumentation and configurable TLS (TLS 1.2-1.3). The EvalHub MCP Server provides a Model Context Protocol interface (via stdio, Streamable HTTP, or deprecated HTTP+SSE transports) for tool, resource, and prompt access to eval-hub data. A standalone Metrics Server serves Prometheus metrics on a dedicated port. The Eval Runtime Init binary runs as an init container to download test data from S3-compatible storage. The service interacts with Kubernetes for job orchestration (batch/v1 Jobs, ConfigMaps, Secrets, HardwareProfile CRs), PostgreSQL and SQLite for data storage, MLflow for results export, and OpenTelemetry Collectors for observability. Identity enforcement uses X-User and X-Tenant headers, conditionally gated by runtime configuration; in cluster mode this is provided by kube-rbac-proxy.

## Architectural Analysis

- **Deployment shape:** The normalized deployment type is Application Service, represented by 4 architecture components (EvalHub API Server, EvalHub MCP Server, Metrics Server, Eval Runtime Init) and 3 listener surfaces.
- **Multi-transport MCP:** The MCP Server supports three transport modes (stdio, Streamable HTTP, deprecated HTTP+SSE) and advertises tool, resource, prompt, and completion capabilities. It runs behind kube-rbac-proxy in cluster mode and disables localhost DNS-rebinding protection to accept the proxy's forwarded Host header.
- **TLS and FIPS:** The API Server enforces TLS 1.2-1.3 when TLS is enabled and validates that InsecureSkipVerify is false in FIPS mode. HTTP timeouts (read, write, idle, header) and max header/body sizes are configurable. The MCP Server has similar TLS support via its own config.
- **Observability pipeline:** Full OpenTelemetry SDK setup for traces, metrics, and logs with dual exporter support (OTLP/gRPC, OTLP/HTTP, stdout). Prometheus metrics are dual-sinked when both OTel metrics and Prometheus are enabled. HTTP request metrics are recorded by HTTPMetricsMiddleware. Per-route OTel spans are added when OTEL is enabled.
