## Data Flows

- **Entry and service surface:** External requests enter via the `llm-d-inference-gateway` Gateway on port 80/HTTP. HTTPRoute resources match requests by model name header (`X-Gateway-Base-Model-Name`) and route them to InferencePool backends. The router EPP with Envoy sidecar selects model server endpoints based on configured plugins.
- **Prefill-decode disaggregation:** The prefill Deployment processes the prefill phase and exposes a NIXL port (TCP/5600) for KV-cache transfer to decode instances. The decode Deployment handles the decode phase and serves final responses on port 8000.
- **Runtime inventory:** The extracted deployment and source facts identify 4 architecture components: decode, prefill, llm-d-inference-gateway, and router EPP. The router connects to model servers via configurable HTTP or gRPC protocol on port 8000.
- **Observability:** The router EPP exports OpenTelemetry traces to localhost:4317 with configurable sampling (default: parentbased_traceidratio at 10%). PodMonitor resources from monitoring.coreos.com enable Prometheus metrics scraping.
