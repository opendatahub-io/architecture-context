## Purpose

**Short**: Kueue is a Kubernetes-native job queueing system that manages quota and fair sharing for batch workloads across multiple AI/ML frameworks.

**Detailed**: Kueue implements cluster-level resource quota management and workload scheduling for Kubernetes batch jobs. It defines ClusterQueue and LocalQueue abstractions that enforce resource quotas, priority-based preemption, and fair sharing across cohorts of queues. The controller manager reconciles Workload objects representing batch jobs from multiple framework integrations (batch/Job, Kubeflow training jobs, Ray jobs, JobSets, AppWrappers, LeaderWorkerSets, Pods, Deployments, StatefulSets) and admits them based on available quota. It supports MultiKueue for cross-cluster workload distribution, Topology-Aware Scheduling (TAS) for GPU/accelerator placement, and ProvisioningRequests for node auto-provisioning. The controller exposes 17 mutating and 18 validating admission webhooks to enforce quota semantics at admission time. An experimental kueue-viz backend provides WebSocket-based real-time visualization of workloads, queues, cohorts, and resource flavors via the Gin HTTP framework. A standalone importer CLI enables migration of existing running pods into Kueue management by creating Workload objects and assigning them to ClusterQueues. In RHOAI, the deployment runs with feature gates `VisibilityOnDemand=false`, `LocalQueueMetrics=true`, and `MultiKueue=false`. (Sources: Analyzer baseline, `apis/config/v1beta1/configuration_types.go:31-106`, `cmd/importer/main.go:56-69`, `cmd/experimental/kueue-viz/backend/handlers/handlers.go:25-50`)

## Data Flows

- **Entry and service surface:** The controller manager exposes 2 internal ClusterIP services: `kueue-webhook-service` (443/TCP -> 9443) for admission webhooks and CRD conversion, and `kueue-metrics-service` (8443/TCP) for Prometheus metrics scraping with RBAC-gated authentication.
- **Admission flow:** When a workload resource (Job, Pod, JobSet, etc.) is created or updated, the Kubernetes API server routes the request to the appropriate mutating webhook, which injects queue labels and suspends the workload. The validating webhook then enforces queue constraints and spec immutability. All webhook traffic is TLS-encrypted via the `kueue-webhook-server-cert` Secret.
- **Reconciliation loop:** Controllers watch their respective resources and create Workload objects representing resource requirements. The scheduler evaluates Workloads against ClusterQueue quotas, ResourceFlavor constraints, and admission checks (MultiKueue, ProvisioningRequest). Admitted workloads have their parent jobs unsuspended.
- **Runtime inventory:** 9 runtime components identified: 6 controllers (AdmissionCheck, LeaderWorkerSet, MultiKueueCluster, Pod, StatefulSet, Workload), 1 CLI tool (importer), 1 experimental service (kueue-viz backend), and 1 Deployment (kueue-controller-manager).
- **Downstream interactions:** 51 integration points cover watches and CRUD operations on Kubernetes core resources (Pods, Secrets, Namespaces, Nodes, PodTemplates), kueue CRDs, and third-party CRDs (Jobs, JobSets, training jobs, Ray resources, AppWrappers). The importer CLI additionally lists ClusterQueues, LocalQueues, ResourceFlavors, and PriorityClasses for pod migration (`cmd/importer/util/util.go:143-168`).
- **Experimental visualization:** The kueue-viz backend provides 13 WebSocket endpoints for real-time streaming of workload, queue, cohort, and resource flavor state via Gin + gorilla/websocket. It connects to the Kubernetes API using dynamic client with either in-cluster or KUBECONFIG-based auth (`cmd/experimental/kueue-viz/backend/kubernetes_client.go:31-69`).
- **Security context:** 7 authentication rules and 3 secret references describe the enforcement and credential inputs. The metrics endpoint uses TokenReview + SubjectAccessReview for RBAC-gated access. Webhook endpoints use TLS mutual auth with the API server. The kueue-viz WebSocket endpoints have no observed authentication middleware.

## Architectural Analysis

- **Deployment shape:** The normalized deployment type is Kubernetes Operator / Controller, represented by 9 architecture components (6 controllers, 1 CLI tool, 1 experimental service, 1 Deployment) and 2 internal ClusterIP services.
- **Control-plane surface:** The document contains 16 CRD identities across 3 API groups (kueue.x-k8s.io, config.kueue.x-k8s.io, visibility.kueue.x-k8s.io), 99 RBAC rules across 38 ClusterRoles, and 4 role bindings. The RBAC footprint covers 15 API groups spanning core Kubernetes, batch, apps, and 7 third-party framework groups.
- **Integration breadth:** Kueue integrates with 10 workload frameworks (batch/Job, JobSet, 5 Kubeflow training operators, 2 Ray operators, AppWrapper) plus Pod, Deployment, StatefulSet, and LeaderWorkerSet as direct integrations. The `Integrations.Frameworks` configuration field in Configuration CRD controls which integrations are active (`apis/config/v1beta1/configuration_types.go:351-368`).
- **Security and network evidence:** 7 authentication rules, 3 secret references, 0 ingress identities, and 1 egress identity. Webhook TLS is managed internally via `open-policy-agent/cert-controller` when `InternalCertManagement` is enabled. The experimental kueue-viz WebSocket endpoints have no observed authentication middleware; they rely on Kubernetes API RBAC for data-plane access but expose unauthenticated WebSocket upgrade paths.
- **RHOAI-specific configuration:** Feature gates `VisibilityOnDemand=false`, `LocalQueueMetrics=true`, `MultiKueue=false` are set in the RHOAI manager deployment patch. The RHOAI distribution includes additional patches for mutating/validating webhook configurations, metrics service, and role bindings.
- **Evidence boundary:** Analyzer coverage is partial for kustomize, platform_semantics, source, and webhooks_source. Authentication coverage is partial: 55 inbound runtime surfaces are not fully accounted for by authentication facts (primarily the 13 kueue-viz WebSocket endpoints and webhook paths where auth is enforced at the API server level). Dynamic behavior outside extracted literal and manifest evidence is not asserted.
