## Purpose

**Short**: REST-to-gRPC reverse proxy that translates KServe Predict V2 HTTP/JSON inference requests into gRPC calls to a co-located ModelMesh inference service.

**Detailed**: rest-proxy is a lightweight sidecar container that implements the KServe Open Inference Protocol (V2) REST API. It accepts HTTP/JSON requests on port 8008 (configurable via `REST_PROXY_LISTEN_PORT`) and translates them into gRPC calls to a co-located inference service on localhost port 8033 (configurable via `REST_PROXY_GRPC_PORT`). The proxy uses grpc-gateway to auto-generate REST-to-gRPC mappings from the `grpc_predict_v2.proto` definition, with custom JSON marshaling/unmarshaling to handle tensor data types including multi-dimensional arrays, base64-encoded bytes, and raw binary tensor contents. It supports optional TLS on both the inbound HTTP listener and the outbound gRPC connection to the inference backend.

## Data Flows

- REST clients send HTTP/JSON inference requests (KServe V2 protocol) to rest-proxy on port 8008.
- The CustomJSONPb decoder transforms JSON tensor data (including multi-dimensional arrays and base64-encoded bytes) into protobuf `ModelInferRequest` messages.
- The grpc-gateway runtime forwards the translated request as a gRPC call to the co-located `inference.GRPCInferenceService` on localhost port 8033.
- gRPC responses are received and the CustomJSONPb encoder transforms protobuf `ModelInferResponse` messages back to JSON, handling raw output contents (little-endian binary), typed tensor arrays, and base64 byte encoding.
- The JSON response is returned to the REST client.

## Architectural Analysis

- **Deployment shape:** rest-proxy is a sidecar container designed to run alongside a gRPC-based ModelMesh inference service pod. It provides a REST/JSON facade for the KServe Predict V2 gRPC protocol. The container image is built on `ubi9/ubi-micro:9.5` and runs as non-root user (UID 2000). The binary is statically compiled (`CGO_ENABLED=0`) and placed at `/go/bin/server`. A version file is copied to `/etc/modelmesh-version`.
- **Protocol translation:** The proxy implements bidirectional translation between REST/JSON and gRPC protobuf. Custom marshaling handles complex tensor data types (BOOL, UINT8-64, INT8-64, FP32, FP64, BYTES) with support for multi-dimensional nested arrays, base64-encoded byte tensors, and raw binary output contents in little-endian format. FP16 tensors are explicitly unsupported.
- **Configuration:** All runtime behavior is controlled via environment variables: `REST_PROXY_LISTEN_PORT` (default 8008), `REST_PROXY_GRPC_PORT` (default 8033), `REST_PROXY_GRPC_MAX_MSG_SIZE_BYTES` (default 16 MiB), `REST_PROXY_USE_TLS`, `REST_PROXY_SKIP_VERIFY`, `MM_TLS_KEY_CERT_PATH`, and `MM_TLS_PRIVATE_KEY_PATH`.
- **Evidence boundary:** Analyzer coverage is partial for agent_baseline, platform_semantics, source, and webhooks_source. The proxy exposes no CRDs, RBAC, or Kubernetes API interactions. Authentication is transport-level only (TLS); no application-level auth middleware was found in source.
