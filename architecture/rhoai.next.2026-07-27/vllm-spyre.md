## Purpose

**Short**: IBM Spyre accelerated vLLM inference server providing OpenAI-compatible HTTP and TGIS gRPC endpoints for high-performance LLM serving on x86_64 RHEL 9.

**Detailed**: vllm-spyre packages upstream vLLM with the vllm-tgis-adapter on an IBM Spyre accelerator base image (`rhaiis/vllm-spyre-rhel9`). The container exposes two runtime API surfaces: an OpenAI-compatible HTTP API on port 8000 (via uvicorn) and a TGIS-compatible gRPC inference API on port 8033. It runs as non-root (UID 2000) and is built through the Konflux pipeline. The repository is a midstream fork that adds a Konflux Dockerfile and RHEL 9 labels on top of the upstream vLLM codebase synced from `nm/midstream-cuda-v0.9.1.0`.

## Data Flows

- Clients send inference requests to the vllm-spyre container on port 8000 (HTTP/OpenAI-compatible) or port 8033 (gRPC/TGIS-compatible).
- The `vllm_tgis_adapter` module routes requests to the vLLM inference engine, which executes model inference using IBM Spyre accelerator hardware.
- Model weights are loaded from Hugging Face Hub or a pre-mounted volume at container startup.
- Evidence for encryption, authentication, and detailed internal routing is not available from this repository's source files.

## Architectural Analysis

- **Deployment shape:** vllm-spyre is a container image (not a Kubernetes operator or controller). It contains no CRDs, no RBAC definitions, no Kubernetes manifests, and no controller watches. Deployment is managed externally, likely through KServe or a similar model-serving controller within RHOAI.
- **Build pipeline:** Built via Konflux using `Dockerfile.konflux.spyre`. The base image is sourced from `registry.redhat.io/rhaiis/vllm-spyre-rhel9:3.2.2` (RHAIIS).
- **Runtime identity:** Runs as non-root user UID 2000.
- **Speculative decoding:** `DISABLE_LOGPROBS_DURING_SPEC_DECODING=false` is set to ensure logprobs remain available even when speculative decoding is active, matching hosted-model user expectations (Source: Dockerfile.konflux.spyre, lines 9-13).
- **Evidence boundary:** This repository is a thin midstream fork. The bulk of vLLM source, TGIS adapter code, and Spyre integration is in the base image and upstream repositories. Authentication, encryption, service mesh integration, and detailed API surface semantics are not evidenced in this repository and are marked `not-extracted`.
