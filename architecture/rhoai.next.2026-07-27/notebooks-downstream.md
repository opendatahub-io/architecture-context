## Purpose

**Short**: Downstream fork that builds and tests RHOAI Notebook/Workbench container images across multiple IDE types (Jupyter, code-server, RStudio) and ML runtime variants (datascience, PyTorch, TensorFlow, ROCm).

**Detailed**: notebooks-downstream is the Red Hat downstream fork of the Open Data Hub notebooks repository. It produces container images for interactive data science workbench environments deployed as part of Red Hat OpenShift AI. The repository contains Dockerfile definitions, dependency manifests (Python requirements.txt, Go modules), kustomize overlays for test deployments, and CI tooling. Image families include Jupyter notebooks (minimal, datascience, PyTorch, TensorFlow), code-server IDE, RStudio IDE (including CUDA-accelerated variants), and lightweight ML runtime images. GPU acceleration is supported through NVIDIA CUDA 12.6 and AMD ROCm variants. The Go module under `scripts/buildinputs/` provides Dockerfile analysis tooling using BuildKit and OCI image-spec libraries. The repository does not deploy long-running services itself; the built images are consumed by the RHOAI Notebook Controller which manages their lifecycle as StatefulSet-backed workbench pods.

## Data Flows

- **Entry and service surface:** This repository builds container images; it does not define its own ingress or service resources. The built images contain HTTP servers (Jupyter Notebook server, code-server, RStudio Server) whose network exposure is configured at deployment time by the RHOAI Notebook Controller via StatefulSets, Services, and Routes with OAuth proxy sidecars.
- **Runtime inventory:** The repository produces multiple container image families: Jupyter notebook images (minimal, datascience, PyTorch, TensorFlow, ROCm variants), code-server IDE images, RStudio IDE images (including CUDA variants), and lightweight ML runtime images. Each image family is built from Dockerfiles with pinned Python and Go dependencies.
- **Security context:** Authentication is not embedded in the images. The RHOAI platform enforces authentication through an OAuth proxy sidecar injected at deployment. The images include cryptographic libraries (cryptography==43.0.3, bcrypt==4.3.0, pynacl==1.5.0, pycryptodome==3.23.0) for user-space data science operations.
- **Data connectivity:** The datascience and ML runtime images bundle client libraries for external data sources: S3-compatible storage (boto3, minio), PostgreSQL (psycopg), MongoDB (pymongo), MySQL (mysql-connector-python), ODBC databases (pyodbc), and Apache Kafka (kafka-python-ng). These connections are user-configured at runtime within the workbench environment.

## Architectural Analysis

- **Deployment shape:** This repository is a container image build project, not a deployed service. It produces multiple image families consumed by the RHOAI Notebook Controller. The analyzer classified it as "Application Service" based on source structure, but the actual deployment type is Container Image Build. Images are built via Dockerfiles and tested via kustomize-based ephemeral deployments in CI (ci/cached-builds/make_test.py).
- **Image variants:** The repository supports multiple OS/Python/GPU combinations: UBI9 with Python 3.11 and 3.12, NVIDIA CUDA 12.6 (torch==2.6.0+cu126), and AMD ROCm (tensorflow-rocm==2.14.0.600, pytorch-triton-rocm==3.2.0). IDE frontends include Jupyter, code-server (with nginx proxy), and RStudio.
- **Security and network evidence:** The images do not embed authentication or authorization middleware. Authentication is delegated to the RHOAI platform's OAuth proxy sidecar. The analyzer's detection of "no auth middleware" from the test harness was a false positive. Cryptographic libraries are included for user-space data science operations, not for transport security enforcement.
- **Build tooling:** The Go module at `scripts/buildinputs/` (go 1.24) uses BuildKit (v0.23.2) and OCI image-spec (v1.1.1) for Dockerfile analysis. The `scripts/check-payload/` module uses openshift/check-payload for payload verification.
- **Evidence boundary:** Analyzer coverage is partial for kustomize, platform_semantics, python, and source surfaces. Shell scripts in codeserver/ and jupyter/ directories are in unsupported runtime languages. The analyzer's HTTP endpoint and authentication detections from the CI test file were false positives corrected in this report.
