## Purpose

**Short**: Latency prediction and training service for llm-d, providing TTFT and TPOT estimates via ML models served over HTTP.

**Detailed**: llm-d-latency-predictor provides latency prediction for the llm-d inference gateway. It consists of two cooperating servers: a **training server** (port 8000) that ingests request telemetry, trains XGBoost and LightGBM models for time-to-first-token (TTFT) and time-per-output-token (TPOT) prediction, and serves trained model artifacts; and a **prediction server** (port 8001) that periodically syncs trained models from the training server via HTTP and exposes single and bulk prediction endpoints. The prediction server supports ensemble mode with queue-gated sub-models, Bayesian Ridge regression with scalers, and configurable quantile objectives. Both servers are deployed as separate Kubernetes Deployments with independent scaling (training: 1 replica, prediction: 10 replicas) and health/readiness probes. `[prediction/prediction_server.py:63-95,125-249; deploy/base/prediction/deployment.yaml:10; deploy/base/training/deployment.yaml:10 — source-confirmed]`

## Data Flows

- **Prediction request flow:** External clients send HTTP POST requests to the prediction-service LoadBalancer (port 80) which routes to prediction-server pods on port 8001. The prediction server loads pre-trained ML models (XGBoost, LightGBM, or Bayesian Ridge) from local ephemeral storage and returns TTFT/TPOT latency estimates. `[deploy/base/prediction/service.yaml:9-17; prediction/prediction_server.py:968-985 — source-confirmed]`
- **Model sync flow:** A background ModelSyncer thread in each prediction-server pod periodically (default every 10 seconds, configurable via `MODEL_SYNC_INTERVAL_SEC`) polls the training-service on port 8000 via HTTP GET `/model/{name}/info` to check for newer models, then downloads updated models via HTTP GET `/model/{name}/download`. Models are validated (joblib.load) and atomically replaced on the local filesystem. `[prediction/prediction_server.py:125-249 — source-confirmed]`
- **Training data flow:** External telemetry sources send training data to the training-server via HTTP POST `/add_training_data_bulk` on port 8000. The training server trains XGBoost and LightGBM models and persists them to a PVC (training-models-pvc). `[deploy/base/training/deployment.yaml:60-65; training/training_server.py:1796 — Analyzer-seeded, source-confirmed]`
- **Health monitoring:** Kubernetes probes hit `/healthz` and `/readyz` on respective ports (8001 for prediction, 8000 for training). The prediction server readiness probe returns 503 until ML models are loaded and validated. `[prediction/prediction_server.py:1130-1144; deploy/base/prediction/deployment.yaml:30-42 — source-confirmed]`
