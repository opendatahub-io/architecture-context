## Purpose

**Short**: Kubernetes controller and Envoy ext_proc payload processor that manages external LLM provider routing via ExternalModel and ExternalProvider CRDs, with weighted multi-provider traffic splitting and per-provider authentication.

**Detailed**: ai-gateway-payload-processing is a Go-based Kubernetes controller built on the llm-d-inference-payload-processor (BBR — Body-Based Router) framework, adapted from the Gateway API Inference Extension. It defines two primary CRDs — ExternalModel and ExternalProvider — in the `inference.opendatahub.io/v1alpha1` API group. The ExternalProvider controller reconciles provider connections (endpoint + credentials) and creates Service, ServiceEntry, and DestinationRule resources. The ExternalModel controller reconciles client-facing model definitions that map to one or more external providers with weighted traffic splitting, creating HTTPRoute resources against a configured Gateway. A legacy migration controller watches `maas.opendatahub.io` ExternalModel CRs and creates corresponding `inference.opendatahub.io` resources. The component registers custom plugins with the llm-d runner framework and runs as an Envoy ext_proc gRPC service for request/response payload processing, API format translation, and credential injection.

## Data Flows

- **Runtime architecture:** The component runs as an Envoy ext_proc (external processing) gRPC service via the llm-d-inference-payload-processor BBR runner framework. Custom plugins registered via `plugins.RegisterPlugins()` handle payload processing, API format translation (openai-chat, messages), and credential injection for external LLM providers. - **Controller reconciliation:** Three controllers run within the process: (1) ExternalProvider controller reconciles provider connections and creates Service, ServiceEntry, and DestinationRule networking resources; (2) ExternalModel controller reconciles model definitions and creates HTTPRoute resources against a Gateway identified by GATEWAY_NAME/GATEWAY_NAMESPACE environment variables, with weighted traffic splitting across providers; (3) Legacy migration controller conditionally watches maas.opendatahub.io ExternalModel CRs and creates corresponding inference.opendatahub.io resources.
