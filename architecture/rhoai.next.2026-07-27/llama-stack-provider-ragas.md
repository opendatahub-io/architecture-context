## Purpose

**Short**: Ragas evaluation framework as an out-of-tree Llama Stack provider, offering inline and remote (Kubeflow Pipelines) execution modes for LLM evaluation benchmarks.

**Detailed**: llama-stack-provider-ragas implements the Llama Stack `Eval` and `BenchmarksProtocolPrivate` APIs as a pluggable provider for the Ragas evaluation framework. It supports two execution modes: inline evaluation (running Ragas directly within the Llama Stack process using Llama Stack's own inference and datasetio APIs) and remote evaluation (submitting evaluation pipelines to Kubeflow Pipelines with S3-backed result storage). The provider type is `trustyai_ragas` and is part of the TrustyAI ecosystem. The component registers as both `inline::trustyai_ragas` and `remote::trustyai_ragas` provider specs, each declaring API dependencies on Llama Stack inference, files, benchmarks, and datasetio services.

## Data Flows

- **Inline evaluation flow:** The `RagasEvaluatorInline` component receives evaluation requests through the Llama Stack `Eval` protocol. It retrieves datasets via the `DatasetIO` API (`iterrows`), wraps Llama Stack's `Inference` API as Ragas-compatible LLM and embedding interfaces (`LlamaStackInlineLLM`, `LlamaStackInlineEmbeddings`), and executes Ragas evaluation synchronously in a thread pool (`asyncio.to_thread`) with `max_workers=1`. Results are returned directly as `EvaluateResponse` with per-metric `ScoringResult` aggregations.
- **Remote evaluation flow:** The `RagasEvaluatorRemote` component submits evaluation jobs to Kubeflow Pipelines. A pre-flight healthz check validates connectivity to the KFP API using Bearer token auth. The pipeline DAG has two steps: (1) `retrieve_data_from_llama_stack` fetches the dataset from the Llama Stack API at `llama_stack_url`, and (2) `run_ragas_evaluation` runs the evaluation with results written to S3 at `{results_s3_prefix}/{job_id}/results.jsonl`. AWS credentials are mounted from a Kubernetes Secret via `kfp.kubernetes.use_secret_as_env`. The provider polls KFP for run status (`get_run`) and fetches results from S3 using `pandas.read_json` with the S3 URI.
- **Downstream interactions:** The structured facts record 7 integration points, 7 internal dependencies, and 3 egress destinations. Named destinations include Kubeflow Pipelines API, Llama Stack API, S3 storage, and the Llama Stack platform APIs (inference, datasetio, files, benchmarks).
