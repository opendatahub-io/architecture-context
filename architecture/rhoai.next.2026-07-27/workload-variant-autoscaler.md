## Purpose

**Short**: GPU-aware autoscaler for LLM inference workloads, operating as a Kubernetes controller that uses Prometheus metrics, InferencePool state, and optional KEDA ScaledObjects to drive saturation-based and scale-from-zero scaling decisions.

**Detailed**: workload-variant-autoscaler (WVA) is a controller-runtime-based operator that provides GPU-aware autoscaling for LLM inference workloads in RHOAI. It runs two core engine loops — a saturation engine that queries Prometheus for real-time utilization metrics and computes optimal replica counts, and a scale-from-zero engine that handles cold-start scaling via dynamic client operations. Four controllers watch ConfigMaps (for runtime configuration), HPAs, InferencePools (GA v1 and v1alpha2), and optionally KEDA ScaledObjects for annotation-based workload discovery. An experimental Coordinator component dispatches cluster-wide GPU rebalancing via a plugin architecture. The manager is deployed as a single-replica Deployment with leader election, exposes health probes on :8081 (HTTP, unauthenticated) and secure metrics on :8443 (HTTPS, TokenReview+SubjectAccessReview authn/authz). It requires a Prometheus API endpoint for metrics queries and mounts an EPP metrics token for outbound authentication to Endpoint Picking Policy metrics endpoints. LeaderWorkerSet support is conditionally enabled based on CRD presence at startup. The extracted dependency view records 7 internal platform dependencies and 23 integration points.
