## Purpose

**Short**: Rust/Axum HTTP gateway that proxies OpenAI-compatible chat completion requests through configurable content-safety detectors (guardrails orchestrator) with mTLS support.

**Detailed**: vllm-orchestrator-gateway is a Rust HTTP service built on Axum and Tokio that acts as a guardrails gateway for vLLM inference endpoints. It accepts OpenAI-compatible `POST /{route}/v1/chat/completions` requests, injects configured input/output detector parameters, and forwards them to a downstream TrustAI guardrails orchestrator at `/api/v2/chat/completions-detection`. Routes and detectors are defined in a YAML configuration file (`GATEWAY_CONFIG` env var, default `config/config.yaml`). The gateway supports both streaming (SSE) and non-streaming JSON responses, forwards `Authorization` and `x-forwarded-*` headers for passthrough authentication, and optionally establishes mTLS connections to the orchestrator using OpenSSL when TLS certificates are mounted. When a detector produces a detection result, the gateway substitutes a configurable fallback message in the response.

## Data Flows

- **Inbound request**: Client sends `POST /{route_name}/v1/chat/completions` with an OpenAI-compatible JSON payload to the gateway on port 8090 (`src/main.rs:84-109`).
- **Detector injection**: The gateway looks up the route's configured detectors, resolves their `detector_params` from the `GatewayConfig`, and injects `input` and `output` detector maps into the payload (`src/main.rs:32-56`).
- **Orchestrator proxy**: The augmented payload is forwarded via HTTP(S) POST to the guardrails orchestrator at `/api/v2/chat/completions-detection`. `Authorization` and `x-forwarded-*` headers are passed through (`src/main.rs:408-476`).
- **Detection check**: If the orchestrator response contains `detections` and the route has a `fallback_message` configured, the gateway replaces the response content with the fallback message (`src/main.rs:138-152`).
- **Response**: The (potentially modified) response is returned to the client. Streaming responses use SSE with `KeepAlive` (`src/main.rs:259-349`).
