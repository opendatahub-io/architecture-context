## Purpose

**Short**: Source-backed analysis represents odh-model-controller as Kubernetes Operator / Controller with 13 runtime components, 16 API identities, and 75 integration points.

**Detailed**: odh-model-controller is a Kubernetes controller-manager that reconciles model serving resources for Red Hat OpenShift AI. It manages the lifecycle of InferenceService, InferenceGraph, LLMInferenceService, ServingRuntime, and NVIDIA NIM Account custom resources through 9 dedicated reconciliation controllers, 2 deployments, and 2 background cleanup runners. The controller provides admission webhooks for validation and mutation of serving resources, manages Gateway API routing for LLM inference, handles Kuadrant AuthPolicy configuration for access control, and integrates with Prometheus for monitoring and OpenTelemetry for distributed tracing. Its documented interface surface contains 16 API identities, including 15 HTTP endpoints and 1 custom resource definition (nim.opendatahub.io/v1 Account). ## Data Flows

- **Entry and service surface:** The controller exposes 4 Kubernetes Service identities routing to 15 HTTP endpoints across two deployments. The `odh-model-controller` deployment handles webhook admission (port 9443/TLS) and metrics (port 8080), while `model-serving-api` serves the Gateway discovery and LLM-D API (port 8443/TLS) with separate metrics (port 8080). No ingress routes are defined; all services are ClusterIP (internal).
- **Runtime inventory:** The controller manager runs 9 reconciliation controllers, 2 background cleanup runners (MaaSRBACCleanupRunner, NIMCleanupRunner), and 8 admission webhooks (5 mutating, 3 validating). Controller startup is sequenced in `setupReconcilers()` and `setupWebhooks()`. The NIM Account controller is conditionally registered based on the `NIM_STATE` environment variable.
- **Downstream interactions:** The controller communicates with the Kubernetes API server via 3 client-go clientsets: a general Kubernetes clientset, an OpenShift template clientset, and a gateway discovery clientset. It manages 75 integration points across KServe, Gateway API, Kuadrant, Istio, Prometheus, KEDA, and OpenShift resource types. Outbound gRPC connections to OpenTelemetry Collector export distributed traces.
- **Security context:** Webhook endpoints are TLS-encrypted using certificates provisioned by the OpenShift service-ca operator. The metrics endpoint supports optional Kubernetes authn/authz via TokenReview and SubjectAccessReview. HTTP/2 is disabled by default for CVE mitigation. The proxy-role ClusterRole grants tokenreviews/subjectaccessreviews permissions for the auth proxy pattern.
- **Cache filtering:** The controller-runtime cache is configured with label selectors: Secrets are filtered to `opendatahub.io/managed=true` and Pods to `component=predictor`, reducing the API server watch load. (Source: `cmd/main.go:261-273`)
