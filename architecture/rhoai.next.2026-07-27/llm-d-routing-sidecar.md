## Purpose

**Short**: Reverse proxy sidecar for LLM inference routing, supporting Prefiller/Decoder disaggregated serving with SSRF protection via InferencePool-backed allowlisting.

**Detailed**: llm-d-routing-sidecar is a reverse proxy sidecar deployed as a StatefulSet alongside vLLM decoder instances. It intercepts OpenAI-compatible inference requests (`/v1/chat/completions`, `/v1/completions`) and orchestrates Prefiller/Decoder (P/D) disaggregated serving using pluggable connector protocols (NIXL v2 default, NIXL v1 deprecated, LMCache deprecated). The proxy dynamically discovers prefiller targets by watching InferencePool resources (`inference.networking.x-k8s.io/v1alpha2`) and enforces SSRF protection by maintaining a pod-IP allowlist derived from InferencePool selectors. Unmatched requests are reverse-proxied to the co-located vLLM decoder. TLS 1.2+ with configurable cipher suites is supported for both proxy-to-client and proxy-to-prefiller connections.

## Data Flows

- **Entry and service surface:** The proxy exposes 4 HTTP routes on port 8080: `GET /health` (health check), `POST /v1/chat/completions` (OpenAI chat), `POST /v1/completions` (legacy), and `/` (catch-all reverse proxy to decoder). External access is via OpenShift Route with HTTPS. The proxy supports optional TLS 1.2+ with configurable cipher suites for ECDHE-based key exchange (`internal/proxy/proxy.go:188`).
- **P/D routing flow:** Chat/completions requests are intercepted by `chatCompletionsHandler`, which inspects request headers (`x-prefiller-url`, `x-prefiller-host-port`, `x-request-id`) and body fields (`kv_transfer_params`, `do_remote_prefill`, `do_remote_decode`) to determine P/D routing. When prefiller routing is required, the AllowlistValidator checks the target against allowed pod IPs before proxying (`internal/proxy/proxy.go:37`, `internal/proxy/allowlist.go:176`).
- **SSRF protection:** The AllowlistValidator watches InferencePool resources (`inference.networking.x-k8s.io/v1alpha2`) and corresponding Pods to maintain a dynamic allowlist of valid prefiller target IPs. Pod informers are created per InferencePool with label selectors derived from pool specs. The allowlist is rebuilt on every pod add/update/delete event (`internal/proxy/allowlist.go:240`, `internal/proxy/allowlist.go:344`).
- **Downstream interactions:** The proxy forwards requests to the co-located vLLM decoder (reverse proxy with LRU-cached handlers) and to dynamically discovered prefiller instances (also via LRU-cached reverse proxy handlers, `internal/proxy/proxy.go:113`). It connects to the Kubernetes API via dynamic client for InferencePool and Pod resource watches.
- **Security context:** 1 RBAC Role permits `pods/exec create` on the StatefulSet pod (`${PROJECT_NAME}-0-0`) for the `system:authenticated` group (`deploy/rbac/patch-rbac-role.yaml`). The proxy does not enforce inbound authentication itself; this is delegated to upstream infrastructure (OpenShift Route, Gateway). TLS cipher suites are explicitly restricted to ECDHE-based algorithms with AES-GCM or ChaCha20 (`internal/proxy/proxy.go:192`).

## Architectural Analysis

- **Deployment shape:** Deployed as a StatefulSet sidecar alongside vLLM decoder instances, with 1 replica. The proxy intercepts and routes inference requests using the P/D disaggregated serving pattern with pluggable connector protocols.
- **Control-plane surface:** No CRDs are owned. 1 RBAC Role grants `pods/exec create` on the StatefulSet pod to the `system:authenticated` group (`deploy/rbac/patch-rbac-role.yaml`). The AllowlistValidator is a control-plane consumer of InferencePool (`inference.networking.x-k8s.io/v1alpha2`) and Pod (`v1`) resources via Kubernetes dynamic client informers with 30-second resync (`internal/proxy/allowlist.go:44`).
- **Connector protocols:** The proxy supports pluggable P/D connector protocols: NIXL v2 (default), NIXL v1 (deprecated), and LMCache (deprecated). Protocol selection is configured via `Config.Connector` (`internal/proxy/proxy.go:53`, `internal/proxy/proxy.go:129`).
- **Security and network evidence:** TLS 1.2+ is supported with explicit cipher suite restriction (6 ECDHE-based suites) for proxy server, decoder proxy, and prefiller proxy connections (`internal/proxy/proxy.go:192`, `internal/proxy/proxy.go:249`, `internal/proxy/proxy.go:298`). SSRF protection validates prefiller targets against InferencePool-derived pod IP allowlists. No inbound authentication is enforced by the proxy itself.
- **Evidence boundary:** Analyzer coverage is partial for kustomize, platform_semantics, source, and webhooks_source. The `chatCompletionsHandler` implementation and individual connector protocol handlers (NIXL v1, NIXL v2, LMCache) were not read due to file budget constraints.
