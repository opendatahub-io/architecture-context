## Purpose

**Short**: Intelligent model-serving mesh that manages model lifecycle, caching, and routing across a distributed cluster via gRPC, backed by etcd for model registry and leader election.

**Detailed**: ModelMesh is a distributed model-serving infrastructure component that acts as a sidecar to collocated model runtime containers. It provides intelligent model lifecycle management (registration, loading, unloading, caching), virtual model (vModel) aliasing for zero-downtime model updates, and transparent gRPC request routing to the appropriate model-mesh instance where a model is loaded. The system uses etcd (via the kvutils library) for distributed model registry, leader election, and dynamic configuration. Inter-instance communication uses litelinks (a Thrift-based service mesh). The external API is exposed as a gRPC service on port 8033, while internal communication with the collocated model runtime uses the ModelRuntime gRPC service over a Unix domain socket or local TCP port.

## Data Flows

- **Entry and service surface:** External gRPC clients connect to the model-mesh ClusterIP service on port 8033 (with optional TLS/mTLS). The ModelMeshApi server receives inference requests, extracts the model ID from gRPC metadata headers (`mm-model-id` or `mm-vmodel-id`), and routes the request to the correct model-mesh instance.
- **Model routing:** If the target model is loaded on the local instance, the request is forwarded to the collocated model runtime via the ModelRuntime gRPC sidecar interface (UDS or localhost port 8085). If the model is loaded on a remote instance, the request is forwarded via litelinks (Thrift) to that instance.
- **Model lifecycle:** Model registration, loading, and unloading are coordinated through etcd via KVTable. Each model's state (NOT_FOUND, NOT_LOADED, LOADING, LOADED, LOADING_FAILED) is tracked in the distributed registry. Leader election ensures coordinated cluster-wide operations.
- **Virtual models:** VModel aliasing provides zero-downtime model updates by maintaining active/target model mappings, transitioning traffic only after the new model is fully loaded.
- **Runtime inventory:** The extracted deployment identifies 1 runtime component: model-mesh (Deployment with container `mm` running `kserve/modelmesh:latest`).
