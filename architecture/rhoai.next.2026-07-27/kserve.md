## Purpose

**Short**: KServe is a Kubernetes-native model serving platform providing InferenceService, InferenceGraph, LLMInferenceService, and LocalModelCache lifecycle management with 12 runtime components, 46 API identities, and 126 integration points.

**Detailed**: KServe is represented by 12 architecture components spanning five independent controller-manager binaries, a sidecar agent, and an inference graph router. The **kserve controller manager** (`cmd/manager/main.go`) hosts InferenceService, TrainedModel, and InferenceGraph controllers along with pod-mutating and serving-runtime-validating webhooks. The **LLMInferenceService controller manager** (`cmd/llmisvc/main.go`) manages LLMInferenceService and LLMInferenceServiceConfig resources across v1alpha1 and v1alpha2 API versions with conversion webhooks and storage version migration. The **LocalModel controller manager** (`cmd/localmodel/main.go`) manages LocalModelCache and LocalModelNamespaceCache resources for pre-cached model distribution across nodes. The **kserve-module controller** operates as the ODH/RHOAI platform integration layer, reconciling the Kserve platform component CR and managing deployment of child resources. The **agent** (`cmd/agent/main.go`) acts as a sidecar with model pulling, request/response logging, and request batching capabilities, reverse-proxying to the user model container. The **InferenceGraph router** (`cmd/router/main.go`) implements splitter, switch, ensemble, and sequence routing patterns with optional Bearer-token authorization via Kubernetes TokenReview and SubjectAccessReview APIs. Its documented interface surface contains 46 API identities, including 32 HTTP endpoints and 14 custom resource identities. The extracted dependency view records 16 internal platform dependencies and 126 integration points.
