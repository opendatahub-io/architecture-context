## Purpose

**Short**: Source-backed analysis represents mlflow-operator as Kubernetes Operator / Controller with 5 runtime components, 6 API identities, and 39 integration points.

**Detailed**: mlflow-operator is a Kubernetes operator that manages MLflow tracking server deployments on OpenShift. It is represented by 5 architecture components in the extracted and source-confirmed evidence. The principal components are the MLflow controller (reconciles MLflow CR instances using Helm chart rendering from `charts/mlflow`), the MLflowOperator controller (reconciles MLflowOperator module CRs for coordinated ODH platform handoff), the Namespace RBAC controller (reconciles per-namespace RBAC bindings based on the platform Auth CR), the SecurityProfileWatcher (monitors OpenShift TLS profile changes and triggers operator restart), and the mlflow-operator-controller-manager Deployment. Its documented interface surface contains 6 API identities, including 3 HTTP endpoints and 3 custom resource identities. The extracted dependency view records 8 internal platform dependencies and 39 integration points. The operator conditionally enables Gateway API HTTPRoute, OpenShift ConsoleLink, and Prometheus ServiceMonitor management based on runtime CRD availability discovery. The MLflowConfig CRD allows namespace owners to override artifact storage configuration per namespace.
