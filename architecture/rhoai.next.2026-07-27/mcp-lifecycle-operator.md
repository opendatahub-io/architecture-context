## Purpose

**Short**: Kubernetes operator that manages Model Context Protocol (MCP) server lifecycle by reconciling MCPServer custom resources into Deployments, Services, and NetworkPolicies.

**Detailed**: mcp-lifecycle-operator is a Kubernetes operator built with controller-runtime (v0.24.1) that watches `MCPServer` custom resources (mcp.x-k8s.io/v1alpha1) and reconciles them into managed Deployments, Services, and NetworkPolicies. Each MCPServer CR specifies a container image source and runtime configuration (port, arguments, environment variables, storage mounts), and the operator creates corresponding Kubernetes resources with ownerReferences. The controller supports resource adoption for orphaned resources from deleted MCPServers with the same name, and rejects updates to resources owned by other controllers to prevent silent overwrites of manually-created resources. The operator uses leader election (lease ID `bed7462b.x-k8s.io`), exposes HTTPS metrics with TokenReview/SubjectAccessReview authentication, and optionally propagates TLS environment variables to managed MCP server containers via the `PROPAGATE_TLS_ENV_VARS` setting. HTTP/2 is disabled by default to mitigate HTTP/2 Stream Cancellation and Rapid Reset CVEs (GHSA-qppj-fm5r-hxr3, GHSA-4374-p667-p6c8).

## Data Flows

- **Entry and service surface:** The controller watches MCPServer CRs (mcp.x-k8s.io/v1alpha1) as its primary input. It exposes no user-facing ingress; its only inbound endpoints are health probes (:8081) and metrics (:8443). The metrics Service (ClusterIP, port 8443) provides internal-only Prometheus scraping.
- **Reconciliation flow:** On each MCPServer reconciliation, the controller creates or updates a Deployment (with the specified container image, port, arguments, env vars), a Service (exposing the MCP server port), and a NetworkPolicy. All managed resources use ownerReferences back to the MCPServer CR. ConfigMap and Secret watches trigger re-reconciliation when referenced configurations change, enabling config hash-based rolling updates.
- **Resource ownership:** The controller manages resources with strict ownership semantics — it rejects updates to resources owned by other controllers and to unowned resources (preventing silent overwrites), but adopts orphaned resources from a deleted MCPServer with the same name.
- **Downstream interactions:** 14 integration points: 6 controller watches, 7 resource operations (CRUD on Deployments, Services, NetworkPolicies; reads on ConfigMaps, Secrets, Pods, MCPServers), and 1 egress to the Kubernetes API server.
- **Security context:** 5 authentication rules covering health probes (unauthenticated), metrics (TokenReview + SubjectAccessReview with TLS), RBAC aggregation for CR access, and ServiceAccount-based API access. HTTP/2 is disabled by default.

## Architectural Analysis

- **Deployment shape:** Single-replica Deployment (with optional leader election for HA) running the MCPServerReconciler controller, a metrics server, and health probes. The controller follows the standard kubebuilder v4 operator pattern with controller-runtime v0.24.1.
- **CRD lifecycle management:** MCPServer CRs declare MCP servers; the controller creates Deployment + Service + NetworkPolicy triads with ownerReferences. The CRD includes printer columns for Ready, Accepted, Image, Port, Address, and Age. Orphaned resource adoption and foreign-owner rejection provide safe resource management semantics.
- **Control-plane surface:** 1 CRD identity (MCPServer), 42 RBAC rules across 14 ClusterRoles/Roles, and 6 role bindings. RBAC aggregation labels (`aggregate-to-admin`, `aggregate-to-edit`, `aggregate-to-view`) integrate MCPServer permissions into built-in Kubernetes admin/edit/view roles.
- **Security and network evidence:** Metrics endpoint secured with TLS (self-signed or external certificates) and controller-runtime authn/authz filter (TokenReview + SubjectAccessReview). HTTP/2 explicitly disabled to mitigate CVEs GHSA-qppj-fm5r-hxr3 and GHSA-4374-p667-p6c8. Health probes intentionally unauthenticated. No ingress routes; metrics service is ClusterIP-only.
- **TLS propagation:** When `PROPAGATE_TLS_ENV_VARS=true`, the operator propagates TLS environment variables from `parseTLSSettings()` to managed MCP server containers, enabling platform TLS profile inheritance.
- **Evidence boundary:** Analyzer coverage is partial for kustomize (image transforms not resolved), source (dynamic routes and watched expressions not resolved), and webhooks_source (literal kubebuilder markers only). The webhook server is scaffolded but no webhooks are registered (only the `+kubebuilder:scaffold:builder` marker is present). Internal platform dependencies are confirmed empty (77 files scanned against 25 platform aliases; cert-manager.io and monitoring.coreos.com appear only in commented/unselected configuration).
