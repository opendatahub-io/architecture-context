## Purpose

**Short**: Python client SDK that provides authentication, cluster management, and job submission interfaces for CodeFlare/Ray clusters on Kubernetes and OpenShift.

**Detailed**: codeflare-sdk is a Python client library that wraps the Ray Job Submission Client and Kubernetes Python client to provide a simplified interface for interacting with Ray clusters managed by the CodeFlare stack on RHOAI. The SDK handles Kubernetes/OpenShift authentication (Bearer token, kubeconfig file, or in-cluster auto-detection), TLS certificate management, and Ray job lifecycle operations (submit, stop, delete, status, logs). It does not expose any HTTP endpoints or gRPC services itself — it operates as an outbound client connecting to Kubernetes API servers and Ray cluster dashboard endpoints. The minio deployment manifest in the repository is test-only e2e infrastructure and is not part of the shipped SDK. Source: `pyproject.toml:1-20`, `auth.py:75-136`, `ray_jobs.py:25-56`. ## Data Flows

- **Client-side SDK:** codeflare-sdk is a pure client library with no server-side components. It makes outbound connections to Kubernetes API servers and Ray cluster dashboards but does not accept inbound requests. The 2 Kubernetes Service identities (minio-service) are test-only e2e infrastructure.
- **Authentication flow:** Users authenticate to Kubernetes clusters via one of three methods: (1) `TokenAuthentication` with an API Bearer token and server address (`auth.py:75-136`), (2) `KubeConfigFileAuthentication` with a kubeconfig file path (`auth.py:138-162`), or (3) automatic detection via `config_check()` which tries `~/.kube/config` then in-cluster configuration (`auth.py:166-191`). TLS certificate verification is enforced by default with CA cert resolution from explicit path, `CF_SDK_CA_CERT_PATH` environment variable, or the OpenShift workbench default path `/etc/pki/tls/custom-certs/ca-bundle.crt` (`auth.py:205-213`).
- **Job submission flow:** `RayJobClient` wraps Ray's `JobSubmissionClient` to connect to a Ray dashboard HTTP endpoint (default port 8265). It supports job submission, deletion, status queries, log retrieval, and log tailing (`ray_jobs.py:25-154`). Connection parameters include address, TLS verification, custom headers, and cookies.
- **Test infrastructure:** The minio deployment (test-only, not shipped) provides S3-compatible object storage for e2e tests. It runs as a ClusterIP service on ports 9000 (API) and 9090 (console UI), authenticated via `minio-secret` (`minio_deployment.yaml:24-129`).
