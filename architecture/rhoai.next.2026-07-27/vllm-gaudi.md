## Purpose

**Short**: Intel Gaudi (HPU) acceleration plugin for vLLM, providing hardware-specific platform integration, attention backends, custom ops, model support, and distributed inference for RHOAI model serving.

**Detailed**: vllm-gaudi is an out-of-tree (OOT) platform plugin for the vLLM inference engine that enables execution on Intel Gaudi accelerators (HPUs). It registers via vLLM's plugin entry points to provide the HpuPlatform backend, HPU-optimized attention implementations, custom operator kernels (FP8, fused MoE, rotary embedding, etc.), model adaptations, and distributed communication via HCCL and NIXL. When containerized for RHOAI, the image serves the vLLM OpenAI-compatible API server on Gaudi hardware, running as a non-root user (UID 2000) for OpenShift compatibility. The plugin itself does not expose its own HTTP or gRPC endpoints; it provides the HPU execution backend while vLLM core handles the API surface.

## Data Flows

- **Runtime inventory:** The extracted deployment and source facts identify 8 architecture components: vllm_gaudi (package), HpuPlatform (platform backend), HPU Attention Backends, HPU Custom Ops, HPU Worker, HpuCommunicator, NIXL KV Connector, and HPU Model Registry.
- **Inference flow:** Client requests arrive at the vLLM OpenAI-compatible API server (provided by vLLM core). The HpuPlatform backend directs model execution to Gaudi HPU devices. The HPU Worker and Model Runner manage per-device inference. For multi-device configurations, HpuCommunicator handles collective operations via HCCL. For disaggregated prefill/serving, the NIXL KV Connector transfers KV cache between nodes.

## Architectural Analysis

- **Deployment shape:** The normalized deployment type is Application Service, built as a multi-stage container image on UBI 9.6 (RHEL 9) with Habana Synapse AI 1.23.0 and PyTorch 2.9.0. The final image runs the vLLM OpenAI API server as a non-root user (UID 2000). Source: `Dockerfile.hpu.ubi`.
- **Plugin architecture:** vllm-gaudi integrates with vLLM via four entry points: `vllm.platform_plugins` (HpuPlatform), and three `vllm.general_plugins` entries for utils, custom ops, and models. This allows the plugin to be installed alongside vLLM without modifying vLLM core. Source: `setup.py:65-72`.
- **Quantization support:** The HpuPlatform declares support for compressed-tensors, fp8, inc, awq_hpu, gptq_hpu, and modelopt quantization methods. INC quantization triggers CPU-first weight loading to prevent OOM. Source: `vllm_gaudi/platform.py:39,166-174`.
- **Attention backend selection:** Dynamic selection among four backends (HPUUnifiedAttention, HPUUnifiedMLA, HPUMLA, HPUAttentionV1) based on MLA mode and unified attention configuration. Source: `vllm_gaudi/platform.py:44-67`.

Dynamic behavior outside the extracted literal and manifest evidence is not asserted. HTTP endpoints are provided by vLLM core (not this plugin) and their exact port/encryption/auth configuration depends on the RHOAI deployment.
