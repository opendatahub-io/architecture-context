## Purpose

**Short**: TrustyAI explainability service providing AI model fairness monitoring and explainability, integrating with KServe inference payloads via a configurable payload processor endpoint.

**Detailed**: trustyai-explainability is a Quarkus-based AI/ML explainability and fairness service deployed as a Kubernetes Workload. It intercepts KServe inference payloads via a dynamically configured payload processor endpoint (`/consumer/kserve/v2`), stores inference data on a PersistentVolumeClaim, and exposes metrics to Prometheus. The deployment includes an init container that creates a `model-serving-config` ConfigMap to register TrustyAI as a KServe payload processor in the current namespace. The service is externally accessible via an OpenShift Route. Runtime configuration is provided by a `trustyai-config` ConfigMap with 6 keys controlling storage format, batch size, data format, and metrics scheduling.

## Data Flows

- **Entry and service surface:** The service is externally exposed via an OpenShift Route (`trustyai`) that forwards to the `trustyai-service` ClusterIP Service (port 80 -> 8080). The Route has no TLS termination in the base manifest (`tls: null`).
- **KServe payload ingestion:** The init container (`config-map-overrider`) creates a `model-serving-config` ConfigMap that registers `http://trustyai-service.$namespace/consumer/kserve/v2` as a KServe payload processor. This causes KServe/ModelMesh model serving infrastructure to send inference payloads to TrustyAI for monitoring and analysis.
- **Runtime inventory:** The deployment contains 1 main container (`trustyai-service`) and 1 init container (`config-map-overrider`). Configuration is sourced from the `trustyai-config` ConfigMap (6 keys controlling storage and metrics behavior).
- **Storage:** Inference data is persisted to a PersistentVolumeClaim (`trustyai-service-pvc`) mounted at `/inputs` (read-write).
- **Monitoring:** Prometheus scrapes metrics from `/q/metrics` on port 8080 via prometheus.io annotations on both the Service and Deployment.
- **Downstream interactions:** The init container makes an outbound call to the OpenShift API server (`oc apply`) to create the `model-serving-config` ConfigMap. The main container serves inference payloads inbound from KServe and metrics outbound to Prometheus.
