NAMESPACES:
- redhat-ods-operator:      Operator control plane (meta-operator, module operators)
- redhat-ods-applications:  Platform services and controllers
- openshift-ingress:        Gateway API infrastructure (data-science-gateway, HTTPRoutes)
- redhat-ods-monitoring:    Observability stack (Prometheus, Thanos, alerting)
- User project namespaces:  ML workloads (InferenceServices, Notebooks, training jobs, pipelines)

GATEWAY API CONFIGURATION:
- Model: Centralized data-science-gateway in openshift-ingress namespace
- Routing: HTTPRoute resources per component (16 components integrate)
- TLS: Terminated at gateway level
- Auth: Kuadrant AuthPolicy for MaaS API; per-component auth for other routes
- Migration: Transitioning from Istio VirtualServices + OpenShift Routes to Gateway API

ADMISSION WEBHOOK ARCHITECTURE:
- Total registrations: 218 across 24 components
- Failure policy: Fail (ALL components — strict admission control)
- Transport: HTTPS on port 9443 (API server mTLS)
- Certificate management: cert-manager CA injection (6 operators), OPA cert-controller (2 operators)
- Critical coordination: Kueue (31 webhooks spanning 10 workload frameworks),
  KServe + odh-model-controller + Kueue (3-way pod mutation),
  CodeFlare + KubeRay + Kueue (3-way RayCluster admission)

RBAC SUMMARY (1903 total entries across 39 components):
- rhods-operator:          27 CRD kinds across 7 API groups, full platform orchestration
- kserve-controller:       serving.kserve.io/*, InferenceService lifecycle
- kueue-controller:        kueue.x-k8s.io/*, 10+ workload framework CRDs for quota
- odh-dashboard:           18 component integrations, opendatahub.io/* resources
