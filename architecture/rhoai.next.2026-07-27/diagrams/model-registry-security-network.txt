SECURITY POSTURE:
- FIPS Compliance: model-registry built with GOEXPERIMENT=strictfipsruntime
- Container Users: BFF runs as nonroot (65532) on distroless; model-registry runs as UID 1001 on UBI9-minimal
- gRPC: Confirmed absent

SECRETS:
- model-catalog-hf-api-key (referenced) - HuggingFace API key for catalog server
- model-catalog-postgres (referenced) - PostgreSQL credentials for catalog server and database
- AWS_SECRET_ACCESS_KEY (environment variable) - S3 credentials for Python client / upload jobs

AUTHORIZATION MODEL:
- BFF Authorization Pipeline:
  1. InjectRequestIdentity: extracts user identity from request
  2. AttachNamespace: resolves target namespace
  3. RequireAccessToMRService: Kubernetes SAR via internal client (SA credentials)
  4. RequireListServiceAccessInNamespace: namespace-level access check
- Token-based AuthZ: SelfSubjectAccessReview for user-scoped checks
- Cluster-admin detection: ClusterRoleBinding inspection optimization
- Parallel SAR: 10-worker pool for namespace enumeration
- GAP: Agent catalog endpoints (/api/v1/agent_catalog/*) lack explicit SAR authorization

RBAC SUMMARY:
- No explicit ClusterRoles or RoleBindings defined in analyzed manifests
- Authorization delegated to Kubernetes API via SAR/SSAR mechanisms
- Service accounts used for controller and BFF internal client operations
