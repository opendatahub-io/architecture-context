RBAC Summary:
- No RBAC roles or bindings defined by this component.
- The plugin runs inside the vLLM serving pod; RBAC is managed by
  the RHOAI model serving controller (e.g., KServe).

Service Mesh Configuration:
- No service mesh configuration defined by this component.
- Service mesh policy (PeerAuthentication, AuthorizationPolicy)
  is managed by the RHOAI platform layer.

Secrets:
- No secrets defined by this component.
- Model storage credentials and serving certificates are managed
  by the RHOAI platform (e.g., storage-config secret, serving certs).

Container Security:
- Runs as non-root user (UID 2000) for OpenShift compatibility.
- Base image: UBI 9.6 (RHEL 9) — Red Hat certified and security-patched.
- No privileged capabilities required by the plugin itself.
- Hardware access (Gaudi HPU) requires device plugin or resource allocation
  at the Kubernetes node level.

Quantization Methods:
- compressed-tensors, fp8, inc, awq_hpu, gptq_hpu, modelopt
- INC quantization triggers CPU-first weight loading to prevent OOM.

Note: This component is an in-tree plugin for vLLM. It does NOT define its
own network services, ingress, egress, RBAC, or secrets. All external-facing
network architecture is managed by the RHOAI serving infrastructure (KServe,
Istio/Service Mesh, OpenShift Routes). The exact port/encryption/auth
configuration depends on the RHOAI deployment topology.
