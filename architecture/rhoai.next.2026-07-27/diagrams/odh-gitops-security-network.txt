TLS Architecture:
- Default CA: rhai-ca-issuer (internal, cert-manager)
- Optional: External ClusterIssuer support
- Certificates issued for:
  - inference-gateway (xKS inference traffic)
  - maas-gateway (xKS MaaS traffic)
  - maas-api-serving (MaaS API endpoint)
- CA trust distribution: rhai-ca-bundle ConfigMap
  - Mounted into istio-proxy containers
  - Patched into Authorino (SSL_CERT_FILE)

xKS Dependency Management:
- CloudManager operator per cloud provider (AWS, Azure, CoreWeave)
- KubernetesEngine CR with dependency policies:
  - cert-manager: Managed / Unmanaged
  - gateway-api: Managed / Unmanaged
  - lws: Managed / Unmanaged
  - sail-operator: Managed / Unmanaged

RBAC Summary:
- No explicit RBAC roles defined in repository
- RBAC delegated to deployed operators and OLM subscriptions
- Post-install hooks (shell scripts) require cluster-level permissions
  to create Gateways, HTTPRoutes, and patch Authorino

Secrets:
- TLS certificates (cert-manager issued, stored in Kubernetes Secrets)
- rhai-ca-bundle (ConfigMap, CA certificate chain)
- Cloud provider credentials (managed by CloudManager per cloud)

Note: odh-gitops is a configuration-only repository. It produces
Kubernetes manifests but does not run workloads itself. All network
architecture described above is configured by the charts/overlays
and realized on the target cluster.
