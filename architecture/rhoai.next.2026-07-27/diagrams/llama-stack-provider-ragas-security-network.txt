SECURITY NETWORK DIAGRAM: llama-stack-provider-ragas
Provider Type: trustyai_ragas (inline + remote)
Deployment: Provider Plugin loaded into Llama Stack Server process
================================================================================

NOTE: This component is NOT a standalone service. It is an out-of-tree
provider plugin loaded into the Llama Stack server process. It does not
expose its own network surfaces. Network interactions occur through the
host Llama Stack server or through outbound connections from KFP pods.

RBAC Summary:
- No ClusterRoles or RoleBindings defined by this component
- Provider runs within the Llama Stack server's security context
- KFP pipeline pods inherit KFP service account permissions
- AWS credentials provisioned via Kubernetes Secrets

Secrets:
- AWS credentials (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY)
  - Mounted into KFP pipeline pods via kfp.kubernetes.use_secret_as_env
  - Used for S3 read/write access to evaluation results
  - Provisioning: External (user-managed K8s Secret)
- KFP Bearer Token
  - Used for authenticating to Kubeflow Pipelines API
  - Source: Provider configuration (RagasProviderConfig)

Trust Boundaries:
- INTERNAL: Provider ↔ Llama Stack APIs (in-process, no network boundary)
- OUTBOUND: Provider → KFP API (Bearer token auth, encryption unknown)
- OUTBOUND: Provider → S3 (AWS IAM credentials, TLS)
- OUTBOUND: KFP Pods → Llama Stack API (auth not evidenced)
- OUTBOUND: KFP Pods → S3 (AWS IAM credentials from K8s Secret)

Evidence Gaps:
- Authentication from KFP pods to Llama Stack API is not evidenced
- KFP API endpoint encryption (TLS) is not confirmed in source
- Exact port numbers for KFP API are not specified (configurable)
