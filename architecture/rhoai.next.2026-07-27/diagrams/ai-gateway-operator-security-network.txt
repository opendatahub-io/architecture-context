RBAC Summary:
  Primary ClusterRole: ai-gateway-manager-role
  - 130+ RBAC rules spanning 20+ API groups
  - Core resources: configmaps, serviceaccounts, services, secrets, namespaces
  - Operator CRDs: aigateways, modelsasservices (components.platform.opendatahub.io)
  - Batch CRDs: llmbatchgateways (batch.llm-d.ai)
  - MaaS CRDs: aitenants, configs, externalmodels, maasauthpolicies, etc. (maas.opendatahub.io)
  - Inference CRDs: externalmodels, externalproviders (inference.opendatahub.io)
  - API Governance: authpolicies, ratelimitpolicies (kuadrant.io)
  - Service Mesh: destinationrules, envoyfilters, serviceentries (networking.istio.io)
  - TLS: certificates (cert-manager.io)
  - Observability: servicemonitors, prometheusrules (monitoring.coreos.com)
  - Network: networkpolicies (networking.k8s.io)

  Delegated Roles:
  - admin-role: full CRUD on AIGateway CR
  - editor-role: full CRUD on AIGateway CR
  - viewer-role: read-only on AIGateway CR

  Leader Election Role: ai-gateway-leader-election-role
  - Namespace: redhat-ods-applications
  - Resources: configmaps, leases, events

  Service Accounts:
  - ai-gateway-operator (primary)
  - Bound via: ai-gateway-manager-rolebinding → ai-gateway-manager-role

Authentication & Authorization:
  - Kubernetes API: ServiceAccount token (in-cluster), RBAC enforced
  - Health probes (/healthz, /readyz): Unauthenticated (kubelet access)
  - Metrics (8443/TCP): TLS + TokenReview/SubjectAccessReview

Security Notes:
  - ConfigMaps and Secrets excluded from client cache (read fresh)
  - Cache scoped to applications namespace + cluster-scoped resources
  - No Secrets declared in architecture (credentials managed externally)
  - No ingress endpoints (internal operator only)
