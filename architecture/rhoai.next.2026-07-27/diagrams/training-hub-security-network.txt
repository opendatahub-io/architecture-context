Inbound Network Surfaces:
- NONE (library, not a service)
- No Kubernetes Services defined
- No Ingress resources defined
- No HTTP/gRPC endpoints exposed
- 0 inbound authentication rules

Outbound Credential References:
- OPENAI_API_KEY (environment variable) - LLM API authentication
- OPENAI_API_BASE (environment variable) - LLM API endpoint URL
- MLFLOW_TRACKING_URI (environment variable) - MLflow server location
- WANDB_API_KEY (environment variable) - Weights & Biases authentication
- WANDB_ENTITY (environment variable) - W&B organization/entity

Credential Lifecycle:
- All credentials are user-provisioned at runtime (environment variables)
- GEPA backend implements save/restore semantics for environment variables
  (saves existing env, sets required vars, restores after training)
- No service accounts or Kubernetes secrets managed by the library
- No certificate rotation or automated credential management

RBAC Summary:
- No ClusterRoles or ClusterRoleBindings defined
- No ServiceAccounts created
- Library runs under the identity of the calling process/pod

Service Mesh / Network Policy:
- Not applicable (library, not a deployed service)
- Network policies would apply to the host pod, not the library itself

Secrets:
- OPENAI_API_KEY (environment variable) - User-provisioned, runtime, no auto-rotate
- No kubernetes.io/tls secrets
- No cert-manager integration

GPU/Compute Security:
- Multi-GPU training via CUDA (requires GPU access in container)
- verl backend launches subprocess workers (Ray/torchrun)
  - Requires process spawning capabilities
  - FSDP sharding for models up to 70B+ parameters
- openpipe-art manages vLLM AsyncLLM engines in-process
