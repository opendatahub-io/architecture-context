## Purpose

**Short**: OpenVINO Model Server (OVMS) is an inference serving engine that exposes KServe v2, TensorFlow Serving, and OpenAI-compatible REST and gRPC APIs for deploying ML models on Intel hardware.

**Detailed**: OpenVINO Model Server is an Intel-developed high-performance inference server built on the OpenVINO toolkit. In RHOAI, it is deployed as a KServe `ServingRuntime` (kind: `ServingRuntime`, API group: `serving.kserve.io/v1alpha1`) that serves ML models via dual REST and gRPC interfaces. The server supports multiple model formats including OpenVINO IR, ONNX, TensorFlow, PaddlePaddle, PyTorch, and Hugging Face generative models. It provides KServe v2 prediction protocol, TensorFlow Serving compatibility, OpenAI-compatible chat/completion/embedding APIs, and Cohere rerank APIs. The Go and Java code in the repository comprises client libraries and demos, not the core server.

## Data Flows

- **Inference request flow**: Client → KServe ingress gateway → Istio sidecar (TLS termination / auth) → OVMS container port 8888 (REST) or 8001 (gRPC) → OpenVINO inference engine → response.
- **Model loading flow**: KServe `InferenceService` creation → OVMS container starts → reads `--model_path` from `storageUri` mount at `/mnt/models` → loads model into OpenVINO runtime → marks model ready.
- **Streaming inference flow**: Client opens gRPC bidirectional stream on port 8001 → `ModelStreamInfer` RPC → MediaPipe graph instantiated per session → packets processed with monotonic timestamps → responses streamed back.
- **Metrics scrape flow**: Prometheus → scrapes `/metrics` on port 8888 (configured via `prometheus.io/path` and `prometheus.io/port` annotations on ServingRuntime).

## Architectural Analysis

- **Deployment shape**: OVMS is deployed as a KServe `ServingRuntime` (apiVersion: `serving.kserve.io/v1alpha1`). Each `InferenceService` creates a pod running the `kserve-container` with OVMS. The RHOAI variant (`kserve-ovms-2026-2`) configures gRPC on port 8001 and REST on port 8888 with GPU support (`latest-gpu` image).
- **Protocol support**: The server implements three protocol families: KServe v2 (REST and gRPC), TensorFlow Serving (REST and gRPC), and OpenAI/Cohere-compatible REST APIs for generative AI workloads (chat completions, completions, embeddings, rerank, image generation, speech-to-text, text-to-speech).
- **Model format breadth**: Supports OpenVINO IR (opset13), ONNX, TensorFlow 1/2, PaddlePaddle 2, PyTorch 2, Hugging Face generative models, and vLLM (non-autoSelect).
- **Security posture**: OVMS itself has no built-in authentication. Security is delegated to the KServe/Istio service mesh layer. An optional NGINX mTLS sidecar pattern is provided for environments requiring certificate-based mutual authentication. The KServe ClusterServingRuntime manifest enforces `runAsNonRoot: true`, `runAsUser: 5000`, drops ALL capabilities, and disables privilege escalation.
- **Streaming support**: gRPC bidirectional streaming is supported via `ModelStreamInfer` RPC for MediaPipe graph servables, enabling stateful inference sessions with automatic or manual timestamping.
- **Evidence boundary**: The primary server is C++ (not analyzed by the Go-focused static analyzer). Architecture facts are derived from Kubernetes manifests, documentation, and configuration files. The Go modules in the repository are client libraries and demos, not the core server. Dynamic runtime behavior beyond the extracted evidence is not asserted.
