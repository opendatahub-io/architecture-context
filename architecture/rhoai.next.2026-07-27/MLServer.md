## Purpose

**Short**: MLServer is a Python-based ML inference server implementing the V2 Inference Protocol over gRPC and REST (FastAPI), with 11 pluggable runtime backends, Prometheus metrics, and OpenTelemetry tracing.

**Detailed**: MLServer provides a standards-compliant inference serving layer for machine learning models in RHOAI. The core server exposes the V2 Inference Protocol via two transports: a gRPC server (insecure port, platform-delegated authentication via kube-rbac-proxy) implementing GRPCInferenceService and ModelRepositoryService, and a FastAPI-based REST API. It supports 10 pluggable ML runtime backends (Scikit-Learn, XGBoost, LightGBM, ONNX, MLflow, HuggingFace, Alibi-Detect, Alibi-Explain, CatBoost, Spark MLlib) as separate Python packages, each depending on the core `mlserver` package. The gRPC layer includes interceptors for request logging (LoggingInterceptor), Prometheus metrics collection (PromServerInterceptor via py-grpc-prometheus), and distributed tracing (OpenTelemetry). Integration points include Kafka (aiokafka) for message streaming, Triton Inference Server client (tritonclient) for protocol compatibility, and OTLP gRPC export for telemetry. The server runs on Python >=3.10,<3.13 with uvicorn as the ASGI server and optional uvloop for event loop acceleration.

## Data Flows

- **Entry and service surface:** MLServer exposes two transport layers: a gRPC server implementing the V2 Inference Protocol via GRPCInferenceService (11 RPCs including streaming inference) and ModelRepositoryService (3 RPCs for model lifecycle), plus a FastAPI REST API (endpoints not enumerated from allowed files; OpenAPI spec bundled at `mlserver/rest/openapi/*.json`). The gRPC server binds on an insecure port (`settings.grpc_port`) with authentication delegated to the platform kube-rbac-proxy sidecar.
- **gRPC interceptor chain:** Incoming gRPC requests pass through a configurable interceptor chain: (1) LoggingInterceptor logs non-health-check method calls (ServerLive, ServerReady, ModelReady are excluded), (2) PromServerInterceptor collects Prometheus metrics (request counts, latency histograms) via py-grpc-prometheus, and (3) OpenTelemetry aio_server_interceptor provides distributed tracing with health-check exclusions. Each interceptor is conditionally enabled via settings (access_log, metrics_endpoint, tracing_server).
- **Runtime inventory:** The server supports 10 pluggable ML runtime backends as separate Python packages, all depending on the core `mlserver` package. The alibi-explain runtime has cross-dependencies on mlserver-sklearn, mlserver-xgboost, and mlserver-lightgbm for baseline model comparison. The ODH runtimes group bundles sklearn, xgboost, lightgbm, and onnx (CPU), with an optional CUDA variant for GPU-accelerated ONNX inference.
- **Downstream interactions:** The structured facts record integration with Kafka (aiokafka for async messaging), Triton Inference Server (tritonclient with HTTP support for protocol-compatible communication), and OTLP telemetry export (opentelemetry-exporter-otlp-proto-grpc).
- **Security context:** 16 authentication rules (all platform-delegated to kube-rbac-proxy) cover the gRPC service surface. The RuntimeSecurity RPC (dataplane.proto:26) exposes runtime security mode (PRODUCTION/DEVELOPMENT) and allowed model implementation paths, providing a security policy query interface. REST API authentication posture is not extracted.
