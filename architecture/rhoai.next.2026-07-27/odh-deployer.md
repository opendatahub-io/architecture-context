## Purpose

**Short**: Shell-based deployment orchestrator that provisions RHOAI platform components, monitoring infrastructure, RBAC, network policies, and dashboard configuration via KfDef custom resources and direct Kubernetes manifests.

**Detailed**: odh-deployer is a Bash deployment script (`deploy.sh`) that orchestrates the installation and upgrade of Red Hat OpenShift AI (RHOAI, formerly RHODS) platform components on OpenShift clusters. It creates three namespaces (`redhat-ods-applications`, `redhat-ods-monitoring`, `rhods-notebooks`), deploys KfDef custom resources for each RHOAI component (Dashboard, Notebook Controller, Model Mesh, Data Science Pipelines Operator, Notebooks, Monitoring, Anaconda), provisions a Prometheus/Alertmanager monitoring stack with OAuth proxy sidecars, configures alerting integrations (PagerDuty, Dead Man's Snitch, SMTP) for OSD managed environments, applies pod security RBAC, network policies, ConsoleLink, and OdhDashboardConfig resources. It differentiates between OSD managed-service and self-managed deployment topologies.

## Data Flows

- **Deployment flow**: `deploy.sh` runs sequentially: creates namespaces with labels -> applies pod security RBAC -> deletes stale CRDs -> applies dashboard ISVs -> applies KfDef CRs for each component (Dashboard, NBC, Model Mesh, DSPO, Notebooks, Monitoring, Anaconda) -> configures OSD-specific alerting secrets -> deploys Prometheus/Alertmanager stack -> applies ConsoleLink -> applies OdhDashboardConfig -> applies network policies. <!-- source: deploy.sh:1-415 -->
- **Monitoring flow**: Prometheus init container blocks until all monitored services are healthy (Dashboard:8443, notebook-controller:8080, model-controller:8080, modelmesh:8080, dspo:8080), then Prometheus scrapes `/metrics` endpoints on each service. Alertmanager routes alerts to PagerDuty, Dead Man's Snitch, and SMTP (OSD) or acts as a sink (engineering clusters). <!-- source: monitoring/prometheus/prometheus.yaml:23-53; deploy.sh:247-293 -->
- **OSD vs self-managed branching**: deploy.sh detects OSD by checking for `addon-managed-odh-catalog` CatalogSource in the operator namespace. OSD path configures external alerting (DMS, PagerDuty, SMTP), applies `rhods-osd-configs.yaml` RBAC, and deploys `rhods-dashboard` Route. Self-managed path creates `rhods-admins` group and skips external alerting. <!-- source: deploy.sh:133-134, 233-344, 391-394 -->

## Architectural Analysis

- **Deployment shape**: odh-deployer is a one-shot deployment script, not a long-running controller. It orchestrates RHOAI installation by applying Kubernetes manifests and KfDef custom resources via the `oc` CLI. The only long-running workload it directly creates is the Prometheus/Alertmanager deployment in `redhat-ods-monitoring`.
- **OSD vs self-managed topology**: The script branches based on the presence of `addon-managed-odh-catalog` CatalogSource. OSD managed clusters receive full external alerting integration (PagerDuty, DMS, SMTP), a dedicated-admins RBAC model, and a dashboard Route in the monitoring namespace. Self-managed clusters create a `rhods-admins` group and skip external alerting.
- **KfDef orchestration**: All major RHOAI components are deployed as KfDef CRs consumed by the KubeFlow operator. The deployer does not directly manage component Deployments, Services, or CRDs for those components (except the monitoring stack and dashboard CRDs/ISVs).
- **Monitoring coupling**: The Prometheus init container creates a hard startup dependency on five RHOAI services. If any service fails to become available within ~38 minutes (230 iterations x 10s), the monitoring pod fails to start.
- **Evidence boundary**: Analyzer coverage is partial for platform_semantics and webhooks_source. The deployer is shell-based (unsupported by the Go/Python analyzer), so all architecture facts derive from direct source reads. KfDef content was not fully resolved due to file budget constraints. Network policies in `network/` were not read. Serving runtime resources in `odh-dashboard/modelserving` were not read.
- **Last activity**: Most recent commit is from 2023-09-15, suggesting this deployer may be superseded by operator-based deployment in newer RHOAI versions.
