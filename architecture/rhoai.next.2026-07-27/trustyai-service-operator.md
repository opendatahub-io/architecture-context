## Purpose

**Short**: Multi-service Kubernetes operator managing TrustyAI, EvalHub, LMEvalJob, GuardrailsOrchestrator, and NemoGuardrails custom resources with 12 runtime components, 11 API identities, and 59 integration points.

**Detailed**: trustyai-service-operator is a multi-service Kubernetes operator that manages AI trustworthiness, evaluation, and guardrails infrastructure for Red Hat OpenShift AI. The operator is flag-driven: the `--enable-services` flag selects which controller sets (EVALHUB, TAS) are active at runtime, and webhook servers are conditionally registered only when EVALHUB or TAS services are enabled (cmd/main.go:151-156). The operator produces two container images: a primary `manager` binary built from `cmd/main.go` and a FIPS-enabled `driver` binary built from `cmd/lmes_driver/*.go` with `GOEXPERIMENT=strictfipsruntime` and CGO_ENABLED=1 (Dockerfile.driver:19). TLS configuration is dynamically resolved from the OpenShift cluster TLS profile via `pkgtls.Resolve()` (cmd/main.go:119-123). The operator disables informer caching for ConfigMap, Secret, Pod, and Service resources to prevent OOM from cluster-wide cache flooding (cmd/main.go:138-146). Its documented interface surface contains 11 API identities, including 5 HTTP endpoints and 6 custom resource identities. The extracted dependency view records 9 internal platform dependencies and 59 integration points.

## Data Flows
