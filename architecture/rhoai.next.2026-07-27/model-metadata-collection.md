## Purpose

**Short**: CLI data pipeline that extracts metadata from Red Hat AI model containers (OCI registries), enriches it with HuggingFace data, and generates structured model, MCP server, and agent catalogs.

**Detailed**: model-metadata-collection is a batch-processing CLI tool comprising two commands (`model-extractor` and `metadata-report`). The `model-extractor` command fetches OCI container manifests from registries such as `registry.redhat.io`, extracts model card metadata from container layers, enriches the metadata with HuggingFace API data (model details, READMEs, tags, tool-calling configuration), and produces YAML catalogs for models, MCP servers, and agents. The `metadata-report` command generates completeness reports from the catalog output. The tool is not deployed as a runtime service and exposes no HTTP or gRPC endpoints.

## Data Flows

1. **Model extraction pipeline**: `model-extractor` reads a models index YAML → fetches OCI manifests from container registries → extracts model card layers (tar/gzip) → parses metadata from Markdown model cards → writes per-model metadata.yaml files to output directory.
2. **HuggingFace enrichment**: Fetches HuggingFace collections from RedHatAI → discovers validated model collections → enriches extracted metadata with HuggingFace model details (tags, license, language, provider, README content, tool-calling configuration) → updates metadata.yaml files.
3. **OCI artifact enrichment**: Updates all models with OCI artifact metadata including architecture information and timestamps from config blobs.
4. **Catalog generation**: Reads all per-model metadata.yaml files → merges with static catalog YAML files → deduplicates and consolidates models → writes unified models-catalog.yaml.
5. **MCP server catalog**: Reads MCP servers index YAML → enriches with OCI registry architecture data → generates MCP servers catalog YAML.
6. **Agent catalog**: Reads agents index YAML → fetches agent.yaml and README.md from GitHub repos → generates agents catalog YAML.
7. **Reporting**: `metadata-report` reads models-catalog.yaml and extraction output → generates completeness reports (Markdown + YAML).

## Architectural Analysis

- **Deployment shape:** CLI tool / data pipeline with two commands. Not deployed as a Kubernetes workload. Runs as batch processing, typically in CI/CD pipelines.
- **Concurrency model:** `model-extractor` processes models in parallel using goroutines with a configurable concurrency limit (`--max-concurrent`, default 5) and semaphore-based throttling.
- **Error handling:** Non-fatal errors during metadata extraction, enrichment, and HuggingFace fallback are logged as warnings; the pipeline continues processing remaining models. Fatal errors (e.g., directory creation failures, catalog write failures) terminate the process.
- **Authentication pattern:** All external API authentication is optional and token-based via environment variables (`HF_TOKEN`, `GITHUB_TOKEN`). A `.env` file is loaded at startup with shell environment variables taking precedence. OCI registry auth uses the `containers/image` library defaults.
