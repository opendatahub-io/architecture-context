## Purpose

**Short**: Llama Stack is a FastAPI-based application service providing a multi-provider AI inference, agents, and tool runtime platform with pluggable authentication, ABAC-based access control, and provider routing.

**Detailed**: ogx packages the Llama Stack framework as a FastAPI application service for RHOAI. The server (llama_stack/distribution/server/server.py) dynamically registers HTTP API routes from protocol definitions, supporting inference, agents, safety, vector I/O, dataset I/O, scoring, eval, and tool runtime APIs. Authentication is configuration-conditional, supporting OAuth2 JWT/JWKS validation, RFC 7662 token introspection, and custom external HTTP authentication delegation (llama_stack/distribution/server/auth_providers.py). An InferenceRouter (llama_stack/distribution/routers/inference.py) routes requests to backend providers based on model identity, while CommonRoutingTableImpl (llama_stack/distribution/routing_tables/common.py) enforces attribute-based access control (ABAC) on resource create, read, and delete operations. Agent session persistence uses a KV store with per-session ABAC checks (llama_stack/providers/inline/agents/meta_reference/persistence.py). A Streamlit-based UI module connects to the Llama Stack API endpoint via the llama-stack-client SDK (llama_stack/distribution/ui/modules/api.py). The service integrates with multiple remote inference and data providers including OpenAI, Cerebras, NVIDIA NeMo, and Tavily.

## Data Flows

- **Runtime inventory:** The application is a FastAPI server (server.py) that dynamically registers API routes from protocol definitions for inference, agents, safety, vector_io, datasetio, scoring, eval, tool_runtime, inspect, and providers APIs. The server listens on port 8321 by default (env `LLAMA_STACK_PORT`) and supports optional TLS via `tls_keyfile`/`tls_certfile`/`tls_cafile` configuration.
- **Request routing:** Incoming inference requests are routed by InferenceRouter (inference.py) to backend provider implementations based on model identity via the routing table. The routing table (common.py) resolves providers by looking up the registered object's `provider_id` and enforces ABAC via `is_action_allowed` on all resource create, read, delete, and list operations.
- **Authentication flow:** When `config.server.auth` is set, AuthenticationMiddleware intercepts all requests and delegates to either OAuth2TokenAuthProvider (JWKS-based JWT validation or RFC 7662 token introspection) or CustomAuthProvider (external HTTP endpoint) based on the configured `provider_type`. OAuth2 claims are mapped to access attributes via configurable `claims_mapping` (default: sub/username->roles, groups/team->teams, project->projects, tenant/namespace->namespaces). A QuotaMiddleware layer provides optional rate limiting with separate thresholds for authenticated and anonymous clients.
