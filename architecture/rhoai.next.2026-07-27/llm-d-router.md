## Purpose

**Short**: LLM inference request router implementing Envoy External Processing (ExtProc) with plugin-driven scheduling, flow control, and a Coordinator HTTP gateway for OpenAI-compatible inference endpoints.

**Detailed**: llm-d-router is an LLM inference request routing system for Kubernetes that operates as an Envoy External Processing (ExtProc) gRPC server. It receives per-request callouts from Envoy proxy and uses a configurable plugin framework to schedule requests across inference endpoint pools. The system comprises two primary runtime components: the **Endpoint Picker (EPP)**, a gRPC service that implements intelligent request routing with scheduling profiles, flow control with priority bands, a data layer for endpoint metrics/attributes, and multi-protocol parser support (OpenAI, Anthropic, vLLM gRPC/HTTP, Vertex AI, passthrough); and the **Coordinator Server**, an HTTP gateway that exposes OpenAI-compatible `/v1/chat/completions` and `/v1/completions` endpoints with health probes. The EPP manages three custom resource definitions (EndpointPickerConfig, InferenceModelRewrite, InferenceObjective) to configure plugin-driven scheduling, model name rewriting with weighted traffic distribution, and priority-based flow control respectively. Four Kubernetes controllers reconcile InferenceModelRewrite, InferenceObjective, InferencePool, and Pod resources. The system also supports a non-Kubernetes file-discovery mode for bare-metal/Slurm/Ray deployments. The documented interface surface contains 15 API identities (6 HTTP endpoints, 2 gRPC services, 3 CRDs), 4 internal platform dependencies, and 12 integration points.
