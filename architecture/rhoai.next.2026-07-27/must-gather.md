## Purpose

**Short**: Diagnostic data collection tool that gathers logs, resource definitions, and cluster state from all RHOAI components for support and troubleshooting.

**Detailed**: must-gather is a shell-script-based diagnostic collection tool invoked via `oc adm must-gather`. It detects the Kubernetes distribution (OpenShift, AKS, CKS, EKS), dispatches to 14+ component-specific collection scripts in parallel, and aggregates namespace logs, custom resource snapshots, Helm release values, and Gateway API/Istio resources into a structured must-gather archive. On OpenShift it collects RHOAI-specific operator resources (DSCI, DSC, component CRs); on non-OpenShift distributions it defaults to llm-d collection only.

## Data Flows

1. User invokes `oc adm must-gather --image=<must-gather-image>` on an OpenShift cluster.
2. OpenShift creates a temporary pod with the must-gather container image and mounts a service account token.
3. `gather.sh` detects the Kubernetes distribution via `llm-d/xks_util.sh`.
4. On OpenShift: collects operator, monitoring, applications, notebooks, model-registries, ingress, kuadrant, and Helm chart namespaces via `oc adm inspect`. Collects DSCI, DSC, component CRs, webhook configurations, and gateway classes.
5. Dispatches to 14 component-specific gather scripts in parallel (or individually if `COMPONENT` is set).
6. Each gather script discovers namespaces where its target CRDs exist, then calls `run_mustgather()` to collect namespace logs and custom resources including default Gateway API and Istio resources.
7. On non-OpenShift (xKS): defaults to llm-d collection only, with optional WVA and batch gateway.
8. Results are written to the `must-gather/` directory, flushed to disk, and a summary report is printed.

## Architectural Analysis

- **Deployment shape:** must-gather is a Container Image deployed as an ephemeral pod by `oc adm must-gather`. It has no persistent runtime, no services, and no inbound network surfaces. It is represented by 19 shell-script architecture components (1 orchestrator, 2 libraries, 16 collectors).
- **Multi-distribution support:** The orchestrator detects OpenShift vs. xKS (AKS, CKS, EKS) distributions. On OpenShift, it collects all RHOAI components in parallel. On xKS, it restricts collection to llm-d only and uses `kubectl` instead of `oc`.
- **Parallel collection:** In the default "all" mode, 14 component gather scripts run in parallel as background processes, with failure tracking and summary reporting.
- **Configurable scope:** The `COMPONENT` environment variable allows targeting a single component (e.g., `kserve`, `dsp`, `dashboard`) instead of collecting all.
