## Purpose

**Short**: Python library that automates hyperparameter optimization for Retrieval-Augmented Generation (RAG) pipelines, returning initialized RAG Templates with optimal parameter values (RAG Patterns).

**Detailed**: ai4rag is an optimization engine for RAG Templates that is LLM and vector database provider-agnostic. It accepts a search space definition encompassing chunking strategies, embedding models, foundation models, retrieval methods, and vector store configurations. Using a Generalized Additive Model (GAM) based optimizer (or random search), it explores the parameter space and evaluates each RAG Pattern configuration against a user-provided benchmark dataset using metrics such as answer correctness, faithfulness, context correctness, and LLM-as-a-Judge answer relevance.

The library is designed to work out-of-the-box with OGX (formerly llama-stack) for embeddings, vector storage, and text generation, but provides extensible base classes (`BaseFoundationModel`, `BaseEmbeddingModel`, `BaseVectorStore`, `BaseRAGTemplate`, `BaseEvaluator`) so users can integrate their own implementations. It also includes pipeline components for S3-based document discovery, text extraction via Docling, search space preparation, and output artifact generation (pattern JSON definitions and Jupyter notebooks for indexing and inference). A `KFPEventHandler` is included for integration with Kubeflow Pipelines.

## Architectural Analysis

ai4rag follows a clean layered architecture with well-defined abstractions at each tier. The `core/experiment` layer orchestrates the optimization loop, the `core/hpo` layer provides pluggable optimization algorithms, the `rag` layer provides composable RAG pipeline building blocks, and the `evaluator` layer handles metric computation. This separation enables users to swap components independently — for example, replacing the OGX vector store with ChromaDB, or using a custom foundation model implementation.

The optimization strategy is noteworthy: ai4rag uses a **Generalized Additive Model** (`pygam.LinearGAM`) as a surrogate model to predict scores for unevaluated parameter combinations, then greedily selects the highest-predicted configurations for evaluation. This is a Bayesian-style optimization approach that balances exploration (initial random phase) with exploitation (GAM-guided selection). The search space is combinatorial — all parameters are categorical (`param_type="C"`), and the optimizer encodes them via `sklearn.LabelEncoder` before fitting the GAM. A set of constraint rules (e.g., chunk_size must exceed 2× chunk_overlap, hybrid chunking requires overlap=0, chunk_size must fit within embedding context length) prunes invalid combinations before optimization begins.

The **model pre-selection** (`ModelsPreSelector`) phase is an interesting optimization: when the search space contains many foundation and embedding models, a quick evaluation on a small benchmark sample using in-memory ChromaDB identifies the top-performing models before the full experiment begins. This reduces the combinatorial explosion. The **LLM-as-a-Judge** evaluation adds a novel dimension — a calibration round selects the best judge model by measuring score spread and call stability across candidates.

Security-wise, the SSL fallback pattern throughout the codebase (`verify=False` on SSL errors) is designed for development environments with self-signed certificates but represents a supply chain risk if used in production. The library delegates all authentication to the consuming application and does not enforce any credential management policies. The `AI4RAGChunk` dataclass uses SHA-256 for deterministic chunk ID generation, which is FIPS-compliant.

The `components/` package provides pipeline-ready orchestration functions (`run_rag_optimization`, `discover_documents`, `extract_text`) designed for Kubeflow Pipelines integration via the `KFPEventHandler`. The asset generation subsystem (`components/assets_generator`) creates Responses API-compatible pattern definitions and Jupyter notebooks, bridging the gap between optimization results and deployment artifacts.
