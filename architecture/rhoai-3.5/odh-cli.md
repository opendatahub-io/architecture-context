## Purpose

**Short**: CLI tool for RHOAI (Red Hat OpenShift AI) that validates cluster configurations, assesses upgrade readiness, executes migrations, and provides operational diagnostics for RHOAI deployments on OpenShift.

**Detailed**: odh-cli is a kubectl plugin (`kubectl-odh` / `rhai-cli`) that provides a comprehensive command-line interface for managing RHOAI platform lifecycle operations. The CLI connects to the Kubernetes API server using kubeconfig credentials and inspects the live state of RHOAI components, operator subscriptions, workloads, and dependencies to produce diagnostic reports.

The tool's primary capabilities span three domains: (1) **upgrade readiness assessment** via the `lint` command, which runs 50+ diagnostic checks across dependency, platform, component, and workload layers to identify blocking issues before version upgrades (2.x→3.x, 3.4→3.5); (2) **automated migration** via the `migrate` command, which executes phased pre-upgrade and post-upgrade actions for workbenches, model serving, AI pipelines, Kueue, TrustyAI, Ray clusters, and LlamaStack; and (3) **operational observability** via `status`, `events`, `logs`, `components`, and `deps` commands that provide real-time cluster health, event streaming, log aggregation, and dependency graph visualization.

The CLI also exposes a Model Context Protocol (MCP) server, allowing AI agents to interact with all CLI capabilities programmatically. It is distributed both as a standalone Go binary and as a container image (`quay.io/rhoai/rhai-cli-rhel9`) that bundles `kubectl` and `oc` for interactive troubleshooting.

## Architectural Analysis

The odh-cli is architecturally significant as the primary user-facing tool for RHOAI cluster lifecycle management. Its design follows a clean separation between command-layer orchestration (`cmd/`) and domain logic (`pkg/`), with a consistent four-phase lifecycle pattern (`AddFlags → Complete → Validate → Run`) across all 15 commands. This uniformity extends to error handling, where a `StructuredError` type with differentiated exit codes (0-5) enables CI/CD pipeline integration without parsing output text.

The lint check framework is the most architecturally complex subsystem. It implements a plugin-style registry where checks self-register with metadata (ID, group, version applicability), and an executor runs them in canonical group order (Dependency → Service → Platform → Component → Workload). The validation builder pattern (ComponentBuilder, DSCBuilder, WorkloadBuilder, OperatorBuilder) provides fluent APIs that abstract repetitive patterns like "fetch DSC, check component state, list workloads by label, filter by annotation." This framework currently contains 50+ checks covering the full upgrade surface from RHOAI 2.x→3.x and 3.4→3.5. Notably, the checks are entirely read-only -- they never modify cluster state, making them safe to run in production.

The migration action framework mirrors the lint framework's registry pattern but adds a prepare/run lifecycle with recording, dry-run support, and phase-based ordering (pre-upgrade, post-upgrade). Migration actions range from simple annotation patches to complex multi-step operations like the workbench auth model migration (which patches OAuth proxy containers to kube-rbac-proxy) and the TrustyAI metrics migration (which makes HTTP calls to back up and restore metrics definitions via OpenShift Routes). The `InsecureSkipVerify: true` in the TrustyAI HTTP client is a documented trade-off for in-cluster self-signed route certificates -- the nolint annotation references the original `curl -sk` behavior being ported.

The MCP (Model Context Protocol) integration is noteworthy as it exposes all CLI capabilities to AI agents via a standardized protocol. The adapter pattern deep-clones ConfigFlags (including auth fields like BearerToken, client certs, and impersonation) per invocation, ensuring thread-safe concurrent access. The server supports both stdio transport (for embedded agent use) and SSE transport (on port 8080 for network-attached agents). This makes the CLI a bridge between AI-powered automation and RHOAI cluster management.

Security design is defense-in-depth despite being a read-mostly tool. The dependency manifest parser validates OLM catalog sources against an allowlist (CWE-829 prevention) and rejects system namespace targeting (CWE-269). The events output sanitizes terminal escape sequences (CWE-150). The MCP backup tool rejects directory traversal in output paths. RBAC is enforced via SelfSubjectAccessReview preflight checks before operations, with graceful degradation on permission denial rather than hard failures.
