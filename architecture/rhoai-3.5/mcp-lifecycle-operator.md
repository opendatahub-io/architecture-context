## Purpose

**Short**: A Kubernetes operator that provides a declarative API to deploy, manage, and safely roll out Model Context Protocol (MCP) servers, handling their full lifecycle with production-grade automation.

**Detailed**: The MCP Lifecycle Operator is a controller-runtime based Kubernetes operator that watches `MCPServer` custom resources and reconciles them into a set of managed Kubernetes resources: a Deployment running the user-specified MCP server container image, a ClusterIP Service for in-cluster discovery, and a NetworkPolicy restricting ingress to the MCP port. The operator is part of the Kubernetes SIG Apps community project (kubernetes-sigs) and has been adopted by Red Hat for inclusion in RHOAI 3.5.

The operator goes beyond simple resource creation by performing an MCP protocol handshake against deployed servers to verify they actually speak the Model Context Protocol. It reports server capabilities (tools, resources, prompts, logging, completions) and connection details in the MCPServer status. The operator also computes a config hash of referenced ConfigMaps and Secrets to trigger rolling updates when external configuration changes, watches ConfigMap and Secret resources to re-reconcile when they are modified, and validates resource ownership to prevent conflicts with manually-created resources.

For RHOAI deployment, the operator is built with FIPS-compliant crypto (`GOEXPERIMENT=strictfipsruntime`, `CGO_ENABLED=1`, `-tags strictfipsruntime`) and supports TLS configuration propagation from the platform to managed MCP server containers via the `PROPAGATE_TLS_ENV_VARS` environment variable. The ODH overlay adds Prometheus ServiceMonitor integration for metrics collection.

## Architectural Analysis

The MCP Lifecycle Operator follows a standard kubebuilder v4 scaffolding pattern with a single controller reconciling the `MCPServer` CRD. The reconciliation flow is structured as a linear pipeline: validate configuration → reconcile Deployment → reconcile Service → reconcile NetworkPolicy → determine Ready condition → perform MCP handshake → update status. Each phase has its own Prometheus histogram metric (`mcpserver_reconcile_phase_duration_seconds`) enabling fine-grained performance analysis. Error handling distinguishes between permanent validation errors (which set `Accepted=False` and stop reconciliation) and transient errors (which preserve existing status and rely on controller-runtime's exponential backoff).

A distinguishing architectural feature is the MCP protocol handshake. After the Deployment reaches `Available` status, the operator opens an MCP Streamable HTTP connection to the server's in-cluster Service URL, performs a protocol-level `initialize` handshake using the `modelcontextprotocol/go-sdk`, and extracts the server's self-reported name, version, protocol version, instructions, and capabilities (tools, resources, prompts, logging, completions). This information is stored in `status.serverInfo`, making the operator not just a deployment manager but also a protocol-aware service registry. The handshake uses exponential backoff (10s → 20s → 40s → 80s → 120s cap) with a maximum of 10 retries before stopping requeue. HTTP 401/403 responses are treated as "reachable" since they indicate the endpoint is alive but requires authentication.

The operator's config hash mechanism (`mcp.x-k8s.io/config-hash` annotation) provides automated rolling updates when referenced ConfigMaps or Secrets change. The controller watches ConfigMap and Secret resources using field indexes (`spec.configMapRefs`, `spec.secretRefs`) to efficiently find which MCPServer CRs reference a given resource, then computes a SHA-256 hash of all referenced data and places it in the pod template annotation, triggering Kubernetes' native rolling update machinery. This avoids the common pitfall where ConfigMap/Secret changes don't trigger pod restarts.

The ownership model is carefully designed: the controller uses `controllerutil.SetControllerReference` for all managed resources and validates ownership before updates. It rejects resources owned by other controllers or unowned resources (preventing silent adoption), but allows adoption of orphaned resources from a deleted MCPServer with the same name—enabling seamless recreation without manual cleanup. This is implemented in `mcpserver_controller_ownership.go` with a custom `OwnershipConflictError` type that the reconciler handles by returning without requeue (since the conflict is permanent until human intervention).

For RHOAI deployment, the operator adds platform-specific capabilities: FIPS-compliant builds via `GOEXPERIMENT=strictfipsruntime` with dynamic linking, configurable TLS profiles via `TLS_MIN_VERSION` and `TLS_CIPHER_SUITES` environment variables (parsed in `cmd/tlsconfig.go`), and TLS environment variable propagation to managed MCP server containers via the `PROPAGATE_TLS_ENV_VARS` flag. HTTP/2 is disabled by default as a mitigation for the HTTP/2 Rapid Reset CVE (GHSA-qppj-fm5r-hxr3). The operator applies restricted Pod Security Standards by default (non-root, read-only root filesystem, drop ALL capabilities, RuntimeDefault seccomp profile).
