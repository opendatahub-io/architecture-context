RBAC Summary:
- No RBAC resources defined by SDK
- SDK assumes user's kubeconfig / ServiceAccount has permissions for:
  - trainer.kubeflow.org: TrainJob (create, get, list, watch)
  - trainer.kubeflow.org: ClusterTrainingRuntime (get, list)
  - trainer.kubeflow.org: TrainingRuntime (get, list)
  - core: Pods (get, list), Pods/log (get)
  - core: Events (list)
  - core: Secrets (get) - for data connection credentials
  - core: ConfigMaps (get) - for kubeflow-trainer-public

Secrets:
- Data Connection (user-specified, Opaque) - S3 credentials, User/RHOAI Dashboard provisioned, No auto-rotate
- HuggingFace access token (user-specified, Opaque) - Private model/dataset auth, User provisioned, No auto-rotate
- S3 credentials (user-specified, Opaque) - S3DatasetInitializer/S3ModelInitializer access, User provisioned, No auto-rotate

Security Notes:
- SDK reads secrets via CoreV1Api.read_namespaced_secret -- never stores or caches values
- TransformersTrainer verify_cloud_storage_ssl=False option disables S3 cert verification (user opt-in)
- HTTP metrics server (port 28080) is unauthenticated -- exposed only within pod network
- SDK is pure Python library -- FIPS compliance depends on runtime environment (Python/OpenSSL)
- No container images produced -- no check-payload validation applicable
- TLS delegated to kubernetes Python client (urllib3/OpenSSL) and fsspec/s3fs
