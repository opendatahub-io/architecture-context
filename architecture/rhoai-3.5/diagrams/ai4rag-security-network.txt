===================================

Note: ai4rag is a Python library, not a deployed Kubernetes service.
It runs within the caller's process (e.g., Kubeflow Pipeline pod) and
makes outbound connections only.  There are no ingress points.

Secrets:
  - OGX API Key (Opaque)
    - Purpose: Authentication to OGX server via OgxClient(api_key=...)
    - Provisioned by: User-provided (environment variable or code)
    - Auto-Rotate: No

  - AWS_ACCESS_KEY_ID (Opaque)
    - Purpose: S3 authentication for document discovery/download
    - Provisioned by: User-provided (environment variable)
    - Auto-Rotate: No

  - AWS_SECRET_ACCESS_KEY (Opaque)
    - Purpose: S3 authentication for document discovery/download
    - Provisioned by: User-provided (environment variable)
    - Auto-Rotate: No

Authentication & Authorization:
  - OGX Server: API Key (Bearer) — required for all operations
  - S3 Storage: AWS SigV4 (IAM credentials) — bucket-level access control
  - HuggingFace Hub: None (public access)

RBAC Summary:
  - N/A — ai4rag is a Python library, not a Kubernetes component.
  - No ClusterRoles, Roles, or RoleBindings.
  - RBAC is inherited from the caller's ServiceAccount.

Service Mesh Configuration:
  - N/A — ai4rag does not deploy services.
  - mTLS depends on the hosting environment's service mesh configuration.

Security Risks:
  ⚠ SSL Fallback Pattern (verify=False)
    - Files: ogx_client.py, documents_discovery.py, text_extraction.py
    - Risk: Certificate verification bypassed on SSL errors (self-signed certs)
    - Acceptable for: Development environments
    - Risk level: HIGH for production — potential MITM attack vector
    - Recommendation: Disable SSL fallback in production; provide proper CA certs

Crypto Summary:
  - hashlib.sha256 (stdlib) — chunk ID generation (FIPS-safe)
  - No non-FIPS crypto libraries detected (no pyOpenSSL, pycryptodome, etc.)
  - TLS configuration delegated to ogx-client and boto3
