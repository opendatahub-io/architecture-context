RBAC Summary:
- This component does NOT define its own RBAC resources.
- Runs as non-root user (UID 1001) within a pod managed by KServe controller.
- RBAC for InferenceService resources is managed by the KServe operator
  and platform operator.
- External request auth is enforced by kube-rbac-proxy sidecar (RHOAI 3.x).

Authentication Summary:
- Inference endpoints: Platform-delegated via kube-rbac-proxy sidecar
  - kube-rbac-proxy listens on 8443/TCP (TLS), proxies to container 8080/TCP (HTTP)
  - Enforces RHOAI platform RBAC (Bearer Token validation)
- Health endpoints: Unauthenticated (direct access for Kubernetes probes)
  - /v2/health/ready and /v2/health/live on 8080/TCP
- Storage egress: Credential-based (IAM, SA, Token per storage provider)
  - Credentials injected by KServe controller via environment variables

Secrets:
- No secrets defined by this component.
- Cloud storage credentials are injected by KServe controller
  via ServiceAccount annotations or environment variables.
- TLS certificates for kube-rbac-proxy are managed by the platform.

FIPS Compliance:
- Base image: AIPCC CPU RHEL 9.6 UBI (FIPS-validated OpenSSL)
- cryptography 48.0.0: Uses system OpenSSL as backend (FIPS-capable)
- No non-FIPS crypto detected in autogluonserver source code
- Pure Python component -- no Go binaries requiring GOEXPERIMENT=strictfipsruntime

Build Hermeticity:
- Hermetic Konflux/Tekton build pipeline
- Python deps: autogluon-all-requirements.txt (SHA256 hash-pinned, ~1092 lines)
- Package source: RHEL AI Python Package Index (console.redhat.com)
- Hermeto (cachi2) prefetch for pip dependencies
- No rpms.lock.yaml -- OS package hermeticity via AIPCC base image

Multi-Tenancy:
- Tenant boundary: per-namespace (via InferenceService)

- Each pod serves exactly one model -- no cross-model API leakage
