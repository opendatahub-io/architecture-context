STORAGE:
- PersistentVolumeClaim mounted at /inputs (default storage mode: PVC)
- Data format: CSV (configurable)
- Batch size: 50,000 records (default)

RBAC Summary:
- ClusterRole: trustyai-role
  - API Groups: "" (core)
  - Resources: configmaps
  - Verbs: create, delete, get, list, patch, update, watch

- ClusterRoleBinding: trustyai-clusterrolebinding
  - Role: trustyai-role (ClusterRole)
  - ServiceAccount: trustyai-serviceaccount (cluster-wide)

Authentication & Authorization:
- In-service: No authentication or authorization
- External enforcement: kube-rbac-proxy sidecar (injected by TrustyAI Service Operator)
  - AuthN: Kubernetes TokenReview
  - AuthZ: Kubernetes SubjectAccessReview
- /q/metrics: Bearer token (ServiceAccount token) via ServiceMonitor

Secrets:
- TLS cert (/etc/tls/internal/tls.crt) — TLS certificate for HTTPS on port 4443
  - Provisioned by: Platform (cert-manager or operator)
  - Auto-Rotate: Unknown
- Database credentials (QUARKUS_DATASOURCE_USERNAME/PASSWORD) — Opaque
  - Provisioned by: Manual / operator
  - Auto-Rotate: No
- MinIO credentials (minio.access-key/secret-key) — Opaque
  - Provisioned by: Manual / operator
  - Auto-Rotate: No

FIPS Compliance Notes:
- Java application on UBI9 OpenJDK 17 runtime (FIPS inherited from JVM + base image)
- Quarkus TLS on port 4443 when certs are mounted
- gRPC connector uses usePlaintext() — no TLS for inference server calls (FIPS gap)
- Upstream Dockerfile disables SunPKCS11 provider but this is NOT in Konflux build
- Build uses PNC (Product Newcastle) for hermetic Maven artifact resolution

Multi-Tenancy:
- Deployment model: per-namespace instance
- Tenant boundary: namespace name + model ID
- Each namespace with model serving gets its own TrustyAI Service instance
- No cross-namespace data access (separate PVC/DB per instance)
- No per-user scoping within a namespace (all namespace users see all models)
