RBAC Summary:
- No Kubernetes ClusterRoles or RoleBindings defined
- This is a standalone containerized service, not a Kubernetes operator
- Access control is delegated to the platform auth layer (kube-rbac-proxy)

Secrets / Credentials:
- OPENAI_API_KEY (env var) - API key for OpenAI-compatible LLM providers
- MAIN_MODEL_BASE_URL (env var) - Base URL for upstream LLM server
- MAIN_MODEL_ENGINE (env var) - LLM provider engine type
- ANTHROPIC_API_KEY (env var) - API key for Anthropic provider
- AZURE_OPENAI_API_KEY (env var) - API key for Azure OpenAI
- COHERE_API_KEY (env var) - API key for Cohere provider
- X-Authorization (HTTP header) - Runtime auth forwarded to upstream LLM

TLS / Crypto Notes:
- Server does NOT terminate TLS — relies on platform ingress/sidecar
- Outbound TLS uses Python stdlib ssl defaults (inherits RHEL 9.6 OpenSSL)
- REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt (system trust store)
- hashlib.md5 used for cache key generation (non-security, but may warn on FIPS)
- verify_ssl option in HF classifier backends can disable TLS verification (risk)

Multi-Tenancy:
- Tenant boundary: per-config_id (each guardrails config is an isolated context)
- Deployment: single-tenant process (all config_ids share same memory/connections)
- No per-config authentication or network isolation
- Thread data isolated by thread_id but not by config_id (cross-config access possible)
