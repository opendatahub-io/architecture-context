RBAC Summary:
- MLServer does not define Kubernetes RBAC roles or bindings
- Runs as a container within KServe-managed InferenceService pods
- Pod-level RBAC managed by KServe controller service account
- No direct Kubernetes API access from MLServer application

Authentication Summary:
- Application-level: No authentication (all endpoints unauthenticated)
- Pod-level: kube-rbac-proxy sidecar provides Bearer Token validation
- Ingress: KServe Gateway API with TLS 1.2+ termination
- CORS: Production mode blocks wildcard origins when trusted runtimes are configured

Secrets:
- No Kubernetes Secrets directly referenced by MLServer
- Model artifacts mounted via PVC (no credential management)
- Trusted runtimes allowlist baked into container image at build time

Security Hardening:
- Trusted runtimes allowlist prevents arbitrary code execution via model-settings.json
- Production mode blocks environment-path and tarball injection attacks
- CORS validation in production mode prevents cross-origin abuse
- gRPC server uses add_insecure_port() — TLS delegated to KServe ingress

Build Security:
- Hermetic builds via Konflux (hermetic: true in Tekton pipelines)
- Hermeto pip prefetch with hash-pinned requirements files
- RHEL AI Python Package Index (packages.redhat.com) as package source
- AIPCC base images provide FIPS-compliant OpenSSL
