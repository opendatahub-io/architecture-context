RBAC Summary:
  No RBAC resources defined in this repository.
  RBAC is managed by the platform operator (rhods-operator).

Secrets:
  - TLS server cert/key (kubernetes.io/tls)
    Purpose: Server TLS for API endpoints
    Configured via: TLS_CERT_PATH, TLS_KEY_PATH env vars
    Provisioned by: Platform operator / cert-manager
    Rotation: Unknown

  - TLS client CA cert (Opaque)
    Purpose: mTLS client verification
    Configured via: TLS_CLIENT_CA_CERT_PATH env var
    Provisioned by: Platform operator
    Rotation: Unknown

  - Per-service TLS certs (Opaque)
    Purpose: Client TLS for outbound connections
    Configured via: Per-service tls_certs config block
    Provisioned by: Platform operator
    Rotation: Unknown

  - API tokens (Opaque)
    Purpose: Bearer token auth for HTTP downstream services
    Configured via: Per-service api_token config (references env vars)
    Provisioned by: Platform operator
    Rotation: Unknown

FIPS Compliance Notes:
  - TLS implementation: rustls + ring crypto backend (NOT FIPS-validated)
  - No FIPS-certified crypto module in application
  - Platform relies on node-level FIPS mode and RHEL crypto policies
  - openssl-devel used at build time for protobuf compilation only, not runtime TLS

Security Risks:
  ⚠ NoVerifier (src/utils/tls.rs:39-91) bypasses ALL certificate verification
    when insecure: true is set in per-service client TLS config.
    Impact: Man-in-the-middle attacks on downstream connections.
    Mitigation: Ensure insecure: true is never set in production config.

  ⚠ No per-request authentication within orchestrator.
    Any request reaching the service (past platform gateway) is processed.
    Relies entirely on upstream gateway for AuthN/AuthZ.

  ⚠ No NetworkPolicy resources shipped in this repository.
    Network isolation must be managed by platform operator.
