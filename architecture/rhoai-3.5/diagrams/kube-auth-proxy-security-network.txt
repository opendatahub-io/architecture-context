RBAC Summary:
- No RBAC manifests in this repository
- ServiceAccount RBAC is configured by the platform operator (rhods-operator)
- Required permissions:
  - authentication.k8s.io/v1: tokenreviews (create) -- for SA token validation
  - user.openshift.io/v1: users (get) -- for user identity lookup
  - oauth.openshift.io/v1: oauthaccesstokens (delete) -- for sign-out cleanup

Secrets:
- OAuth client credentials (Opaque) -- client_id + client_secret, provisioned by platform operator, no auto-rotate
- TLS certificate/key (kubernetes.io/tls) -- HTTPS listener, cert-manager or operator provisioned, auto-rotate via cert-manager
- Cookie secret (Opaque) -- AES encryption key for session cookies, provisioned by platform operator, no auto-rotate
- Redis password (Opaque) -- Redis session store auth, provisioned by platform operator, no auto-rotate
- ServiceAccount token (Projected) -- in-cluster K8s API auth, auto-rotated by Kubernetes
- ServiceAccount CA (Projected) -- TLS CA for K8s API, no auto-rotate (requires pod restart)

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Runtime: All crypto via OpenSSL (UBI9 base image)
- TLS: MinVersion TLS 1.2, configurable cipher suites, HTTP/2 ALPN
- No weak crypto: No MD5, RC4, or DES imports
- Risk: --ssl-insecure-skip-verify flag exists (defaults false, development only)

Authentication Chain (ordered):
1. K8s ServiceAccount token (TokenReview API) -- machine-to-machine
2. JWT Bearer token (OIDC verification) -- programmatic access
3. OAuth Bearer token (sha256~ format, OpenShift validation) -- programmatic access
4. Stored session (cookie or Redis) -- interactive browser sessions

Session Security:
- Cookie encryption: AES-GCM (authenticated) or AES-CFB + HMAC
- Cookie splitting: 4000-byte limit per cookie, auto-split for large sessions
- Redis sessions: Per-session key isolation, distributed refresh locking
- Minimal mode: --session-cookie-minimal strips tokens from cookies
