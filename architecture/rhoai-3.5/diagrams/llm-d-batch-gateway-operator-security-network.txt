Service Account Bindings:

- llm-d-batch-gateway-operator → leader-election-role (RoleBinding, operator namespace)

Cross-Namespace Secret Access:
- Mechanism: Gateway API ReferenceGrant authorization
- Operator copies referenced Secret into CR namespace as {gateway-name}-credentials
- SecretRef immutable after creation (prevents credential-swap attacks)

Secrets:
- {spec.secretRef.name} (Opaque) - User-provisioned runtime credentials
  Keys: postgresql-url, redis-url, s3-secret-access-key, inference-api-key
  Auto-Rotate: No (manual)
- {gateway-name}-credentials (Opaque) - Controller-managed cross-namespace copy
  Synced on reconcile, authorized via ReferenceGrant
- {apiserver}-tls (kubernetes.io/tls) - Optional TLS cert for API server
  Provisioned by cert-manager Certificate CR or user-provisioned
  Auto-Rotate: Yes (cert-manager) or No (manual)

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Linking: Dynamic (CGO via UBI 9 ubi-minimal with OpenSSL)
- Crypto: stdlib crypto with FIPS via OpenSSL strictfipsruntime
- TLS: Delegated to managed workloads (cert-manager or pre-provisioned)

Multi-Tenancy:
- Tenant boundary: per-CR (each LLMBatchGateway CR is independent)
- Deployment model: single operator, multi-tenant across namespaces
- No NetworkPolicy created by operator (network isolation gap)
- No ResourceQuota/LimitRange created (relies on namespace-level)
