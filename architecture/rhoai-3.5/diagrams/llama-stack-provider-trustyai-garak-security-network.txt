RBAC Summary:
- RBAC is managed externally by eval-hub service and KFP infrastructure
- Adapter reads Secrets via K8s API using pod's ServiceAccount
- No ClusterRoles or ClusterRoleBindings defined by this component

Secrets:
- model-auth (Opaque) - API keys for target, judge, attacker, evaluator, SDG,
  translation models; K8s API proxy URL and SA token.
  Provisioned by: Manual (operator). No auto-rotation.
- Data Connection / s3_secret_name (Opaque) - S3 credentials:
  AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_S3_ENDPOINT,
  AWS_S3_BUCKET, AWS_DEFAULT_REGION.
  Provisioned by: Manual (operator). No auto-rotation.

API Key Resolution Chain (7-step fallback):
1. Direct value from JobSpec
2. Named key in model-auth Secret
3. Environment variable
4. Role-based convention in model-auth Secret
5. Generic secret key in model-auth Secret
6. Generic environment variable
7. "DUMMY" (fallback for unauthenticated endpoints)
⚠ Risk: Silent fallback to "DUMMY" may mask misconfiguration

S3 Credential Resolution Chain (5-step fallback):
1. Direct K8s API Secret read
2. KFP_AUTH_TOKEN-based access
3. Sidecar proxy injection
4. model-auth Secret fields
5. kubeconfig-based access

Security Annotations:
- Config redaction (redact_api_keys) applied before any persistence to S3, OCI, Files API
- TLS verification configurable via KFP_VERIFY_SSL (defaults to True)
- Custom CA cert supported via KFP_SSL_CA_CERT and ssl_ca_cert config
- No NetworkPolicy defined; relies on namespace-level isolation
- Ephemeral pods: cleanup_scan_dir_on_exit defaults to True
- FIPS: Python interpreted, uses system OpenSSL from UBI9/AIPCC base image
