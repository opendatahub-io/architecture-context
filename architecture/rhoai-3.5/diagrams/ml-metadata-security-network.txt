RBAC Summary:
- No Kubernetes RBAC manifests in this repository
- RBAC is managed by the deploying operator (rhods-operator/opendatahub-operator)
- The MLMD server itself has NO built-in authorization
- Any client reaching port 8080 has full read/write access to all metadata

Authentication Summary:
- gRPC Server: Optional mTLS via SSLConfig.client_verify (BoringSSL)
- Default: InsecureServerCredentials (no TLS, no auth)
- Database: Username/Password authentication
- No application-level auth/authz beyond optional mTLS
- Platform-level auth (e.g., kube-rbac-proxy) may be added by operator

Secrets:
- Database credentials (Opaque) - MySQL/PostgreSQL username and password
  - Provisioned by: Platform operator / Administrator
  - Auto-Rotate: No
- SSL certificates (kubernetes.io/tls) - Optional, for gRPC server and DB connections
  - Provisioned by: cert-manager / Administrator
  - Auto-Rotate: No
- Secret names depend on deploying platform configuration

Multi-Tenancy:
- Single-tenant: One server instance per database
- No tenant isolation within the database (shared tables)
- No per-user or per-tenant authorization
- All clients have full access to entire metadata store

FIPS Compliance:
- C++ binary (not Go) - check-payload Go FIPS requirements do not apply
- TLS via BoringSSL (bundled, commit 648cbaf)
- BoringSSL provides FIPS-validated crypto when built in FIPS mode
- No explicit FIPS module build flags detected in Bazel config
- Default runs without TLS (InsecureServerCredentials)

Build Hermeticity:
- Build: Non-hermetic (hermetic: false in Tekton PipelineRun)
- Bazel pins deps by SHA256 in WORKSPACE file
- No RPM lock files, no Hermeto/cachi2 prefetch
- Dependencies fetched from internet during build
