RBAC Summary:
- No Kubernetes RBAC roles or bindings
- ServiceAccounts created (no bound roles):
  - batch-gateway-apiserver
  - batch-gateway-processor
  - batch-gateway-gc
- All authorization delegated to Kuadrant/Authorino at gateway layer

Authentication & Authorization:
- External API endpoints: Delegated to Kuadrant/Authorino via Gateway API AuthPolicy
- Tenant isolation: X-MaaS-Username header → application middleware
  - Cross-tenant requests return HTTP 404 (not 403 — prevents enumeration)
  - DB queries scoped by TenantID in all BaseQuery filters
  - File storage: SHA256-hashed tenant folder partitioning
- Inference endpoints: API key (Bearer) or mTLS client cert per model
- Observability endpoints: Unauthenticated (separate port)

Secrets:
- global.secretName (Opaque, projected)
  - redis-url: Redis/Valkey connection string
  - postgresql-url: PostgreSQL connection string
  - inference-api-key: Default API key for inference gateway
  - s3-secret-access-key: S3 storage credentials
  - Provisioned: Manual / external secret operator
  - Rotation: Manual (no auto-rotate)
- apiserver TLS secret (kubernetes.io/tls)
  - TLS cert/key for HTTPS API server
  - Provisioned: cert-manager or manual
  - Rotation: Depends on provisioner
- Per-model API key files (Opaque)
  - Individual API keys for per-model inference auth
  - Provisioned: Manual
  - Rotation: Manual
- Per-model TLS client certs (kubernetes.io/tls)
  - mTLS client certs for inference gateway
  - Provisioned: Manual / cert-manager
  - Rotation: Depends on provisioner

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1 (all 3 Konflux Dockerfiles)
- Runtime: UBI 9 base image (ubi-minimal) provides OpenSSL for FIPS-compliant crypto
- TLS: MinVersion TLS 1.2 enforced; no non-FIPS crypto primitives detected
- Note: Non-Konflux Dockerfiles use CGO_ENABLED=0 (upstream dev only, not FIPS)

Multi-Tenancy Risks:
- Tenant ID from HTTP header — if gateway bypassed, tenant impersonation possible
- No database-level row security (application-enforced only)
- No per-tenant NetworkPolicy
- No per-tenant compute quotas or priority classes
- Shared inference API keys across all tenants
- Redis key space is global (no per-tenant boundary)
