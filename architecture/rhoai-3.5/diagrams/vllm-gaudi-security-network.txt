RBAC Summary:
  No RBAC defined -- this is a container image, not an operator.
  RBAC is defined by KServe and the platform operator (rhods-operator).

Secrets:
  No secrets defined by this component.
  - HF_TOKEN: Provided by KServe InferenceService CR (env var injection)
  - storage-config: Managed by KServe for model artifact storage access

Authentication & Authorization:
  - All /v1/* endpoints have NO application-level auth
  - Auth is enforced by kube-rbac-proxy sidecar (SubjectAccessReview)
  - vLLM serves plaintext HTTP on port 8000 inside the pod
  - Platform Gateway handles external TLS termination

FIPS Compliance Risks:
  - OpenSSL FIPS provider explicitly removed in Dockerfile (line 63)
    Command: rpm -e --nodeps openssl-fips-provider-so
  - Reason: Habana libraries not compatible with FIPS-mode OpenSSL
  - Impact: All Python libraries (requests, urllib3) use non-FIPS OpenSSL
  - Risk Level: Known trade-off, compliance gap for FIPS-mandated environments

Build Hermeticity:
  - hermetic: false (explicit in Tekton pipeline)
  - No lock files: No rpms.lock.yaml, no poetry.lock, no uv.lock
  - External sources at build time:
    - GitHub: vllm-project/vllm, vllm-project/vllm-gaudi
    - PyPI: Public PyPI + Habana extra index
    - RPMs: vault.habana.ai
  - Version pinning: VLLM_GAUDI_COMMIT=v0.16.0, VLLM_PROJECT_COMMIT=v0.16.0
  - Supply chain risk: Dependencies resolved from external sources at build time

Multi-Tenancy:
  - Tenant boundary: per-pod (single model per container instance)
  - No request-level tenant filtering
  - Network isolation: Pod-level NetworkPolicy (platform-managed)
  - Device isolation: Kubernetes Gaudi device plugin
