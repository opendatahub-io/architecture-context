Service Mesh Configuration:
- No explicit service mesh (Istio) sidecar injection
- TLS provided by OpenShift Service Serving Certificates (annotation-driven)
- Intra-service communication uses HMAC-SHA256 JWT tokens
- ⚠️  Operator→Registry: InsecureSkipVerify=true (bypasses TLS verification)

Secrets:
- {service}-tls (kubernetes.io/tls) - TLS cert, OpenShift service serving certs, auto-rotate
- User-provided store secrets (Opaque) - DB credentials (referenced via secretRef in CR)
- User-provided OIDC secrets (Opaque) - client_id, client_secret, discovery URL
- User-provided Git secrets (Opaque) - Git auth tokens or SSH keys

Security Gaps:
- ⚠️  InsecureSkipVerify=true in operator→registry calls (cluster-internal only)
- ⚠️  No NetworkPolicy resources created by operator (relies on namespace-level policies)
- ⚠️  No ResourceQuota or LimitRange created by operator
- ⚠️  With no auth configured (default), all features are accessible to any caller
- ⚠️  Intra-communication JWT (HMAC-SHA256): if key compromised, cross-FeatureStore access possible
- ⚠️  Python feature-server has no explicit FIPS opt-in at application level
- ⚠️  bigtable online store uses hashlib.md5 for key hashing (non-cryptographic use)
