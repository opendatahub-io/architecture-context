RBAC Summary:
- No RBAC resources defined by vLLM CPU
- vLLM is an inference service, not a Kubernetes operator
- Pod RBAC is managed by KServe service accounts
- ServiceAccount: KServe-managed (per InferenceService)

Secrets:
- HuggingFace token (Opaque) - Model download auth - User/KServe provisioned - No auto-rotate
- SSL certificates (kubernetes.io/tls) - HTTPS endpoint encryption (optional) - cert-manager - Auto-rotate via --enable-ssl-refresh

Authentication & Authorization:
- /v1/*, /v2/*, /inference/* endpoints: Bearer Token (SHA256 hashed, timing-safe comparison)
  - Enforcement: AuthenticationMiddleware (FastAPI)
  - Policy: Optional; enabled via --api-key or VLLM_API_KEY env var
- /health, /metrics, /ping, /version: Unauthenticated (health/monitoring)

FIPS Compliance Notes:
- Default hasher: blake3 (NON-FIPS) -- override with VLLM_MM_HASHER_ALGORITHM=sha256
- md5 usage: Non-security config hashing with sha256 fallback (safe_hash())
- gRPC: Linked against system OpenSSL (GRPC_PYTHON_BUILD_SYSTEM_OPENSSL=1)
- TLS: Optional via --ssl-keyfile/--ssl-certfile; cipher suites configurable
- Risk: opencv-python-headless may bundle non-FIPS OpenSSL
- FIPS production requires: VLLM_MM_HASHER_ALGORITHM=sha256, --prefix-caching-hash-algo sha256,
  FIPS-approved --ssl-ciphers, host OS OpenSSL in FIPS mode

Build Hermeticity:
- OS packages (RPM): No lock file (rpms.lock.yaml absent)
- Python deps: Version-pinned in requirements/*.txt but NO hash verification
- Rust deps: Fully locked via Cargo.lock
- Hermeto prefetch: Not present
- Build-time downloads from external indices are NOT integrity-verified

Multi-Architecture Support:
- x86_64: Intel Extension for PyTorch, AVX2/AVX512 kernels
- ppc64le: Custom build via build_vllm_ppc64le.sh, IBM DevPI wheels
- s390x: Custom build via build_vllm_s390x.sh, source compilation of numactl/TorchVision/hf-xet
