## How to Use

### Mermaid Diagrams (.mmd files)
- **In GitHub/GitLab**: Paste into markdown with ```` ```mermaid ```` code blocks
- **Render to PNG locally**:
   ```bash
   PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome mmdc -i diagram.mmd -o diagram.png -s 3
   ```
- **Online viewer**: Paste into https://mermaid.live

### ASCII Diagrams (.txt files)
- View in any text editor or terminal
- Include directly in security documentation
- Perfect for SAR (Security Architecture Review) submissions

## Diagram Descriptions

### Component Dependency Graph
Shows how 69 platform components depend on each other. Central components highlighted: rhods-operator (24 reverse deps), KServe (16 reverse deps), kube-rbac-proxy (7 reverse deps), Kueue (8 reverse deps), Model Registry (5 reverse deps). Components grouped by function: Platform Operator, Core Services, Model Serving, LLM Inference (llm-d), ML Pipeline & Training, Experiment & Evaluation, User Interface & MCP. Useful for understanding blast radius of changes and planning upgrades.

### Platform Network Topology
Complete network architecture for RHOAI 3.5 showing:
- **Ingress**: Gateway API + OpenShift Routes (5 ingress points)
- **Platform Gateway**: Centralized Envoy with ext_authz and ext_proc
- **4 namespace tiers**: operator, applications, monitoring, user namespaces
- **Service mesh**: Istio mTLS for inference pods
- **Egress**: S3, container registries, K8s API, NVIDIA NGC

**Two formats provided**:
- **Mermaid (.mmd)**: Visual diagram with color-coded trust zones. Great for presentations and architecture discussions.
- **ASCII (.txt)**: Precise text format with no ambiguity. Required for SAR (Security Architecture Review) submissions and compliance documentation.

### Cross-Component Workflows
Four sequence diagrams showing end-to-end user workflows:
1. **LLM Model Serving**: LLMInferenceService creation through Gateway API routing with llm-d EPP endpoint selection
2. **ML Pipeline Execution**: Pipeline submission through Argo Workflows DAG execution with MLMD metadata tracking
3. **Distributed Training**: TrainJob submission through Kueue admission with MLflow tracking and Model Registry registration
4. **Model Evaluation & Guardrails**: EvalHub evaluation through LMEvalJob with TrustyAI fairness monitoring and GORCH guardrails

### Platform Security Overview
Visual representation of RHOAI 3.5's defense-in-depth security architecture:
- **5 authentication layers**: Gateway ext_authz, Kuadrant AuthPolicy, kube-rbac-proxy, Istio mTLS, bearer tokens
- **FIPS 140 compliance**: Go native FIPS module across 10+ components, with one identified gap (llm-d Router EPP)
- **Container security**: UBI base images, distroless/scratch, non-root execution, Konflux hermetic builds
- **TLS configuration**: Webhook TLS, kube-rbac-proxy metrics, service-ca, Istio mTLS
- **TLS bypass patterns** (risk): 3 identified InsecureSkipVerify usages, mitigated by mesh mTLS
- **Disconnected security**: RELATED_IMAGE pattern, digest pinning, CA bundle aggregation

### Platform Observability
Maps all monitoring and observability endpoints:
- **28+ Prometheus scrape targets**: kube-rbac-proxy HTTPS metrics (8443/TCP), application HTTP metrics, service mesh metrics
- **Health probes**: Operator probes (8081), service probes (various), inference server probes
- **Alerting**: Platform health, inference performance, pipeline failures, security events
- **Monitoring stack**: Prometheus + AlertManager + Perses dashboards in redhat-ods-monitoring namespace

### Platform Maturity Dashboard
High-level metrics:
- 69 components (24 operators, 28 services, 8 SDK/CLI tools)
- 162 shipped container images from 442 Dockerfiles
- 164 CRDs across 15+ API groups
- 90 gRPC service definitions
- Full multi-architecture support (amd64, arm64, ppc64le, s390x)
- Disconnected deployment support
- OCP v4.19-v4.22 + EKS/AKS/CoreWeave via CloudManager
