Per-DSPA Roles (namespace-scoped):
- ds-pipeline-{name}: API server service account role
- pipeline-runner-{name}: Pipeline execution service account (workflows, pods, secrets, CRDs)
- ds-pipeline-persistenceagent-{name}: Persistence agent role
- ds-pipeline-scheduledworkflow-{name}: Scheduled workflow role
- ds-pipeline-workflow-controller-role-{name}: Argo controller role
- ds-pipeline-user-access-{name}: End-user access to DSPA API subresource

ClusterRoleBindings:
- ds-pipeline-ui-auth-delegator-{ns}-{name}: Binds system:auth-delegator for OAuth

Service Mesh / Network Policies:
- ds-pipelines-{name}: Restricts API server ingress
- mariadb-{name}: Restricts DB access to API server and MLMD only
- ds-pipeline-metadata-grpc-{name}: Restricts MLMD to v2_component and data-science-pipelines pods
- mlmd-envoy-dashboard-access: Allows Dashboard access to MLMD Envoy

Secrets:
- {db-credential-secret} (Opaque) - MariaDB password, auto-generated or user-provided, no auto-rotate
- {storage-credential-secret} (Opaque) - S3 AccessKey/SecretKey/host/port, auto-generated or user-provided, no auto-rotate
- ds-pipeline-metadata-grpc-tls-config-secret-{name} (Opaque) - MLMD TLS certs + DB proto, service-ca rotation
- ds-pipeline-{name}-tls (kubernetes.io/tls) - API Server pod-to-pod TLS, service-ca auto-rotation
- mariadb-{name}-tls (kubernetes.io/tls) - MariaDB pod-to-pod TLS, service-ca auto-rotation
- ds-pipeline-md-{name}-tls (kubernetes.io/tls) - MLMD Envoy pod-to-pod TLS, service-ca auto-rotation

TLS Configuration:
- Cluster TLS security profile via openshift/controller-runtime-common/pkg/tls
- SecurityProfileWatcher triggers graceful pod restart on profile change
- Pod-to-pod TLS via OpenShift service-ca (PodToPodTLS flag, default: true)
- CA bundle: odh-trusted-ca-bundle ConfigMap + user CAs + service-ca certs → dsp-trusted-ca-{name}

FIPS Compliance:
- Build: GOFIPS140=v1.0.0, -tags no_openssl, CGO_ENABLED=0 (static binary)
- Runtime: godebug fips140=on in go.mod (Go 1.26 native FIPS 140 module)
- Risk: InsecureSkipVerify=true available via user opt-in (CustomExtraParams tls=skip-verify)

Authentication:
- API Server (8443): SubjectAccessReview via kube-rbac-proxy
- MLMD Envoy (8443): SubjectAccessReview via kube-rbac-proxy
- Routes: OpenShift OAuth (reencrypt TLS) → kube-rbac-proxy
- Webhook (8443): mTLS (Kubernetes API server ↔ webhook)
- Pipeline Runner: ServiceAccount RBAC
