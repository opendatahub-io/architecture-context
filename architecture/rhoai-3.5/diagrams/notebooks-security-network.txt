PLATFORM INTEGRATION:
- ODH Notebook Controller: Mutating webhook injects kube-rbac-proxy sidecar,
  mounts CA bundles at /etc/pki/tls/custom-certs/ca-bundle.crt,
  configures Elyra runtime ConfigMap and DSPA secrets
- ODH Dashboard: Reads ImageStream annotations (opendatahub.io/*)
  to populate workbench selection UI
- rhods-operator: Deploys ImageStream manifests via kustomize

RBAC Summary:
- No ClusterRoles or Roles defined by this component
- Workbench images run as unprivileged user 1001
- Authentication/authorization delegated entirely to kube-rbac-proxy sidecar
- User must have Kubernetes RBAC access to the Notebook CR namespace

Secrets:
- No Secrets defined in this repository
- DSPA connection secrets mounted into pods by the notebook controller
- CA bundles mounted at /etc/pki/tls/custom-certs/ca-bundle.crt by controller

FIPS Compliance:
- Go mongocli binary: CGO_ENABLED=1, -tags strictfipsruntime (dynamic linking)
- Python crypto: cryptography 46.0.7, pycryptodome 3.23.0 from RHEL AI PyPI
  (FIPS-validated builds)
- TLS: Not configured in images (kube-rbac-proxy handles TLS termination)
- OpenSSL: compat-openssl11 installed; base image provides system OpenSSL
- Certificate handling: System trust store from RHEL base image

Multi-Tenancy:
- Tenant boundary: per-namespace (one workbench pod per Notebook CR)
- Deployment model: single-tenant (each workbench is single-user)
- Network isolation: Depends on platform NetworkPolicy (none in this repo)
- Data isolation: Per-namespace PVC, no file-level access control within workbench
- Risk: If kube-rbac-proxy sidecar is bypassed (e.g., direct pod port-forward),
  workbench is unauthenticated
