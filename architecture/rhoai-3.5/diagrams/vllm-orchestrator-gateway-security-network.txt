RBAC Summary:
  No RBAC definitions — this is a standalone service, not a Kubernetes operator.
  No ClusterRoles, Roles, or RoleBindings defined in this component.

Authentication & Authorization:
  - Endpoint: /{route_name}/v1/chat/completions (POST)
  - Auth mechanism: Passthrough (forwards Authorization header to orchestrator)
  - Enforcement point: NONE at gateway layer
  - Policy: No authentication or authorization enforced by the gateway
  - Expected enforcement: External platform (kube-rbac-proxy, Gateway API, Istio)
  ⚠ RISK: Gateway does not validate tokens — a misconfigured platform could
    expose unguardrailed access to the orchestrator

Secrets:
  - /etc/tls/private/tls.crt (kubernetes.io/tls) — Client cert for mTLS
    Provisioned by: cert-manager or service-serving-cert-signer
    Auto-Rotate: Unknown
  - /etc/tls/private/tls.key (kubernetes.io/tls) — Private key for mTLS
    Provisioned by: cert-manager or service-serving-cert-signer
    Auto-Rotate: Unknown
  - /etc/tls/ca/service-ca.crt (Opaque) — CA cert for orchestrator TLS validation
    Provisioned by: service-ca-operator
    Auto-Rotate: Unknown

TLS Configuration:
  - Crypto library: openssl crate 0.10.73 (binds to system libssl)
  - TLS backend: native-tls 0.2.12 (delegates to OpenSSL on Linux)
  - Client identity: PEM certs converted to PKCS#12 via openssl crate
  - Custom CA: Added from /etc/tls/ca/service-ca.crt
  - OpenSSL in image: openssl-libs from UBI9 repos (dynamic linking)
  ⚠ RISK: danger_accept_invalid_hostnames(true) when host == "localhost"

Network Policies:
  No NetworkPolicy resources defined in this component.
  Network isolation must be provided by the deploying platform.

Multi-Tenancy:
  - Single-tenant deployment model (one gateway per deployment)
