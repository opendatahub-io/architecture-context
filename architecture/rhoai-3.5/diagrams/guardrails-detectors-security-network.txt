INGRESS:
  - No direct external ingress. Detectors are internal services accessed
    only by the FMS Guardrails Orchestrator within the cluster.
  - Ingress is managed by KServe and the RHOAI platform operator.

RBAC Summary:
  - No RBAC manifests in repository
  - RBAC is managed by KServe and the platform operator for
    InferenceService deployments

Service Mesh Configuration:
  - Istio sidecar injection: sidecar.istio.io/inject: "true"
    (annotation on InferenceService pods)
  - mTLS mode: STRICT (via Istio service mesh)
  - Authentication: Delegated to KServe auth annotations
    (security.opendatahub.io/enable-auth: "true")

Secrets:
  - aws-connection-* (Opaque) - S3/MinIO credentials
    (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY)
    Provisioned by: User via RHOAI dashboard data connection
    Auto-Rotate: No

TLS Configuration:
  - Application-level: Optional TLS via ssl.CERT_REQUIRED when
    ssl_ca_certs config key is set in server config
  - Production: Plaintext HTTP; TLS terminated by Istio sidecar
  - Crypto: stdlib ssl module only; no third-party crypto libraries
  - FIPS: Delegates to UBI RHEL 9.6 OpenSSL (via AIPCC base image)

Multi-Tenancy:
  - Tenant boundary: per-namespace (via KServe InferenceService)
  - Each InferenceService is a separate detector instance
  - No cross-tenant API access; detectors are stateless
  - No NetworkPolicy manifests in repo; relies on platform-level
    network isolation
