RBAC Summary:
- kube-rbac-proxy does NOT define its own ClusterRoles or RoleBindings
- Uses the ServiceAccount of the pod it runs in (injected by rhods-operator)
- Required SA permissions:
  - API Group: authentication.k8s.io
    Resource: tokenreviews
    Verbs: create
  - API Group: authorization.k8s.io
    Resource: subjectaccessreviews
    Verbs: create

Auth Caching:
- TokenReview cache: 2 minutes TTL (per user identity)
- SAR allow cache: 5 minutes TTL (per user + resource)
- SAR deny cache: 30 seconds TTL (per user + resource)

Secrets:
- TLS serving cert/key (kubernetes.io/tls) - HTTPS listener, cert-manager, hot-reload 1m
- Upstream client cert/key (kubernetes.io/tls) - mTLS to upstream, platform operator, no auto-rotate
- Client CA cert (Opaque) - X.509 client auth, platform operator, dynamic reload (DynamicFileCAContent)
- OIDC CA cert (Opaque) - OIDC issuer TLS, platform operator, dynamic reload (DynamicFileCAContent)

Security Controls:
- --ignore-paths: WARNING - bypasses ALL auth for matching paths
- --allow-paths: Only matched paths are proxied; others get 404
- Token sanitization: Bearer tokens masked in all klog output
- HTTP/2: Always enabled with ALPN (h2, http/1.1)
- FIPS: Built with GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, dynamic linking to OpenSSL
