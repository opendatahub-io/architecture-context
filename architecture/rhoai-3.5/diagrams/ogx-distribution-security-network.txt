RBAC Summary:
- No RBAC manifests in this repository
- RBAC is managed by the platform operator (rhods-operator)
- kube-rbac-proxy sidecar enforces authentication at the pod level

Secret Management:
- 18 provider secret environment variables with _FILE variant support
  (avoids exposure via /proc/1/environ)
- POSTGRES_PASSWORD / POSTGRES_PASSWORD_FILE for database auth
- Secrets provisioned via manual config or Kubernetes Secret mounts

Authentication Architecture:
- Transport security: TLS terminated at Gateway API / kube-rbac-proxy level
- Application auth: OAuth2 JWT validation (conditional, AUTH_ISSUER env var)
  - When AUTH_ISSUER is SET: validates JWT tokens via JWKS endpoint
    - Configurable: AUTH_JWKS_URI, AUTH_AUDIENCE, AUTH_VERIFY_TLS, AUTH_TLS_CAFILE
  - When AUTH_ISSUER is UNSET: no authentication (--insecure flag always passed)
- Access policy (when auth enabled):
  - Unowned resources (system models): readable by all authenticated users
  - Created resources: scoped to creator (owner-based access control)
  - Owners can read, update, delete their own resources

Multi-Tenancy Notes:
- Single instance, multi-tenant via OAuth2 JWT subject
- All tenants share same PostgreSQL database (no schema-level isolation)
- All tenants share same provider credentials (no per-user API keys)
- Isolation enforced at application level only (owner-based filtering)

FIPS Compliance:
- Inherits FIPS-validated OpenSSL from AIPCC CPU base image (RHEL 9.6 UBI)
- Python ssl module backed by system OpenSSL
- No non-FIPS crypto detected in this repo's code
- SHA-256 used for artifact checksum verification (FIPS-approved)

Build Hermeticity:
- Python deps: uv pip compile with hashes (requirements-lock-konflux.txt)
- ML artifacts: SHA-256 checksums (artifacts.lock.yaml) via Hermeto generic cache
- Hermeto (cachi2) prefetch for hermetic Konflux builds
- RPM hermeticity: inherited from AIPCC base image (no rpms.lock.yaml)
