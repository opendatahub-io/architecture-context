## Purpose

**Short**: A reverse proxy sidecar that orchestrates disaggregated prefill/decode (P/D) inference by routing requests between prefill workers and a co-located vLLM decoder.

**Detailed**: The llm-d-routing-sidecar is a lightweight HTTP/HTTPS reverse proxy designed to run as a sidecar container alongside a vLLM decoder server in a Kubernetes pod. It implements the disaggregated prefill/decode pattern used in llm-d's inference architecture, where the computationally expensive "prefill" phase of LLM inference is offloaded to a remote worker, and only the "decode" phase runs on the local GPU.

When a request arrives with an `x-prefiller-host-port` header, the sidecar intercepts it, forwards the prompt to the specified prefill worker (with `max_tokens=1` and KV transfer parameters), collects the prefilled KV cache metadata from the response, then constructs a decode request containing those KV transfer parameters and forwards it to the local vLLM decoder. Requests without the prefiller header are passed through directly to the decoder. The sidecar supports three connector protocols: NIXL v2 (default, active), NIXL v1 (deprecated), and LMCache (deprecated).

The sidecar includes an optional SSRF protection feature that watches an InferencePool custom resource (from the Gateway API Inference Extension) via the Kubernetes API. When enabled, it maintains a dynamic allowlist of pod IPs/hostnames from the InferencePool's selector, rejecting prefill requests targeting hosts not in the pool. This prevents request forgery attacks where a malicious client could redirect prefill traffic to arbitrary endpoints.

> **Note**: This repository is deprecated. The code has been moved to the [llm-d-inference-scheduler repository](https://github.com/llm-d/llm-d-inference-scheduler) under `cmd/pd_sidecar` and `pkg/sidecar`.

## Architectural Analysis

The llm-d-routing-sidecar implements a focused sidecar pattern optimized for the disaggregated prefill/decode inference architecture. Its design reflects several deliberate trade-offs worth noting.

**Proxy architecture and caching**: The sidecar creates `httputil.NewSingleHostReverseProxy` instances for each unique prefiller endpoint and caches them in a 16-entry LRU cache (`internal/proxy/proxy.go:114`). This means the sidecar can efficiently handle requests directed at up to 16 concurrent prefiller endpoints without recreating proxy objects. The decoder proxy is created once at startup since it always points to localhost. Each TLS-enabled proxy connection independently configures cipher suites and `InsecureSkipVerify`, which is correct but creates three near-identical TLS config blocks (server, decoder client, prefiller client) that could diverge.

**Protocol connector abstraction**: The three connector protocols (NIXL v1, NIXL v2, LMCache) are cleanly abstracted through the `protocolRunner` function type (`internal/proxy/proxy.go:94`). Each connector follows the same pattern -- read body, parse JSON, modify fields, forward to prefiller, process response, forward to decoder -- but they differ in which JSON fields they manipulate. NIXL v2 uses a nested `kv_transfer_params` object, NIXL v1 uses flat top-level fields (`remote_block_ids`, `remote_engine_id`, `remote_host`, `remote_port`), and LMCache simply truncates tokens. The v1 and LMCache connectors are deprecated per code comments and README.

**SSRF protection design**: The AllowlistValidator (`internal/proxy/allowlist.go`) uses Kubernetes dynamic client with shared informers rather than controller-runtime, keeping the dependency footprint minimal. It watches a single named InferencePool via field selector, then creates per-pool pod informers scoped to the pool's label selector. The allowlist tracks hosts only (not ports) -- `normalizeHostPort()` strips the port component -- which means any port on an allowed host is permitted. This is documented as intentional but reduces the granularity of the protection. The allowlist is rebuilt from scratch on every pod event (`rebuildAllowlist()`), which is simple but could cause brief windows of stale data under high pod churn.

**Deprecation status**: The README prominently declares this repository deprecated, with code moved to `llm-d-inference-scheduler` under `cmd/pd_sidecar` and `pkg/sidecar`. No Konflux Dockerfile exists, suggesting RHOAI product builds source from the successor repository. The deployment manifests use `envsubst` variable substitution rather than standard kustomize variable references, and the StatefulSet references `serviceAccountName: operator-controller-manager` -- a service account presumably created by the llm-d operator rather than by this repository's manifests. These are typical patterns for a component that is deployed as part of a larger system rather than standalone.

**Security considerations**: The sidecar defaults to TLS-enabled (`-secure-proxy=true`) with a self-signed certificate fallback, which provides encryption in transit but without certificate verification by default. The explicit cipher suite configuration (`internal/proxy/proxy.go:195-200`) restricts to AEAD ciphers (AES-GCM, ChaCha20-Poly1305) which are all FIPS-approved. However, the build uses `CGO_ENABLED=0` producing a statically linked binary with pure-Go crypto, which would fail Konflux's check-payload FIPS validation. The RBAC manifest for SSRF protection grants `pods` list/watch and `inferencepools` list/watch -- appropriately minimal for the allowlist use case.
