## Purpose

**Short**: A lightweight GPU-free simulator that mimics vLLM's HTTP and gRPC inference API surface for testing routing, scheduling, and infrastructure without real model serving.

**Detailed**: llm-d-inference-sim is a configurable simulator designed as a drop-in replacement for vLLM inference servers. It exposes the full OpenAI-compatible REST API (chat completions, text completions, responses, messages, embeddings, tokenization, model listing) and the vLLM-native gRPC protocol on a single multiplexed port using cmux. The simulator models realistic inference behavior including time-to-first-token latency, inter-token decode delays, load-proportional latency scaling, and disaggregated prefill/decode KV-cache transfer simulation.

The component supports two response generation modes: echo (loopback of input) and random (probabilistic histogram-based generation with optional real dataset backing via SQLite). It simulates LoRA adapter lifecycle management (load/unload), publishes KV-cache block allocation and eviction events over ZMQ for EPP/router integration testing, and exposes a subset of vLLM's Prometheus metrics. An optional vLLM render sidecar container provides real HuggingFace tokenization; without it, a fast regex-based tokenizer is used. A companion Python ZMQ listener utility (separate container image) subscribes to the KV-cache event stream for debugging. A dataset-tool CLI generates SQLite conversation corpora from HuggingFace datasets.

## Architectural Analysis

The simulator is architected around a clean engine abstraction (`pkg/engine`) that decouples protocol handling from simulation logic. The vLLM engine is the primary backend; an experimental SGLang engine is also registered. Each engine binds its own HTTP routes and gRPC service on top of a shared communication layer (`pkg/communication`), and defines its own error framing format. The communication layer uses cmux to multiplex HTTP/1.1 and HTTP/2 (gRPC) traffic on a single TCP port, avoiding the need for separate listeners.

Request processing follows a pipeline: the communication layer parses and validates inbound requests, passes them to the simulator core (`pkg/simulator`) which manages a worker queue with configurable concurrency, applies latency simulation, generates tokens through the response engine, and returns results via Go channels. Streaming responses are handled through server-sent events (SSE) with pipe-based body streaming on the HTTP side and gRPC server streaming on the protobuf side.

TLS is optional and configurable: the server supports file-based certificates with automatic hot-reload via fsnotify, or self-signed certificate generation. When TLS is enabled, the cipher suite is explicitly restricted to AEAD ciphers with ECDHE key exchange, and the minimum version is set to TLS 1.2.

The KV-cache subsystem (`pkg/kvcache`) maintains an in-memory block cache that tracks simulated GPU memory allocation. Block store/remove/clear events are serialized as msgpack-encoded tagged unions and published over ZMQ PUB sockets, matching the wire format expected by the llm-d-router's EPP. This integration is the primary consumer of the `llm-d-router` Go library dependency, specifically the `kvevents` package for event type definitions.

The codebase is statically linked (`CGO_ENABLED=0`) and ships on a distroless base image, which is favorable for minimal attack surface but means no OpenSSL is present in the runtime image. No Konflux Dockerfiles exist in this checkout, indicating that Konflux-specific build hardening is handled downstream or has not yet been added.
