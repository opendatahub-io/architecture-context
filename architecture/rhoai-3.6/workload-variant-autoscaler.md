## Purpose

**Short**: A Kubernetes controller that performs intelligent autoscaling of LLM inference model servers based on saturation metrics (KV cache utilization, queue depth) collected from Prometheus.

**Detailed**: The Workload-Variant-Autoscaler (WVA) is a controller-runtime-based Kubernetes controller designed to autoscale LLM inference workloads managed by the llm-d inference platform. It watches HorizontalPodAutoscalers, InferencePools (from the Gateway API Inference Extension), and optionally KEDA ScaledObjects to discover model-server deployments, then runs a continuous optimization loop that queries Prometheus for real-time inference metrics — principally KV cache utilization and request queue depth — and adjusts replica counts based on configurable saturation thresholds.

The controller supports two scaling approaches: a V2 token/capacity-based saturation analyzer (default since v0.9.0) and a legacy V1 percentage-based analyzer. It also includes a scale-from-zero engine for cold-start scenarios and an experimental Coordinator component for GPU rebalancing across multiple models sharing a cluster. Configuration is driven by Kubernetes ConfigMaps (a manager config and a per-model saturation-scaling config), with a unified config system that merges CLI flags, environment variables, config files, and ConfigMap values using Viper. On the upstream `main` branch the WVA controller is deprecated in favor of pure KEDA-based autoscaling; however, the RHOAI 3.6 release branch carries the full controller under the `legacy/` directory.

## Architectural Analysis

WVA follows a classic controller-runtime operator pattern but with an unusual twist: the primary scaling logic lives outside reconcilers, in leader-elected `RunnableFunc` goroutines (the saturation engine and scale-from-zero engine) that run optimization loops on a configurable interval (default 15 s on Kubernetes, 60 s on OpenShift). The four reconcilers (ConfigMap, HPA, InferencePool, ScaledObject) are strictly discovery and configuration plumbing — they feed the in-memory `Datastore` that the engines read.

A notable design choice is the conditional CRD registration: LeaderWorkerSet and KEDA ScaledObject support is detected at startup via discovery API probes, and the controller auto-restarts (exits with code 1) when an optional CRD appears after boot. This avoids requiring all optional CRDs to be pre-installed but introduces an intentional restart cycle that operators should expect.

The Prometheus integration is central and tightly validated: the controller fail-fast exits if it cannot reach Prometheus at startup. TLS is configurable with mutual auth, CA bundles, and server name verification. On OpenShift, the deployment overlay automatically points WVA at the in-cluster Thanos Querier and mounts the Service CA for certificate verification.

The GPU limiter subsystem supports two modes — physical-inventory (listing Nodes with GPU labels) and operator-declared quota — each governed by the `limiters:` key in the saturation-scaling ConfigMap. An experimental priority-weighted rescale feature redistributes GPU budget across models under contention.
