## Purpose

**Short**: Kubernetes operator that declaratively deploys, manages, and verifies MCP (Model Context Protocol) servers on OpenShift, handling their full lifecycle with production-grade automation and gateway integration.

**Detailed**: The mcp-lifecycle-operator implements the Kubernetes-native lifecycle for MCP servers — the emerging standard for exposing AI model capabilities as discoverable, interoperable tool endpoints. Users declare an `MCPServer` custom resource specifying a container image, transport, and network configuration; the operator reconciles this into a running Deployment, ClusterIP Service, NetworkPolicy, and optional Gateway API HTTPRoute, then performs an MCP protocol handshake to verify the server is responding correctly before publishing its address.

The operator supports two API versions (v1alpha1 and v1beta1) with a conversion webhook for seamless migration. A pluggable gateway provider architecture supports both direct HTTPRoute-based exposure and Kuadrant-based registration (via MCPServerRegistration and MCPGatewayExtension CRDs). Admission webhooks enforce platform policies including image allowlists, digest-only references, storage mount limits, and required labels. The operator can propagate TLS settings (minimum version, cipher suites, and TLS 1.3 named groups including the post-quantum X25519MLKEM768 hybrid) to managed MCP server containers.

This is a Kubernetes SIG upstream project (`kubernetes-sigs/mcp-lifecycle-operator`) forked into the Red Hat downstream chain (`opendatahub-io` → `red-hat-data-services`) for inclusion in RHOAI. The downstream Konflux build adds FIPS-compliant compilation (`GOEXPERIMENT=strictfipsruntime`, CGO_ENABLED=1) and the DEFAULT:PQ system crypto policy for post-quantum readiness.

## Architectural Analysis

The mcp-lifecycle-operator follows a controller-runtime reconciliation pattern with three distinct reconciliation loops. The primary `MCPServerReconciler` owns the full operand lifecycle: it creates and maintains a Deployment, Service, and NetworkPolicy for each MCPServer CR, then performs an MCP protocol handshake (using `modelcontextprotocol/go-sdk`) to verify endpoint health before surfacing a `Verified` condition and publishing the server address in status. This handshake verification is generation-aware — it only re-runs when the MCPServer spec changes or when a TLS CA bundle rotates (tracked via SHA-256 hash).

Gateway integration uses a provider registry pattern where providers self-register via Go `init()` imports. Two providers ship: an `httproute` provider that creates Gateway API HTTPRoute resources directly, and a `kuadrant` provider that creates MCPServerRegistration and MCPGatewayExtension resources for integration with Kuadrant's API management stack. Both are triggered by MCPGatewayBinding resources that the MCPServerReconciler creates as owned child resources when gateway exposure is configured.

The NetworkPolicy design is architecturally notable: the operator supports an `--network-policy-default-posture` flag with `open` and `restricted` modes. In restricted mode, the operator automatically injects ingress peers for its own controller pods (so verification handshakes can reach the operand) and for any configured gateway source. The ODH overlay further patches the base NetworkPolicy to pin metrics scraping to OpenShift monitoring namespaces and adds allow-all egress as a stopgap until upstream least-privilege egress lands.

TLS handling is layered: the operator reads `TLS_MIN_VERSION`, `TLS_CIPHER_SUITES`, and `TLS_GROUPS` from environment variables, validates them against the Go stdlib cipher/group registry, and applies them as a profile to both its own webhook/metrics servers and (optionally via `PROPAGATE_TLS_ENV_VARS`) to managed MCP server containers. The TLS group support includes X25519MLKEM768 for post-quantum hybrid key exchange. HTTP/2 is disabled by default to mitigate the Stream Cancellation and Rapid Reset CVEs.
