## Purpose

**Short**: Deprecated monolithic Helm chart and quickstart installer for deploying the llm-d distributed LLM inference framework on Kubernetes and OpenShift.

**Detailed**: llm-d-deployer is a Helm-based deployment package that orchestrates the installation of the entire llm-d ecosystem -- a Kubernetes-native high-performance distributed LLM inference framework built on vLLM with prefill/decode disaggregation. The chart bundles the ModelService CRD (from llm-d-model-service), configures the endpoint picker (EPP) for intelligent request routing, deploys vLLM inference pods with NixL and LMCache KV-cache transfer connectors, provisions a Gateway API ingress layer (supporting Istio, kgateway, and GKE L7), and optionally installs Redis for KV-cache lookup coordination and Prometheus/Grafana for metrics collection.

As of July 2025, this repository is **deprecated** in favor of [`llm-d-infra`](https://github.com/llm-d-incubation/llm-d-infra), which provides a more modular Helmfile-based composition approach. The charts are no longer updated, and users are encouraged to migrate. The repo contents remain available for legacy monolithic installs. This deprecation is architecturally significant: it signals that RHOAI's llm-d deployment model is shifting from a single umbrella chart to composable per-component Helm charts orchestrated via Helmfile.

## Architectural Analysis

llm-d-deployer follows a controller-and-preset pattern: a central ModelService controller watches `ModelService` CRs and reconciles them into Kubernetes-native workloads (Deployments, Services, InferencePools, InferenceModels, HTTPRoutes). Rather than encoding all configuration in the CR, presets are stored as ConfigMaps that provide deployment templates for prefill, decode, and EPP components. The CR then selects a preset and overrides specific fields. This is an opinionated abstraction over the Kubernetes Gateway API Inference Extension (GAIE) primitives.

The chart architecture is layered: (1) infrastructure dependencies installed via `ci-deps.sh` (Gateway API CRDs, GAIE CRDs, and a gateway provider), (2) the ModelService controller and RBAC, (3) preset ConfigMaps with deployment templates, and (4) a sample application that instantiates a ModelService CR with an HTTRoute. The quickstart installer (`llmd-installer.sh`) wraps Helm with environment validation, namespace creation, HF token provisioning, optional model download jobs, and conditional Prometheus/Grafana installation.

The prefill/decode disaggregation is the core architectural pattern: prefill pods run vLLM with NixL connectors for KV-cache transfer, decode pods run behind a routing proxy sidecar that bridges port 8000 (external) to vLLM on port 8001 while providing NixL v2 connectivity. Redis serves as a centralized lookup store for LMCache, enabling KV-cache-aware request routing by the endpoint picker. The EPP runs as a gRPC external processor for Envoy (ports 9002/9003), implementing configurable scoring strategies (prefix-aware, load-aware, KV-cache-aware, session-aware) with tunable weights.

Gateway support is abstracted through the Kubernetes Gateway API, but with provider-specific handling for Istio (ClusterIP service type annotation, inference extproc label), kgateway (GatewayParameters with proxy UID for OpenShift SCC), and GKE L7 (GCPBackendPolicy, HealthCheckPolicy). This multi-gateway support adds deployment complexity but enables the chart to work across cloud providers and on-premises OpenShift.
