## Purpose

**Short**: AI Grid Network (AGN) is a distributed control plane that connects AI inference backends across Kubernetes clusters, cloud providers, and third-party APIs into a single routable mesh for the Praxis AI gateway.

**Detailed**: The AGN Operator is an orchestration daemon — not a proxy — that manages multi-site AI inference routing. It watches Kubernetes custom resources (GridNetwork, GridSite, InferenceProvider, AgentToolProvider), discovers peer sites via the SWIM gossip protocol (using the `foca` library), propagates provider state through delta CRDTs (LWW registers, OR-Sets, G-Counters), scores inference candidates using configurable strategies (noMetrics, queueDepth, kvCachePressure), and writes a versioned routing overlay ConfigMap that the Praxis AI gateway hot-reloads without restarts.

The operator establishes trust between sites through mTLS certificates with a per-grid CA, supports both certificate-pinning and SPIFFE-based peer trust modes, and encrypts all SWIM gossip traffic with AES-256-GCM. The architecture cleanly separates the control plane (AGN: what should be routable) from the data plane (Praxis: routing and proxying actual requests). The operator never sits in the request path; all routing decisions use a pre-computed local overlay file. An optional enrollment service handles automated site onboarding with certificate issuance and rotation, and an overlay-sync sidecar watches ConfigMaps via the Kubernetes API for validated delivery to the gateway.

## Architectural Analysis

The Grid operator's architecture reflects a peer-to-peer mesh design where each site runs an independent operator instance that converges state through gossip rather than a centralized control plane. This is a deliberate choice: a single-cluster operator would be a single point of failure for the entire mesh, while the gossip-based approach degrades gracefully when individual sites disconnect.

The SWIM membership protocol (`foca` crate) handles peer discovery and failure detection, while delta CRDTs ensure eventually consistent state propagation without coordination. Each operator instance maintains its own scoring engine, so routing decisions survive network partitions — a site continues serving its local providers even when disconnected from the mesh. The operator writes a content-addressed routing overlay ConfigMap that Praxis hot-reloads, meaning the data plane never blocks on control plane availability.

The dual TLS backend design (rustls+ring for default, OpenSSL for FIPS) is enforced at compile time with mutually exclusive Cargo features, preventing accidental mixed configurations. The `certs` crate abstracts certificate generation behind a provider trait, with `rcgen` for non-FIPS and `openssl` for FIPS paths. The `unsafe_code = "forbid"` workspace lint eliminates memory safety risks across the entire codebase.

The Recreate deployment strategy on the operator is load-bearing: SWIM assigns one identity per site, and a rolling update would briefly gossip two identities. The revision-lease mechanism durably reserves disjoint transport-revision ranges in a ConfigMap, preventing revision conflicts across operator restarts. The enrollment service uses a separate binary with its own TLS stack and PostgreSQL backing store (via `sqlx`), isolating the onboarding lifecycle from the operator's runtime reconciliation loops.
