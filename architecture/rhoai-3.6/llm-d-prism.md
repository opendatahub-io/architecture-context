## Purpose

**Short**: Interactive performance analysis dashboard for distributed LLM inference systems that unifies benchmark data from cloud APIs, repositories, and local experiments into a single analysis experience.

**Detailed**: Prism is a full-stack web application built on a Backend-for-Frontend (BFF) architecture using React 19 (Vite) on the frontend and Node.js/Express on the backend. It helps AI platform engineers and ML engineers choose, configure, and optimize AI inference infrastructure by aggregating benchmark data from disparate sources—Google Cloud Storage (GCS), AWS S3, Google Infrastructure Quality (GIQ) APIs, Google Drive/Sheets, and local uploads—into interactive dashboards with scatter charts, comparison views, and regression analysis.

The application includes a "Results Store" subsystem for submitting, reviewing, promoting, and managing benchmark results with GitHub OAuth-based authentication and role-based authorization (admin/user/none). It supports multiple specialized dashboards: a main benchmark browser, regression analysis, prefix cache offloading analysis, prefill/decode (P/D) disaggregation analysis, agentic workloads, and a workload catalog. Prism is primarily deployed to Google Cloud Run but can run on any container platform.

## Architectural Analysis

Prism follows a clean BFF pattern where the Express backend serves three roles: (1) static asset hosting for the production React build, (2) API proxying to Google Cloud services with server-side credential injection via Application Default Credentials (ADC), and (3) a lightweight data-management layer (the Results Store) backed entirely by GCS object storage with custom metadata contexts rather than a traditional database.

The authentication model is noteworthy: GitHub OAuth tokens are used to identify users, while authorization combines GitHub organization membership in `llm-d` with GCS-hosted allowlist files (`prism-iam/github-admin-allowlist.txt`). A "Playground Mode" bypasses all auth checks, giving anonymous users admin access—useful for demos but a significant security consideration in production.

The repository has an unusual language profile: although `go.mod` and `cmd/main.go` exist, the Go code is a skeleton placeholder (`"TODO: implement your service here"`). The actual application is entirely JavaScript/TypeScript (Node.js + React). A single Python script (`tools/update_arena_scores.py`) scrapes LMSYS Arena leaderboard data for model quality scores. The Makefile includes Go tooling targets that gracefully skip when no substantive Go code is found.

Data flows are predominantly outbound from the backend to Google Cloud APIs (GCS, GIQ). The server caches regression data with a 5-minute TTL and processes benchmark report YAML files (v0.2 format from llm-d-benchmark) into normalized metrics including throughput, latency percentiles (TTFT, TPOT, ITL, nTPOT), and hardware metadata. Rate limiting is configured at 50,000 requests per minute per IP—effectively unlimited and intended only for local development.
