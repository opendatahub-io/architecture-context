## Purpose

**Short**: KServe is the Kubernetes-native model serving platform that manages the lifecycle of inference services, LLM inference deployments, serving runtimes, and local model caching on OpenShift AI.

**Detailed**: KServe provides a comprehensive model serving control plane built on controller-runtime. It defines and reconciles a rich set of custom resources — InferenceService (v1beta1), LLMInferenceService (v1alpha1/v1alpha2), ServingRuntime, InferenceGraph, LocalModelCache, and KernelCache — to orchestrate model deployment, traffic routing, autoscaling, and storage across Kubernetes clusters. The platform supports diverse ML frameworks (TensorFlow, PyTorch, vLLM, OVMS, MLServer, HuggingFace, SGLang) through a pluggable ClusterServingRuntime abstraction.

The RHOAI distribution extends the upstream KServe project with OpenShift-specific functionality through a build-tag isolation pattern (`distro` / `!distro`). ODH-specific behavior — including OpenShift Route management, Gateway API integration via HTTPRoute, TLS profile resolution from the cluster APIServer, kube-rbac-proxy sidecar injection, and NVIDIA NIM account management — lives in companion `*_odh.go` files that compile only when the `distro` build tag is set. This pattern preserves upstream compatibility while enabling deep OpenShift integration.

The repository produces eight distinct Konflux container images (controller, llmisvc-controller, kserve-module-controller, localmodel-controller, localmodelnode-agent, router, agent, and storage-initializer), plus an autogluon model server built from an AIPCC base image. A Python SDK and model server framework (`kserve` package) provides the serving runtime for Python-based model servers (HuggingFace, sklearn, XGBoost, LightGBM, etc.).

## Architectural Analysis

KServe's architecture is organized around a separation of concerns across multiple controller binaries, each responsible for a distinct domain within the model serving lifecycle. The **manager** binary runs the core InferenceService and InferenceGraph reconcilers along with admission webhooks; the **llmisvc** controller handles the newer LLM-focused inference services with support for LeaderWorkerSets, Gateway API inference extensions (InferencePool, InferenceModel), and KEDA-based autoscaling; the **localmodel** controller manages model pre-caching onto cluster nodes via PersistentVolumes and download Jobs; and the **kserve-module** controller acts as a meta-operator that installs and configures the other components, managing CRDs, webhooks, RBAC, serving runtimes, and monitoring resources.

A notable architectural pattern is the distro build-tag system. Rather than forking upstream files, OpenShift-specific behavior is injected through hook functions: upstream code calls a hook, a `_default.go` implementation no-ops, and a `_odh.go` implementation provides the real behavior. This spans networking (OpenShift Routes, Gateway API HTTPRoute reconciliation), security (TLS profile resolution from `config.openshift.io/v1/APIServer`, cert-manager integration, self-signed TLS for workloads), and platform integration (ODH platform detection, HardwareProfile CRD awareness, NIM account management).

The TLS subsystem deserves special attention. On OpenShift, the distro resolver reads the cluster-wide TLS security profile from `apiservers.config.openshift.io/cluster` with retry logic and graceful fallback to Intermediate defaults (TLS 1.2, ECDHE AEAD ciphers). A `ProfileWatcher` controller watches the APIServer resource for changes and dynamically updates TLS configuration. The non-distro path accepts explicit `--tls-min-version` and `--tls-cipher-suites` flags. All paths default to TLS 1.2 minimum with ALPN `h2` and `http/1.1`.

The router binary provides an inference graph request routing layer, implementing traffic splitting, switching, ensembling, and sequential pipeline patterns. It validates bearer tokens against the Kubernetes TokenReview API for authenticated request routing.

The storage-initializer is a Python-based init container that downloads model artifacts from S3, GCS, Azure Blob Storage, HDFS, OCI registries, and Hugging Face Hub before the model server starts. It supports Kerberos authentication for HDFS and confidential container decryption.

## Multi-Tenancy

### Tenant Model

| Aspect | Value | Source |
|--------|-------|--------|
| **Tenant boundary** | per-namespace | CRD scope: all core CRDs (InferenceService, LLMInferenceService, ServingRuntime, LocalModelCache) are Namespaced |
| **Deployment model** | multi-tenant (single controller serves all namespaces) | cmd/manager/main.go, cmd/llmisvc/main.go |
| **Tenant identifier** | namespace name | Inferred from CRD scope and namespace-scoped watches |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Per-tenant RBAC via namespace-scoped Roles; kube-rbac-proxy for metrics; Kubernetes admission for webhooks | Kubernetes / kube-rbac-proxy | Python model servers have no built-in auth middleware — authentication relies on external enforcement (Istio sidecar, kube-rbac-proxy, or NetworkPolicy) |
| Data storage | Per-namespace PVCs for local model cache; model artifacts referenced by per-namespace storage credentials | Kubernetes | LocalModelCache uses shared PersistentVolumes across namespaces (cluster-scoped PV, namespace-scoped PVC); node-level model data is shared |
| Network traffic | NetworkPolicy created per LLMInferenceService namespace by llmisvc controller | Kubernetes / Controller | NetworkPolicy creation is conditional on ODH mode; not all ingress patterns enforce per-namespace isolation |
| Compute & resources | Resource requests/limits set on serving runtime containers; node affinity via LocalModelNodeGroup | Kubernetes | No automatic ResourceQuota or LimitRange enforcement per tenant namespace |
| Configuration & secrets | Per-namespace Secrets for model storage credentials; per-namespace ServingRuntime and LLMInferenceServiceConfig | Kubernetes | ClusterServingRuntime and ClusterStorageContainer are cluster-scoped shared resources; configuration changes affect all tenants |
| API scoping | Controllers use namespace-scoped watches via owner references; InferenceService and LLMInferenceService are namespace-scoped | Kubernetes | Controllers have cluster-wide list permissions for some resources (nodes, ClusterServingRuntimes) |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| KServe controllers | All namespaces | Kubernetes RBAC; namespace-scoped CRDs; owner-reference-based event filtering |
| ClusterServingRuntimes | All namespaces | Cluster-scoped templates; no per-tenant override except namespace-scoped ServingRuntime |
| LocalModelCache node storage | Per-node | PersistentVolumes are cluster-scoped; tenants sharing a node share model cache storage |
