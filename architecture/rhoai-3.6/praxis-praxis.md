## Purpose

**Short**: Praxis is a Rust-based framework and runtime for building cloud-native and AI-native proxy servers, built on Cloudflare's Pingora library with a composable filter pipeline architecture.

**Detailed**: Praxis is a high-performance, security-first proxy server designed for ingress, egress, east/west, and AI inference gateway deployments. It implements a filter-first architecture where every behavior — routing, load balancing, rate limiting, body inspection, and security enforcement — is implemented as a composable filter using shared `HttpFilter` and `TcpFilter` traits. Filters are assembled into named chains and concatenated into per-listener pipelines at configuration time.

The proxy delegates HTTP/TCP framing, connection pooling, and protocol compliance to a forked build of Cloudflare's Pingora library (`quixotic-plecostomus-*`), while Praxis owns the filter pipeline execution, routing decisions, observability, and security hardening. All TLS cryptography goes through the system OpenSSL via a `rustls-openssl` provider — a deliberate architectural choice that makes the FIPS 140-3 build's compliance boundary the host's validated OpenSSL module on Red Hat Enterprise Linux.

Praxis supports dynamic configuration hot-reload (swapping filter pipelines atomically via `ArcSwap` without disrupting in-flight requests), an admin API with health/metrics endpoints, and an extensive set of built-in HTTP and TCP filters spanning observability, security, traffic management, payload processing, and transformation categories. AI-specific features (inference gateway, guardrails) are developed in a separate `praxis-proxy/ai` repository.

## Architectural Analysis

Praxis's architecture centers on three key design decisions that shape its codebase and deployment model:

**Filter-pipeline composition over monolithic behavior.** The crate dependency flow (`server → protocol → filter → core → tls`) cleanly separates concerns: `core` owns config parsing and validation, `filter` owns the filter trait definitions and pipeline executor, `protocol` adapts Pingora's HTTP/TCP callbacks into pipeline invocations, and `server` is the binary entry point. This layering enables lean builds — the FIPS build omits the policy engine via cargo features (`--no-default-features --features config-reload,admin-api`), and experimental capabilities like SPIFFE mTLS, upstream binding, and syslog access logs are individually gatable. The workspace enforces extreme lint strictness (no `unsafe_code`, no `unwrap`, no unchecked arithmetic, no `as` casts) with `#[expect(lint, reason = "...")]` as the only escape hatch.

**Single cryptographic provider, no fallback.** Every TLS operation routes through `rustls` configured with exactly one provider: `rustls-openssl`, which delegates all cryptographic primitives to the system `libcrypto.so`. The Pingora fork's `custom-provider` feature removes rustls's implicit fallback, so an uninstalled provider causes a loud failure rather than a silent downgrade. This is installed once during server bootstrap (`crates/tls/src/provider.rs`) before any listener or upstream connector is constructed. The FIPS build adds `cargo-auditable` embedding and an `xtask fips report` compliance verifier, and the `PRAXIS_REQUIRE_FIPS` environment variable enforces fail-closed behavior at startup when both the kernel flag and OpenSSL provider FIPS status aren't present.

**Zero-downtime configuration reload.** Each handler holds an `Arc<ArcSwap<FilterPipeline>>`; a `notify`-based file watcher with 500ms debounce rebuilds and atomically swaps pipelines on config change while in-flight requests drain on the old pipeline. Listener topology, protocol types, and TLS on/off state cannot be changed dynamically — only filter pipelines, routing rules, and filter configurations. This is a deliberate constraint: protocol handlers execute only the filter type they were started with.

The project uses jemalloc as the global allocator on Unix for reduced contention under concurrent load, maintains ≥96% line coverage with 6 dedicated test suites (unit, schema, integration, conformance, security, resilience), and enforces security via reserved header prefixes (`x-praxis-*`, `x-ext-protocol-*`, `x-ext-agent-*`) that are unspoofable from clients.

_The FIPS build (`make container-fips`) produces a separate image on UBI 9 with Red Hat's rust-toolset. It disables the `policy-engine` feature to exclude non-FIPS cryptography (sha2, hmac, jsonwebtoken/aws-lc-rs). The standard build includes all features by default. `PRAXIS_REQUIRE_FIPS=1` enforces fail-closed at startup: the binary checks both the kernel FIPS flag (`/proc/sys/crypto/fips_enabled`) and the OpenSSL provider's FIPS status, and refuses to start if either is missing. Red Hat's check-payload scanner (`make fips-scan`) validates the FIPS image._
