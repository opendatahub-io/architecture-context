## Purpose

**Short**: Maintains a registry of additional RHOAI container images that are not referenced in component manifests, ensuring they are included in disconnected/air-gapped deployment image lists.

**Detailed**: rhoai-additional-images is a metadata-only repository that serves a critical role in RHOAI's disconnected deployment story. OpenShift clusters in air-gapped environments must pre-mirror all required container images into a local registry before installation. While most RHOAI images are discoverable through component manifests and the operator's ClusterServiceVersion, some images — particularly N-1 and deprecated notebook workbench images, training runtime variants, and pipeline runtime images — are not directly referenced in any deployment manifest but must still be available on the cluster for user workloads.

This repository maintains a single YAML file (`rhoai-disconnected-images.yaml`) that lists these "orphan" images by their digest-pinned references. The list is consumed by the RHOAI disconnected deployment tooling to ensure complete image mirroring. Images are organized by category (training runtimes, notebook workbenches, pipeline runtimes) and by version generation (current N-1, deprecated N-x), with JIRA references linking each group to its inclusion rationale.

## Architectural Analysis

This repository is architecturally minimal — it contains no source code, no Dockerfiles, no deployable workloads, and no Kubernetes manifests. Its value is entirely as a structured inventory of container image references that fall outside the normal manifest-driven discovery path.

The design choice to maintain a separate repository for these image references (rather than embedding them in the operator or installer manifests) reflects a deliberate decoupling: the images listed here belong to other components (notebooks, training runtimes, pipelines, Ray) but need to be tracked centrally for disconnected mirroring. This avoids polluting component manifests with references to deprecated or N-1 versions that are no longer actively deployed but must remain available for existing user workloads.

All images are digest-pinned (`@sha256:...`), which provides cryptographic integrity guarantees and ensures that disconnected mirrors receive exactly the validated image, not a potentially different image at the same tag. The image references span two registries: `quay.io/modh` for upstream/community builds (Ray, fms-hf-tuning) and `registry.redhat.io/rhoai` for productized Red Hat images.

The versioning pattern in the YAML reveals the notebook image lifecycle: current release images are in component manifests, N-1 images are tracked here as "additional," and N-x (two or more releases old) images are tracked here as "deprecated." This three-tier lifecycle management ensures graceful deprecation while maintaining availability for existing notebook sessions.
