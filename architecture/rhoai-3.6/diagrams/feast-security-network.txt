Authentication & Authorization:
- Feature server: Configurable per-CR (exactly one of: Kubernetes RBAC, OIDC, NoAuth)
  - CEL validation enforces single selection
  - Kubernetes: operator creates Roles/RoleBindings in feature store namespace
  - OIDC: reads credentials from referenced Secret, JWT validation via PyJWT
- Go feature server: No built-in auth middleware (relies on network controls)
- Operator /metrics: TokenReview + SubjectAccessReview
- Operator /healthz, /readyz: Unauthenticated (health probes)

FIPS Compliance:
- Operator: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime, ubi9/ubi-minimal-pqc base
- Feature server (Python): cryptography>=43.0, FIPS via system OpenSSL on RHEL 9.8
- Go feature server: TLS 1.2 minimum, post-quantum key exchange (X25519MLKEM768)
- Risk: InsecureSkipVerify=true in operator registry client for cluster-internal certs
- Risk: hashlib.md5 used for Bigtable row key distribution (not security-critical)

Multi-Tenancy:
- Tenant boundary: per-namespace (FeatureStore CR is Namespaced)
- Operator: cluster-wide singleton, manages all FeatureStore CRs
- Isolation: per-namespace services, RBAC, secrets; no NetworkPolicy enforcement by operator
- Gap: NoAuth option can be selected; Go feature server has no auth middleware
