Secrets:
- TLS server cert/key (kubernetes.io/tls) — Server TLS for guardrails API (port 8033)
  Provisioned by: Platform operator / cert-manager
- TLS client CA cert (Opaque) — Client CA certificate for mTLS verification
  Provisioned by: Platform operator
- API tokens (Opaque, env var) — Bearer tokens forwarded to downstream detector/OpenAI services
  Provisioned by: Platform operator
- Downstream TLS certs (Opaque) — Client certificates for mTLS to downstream services
  Provisioned by: Platform operator

RBAC Summary:
- No RBAC roles defined — orchestrator is a user-space application service

Authentication & Authorization:
- /api/v1/*, /api/v2/*: Header passthrough only — no authN/authZ enforcement
- X-Forwarded-Access-Token rewrite to Authorization Bearer (when enabled)
- TLS/mTLS: Optional, via rustls with ring (NOT FIPS-validated)
- /health, /info: Unauthenticated, plaintext HTTP

FIPS Compliance:
- TLS Provider: rustls with ring crypto provider — NOT FIPS-validated
- OpenSSL: Present in build image for protobuf-src, NOT used for runtime TLS
- Risk: ring is hardcoded across rustls, hyper-rustls, tokio-rustls, tonic
- NoVerifier: Disables all certificate verification when insecure: true

Build Hermeticity:
- RPM deps: Locked (rpms.lock.yaml)
- Cargo deps: Locked (Cargo.lock)
- Hermeto/cachi2 prefetch: Not configured — Cargo fetches from crates.io during build
