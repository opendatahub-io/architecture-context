Secrets Summary:
- model-auth (K8s Secret, volume mount at /mnt/model-auth, optional=True)
  - API_KEY: Generic fallback for all model roles
  - TARGET_API_KEY: Target model API key
  - JUDGE_API_KEY: Judge model API key (intents mode)
  - ATTACKER_API_KEY: Attacker model API key (intents mode)
  - EVALUATOR_API_KEY: Evaluator model API key (intents mode)
  - SDG_API_KEY: SDG model API key (intents mode)
  - Auto-rotate: No
- S3 Data Connection (K8s Secret, environment variables)
  - AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_S3_ENDPOINT, AWS_S3_BUCKET
  - Injected via kubernetes.use_secret_as_env in KFP steps
  - Auto-rotate: No
- KFP_AUTH_TOKEN (environment variable / SA token)
  - Auto-rotate: No
- OPENAICOMPATIBLE_API_KEY (runtime environment)
  - Garak OpenAI-compatible generator API key

Credential Resolution:
- resolve_api_key() implements 13-step resolution chain:
  1-4: Environment variables (role-specific: TARGET_API_KEY, JUDGE_API_KEY, etc.)
  5-8: KFP secret volume mounts (/mnt/model-auth/{role}-api-key)
  9-12: eval-hub SDK secret readers
  13: Generic API_KEY fallback
- API keys are redacted from config.json before persistence (S3, OCI, Files API)
- Intents model overlay forces API keys to __FROM_ENV__ to prevent leakage

S3 Credential Resolution (5 fallback strategies):
1. Direct K8s API (kubernetes client)
2. KFP auth token
3. Sidecar proxy (evalhub >= 0.4.4, AutomountServiceAccountToken=false)
4. Model auth secret
5. Local kubeconfig

TLS/Crypto Notes:
- Default TLS verification: True (httpx verify=True, KFP verify_ssl=True)
- FIPS Risk: Conditional SSL verification disable when K8s CA cert not found
  (garak_adapter.py:893-896, fallback path only)
- Crypto libraries: cryptography==50.0.1, pyjwt==2.14.0 (transitive)
- Certificate handling: System trust store (UBI base) + optional custom CA via KFP_SSL_CA_CERT
