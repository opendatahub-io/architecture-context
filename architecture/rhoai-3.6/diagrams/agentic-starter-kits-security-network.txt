RBAC Summary:
- ClusterRole: system:auth-delegator
  - API Groups: rbac.authorization.k8s.io
  - Resources: tokenreviews
  - Verbs: create
  - Condition: Created only when auth.createAuthDelegatorBinding=true
- ClusterRoleBinding: {agent}-{ns-hash}-auth-delegator
  - Binds: system:auth-delegator → {agent} ServiceAccount

Authentication Mechanisms:
- SATokenAuthMiddleware (opt-in via AUTH_ENABLED=true)
  - Validates Bearer tokens via Kubernetes TokenReview API
  - Authorizes by namespace:serviceaccount allowlist
  - Excludes /health, /api/health by default
- OpenClaw: OPENCLAW_GATEWAY_TOKEN (static token)

Secrets:
- openclaw-secrets (Opaque) - Gateway token, vLLM API key - Manual provisioning, no auto-rotate
- {agent}-secret (Opaque) - API key, PostgreSQL password, MLflow token - Helm chart, no auto-rotate
- API_KEY (env) - LLM provider auth
- GITHUB_TOKEN (env) - GitHub API access
- POSTGRES_PASSWORD (env) - PostgreSQL auth
- MLFLOW_TRACKING_TOKEN (env) - MLflow tracking auth
- K8S_REVIEWER_TOKEN (env) - Kubernetes reviewer token for auth testing
- AGENT_TOKEN (env) - Agent-to-agent auth

Security Context:
- All standard agents: runAsNonRoot=true, drop ALL capabilities, UID 1001
- Base image: UBI9 Python 3.12 (digest-pinned) - OpenSSL via UBI9 for FIPS-capable crypto
- OpenClaw: pre-built upstream image (digest-pinned, NOT rebuilt by Red Hat)

Risks:
- Auth is opt-in (AUTH_ENABLED=false by default) — unauthenticated deployments lack tenant isolation
- MLFLOW_TRACKING_INSECURE_TLS=true bypasses TLS verification (development convenience)
- No NetworkPolicy templates in Helm charts
- Milvus connection has no authentication
- PostgreSQL connection unencrypted (in-cluster)
- OpenClaw uses pre-built upstream community image (not validated by Red Hat)
