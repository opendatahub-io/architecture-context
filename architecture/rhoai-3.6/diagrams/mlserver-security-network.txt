RBAC Summary:
  MLServer does not define RBAC resources.
  RBAC is managed by the KServe controller.

Authentication & Authorization:
  - REST endpoints (8080): kube-rbac-proxy sidecar validates OAuth/SA tokens
  - gRPC endpoints (8081): kube-rbac-proxy sidecar validates OAuth/SA tokens
  - Metrics endpoint (8082): No authentication (Prometheus scraping)

Runtime Security (Application-Level):
  - PRODUCTION mode: /etc/mlserver/trusted-runtimes.json allowlist enforced
  - DEVELOPMENT mode: Any model implementation allowed (no allowlist file)
  - Custom environments (tarballs, sys.path injection): Blocked in PRODUCTION
  - Wildcard CORS / regex origins: Blocked in PRODUCTION

Secrets:
  MLServer does not directly reference Kubernetes secrets.
  Model credentials provided via KServe storage initializer or env vars.

FIPS Compliance:
  - No application-level TLS (delegated to platform)
  - SHA-256 used for file checksums (FIPS-compliant)
  - OTLP exporter uses insecure=True (no TLS to collector)
  - AIPCC base image provides FIPS-enabled OpenSSL and Python runtime

Build Security:
  - Trusted runtimes allowlist generated at build time from TRUSTED_RUNTIMES build arg
  - Wheels installed with --no-deps --require-hashes (hash-verified)
  - AIPCC base images (cpu-el9.8:3.6, cuda-12.9-el9.8:3.6)
