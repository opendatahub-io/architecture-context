SECURITY PROPERTIES:
- Code safety: #![forbid(unsafe_code)] across all PPE crates
- Adversary model: LLM treated as fully untrusted (compromised or steerable via prompt injection)
- Secret handling: zeroize on drop for all secret material (credentials, tokens, keys)
- Content provenance: HMAC-SHA256 keyed + SHA-256 unkeyed digests for audit integrity
- Plugin isolation: Capability-based filtering — plugins see only context their declared capabilities grant
- PDP restriction (OPA): http.send, net, opa.runtime builtins excluded from Rego
- Egress protection: DNS + IP-level SSRF prevention (private/link-local/CGNAT/metadata blocked)

CRYPTO INVENTORY:
- TLS: rustls 0.23 with ring 0.17 (explicit crypto provider, not process default)
- JWT signatures: aws-lc-rs 1.18 via jsonwebtoken (RS256/384/512, ES256/384, EdDSA, HS256/384/512)
- Hashing: sha2 0.11 (SHA-256 for session keys, API-key index, content provenance, PKCE)
- HMAC: hmac 0.13 (HMAC-SHA256 for audit provenance, OAuth cache-key derivation)
- Random: getrandom 0.4 (per-process HMAC secret generation)
- Certificates: webpki-roots (Mozilla CA bundle)
- FIPS status: Neither ring nor aws-lc-rs configured for FIPS mode; no FIPS claims made

RBAC Summary:
- Not applicable — PPE is a Rust library, not a Kubernetes workload
- No ClusterRoles, RoleBindings, or ServiceAccounts defined
- Authorization is handled in-process via APL policy predicates evaluated by Cedar/CEL/OPA

Secrets Management:
- Providers: env (environment variables), file (local filesystem), vault (Vault KV v2)
- Startup behavior: Fail-fast (missing secret = initialization failure)
- Refresh behavior: Last-good (failed refresh keeps previous value, no gap)
- Erasure: All secret material wrapped in zeroize::Zeroizing, erased on drop
- Plugin visibility: Secrets propagated to HTTP headers via assertions but never exposed in
  plugin views, audit logs, or effective-policy artifacts

Session State:
- In-memory fallback: Per-process only, no persistence across restarts
- Valkey/Redis: SHA-256-derived session keys, optional TLS, deadpool connection pooling
- No per-tenant Valkey ACL; isolation is application-level key derivation
