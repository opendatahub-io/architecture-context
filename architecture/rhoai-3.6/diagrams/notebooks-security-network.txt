RBAC Summary:
  No RBAC roles defined by the notebooks component.
  Runtime RBAC is managed by the workbenches-operator, which creates
  per-notebook ServiceAccounts with scoped permissions.

Authentication & Authorization:
  - JupyterLab UI/API: OAuth proxy sidecar → OpenShift OAuth
  - Code-Server UI: OAuth proxy sidecar → OpenShift OAuth
  - Enforcement: ODH Notebook Controller injects oauth-proxy container
  - Jupyter server itself does NOT configure authentication

Multi-Tenancy:
  - Tenant boundary: per-user (each user gets their own pod)
  - Deployment model: StatefulSet per notebook (created by workbenches-operator)
  - Isolation: OAuth proxy per pod, per-user PVC, namespace-scoped

Secrets (CI/Build-Time Only):
  - GITHUB_TOKEN - CI agentic reviewer (NOT in shipped images)
  - GEMINI_API_KEY - CI summarization (NOT in shipped images)
  - RENOVATE_TOKEN - Dependency update bot (NOT in shipped images)
  - PULL_SECRET - Container registry pull auth (NOT in shipped images)

FIPS Compliance:
  - Base: AIPCC UBI 9 with system OpenSSL (FIPS-compatible)
  - cryptography==50.0.1 (OpenSSL-backed, FIPS-compatible)
  - Risk: pycryptodome==3.23.0 is non-FIPS pure-Python crypto
    (bundled in datascience/codeserver variants)

Build Hermeticity:
  - OS packages: rpms.lock.yaml (rpm-lockfile-prototype)
  - Python deps: pylock.*.toml (uv), installed via --no-index --find-links /cachi2/
  - Artifacts: artifacts.lock.yaml (Hermeto/Cachi2)
  - Go deps: go.sum (go mod)
  - Base images: SHA256 digest-pinned via build-args/*.conf
