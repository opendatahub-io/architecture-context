FIPS Compliance Summary:
- Build: Dynamic linking, system OpenSSL, cargo-auditable manifest, check-payload scan
- Runtime: PRAXIS_REQUIRE_FIPS env var → refuse start unless FIPS active
- Crypto: All SHA-256/HMAC-SHA256 via OpenSSL EVP API; rustls with OpenSSL provider
- Denylisted: ring, aws_lc_rs default features disabled; policy engine excluded from FIPS
- Store: Certificate-only PostgreSQL via forked SQLx (no password-auth crypto in FIPS)

Authentication & Authorization:
- /v1/* routes: Bearer Token passthrough or credential_inject filter
- Provider routes: peer_identity_trust (SPIFFE certificate digest verification)
- Admin /healthy: No auth (localhost-only bind)
- state_owner filter: Scopes Responses API read access by authenticated owner
- callout_credentials: Captures per-user credentials for downstream callouts

Secrets:
- TLS certificates (kubernetes.io/tls) - Listener TLS termination - External provisioning
- Upstream credentials (Opaque) - Backend API keys via credential_inject - Manual/external
- PostgreSQL TLS certs (kubernetes.io/tls) - mTLS to response store DB - External provisioning

Multi-Tenancy:
- Tenant boundary: per-request (no persistent tenant concept)
- Deployment model: single-instance / multi-replica stateless proxy
- Tenant identifier: Bearer token identity / state_owner / SPIFFE peer identity
- Data isolation: Shared PostgreSQL store, application-level response ID keying
- Risk: No row-level tenant partitioning in store; relies on upstream identity enforcement

Build Hermeticity:
- Cargo.lock: Yes (hermetic Rust dependency resolution)
- rpms.lock.yaml: No (not present on upstream branch)
- OS packages: Not hermetic (apk add / dnf install at build time)
- FIPS build: UBI 9 with digest-pinned base images
