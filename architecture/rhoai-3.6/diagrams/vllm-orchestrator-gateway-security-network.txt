RBAC Summary:
- No RBAC manifests defined in this repository
- RBAC expected to be managed by deploying operator or platform
- Gateway does not authenticate or authorize callers directly

Secrets:
- TLS certificate (/etc/tls/private/tls.crt, /etc/tls/private/tls.key)
  - Type: kubernetes.io/tls (inferred)
  - Purpose: mTLS client identity for orchestrator communication
  - Provisioned by: OpenShift service-serving-cert-signer
  - Auto-rotate: Yes (OpenShift managed)

- CA certificate (/etc/tls/ca/service-ca.crt)
  - Type: ConfigMap (inferred)
  - Purpose: Custom CA for orchestrator certificate verification
  - Provisioned by: OpenShift service-ca operator
  - Auto-rotate: Yes (OpenShift managed)

TLS Architecture:
- Inbound: No TLS (plain HTTP on 8090/TCP)
  - TLS termination expected at platform ingress layer (Route/Gateway)
- Outbound: Optional mTLS to orchestrator
  - Probes /etc/tls/private/ at startup for certificate presence
  - If certs found: constructs PKCS#12 identity, enables mTLS
  - If no certs: plain HTTP to orchestrator
  - Custom CA loaded from /etc/tls/ca/service-ca.crt if present
  - Uses native-tls (system OpenSSL), NOT rustls
  - danger_accept_invalid_hostnames(true) ONLY when host=localhost (dev)

FIPS Compliance:
- Rust binary dynamically linked against system OpenSSL (openssl-libs)
- Uses native-tls crate (wraps system OpenSSL via FFI)
- No pure-Rust crypto (rustls not used)
- FIPS mode inherited from RHEL 9 base image OpenSSL configuration
- No OLM FIPS annotation (no OLM manifests)

Multi-Tenancy:
- Single-tenant deployment model
- No tenant isolation mechanisms in gateway
- All routes exposed to all callers equally
- Auth enforcement delegated to orchestrator and platform ingress

Network Policies:
- None shipped with this component
- Expected to be managed by deploying operator or platform
