  - API Groups: authentication.k8s.io
  - Resources: tokenreviews
  - Verbs: create
  - API Groups: authorization.k8s.io
  - Resources: subjectaccessreviews

  - Non-Resource URLs: /metrics
  - Verbs: get

- ClusterRoleBinding: kube-rbac-proxy
  - Namespace: default
  - Service Account: kube-rbac-proxy
  - Role: kube-rbac-proxy (ClusterRole)

Authentication Mechanisms:
- Bearer Token: Delegated to Kubernetes API via TokenReview
- Client TLS Certificate: CommonName extracted, mapped to user identity
- OIDC JWT: Validated against configured OIDC issuer

Authorization Flow:
1. Hardcoded authorizer: auto-allow prometheus-k8s for GET /metrics
2. Static authorizer: check configured static rules
3. SAR authorizer: SubjectAccessReview against configured resource attributes
   - Format1: top-level resource attributes with query/header rewrites
   - Format2: path-scoped endpoints with per-method SAR, named captures ({tenant})

Secrets:
- TLS cert/key pair (kubernetes.io/tls) - Server TLS certificate, provisioned by cert-manager or operator, auto-rotated via CertReloader

FIPS Configuration:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, -tags strictfipsruntime
- Runtime: crypto/tls routed through OpenSSL for FIPS compliance
- Base image: ubi9/ubi-minimal-pqc (post-quantum cryptography capable)
- No non-FIPS crypto risks detected (no InsecureSkipVerify, no MD5, no RC4)

Multi-Tenancy:
- Tenant boundary: per-namespace (via SAR resource attributes)
- Format2 named captures ({tenant}) enable per-path, per-method authorization
- Example: trustyai.opendatahub.io API group with URL-to-resource mapping
