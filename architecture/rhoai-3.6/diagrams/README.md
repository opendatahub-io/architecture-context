## How to Use

### Mermaid Diagrams (.mmd files)
- **In GitHub/GitLab**: Paste into markdown with ` ```mermaid ` code blocks
- **Render to PNG locally**:
   ```bash
   PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome mmdc -i diagram.mmd -o diagram.png -s 3
   ```
- **Online viewer**: Paste contents at https://mermaid.live

### ASCII Diagrams (.txt files)
- View in any text editor or terminal
- Include directly in security documentation
- Perfect for SAR (Security Architecture Review) submissions

## Diagram Descriptions

### Component Dependency Graph
Shows how RHOAI 3.6's 95 components depend on each other, organized across Core Platform Infrastructure, Gateway & Ingress Layer, Model Serving, ML Pipeline & Training, Feature Store & Experiment Tracking, User Workloads & UI, Security & Observability, and AI Services layers. Central components (rhods-operator, KServe, data-science-pipelines-operator, MaaS, odh-model-controller) are highlighted with thicker borders. Useful for understanding blast radius of changes and planning upgrades.

### Platform Network Topology
Complete network architecture showing RHOAI 3.6's 4-gateway ingress architecture (data-science-gateway, maas-default-gateway, openshift-ai-inference, inference-gateway), service mesh communication, and egress destinations. Includes exact port numbers, protocols, encryption, and authentication mechanisms for each path.

**Two formats provided**:
- **Mermaid (.mmd)**: Visual diagram with color-coded trust zones (External, Ingress, Platform Services, MaaS, Kuadrant, User Workloads, Egress). Great for presentations and architecture discussions.
- **ASCII (.txt)**: Precise text format with full gateway inventory, TLS configuration table, RBAC summary, and admission webhook details. Required for SAR (Security Architecture Review) submissions and compliance documentation.

Both formats contain the same information, just different representations.

### Cross-Component Workflows
Four sequence diagrams showing end-to-end user workflows that span multiple components:
1. **Model Deployment via Dashboard** — OAuth login, InferenceService creation, KServe reconciliation, model serving, inference request flow
2. **MaaS Multi-Tenant Model Access** — AITenant creation, per-tenant maas-api deployment, API key authentication via Authorino, praxis-extproc pre/post-auth processing, rate limiting
3. **ML Pipeline Execution** — Pipeline submission, Argo Workflow scheduling, distributed training via KubeRay, MLflow experiment tracking, model deployment
4. **Distributed LLM Inference (llm-d)** — EPP ext_proc routing, KV-cache locality-aware scheduling, disaggregated prefill/decode with NIXL RDMA

### Platform Security Overview
Visual representation of the full security architecture including:
- **Authentication**: 6 mechanisms (ext_authz, Kuadrant AuthPolicy, kube-rbac-proxy, TokenReview, bearer forwarding, Istio mTLS)
- **Gateway security**: 4 gateways with different auth models, credential stripping
- **ServiceAccounts**: 7 key accounts with RBAC bindings
- **ClusterRoles**: 5 most privileged roles (highlighted in red)
- **Secrets**: Webhook certs, storage credentials, OAuth proxy TLS, MaaS API keys
- **TLS**: Per-component TLS configuration (webhooks, metrics, gateway, internal, cluster profile)
- **Container security**: UBI 9 PQC, FIPS (Go + Rust), non-root, read-only FS, Konflux builds
- **Service mesh**: TLS profile adherence, DestinationRules, EnvoyFilters, known TLS gap (RHOAIENG-61070)
- **Webhooks**: 218 endpoints, all fail-closed, cross-component coordination risks

### Platform Observability
Maps all monitoring and observability coverage:
- **Prometheus**: 18 scrape targets with port and auth details (most via kube-rbac-proxy on 8443/TCP)
- **Health Probes**: 15 components with liveness and readiness endpoints (standard :8081 or :8080)
- **Distributed Tracing**: 4 OTLP gRPC exporters → OpenTelemetry Collector
- **Alerting**: PrometheusRule resources from rhods-operator and odh-observability
- **Webhook monitoring**: PodMonitor label injection for observability
- **Diagnostics**: must-gather for cluster diagnostics collection

### Platform Maturity Dashboard
High-level metrics for RHOAI 3.6:
- **Components**: 95 total, 18+ operators, 653 container images, 175 CRDs, 218 webhooks, 916 RBAC definitions
- **Gateway API**: Full v1 adoption, 4 gateways, 4 ingress patterns
- **Security**: FIPS compliant (Go + Rust), cluster TLS profile adherence, all webhooks fail-closed, mTLS MIXED
- **API maturity**: Active v1alpha1→v1alpha2 migrations, 8+ conversion webhooks
- **Deployment**: Leader election HA, kube-auth-proxy HPA, disconnected UNRESOLVED, multi-arch partial
- **New in 3.6**: MaaS, llm-d (16 sub-components), AI Gateway, federated dashboard, Kubeflow Trainer, MCP lifecycle
