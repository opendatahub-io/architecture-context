Authentication & Authorization:
- Backend API (/api/v1/*): Bearer token validated via TokenReview OR header-based
  identity (kubeflow-userid/kubeflow-groups headers from trusted reverse proxy)
- Every API call authorized via SubjectAccessReview against user identity
  (10-second allow/deny cache TTL)
- Multi-header protection: duplicate authorization headers are rejected
- Controller: ServiceAccount token for all Kubernetes API operations
- Webhooks: Kubernetes admission authentication

Network Policies:
- Default-deny ingress NetworkPolicy in kubeflow-workspaces namespace
- Workspace pods in user namespaces: no controller-managed NetworkPolicies

Secrets:
- webhook TLS cert (kubernetes.io/tls) — cert-manager or OpenShift service-serving-cert-signer, auto-rotate

FIPS Compliance:
- Controller: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime, -tags strictfipsruntime
- Base image: ubi9/ubi-minimal-pqc (post-quantum cryptography)
- TLS: OpenShift profile or Mozilla Intermediate (TLS 1.2+, ECDHE cipher suites)
- Backend TLS: MinVersion TLS 1.3 when cert/key provided
- No non-FIPS crypto detected (no MD5, RC4, custom RNG)
