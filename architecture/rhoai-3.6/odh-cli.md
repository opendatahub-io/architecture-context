## Purpose

**Short**: CLI tool (kubectl plugin) for interacting with, validating, diagnosing, and migrating Red Hat OpenShift AI deployments on Kubernetes.

**Detailed**: odh-cli is a Go-based command-line tool that operates as a kubectl plugin (`kubectl odh`) for managing OpenShift AI / RHOAI platform deployments. It provides a comprehensive suite of subcommands for cluster validation (`lint`), workload backup (`backup`), version-aware migration (`migrate`), platform diagnostics (`diagnose`), resource inspection (`get`, `status`, `components`), log and event tailing (`logs`, `events`), dependency management (`deps`), and an embedded Model Context Protocol server (`mcp serve`) that exposes all CLI operations as typed tool calls for AI agent integration.

The CLI is distributed as both a standalone binary (`kubectl-odh`) and a container image (`quay.io/rhoai/rhai-cli-rhel9`) that bundles `kubectl`, `oc`, and standard debugging utilities. It communicates exclusively with the Kubernetes API server using the user's kubeconfig credentials and performs RBAC pre-flight checks via SelfSubjectAccessReview before privileged operations. The tool is not deployed as a cluster workload — it runs client-side and has no in-cluster network presence, services, or RBAC manifests.

## Architectural Analysis

odh-cli follows a modular Cobra command architecture where each subcommand implements a four-phase lifecycle: AddFlags → Complete → Validate → Run. This pattern separates flag registration from runtime initialization, input validation, and business logic execution, enabling consistent error handling and structured output (table/JSON/YAML) across all commands.

The client layer is notable for its multi-interface approach: a single `defaultClient` struct aggregates dynamic, discovery, API extensions, OLM, metadata, typed Kubernetes, and controller-runtime clients, all initialized from a shared REST config with configurable QPS/burst throttling (default 50/100). This "fat client" design enables individual commands to choose the most appropriate client surface for their resource interactions without repeated configuration.

The MCP server integration (`mcp serve`) is architecturally significant — it wraps every CLI command as a typed MCP tool with schema-validated inputs and JSON output, enabling AI agents (Claude, GPT, Cursor) to programmatically invoke platform operations over stdio or SSE transports. The server also registers five diagnostic tools from the opendatahub-operator's `mcptools` package, creating a unified agent-accessible surface across CLI and operator diagnostics.

The migration framework (`pkg/migrate`) implements a registry-based action pattern with version-aware filtering and lifecycle phases (pre-upgrade, post-upgrade, pre-enablement). Migration actions span multiple RHOAI components (RayCluster, Kueue RHBOK, model serving, TrustyAI, AI Pipelines, workbenches, training, LlamaStack) and support dry-run mode for safe previewing of cluster mutations.

A potential security observation: the TrustyAI metrics migration helper configures `InsecureSkipVerify: true` for in-cluster HTTPS connections to TrustyAI routes. While documented as matching the original `curl -sk` behavior for self-signed in-cluster certificates, this bypasses certificate validation during metric backup/restore operations.
