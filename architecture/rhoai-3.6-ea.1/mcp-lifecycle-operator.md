## Purpose

**Short**: Kubernetes operator that manages the lifecycle of Model Context Protocol (MCP) servers, reconciling MCPServer custom resources into Deployments, Services, and NetworkPolicies. [source: cmd/main.go:188-202, internal/controller/mcpserver_controller.go:653-673]

**Detailed**: The mcp-lifecycle-operator is a controller-runtime-based Kubernetes operator that implements the MCPServer custom resource (mcp.x-k8s.io/v1alpha1). When users create or update MCPServer resources, the operator's MCPServerReconciler creates and manages corresponding Deployments, Services, and NetworkPolicies to run MCP server workloads. The operator watches ConfigMaps and Secrets referenced by MCPServer specs, computing configuration hashes to trigger rolling updates when referenced configuration changes. It uses the upstream MCP Go SDK (github.com/modelcontextprotocol/go-sdk) for protocol interactions. The operator supports TLS configuration propagation to managed MCP server containers via the PROPAGATE_TLS_ENV_VARS environment variable, enabling platform-level TLS policy to be inherited by workloads. [source: cmd/main.go:188-198, cmd/tlsconfig.go:17-76, internal/controller/mcpserver_controller.go:44-58, 653-673]

## Architectural Analysis

The mcp-lifecycle-operator follows the standard Kubernetes operator pattern built on controller-runtime v0.24.1. A single MCPServerReconciler controller watches MCPServer custom resources (the primary "For" resource) and owns Deployments, Services, and NetworkPolicies as child resources. The reconciler also sets up secondary watches on ConfigMaps and Secrets with field indexes, allowing it to detect when referenced configuration changes and trigger Deployment rolling updates via config hash annotations. [source: internal/controller/mcpserver_controller.go:653-673, internal/controller/mcpserver_controller_deployment.go:38-74]

The operator's security model uses controller-runtime's built-in metrics authentication filter (`filters.WithAuthenticationAndAuthorization`) when secure metrics mode is enabled, protecting the :8443/metrics endpoint with TokenReview and SubjectAccessReview checks. TLS certificates for the metrics server can be provided externally or are auto-generated as self-signed certificates by controller-runtime. The operator also supports configurable TLS minimum version and cipher suites via environment variables (`TLS_MIN_VERSION`, `TLS_CIPHER_SUITES`), with validated settings optionally propagated to managed MCP server containers when `PROPAGATE_TLS_ENV_VARS=true`. [source: cmd/main.go:133-162, 194-198, cmd/tlsconfig.go:30-93]

Leader election uses the `bed7462b.x-k8s.io` identity with Lease-based coordination, supported by a dedicated leader-election Role scoped to the operator's namespace. RBAC aggregation ClusterRoles (admin, editor, viewer) integrate MCPServer permissions into Kubernetes' built-in role hierarchy. The operator has no internal platform dependencies on other RHOAI components—it operates as a standalone controller managing the MCPServer lifecycle. [source: cmd/main.go:170, config/rbac/mcpserver_admin_role.yaml:11, go.mod:1-18]

The reconciliation loop begins when a user creates or modifies an MCPServer CR. The controller watches for MCPServer changes (primary), plus ConfigMap and Secret changes (secondary watches with field indexes). On each reconciliation, the controller reads referenced ConfigMaps and Secrets to compute a config hash, then creates or updates the target Deployment, Service, and NetworkPolicy. ConfigMap or Secret changes trigger re-reconciliation of all MCPServer resources that reference them, ensuring rolling updates propagate configuration changes.
