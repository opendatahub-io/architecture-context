**Detailed**: odh-gitops is the deployment packaging layer for Red Hat OpenShift AI (RHOAI). It contains two primary Helm charts — `rhai-on-xks-chart` for non-OLM installation on external Kubernetes services (Azure AKS, CoreWeave, AWS EKS) and `rhai-on-openshift-chart` for OpenShift-native deployments with OLM-managed operator dependencies. The repository also provides Kustomize overlays that declare operator subscriptions (cert-manager, kueue, cluster-observability, opentelemetry, leader-worker-set, job-set, tempo, custom-metrics-autoscaler, rhcl-operator) and their post-install configurations. The XKS chart bundles dependency sub-charts for sail-operator (Istio), rhcl-operator, lws-operator, gateway-api, and cert-manager-operator, enabling self-contained non-OLM deployment. Gateway TLS, Authorino-based authorization, and certificate lifecycle management are configurable through the chart values. ## Architectural Analysis

odh-gitops implements a two-track deployment model: a Kustomize-based path for OpenShift clusters with OLM, and a Helm chart path for non-OpenShift Kubernetes services. The Kustomize path (`kustomization.yaml` → `dependencies/` + `configurations/`) declares OLM `Subscription` resources for each operator dependency and provides post-install configuration overlays. The Helm path packages the RHAI operator deployment, cloud-specific managers (Azure, CoreWeave, AWS), and dependency sub-charts (sail-operator, rhcl-operator, lws-operator, gateway-api, cert-manager-operator) into self-contained charts that do not require OLM.

The XKS chart (`rhai-on-xks-chart` v3.5.0) manages the RHAI operator, KServe inference gateway, and optional AIGateway/Models-as-a-Service module. It supports per-cloud configuration with dedicated `azure`, `coreweave`, and `aws` value blocks, each providing a cloud manager operator and a cloud-specific KubernetesEngine CR. Gateway TLS is enabled by default with a platform-managed internal CA (`rhai-ca-issuer` ClusterIssuer via cert-manager), and Authorino provides cluster-wide authorization enforcement with TLS-enabled listener endpoints. The chart uses Helm hooks for post-install CR creation (KServe, Gateway resources, certificates) to sequence resource creation after operator readiness.

The OpenShift chart (`rhai-on-openshift-chart` v3.4.0) targets environments where OLM handles operator lifecycle and focuses on dependency configuration and component wiring rather than operator deployment. The Kustomize configurations layer applies operator-specific post-install tuning — for example, the `rhcl-operator/tls-enabled` overlay deploys an Authorino CR with TLS-enabled listeners and cert-manager integration.

Key architectural decisions include: (1) separating operator subscription declarations from post-install configurations to allow independent overlay composition, (2) bundling dependency operators as Helm sub-charts for non-OLM environments rather than requiring external operator installation, and (3) defaulting to secure-by-default gateway configuration (`allowedRoutes.namespaces.from: Same`) with explicit opt-in for cross-namespace route attachment. ## Data Flows

odh-gitops is a configuration repository and does not implement runtime data flows directly. It declares deployment manifests that configure data flows in the deployed platform:

- **Inference flow**: Client → Istio Gateway (TLS) → KServe Inference Service → Model Runtime. The XKS chart configures the Gateway resource, TLS certificates via cert-manager, and namespace-scoped route attachment policies. [source: charts/rhai-on-xks-chart/values.yaml:80-100]
- **MaaS flow**: Client → MaaS Gateway (TLS) → AIGateway → ExternalModel/LLMInferenceService. The MaaS gateway operates in a dedicated namespace with configurable cross-namespace route attachment. [source: charts/rhai-on-xks-chart/values.yaml:102-137]
- **Authorization flow**: Service request → Authorino (TLS listener, port not specified in config) → Policy evaluation. Authorino operates cluster-wide with cert-manager provisioned server certificates. [source: configurations/rhcl-operator/tls-enabled/authorino-tls.yaml:1-17]
