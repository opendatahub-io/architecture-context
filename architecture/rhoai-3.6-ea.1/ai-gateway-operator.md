## Purpose

**Short**: Kubernetes operator that reconciles AIGateway custom resources to provision and manage AI inference gateway infrastructure, including Gateway API routing, multi-tenant Model-as-a-Service (MaaS), and batch inference gateways on the RHOAI platform. [source: config/crd/bases/components.platform.opendatahub.io_aigateways.yaml:2, cmd/operator/operator.go:124, internal/controller/aigateway/aigateway.go:147]

**Detailed**: ai-gateway-operator is a standalone controller-runtime operator that manages the AIGateway component lifecycle within the Red Hat OpenShift AI platform. It watches a cluster-scoped `AIGateway` custom resource (`components.platform.opendatahub.io/v1alpha1`) and reconciles the desired state by deploying and managing Gateway API HTTPRoutes, KServe InferenceService integrations, cert-manager TLS certificates, Kuadrant auth and rate-limiting policies, Istio networking resources, and OpenTelemetry collectors. The operator supports a multi-tenant Model-as-a-Service model through the `maas.opendatahub.io` API group, managing tenants, subscriptions, auth policies, and external model references. It also manages llm-d batch gateways as a sub-component when `spec.batchGateway.managementState` is set to `Managed`. The operator reads platform initialization state from `DSCInitialization` CRs and uses packages from the opendatahub-operator runtime library. It is built with `GOEXPERIMENT=strictfipsruntime` and `CGO_ENABLED=1` for FIPS-compliant dynamic linking. [source: cmd/main.go:30, cmd/operator/operator.go:69-153, config/rbac/role.yaml:2, Containerfile.konflux:4,33]

## Architectural Analysis

ai-gateway-operator follows a standard controller-runtime single-reconciler pattern with a Cobra CLI entrypoint delegating to the `operator` subcommand. The operator constructs a controller-runtime manager configured with leader election, health probes on port 8081, and a metrics server patched to bind on port 8443 via the `ODH_MODULE_OPERATOR_METRICS_BIND_ADDRESS` environment variable. All configuration flows through a Viper-based loader (`pkg/config`) that merges ConfigMap files, environment variables with the `ODH_MODULE_OPERATOR_` prefix, and built-in defaults, giving platform operators full runtime parameterization without image rebuilds. [source: cmd/operator/operator.go:69-153, pkg/config/config.go:33-59, config/default/manager_metrics_patch.yaml:1]

The operator's RBAC footprint is notably broad (57 rules in the manager role), spanning core Kubernetes resources, Gateway API, cert-manager, Kuadrant auth/rate-limiting, Istio networking, MaaS-specific CRDs (`maas.opendatahub.io`), llm-d batch gateways, KServe serving runtimes, and OpenTelemetry collectors. This breadth reflects its role as an infrastructure orchestrator: it does not serve inference traffic directly but provisions the complete networking, security, and observability stack that surrounds AI inference endpoints. The operator creates owned sub-resources (Deployments, Services, ConfigMaps, RBAC, Webhooks, CRDs) and manages their lifecycle through controller watches with ownership references. [source: config/rbac/role.yaml:2, internal/controller/aigateway/aigateway.go:147]

The build pipeline uses `GOEXPERIMENT=strictfipsruntime` with `CGO_ENABLED=1` on a UBI9 Go toolset base image, producing a dynamically linked binary that delegates cryptographic operations to OpenSSL for FIPS compliance. The final runtime image is `ubi9/ubi-minimal`, and the operator runs as non-root (UID 65532). Manifests for sub-components (batchgateway, maascontroller) are embedded in the container image at `/manifests/` and rendered during reconciliation using kustomize through the opendatahub-operator library. [source: Containerfile.konflux:1-44, cmd/operator/operator.go:129-134]

## Data Flows

- **Control plane entry:** The operator watches the cluster-scoped `AIGateway` CR as its primary reconciliation trigger. Platform state is read from `DSCInitialization` CRs and `KServe InferenceService` resources. All Kubernetes API interactions use the in-cluster ServiceAccount token with TLS 1.2+ to the kube-apiserver. [source: cmd/operator/operator.go:124, config/rbac/role.yaml:2]
- **Reconciliation outputs:** On each reconciliation cycle, the operator creates and manages owned sub-resources including Deployments, Services, ConfigMaps, ServiceAccounts, RBAC roles/bindings, HTTPRoutes, ValidatingWebhookConfigurations, and CRDs. cert-manager Certificate CRs are created for TLS provisioning. Kuadrant AuthPolicies and RateLimitPolicies enforce authentication and traffic shaping on Gateway API routes. [source: config/rbac/role.yaml:2, internal/controller/aigateway/aigateway.go:147]
- **Observability surface:** Prometheus metrics are served on port 8443 (HTTPS) via the controller-runtime metrics server with TokenReview/SubjectAccessReview authentication. The operator manages ServiceMonitors, PodMonitors, PrometheusRules, OpenTelemetry collectors, and Perses dashboards as owned resources. Health and readiness probes are unauthenticated on port 8081.
