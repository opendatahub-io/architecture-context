## Purpose

**Short**: MLServer is a Python-based model serving runtime implementing the KServe V2 Inference Protocol, providing both REST (FastAPI/Uvicorn on port 8080) and gRPC (port 8081) inference endpoints with pluggable ML framework backends. [source: mlserver/rest/server.py:72-73, mlserver/grpc/server.py:88-89, mlserver/settings.py:429-436]

**Detailed**: MLServer implements the KServe V2 Inference Protocol as a Python serving runtime built on FastAPI and gRPC. It exposes a dual-protocol API surface: REST endpoints on port 8080 via Uvicorn and gRPC services on port 8081 via the gRPC AsyncIO server. The server supports pluggable ML framework runtimes including Scikit-Learn, XGBoost, LightGBM, ONNX, MLflow, HuggingFace, CatBoost, Alibi Detect, Alibi Explain, and Spark MLlib, each distributed as a separate Python package. MLServer is designed to run as the model serving container within KServe InferenceService pods in the RHOAI platform, where authentication is platform-delegated to a kube-rbac-proxy sidecar. A dedicated Prometheus metrics endpoint runs on port 8082. The Konflux build uses an AIPCC base image (`quay.io/aipcc/base-images/cpu:3.6.0-ea.1`) and enforces a trusted runtimes allowlist (`/etc/mlserver/trusted-runtimes.json`) for production security. [source: mlserver/rest/app.py:60-181, mlserver/grpc/server.py:75-89, mlserver/settings.py:341-454, Dockerfile.konflux:1-66]

## Architectural Analysis

MLServer follows a dual-protocol serving architecture implementing the KServe V2 Inference Protocol. The REST surface is built on FastAPI with custom route handling and serves the V2 dataplane API—inference, model management, health checks, and repository operations—on port 8080 via Uvicorn. The gRPC surface registers two services (GRPCInferenceService and ModelRepositoryService) on port 8081 using insecure transport (`add_insecure_port` at `mlserver/grpc/server.py:88`). Both protocols share a common DataPlane handler layer that delegates to pluggable ML framework runtimes. [source: mlserver/rest/app.py:52-181, mlserver/grpc/server.py:75-92, mlserver/rest/server.py:64-73]

The runtime plugin architecture allows model-specific backends (SKLearn, XGBoost, LightGBM, ONNX, MLflow, HuggingFace, CatBoost, Alibi Detect, Alibi Explain, MLlib) to be installed as separate Python packages. A trusted runtimes allowlist mechanism (`/etc/mlserver/trusted-runtimes.json`) enforces production security by restricting which runtime implementations can be loaded. When the file is absent, development mode permits any valid runtime import path; when present, only allowlisted implementations are accepted. [source: mlserver/settings.py:42, 63-74, 140-166, Dockerfile.konflux:44-61]

MLServer itself provides no authentication or TLS termination. In the RHOAI platform, it operates as the inference container within KServe InferenceService pods, where authentication is enforced by a kube-rbac-proxy sidecar using OpenShift OAuth/ServiceAccount token validation. The gRPC server explicitly uses `add_insecure_port`, confirming that TLS is expected to be terminated externally by the platform's ingress chain or sidecar proxy. [source: mlserver/grpc/server.py:88]

Observability is integrated through OpenTelemetry instrumentation for both FastAPI and gRPC (with health check endpoint exclusions), Prometheus metrics via starlette-exporter and py-grpc-prometheus interceptors, and a dedicated metrics server on port 8082. [source: mlserver/rest/app.py:192-236, mlserver/grpc/server.py:53-73, mlserver/grpc/interceptors.py:46-54, mlserver/settings.py:444-454]

## Data Flows

- **Inference request flow:** Inference requests enter MLServer on port 8080 (REST/HTTP via FastAPI/Uvicorn) or port 8081 (gRPC via gRPC AsyncIO server). In the RHOAI platform, requests first pass through the KServe ingress chain and kube-rbac-proxy sidecar for authentication before reaching MLServer. Both protocol surfaces delegate to a shared DataPlane handler layer, which routes to the appropriate pluggable ML runtime based on model configuration. [source: mlserver/rest/app.py:60-162, mlserver/grpc/server.py:75-89, mlserver/rest/endpoints.py:93-113]
- **Streaming inference:** REST streaming inference endpoints (`/v2/models/{model_name}/infer_stream`, `/v2/models/{model_name}/generate_stream`) return Server-Sent Events (SSE) via `StreamingResponse`. The gRPC `ModelStreamInfer` RPC provides equivalent streaming via bidirectional gRPC streams. [source: mlserver/rest/endpoints.py:115-137, mlserver/rest/app.py:92-113]
- **Model repository operations:** The V2 model repository API (`/v2/repository/index`, `/v2/repository/models/{model_name}/load|unload`) allows dynamic model loading and unloading at runtime. Models are loaded from the directory specified by `MLSERVER_MODELS_DIR` (default `/mnt/models`). [source: mlserver/rest/app.py:164-181, mlserver/rest/endpoints.py:153-167, Dockerfile.konflux:14]
- **Observability:** Prometheus metrics are exported on port 8082 via starlette-exporter (REST) and py-grpc-prometheus (gRPC). OpenTelemetry traces are exported to configured collectors via gRPC when `tracing_server` is set, with health check endpoints excluded from tracing. [source: mlserver/rest/app.py:192-236, mlserver/grpc/server.py:53-73, mlserver/settings.py:444-454]
- **Security context:** 16 gRPC authentication rules and 1 REST API authentication rule use platform-delegated kube-rbac-proxy sidecar enforcement. MLServer itself has no application-level authentication middleware. [source: mlserver/rest/app.py:52-238, mlserver/grpc/server.py:33-92]
