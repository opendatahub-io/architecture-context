## Purpose

**Short**: Kubernetes operator that reconciles the Trainer component CR to deploy and manage Kubeflow Trainer v2 (TrainJobs, TrainingRuntimes, ClusterTrainingRuntimes) on OpenShift AI, using the odh-platform-utilities reconciliation framework. [source: cmd/main.go:68, 91, api/v1alpha1/trainer_types.go:20, go.mod:7]

**Detailed**: trainer-operator is a controller-runtime-based Kubernetes operator that watches the `Trainer` custom resource (components.platform.opendatahub.io/v1alpha1) and reconciles the deployment of Kubeflow Trainer v2 resources into a target namespace. It renders manifests from bundled templates for trainer components, training runtimes, and OpenShift image streams, then applies them using the odh-platform-utilities framework's deploy action with field ownership and apply ordering. The operator gates reconciliation behind dependency checks — on OpenShift clusters, it verifies that the JobSet Operator is installed, its CR exists, and the operator is healthy before proceeding. It scopes its informer cache to the applications namespace (when `APPLICATIONS_NAMESPACE` is set) and uses label selectors to limit cached objects to trainer-managed resources, hardening against OOMKill from unrelated objects. The operator exposes plaintext HTTP metrics on port 8080 (SecureServing explicitly disabled) and health/readiness probes on port 8081. [source: cmd/main.go:68-196, internal/controller/trainer_controller.go:180-198, 231-269, Dockerfile.konflux:27-28]

## Architectural Analysis

trainer-operator follows the ODH platform operator pattern: a single controller watches a cluster-scoped component CR (`Trainer`) and reconciles a set of downstream Kubernetes resources into a target namespace. The operator uses the `odh-platform-utilities/framework` reconciliation library, which provides a composable action pipeline — `checkDependencies`, `ensureNamespace`, `updateReleases`, `renderManifests`, and the framework's deploy and deployments actions — executed sequentially during each reconciliation cycle. [source: internal/controller/trainer_controller.go:180-198]

The operator manages three categories of bundled manifests: trainer infrastructure (from `/opt/manifests-template/`), Kubeflow training runtimes (`/opt/runtimes-template/`), and OpenShift image streams (`/opt/imagestreams-template/`). These are copied into the container image at build time from the repository's `manifests/` directories. The deploy action applies resources with field ownership (`trainer-module-controller`) and apply ordering, enabling the framework's garbage collection to remove stale resources from previous versions. [source: cmd/main.go:137-164, Dockerfile.konflux:27-28, internal/controller/trainer_controller.go:193-196]

A notable design decision is the dependency-gating pattern on OpenShift: before reconciling, the operator verifies that the JobSet Operator CRD is installed (`operator.openshift.io/jobsetoperators`), that a JobSetOperator CR exists, and that the operator reports healthy status. On vanilla Kubernetes, only the JobSet CRD availability is checked. This makes the JobSet Operator a hard prerequisite on OpenShift, and the controller will report a `Degraded` condition and halt reconciliation if any check fails. [source: internal/controller/trainer_controller.go:231-269]

The informer cache is hardened against resource exhaustion: watches are scoped to the applications namespace via `APPLICATIONS_NAMESPACE` and filtered by the `platform.opendatahub.io/part-of: trainer` label selector. Namespace objects are excluded from the cache entirely to prevent a cluster-wide informer from the `ensureNamespace` Get call. The `StripUnusedFields` transform from odh-platform-utilities further reduces memory footprint by removing managed-fields and other metadata from cached objects. [source: cmd/main.go:82-131]

## Data Flows

- **Reconciliation trigger:** The platform operator creates or updates a `Trainer` CR (components.platform.opendatahub.io/v1alpha1). The trainer-operator controller receives the event via its informer, scoped to the applications namespace when `APPLICATIONS_NAMESPACE` is set. [source: cmd/main.go:82-89, internal/controller/trainer_controller.go:180]
- **Dependency verification:** On OpenShift, the controller queries the Kubernetes API for the JobSet Operator CRD, its CR, and its health status. If any check fails, reconciliation halts with a `Degraded` condition. On vanilla Kubernetes, only the JobSet CRD is verified. [source: internal/controller/trainer_controller.go:231-269]
- **Manifest rendering and deployment:** The controller reads the platform version from a ConfigMap in the target namespace, renders manifests from bundled templates (`/opt/manifests-template/`, `/opt/runtimes-template/`, `/opt/imagestreams-template/`), and applies them to the target namespace using the framework's deploy action with field ownership (`trainer-module-controller`). Stale resources from previous versions are garbage-collected. [source: cmd/main.go:137-164, internal/controller/trainer_controller.go:189-198, 553-563]
- **Observation surface:** The operator exposes plaintext HTTP metrics on port 8080 (no authentication, no TLS) and health/readiness probes on port 8081. Metrics are scraped by the platform monitoring stack via the `trainer-operator-controller-manager-metrics-service` ClusterIP Service. [source: cmd/main.go:69-72, 93-95, 183-190, config/default/metrics_service.yaml:1]
