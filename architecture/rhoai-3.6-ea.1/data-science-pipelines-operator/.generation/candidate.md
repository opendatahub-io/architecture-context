## Purpose

**Short**: Kubernetes operator that manages the lifecycle of Data Science Pipelines (DSP) instances on OpenShift, reconciling DataSciencePipelinesApplication custom resources into fully configured pipeline stacks backed by Argo Workflows. [source: main.go:165, config/crd/bases/datasciencepipelinesapplications.opendatahub.io_datasciencepipelinesapplications.yaml:2]

**Detailed**: The data-science-pipelines-operator is a controller-runtime operator that watches `DataSciencePipelinesApplication` (DSPA) custom resources and reconciles the full set of Kubernetes objects needed to run a Kubeflow Pipelines v2-compatible stack. Each DSPA instance drives the creation of pipeline API server deployments, persistence-agent, scheduled-workflow controller, Argo Workflow engine components, database connections (MariaDB or external), object storage connections (MinIO or external), and associated RBAC, Services, Routes, and NetworkPolicies. The operator uses manifestival to apply templated manifests from `config/internal/`, applying label transformations to track owned resources. It integrates with several RHOAI platform components including MLflow for experiment tracking, KServe for model serving state, Ray/CodeFlare for distributed workload scheduling, and prometheus-operator for monitoring. The operator also manages PipelineVersion validation and mutation webhooks with TLS secured by the cluster's OpenShift TLS profile. [source: main.go:165, main.go:265-372, controllers/dspipeline_controller.go:893-903, config/manager/manager-service.yaml:1]

## Architectural Analysis

The operator follows a single-controller reconciliation pattern centered on the `DSPAReconciler`, which watches the primary `DataSciencePipelinesApplication` CR and a broad set of owned child resources (Deployments, Services, ServiceAccounts, ConfigMaps, Secrets, PVCs, Roles, RoleBindings, Routes, and NetworkPolicies). All child resources are created through manifestival template application with a `dsp-version` label, enabling the controller to scope its informer caches to only operator-managed objects and avoid watching unrelated cluster resources. [source: main.go:209-220, controllers/dspipeline_controller.go:893-903]

The operator's RBAC footprint is deliberately wide, reflecting its role as an orchestrator that provisions an entire pipeline stack per namespace. The `manager-role` ClusterRole includes permissions across multiple platform API groups — `ray.io`, `workload.codeflare.dev`, `serving.kserve.io`, `mlflow.opendatahub.io`, and `machinelearning.seldon.io` — indicating integration points with distributed compute, model serving, and experiment-tracking subsystems. RBAC aggregation ClusterRoles (`aggregate-dspa-admin-edit`, `aggregate-dspa-admin-view`) provide tiered access to DSPA resources for platform users, mirroring the pattern used for Argo Workflow CRDs. [source: config/rbac/role.yaml:2, config/rbac/aggregate_dspa_role_edit.yaml:1, config/rbac/aggregate_dspa_role_view.yaml:1]

TLS configuration is dynamically derived from the OpenShift APIServer TLS profile via `controller-runtime-common/pkg/tls`, with an `Intermediate` fallback for non-OpenShift clusters. A `SecurityProfileWatcher` monitors for TLS profile changes and triggers a graceful restart to reload the configuration, ensuring the operator remains compliant with cluster-level TLS policy changes. The webhook server (port 9443) and metrics server (port 8080) both share this TLS configuration. [source: tls_profile.go:22-64, main.go:265-274, main.go:385-400]

The build uses Go 1.26 with `GOFIPS140=v1.0.0` and `-tags no_openssl`, selecting Go's native FIPS 140 crypto module rather than the traditional CGO+OpenSSL approach. This is a statically linked binary (`CGO_ENABLED=0`) that relies on Go's built-in FIPS-validated cryptography. [source: Dockerfile.konflux:28]

## Data Flows

- **Reconciliation flow:** A DSPA CR change triggers the `DSPAReconciler`, which reads the CR spec, resolves database and object storage connection parameters (from embedded config or referenced Secrets/ConfigMaps), renders manifestival templates from `config/internal/`, and applies the resulting Kubernetes objects — Deployments, Services, ServiceAccounts, Roles, RoleBindings, Routes, NetworkPolicies, and PVCs — into the target namespace. All created resources carry the `dsp-version` label for ownership tracking. [source: main.go:209-220, controllers/dspipeline_controller.go:893-903]
- **Platform integrations:** The reconciler reads MLflow CRs (bypassing client cache for availability tolerance), watches KServe InferenceService resources for model serving state, and manages Ray clusters/jobs, CodeFlare AppWrappers, and Seldon deployments through CRD CRUD operations. These interactions use the Kubernetes API over HTTPS/TLS with ServiceAccount authentication. [source: main.go:328-330, config/rbac/role.yaml:2]
- **Observability:** The operator exposes a metrics Service on port 8080 (TLS-encrypted using the OpenShift TLS profile) scraped by a ServiceMonitor. Health and readiness probes are served unauthenticated on port 8081. [source: config/manager/manager-service.yaml:1, config/prometheus/monitor.yaml:1, main.go:170-171]
- **Webhook flow:** PipelineVersion validation and mutation webhooks are served on port 9443 with TLS derived from the cluster's OpenShift TLS profile. The operator dynamically manages the ValidatingWebhookConfiguration and MutatingWebhookConfiguration resources. [source: main.go:271-274, main.go:207]
- **Security context:** Access to DSPA and Argo Workflow CRDs is governed by RBAC aggregation ClusterRoles that provide tiered admin/edit/view access. The Argo cluster role restricts secret access to `argo-workflows-agent-ca-certificates` only via resourceNames restriction. [source: config/rbac/aggregate_dspa_role_edit.yaml:1, config/argo/clusterrole.argo-cluster-role.yaml:1]
