## Purpose

**Short**: Kubernetes operator that manages the lifecycle of Model Context Protocol (MCP) server deployments, including provisioning Deployments, Services, and NetworkPolicies, and verifying MCP protocol compliance via handshake probes. [source: cmd/main.go:188-202, internal/controller/mcpserver_controller.go:653-673, internal/controller/mcpserver_controller_handshake.go:36-90]

**Detailed**: mcp-lifecycle-operator is a controller-runtime-based Kubernetes operator that reconciles MCPServer custom resources (mcp.x-k8s.io/v1alpha1). When a user creates or updates an MCPServer CR, the operator provisions a complete runtime stack: a Deployment running the specified MCP server container, a Service exposing the MCP endpoint, and a NetworkPolicy governing network access. The operator watches ConfigMaps and Secrets referenced by MCPServer specs and triggers reconciliation when they change, computing a configuration hash to force rolling updates. After the Deployment becomes available, the operator performs an MCP protocol handshake against the server endpoint using the upstream MCP Go SDK, verifying that the server speaks valid MCP protocol and extracting its capabilities (tools, resources, prompts, logging, completions) into the MCPServer status. The operator supports configurable TLS settings via environment variables (TLS_MIN_VERSION, TLS_CIPHER_SUITES) that can be propagated to managed MCP server containers. It is deployed as a single-replica Deployment with leader election and exposes health/readiness probes on port 8081 and RBAC-protected metrics on port 8443 with TLS. [source: cmd/main.go:130-218, cmd/tlsconfig.go:17-93, internal/controller/mcpserver_controller.go:49-57, internal/controller/mcpserver_controller_handshake.go:92-131]

## Architectural Analysis

mcp-lifecycle-operator follows the standard kubebuilder operator pattern with a single MCPServerReconciler that owns the full lifecycle of MCP server instances. The reconciler uses controller-runtime's ownership model: it creates and owns Deployments, Services, and NetworkPolicies for each MCPServer CR, which means Kubernetes garbage collection automatically cleans up child resources when the parent MCPServer is deleted. ConfigMaps and Secrets are watched via mapped references rather than ownership, allowing shared configuration across MCPServer instances while still triggering reconciliation on changes. [source: internal/controller/mcpserver_controller.go:653-673]

A distinctive architectural feature is the MCP protocol handshake verification. After deploying the MCP server container, the operator acts as an MCP client using the upstream `github.com/modelcontextprotocol/go-sdk` library to perform an initialize handshake against the server's HTTP endpoint. This verifies that the server actually speaks MCP protocol and extracts its advertised capabilities into the MCPServer status. The handshake uses exponential backoff (10s, 20s, 40s, 80s up to a configurable max) and gracefully handles authentication errors (HTTP 401/403) by treating the endpoint as reachable without failing the readiness condition. This design ensures the operator can manage MCP servers that require external authentication without blocking their deployment. [source: internal/controller/mcpserver_controller_handshake.go:36-90, 92-131, 158-169, 171-182]

The operator's TLS configuration is environment-driven via a centralized `tlsSettings` struct that parses `TLS_MIN_VERSION` and `TLS_CIPHER_SUITES` environment variables. These validated settings serve dual purpose: they configure the operator's own metrics server TLS and can optionally be propagated as environment variables into managed MCP server containers when `PROPAGATE_TLS_ENV_VARS=true`. This provides a consistent TLS profile across the operator and its managed workloads without requiring per-server configuration. [source: cmd/tlsconfig.go:17-93, cmd/main.go:194-198]

The metrics endpoint on port 8443 is protected by controller-runtime's built-in authentication and authorization filter, which performs TokenReview and SubjectAccessReview checks against the Kubernetes API server. This ensures only service accounts with the `mcp-lifecycle-operator-metrics-reader` ClusterRole can scrape metrics. TLS certificates are self-signed by default but support external certificate injection via command-line flags. [source: cmd/main.go:133-162]
