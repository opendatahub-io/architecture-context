## Purpose

**Short**: TrustyAI Service is a Python FastAPI application providing AI model explainability, fairness metrics, and drift detection, served via Hypercorn with kube-rbac-proxy authentication delegation and optional MariaDB or PVC-backed storage. [source: src/main.py:109-114, Dockerfile.konflux:130, pyproject.toml:7-24]

**Detailed**: TrustyAI Service is a Python-based AI observability service built on FastAPI and served by Hypercorn. It exposes 87 HTTP endpoints organized into functional groups: inference data consumption (KServe v2 protocol via `/consumer/kserve/v2`), fairness metrics (Statistical Parity Difference, Disparate Impact Ratio), drift detection (KS test, Jensen-Shannon, Fourier MMD, mean comparison), model explainability (LIME, SHAP, counterfactual, PDP, time-series saliency), and service metadata. The service supports two storage backends: PVC-based HDF5 file storage (default) and optional MariaDB with TLS. Authentication is delegated to kube-rbac-proxy, which forwards authenticated requests to the service's loopback-bound HTTP port (8080); a separate HTTPS listener on port 4443 provides direct TLS access. The container image uses a UBI10 base with FIPS crypto policy enabled by default. [source: src/main.py:109-114, 251-293, src/service/data/storage/__init__.py:47-118, src/endpoints/consumer/consumer_endpoint.py:65-81, Dockerfile.konflux:8, 62-85, 115, 130]

## Architectural Analysis

TrustyAI Service follows a sidecar-adjacent deployment pattern common in RHOAI: it runs alongside inference services, consuming prediction payloads via the KServe v2 protocol and computing fairness, drift, and explainability metrics over accumulated inference data. The service uses a dual-port networking model where HTTP on port 8080 is bound to loopback only (127.0.0.1) and fronted by kube-rbac-proxy for Kubernetes-native authentication, while an optional HTTPS listener on port 4443 binds to all interfaces for direct TLS access when certificates are mounted at `/etc/tls/internal/`. [source: src/main.py:257-280]

The storage layer is pluggable via the `SERVICE_STORAGE_FORMAT` environment variable, supporting PVC-backed HDF5 files (default) or MariaDB with optional TLS (CA cert at `/etc/tls/db/ca.crt`). The MariaDB path requires the `mariadb` optional dependency extra and supports both Quarkus-style operator environment variables (`QUARKUS_DATASOURCE_*`) and direct deployment variables (`DATABASE_*`), reflecting the service's migration from a prior Java/Quarkus implementation. [source: src/service/data/storage/__init__.py:47-118, pyproject.toml:62]

CORS is configured permissively (`allow_origins=["*"]`) on the FastAPI application, which is architecturally acceptable because the service is not directly internet-facing — external traffic is authenticated and authorized by kube-rbac-proxy before reaching the loopback-bound HTTP port. A background asyncio task periodically calculates Prometheus metrics and exposes them at `/q/metrics`. Health probes at `/q/health/ready` and `/q/health/live` support Kubernetes liveness and readiness checks. [source: src/main.py:117-123, 74-87, 197-224]

The FIPS crypto policy is enabled by default in the container image via `update-crypto-policies --set FIPS`, but full FIPS mode requires deployment on a FIPS-enabled host with kernel `fips=1`. The `cryptography` library (>=48.0.1) provides OpenSSL bindings for TLS operations, and no non-FIPS cryptographic operations were detected in the application code. [source: Dockerfile.konflux:8, 62-85, pyproject.toml:21]

## Data Flows

- **Inference data ingestion:** KServe/ModelMesh inference services send prediction request and response payloads to `/consumer/kserve/v2` as POST requests. The consumer endpoint reconciles input/output pairs by inference ID and stores them in the configured storage backend (PVC HDF5 or MariaDB). [source: src/endpoints/consumer/consumer_endpoint.py:65-99]
- **Authentication flow:** External requests arrive at kube-rbac-proxy, which performs Kubernetes RBAC authentication and forwards authenticated traffic to the service's loopback-bound HTTP port 8080. When TLS certificates are mounted, a parallel HTTPS listener on port 4443 accepts direct connections. [source: src/main.py:257-280]
- **Metrics pipeline:** A background asyncio task periodically calculates fairness, drift, and batch-mean metrics from stored inference data and publishes them as Prometheus metrics at `/q/metrics`. The calculation interval is configurable via `metrics_schedule` (default 30 seconds). [source: src/main.py:74-87, 197-204]
- **Storage backends:** Data flows through a pluggable storage interface configured via `SERVICE_STORAGE_FORMAT`. PVC mode writes HDF5 files to a mounted volume; MariaDB mode connects to a database service on port 3306 with optional TLS (CA cert at `/etc/tls/db/ca.crt`) and credentials from environment variables. [source: src/service/data/storage/__init__.py:47-118]
