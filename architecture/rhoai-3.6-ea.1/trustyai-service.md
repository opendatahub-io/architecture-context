## Purpose

**Short**: TrustyAI Service is a Python FastAPI application providing AI model explainability, fairness metrics, and data drift detection for RHOAI, served via Hypercorn with platform-delegated authentication through kube-rbac-proxy. [source: src/main.py:110-114, pyproject.toml:2-4, Dockerfile.konflux:37]

**Detailed**: TrustyAI Service is a FastAPI-based Python application that provides AI/ML model monitoring capabilities including fairness metrics (Statistical Parity Difference, Disparate Impact Ratio), data drift detection (Kolmogorov-Smirnov, Jensen-Shannon, Fourier MMD, Compare Means), local and global explainers (LIME, SHAP, Counterfactual, PDP, Time Series Saliency), and an optional LM Evaluation Harness integration. It receives inference data from ModelMesh/KServe model serving infrastructure via the `/consumer/kserve/v2` endpoint and stores observations in either PVC-based HDF5 files or an optional MariaDB database. Prometheus metrics are computed on a configurable schedule and exposed at `/q/metrics`. The service binds HTTP on loopback (127.0.0.1:8080) behind a kube-rbac-proxy sidecar for authentication, with optional direct HTTPS access on 0.0.0.0:4443 when TLS certificates are mounted. [source: src/main.py:110-114, 251-293, src/endpoints/consumer/consumer_endpoint.py:66, src/service/data/storage/__init__.py:48-119, pyproject.toml:8-25, Dockerfile.konflux:35-37]

## Architectural Analysis

TrustyAI Service is a single-process Python application built on FastAPI and served by Hypercorn, an HTTP/2-capable ASGI server. The application exposes 87 HTTP endpoints organized into functional groups: inference data consumption (KServe v2 protocol), fairness metrics (SPD, DIR), data drift detection (KS test, Jensen-Shannon divergence, Fourier MMD, Compare Means, Mean Shift, Approximate KS), local explainers (LIME, SHAP, Counterfactual, Time Series Saliency), global explainers (LIME, PDP), model metadata management, and Prometheus metrics. An optional LM Evaluation Harness integration is conditionally loaded when the `eval` extra is installed. [source: src/main.py:22-51, 141-176]

The service follows a dual-bind networking model: HTTP traffic is bound to loopback (`127.0.0.1:8080`) and is expected to be fronted by a kube-rbac-proxy sidecar that handles authentication before forwarding to the application. When TLS certificates are available at `/etc/tls/internal/tls.crt` and `/etc/tls/internal/tls.key`, the service also binds HTTPS on `0.0.0.0:4443` for direct access. No application-level authentication middleware is registered; authentication is entirely platform-delegated. [source: src/main.py:228-293]

Data persistence uses a pluggable storage backend selected by the `SERVICE_STORAGE_FORMAT` environment variable. The default `PVC` backend stores observations in HDF5 files on a mounted persistent volume. The `MARIA`/`DATABASE` backend connects to a MariaDB instance using credentials from environment variables, with optional TLS via a CA certificate at `DATABASE_TLS_CA_CERT`. The MariaDB connector is a lazy-loaded optional dependency installed via the `mariadb` extra. [source: src/service/data/storage/__init__.py:48-119, pyproject.toml:63]

Prometheus metrics are computed on a configurable schedule (default 30 seconds) by a background asyncio task and published via the prometheus-client library at `/q/metrics`. Health probes at `/q/health/ready` and `/q/health/live` provide Kubernetes readiness and liveness signals. [source: src/main.py:75-87, 198-225, src/service/prometheus/prometheus_scheduler.py:70-81]

## Data Flows

- **Inference data ingestion:** ModelMesh/KServe sends inference request and response payloads to the `/consumer/kserve/v2` endpoint. Payloads are reconciled by correlation ID — when both input and output for the same inference are received, they are joined and persisted to the configured storage backend. [source: src/endpoints/consumer/consumer_endpoint.py:66-100]
- **Storage persistence:** Inference observations are stored either in HDF5 files on a PVC mount (default) or in a MariaDB database when `SERVICE_STORAGE_FORMAT` is set to `MARIA` or `DATABASE`. The MariaDB backend uses credentials from environment variables with optional TLS via a CA certificate. [source: src/service/data/storage/__init__.py:48-119]
- **Metrics computation and export:** A background asyncio task periodically calculates fairness, drift, and statistical metrics from stored observations and publishes them as Prometheus gauges, scraped at `/q/metrics`. The calculation interval is configurable via `SERVICE_METRICS_SCHEDULE` (default 30s). [source: src/main.py:75-87, src/service/prometheus/prometheus_scheduler.py:27-81]
- **Network entry:** HTTP traffic enters via kube-rbac-proxy on the pod's external interface, which authenticates requests and forwards them to the service on `127.0.0.1:8080`. When TLS certificates are mounted, direct HTTPS access is available on `0.0.0.0:4443`. [source: src/main.py:251-293]
