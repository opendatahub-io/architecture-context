## Purpose

**Short**: odh-model-controller is a dual-workload Kubernetes operator that manages the lifecycle of model serving resources (InferenceService, InferenceGraph, LLMInferenceService, ServingRuntime, NIM Account) on RHOAI, providing admission webhooks, Gateway API integration, and a dedicated model-serving REST API. [source: cmd/main.go:89, server/main.go:27, server/server.go:16-44]

**Detailed**: odh-model-controller runs as two Deployments within the RHOAI platform. The primary `odh-model-controller` Deployment is a controller-runtime operator that reconciles KServe InferenceService, InferenceGraph, LLMInferenceService, ServingRuntime, and NIM Account custom resources. It manages subordinate Kubernetes resources including Routes, NetworkPolicies, ServiceAccounts, ClusterRoleBindings, KEDA TriggerAuthentications, Kuadrant AuthPolicies, Istio EnvoyFilters, and Prometheus monitoring resources. Eight admission webhooks (5 mutating, 3 validating) intercept creation and update of inference workloads and NIM accounts. The secondary `model-serving-api` Deployment provides an HTTPS REST API for gateway discovery (`/api/v1/gateways`) and sample LLM-d templates (`/api/v1/samples/llm-d`), backed by a Kubernetes client that queries Gateway API resources. Both workloads resolve their TLS configuration from the OpenShift APIServer TLS profile, falling back to Mozilla Intermediate defaults (TLS 1.2+) on non-OpenShift clusters. The controller watches the OpenShift `config.openshift.io/v1/APIServer` resource and restarts on TLS profile changes. [source: cmd/main.go:89-177, server/main.go:27-134, server/server.go:16-44, pkg/tls/tls.go:76-139]

## Architectural Analysis

odh-model-controller is architecturally notable for its dual-workload design: a controller-runtime operator and a standalone HTTPS API server, both deployed from the same repository but as separate Kubernetes Deployments with distinct service accounts and RBAC scopes.

**Controller architecture.** The operator runs 10 reconcilers spanning core Kubernetes resources (ConfigMap, Secret, Pod), KServe serving resources (InferenceService, InferenceGraph, ServingRuntime), LLM-specific resources (LLMInferenceService, Gateway), NIM account management, and OpenShift APIServer TLS profile watching. The InferenceServiceReconciler is the most broadly connected, owning subordinate watches on 13 resource types including Routes, NetworkPolicies, ServiceAccounts, ClusterRoleBindings, PodMonitors, ServiceMonitors, ServingRuntimes, and KEDA TriggerAuthentications. The GatewayReconciler manages Gateway API resources, Kuadrant AuthPolicies, Istio EnvoyFilters, and PodMonitors for the LLM gateway ingress path. A conditional prometheus-operator watch allows the controller to degrade gracefully when monitoring CRDs are absent. [source: cmd/main.go:89-177, internal/controller/serving/inferenceservice_controller.go:208-219, internal/controller/serving/llm/gateway_controller.go:1003-1062]

**API server architecture.** The model-serving-api Deployment provides a TLS-mandatory REST API. The `/api/v1/gateways` endpoint requires Bearer token authentication via a middleware that extracts tokens from the Authorization header and returns 401 for unauthenticated requests. The `/api/v1/samples/llm-d` endpoint is intentionally unauthenticated, serving static embedded YAML templates. A dedicated metrics listener on port 8080 serves Prometheus metrics over HTTPS without application-level authentication. OpenTelemetry tracing is optionally exported via OTLP/gRPC when configured. [source: server/server.go:16-44, server/middleware/auth.go:24-41, server/main.go:91-98, server/observability/observability.go:67-97]

**TLS management.** Both workloads derive their TLS configuration from the OpenShift `apiservers.config.openshift.io/cluster` resource. The `pkg/tls` package reads the cluster TLS profile at startup, maps OpenSSL cipher names to Go constants, and applies the resolved minimum TLS version and cipher suites. When the profile cannot be read (non-OpenShift clusters, transient errors), it falls back to a hardened Intermediate profile (TLS 1.2, Mozilla Intermediate cipher suite). A `ProfileWatcher` controller triggers a graceful shutdown and restart when the cluster TLS profile changes, ensuring the operator always serves with the current cluster-wide policy. [source: pkg/tls/tls.go:76-145, cmd/main.go:117-171]

**Platform integration pattern.** The controller reads `DataScienceCluster` and `DSCInitialization` CRs to determine which platform components are enabled, gating feature-specific behavior. It manages Kuadrant AuthPolicies for LLMInferenceService authentication, creates KEDA TriggerAuthentications for autoscaling, and provisions OpenShift Routes for model serving endpoints. The SelfSubjectAccessReview call in the gateway discoverer validates the caller's permissions before exposing gateway information. [source: config/rbac/role.yaml:3, server/gateway/discovery.go:154-171]
