## Purpose

**Short**: Kubernetes operator that manages Apache Spark application lifecycle on OpenShift, providing CRD-based submission, scheduling, and monitoring of Spark workloads with admission webhook validation and an RHOAI platform integration module. [source: cmd/operator/main.go:44, spark-operator-module/pkg/apis/v1alpha1/types.go:18]

**Detailed**: The spark-operator manages the full lifecycle of Apache Spark applications on Kubernetes and OpenShift through three CRDs: SparkApplication for on-demand jobs, ScheduledSparkApplication for cron-style recurring workloads, and SparkConnect for Spark Connect server sessions. The operator runs as two core Deployments—a controller that reconciles Spark CRs into driver/executor Pods, Services, ConfigMaps, and PodDisruptionBudgets, and a webhook server that validates, defaults, and mutates Spark resources and injected Spark pods. An RHOAI-specific spark-operator-module meta-controller wraps the core operator to implement the ODH platform component contract (SparkOperator CR under `components.platform.opendatahub.io`), managing the full deployment stack including CRDs, RBAC roles, Deployments, webhook configurations, and cert-manager Certificates. The operator integrates with the OpenShift TLS profile API to enforce cluster-aligned cipher suites and is built with FIPS-compliant settings (strictfipsruntime, dynamic linking). [source: cmd/operator/main.go:44, spark-operator-module/pkg/apis/v1alpha1/types.go:18, Dockerfile.konflux:24, pkg/tls/profile.go:49]

## Architectural Analysis

The spark-operator follows a layered controller architecture with clear separation between the upstream Kubeflow operator logic and RHOAI platform integration.

The core operator layer consists of two Deployments sharing the same container image but running different command paths. The controller Deployment (`spark-operator-controller`) runs five reconciliation loops: SparkApplication and ScheduledSparkApplication controllers manage Spark workload lifecycle by creating driver Pods, executor Pods, Services, ConfigMaps for monitoring, and PodDisruptionBudgets; the SparkConnect controller reconciles SparkConnect server sessions; and two webhook configuration controllers maintain MutatingWebhookConfiguration and ValidatingWebhookConfiguration resources with current CA bundles. The webhook Deployment (`spark-operator-webhook`) serves seven admission webhook endpoints with Fail failure policy, covering validation, defaulting, and pod mutation across all three CRD types plus raw Pod resources. [source: internal/controller/sparkapplication/controller.go:279-284, internal/controller/sparkconnect/reconciler.go:111-198, internal/controller/mutatingwebhookconfiguration/controller.go:68-89, internal/webhook/sparkapplication_defaulter.go:30, internal/webhook/sparkapplication_validator.go:37]

The RHOAI platform integration layer is the spark-operator-module, a separate controller-runtime operator that manages the entire spark-operator deployment as a platform component. It watches a singleton cluster-scoped SparkOperator CR (`default-sparkoperator`) and reconciles the full resource set: Deployments, Services, ServiceAccounts, ClusterRoles, ClusterRoleBindings, CRDs, webhook configurations, NetworkPolicies, cert-manager Certificates/Issuers, and PodMonitors. This module implements the `common.PlatformObject` interface from odh-platform-utilities, providing the ODH Operator with standardized condition reporting, management state control (Managed/Unmanaged), and component release status tracking. [source: spark-operator-module/pkg/apis/v1alpha1/types.go:18, spark-operator-module/config/rbac/role.yaml:83-95]

TLS certificate management for webhooks uses a dual strategy: the core operator includes an internal `pkg/certificate` provider that creates and rotates self-signed certificates stored in a scoped Secret (`spark-operator-webhook-certs`), while the module controller provisions cert-manager Certificate and Issuer CRs for production-grade certificate lifecycle. The webhook Role restricts secret access to the named certificate secret only, with leader election locks scoped to `spark-operator-webhook-lock`. [source: config/webhook/role.yaml:26-49, spark-operator-module/config/rbac/role.yaml:83-95, pkg/certificate/certificate.go:94]

The operator reads the OpenShift APIServer TLS profile (`config.openshift.io/v1`) at startup to align its TLS configuration with cluster-wide cipher policy. It defaults to TLS 1.2 with an Intermediate cipher suite (ECDHE+AES-GCM and ECDHE+CHACHA20-POLY1305) and dynamically applies Custom, Modern, or Old profiles when configured on the cluster. [source: pkg/tls/profile.go:49-112, pkg/tls/profile.go:163-170]

## Data Flows

### Flow 1: Spark Application Submission

| Step | Source | Destination | Port | Protocol | Encryption | Auth |
|------|--------|-------------|------|----------|------------|------|
| 1 | User/CI | kube-apiserver | 6443/TCP | HTTPS | TLS 1.2+ | User token |
| 2 | kube-apiserver | spark-operator-webhook | 443/TCP | HTTPS | TLS | Kubernetes admission |
| 3 | kube-apiserver | spark-operator-controller | — | watch | TLS 1.2+ | ServiceAccount token |
| 4 | spark-operator-controller | kube-apiserver | 6443/TCP | HTTPS | TLS 1.2+ | ServiceAccount token |

A user creates a SparkApplication CR. The kube-apiserver invokes the mutating and validating admission webhooks served by `spark-operator-webhook` to set defaults and validate the spec. The `spark-operator-controller` receives the CR through its watch, creates a driver Pod, monitors executor Pods through an owned-resource watch, and manages associated Services, ConfigMaps, and PodDisruptionBudgets. All Kubernetes API interactions use the controller's ServiceAccount with RBAC-scoped permissions. [source: cmd/operator/controller/start.go:345, internal/controller/sparkapplication/controller.go:279-284, config/webhook/service.yaml:3]

### Flow 2: Platform Component Management

| Step | Source | Destination | Port | Protocol | Encryption | Auth |
|------|--------|-------------|------|----------|------------|------|
| 1 | ODH Operator | kube-apiserver | 6443/TCP | HTTPS | TLS 1.2+ | ServiceAccount token |
| 2 | spark-operator-module | kube-apiserver | 6443/TCP | HTTPS | TLS 1.2+ | ServiceAccount token |

The ODH Operator creates a SparkOperator CR. The spark-operator-module reconciles it by deploying or updating the complete spark-operator stack: controller and webhook Deployments, CRDs, RBAC, Services, webhook configurations, NetworkPolicies, cert-manager Certificates, and PodMonitors. Status conditions are reported back through the PlatformObject interface. [source: spark-operator-module/pkg/apis/v1alpha1/types.go:18, spark-operator-module/config/rbac/role.yaml:2]
