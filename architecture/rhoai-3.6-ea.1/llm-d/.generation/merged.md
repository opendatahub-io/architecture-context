## Purpose

**Short**: llm-d is a disaggregated LLM inference platform that runs vLLM-based model servers as Kubernetes Deployments, coordinated by a routing layer (EPP + Envoy/Agent Gateway proxy) and optionally a ModelExpress metadata broker for peer-to-peer KV cache sharing over RDMA. [source: docker/Dockerfile.cpu:142, guides/recipes/modelserver/base/single-host/default/decode-deployment.yaml:1, guides/recipes/router/base.values.yaml:1]

**Detailed**: llm-d packages vLLM as container images for multiple accelerator targets (CPU, ROCm, XPU, RDMA-tools) and provides Kubernetes deployment recipes for running disaggregated inference workloads. The primary deployable unit is the `decode` Deployment, which runs the vLLM OpenAI-compatible API server on port 8000/TCP, exposing `/health` and `/v1/models` HTTP probe endpoints. Inference requests reach the model server pods through an llm-d-router stack consisting of an Endpoint Picker Plugin (EPP) and an Envoy (or Agent Gateway) sidecar proxy, which together implement Gateway API InferencePool-based routing. For advanced disaggregated prefill/decode topologies, llm-d integrates with an NVIDIA ModelExpress metadata broker over gRPC (port 8001) to coordinate peer-to-peer KV cache transfers via RDMA, with each decode worker exposing additional gRPC ports (5555, 6555) for metadata and tensor transfer. The repository is upstream-only and does not contain Konflux Dockerfiles, Helm charts, or downstream FIPS hardening. [source: docker/Dockerfile.cpu:142, guides/recipes/modelserver/base/single-host/default/decode-deployment.yaml:1, guides/modelexpress-p2p/modelexpress/modelexpress-server.yaml:47, guides/modelexpress-p2p/modelserver/gpu/vllm/base/patch-vllm.yaml:1]

## Architectural Analysis

llm-d follows a disaggregated inference architecture where model serving is separated into prefill and decode roles, each running as independent Kubernetes Deployments with the vLLM OpenAI-compatible API server as the primary entrypoint. The routing layer—comprising an Endpoint Picker Plugin (EPP) and an Envoy or Agent Gateway sidecar proxy—selects backend pods through Gateway API InferencePool resources, enabling model-aware request routing without custom ingress controllers.

The peer-to-peer KV cache sharing subsystem (ModelExpress) introduces a gRPC metadata broker that coordinates RDMA-based tensor transfers between decode workers, bypassing the service mesh for data-plane traffic while relying on Istio STRICT mTLS and AuthorizationPolicy to protect the gRPC control plane (port 8001). This split between mesh-protected control traffic and out-of-mesh RDMA data transfer is a deliberate design trade-off documented in the security manifests. [source: guides/modelexpress-p2p/security/istio-mtls-authz.yaml:1-4]

The repository provides multi-accelerator Dockerfile variants (CPU, ROCm, XPU) but no Helm charts or Konflux build infrastructure; deployment is recipe-driven through kustomize overlays and guide YAML files. Authentication is not enforced at the model server HTTP endpoints—the decode containers expose port 8000 without built-in auth, relying on platform-level network policies or service mesh authorization for access control. [source: guides/recipes/modelserver/base/single-host/default/decode-deployment.yaml:17-39, docker/Dockerfile.cpu:1]
