## Purpose

**Short**: Python SDK providing a high-level client for submitting and managing distributed compute workloads on Ray clusters within RHOAI, with integrated Kueue queue management and Kubernetes authentication via kube-authkit. **Detailed**: codeflare-sdk is a Python client library (v0.38.2) that wraps the Ray Job Submission Client and Kubernetes API to provide a unified interface for submitting, monitoring, and managing distributed compute workloads on OpenShift AI. The SDK authenticates to Kubernetes clusters using kube-authkit with support for Bearer token, kubeconfig file, and in-cluster auto-detection strategies. It integrates with Kueue for workload queue management, querying LocalQueues and WorkloadPriorityClasses via the kueue.x-k8s.io/v1beta1 API. The SDK also generates TLS certificates for Ray cluster mTLS communication using the `cryptography` library with RSA-3072 keys and SHA-256 signing. Test infrastructure includes a containerized test runner (images/tests/Dockerfile) and a MinIO deployment for object storage in end-to-end tests. [source: pyproject.toml:2-8, src/codeflare_sdk/ray/client/ray_jobs.py:16-20, src/codeflare_sdk/common/kubernetes_cluster/auth.py:29-31, src/codeflare_sdk/common/kueue/kueue.py:27-46, src/codeflare_sdk/common/utils/generate_cert.py:56-59]

## Architectural Analysis

The CodeFlare SDK follows a layered client-library architecture. At the core, `RayJobClient` wraps Ray's `JobSubmissionClient` to provide job submission, monitoring, and lifecycle management against Ray cluster dashboard endpoints. Authentication is decoupled through a pluggable layer built on `kube-authkit`, which abstracts Kubernetes authentication into three strategies: Bearer token, kubeconfig file, and in-cluster auto-detection. Legacy `TokenAuthentication` and `KubeConfigFileAuthentication` classes remain for backward compatibility but are deprecated in favor of direct `AuthConfig` usage. [source: src/codeflare_sdk/ray/client/ray_jobs.py:20-58, src/codeflare_sdk/common/kubernetes_cluster/auth.py:30-31, 90-91]

The SDK integrates with Kueue for workload scheduling by querying `LocalQueue` and `WorkloadPriorityClass` custom resources via the `kueue.x-k8s.io/v1beta1` API. Queue labels are injected into workload metadata to enable Kueue-managed scheduling, with support for default queue resolution and existence validation. This tight coupling means the SDK is aware of—and depends on—Kueue's scheduling semantics at the API level. [source: src/codeflare_sdk/common/kueue/kueue.py:41-46, 212-253]

Certificate management for Ray cluster mTLS uses the `cryptography` library to generate self-signed CA certificates and server/client keypairs with RSA-3072 keys signed using SHA-256—both FIPS-approved algorithms. Certificates are stored as Kubernetes Secrets and referenced by Ray clusters for inter-node TLS. The SDK also supports custom CA certificate paths via the `CF_SDK_CA_CERT_PATH` environment variable and auto-detects the OpenShift workbench CA bundle at `/etc/pki/tls/custom-certs/ca-bundle.crt`. [source: src/codeflare_sdk/common/utils/generate_cert.py:21-24, 56-59, src/codeflare_sdk/common/kubernetes_cluster/auth.py:40, 316-325]

The repository's test infrastructure—including the MinIO deployment and test Dockerfile—is not part of the production SDK but is packaged in the repository for end-to-end testing. The HTTP endpoint detected by the analyzer (`builtins.print / PATCH`) originates from a test helper file and does not represent a production API surface.

## Data Flows

- **Kubernetes authentication flow:** The SDK authenticates to the Kubernetes API server using kube-authkit's `AuthConfig` with auto-detection (in-cluster service account, kubeconfig, or explicit Bearer token). The authenticated client is reused across all Kubernetes API operations including Ray cluster management, Kueue queue queries, and certificate secret management. TLS certificate verification uses the system trust store, the OpenShift workbench CA bundle at `/etc/pki/tls/custom-certs/ca-bundle.crt`, or a custom path via `CF_SDK_CA_CERT_PATH`. [source: src/codeflare_sdk/common/kubernetes_cluster/auth.py:30-31, 257-264, 316-325]
- **Ray job submission flow:** Users submit jobs through `RayJobClient`, which wraps Ray's `JobSubmissionClient` to communicate with the Ray cluster dashboard over HTTP/HTTPS. The client supports custom headers for authentication and configurable TLS certificate verification. [source: src/codeflare_sdk/ray/client/ray_jobs.py:20, 51-58]
- **Kueue queue management flow:** The SDK queries Kueue LocalQueues and WorkloadPriorityClasses via the Kubernetes CustomObjects API (`kueue.x-k8s.io/v1beta1`). It resolves default queues by annotation, validates queue existence, and injects `kueue.x-k8s.io/queue-name` labels into workload metadata for Kueue-managed scheduling. [source: src/codeflare_sdk/common/kueue/kueue.py:41-46, 186-190, 252]
- **Certificate provisioning flow:** The SDK generates self-signed CA certificates (RSA-3072, SHA-256) and stores them as Kubernetes Secrets labeled with `ray.openshift.ai/cluster-name` for Ray cluster mTLS. [source: src/codeflare_sdk/common/utils/generate_cert.py:56-59, 146-155]
