## Purpose

**Short**: Kubernetes operator that reconciles the Workbenches custom resource to deploy and manage Kubeflow Notebook Controller, admission webhooks for hardware profile injection and connection mutation, and supporting RBAC and TLS infrastructure on RHOAI. [source: cmd/main.go:189-197, config/crd/bases/components.platform.opendatahub.io_workbenches.yaml:53-90, internal/webhook/hardwareprofile/mutating.go:67, internal/webhook/notebook/mutating.go:55]

**Detailed**: workbenches-operator is a controller-runtime operator that watches the cluster-scoped `Workbenches` custom resource (`components.platform.opendatahub.io/v1alpha1`). When the CR is set to `Managed`, the reconciler applies kustomize-based manifests to deploy the Kubeflow Notebook Controller (kf-notebook-controller), its CRDs, RBAC roles, and webhook configurations into the resolved applications namespace. The operator owns two mutating admission webhooks — one injects hardware profile resource limits into Notebook pods, the other mutates connection-related annotations — and a CRD conversion webhook for `notebooks.kubeflow.org`. The Workbenches CR spec receives orchestrator-projected fields (`gatewayDomain`, `mlflowEnabled`, `platform`) from the DSC/DSCI layer, allowing the operator to adapt behavior per platform without direct dependency on those APIs. TLS configuration integrates with the OpenShift cluster-wide TLS security profile, falling back to Mozilla Intermediate ciphers on non-OpenShift clusters. [source: cmd/main.go:120-163, 189-210, config/crd/bases/components.platform.opendatahub.io_workbenches.yaml:55-90, internal/controller/workbenches_controller.go:111-139, 146-172]

## Architectural Analysis

The workbenches-operator follows a single-CR reconciler pattern: one cluster-scoped `Workbenches` resource controls the entire component lifecycle. The reconciler applies upstream Kubeflow Notebook Controller manifests via kustomize server-side apply, setting owner references on all created resources (ConfigMaps, Secrets, Services, ServiceAccounts, Deployments, RBAC objects, and webhook configurations) so that deletion cascades cleanly through `reconcileDelete`. A finalizer guards teardown to ensure webhook configurations and CRDs are removed before the CR disappears. [source: internal/controller/workbenches_controller.go:111-139, 146-160]

The operator's two mutating webhooks intercept `CREATE` and `UPDATE` on `notebooks.kubeflow.org` resources with `Fail` policy, meaning notebook creation blocks if the webhook service is unavailable. The hardware-profile injector resolves `HardwareProfile` CRs (`infrastructure.opendatahub.io`) and patches resource requests/limits into notebook pod templates, emitting Kubernetes Events on validation errors. The connection-notebook webhook reads Secrets to inject data-connection metadata. Both webhooks are served on port 9443 behind OpenShift service-CA TLS certificates, with a periodic TLS ensurer that reconciles the serving certificate and MutatingWebhookConfiguration CA bundle. [source: cmd/main.go:158-163, 206-210, internal/webhook/hardwareprofile/mutating.go:67, internal/webhook/notebook/mutating.go:55]

TLS posture is driven by the OpenShift APIServer TLS security profile via `controller-runtime-common/pkg/tls`. At startup, the operator fetches the cluster profile and adherence policy; on non-OpenShift clusters or transient API errors, it falls back to TLS 1.2 minimum with Mozilla Intermediate ciphers (all FIPS-approved). A `SecurityProfileWatcher` cancels the manager context on profile changes, triggering a pod restart to adopt the new configuration. The metrics endpoint at `:8443` uses the same TLS options and gates access through controller-runtime's `WithAuthenticationAndAuthorization` filter (TokenReview + SubjectAccessReview). [source: cmd/main.go:120-146, 223-228, internal/tlsconfig/tlsconfig.go:41-48, 107-154]

Platform awareness is achieved through orchestrator-projected CR fields rather than direct API dependencies. The `gatewayDomain`, `mlflowEnabled`, and `platform` fields in the Workbenches spec are set by the DSC/DSCI reconciler, decoupling this operator from GatewayConfig and MLflow lifecycle details. The ConfigMap informer cache is namespace-scoped to the resolved applications namespace (or both platform defaults when unset), reducing watch overhead while ensuring platform configuration changes trigger reconciliation. [source: config/crd/bases/components.platform.opendatahub.io_workbenches.yaml:55-90, cmd/main.go:164-181]
