- OAuth2 bearer token validation via JWKS endpoint
- Issuer configured via AUTH_ISSUER environment variable
- TLS verification configurable for JWKS endpoint (verify_tls)
- Audience checking configurable
- Access Policy: Owner-based resource isolation

  - Resource owners: read, update, delete own resources
  - System resources (unowned): readable by all authenticated users

Secrets & Credentials:
- Secret injection pattern: _FILE-suffixed env vars resolved from file paths
  (supports Kubernetes secret volume mounts; avoids /proc/1/environ exposure)
- PostgreSQL credentials: username/password (env vars or _FILE pattern)
- Provider API keys: per-provider env vars (VLLM_URL, AWS credentials, etc.)
- Auth JWKS: configured via AUTH_ISSUER, AUTH_AUDIENCE env vars

FIPS Compliance:
- Python cryptography==50.0.0 (binds to system OpenSSL via cffi)
- FIPS mode inherited from AIPCC base image OpenSSL configuration
- No explicit FIPS opt-in detected; no non-FIPS algorithm usage detected
- TLS configuration: per-provider tls_verify flags (default true for vLLM)
- Certificate handling: system trust store + configurable CA paths
- Note: --insecure flag on ogx run controls app-level validation, not TLS bypass
