RBAC Summary:
- No ClusterRoles or RoleBindings defined
- Application does not interact with Kubernetes API
- Access control delegated entirely to infrastructure layer

Authentication Architecture:
- Inbound: No application-level authentication
  - Delegated to Kubernetes ingress/proxy/service mesh
  - Server accepts all requests that reach it
- Outbound (LLM providers):
  - Static API key from environment variable (AZURE_OPENAI_API_KEY, etc.)
  - OR X-Authorization header forwarding from inbound request
  - Inbound Authorization header explicitly EXCLUDED from forwarding
  - Prevents credential leakage between infrastructure and application auth
