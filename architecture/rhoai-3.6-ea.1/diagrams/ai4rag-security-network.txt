SECURITY NOTES:

⚠ TLS Verification Bypass:
  The OGX client (ogx_client.py:63-65) catches SSL certificate errors
  and retries with verify=False. This disables certificate validation
  and is a known risk for man-in-the-middle attacks. Intended for
  development environments with self-signed certificates.

Credential Management:
  - AWS credentials: Sourced from environment variables or explicit parameters
  - OGX API key: Passed at client construction time
  - No secrets stored in files or Kubernetes secrets (library pattern)

RBAC Summary:
  - No Kubernetes RBAC defined (pure Python library)
  - Access control delegated to consumer application

Service Mesh Configuration:
  - N/A (no Kubernetes deployment)

Secrets:
  - AWS_SECRET_ACCESS_KEY (environment variable) - AWS credentials, consumer-managed rotation
  - OGX API Key (runtime parameter) - API authentication, consumer-managed rotation

FIPS Compliance:
  - No container image or Konflux pipeline
  - Crypto behavior inherited from host Python runtime OpenSSL
  - verify=False fallback in OGX client is a non-FIPS risk
  - No FIPS mode enforcement at library level

Network Posture:
  - INBOUND: None (library, no listening ports)
  - OUTBOUND: S3 storage (HTTPS), OGX inference (HTTPS)
  - No Kubernetes services, ingress, or egress resources defined
