NETWORK SUMMARY:
- No listening ports or services exposed by must-gather
- Single outbound connection: pod → Kubernetes API server (443/TCP HTTPS)
- No external egress (no data exfiltration risk)
- No ingress routes, no load balancers

RBAC Summary:
- ServiceAccount: provisioned by oc adm must-gather framework
- Privileges: cluster-reader (read-only access to all cluster resources)
- No ClusterRoles or RoleBindings defined by must-gather itself
- RBAC is entirely delegated to the must-gather framework

Authentication & Authorization:
- Endpoint: Kubernetes API
- Auth Mechanism: ServiceAccount token
- Enforcement Point: Kubernetes RBAC
- Policy: cluster-reader (provisioned by oc adm must-gather framework)

Secrets:
- No secrets defined or managed by must-gather
- ServiceAccount token is auto-mounted by Kubernetes

FIPS Compliance:
- No application-level cryptographic operations
- All TLS handled by oc/kubectl/helm binaries from ose-cli-rhel9
- Base image: ose-must-gather-rhel9 (UBI-based, FIPS-capable)
- Inherits host system crypto policies

Cross-Distribution Support:
- OpenShift: uses oc adm inspect (native)
- AKS/EKS/CoreWeave: uses kubectl_inspect fallback
  - Auto-discovers API resources per namespace
  - Collects pod logs in parallel
  - Same container image works across all distributions
