FIPS Compliance:
- Build flags: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- All four shipped binaries: eval-hub, eval-runtime-sidecar, eval-runtime-init, evalhub-mcp
- Linking: Dynamic (CGO) against system OpenSSL via UBI9
- Base image: UBI9 ubi-minimal
- Crypto: stdlib crypto/tls routed through OpenSSL via strictfipsruntime
- No non-FIPS crypto risks detected

Authentication & Authorization Summary:
- /api/v1/evaluations/* endpoints: Conditional X-User + X-Tenant header enforcement
  - Cluster mode: Headers required (enforced by identity middleware)
  - Local/dev mode: Headers bypassed
- /health, /docs, /openapi.yaml: No authentication required
- Kubernetes API: ServiceAccount kubeconfig credential chain
- Design assumption: Perimeter authentication configured correctly in production

Security Evidence:
- TLS config: crypto/tls (stdlib), google.golang.org/grpc/credentials
- InsecureSkipVerify recently removed from API client (commit fdc0346)
- Per-target TLS configuration: MLflow, OCI registry, eval-hub client, model endpoint
- Custom CA certificate bundle paths configurable per integration target

Secrets:
- Kubernetes Secrets mounted into sidecar for credential injection
- Sidecar reads Secret values and injects into proxied requests
- Evaluation adapter never accesses raw API keys directly
