RBAC Summary:
- SDK defines NO ClusterRoles or RoleBindings itself
- All RBAC is delegated to the Kubernetes cluster and Kubeflow control plane
- SDK consumers must ensure their kubeconfig/ServiceAccount has appropriate
  permissions on Kubeflow CRDs (trainjobs, experiments, sparkconnects)

Authentication & Authorization:
- External access: kubeconfig (client certificate or token-based)
  via kubernetes.config.load_kube_config()
- In-cluster access: ServiceAccount token mounted at
  /var/run/secrets/kubernetes.io/serviceaccount/token
  via kubernetes.config.load_incluster_config()
- No SDK-level auth middleware — fully delegated to kubernetes Python client
- pyjwt dependency is transitive only (not directly used by SDK)

Secrets:
- No secrets are created, managed, or stored by the SDK
- Credentials are sourced from kubeconfig file or SA token mount
- S3/storage credentials (if used) are managed externally via storage-config Secret

FIPS Compliance:
- Pure Python client library — no compiled binaries
- TLS/cryptography delegated to host Python runtime's OpenSSL
- cryptography package (v46.0.5) is transitive, not directly imported
- FIPS compliance depends on host Python installation's OpenSSL linkage

Network Posture:
- SDK is a CLIENT LIBRARY — no listening ports, no inbound connections
- All traffic is OUTBOUND to Kubernetes API server only
- No service mesh sidecar needed (not a deployed service)
