NAMESPACES:
- redhat-ods-operator / opendatahub-operator-system: Platform operator
- redhat-ods-applications / opendatahub: Platform applications and controllers
- openshift-ingress: Gateway infrastructure (data-science-gateway)
- kserve: KServe controllers (4 processes)
- models-as-a-service: MaaS API and controller
- kuadrant-system: Kuadrant/Authorino controllers
- {user-namespaces}: User workloads (inference, notebooks, pipelines, training)

GATEWAY ARCHITECTURE:
- Primary: Gateway API through data-science-gateway (central, shared)
- MaaS: maas-default-gateway (capability-specific, Kuadrant-authenticated)
- Legacy: OpenShift Routes (backward compatibility, TLS termination at router)
- Relationship between data-science-gateway and maas-default-gateway is unresolved
  (may be same Gateway with different names, or distinct resources)
- Istio integration: conditional (EnvoyFilter/DestinationRule only when CRDs detected)

AUTHENTICATION SUMMARY (4 patterns):
1. kube-auth-proxy OIDC (gateway-level, dashboard)
2. Kuadrant/Authorino AuthPolicy (gateway-level, MaaS + serving)
3. kube-rbac-proxy sidecar (pod-level, SubjectAccessReview)
4. Application-level TokenReview/SAR (in-code, BFF sidecars)

ADMISSION WEBHOOKS:
- Total: 210 webhooks across 17 components
- All use Fail policy (fail-closed)
- Cross-component targets: rhods-operator -> prometheus-operator PodMonitors,
  odh-model-controller -> kserve InferenceServices,
  workbenches-operator -> kubeflow Notebooks

RBAC SUMMARY:
- Total RBAC entries: 1658 across all components
- Most privileged: ai-gateway-operator (128 entries, 10+ API groups)
- Module operators: independent SA, ClusterRoles, leader election per process
- 19+ operators/controllers with dedicated RBAC identities

ISTIO / SERVICE MESH:
- Mode: Conditional (when Istio/SAIL CRDs detected on cluster)
- mTLS: STRICT for llm-d ModelExpress gRPC control plane
- Platform-wide mTLS depends on Istio deployment presence
- EnvoyFilter: created by rhods-operator (dashboard), odh-model-controller
- DestinationRule: created by rhods-operator, kserve llmisvc

TLS CONFIGURATION:
- Platform TLS profile alignment: operators read OpenShift APIServer TLS profile
- Fallback: TLS 1.2 + Mozilla Intermediate cipher suites
- Webhook TLS: service-CA provisioned certificates
- Components aligning: rhods-operator, kserve, odh-model-controller,
  model-registry-operator, workbenches-operator, trainer

FIPS POSTURE:
- All shipped Go binaries: CGO_ENABLED=1 + GOEXPERIMENT=strictfipsruntime
- Python components: inherit FIPS from UBI 9 base OpenSSL
- Base images: UBI 9 (FIPS-validated OpenSSL)
- Exception: upstream KServe core manager uses CGO_ENABLED=0 (overridden by Konflux)
