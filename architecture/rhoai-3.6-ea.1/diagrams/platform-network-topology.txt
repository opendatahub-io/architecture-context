NAMESPACES:
- redhat-ods-operator: Platform operator (OLM-installed rhods-operator)
- redhat-ods-applications: 25+ operator controllers + platform services
- User data science projects: Per-project workloads (models, notebooks,
  pipelines, training, registry instances)
- openshift-ingress / istio-system: Gateway data planes, Envoy proxies

INGRESS ARCHITECTURE (Multi-Generation):
- Gateway API HTTPRoute: models-as-a-service, model-registry-operator,
  ai-gateway-operator, ai-gateway-payload-processing, kserve
- Istio VirtualService: data-science-pipelines, model-registry (internal),
  kserve InferenceGraph
- OpenShift Routes: model-registry, trustyai, kube-auth-proxy, odh-dashboard
- Envoy ExtProc gRPC: llm-d-router EPP (LLM-optimized request routing)

AUTHENTICATION LAYERS:
- Gateway layer: Kuadrant AuthPolicy (API key, TokenReview, OIDC JWT)
- Route layer: kube-auth-proxy (OAuth2/OIDC -> cookie -> x-forwarded-access-token)
- Pod layer: kube-rbac-proxy sidecar (Kubernetes SubjectAccessReview)
- Application layer: ServiceAccount tokens, bearer tokens

WEBHOOK DENSITY:
- 16 components register 30+ unique webhook configurations
- All use Fail failure policy (webhook unavailability blocks API operations)
- Cross-component: odh-model-controller intercepts kserve CRDs and core Pods
- Both kserve and odh-model-controller register pod-mutating webhooks

RBAC HIGHLIGHTS (Most Privileged):
- ai-gateway-operator: 57 RBAC rules spanning Gateway API, cert-manager,
  Kuadrant, Istio, MaaS, llm-d, KServe, OpenTelemetry
- rhods-operator: Cluster-wide lifecycle management (19 CRDs)
- kserve-controller-manager: 13 CRDs, Gateway API, Istio integration
- odh-model-controller: Cross-component webhook interception
