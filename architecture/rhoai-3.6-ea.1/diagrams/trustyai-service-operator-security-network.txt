  - API Groups: authentication.k8s.io, authorization.k8s.io
  - Resources: tokenreviews, subjectaccessreviews
  - Verbs: create

- ClusterRole: tls-profile-reader
  - API Groups: config.openshift.io
  - Resources: apiservers
  - Verbs: get

- Role: leader-election-role (namespace: system)
  - API Groups: core, coordination.k8s.io
  - Resources: configmaps, leases, events
  - Verbs: create, delete, get, list, patch, update, watch

TLS Configuration:
- Cluster TLS profile: Resolved from OpenShift APIServer config
- Default fallback: Mozilla Intermediate (TLS 1.2+)
- Cipher suites: ECDHE-AES-128-GCM, ECDHE-AES-256-GCM, ECDHE-ChaCha20-Poly1305
- FIPS mode: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1 (OpenSSL backend)

Secrets:
- {instance-name}-tls (kubernetes.io/tls) - TLS cert for kube-rbac-proxy, controller template
- {instance-name}-internal (Opaque) - Internal service creds, controller template
- {instance-name}-db-ca (Opaque) - Database CA certificate, controller template

Authentication Flows:
- TrustyAI Service API: kube-rbac-proxy performs TokenReview + SubjectAccessReview
- Operator → K8s API: ServiceAccount token (in-cluster)
- Health probes (:8081, :9443): Unauthenticated by design
