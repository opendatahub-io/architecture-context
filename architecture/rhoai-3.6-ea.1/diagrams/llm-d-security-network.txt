RBAC Summary:
- No ClusterRoles or RoleBindings defined in the llm-d repository.
- RBAC is expected to be provided by the platform or operator that deploys llm-d.

Service Mesh Configuration:
- PeerAuthentication: STRICT (for ModelExpress gRPC on port 8001)
- AuthorizationPolicy: Restricts ModelExpress access to decode ServiceAccount principals only
- NOTE: RDMA data-plane traffic (ports 5555, 6555) bypasses the service mesh entirely.
  This is a deliberate design trade-off documented in:
  guides/modelexpress-p2p/security/istio-mtls-authz.yaml

Authentication & Authorization Summary:
- Model server HTTP API (port 8000): NO built-in authentication
  → Relies on platform network policy or service mesh authorization
- ModelExpress gRPC API (port 8001): Istio mTLS STRICT + AuthorizationPolicy
  → Only decode ServiceAccount principals allowed
- P2P RDMA ports (5555, 6555): No authentication or encryption
  → RDMA bypass, outside service mesh

- HF_TOKEN (model download credentials) - provisioning mechanism not specified
- No TLS secrets or cert-manager configuration defined in the repository
