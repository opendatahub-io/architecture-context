- /validate-ray-io-v1-raycluster (validating, failurePolicy: fail)
  - Operations: CREATE, UPDATE on rayclusters
- /validate-ray-io-v1-rayjob (validating, failurePolicy: fail)
  - Operations: CREATE, UPDATE on rayjobs
- /validate-ray-io-v1-rayservice (validating, failurePolicy: fail)
  - Operations: CREATE, UPDATE on rayservices

RBAC Summary (kuberay-operator ClusterRole):
- ray.io: rayclusters, rayjobs, rayservices, raycronjobs (full CRUD + finalizers/status)
- core: pods, services, secrets, configmaps, serviceaccounts, events (full CRUD)
- apps: deployments (get, list, patch, update, watch)
- batch: jobs (full CRUD)
- cert-manager.io: certificates, issuers (full CRUD)
- gateway.networking.k8s.io: gateways, httproutes, referencegrants (full CRUD)
- networking.k8s.io: networkpolicies, ingresses (full CRUD)
- route.openshift.io: routes (full CRUD)
- rbac.authorization.k8s.io: roles, rolebindings (CRUD), clusterroles, clusterrolebindings (read)
- authentication.k8s.io: tokenreviews (create)
- authorization.k8s.io: subjectaccessreviews (create)
- operator.openshift.io: kubeapiservers (read)

Network Isolation:
- NetworkPolicyController creates per-RayCluster NetworkPolicy resources
- Ray inter-node mTLS via cert-manager Certificate resources
- Operator webhook server uses OpenShift cluster-wide TLS profile (Intermediate default)

FIPS Compliance:
- Build: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime, -tags strictfipsruntime
- Linking: Dynamic (delegates crypto to OpenSSL via UBI9 base image)
- TLS: Intermediate profile (TLS 1.2+, ECDHE cipher suites, FIPS-approved algorithms)
- No explicit FIPS mode runtime assertion in application code

Secrets:
- No application-managed secrets documented
- cert-manager provisions TLS certificates for webhooks and inter-node mTLS
- ServiceAccount tokens used for Kubernetes API authentication
