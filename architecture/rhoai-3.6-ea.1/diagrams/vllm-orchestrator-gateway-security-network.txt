TLS Configuration:
- Gateway-to-Orchestrator TLS is CONDITIONAL:
  - mTLS ENABLED when certs present at /etc/tls/private/ (OpenShift service-ca injection)
  - Plain HTTP when no certificates are mounted
- OpenSSL PKCS#12 identity constructed at startup from PEM cert + key
- Cipher suites and protocol versions: system OpenSSL defaults (UBI9)
- No explicit FIPS mode flag (OPENSSL_FIPS=1 not set)
- FIPS compliance depends on runtime OpenSSL configuration of UBI9 base image

RBAC Summary:
- No cluster-scoped RBAC roles or bindings defined
- Gateway does not interact with Kubernetes API
- All authorization delegated to platform infrastructure and orchestrator

Secrets:
- No Kubernetes Secrets defined in component manifests
- TLS certificates expected via platform-injected volume mounts:
  - /etc/tls/private/tls.crt (client certificate)
  - /etc/tls/private/tls.key (client private key)
  - /etc/tls/ca/service-ca.crt (CA certificate)

Authentication & Authorization:

- Enforcement Point: Platform / Orchestrator (NOT gateway)
