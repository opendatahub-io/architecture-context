TLS Configuration:
- Outbound mTLS is OPTIONAL - depends on certificate availability
- When /etc/tls/private/ contains tls.crt and tls.key:
  - Gateway builds PKCS#12 identity from certificates via OpenSSL
  - Connects to orchestrator over HTTPS with client certificate
  - CA bundle loaded from /etc/tls/ca/service-ca.crt
- When certificates absent:
  - Gateway connects to orchestrator over plain HTTP
  - No encryption on backend connection

Crypto Provider:
- Uses openssl (0.10.73) and native-tls (0.2.12) Rust crates
- Delegates to system OpenSSL library (not rustls)
- On UBI 9: OpenSSL 3.0, FIPS-capable when system FIPS mode enabled
- No explicit FIPS mode selection or cipher suite configuration in code
- FIPS compliance depends entirely on host system configuration

RBAC Summary:
- No ClusterRoles defined
- No RoleBindings defined
- Gateway does not enforce any RBAC or authentication locally

Secrets:
- TLS certificates mounted at /etc/tls/private/ (optional)
  - tls.crt: Client certificate for mTLS
  - tls.key: Client private key for mTLS
- CA bundle at /etc/tls/ca/service-ca.crt (optional)
- No application-level secrets management

Authentication & Authorization:
- Endpoint: /{route_name}/v1/chat/completions
- Auth Mechanism: Header passthrough (Authorization)
- Enforcement: None at gateway level
- Policy: Gateway forwards Authorization and x-forwarded-* headers
         to orchestrator backend; no local enforcement
