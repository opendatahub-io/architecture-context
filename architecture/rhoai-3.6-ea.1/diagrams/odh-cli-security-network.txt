RBAC Summary:
- No ClusterRoles/RoleBindings defined by odh-cli itself
- CLI operates with the user's kubeconfig credentials (user-scoped RBAC)
- RBAC pre-flight: SelfSubjectAccessReview before privileged operations
  - API Group: authorization.k8s.io
  - Resource: selfsubjectaccessreviews
  - Verbs: create
- Actual permissions depend on the user's cluster role bindings

Authentication & Authorization:
- Primary: kubeconfig credential chain
  - Bearer token
  - Client certificate
  - OIDC token
- TrustYAI migration: Bearer token forwarded from kubeconfig REST config
- MCP server: Inherits kubeconfig credentials (no additional auth layer)

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Crypto: OpenSSL via UBI/RHEL 9 base image (ose-cli-rhel9)
- TLS: MinVersion TLS 1.2 enforced
- Risk: InsecureSkipVerify on TrustYAI connections (cert validation bypass,
        not a FIPS bypass)

Secrets:
- No secrets provisioned by odh-cli
- Uses kubeconfig credentials from user's environment
- TrustYAI bearer token extracted from kubeconfig REST config at runtime

Network Exposure:
- MCP SSE mode: 8080/TCP HTTP (no TLS, no auth on transport)
  - Risk: Network-accessible JSON-RPC endpoint with no encryption
  - Mitigation: Optional mode, user-invoked, inherits kubeconfig auth
- MCP stdio mode: No network exposure (process-local)
