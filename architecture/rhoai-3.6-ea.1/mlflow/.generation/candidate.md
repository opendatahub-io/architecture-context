**Detailed**: MLflow is deployed as a containerized tracking server on port 5000, serving the MLflow UI, REST API, and artifact proxy behind the `kubernetes-auth` authentication plugin from the external `mlflow-kubernetes-plugins` package (v1.5.0). The server runs Python 3.12 under gunicorn/uvicorn on a UBI9-minimal base image, with Kubernetes service account bearer tokens providing authentication and the `mlflow/server/auth` module enforcing RBAC-based authorization with roles, permissions, and per-resource access control. The `--enable-workspaces` flag activates multi-tenant workspace isolation backed by a Kubernetes workspace store (`kubernetes://`), where each workspace maps to a Kubernetes namespace. The component surface includes 6 architecture components—the container entrypoint, gunicorn and uvicorn ASGI/WSGI servers, the mlflow and mlflow-skinny Python services, and the mlflow-tracing SDK—exposing 48 HTTP endpoints for experiment tracking, model registry, gateway proxy, assistant, job execution, and MCP server APIs. External integrations include S3-compatible storage via boto3, Google Cloud Storage, and the Kubernetes API for project execution as Jobs. ## Architectural Analysis

MLflow operates in RHOAI as a multi-tenant experiment tracking and model registry server. The container entrypoint (`Dockerfile.konflux:80`) starts the MLflow tracking server with three key flags that define its RHOAI-specific behavior: `--app-name kubernetes-auth` loads the server-side authentication plugin from the separately packaged `mlflow-kubernetes-plugins` (v1.5.0, installed from PyPI via hermetic Konflux build), `--enable-workspaces` activates namespace-scoped workspace isolation, and `--workspace-store-uri kubernetes://` delegates workspace storage to the Kubernetes API. [source: Dockerfile.konflux:80, requirements/konflux-pypi.in:13]

The authentication architecture has two layers. On the server side, the `--app-name kubernetes-auth` entry point loads an auth middleware plugin that intercepts API requests. On the client side, `mlflow/tracking/request_auth/kubernetes_request_auth_provider.py` provides two auth providers activated via `MLFLOW_TRACKING_AUTH`: `kubernetes` (bearer token only) and `kubernetes-namespaced` (bearer token plus `X-MLFLOW-WORKSPACE` header derived from the pod's service account namespace). Both resolve credentials from the Kubernetes service account token file at `/var/run/secrets/kubernetes.io/serviceaccount/token`, falling back to kubeconfig when running outside a cluster. The core `mlflow/server/auth/__init__.py` module provides RBAC enforcement with role-based permissions, per-resource access control for experiments, registered models, gateway endpoints, and workspaces. [source: mlflow/tracking/request_auth/kubernetes_request_auth_provider.py:1-11, 38-41, 203-294, mlflow/server/auth/__init__.py:229-367, mlflow/server/__init__.py:218-226]

The Kubernetes API integration serves two distinct purposes: project execution (creating and monitoring Kubernetes Jobs for ML experiment runs via `mlflow/projects/kubernetes.py`) and workspace management (the `kubernetes://` workspace store URI). The project execution path uses the `kubernetes` Python client to construct Job manifests, push container images, and poll Job status. [source: mlflow/projects/kubernetes.py:8-9, 32-49, Dockerfile.konflux:80]

The RHOAI container disables several upstream features via environment variables: `MLFLOW_ENABLE_AI_GATEWAY=false`, `MLFLOW_ENABLE_ASSISTANT=false`, `MLFLOW_SERVER_ENABLE_JOB_EXECUTION=false`, and `MLFLOW_DISABLE_TELEMETRY=true`. This means the gateway and assistant HTTP endpoints present in the codebase are not active in the default RHOAI deployment. [source: Dockerfile.konflux:38-43]

## Data Flows

- **Entry and service surface:** Clients connect to the MLflow Tracking Server on port 5000. The `kubernetes-auth` plugin intercepts inbound requests and validates Kubernetes service account bearer tokens from the `Authorization` header. When workspaces are enabled, the `X-MLFLOW-WORKSPACE` header routes requests to the appropriate namespace-scoped workspace. The Flask application dispatches authenticated requests to tracking, model registry, artifact, gateway proxy, assistant, job, and MCP server API handlers. The `mlflow-skinny` service identity exposes the same surface with a minimal dependency set. [source: Dockerfile.konflux:76-80, mlflow/server/__init__.py:68-88, mlflow/tracking/request_auth/kubernetes_request_auth_provider.py:229-258]
- **Runtime inventory:** The container runs gunicorn or uvicorn as the ASGI/WSGI server, hosting the Flask-based MLflow tracking server. The 6 runtime components form a layered stack: the container entrypoint invokes `mlflow server`, which initializes the Flask app with security middleware, endpoint routing, workspace handlers, and optional Prometheus metrics export. The mlflow-tracing SDK is packaged alongside but operates as a client-side instrumentation library. [source: Dockerfile.konflux:80, mlflow/server/__init__.py:68-96]
- **Downstream interactions:** The tracking server stores experiment metadata in a SQL backend (PostgreSQL via psycopg2, or SQLite) and manages artifacts via a pluggable store that can target S3-compatible storage (boto3), Google Cloud Storage, or local filesystem. The Kubernetes API is used for workspace management (`kubernetes://` store URI) and optionally for project execution as Kubernetes Jobs. External LLM provider integrations (OpenAI, AWS Bedrock) are available in the codebase but the AI Gateway feature is disabled by default in RHOAI (`MLFLOW_ENABLE_AI_GATEWAY=false`). [source: Dockerfile.konflux:38-43, 50, mlflow/projects/kubernetes.py:8-9, 32-49, mlflow/gateway/providers/bedrock.py:212, mlflow/deployments/openai/__init__.py:175]
- **Security context:** The `kubernetes-auth` plugin and RBAC module enforce authentication and authorization across all tracking server endpoints. 19 environment-variable secrets reference API keys for external LLM providers (OpenAI, Anthropic, Cohere, Mistral, etc.) and cloud storage credentials. The `cryptography` package (>=43.0.0) provides TLS support via OpenSSL on the UBI9 base image. [source: mlflow/server/auth/__init__.py:229-367, mlflow/tracking/request_auth/kubernetes_request_auth_provider.py:38-41, pyproject.toml:37]
