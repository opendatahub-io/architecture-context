## Purpose

**Short**: Kubernetes operator that manages the AI Gateway component for RHOAI, orchestrating Gateway API routing, Kuadrant auth/rate-limiting policies, Istio service mesh resources, and llm-d batch gateway lifecycles for model-as-a-service workloads. [source: cmd/main.go:30, config/rbac/role.yaml:2, internal/controller/aigateway/aigateway_controller.go:136]

**Detailed**: The ai-gateway-operator is a standalone controller-runtime operator that reconciles the cluster-scoped `AIGateway` custom resource (`components.platform.opendatahub.io/v1alpha1`). It implements a module operator pattern from the opendatahub-operator SDK, using kustomize-based manifest rendering and ordered deployment actions to manage a broad set of downstream resources. The operator's primary responsibility is to create and maintain the infrastructure for AI model serving via Gateway API (HTTPRoutes, Gateways, ReferenceGrants), enforce authentication and rate-limiting through Kuadrant AuthPolicies and TokenRateLimitPolicies, manage TLS certificates through cert-manager, and configure Istio service mesh resources (DestinationRules, EnvoyFilters, ServiceEntries). It watches DSCInitialization and KServe InferenceService CRs to coordinate with platform-level initialization and model serving state. The operator also manages the llm-d batch gateway sub-component when `spec.batchGateway.managementState` is set to Managed, providing full lifecycle control over `LLMBatchGateway` resources. Configuration is loaded from mounted ConfigMap files and environment variables with the `ODH_MODULE_OPERATOR_` prefix. [source: cmd/operator/operator.go:69-153, pkg/config/config.go:70-95, internal/controller/aigateway/aigateway_controller.go:125-174]

## Architectural Analysis

The ai-gateway-operator follows the ODH module operator pattern, embedding the `opendatahub-operator/v2` SDK to share reconciliation primitives (kustomize rendering, ordered deploy actions, garbage collection, status reporting) with the platform operator while running as an independent process. This design allows the AI Gateway component to have its own release cadence and operator lifecycle separate from the main ODH operator, with the `AIGateway` CR acting as the component-level activation toggle.

The reconciliation pipeline is action-based: `initialize → ensureInfraSecretMigrationRBAC → upgradeIfNeeded → releases → kustomize render → annotateResource → migrateSelector → deploy → reportSubModuleStatus → reportStatus → gc`. This ordered chain ensures infrastructure RBAC and upgrades complete before manifest rendering, and garbage collection runs last to clean up orphaned resources. The operator owns a wide surface of child resources (ConfigMaps, Deployments, Services, ServiceAccounts, RBAC objects, CRDs, ValidatingWebhookConfigurations) and uses controller-runtime's `Owns()` to trigger re-reconciliation when they drift.

A notable architectural characteristic is the operator's role as an integration hub: it manages Kuadrant AuthPolicies and TokenRateLimitPolicies for API authentication and rate limiting, Istio networking resources (DestinationRules, EnvoyFilters, ServiceEntries) for service mesh integration, Gateway API HTTPRoutes for traffic routing, cert-manager Certificates for TLS, and OpenTelemetry collectors and Perses dashboards for observability. This positions the operator as the single control point for the MaaS (Model-as-a-Service) infrastructure stack, creating a wide RBAC footprint (57 rules in the manager role) that spans multiple API groups.

The operator reads ConfigMaps and Secrets without caching (`DisableFor` in the client options) to ensure it always sees fresh values for sensitive or frequently-changing data. Leader election is enabled by default with a configurable lock name, supporting high-availability deployments. The FIPS-compliant build uses `GOEXPERIMENT=strictfipsruntime` with dynamic linking (`CGO_ENABLED=1`) on a UBI9 base image, routing Go cryptographic operations through the system OpenSSL provider. ## Data Flows

- **Reconciliation trigger:** The operator watches `AIGateway` CRs (cluster-scoped) and owned child resources. When an `AIGateway` CR is created or modified, the reconciler executes an ordered action chain: initialization, RBAC migration, upgrade checks, release metadata, kustomize rendering, annotation, selector migration, deployment, status reporting, and garbage collection. [source: internal/controller/aigateway/aigateway_controller.go:136-174, cmd/operator/operator.go:142-144]
- **Platform coordination:** The operator reads `DSCInitialization` CRs to obtain platform initialization state and `KServe InferenceService` / `LLMInferenceService` CRs to observe model serving status.
