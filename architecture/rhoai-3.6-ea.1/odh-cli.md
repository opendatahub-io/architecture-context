## Purpose

**Short**: A Cobra-based kubectl plugin (`kubectl-odh` / `rhai-cli`) that provides operational diagnostics, migration assistance, component inspection, and an MCP server for AI agent integration with RHOAI clusters. [source: cmd/main.go:27, Dockerfile.konflux:60]

**Detailed**: odh-cli is a Go CLI application distributed as a kubectl plugin and a standalone container image (`rhai-cli`). It connects to Kubernetes clusters via the standard kubeconfig credential chain and provides subcommands for platform diagnostics (`diagnose`), component status inspection (`status`, `components`, `get`), operator migration (`migrate`), event streaming (`events`, `logs`), dependency analysis (`deps`), manifest linting (`lint`), and API resource queries (`api`). The CLI also embeds a Model Context Protocol (MCP) server that exposes all CLI operations as typed tool calls for AI agent consumption over stdio or SSE transports. Migration actions include TrustYAI metrics backup/restore via direct HTTPS calls to TrustYAI service routes. The tool imports runtime packages from the opendatahub-operator for cluster health assessment and failure classification, and uses OLM client libraries for operator lifecycle inspection. [source: cmd/main.go:27-53, cmd/mcp/mcp.go:17-33, pkg/migrate/actions/trustyai/metrics/http.go:29-36, pkg/diagnose/format.go:8]

## Architectural Analysis

odh-cli follows a standard Cobra command-tree pattern with a central Kubernetes client abstraction (`pkg/util/client`) that wraps dynamic, discovery, OLM, metadata, and typed API clients behind a single `Client` interface. All subcommands receive `genericclioptions.ConfigFlags` for kubeconfig resolution, inheriting kubectl-standard authentication flags (--token, --kubeconfig, --context, --certificate-authority, --client-certificate, --client-key, --insecure-skip-tls-verify). The client performs RBAC pre-flight checks via `SelfSubjectAccessReview` before privileged operations, providing early user-facing errors for insufficient permissions. [source: cmd/main.go:28-39, pkg/util/client/client.go:70-117, pkg/util/kube/rbac/check.go:36-71]

The migration subsystem is architecturally notable: TrustYAI metrics migration connects directly to TrustYAI service OpenShift Routes (discovered by label or name) over HTTPS with bearer token authentication forwarded from the kubeconfig REST config. The TLS client uses `InsecureSkipVerify` for in-cluster self-signed certificates with a minimum of TLS 1.2. This is an outbound HTTP client interaction, not a server endpoint. [source: pkg/migrate/actions/trustyai/metrics/http.go:43-68, pkg/migrate/actions/trustyai/metrics/http.go:122-149]

The MCP server capability (`mcp serve`) extends the CLI into an agent-accessible tool server. In SSE mode, it binds to a configurable HTTP port (default 8080) for network-accessible JSON-RPC; in stdio mode, it communicates over stdin/stdout for container and CI use. The MCP tool definitions are sourced from the opendatahub-operator's `mcptools` package. [source: cmd/mcp/mcp.go:17-34, cmd/mcp/mcp.go:58-65]

The build pipeline targets FIPS compliance: the Konflux Dockerfile uses `CGO_ENABLED=1`, `GOEXPERIMENT=strictfipsruntime`, and `-tags strictfipsruntime`, ensuring the Go runtime uses OpenSSL from the UBI base image rather than pure-Go crypto. The runtime image is based on `ose-cli-rhel9`, which inherits OpenSSL from the RHEL 9 userspace. [source: Dockerfile.konflux:32-36, Dockerfile.konflux:43]
