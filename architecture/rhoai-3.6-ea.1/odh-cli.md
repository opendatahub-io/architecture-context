## Purpose

**Short**: Cobra-based kubectl plugin (branded `rhai-cli`) for operating, diagnosing, migrating, and linting RHOAI platform deployments. [source: cmd/main.go:28, Dockerfile.konflux:53]

**Detailed**: odh-cli is a Go CLI application that functions as a kubectl plugin (`kubectl-odh` / `rhai-cli`) for managing Red Hat OpenShift AI deployments. It provides subcommands for platform status inspection, component diagnostics with failure classification, serving runtime migration (including serverless-to-raw conversion and KServe webhook bypass), DSC/DSCI configuration linting with MaaS modularization support, event aggregation, log collection, and dependency analysis. The CLI also embeds a Model Context Protocol (MCP) server that can expose all CLI operations as typed tool calls for AI agent integration via stdio or SSE transport. Authentication delegates entirely to the kubeconfig credential chain inherited from the user's environment, with RBAC pre-flight checks via SelfSubjectAccessReview before privileged operations. The tool is packaged as a container image based on `ose-cli-rhel9` with FIPS-compliant build flags (`GOEXPERIMENT=strictfipsruntime`, `CGO_ENABLED=1`). [source: cmd/main.go:28-56, Dockerfile.konflux:32-35, Dockerfile.konflux:53, pkg/util/kube/rbac/check.go:49-60]

## Architectural Analysis

odh-cli follows a standard Cobra command-tree pattern with a root `kubectl-odh` command and thirteen subcommands (`api`, `completion`, `components`, `deps`, `diagnose`, `events`, `get`, `lint`, `logs`, `mcp`, `migrate`, `status`, `version`), each registered in `cmd/main.go`. All subcommands share a `genericclioptions.ConfigFlags` instance that provides standard kubectl authentication flags (`--kubeconfig`, `--token`, `--context`, etc.) and produces a `rest.Config` used by a unified client layer in `pkg/util/client/`. This client layer wraps dynamic, discovery, OLM, API-extensions, metadata, core, and authorization clients into a single `Client` interface, enabling the CLI to operate across arbitrary Kubernetes resource types without code-generated clients. [source: cmd/main.go:29-56, pkg/util/client/client.go:34-44, pkg/util/client/client.go:70-117]

The migration subsystem (`pkg/migrate/`) includes a TrustYAI metric migration action that discovers TrustYAI Service OpenShift Routes and performs HTTP backup/restore of metric scheduling requests. This is the only outbound HTTP interaction outside the Kubernetes API, using Bearer token authentication inherited from the kubeconfig and TLS 1.2+ with certificate verification disabled for in-cluster self-signed routes. [source: pkg/migrate/actions/trustyai/metrics/http.go:43-68, pkg/migrate/actions/trustyai/metrics/http.go:122-149]

The diagnostics subsystem imports `opendatahub-operator` packages (`clusterhealth`, `failureclassifier`, `mcptools`) for health classification and MCP tool definitions, creating a direct runtime-library dependency on the platform operator. The MCP server mode (`kubectl odh mcp serve`) exposes all CLI operations as MCP tool calls, supporting stdio (default) and SSE (HTTP on `127.0.0.1:8080`) transports for AI agent integration. The SSE transport binds to localhost only and is user-initiated, not a persistent service. [source: pkg/diagnose/format.go:8, pkg/mcp/server.go:35-52, pkg/mcp/server.go:81-108, cmd/mcp/mcp.go:24-34]

The build uses a two-stage Dockerfile with `ubi9/go-toolset:1.26` for compilation and `ose-cli-rhel9` as the runtime base. FIPS compliance is enforced at build time via `GOEXPERIMENT=strictfipsruntime` and `CGO_ENABLED=1`, ensuring the Go binary links dynamically against OpenSSL for FIPS-validated cryptography. [source: Dockerfile.konflux:2, Dockerfile.konflux:32-35, Dockerfile.konflux:43]

## Data Flows

- **Kubernetes API operations:** All subcommands authenticate via the kubeconfig credential chain, constructing a unified client (`pkg/util/client/`) that wraps dynamic, discovery, OLM, API-extensions, and core Kubernetes clients. Before privileged operations, the CLI performs RBAC pre-flight checks by creating `SelfSubjectAccessReview` resources. Interactions traverse the standard Kubernetes API at port 6443 with TLS 1.2+ encryption. [source: cmd/main.go:29, pkg/util/client/client.go:70-117, pkg/util/kube/rbac/check.go:49-60]
- **TrustYAI metric migration:** The `migrate` subcommand includes a TrustYAI action that discovers an OpenShift Route for the TrustYAI Service (by label or name), then performs HTTP GET to back up metric scheduling requests and HTTP POST to restore them. Authentication uses the Bearer token from the kubeconfig REST config. TLS 1.2+ is enforced but certificate verification is disabled for in-cluster self-signed routes. [source: pkg/migrate/actions/trustyai/metrics/http.go:29-36, pkg/migrate/actions/trustyai/metrics/http.go:43-68, pkg/migrate/actions/trustyai/metrics/http.go:122-149]
- **OLM inspection:** The CLI queries OLM ClusterServiceVersions and Subscriptions to inspect operator lifecycle state for diagnostics, dependency analysis, and status reporting. [source: pkg/util/client/client.go:87-90, pkg/util/client/client.go:115]
- **MCP server (optional):** When invoked via `mcp serve`, the CLI registers all subcommands as MCP tools and serves them over stdio (default) or SSE HTTP transport. The SSE transport binds to `127.0.0.1` only and does not authenticate MCP clients; security relies on localhost-only binding and process-level kubeconfig credentials.
