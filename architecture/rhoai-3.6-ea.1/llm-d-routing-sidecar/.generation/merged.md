## Purpose

**Short**: Reverse proxy sidecar for llm-d disaggregated prefill/decode inference, routing OpenAI-compatible completion requests between co-located vLLM decoder and remote prefiller pods using NIXL v2, NIXL v1, or LMCache protocols. [source: cmd/llm-d-routing-sidecar/main.go:30-33, internal/proxy/proxy.go:55-62, internal/proxy/chat_completions.go:24-28]

**Detailed**: llm-d-routing-sidecar is a Go reverse proxy deployed as a sidecar container alongside a vLLM inference engine. It intercepts OpenAI-compatible chat completion and completion requests (`/v1/chat/completions`, `/v1/completions`) and implements disaggregated prefill/decode (P/D) inference by routing prefill requests to remote pods when specified via HTTP headers (`x-prefiller-host-port`). When no prefill target is specified, requests pass through to the co-located vLLM decoder on localhost. The sidecar supports three P/D connector protocols: NIXL v2 (default), NIXL v1 (deprecated), and LMCache (deprecated). It includes optional SSRF protection that watches Gateway API InferencePool resources (`inference.networking.x-k8s.io/v1alpha2`) via the Kubernetes API to maintain a dynamic allowlist of permitted prefill targets based on pod IPs. TLS is configurable for both the proxy listener (enabled by default with self-signed certificates) and upstream connections to prefiller/decoder endpoints. [source: cmd/llm-d-routing-sidecar/main.go:30-109, internal/proxy/proxy.go:64-146, internal/proxy/allowlist.go:41-44, internal/proxy/chat_completions.go:31-58]

## Architectural Analysis

llm-d-routing-sidecar implements the sidecar proxy pattern for disaggregated prefill/decode (P/D) inference in the llm-d platform. It runs as a co-located container alongside a vLLM decoder instance, intercepting all OpenAI-compatible API traffic and selectively routing prefill operations to remote pods when the `x-prefiller-host-port` header is present. The design separates the routing concern from the inference engine, allowing the vLLM decoder to remain unmodified while the sidecar handles the P/D protocol orchestration.

The proxy supports three connector protocols — NIXL v2 (default and actively maintained), NIXL v1 (deprecated), and LMCache (deprecated) — selectable at startup. This connector abstraction isolates the protocol-specific request mutation and forwarding logic from the common routing and SSRF-protection path. The sidecar maintains an LRU cache of reverse proxy handlers for prefiller endpoints, avoiding repeated URL parsing and handler construction for frequently-targeted pods.

A notable security feature is the optional SSRF protection system, which uses Kubernetes informers to watch InferencePool custom resources from the Gateway API Inference Extension (`inference.networking.x-k8s.io/v1alpha2`). When enabled, it dynamically builds an allowlist of permitted prefill targets from the pod IPs selected by the InferencePool's label selector, blocking requests to any prefill target not in the current pool membership. This prevents header-injection attacks from redirecting prefill traffic to arbitrary endpoints.

TLS is configurable at multiple points: the proxy listener defaults to TLS-enabled with either operator-provided certificates or auto-generated self-signed certificates, and upstream connections to both prefiller and decoder endpoints can independently enable TLS with optional certificate verification skip. The TLS configuration enforces a minimum of TLS 1.2 with a restricted set of ECDHE cipher suites. The component is noted as deprecated per README commits from late 2025. The upstream Dockerfile builds with `CGO_ENABLED=0`, producing a statically linked Go binary. This configuration would fail the Konflux check-payload FIPS gate, which requires dynamically linked Go binaries with OpenSSL present in the container image. The `ubi9/ubi-micro` base image is a minimal image that does not include OpenSSL libraries. No FIPS-related build flags (`GOEXPERIMENT=strictfipsruntime`, `-tags strictfipsruntime`) are present.
