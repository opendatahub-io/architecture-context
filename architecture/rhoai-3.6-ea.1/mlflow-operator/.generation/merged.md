## Purpose

**Short**: Kubernetes operator that manages the lifecycle of MLflow Tracking Server instances on OpenShift, including Helm-based deployment, Gateway API routing, namespace-scoped workspace RBAC, and integration with the RHOAI platform Auth service. [source: cmd/main.go:171, internal/controller/mlflow_controller.go:539, internal/controller/namespace_rbac_controller.go:67]

**Detailed**: mlflow-operator is a controller-runtime operator that reconciles three custom resources — `MLflow` (mlflow.opendatahub.io/v1), `MLflowOperator` (components.platform.opendatahub.io/v1alpha1), and `MLflowConfig` (mlflow.kubeflow.org/v1) — to deploy and manage MLflow Tracking Server instances on RHOAI. The MLflow controller renders Helm charts into Kubernetes resources (Deployments, Services, PersistentVolumeClaims, CronJobs, NetworkPolicies) and conditionally creates Gateway API HTTPRoutes, OpenShift ConsoleLinks, and Prometheus ServiceMonitors based on cluster capability discovery. A dedicated NamespaceRBACReconciler watches the platform Auth CRD (`services.platform.opendatahub.io/v1alpha1`) and labeled namespaces to propagate view/edit RoleBindings for workspace-level access control. The operator uses leader election, caches filtered by label selectors, and field-selector-scoped watches for shared RBAC objects to minimize API server load. [source: cmd/main.go:171, 272, 300, internal/controller/mlflow_controller.go:473-552, internal/controller/namespace_rbac_controller.go:48-106, internal/controller/routing.go:46-179]

## Architectural Analysis

mlflow-operator follows a multi-controller architecture built on controller-runtime v0.23.3. The primary **MLflowReconciler** owns the full lifecycle of MLflow Tracking Server deployments: it renders bundled Helm charts into Kubernetes objects (Deployments, Services, Secrets, ServiceAccounts, PersistentVolumeClaims, CronJobs, and NetworkPolicies) and applies them via server-side apply with owner references. The controller conditionally extends its watch surface at startup using the Kubernetes discovery API — adding Gateway API HTTPRoute, OpenShift ConsoleLink, and Prometheus ServiceMonitor watches only when those CRDs are present in the cluster. This discovery-gated pattern avoids hard dependencies on optional platform APIs. [source: internal/controller/mlflow_controller.go:528-552, internal/controller/routing.go:46-179]

The **MLflowOperatorReconciler** manages the component-level `MLflowOperator` CRD from `components.platform.opendatahub.io`, acting as the integration surface for the RHOAI platform operator (odh-operator). A dedicated **NamespaceRBACReconciler** watches namespaces labeled with `opendatahub.io/mlflow-workspace`, the platform Auth CRD (`services.platform.opendatahub.io/v1alpha1`), and MLflow CRs to propagate view/edit RoleBindings into workspace namespaces, enabling multi-tenant access isolation delegated through the platform's centralized auth configuration. [source: internal/controller/namespace_rbac_controller.go:48-106, internal/controller/mlflowoperator_controller.go:76-143]

The operator restricts its Kubernetes API footprint through label-selector-filtered caches (keyed on `app=mlflow`) and field-selector-scoped watches for shared RBAC objects (ClusterRole/ClusterRoleBinding filtered by `metadata.name`). Secret access is restricted via `resourceNames`-scoped RBAC to the single `mlflow-artifact-connection` secret per namespace. The metrics endpoint on port 8443 is protected by controller-runtime's TokenReview/SubjectAccessReview filter with TLS (self-signed or operator-provided certificates), while health and readiness probes on port 8081 are unauthenticated by design. FIPS compliance is enforced at build time via `GOEXPERIMENT=strictfipsruntime` and dynamic linking against OpenSSL on UBI9. [source: cmd/main.go:267-284, 293-318, Dockerfile.konflux:31-32, config/rbac/role.yaml:2]

## Data Flows

- **Control plane reconciliation:** The operator watches MLflow, MLflowOperator, and MLflowConfig CRs, ConfigMaps, and owned resources (Deployments, Services, Jobs, PVCs, Secrets, ServiceAccounts). On reconciliation, the MLflowReconciler renders Helm charts into Kubernetes objects and applies them via the Kubernetes API (port 6443, TLS, ServiceAccount token auth). Owned resources are label-filtered (`app=mlflow`) to minimize watch bandwidth. [source: cmd/main.go:293-318, internal/controller/mlflow_controller.go:473-552]
- **Conditional platform integration:** At startup, the operator probes the Kubernetes discovery API for Gateway API, ConsoleLink, ServiceMonitor, and MLflowOperator CRDs. When present, additional watches and owned-resource management are activated; when absent, the operator operates without those integrations. [source: internal/controller/routing.go:46-179, internal/controller/mlflow_controller.go:528-552]
- **Workspace RBAC propagation:** The NamespaceRBACReconciler watches the platform Auth CR (`services.platform.opendatahub.io/v1alpha1`), MLflow CRs, and labeled namespaces. When a namespace carries the `opendatahub.io/mlflow-workspace` label, the controller creates RoleBindings referencing the mlflow-view and mlflow-edit ClusterRoles, enabling workspace-scoped multi-tenant access. [source: internal/controller/namespace_rbac_controller.go:48-106, 135-154]
- **Metrics and observability:** The operator exposes a TLS-protected metrics endpoint on port 8443 with TokenReview/SubjectAccessReview enforcement, accessible only to subjects authorized by the `mlflow-operator-metrics-auth-role` ClusterRole. A ClusterIP Service fronts this endpoint. Health and readiness probes on port 8081 are unauthenticated. [source: cmd/main.go:261-284, config/base/metrics_service.yaml:1]
