## Purpose

**Short**: Kubernetes operator that reconciles TrainJob, TrainingRuntime, and ClusterTrainingRuntime CRDs to orchestrate distributed machine learning training across JobSet, CoScheduling, and Volcano scheduling backends. [source: cmd/trainer-controller-manager/main.go:62-68, manifests/base/crds/trainer.kubeflow.org_trainjobs.yaml:2]

**Detailed**: The trainer component is a Kubernetes operator built on controller-runtime that reconciles TrainJob custom resources by matching them against TrainingRuntime or ClusterTrainingRuntime templates. The controller translates training specifications into concrete workloads via a plugin-based runtime framework, supporting JobSet for replicated distributed jobs, and optional CoScheduling (scheduler-plugins) or Volcano for gang scheduling of training pods.

The RHOAI distribution extends the upstream Kubeflow Trainer with platform-specific behaviors in the `pkg/rhai/` package: per-TrainJob NetworkPolicy creation for workload network isolation, and progression tracking that polls primary training pods via HTTP for real-time training metrics (progress percentage, steps, epochs). The controller reads the OpenShift APIServer TLS security profile at startup to configure webhook and metrics server TLS, falling back to hardened Intermediate cipher suites when the OpenShift API is unavailable. Three validating admission webhooks enforce schema correctness on TrainJob, TrainingRuntime, and ClusterTrainingRuntime resources. Dataset and model initializer containers handle pre-training data and model preparation as init containers. [source: cmd/trainer-controller-manager/main.go:70-118, pkg/rhai/networkpolicy.go:152-180, pkg/rhai/progression/progression.go:48-96, pkg/tls/tls.go:88-131]

## Architectural Analysis

The trainer controller employs a plugin-based runtime framework (`pkg/runtime/framework/`) where each scheduling backend—JobSet, CoScheduling (scheduler-plugins), and Volcano—is implemented as a separate plugin. This design allows the controller to target different cluster scheduling topologies without modifying the core reconciliation loop. Each plugin registers its own controller watches: JobSet watches `jobset/v1alpha2/JobSet`, CoScheduling watches `scheduling/v1alpha1/PodGroup`, and Volcano watches `scheduling/v1beta1/PodGroup`. The MPI plugin additionally watches `/v1/ConfigMap` and `/v1/Secret` to manage SSH keys and configuration for distributed MPI training. [source: pkg/runtime/framework/plugins/jobset/jobset.go:198, pkg/runtime/framework/plugins/coscheduling/coscheduling.go:268, pkg/runtime/framework/plugins/volcano/volcano.go:341]

The RHOAI distribution introduces two significant platform-specific extensions. First, the `pkg/rhai/networkpolicy` package creates a per-TrainJob NetworkPolicy with owner references, ensuring that training workloads are network-isolated and that policies are automatically cleaned up when the TrainJob is deleted. Second, the `pkg/rhai/progression` package provides a progression-tracking system that locates the primary training pod (using multiple label selector fallback strategies across trainer, training-operator, and JobSet labeling conventions) and polls it over HTTP for training metrics. These metrics—including progress percentage, estimated remaining time, current step/epoch, and training/eval loss—are stored as TrainJob annotations. [source: pkg/rhai/networkpolicy.go:152-180, pkg/rhai/progression/progression.go:48-96, pkg/rhai/progression/progression.go:144-179]

The TLS configuration is noteworthy: rather than hardcoding cipher suites, the controller reads the OpenShift `config.openshift.io/v1/APIServer` resource at startup to adopt the cluster-wide TLS security profile. When running outside OpenShift or when the API is transiently unavailable, it falls back to a hardened Intermediate profile (TLS 1.2+ with AEAD cipher suites only). This profile is applied to both the webhook server (port 9443) and the metrics server. The Konflux build uses `CGO_ENABLED=1` and `GOEXPERIMENT=strictfipsruntime`, ensuring the Go runtime uses FIPS-validated cryptographic implementations via OpenSSL on RHEL. [source: cmd/trainer-controller-manager/main.go:94-111, pkg/tls/tls.go:39-60, pkg/tls/tls.go:88-131, cmd/trainer-controller-manager/Dockerfile.rhoai.konflux:16]

## Data Flows

- **Training job reconciliation:** Users create TrainJob resources referencing a TrainingRuntime or ClusterTrainingRuntime. The controller reconciles the TrainJob by resolving the runtime template, selecting the appropriate scheduling plugin (JobSet, CoScheduling, or Volcano), and creating the downstream workload resources. Three validating admission webhooks intercept CREATE and UPDATE operations on these CRDs via the webhook service on port 9443. [source: cmd/trainer-controller-manager/main.go:70-118, manifests/base/webhook/patch.yaml:1-12]
- **Workload scheduling:** The selected plugin creates backend-specific scheduling resources—JobSet objects for replicated jobs, PodGroup resources for gang scheduling—and the controller watches these resources for status updates to reflect back on the TrainJob status. The MPI plugin additionally creates ConfigMaps and Secrets for SSH key distribution across worker pods. [source: pkg/runtime/framework/plugins/jobset/jobset.go:198, pkg/runtime/framework/plugins/coscheduling/coscheduling.go:268, pkg/runtime/framework/plugins/volcano/volcano.go:341]
- **RHOAI platform extensions:** On RHOAI clusters, the controller creates a per-TrainJob NetworkPolicy for workload isolation and, when progression tracking is enabled via annotation, polls the primary training pod's HTTP metrics endpoint to collect and annotate training progress. [source: pkg/rhai/networkpolicy.go:152-180, pkg/rhai/progression/progression.go:48-96, pkg/rhai/progression/progression.go:144-179]
- **TLS and API authentication:** The controller authenticates to the Kubernetes API server using the in-cluster ServiceAccount token. At startup, it reads the OpenShift APIServer TLS profile to configure webhook and metrics server cipher suites, falling back to hardened Intermediate defaults. [source: pkg/tls/tls.go:88-131, cmd/trainer-controller-manager/main.go:94-101]
