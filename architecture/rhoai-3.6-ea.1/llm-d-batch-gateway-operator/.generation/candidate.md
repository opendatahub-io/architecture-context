## Purpose

**Short**: Kubernetes operator that manages LLMBatchGateway custom resources, deploying and reconciling batch inference gateway infrastructure via embedded Helm charts for the batch-gateway API server and async processor components. [source: cmd/main.go:94-176, config/crd/bases/batch.llm-d.ai_llmbatchgateways.yaml:2]

**Detailed**: The llm-d-batch-gateway-operator is a controller-runtime operator that watches `LLMBatchGateway` custom resources (batch.llm-d.ai/v1alpha1) and reconciles the full stack of resources required to run a batch inference gateway. On each reconcile, it renders two embedded Helm charts — `batch-gateway` (API server, garbage collector) and `async-processor` — injecting operator-managed container images and the cluster's TLS profile into the chart values. The operator creates and owns Deployments, Services, ConfigMaps, and ServiceAccounts, and conditionally manages Gateway API HTTPRoutes, cert-manager Certificates, and prometheus-operator monitoring resources when those CRDs are available in the cluster. [source: cmd/main.go:94-176, internal/controller/llmbatchgateway_controller.go:544-571, config/manager/manager.yaml:1-82]

A dedicated MetricsController runs alongside the main reconciler and ensures the operator's own metrics Service, ServiceMonitor, and PrometheusRule are always present, providing self-monitoring with alerting for high reconcile error rates and leader election loss. [source: internal/monitoring/controller.go:42-242]

## Architectural Analysis

The operator follows a Helm-rendering reconciler pattern: rather than creating Kubernetes resources imperatively, each `LLMBatchGateway` reconciliation renders two embedded Helm charts (`batch-gateway` and `async-processor`) with runtime-resolved values — including component container images sourced from environment variables and the cluster's TLS cipher/version profile. This design isolates the deployment topology of managed workloads into chart templates while keeping the operator responsible for lifecycle, status, and cross-resource watches. [source: cmd/main.go:148-166, config/manager/manager.yaml:26-41]

Optional platform integrations are feature-gated at startup via REST mapper probes: the controller conditionally registers `Owns` watches for HTTPRoute, Certificate, ServiceMonitor, PodMonitor, and PrometheusRule resources, and a `Watches` for ReferenceGrant, only when those CRDs are installed. This allows the same operator binary to run on clusters with or without Gateway API, cert-manager, and prometheus-operator. [source: internal/controller/llmbatchgateway_controller.go:554-568]

The metrics endpoint on port 8443 is secured with TLS (certificates sourced from the OpenShift service-serving-cert signer or an explicit cert directory) and gated by `WithAuthenticationAndAuthorization`, which performs TokenReview and SubjectAccessReview against the Kubernetes API for every scrape request. The operator's TLS configuration is dynamically derived from the cluster's `APIServer` TLS profile, defaulting to Intermediate, and a SecurityProfileWatcher triggers a graceful operator restart if the profile changes. [source: cmd/main.go:130-138, internal/tls/profile.go:60-150, internal/monitoring/controller.go:120-148]

The operator creates a Secret watch filtered to secrets referenced by `LLMBatchGateway` resources and performs cross-namespace secret synchronization via ReferenceGrant-gated copies. This enables managed workloads to consume secrets from the operator's namespace or other authorized namespaces. [source: internal/controller/llmbatchgateway_controller.go:550, internal/controller/secret_sync.go:62-107]

## Data Flows

- **Control plane loop:** The operator watches LLMBatchGateway CRs and reconciles by rendering two embedded Helm charts (batch-gateway and async-processor) into Deployments, Services, ConfigMaps, and ServiceAccounts. Container images for the managed workloads (apiserver, processor, gc, async) are injected from environment variables. [source: cmd/main.go:148-176, config/manager/manager.yaml:34-41]
- **Secret synchronization:** The controller watches Secrets referenced by LLMBatchGateway resources and performs cross-namespace copies gated by ReferenceGrant resources, enabling managed workloads to consume credentials from authorized source namespaces. [source: internal/controller/llmbatchgateway_controller.go:550, internal/controller/secret_sync.go:62-107]
- **TLS profile propagation:** At startup, the operator resolves the cluster's TLS profile from the OpenShift APIServer CR (defaulting to Intermediate), applies it to the metrics server, and injects the resolved cipher suites and minimum version into Helm chart values for managed workloads. A SecurityProfileWatcher restarts the operator if the profile changes. [source: cmd/main.go:124-128, 154-155, internal/tls/profile.go:60-150]
- **Metrics and monitoring:** The MetricsController dynamically creates a ClusterIP Service (port 8443/HTTPS with OpenShift serving cert), a ServiceMonitor for Prometheus scraping via bearer token with TLS, and a PrometheusRule with alerts for high reconcile error rate and leader election loss. [source: internal/monitoring/controller.go:120-242]
- **Security context:** The metrics endpoint is secured by TLS and TokenReview/SubjectAccessReview authentication. Health and readiness probes on port 8081 are unauthenticated by design. The operator runs as non-root with a read-only root filesystem and all capabilities dropped. [source: cmd/main.go:130-138, config/manager/manager.yaml:70-80]
