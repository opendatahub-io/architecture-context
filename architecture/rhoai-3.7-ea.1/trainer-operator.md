## Purpose

**Short**: A standalone module operator that reconciles the singleton cluster-scoped `Trainer` CR and deploys the upstream Kubeflow Trainer v2 control plane, training runtimes and training images into the RHOAI applications namespace.

**Detailed**: trainer-operator is the Trainer "module controller" in the ODH/RHOAI modular architecture (RHAISTRAT-1064). Distributed training used to be deployed by the monolithic platform operator. This repository moves it into its own operator. The platform operator (rhods-operator) creates a `Trainer` CR (`components.platform.opendatahub.io/v1alpha1`, which must be named `default-trainer`) and injects `APPLICATIONS_NAMESPACE` and `RELATED_IMAGE_*` environment variables. trainer-operator then renders and applies everything Kubeflow Trainer needs to run.

The operator image bundles three kustomize trees, which are synced from `opendatahub-io/trainer` and committed under `manifests/`:
- `/opt/manifests-template`: the upstream Kubeflow Trainer controller-manager. This includes its Deployment, Service, CRDs (`TrainJob`, `TrainingRuntime`, `ClusterTrainingRuntime`, `OptimizationJob`), RBAC, admission webhooks, NetworkPolicies and ServiceMonitor, rendered through the `rhoai` overlay.
- `/opt/runtimes-template`: 16 Red Hat-curated `ClusterTrainingRuntime`s, including torch-distributed, training-hub, OpenMPI, speculator model-opt and vLLM-extract, in CUDA, ROCm and CPU variants.
- `/opt/imagestreams-template`: OpenShift `ImageStream`s for the training-hub universal workbench images.

On every reconcile the operator does the following:
1. Checks the JobSet prerequisites.
2. Ensures the target namespace exists.
3. Substitutes image parameters from environment variables.
4. Renders the kustomize trees.
5. Injects the cluster TLS profile into the operand's configuration.
6. Server-Side Applies the result.
7. Tracks Deployment availability.
8. Garbage-collects resources that are no longer rendered.

Users never interact with trainer-operator directly. They create `TrainJob`s against the Kubeflow Trainer controller that this operator deploys. That controller in turn creates JobSets, which are reconciled by the Red Hat JobSet Operator, a hard prerequisite on OpenShift. trainer-operator therefore sits between the platform operator above and the training data plane below.

## Architectural Analysis

**Module-controller pattern built on odh-platform-utilities.** Almost all of the controller logic is assembled from `odh-platform-utilities/framework`: a reconciler builder, a deploy action that uses SSA with field owner `trainer-module-controller` and ordered apply, a deployments-status action, a GC action, condition management and dependent predicates (`internal/controller/trainer_controller.go:203-237`). The repository's own code is mostly the action chain (`checkDependencies` → `ensureNamespace` → `updateReleases` → `renderManifests` → deploy → deployments status → `stripRuntimeFinalizers` → GC), plus two pieces of glue: parsing `params.env` (explicitly marked `[TEMPORARY]` until it moves into platform-utilities, `internal/controller/params.go:17`) and translating TLS profiles. This keeps the component small, but its behaviour is tightly coupled to the versions of `odh-platform-utilities` v0.5.0 and its `framework` module v0.3.1.

**Manifests are baked into the image; the CR barely shapes the output.** All operand manifests are copied into the image at build time (`Dockerfile.konflux:22-24`). At startup the operator exits if any of the three template paths is missing (`cmd/main.go:152-177`). At runtime the templates are copied once into an `emptyDir` work directory (`/opt/manifests-work`, 256Mi) and edited in place: image keys in `params.env` are replaced from `RELATED_IMAGE_*` env vars, and `operator-namespace` is set from the CR. The kustomize overlay used is hard-coded to `rhoai` (`internal/controller/manifests.go:39`). `TrainerSpec` declares `featureGates` and `controllers[].resources`, but no code in `internal/controller` reads them on this branch, so they are effectively inert. Only `spec.appNamespace` affects rendering. If it is empty, the target namespace falls back to `opendatahub` (`internal/controller/trainer_controller.go:68, 773-778`), even though the rhoai overlay declares `redhat-ods-applications`. The `WithNamespace` render option overrides the overlay's namespace, so the platform operator must set `appNamespace` correctly.

**Startup-time TLS profile with restart-on-change.** At startup the operator reads the OpenShift `APIServer` TLS profile and its adherence policy through `frameworktls.LoadWithAdherence`. It honors the cluster profile when the adherence policy requires it, and otherwise uses hardened Intermediate defaults (`internal/tls/profile.go:47-82`). The resulting `tls.Config` options apply to the operator's own metrics server. The same effective profile is translated into the operand's `controller_manager_config.yaml` `tls` section (`internal/tls/operand.go:267-298`). During translation, TLS 1.3 suite IDs and RC4 suites are dropped, curve IDs are mapped, and translation fails if a profile specifies only curves this Go build can't support. A SHA-256 hash of the rendered config is stamped onto the operand pod template to force a rollout (`internal/controller/manifests.go:87-161`). A `SecurityProfileWatcher` cancels the manager context when the profile or adherence policy changes, so the pod restarts to pick up new settings (`internal/tls/profile.go:84-113`). This gives cluster-wide crypto-policy propagation to both the operator and the operand.

**Narrow cache, broad RBAC.** The informer cache is scoped to `APPLICATIONS_NAMESPACE` when that variable is set. Deployments, Services and ValidatingWebhookConfigurations are additionally filtered by `platform.opendatahub.io/part-of=trainer`, and caching is disabled for Namespaces so the `ensureNamespace` Get doesn't create a cluster-wide informer (`cmd/main.go:103-146`). The ClusterRole, however, is very broad: cluster-wide CRUD on Secrets, ConfigMaps, Services, Deployments, CRDs, Mutating/ValidatingWebhookConfigurations, NetworkPolicies, PodGroups, JobSets and TrainJobs, plus create on ClusterRoles/Bindings. The README explains why: Kubernetes RBAC escalation prevention requires the operator's ServiceAccount to hold every permission that the upstream Trainer ClusterRoles grant. Mutating verbs on RBAC objects and ServiceAccounts are restricted with `resourceNames` (`config/rbac/role.yaml:59-70, 253-320`), but `create` cannot be restricted that way. As a result the operator ServiceAccount is a high-value credential, roughly equivalent to the Trainer controller plus CRD and webhook administration.

**Dependency gating on JobSet.** On OpenShift, reconciliation is blocked (`Degraded=True`, and an error forces a requeue) until all of the following hold: the `jobset-operator` is found through OLM (`operatorconditions` / `clusterextensions`), a `JobSetOperator` CR named `cluster` exists with no degraded conditions, and the `jobsets.jobset.x-k8s.io` CRD is established. On non-OpenShift clusters only the CRD is checked (`internal/controller/trainer_controller.go:271-309`, `internal/controller/dependencies.go`). The `JobSetOperator` kind is watched dynamically, only once its CRD exists, so a change in JobSet health triggers a Trainer reconcile. The bundled third-party JobSet kustomization is commented out in the rhoai overlay, so JobSet must be provided externally.

**Lifecycle edge cases handled explicitly.**
- If SSA fails with "field is immutable", every rendered Deployment is deleted and recreated on the next reconcile (`internal/controller/trainer_controller.go:518-557`).
- GC runs with `OnlyCollectOwned=false`, because cluster-scoped objects such as ClusterTrainingRuntimes cannot carry an owner reference to the Trainer CR. Training runtimes are marked unremovable by GC and are deleted only in the finalizer.
- The legacy upstream finalizer `trainer.kubeflow.org/resource-in-use`, removed in Trainer 2.3, is stripped from runtimes on each reconcile and again on deletion. This prevents upgrades and deletes from getting stuck.
- The platform version is read live (bypassing the cache) from the `odh-trainer-config` ConfigMap and recorded in `status.releases`. A version-change hook exists but is currently a no-op.

**Risks and observations.**
- The README and AGENTS.md describe a `Removed` management state, but `TrainerSpec` has no management-state field, and the only cleanup path is deleting the CR, which runs the finalizer.
- README and AGENTS.md reference `hack/get_trainer_manifests.sh`, but it is not on this branch. Manifests are synced by the `.github/workflows/sync-trainer-manifests.yml` PR workflow, which clones `opendatahub-io/trainer`.
- The operand's ingress NetworkPolicy allows port 9443 (webhooks) from any source. It also allows port 10443 (the TrainJob status server) from any pod in any namespace that carries the label `training.kubeflow.org/job-name`, which a tenant can set on its own pods. Egress is fully open.
- If the operand's metrics TLS `serverName` replacement fails, the operand ServiceMonitor is left with the placeholder `kubeflow-trainer-controller-manager..svc` (`manifests/trainer/rhoai/monitor.yaml`, patched via a kustomize replacement).
- `config/prometheus/monitor.yaml` (the operator's own ServiceMonitor) uses `insecureSkipVerify: true`, but it is not included in `config/default`, so it is not deployed by default.
- The operator runs with `replicas: 1` and no leader-election flag in `cmd/main.go`. It does hold `leases` RBAC, but HA is not configured.

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Aggregated `training-edit`, `training-admin` and `training-view` ClusterRoles bound per namespace by admins; `training-view` aggregates to `view` | Kubernetes RBAC | The operator SA has cluster-wide CRUD on Secrets, ConfigMaps, webhooks and CRDs, so its compromise crosses all tenants |
| Data storage | None owned by the operator; training jobs bring their own PVCs | Kubernetes | N/A |
| Network traffic | Operator: metrics-only ingress NetworkPolicy. Operand: ingress policy (9443 any, 10443 from job pods, 8443 from openshift-monitoring), egress allow-all | Kubernetes NetworkPolicy | The status-server rule trusts a pod label that any tenant can set; no per-tenant NetworkPolicies for training pods |
| Compute & resources | Shared ClusterTrainingRuntimes; quotas delegated to Kueue / ResourceQuota (not managed here) | Kubernetes / external | The operator creates no ResourceQuota or LimitRange |
| Configuration & secrets | Platform ConfigMap `odh-trainer-config` and operand config live in the applications namespace | Kubernetes | The cluster-wide secrets permission is broader than the namespace-scoped need |
| API scoping | Operator cache scoped to `APPLICATIONS_NAMESPACE` plus label filters; runtime cleanup lists cluster-wide by label | controller-runtime cache | Falls back to all namespaces if the env var is unset |
