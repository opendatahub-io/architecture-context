## Purpose

**Short**: Runs Apache Spark workloads on OpenShift AI. Users declare `SparkApplication`, `ScheduledSparkApplication` and `SparkConnect` custom resources, and the operator handles submission, lifecycle, admission and defaulting. A platform module controller installs and configures the operator through a cluster-scoped `SparkOperator` CR.

**Detailed**: The repository is the Red Hat downstream of the Kubeflow Spark Operator, extended with an ODH/RHOAI "module" layer. The upstream-derived workload operator ships as one image (`odh-spark-operator`, built from `Dockerfile.konflux`) that runs in two modes. In `controller start` mode it reconciles `SparkApplication` (v1beta2), `ScheduledSparkApplication` (v1beta2) and `SparkConnect` (v1alpha1). In `webhook start` mode it serves mutating, validating and conversion admission webhooks for those CRDs and for Spark driver and executor pods. In the default configuration the controller submits applications by running `spark-submit` inside its own container. For that reason the image bundles OpenJDK 17, PySpark 4.0.4 and `catatonit` as PID 1. The controller also creates the Spark UI Service and Ingress, driver PodDisruptionBudgets, and the SparkConnect server pod and Service (gRPC 15002).

The second image (`odh-spark-operator-module-controller`, built from `Dockerfile.konflux.module-controller`) is a controller-runtime operator written against `odh-platform-utilities`. It reconciles the singleton cluster-scoped `SparkOperator` CR (`components.platform.opendatahub.io/v1alpha1`, name fixed to `default-sparkoperator`). It renders the workload operator's kustomize manifests, which are baked into the image at `/opt/manifests-template`, choosing `config/overlays/rhoai` or `config/overlays/odh` from the platform type that opendatahub-operator injects. It then applies image overrides from `RELATED_IMAGE_ODH_SPARK_OPERATOR_IMAGE`, rewrites the webhook `namespaceSelector` from `spec.spark.jobNamespaces`, patches controller resources and tuning, and applies the result with owner references. It reports `Ready`/`ProvisioningSucceeded`/release status back to the platform through the `common.PlatformObject` contract.

In RHOAI the workload operator runs in `redhat-ods-applications`. Its HTTPS metrics endpoints use OpenShift service-CA serving certificates and are scraped by PodMonitors. NetworkPolicies protect the operator and the Spark pods. Data scientists usually reach it through the Kubeflow SDK (`kubeflow.spark`), which creates `SparkConnect` sessions from workbenches (see overlay 0012).

## Architectural Analysis

**Two-tier operator ("module") pattern.** The repo is an example of the RHOAI 3.x module architecture. opendatahub-operator does not render Spark manifests itself. It deploys `spark-operator-module-controller-manager` and creates the `SparkOperator` CR, and the module controller owns the full lifecycle of the workload operator. The module image carries the entire `config/` tree, copied at build time by `spark-operator-module/hack/get_spark_manifests.sh`, so the deployed operand is exactly the overlay in this commit. Platform selection relies on the injected `ODH_MODULE_OPERATOR_PLATFORM_TYPE`/`ODH_PLATFORM_TYPE` and `APPLICATIONS_NAMESPACE` env vars. The module never probes OLM (`spark-operator-module/pkg/sparkoperatormodule/platform.go:10-34`), so mis-injection quietly falls back to the ODH overlay and the `opendatahub` namespace.

**Privilege concentration in the module controller.** To own the operand's RBAC, CRDs and webhook configurations, the module ClusterRole has `bind`/`escalate` on a named list of ClusterRoles and Roles, cluster-wide create/patch/delete on all `clusterroles`/`clusterrolebindings`/`roles`/`rolebindings`, and CRUD on CRDs, Deployments and NetworkPolicies (`spark-operator-module/pkg/sparkoperatormodule/reconciler.go:27-45`). The `resourceNames` scoping on webhook configurations, the `SparkOperator` CR, and bind/escalate is good practice. However, plain `create` on clusterrolebindings is not name-scoped, so a compromise of this service account is effectively cluster-admin-equivalent. It also has RBAC for `cert-manager.io` Certificates/Issuers even though no rendered RHOAI overlay includes `config/certmanager`. That grant is currently latent.

**Admission scope differs from controller scope.** The module sets the webhook `namespaceSelector` to `In(kubernetes.io/metadata.name, jobNamespaces)`, with a default of `["default"]` (`spark-operator-module/pkg/sparkoperatormodule/webhook_namespaces.go:16-50`, `spark-operator-module/pkg/apis/v1alpha1/types.go:45-55`). Both the controller and the webhook start with `--namespaces=`, which means all namespaces (`config/manager/manager.yaml:67`, `config/webhook/deployment.yaml:42`). As a result the controller reconciles `SparkApplication`s and `SparkConnect`s in every namespace, but defaulting, validation (DNS-1035 names, sparkConf checks, ResourceQuota enforcement) and pod mutation (volumes, env, affinity, tolerations, security context, sidecars) apply only in job namespaces. Every webhook has `failurePolicy: Fail`. Applications outside job namespaces are submitted without admission defaulting, and their driver and executor pods are not mutated by the operator. This is an operational and policy risk worth tracking.

**TLS posture is mostly platform-aligned, but certificates are long-lived.** The controller and webhook read `apiservers.config.openshift.io/cluster` at startup. They apply the cluster TLS profile (min version, ciphers, curves) to the webhook server, the metrics server and the optional REST submitter client, and restart on profile change (`pkg/tls/profile.go:77-140`, `cmd/operator/controller/start.go:334-415`). The fallback is TLS 1.2 on non-OpenShift clusters, or Mozilla Intermediate if the read is transient. Denied or malformed reads fail startup. The webhook serving certificate is not issued by service-ca or cert-manager in RHOAI. The webhook binary generates a self-signed CA and server certificate: RSA-2048, `NotAfter = now + 10 years` (`pkg/certificate/util.go:57-69`, `pkg/common/constants.go:29`). It stores them in Secret `spark-operator-webhook-certs` and regenerates them when they would expire within 180 days (`pkg/certificate/certificate.go:118-126`). Metrics, by contrast, use service-CA certificates, which rotate automatically.

**Metrics are encrypted but unauthenticated.** `--secure-metrics=true` turns on `SecureServing`, but no authn/authz `FilterProvider` is configured (`cmd/operator/controller/start.go:650-657`, `cmd/operator/webhook/start.go:449-456`). The `/metrics` endpoint on 8080 is therefore HTTPS without a bearer-token check. Access is limited only by NetworkPolicy `spark-operator-allow-metrics`, which admits namespaces labeled `network.openshift.io/policy-group: monitoring`.

**Network posture.** The operator pods get allow-all egress (`networkpolicy-egress.yaml`, citing ADR-0016: user-supplied dependency URLs cannot be enumerated). Ingress is port-scoped: 9443 from any source, because API-server traffic is unselectable, and 8081 for probes. On the Spark pods themselves, ports 7078/7079/4040 accept traffic from any pod in the operator namespace and from the OpenShift ingress policy group. SparkConnect gRPC 15002 accepts traffic from the same namespace and from dashboard-labelled namespaces' workbench pods. These Spark-pod NetworkPolicies exist only in the operator's namespace. Spark pods in user namespaces depend on the controller's `OperandNetworkPolicy` feature gate, which the RHOAI overlay enables, and on the controller's networkpolicy reconciler (`internal/controller/networkpolicy/networkpolicy.go:129`).

**Image composition.** The workload operator image is built on the AIPCC CPU base (`quay.io/aipcc/base-images/cpu-el9.8`), not on UBI minimal. It is a heavy image because `spark-submit` executes in-process: JDK 17, podman (pulled in only for `catatonit`), and PySpark from the RHOAI public PyPI index. The module image is a small `ubi9/ubi-minimal-pqc` image. Both Go binaries are built with `CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime -tags strictfipsruntime`.

**Upstream drift indicators.** The CRD kustomization applies conversion-webhook patches (`/convert`) to CRDs that each serve a single version. This is harmless but adds an admission dependency on CRD reads. The root `go.mod` targets Go 1.26 with toolchain go1.26.10, while the module uses Go 1.25.7 and a pinned `go-toolset:1.25.7` builder. The root Konflux Dockerfile uses an unpinned-version `go-toolset` digest, so the root build toolchain version is set by the builder image digest.

## Multi-Tenancy

### Tenant Model

| Aspect | Value | Source |
|--------|-------|--------|
| **Tenant boundary** | per-namespace (Spark CRs and their pods are namespaced) | CRD scope; `config/crd/bases/*` |
| **Deployment model** | single shared operator instance (cluster-wide watch) serving all namespaces; singleton cluster-scoped `SparkOperator` | `config/manager/manager.yaml:67` (`--namespaces=`), `spark-operator-module/pkg/apis/v1alpha1/types.go:22-24` |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | User RBAC on Spark CRs; editor/viewer ClusterRoles; operator uses shared SAs with cluster-wide pod/service/configmap rights | Kubernetes | The operator creates pods in any namespace on users' behalf, so the operator SA is a cross-tenant privilege holder. Driver SA defaults to the namespace default unless `--default-service-account` is set |
| Data storage | None owned by operator; Spark apps use user-supplied PVCs/object stores | Application (user) | N/A |
| Network traffic | NetworkPolicies on Spark pods (same-namespace + ingress/workbench peers); operand NetworkPolicies via `OperandNetworkPolicy` gate | Kubernetes | Allow-all egress for operator pods; Spark pods allow any same-namespace pod on 7078/7079/4040/15002; SparkConnect gRPC has no app-level auth |
| Compute & resources | ResourceQuota check in validating webhook; optional batch schedulers (Volcano/YuniKorn/kube-scheduler) | Kubernetes + Application | Quota validation and pod mutation apply only in `jobNamespaces` (default `["default"]`), while the controller reconciles all namespaces |
| Configuration & secrets | Per-namespace ConfigMaps (spark conf, hadoop conf); webhook certificate Secret in operator namespace only | Kubernetes | Pod defaulter mounts user-referenced ConfigMaps/Secrets from the app's own namespace |
| API scoping | Cluster-wide informers for SparkApplication/Pod/Service; webhook `namespaceSelector` | Kubernetes / Application | Controller cache spans all namespaces, so there is no tenant filtering at the controller level |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| spark-operator-controller (submission engine running spark-submit in one container) | namespace | Owner references and per-namespace resources; a shared process handles all tenants' submissions |
| spark-operator-webhook | namespace (`jobNamespaces`) | Admission namespaceSelector |
