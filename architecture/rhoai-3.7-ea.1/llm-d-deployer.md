## Purpose

**Short**: A single Helm chart and installer that deploys the early llm-d distributed LLM inference stack: the ModelService controller and CRD, an inference Gateway, vLLM prefill/decode preset templates, the Endpoint Picker (EPP), and an optional Redis KV-cache index.

**Detailed**: `llm-d-deployer` packaged the first-generation llm-d stack ("Kubernetes-native high-performance distributed LLM inference framework", `charts/llm-d/Chart.yaml`) as one Helm chart named `llm-d`. The chart installs the `ModelService` CRD (`llm-d.ai/v1alpha1`) and deploys the `llm-d-model-service` controller image (`ghcr.io/llm-d/llm-d-model-service:v0.0.15`). It also ships four "preset" ConfigMaps (`basic-gpu-preset`, `basic-gpu-with-nixl-preset`, `basic-gpu-with-nixl-and-redis-lookup-preset`, `basic-sim-preset`). These ConfigMaps hold Go-templated Deployment, Service, InferencePool and InferenceModel skeletons. The controller combines them with a `ModelService` CR to render per-model prefill and decode vLLM Deployments, a routing-sidecar init container, an EPP Deployment (`ghcr.io/llm-d/llm-d-inference-scheduler:v0.1.0`), and Gateway API Inference Extension objects.

The chart also creates a Gateway API `Gateway` (default GatewayClass `istio`, with `kgateway` and GKE L7 options). When `sampleApplication.enabled` is true (the default), it also creates a sample `ModelService` for `meta-llama/Llama-3.2-3B-Instruct`, an `HTTPRoute` to its `InferencePool`, and an Istio `DestinationRule`. The Bitnami Redis subchart (image `quay.io/sclorg/redis-7-c9s:c9s`) backs the KV-cache-aware scorer and LMCache lookup. `quickstart/llmd-installer.sh` ties these together. It installs Gateway API and GIE CRDs plus a gateway provider (Istio from `gcr.io/istio-testing`, or kgateway v2.0.3), creates the HF token Secret, and can download a model to a PVC. It wires up metrics: OpenShift user-workload monitoring on OpenShift, otherwise kube-prometheus-stack.

**Status for RHOAI 3.7 EA1**: `README.md` says the repo "is no longer actively maintained" and points to `llm-d-incubation/llm-d-infra`, which uses Helmfile with modular `llm-d-modelservice` charts and upstream GIE charts. The ModelService *controller* pattern, `baseConfig` presets, and `sampleApplication` were all deprecated. In this platform snapshot the repo should be treated as a historical reference and deployment template only. It is not a runtime component of RHOAI. It has no Konflux Dockerfiles, no `.konflux` build, and no RHOAI kustomize manifests. RHOAI deploys llm-d through KServe's `LLMInferenceService` path (see the `kserve`, `llm-d-router`, `llm-d-routing-sidecar`, `llm-d-kv-cache` and related component documents).

## Architectural Analysis

**Controller + template-ConfigMap pattern.** The design separates *what to run* from *how to run it*. A namespaced `ModelService` CR (`charts/llm-d/crds/modelservice-crd.yaml`) holds model identity (`routing.modelName`), artifact URI (`modelArtifacts.uri`, supporting `hf://`, `pvc://`, and `oci://` per the installer), replica counts, and container overrides. It points via `baseConfigMapRef` at a preset ConfigMap. The preset holds double-escaped Go templates (`{{ .HFModelName }}`, `{{ .InferencePoolName }}`, `{{ .ModelServiceNamespace }}`). The deployer's Helm render fills these in for chart-level values, and the controller fills the rest at reconcile time. Platform operators could therefore change the runtime shape (NIXL connectors, LMCache, sidecars) without touching the controller. The cost is a two-stage templating layer that is hard to validate statically and that couples chart values to controller internals. One example is the explicit `HACK` comment injecting `HF_TOKEN` into the EPP pending llm-d-model-service#123 (`basic-gpu-with-nixl-and-redis-lookup-preset.yaml:426`). Upstream later dropped this pattern for plain per-model Helm charts.

**Disaggregated prefill/decode topology.** The NIXL presets render separate prefill and decode vLLM Deployments. The decode pod runs `llm-d-routing-sidecar` as a native sidecar (init container with `restartPolicy: Always`) on port 8000, with `--connector=nixlv2`, proxying to vLLM on 8001. Prefill vLLM listens directly on 8000. KV blocks move between pods over the NIXL side channel (5557/TCP, `VLLM_NIXL_SIDE_CHANNEL_HOST=status.podIP`) using UCX with `UCX_TLS=^cuda_ipc`. The redis-lookup preset adds LMCache (`LMCacheConnectorV1` inside a `MultiConnector`) with a Redis lookup URL. Prefill and decode Services are headless (`clusterIP: None`), so the EPP selects individual pods, not a VIP.

**Gateway API Inference Extension integration.** The Gateway is labelled `istio.io/enable-inference-extproc: "true"` (`inference-gateway/gateway.yaml:15`). The sample HTTPRoute backend is an `InferencePool` (`inference.networking.x-k8s.io/v1alpha2`), not a Service. Envoy calls the EPP over gRPC ext_proc (9002/TCP, health on 9003, metrics on 9090). The EPP scores endpoints with prefix-aware (weight 2) and load-aware (weight 1) scorers enabled by default. The KV-cache-aware, session-aware and P/D scorers are off by default, with Redis as the KV-cache index (`values.yaml:569-609`).

**Security posture is "quickstart grade".** Several defaults are unsuitable for production and would conflict with RHOAI hardening:
- Redis auth is disabled (`redis.auth.enabled: false`) and its NetworkPolicy is disabled. The KV-cache index is reachable unauthenticated in-cluster on port 8100.
- The Gateway listener is plain HTTP on port 80. Ingress TLS is off by default, and no authentication sits in front of the inference endpoint.
- Envoy → EPP traffic uses an Istio `DestinationRule` with `tls.mode: SIMPLE` and `insecureSkipVerify: true` (`sample-application/destinationrule.yaml:10-11`). The connection is encrypted, but the EPP certificate is not verified.
- `global.security.allowInsecureImages: true`. Images come from `ghcr.io` and `quay.io` (community) with mutable tags, `imagePullPolicy: Always`, and the test image `curl/curl:latest`.
- The Grafana quickstart hardcodes `admin_password: "admin"`, sets `tlsSkipVerify: true` against Thanos, and binds the Grafana SA to the cluster-wide `view` ClusterRole.
- The ModelService manager ClusterRole can create and patch `rolebindings`, `serviceaccounts`, `deployments` and `services` cluster-wide. That is effectively a privilege-escalation path, because it can bind any role it holds into any namespace.

On the positive side, the controller pod runs `runAsNonRoot`, `RuntimeDefault` seccomp and drops `ALL` capabilities. The kgateway Envoy and SDS containers run with a read-only root filesystem.

**Not a RHOAI deliverable.** It has no Konflux pipeline, no Dockerfile, no lock files, and no FIPS signals. Its Tekton PipelineRun (`.tekton/pipelinerun.yaml`) only runs chart lint and testing on an IBM Cloud CI cluster (`icr-secret`). Release publishes the chart to `oci://ghcr.io/llm-d/llm-d-deployer` signed with cosign (`.github/workflows/release.yaml:63-70`). Architects should treat it as lineage for the llm-d deployment model, not as a supported install path.

## Multi-Tenancy

### Tenant Model

| Aspect | Value | Source |
|--------|-------|--------|
| **Tenant boundary** | per-namespace (ModelService is Namespaced); controller is cluster-scoped | `crds/modelservice-crd.yaml` (`scope: Namespaced`), `manager_clusterrole.yaml` |
| **Deployment model** | single shared controller per cluster/release; one Gateway and one Redis per release namespace | `modelservice/deployment.yaml`, `values.yaml` |
| **Tenant identifier** | namespace name (`{{ .ModelServiceNamespace }}` passed to EPP `--poolNamespace`) | `presets/*.yaml` eppDeployment args |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Kubernetes RBAC on ModelService (admin/editor/viewer ClusterRoles); per-model EPP SA + RoleBinding | Kubernetes | Controller SA holds cluster-wide create on rolebindings, serviceaccounts and deployments, so a compromised controller crosses all namespaces; no auth on the inference endpoint |
| Data storage | Per-pod emptyDir model cache, or per-namespace PVC (`pvc://`) | Kubernetes | Shared HF token per namespace; RWX model PVCs can be shared by multiple ModelServices |
| Network traffic | None (no NetworkPolicy; Redis NetworkPolicy disabled) | — | Any pod can reach vLLM, EPP, NIXL and Redis ports; EPP Service is NodePort |
| Compute & resources | GPU requests/limits and `nvidia.com/gpu` tolerations; no ResourceQuota/LimitRange | Kubernetes | No quota enforcement; relies on cluster admin |
| Configuration & secrets | Preset ConfigMaps and HF Secret in release namespace | Kubernetes | Presets are templates shared by every ModelService that references them |
| API scoping | Controller watches cluster-wide (ClusterRole); EPP scoped to one InferencePool in its namespace | Kubernetes / Application | Cluster-wide list/watch of pods, services and deployments by controller |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| Redis (KV-cache index / LMCache lookup) | per Helm release | None: unauthenticated, shared by every ModelService in the release |
| Inference Gateway (Envoy) | per Helm release | HTTPRoute per model; no auth |
| modelservice controller | cluster | Kubernetes RBAC only |
