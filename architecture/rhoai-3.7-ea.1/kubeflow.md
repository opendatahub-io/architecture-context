## Purpose

**Short**: Reconciles `Notebook` (`kubeflow.org`) custom resources into running Jupyter/IDE workbenches on OpenShift, including StatefulSets, Services, Gateway API HTTPRoutes, kube-rbac-proxy auth sidecars, NetworkPolicies, and pipeline/MLflow/Feast integration.

**Detailed**: This repository is the RHOAI downstream of the Kubeflow notebook subsystem. It contains two independently built controllers that watch the same `Notebook` CRD. The upstream **Kubeflow Notebook Controller** (`components/notebook-controller`, image `odh-kf-notebook-controller-rhel9`) owns the core workload lifecycle. It turns each Notebook into a single-replica StatefulSet plus a ClusterIP Service on port 80→8888. It can also cull idle notebooks: it polls each notebook's Jupyter `/api/kernels` endpoint and sets a stop annotation after a configurable idle period.

The **ODH Notebook Controller** (`components/odh-notebook-controller`, image `odh-notebook-controller-rhel9`) adds every OpenShift- and RHOAI-specific behavior. Its mutating webhook resolves workbench images from OpenShift ImageStreams. The same webhook mounts the trusted CA bundle, pipeline runtime images, the Elyra/DSPA pipeline config, Feast config, and MLflow env vars. When `notebooks.opendatahub.io/inject-auth: "true"` is set, it also injects a `kube-rbac-proxy` sidecar whose TLS flags follow the cluster TLS profile. The validating webhook rejects privileged pod specs and unsafe MLflow annotation removal. The reconciler creates per-notebook HTTPRoutes in the central gateway namespace, plus a ReferenceGrant in each user namespace so those routes can point at the notebook Service. It also creates kube-rbac-proxy Service, ConfigMap, ServiceAccount, and ClusterRoleBinding objects, NetworkPolicies, DSPA RoleBindings and Secrets, and the MLflow RoleBinding.

Within RHOAI, the platform operator (rhods-operator, "Workbenches" component) deploys both controllers through the `rhoai` kustomize overlay into the applications namespace. ODH Dashboard creates Notebook CRs. The Gateway API `data-science-gateway` in `openshift-ingress`, owned by the platform operator, serves user traffic to notebooks.

## Architectural Analysis

**Split-brain controller design by intent.** Two managers reconcile the same CR without sharing code paths. They coordinate implicitly through Kubernetes objects. The upstream controller is kept close to `kubeflow/kubeflow` for rebases (REBASE.md). All downstream behavior lives in the ODH controller and its webhook. The ODH mutating webhook adds a *reconciliation lock* annotation on CREATE (`InjectReconciliationLock`). This stops the upstream controller from starting the StatefulSet until the ODH controller has prepared its dependencies (ServiceAccount, kube-rbac-proxy resources, CA bundle). Most of the platform-specific logic runs in the webhook rather than the reconciler: image resolution, CA bundle, runtime images, Elyra secret, Feast, MLflow env, and sidecar injection. The design therefore depends on `failurePolicy: Fail` for both webhooks. If the webhook is unavailable, nobody can create or update Notebooks.

**Ingress has moved to Gateway API (RHOAI 3.x pattern).** The controller writes HTTPRoutes into its **own namespace**, the central namespace, with path prefix `/notebook/<ns>/<name>`. Their parent is the Gateway chosen from the `odh-notebook-controller-config` ConfigMap `ingresses` list. The namespace annotation `opendatahub.io/ingress-name` picks an entry; without it, the default is `data-science-gateway`/`openshift-ingress`. Because a central-namespace route points at a Service in another namespace, the controller keeps a shared `notebook-httproute-access` ReferenceGrant in each user namespace and deletes it when the last notebook goes away. With auth enabled, the backend is the kube-rbac-proxy Service on 8443/TLS (service-ca serving cert). Without auth, it is the notebook Service on 8888. `EnsureConflictingHTTPRouteAbsent` switches between the two modes. OpenShift `Route` objects are only *read*, to find the gateway hostname for the Elyra public endpoint. `OAuthClient` objects are only *deleted*, as finalizer-driven cleanup from the 2.x oauth-proxy era. Istio VirtualService support from upstream is turned off (`USE_ISTIO=false`) in the OpenShift overlay, but upstream RBAC still grants `virtualservices *`.

**TLS posture follows the cluster.** Both managers read `config.openshift.io/v1 APIServer.spec.tlsSecurityProfile` at startup and apply it to the metrics server and, for ODH, the webhook server. If the profile changes, the process exits so it restarts with the new settings. The ODH controller also reads the OpenShift 4.22+ `tlsAdherence` policy. It refuses to start under an unknown TLS posture, for example when a read is denied or a profile has no ciphers under Strict adherence. On clusters without the OpenShift config API, both fall back to TLS 1.2 with the Mozilla Intermediate ciphers. The same profile is translated into kube-rbac-proxy `--tls-min-version/--tls-cipher-suites/--tls-curve-preferences` flags, and X25519 and ML-KEM hybrids are dropped when `fips140.Enabled()`. A running workbench is never restarted for a TLS change; the controller only records a "pending" event.

**Cache and memory hygiene.** The ODH manager strips managed fields everywhere and removes `data` from all cached Secrets and from every ConfigMap except its own config. Secret and ConfigMap reads bypass the cache (`DisableFor`). Watching cluster-wide Secrets and ConfigMaps therefore does not keep tenant secret payloads in the controller's memory.

**Risks and observations.**
- The culler polls notebooks over **plaintext HTTP** to `http://<nb>.<ns>.svc.cluster.local/notebook/<ns>/<nb>/api/kernels`. That only works because the notebook's `-ctrl-np` NetworkPolicy allows port 8888 from the *entire* controller namespace, which the code itself flags as an over-broad peer.
- The kube-rbac-proxy NetworkPolicy allows port 8443 from any source by design; auth is enforced by the proxy's SubjectAccessReview (`get notebooks/<name>`). Notebook egress is allow-all.
- The ODH controller's ClusterRole lets it create and delete `clusterrolebindings` (for per-notebook `system:auth-delegator` bindings) and grants `bind` on `mlflow-operator-mlflow-integration`. These are privilege-escalation-adjacent permissions held by a cluster-wide controller.
- The Elyra/DSPA secret is built by copying S3 access and secret keys out of the DSPA's credentials Secret into a new `ds-pipeline-config` Secret in the same namespace.
- Both controllers run one replica with leader election off by default and `maxUnavailable: 100%`. There is no HA, and with the fail-closed webhook this means a short Notebook admission outage during each rollout.

## Multi-Tenancy

### Tenant Model

| Aspect | Value | Source |
|--------|-------|--------|
| **Tenant boundary** | per-namespace (Data Science Project) | Notebook CRD is Namespaced; per-namespace ReferenceGrant/DSPA/RBAC (notebook_referencegrant.go:39, notebook_rbac.go:144) |
| **Deployment model** | single cluster-wide controller pair serving all namespaces | config/rbac/role.yaml (ClusterRole), no namespace-restricted cache |
| **Tenant identifier** | namespace name; per-notebook identity = ServiceAccount `<nb>` | notebook_podspec_validation.go (serviceAccountName must equal notebook name) |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | kube-rbac-proxy SAR `get notebooks/<name>` per notebook; per-notebook SA; aggregated notebooks-edit/view roles | Kubernetes RBAC + sidecar | Auth is opt-in (`inject-auth` annotation); without it the backend has no auth |
| Data storage | User-supplied PVCs in the notebook namespace | Kubernetes | Controller doesn't manage storage; S3 creds copied into `ds-pipeline-config` within same ns |
| Network traffic | Per-notebook NetworkPolicies: `-ctrl-np` (8888 from controller ns), kube-rbac-proxy NP (8443 from any), egress allow-all | Kubernetes NetworkPolicy | 8888 open to entire shared applications namespace; 8443 open to all sources; egress unrestricted |
| Compute & resources | None set by controller (user/Dashboard sets PodSpec resources; hardware profiles elsewhere) | n/a | No ResourceQuota/LimitRange management |
| Configuration & secrets | Per-namespace ConfigMaps/Secrets (CA bundle, runtime images, Elyra config); cache strips Secret data | Kubernetes + application | Controller has cluster-wide Secret create/update |
| API scoping | Cluster-wide watches; HTTPRoutes centralised in controller namespace keyed by labels; ReferenceGrant scoped to Services in the user ns | Application | Validating webhook blocks hostPath/hostNetwork/privileged and foreign SAs, limiting escape from tenancy |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| Platform Gateway (`data-science-gateway`) | Path prefix `/notebook/<ns>/<name>` | HTTPRoute per notebook + kube-rbac-proxy SAR |
| Controller namespace (HTTPRoute store, ImageStreams) | Labels `notebook-name`/`notebook-namespace` | Application-managed naming; only controller writes |
