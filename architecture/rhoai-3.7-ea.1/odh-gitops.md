## Purpose

**Short**: A GitOps repo of Kustomize layers and Helm charts that installs the ODH/RHOAI operator, the operators it depends on, and their post-install configuration. It targets OpenShift (through OLM) and non-OpenShift Kubernetes services (AKS, EKS, CoreWeave).

**Detailed**: odh-gitops is the administrator-facing "single source of truth" for the prerequisites that ODH/RHOAI treats as admin-owned. Examples are cert-manager, Kueue, Leader Worker Set, JobSet, Red Hat Connectivity Link (Kuadrant/Authorino), Cluster Observability, OpenTelemetry, Tempo, Loki, Custom Metrics Autoscaler, NFD, the NVIDIA GPU Operator, Agent Sandbox and MariaDB. It offers three ways to consume it. Kustomize `components/operators/*` are reusable units that each define a Namespace, OperatorGroup and Subscription. `dependencies/operators/` composes those components. `configurations/` holds the operator CRs, which can only be applied once OLM has installed the CRDs. Admins apply these with `kubectl apply -k` or point an Argo CD Application at the repo root, with `SkipDryRunOnMissingResource=true`.

The main delivery vehicle in 3.x is the **`rhai-on-openshift-chart`** Helm chart. It renders OLM Subscriptions for the ODH or RHOAI operator and its dependencies, and it renders the `DSCInitialization` (`default-dsci`) and `DataScienceCluster` (`default-dsc`, DSC v3) from a component-centric values model. Each dependency has a tri-state `enabled` flag (`auto`/`true`/`false`). With `auto`, a dependency is installed only when an active component or service needs it (`shouldInstall`). Bundled profiles (`default`, `rhaii`, `maas`, `ai-grid-ingress`, `ai-grid-inference`, `ai-grid-combined`) preset common topologies. The chart also creates the platform Gateway API objects: the `openshift-ai-inference` Gateway for KServe, and the `maas-default-gateway` Gateway with an optional re-encrypt Route for Models-as-a-Service. When AIGateway's `aiGrid` sub-component is Managed, it embeds the upstream **Praxis/AI Grid** subcharts: `praxis-gateway` (a consumer `grid-gateway` and an aliased provider `grid-provider-gateway`), `grid-enrollment` (Grid CA, site identities and ACM enrollment policies) and the `ai-grid-o11y-hub`/`ai-grid-o11y-spoke` observability charts.

The **`rhai-on-xks-chart`** Helm chart is a non-OLM install path for Red Hat AI Inference on non-OpenShift Kubernetes. It deploys the `rhai-operator` (the opendatahub-operator image with `ODH_PLATFORM_TYPE=XKS` and most modules turned off) and exactly one cloud-specific `*-cloud-manager-operator` (AWS, Azure or CoreWeave). The cloud manager installs cert-manager, Gateway API, Sail (OSSM 3), LWS and RHCL by reconciling an `*KubernetesEngine` CR. Helm hook Jobs built on `ose-cli` create the post-install CRs and the KServe `inference-gateway`. Vendored dependency charts under `charts/dependencies/` (cert-manager-operator, gateway-api, lws-operator, rhcl-operator, sail-operator, xks-gateway) provide non-OLM installs of those operators. The optional `xks-gateway` subchart configures an OIDC platform auth gateway (`GatewayConfig`) that `kube-auth-proxy` enforces.

## Architectural Analysis

**A configuration repository, not a runtime component.** The repository has no application source and no Dockerfiles. Its architecture lives entirely in templated Kubernetes manifests. Almost everything this repo "deploys" is either an OLM `Subscription`, which hands lifecycle to the Red Hat/certified/community catalogs, or a CR consumed by an operator that lives elsewhere (`DSCInitialization`, `DataScienceCluster`, `Kuadrant`, `Authorino`, `LeaderWorkerSetOperator`, `JobSetOperator`, `Kueue`, `NodeFeatureDiscovery`, `ClusterPolicy`, and so on). The only long-running workloads defined directly in this repo are third-party:
- the Praxis gateways (`ghcr.io/praxis-proxy/grid-gateway`, pinned by digest)
- the XKS operator Deployments (`rhai-operator` and the cloud managers)
- the vendored operator Deployments in `charts/dependencies/*`, which come from Red Hat registry images pinned by digest

**Two-phase CRD problem and how each path handles it.** Every install path has the same ordering problem: operator CRs can't be applied until OLM or Helm has installed the CRDs. The Kustomize path splits the work into `dependencies/` and `configurations/` and asks the admin to wait between them. The OpenShift chart gates each CR template on `rhoai-dependencies.crdExists`, which uses Helm `lookup` (`_helpers.tpl:457`). The first `helm install` therefore renders only Subscriptions, and a later `helm upgrade` (or an Argo CD resync) adds the CRs. `skipCrdCheck` forces rendering for GitOps tools where `lookup` returns nothing. The XKS chart moves CR creation into post-install hook Jobs (`post-install-crs-job`, `post-install-gateway-job`). Those Jobs poll for CRDs, CA Secrets and GatewayClasses with `kubectl wait`-style loops capped at 300 s. These are three different convergence models with different failure modes:
- the OpenShift chart can render silently partial output
- the XKS hooks can time out
- the Kustomize path depends on the admin doing a manual wait

**Dependency resolution is in the chart.** `shouldInstall`/`isRequiredByComponent`/`isRequiredByService`/`isRequiredByDependency` compute a transitive closure over `components.*.dependencies`, `services.monitoring.dependencies` and `dependencies.*.dependencies`. For example, nvidiaGPUOperator requires nfd, kueue requires certManager, and tempo requires opentelemetry. As a result, the chart's dependency graph is the de facto install-time contract between RHOAI components and their prerequisites. When a component starts needing a new operator, `values.yaml` has to be updated here. The rhods-operator Subscription always gets `DISABLE_DSC_CONFIG=true` (`templates/operator/operator.yaml:10`), so the operator won't create its own default DSC/DSCI and the chart's `default-dsc`/`default-dsci` are authoritative.

**AI Grid introduces a cross-cluster trust domain.** The `grid-enrollment` subchart, in the RHOAI-adapted "external" mode, generates a Grid root CA through cert-manager: a self-signed Issuer, an ECDSA P-256 CA, and `rotationPolicy: Never`. It issues per-site identity Certificates and, through ACM `Policy`/`Placement`, distributes identities and membership to managed clusters. `grid-provider-gateway` serves an mTLS listener on 8080 with `client_cert_mode: require_named`, so peers must present a Grid-CA-signed cert with an allowed SPIFFE identity. The Route uses `passthrough` so the TLS session terminates in the pod and isn't broken by re-encryption. `grid-gateway` (the consumer) terminates TLS on 8443 with an OpenShift service-ca cert, strips the caller's `Authorization` header, maps the model name to `X-Gateway-Model-Name`, and routes over `grid_site_route` to peer sites. Calls to the local KServe gateway use a long-lived ServiceAccount token (`grid-model-client-token`, `kubernetes.io/service-account-token`). That token has no automatic rotation and is mounted into both gateways.

**Upstream chart adaptation.** The Praxis subcharts are pulled from `praxis-proxy/grid` and mechanically rewritten by `scripts/adapt-ai-grid-charts.py`. Each template is wrapped in a `*.rhoai.<file>` define plus an `if .Chart.IsRoot` guard, and the parent chart renders them explicitly through `<chart>.rhoai.resources` in `templates/components/ai-grid.yaml`. This lets the parent gate them on DSC state (`aiGridManaged`) and alias `praxis-gateway` as `praxis-provider-gateway`. The trade-off is that upstream changes have to be re-adapted. These charts are at `0.3.0-rc.4`, so they are pre-release.

**Risk observations.**
- The XKS chart's `rhai-operator-role` ClusterRole grants `*` verbs on `roles`, `clusterroles`, `rolebindings` and `clusterrolebindings` (privilege-escalation capable), plus `*` apiGroups for Deployments, Services and StatefulSets.
- The XKS `rhai-operator` serves metrics on `0.0.0.0:8080` over plain HTTP with `--metrics-secure=false`.
- The XKS `inference-gateway` always renders an HTTP:80 listener alongside HTTPS:443.
- The ACM `ScrapeConfig` scrapes the RHOAI OTel collector over plain HTTP on 8890.
- The XKS images default to `quay.io/opendatahub/opendatahub-operator:latest` with `imagePullPolicy: Always`. According to the values comment, Konflux replaces them at chart-build time, but a source install pulls a floating tag.
- On this RHOAI branch, the OpenShift chart still defaults `operator.type: odh` (`community-operators`, `fast-3`). RHOAI consumers must set `operator.type: rhoai`, or use an AI Grid profile, which sets it.

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Gateway `allowedRoutes.namespaces.from` is mandatory (Selector/Same); Authorino cluster-wide; grid mTLS between sites | Kubernetes Gateway API / Authorino / Praxis | `grid-gateway` strips caller identity, so cross-site requests carry only site identity plus a shared `grid-model-client` token. Per-user tenancy can't be enforced at the provider site |
| Data storage | Usage-log LokiStack in `openshift-logging` tenant mode, with `cluster_name` stream label per spoke | Loki gateway (application) | All spokes write to the `infrastructure` tenant. Separation between spokes is by label only |
| Network traffic | NetworkPolicies for grid-gateway (ingress policy-group + monitoring namespaces), `allow-acm-rhai-metrics` | Kubernetes NetworkPolicy | `grid-provider-gateway` has no NetworkPolicy in the combined profile render. Peers reach it through the passthrough Route, protected by mTLS only |
| Compute & resources | None defined (praxis `resources: {}` by default) | n/a | No ResourceQuota/LimitRange. Kueue integration is configured for workloads but not for platform pods |
| Configuration & secrets | Per-namespace Secrets; bootstrap Role names the Secrets it may read | Kubernetes RBAC | grid-enrollment hub-site Role can `create` any Secret in the operator namespace. Bootstrap RBAC persists after uninstall |
| API scoping | Cluster-scoped CRs (`DataScienceCluster`, `Platform`, `*KubernetesEngine`, `GatewayConfig`) | Kubernetes | Platform-wide singletons by design |
