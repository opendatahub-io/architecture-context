NOTE: kube-rbac-proxy is a sidecar utility. This repo ships NO production
Deployment, Service, Ingress/HTTPRoute, RBAC or Secret. Ports, namespaces,
certificates and RBAC are supplied by the consuming RHOAI operator. The
topology below is the typical sidecar pattern used in RHOAI 3.x.

Data Flows:
  Flow 1 — Authenticated request (TokenReview + SAR)
    1. Client          → kube-rbac-proxy  8443/TCP HTTPS TLS1.2+  Bearer / client cert
    2. kube-rbac-proxy → kube-apiserver   6443/TCP HTTPS TLS1.2+  SA token (TokenReview)
    3. kube-rbac-proxy → kube-apiserver   6443/TCP HTTPS TLS1.2+  SA token (SAR, per attribute set)
    4. kube-rbac-proxy → upstream         8080/TCP HTTP localhost optional identity headers
    5. kube-rbac-proxy → stdout           OCSF JSON (optional)
  Flow 2 — Prometheus metrics scrape
    1. Prometheus      → kube-rbac-proxy  8443/TCP HTTPS TLS1.2+  Bearer SA token
    2. kube-rbac-proxy → kube-apiserver   6443/TCP HTTPS TLS1.2+  SA token (TokenReview)
    3. kube-rbac-proxy → upstream /metrics 8080/TCP HTTP          hardcoded allow, NO SAR
  Flow 3 — OIDC-authenticated request
    1. kube-rbac-proxy → OIDC issuer      443/TCP HTTPS           none (discovery/JWKS)
    2. Client          → kube-rbac-proxy  8443/TCP HTTPS TLS1.2+  OIDC JWT bearer
    3. kube-rbac-proxy → kube-apiserver   6443/TCP HTTPS TLS1.2+  SA token (SAR)
    4. kube-rbac-proxy → upstream         8080/TCP HTTP           identity headers (optional)

Unauthenticated / Reduced-Auth Surfaces:
  - --ignore-paths matches: authentication and authorization bypassed by design
  - /healthz on --proxy-endpoints-port: TLS only, no auth
  - GET /metrics for openshift-monitoring:prometheus-k8s: always allowed by the
    hardcoded authorizer, regardless of cluster RBAC (TODO in source to remove)
  - --insecure-listen-address (deprecated): plaintext HTTP/h2c, same auth chain
    but no transport encryption (examples/oidc still uses it)
  - Upstream hop is plaintext by default; identity headers are only safe on a
    localhost hop

Authorization Model:
  Union authorizer = hardcodedMetricsAuthorizer → staticAuthorizer → sarAuthorizer
  - Format1: resourceAttributes + rewrites (query param / header templating)
  - Format2: endpoints[].mappings[].resources[] with named path captures,
             per-method mappings; unmapped method → 403 (deny by default)
  - Templates use Go text/template, e.g.
        namespace: '{{ index .PathParams "tenant" }}'
  - Risk: a template resolving to an empty namespace makes the SAR
          cluster-wide; caller-controlled header/query/path values feed SARs
  - Revocation latency: up to 5 min (SAR allow cache), 2 min (TokenReview)

RBAC Summary (no production RBAC in repo; from test/ and examples/):
  Proxy ServiceAccount (required, ≈ system:auth-delegator):
  - ClusterRole: kube-rbac-proxy / kube-rbac-proxy-verb-override /
                 named-captures-kube-rbac-proxy
    - API Groups: authentication.k8s.io   Resources: tokenreviews          Verbs: create
    - API Groups: authorization.k8s.io    Resources: subjectaccessreviews  Verbs: create
  Client-side roles (examples of what callers need, checked via SAR):
  - ClusterRole metrics                              nonResourceURL /metrics     get
  - ClusterRole kube-rbac-proxy-client               services/proxy              get
  - Role namespace-metrics                           namespace/metrics           get
  - Role named-job-reader (ns tenant-a)              batch.example.io/jobs       get
  - Role kube-rbac-proxy-verb-override-client        pods                        list
  - cluster-reader / cluster-writer (minikube fix example only)  * / *   get,list,watch / *
  Bindings:
  - kube-rbac-proxy (default)                    → SA kube-rbac-proxy
  - kube-rbac-proxy-verb-override (default)      → SA kube-rbac-proxy-verb-override
  - named-captures-kube-rbac-proxy (named-captures) → SA kube-rbac-proxy
  - kube-rbac-proxy-client (default)             → SA default
  - namespace-metrics (default)                  → SA default
  - named-job-reader (tenant-a)                  → SA job-reader
  - kube-rbac-proxy-verb-override-client (monitoring) → SA krp-curl-verb-override
  - metrics (default)                            → User admin

Service Mesh Configuration:
  - None. kube-rbac-proxy does not configure PeerAuthentication or
    AuthorizationPolicy; it performs its own TLS termination and authz.
  - Network isolation relies on consumer NetworkPolicies and on the upstream
    binding only to localhost.

Secrets (all consumer-defined and mounted as files; none in this repo):
  - Serving cert (kubernetes.io/tls) — --tls-cert-file/--tls-private-key-file,
    usually OpenShift service-ca; hot-reloaded (pkg/tls/reloader.go)
  - Client CA / upstream CA / upstream client cert (Opaque or ConfigMap) —
    client and OIDC CA reloaded dynamically; upstream CA read once at start
  - ServiceAccount token (projected) — Kubernetes API calls; auto-rotated
  - Token leakage: TokenReview spec.token masked in klog (SanitizingFilter)

Crypto / FIPS:
  - Build: GOEXPERIMENT=strictfipsruntime, -tags=strictfipsruntime, CGO_ENABLED=1
           (Dockerfile.konflux, Dockerfile.redhat)
  - Runtime base: ubi9/ubi-minimal-pqc (OpenSSL with PQC), digest-pinned
  - No MD5/SHA1/RC4/DES, math/rand or InsecureSkipVerify in non-test code
  - Config risk: no --tls-cipher-suites → Go defaults; relies on injecting
    operator to project the OpenShift APIServer TLS security profile
  - Build hermeticity: Konflux hermetic, gomod prefetch (Hermeto); no RPM lock

Multi-Tenancy:
  - Tenant boundary: per namespace, from static or templated SAR attributes
  - One stateless sidecar per workload pod; single upstream
  - Gaps: config correctness, 5 min revocation delay, hardcoded Prometheus
    grant, --ignore-paths bypass, upstream bound to pod IP bypasses proxy
