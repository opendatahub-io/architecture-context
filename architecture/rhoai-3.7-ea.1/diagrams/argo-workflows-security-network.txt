Data Flows:
  Flow 1 KFP run:  KFP API -> kube API (create Workflow) -> controller watches,
                   creates pods -> argoexec init pulls inputs (S3 443) ->
                   argoexec wait uploads outputs/logs (S3 443) -> writes
                   WorkflowTaskResult (6443) -> controller updates status (6443)
  Flow 2 HTTP:     controller creates WorkflowTaskSet + agent pod -> agent calls
                   user endpoint (any port, TLS optional) -> patches status
  Flow 3 Metrics:  Prometheus -> controller 9090/TCP HTTPS (self-signed, no auth)

RBAC Summary:
- RHOAI: DSPO namespace Role for the controller SA
  (data-science-pipelines-operator config/internal/workflow-controller/role.yaml.tmpl).
  Workflow pods run as the workflow-specified SA (default pipeline-runner-<dspa>).
- Upstream cluster-install (NOT used by RHOAI), ClusterRole argo-cluster-role -> SA argo:
  - core: pods, pods/exec            create,get,list,watch,update,patch,delete
  - core: configmaps                 get,watch,list
  - core: persistentvolumeclaims(+finalizers)  create,update,delete,get
  - core: serviceaccounts            get,list
  - core: events                     create,patch
  - core: secrets (argo-workflows-agent-ca-certificates)  get
  - argoproj.io: workflows, workflowtasksets, workflowartifactgctasks (+finalizers)
                                     get,list,watch,update,patch,delete,create
  - argoproj.io: workflowtemplates, clusterworkflowtemplates  get,list,watch
  - argoproj.io: workflowtaskresults list,watch,deletecollection
  - argoproj.io: cronworkflows(+finalizers)  get,list,watch,update,patch,delete
  - policy: poddisruptionbudgets     create,get,delete
- Upstream Role argo-role (ns argo) -> SA argo: leases create,get,update; secrets get
- Upstream ClusterRole argo-server-cluster-role -> SA argo-server (not shipped)
- argo-aggregate-to-view/edit/admin aggregate Workflow CR access into built-in roles

Network Policy:
- DSPO NetworkPolicy: controller ingress on 9090/TCP allowed only from monitoring
  namespaces. Step pod egress is not restricted by this repo.

Service Mesh Configuration:
- None. No PeerAuthentication / AuthorizationPolicy defined.

Secrets:
- Artifact repository credentials (Opaque) - S3/GCS/Azure keys used by argoexec;
  provisioned by DSPO / user; no auto-rotation
- argo-workflows-agent-ca-certificates (Opaque) - optional CA bundle for agent pods
- sso (Opaque) - argo-server SSO RSA key (not shipped)
- argo-workflows-webhook-clients (Opaque) - webhook client tokens (not shipped)
- argo-server TLS secret (kubernetes.io/tls) - else self-signed (not shipped)

Security Observations:
- Unauthenticated /healthz on 6060/TCP (plain HTTP, default mux).
- Metrics on 9090 use a self-signed cert generated at startup; no client auth.
- util/tls/tls.go:127 sets InsecureSkipVerify on the generated self-signed config.
- HTTP templates can disable TLS verification per template.
- FIPS: CGO_ENABLED=0 GOFIPS140=v1.0.0 -tags no_openssl, static binaries
  (Go native FIPS 140-3 module, not OpenSSL). Base: ubi9/ubi-minimal-pqc.
  Departs from the classic check-payload dynamic-OpenSSL rule; track acceptance.
- Build: hermetic Konflux (gomod + rpm prefetch), multi-arch x86_64/arm64/ppc64le.
