Admission Control:
- MutatingWebhookConfiguration mraycluster.kb.io (failurePolicy: Fail)
  - Sets odh.ray.io/secure-trusted-network="true", spec.tlsOptions.enabled,
    platform NetworkPolicy profile, enableIngress=false
- ValidatingWebhookConfiguration vraycluster.kb.io (failurePolicy: Fail)
  - Forbids custom egress, extra ingress beyond platform set, unmanaged
    managedBy values, invalid managed port overrides
- RayJob / RayService validating handlers registered in-process but not
  configured in the OpenShift overlay webhook.yaml

Service Mesh Configuration:
- None. No Istio sidecars / PeerAuthentication defined by this component.
- Ray-internal mTLS (gRPC/GCS) provided by Ray itself (RAY_USE_TLS) with
  per-cluster cert-manager PKI.

Network Policies:
- kuberay-operator-allow-metrics-traffic (operator pod): 8443 from monitoring
  namespaces; 8082 and 9443 port-only (no source restriction)
- Per-RayCluster head/worker policies: same cluster, same namespace (8265/
  10001), operator, Gateway pods, monitoring namespace, RayJob submitters;
  source-less 8443 rule retained; legacy OpenShift policies kept during
  migration

Secrets:
- kuberay-webhook-server-cert (kubernetes.io/tls) - webhook serving cert,
  cert-manager (selfsigned-issuer -> serving-cert), auto-rotated
- kuberay-operator-metrics-tls (kubernetes.io/tls) - metrics HTTPS cert,
  OpenShift service-ca, auto-rotated
- <cluster>-ca-secret-<uid> (kubernetes.io/tls) - per-RayCluster root CA,
  RSA-4096, ~10y, renew 30d before; cert-manager
- ray-head-secret-<cluster> / ray-worker-secret-<cluster> (kubernetes.io/tls)
  - Ray mTLS leaf certs, 90d, renew 15d before; pods keep old cert until restart
- <cluster> (Opaque) - Ray auth token (32 bytes crypto/rand) when
  authOptions.mode=token and no user secret; NOT auto-rotated

Crypto / FIPS:
- Build: CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime -tags strictfipsruntime,
  dynamic link, OpenSSL from ubi-minimal-pqc
- TLS: cluster APIServer TLSSecurityProfile; CBC/3DES/RC4 banned under any
  profile; fallback Intermediate (TLS 1.2+, ECDHE-GCM/ChaCha20); ALPN h2,http/1.1
- No InsecureSkipVerify in operator source; SHA-1 only for pod-template hashing
- Hermetic Konflux build (Hermeto gomod prefetch), digest-pinned base images,
  x86_64 / arm64 / ppc64le

Key Security Observations:
1. Gateway -> Ray dashboard path (8265) bypasses kube-rbac-proxy per-cluster SAR;
   tenant authorization relies on platform Gateway auth (unverified here).
2. Operator -> Ray dashboard, Submitter -> dashboard, and Ray metrics are
   plaintext HTTP; Ray mTLS covers only the gRPC/GCS plane.
3. Single-replica operator + failurePolicy: Fail webhooks: restarts (including
   automatic TLS-profile-change restarts) briefly block RayCluster admission.
4. Possible metrics port mismatch (Service 8443 vs binary bind :8080).
5. Cluster-wide create/delete on Secrets, Pods, Roles/RoleBindings,
   NetworkPolicies, Gateways/HTTPRoutes: high-value service account.
6. Any pod in the same namespace can reach dashboard (8265) and client (10001).
7. All tenants' HTTPRoutes live in one platform namespace.
