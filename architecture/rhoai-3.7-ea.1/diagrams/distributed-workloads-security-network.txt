DISTRIBUTED-WORKLOADS — SECURITY NETWORK DIAGRAM (RHOAI 3.7.0-ea.1)
Source: architecture/rhoai-3.7-ea.1/distributed-workloads.md
Repo commit: 1b79f85e5b48451abf5a245ca78b7fc37a66047a (branch rhoai-3.7-ea.1)

SCOPE NOTE: This repo is a container-image build repo plus an E2E test suite.
It deploys NO platform Service, Route, operator or controller. The network paths
below are the runtime behaviour of the images it ships (universal training images)
inside workloads owned by other components (notebooks, trainer), plus the E2E
test client. Example/workshop manifests are listed separately as DEMO ONLY.

RBAC Summary:
- ClusterRoles defined by this repo: NONE
- E2E suite creates namespaced Roles/RoleBindings per test (tests/common/support/rbac.go)
- Example/workshop RoleBindings only:
  - edit (ns: distributed) → ClusterRole edit → SA stable-diffusion-nb
  - nfs-server-sa-anyuid (ns: nfs) → system:openshift:scc:anyuid → SA nfs-server-sa
  - nfs-server-sa-privileged (ns: nfs) → system:openshift:scc:privileged → SA nfs-server-sa

Authentication & Authorization:
- Jupyter (workbench mode): in-pod token disabled; enforced by workbench
  gateway/auth proxy (notebooks component); namespace user access
- sshd 2222 (MPI): public key only; enforced by sshd (mpiuser-sshd.conf)

Service Mesh Configuration:
- None defined. No PeerAuthentication, AuthorizationPolicy or NetworkPolicy shipped.

Secrets:
- MPI SSH key (/home/mpiuser/.ssh/id_rsa, authorized_keys) - mounted, provisioned
  per job by Kubeflow Trainer MPI runtime, no rotation (per-job)
- Test env credentials (AWS_*, HF_TOKEN, NOTEBOOK_USER_TOKEN) - env vars, CI operator,
  no rotation
- minio / minio-secret (Opaque, EXAMPLE ONLY) - hardcoded minio/minio root creds

Crypto / FIPS Posture:
- Images are "FIPS-friendly by construction", not FIPS-validated
- OpenSSL inherited from RHEL9 workbench base
- TensorBoard Rust tensorboard_data_server removed (non-FIPS bundled crypto)
- Native wheels not verified against FIPS OpenSSL: grpcio (BoringSSL), blake3,
  cryptography, pyOpenSSL, sigstore
- Test code uses InsecureSkipVerify for Ray dashboard, S3, Trainer metrics

Build Hermeticity:
- Universal images: Hermeto/Cachi2 prefetch, hermetic: "true", --no-index
- RPM lock: CUDA + CPU (openssh-server only); ROCm has none
- requirements.txt fully pinned but WITHOUT --hash
- Ray images: non-hermetic, UBI9 python base, not AIPCC
- tests image downloads oc 4.18 over HTTPS without checksum

Notable Risks:
- /etc/passwd group-writable in CUDA/CPU images (needed for arbitrary UID)
- MPI sshd on 2222 relies on keys only; no NetworkPolicy
- Lockfiles compiled against AIPCC rhoai/3.6 index on 3.7 branch
