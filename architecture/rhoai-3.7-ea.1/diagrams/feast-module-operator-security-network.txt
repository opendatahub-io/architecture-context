external (north-south) exposure. All traffic is cluster-internal.

EGRESS
- Kubernetes API server 6443/TCP HTTPS TLS 1.2+, SA token.
- No external network calls at runtime; manifests are read from the image.
- NetworkPolicy allows all egress (unrestricted).

RBAC Summary:
- ClusterRole: opendatahub-feast-manager-role
  (bound via ClusterRoleBinding opendatahub-feast-manager-rolebinding
   to SA opendatahub-feast-operator)
  - core: configmaps, serviceaccounts, services - full CRUD + deletecollection
  - core: namespaces - create, get, list, patch, update, watch
  - core: pods - create, delete, deletecollection, get, list, watch
  - core: pods/exec - create                          !! high privilege
  - core: secrets - get, list, watch (cluster-wide)   !! high privilege
  - core: persistentvolumeclaims, pods/log, events
  - apiextensions.k8s.io: customresourcedefinitions - CRUD
  - apps/deployments, batch/cronjobs+jobs, autoscaling/hpa, policy/pdb,
    networking.k8s.io/networkpolicies, coordination.k8s.io/leases - CRUD
  - rbac.authorization.k8s.io: clusterroles, clusterrolebindings, roles,
    rolebindings - CRUD; clusterroles bind (system:auth-delegator)  !! high
  - authentication.k8s.io/tokenreviews, authorization.k8s.io/subjectaccessreviews - create
  - components.platform.opendatahub.io: feastoperators (+status, finalizers)
  - feast.dev: featurestores (+status, finalizers) - CRUD
  - dataregistry.opendatahub.io: registries, tables, volumes, ... - CRUD; connections use
  - monitoring.coreos.com/servicemonitors - CRUD
  - route.openshift.io: routes, routes/custom-host
  - config.openshift.io: apiservers - get, list, watch
  - sparkoperator.k8s.io/sparkapplications - create, delete, get
  - kubeflow.org/notebooks, mlflow.opendatahub.io/mlflows - read
  - olm.operatorframework.io, operators.coreos.com - read
  - nonResourceURL /metrics - get
  Rationale: most grants exist only so the module can create the Feast
  operator's ClusterRole (Kubernetes RBAC escalation prevention).
- ClusterRole: opendatahub-feast-metrics-auth-role (tokenreviews/SARs create)
  bound via opendatahub-feast-metrics-auth-rolebinding
- ClusterRole: opendatahub-feast-metrics-reader (/metrics get)
- ClusterRoles: opendatahub-feast-components-feastoperator-{admin,editor,viewer}-role
- Role: opendatahub-feast-leader-election-role (configmaps, events, leases)
  bound via RoleBinding opendatahub-feast-leader-election-rolebinding
- Payload (RHOAI): feast-operator-openshift-tls-profile-reader-binding ->
  SA feast-operator-controller-manager (redhat-ods-applications)

Service Mesh Configuration:
- None. No PeerAuthentication / AuthorizationPolicy; no sidecars.

Secrets:
- controller-manager-metrics-tls (kubernetes.io/tls) - Feast operator metrics
  serving cert; OpenShift service-ca; auto-rotated.
- metrics-server-cert (kubernetes.io/tls) - optional module metrics cert via
  cert_metrics_manager_patch.yaml; NOT wired by default (module uses
  self-signed cert).
- The module reads no Secrets at runtime (Secrets bypass the cache).

Crypto / FIPS:
- Build: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime, dynamic link,
  ubi-minimal-pqc base (Dockerfile.konflux). Upstream Containerfile is non-FIPS.
- Metrics TLS follows cluster APIServer tlsSecurityProfile when adherence is
  strict; supportedCipherSuiteIDs() includes tls.InsecureCipherSuites(), so an
  Old/Custom profile can enable legacy ciphers.

Key Risks:
1. Metrics bind-address env var mismatch (likely :8080 vs 8443 Service/NetPol).
2. Self-signed metrics certificate on the module operator.
3. Broad ClusterRole concentrated in one SA (pods/exec, secrets, RBAC CRUD, bind).
4. migrateDeploymentSelector deletes the Feast Deployment on selector mismatch
   -> brief Feast operator outage on first upgrade from monolith installs.
5. Egress unrestricted by NetworkPolicy.
