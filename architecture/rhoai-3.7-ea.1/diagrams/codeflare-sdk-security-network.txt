Deployment type: Client library. No in-cluster workload, no Service, no Ingress,
no listening port, no service account. All calls use the END USER's identity.

Trust Boundary Notes:
- The SDK adds no privilege; security posture == user's RBAC in the namespace.
- Ray mTLS trust boundary == namespace Secret-read RBAC: any user who can read
  Secrets in the namespace can read the CA private key and mint client certs
  trusted by that Ray cluster.
- SDK sets enableIngress: false on the RayCluster head; dashboard exposure is
  left to KubeRay + RHOAI networking.
- Opt-outs that weaken TLS: deprecated TokenAuthentication(skip_tls=True)
  (silences urllib3 warnings), verify_tls=False for dashboard, migration script
  suppresses InsecureRequestWarning by default.

RBAC Summary (TEST ONLY - images/tests/rbac-test-user-permissions.yaml; not shipped):
- The SDK has NO ServiceAccount. Minimum user permissions illustrated by tests:
- ClusterRole: test-user-ray-admin
  - API Groups: ray.io
  - Resources: rayclusters, rayjobs

- ClusterRole: test-user-kueue-admin

  - Resources: clusterqueues, localqueues, resourceflavors, workloads
  - Verbs: create, delete, get, list, patch, update, watch
- ClusterRole: kueue-batch-user-role
  - "" namespaces: create, get, list, watch
  - kueue.x-k8s.io clusterqueues, localqueues, resourceflavors: full CRUD+watch
  - ray.io rayclusters, rayjobs: full CRUD+watch

Service Mesh Configuration:
- None. The SDK relies on platform Gateway auth (kube-auth-proxy) and
  NetworkPolicies; it creates no PeerAuthentication / AuthorizationPolicy.

Secrets:
- <cluster>-ca-secret-* (Opaque: ca.crt/tls.crt + tls.key/ca.key) - Ray cluster
  CA; provisioned by KubeRay/RHOAI; SDK READS PRIVATE KEY; no auto-rotate
  (refresh_certificates() / force_regenerate available)
- <rayjob> file Secret (Opaque) - zipped local files for submitter pod; created
  by SDK; ownerRef -> RayJob; GC'd; size checked by validate_secret_size
- image_pull_secrets (kubernetes.io/dockerconfigjson) - user-specified,
  referenced in RayCluster pod specs
- Local ~/.local/share/codeflare/tls/<cluster>-<ns>/ files (0600) - client
  mTLS material; RSA-3072/SHA-256; 30-day default validity; dir key omits API
  server (cross-cluster collision possible)
- minio-secret (test only) - e2e fixture with hardcoded credentials

Crypto / FIPS:
- cryptography (OpenSSL-backed); FIPS depends on workbench image OpenSSL and
  host FIPS mode. No MD5/SHA1/custom RNG in library code.
