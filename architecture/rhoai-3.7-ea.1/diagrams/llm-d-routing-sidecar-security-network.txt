Key Risks:
- SSRF: the prefill target comes from the x-prefiller-host-port request header. SSRF
  protection is OFF by default (allow all). Any caller that reaches :8000 directly can make
  the decode pod POST arbitrary bodies to any reachable host, including in other namespaces.
- When the allowlist is on, it matches host only (pod IP + pod name), so any port on a
  member pod is reachable. Only the pool informer is waited on, so requests may get 403
  until the pod cache syncs. Scheme-prefixed header values fail closed (403).
- No authentication in the sidecar. It relies on the Gateway AuthPolicy and network
  reachability.
- TLS certificates are loaded once with no reload. The upstream DestinationRule therefore
  uses InsecureSkipVerify for Gateway -> sidecar in P/D mode.
- Egress to the prefiller and decoder is plaintext by default.
- The cipher list includes ChaCha20-Poly1305 (not FIPS-approved). CGO_ENABLED=0 static
  build: the image would fail the Konflux check-payload FIPS gate as built here.

Service Mesh / Gateway Configuration (RHOAI, per overlay 0011):
- Gateway-level Kuadrant AuthPolicy authenticates clients (Bearer token).
- Workload DestinationRule: TLS origination to sidecar :8000, InsecureSkipVerify=true in P/D mode.
- No PeerAuthentication / AuthorizationPolicy defined by this repo.

Secrets:
- (name set by deployer, mounted at -cert-path) kubernetes.io/tls - tls.crt / tls.key server
  cert, provisioned externally (KServe / OpenShift service-ca); no reload, no auto-rotate in-process
- (in-memory) self-signed RSA-4096 fallback cert, 10-year validity, regenerated on restart

Scaffold-only network objects (not the RHOAI deployment path):
- Service ${PROJECT_NAME}-service ClusterIP 8080/TCP. The selector does not match the pod
  labels, and port 8080 does not match the default listener port 8000.
- Route ${PROJECT_NAME}-route, edge TLS -> 8080. Plaintext goes to a backend that serves TLS
  by default.
