Endpoints:
- POST /api/v1/text/contents  8080/TCP  HTTP  Encryption: none  Auth: none
    Body: {contents: [str], detector_params: {regex: [str]}}
    Returns: [[{start, end, text, detection_type, detection, score: 1.0}]]
    Errors: 400 "empty regex" only; invalid custom regex -> warn! log, still 200
- GET  /health                8080/TCP  HTTP  Encryption: none  Auth: none  -> "healthy"

Security Observations:
1. Sensitive data in logs: full payload (SSNs, card numbers, emails) logged at INFO
   (src/detectors.rs:100). Leftover println!("hi") at src/detectors.rs:99.
2. Unauthenticated, plaintext endpoint: any client that can reach 8080/TCP can submit text.
3. Untrusted regex input: the regex crate is linear-time (no catastrophic backtracking),
   but there is no body-size limit beyond Axum's default, no pattern-size limit and no
   timeout. Patterns are compiled per request, so CPU/memory use is unbounded.
4. Silent errors: built-in detector errors dropped; invalid custom regex ignored with 200.
5. Response shape: detections flattened into one nested array and not grouped per input,
   which differs from the orchestrator's per-content list-of-lists contract.
