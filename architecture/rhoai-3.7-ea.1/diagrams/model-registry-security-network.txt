NOTE: The registry (proxy) and catalog servers serve plain HTTP on 8080/TCP with
NO in-process authentication or authorization. In RHOAI all access control is
provided by the model-registry-operator (kube-rbac-proxy / Gateway HTTPRoute),
which lives outside this repo. Steps marked "operator-defined" are inferred.

RBAC Summary (upstream controller manifests; RHOAI uses operator-owned RBAC):
- ClusterRole: controller-model-registry-manager-role
  - "" services: get, list, watch
  - serving.kserve.io inferenceservices: get, list, patch, update, watch
  - serving.kserve.io inferenceservices/finalizers: create, delete, get, list,
    patch, update, watch
- ClusterRole: controller-metrics-auth-role
  - authentication.k8s.io tokenreviews: create
  - authorization.k8s.io subjectaccessreviews: create
- ClusterRole: controller-metrics-reader
  - nonResourceURL /metrics: get
- Role: controller-leader-election-role (ns: kubeflow)
  - "" configmaps, coordination.k8s.io leases: create, delete, get, list,
    patch, update, watch
  - "" events: create, patch
- Bindings (SA controller-controller-manager):
  - controller-model-registry-manager-rolebinding -> manager-role (ClusterRole)
  - controller-metrics-auth-rolebinding -> metrics-auth-role (ClusterRole)
  - controller-leader-election-rolebinding -> leader-election-role (Role)
- Registry and catalog servers: no Kubernetes RBAC, no in-process authz.

Authentication & Authorization:
- /api/model_registry/* (8080): none in-process. RHOAI: kube-rbac-proxy/Gateway
  (operator). Upstream: Istio AuthorizationPolicy ALLOW ingress-gateway SA, or
  kubeflow-namespace callers with Authorization header and no kubeflow-userid.
- /api/*_catalog/* (8080): none in-process; upstream ships no
  AuthorizationPolicy for the catalog.
- :8443/metrics (upstream controller): TokenReview + SubjectAccessReview,
  controller-runtime self-signed TLS, HTTP/2 disabled.
- :8081/healthz,/readyz (upstream controller): unauthenticated probes.

Service Mesh Configuration (upstream Kubeflow only, not used in RHOAI):
- VirtualService model-registry on kubeflow-gateway, /api/model_registry/
- VirtualService model-catalog, model-registry-ui
- DestinationRule: ISTIO_MUTUAL
- AuthorizationPolicy: see above

Secrets:
- model-catalog-postgres (Opaque) - catalog DB POSTGRES_USER/POSTGRES_PASSWORD;
  kustomize secretGenerator dev defaults / operator; no rotation
- model-catalog-hf-api-key (Opaque, optional) - Hugging Face API key; no rotation
- skill-catalog-git-credentials (Opaque, optional) - git creds; admin; no rotation
- mysql-secret (Opaque) - registry DB username/password (upstream); no rotation
- registry-redhat-io-credentials (kubernetes.io/dockerconfigjson) - pull secret
  for performance-data init image (RHOAI overlay)
- Job credentials (Opaque, env/mounted) - AWS keys, OCI creds, registry token;
  created per Job by BFF/dashboard; no rotation

Key Risks:
1. No in-process auth on registry/catalog; a reachable Service = full
   unauthenticated read/write. No NetworkPolicy for these Services in repo.
2. DB client TLS skips server cert verification by default.
3. Catalog Postgres connection has no TLS configured in manifests.
4. ISVC controller optional InsecureSkipVerify; Job optional OCI TLS-verify off.
5. DB cipher list option includes non-FIPS suites (CBC-SHA, ChaCha20).
