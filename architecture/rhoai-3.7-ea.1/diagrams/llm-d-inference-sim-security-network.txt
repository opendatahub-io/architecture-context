RBAC Summary:
- None. The simulator makes no Kubernetes API calls (controller-runtime is
  imported only for logging helpers). No ClusterRoles, Roles or bindings.

Authentication & Authorization:
- All HTTP routes (inference, admin, LoRA, sleep, metrics): NONE
- gRPC VllmEngine + reflection: NONE, no transport credentials
- ZMQ PUB / ROUTER: NONE, no CURVE
- Rely on namespace/network isolation; never expose outside a trusted
  test namespace.

Service Mesh Configuration:
- None shipped (no PeerAuthentication, AuthorizationPolicy or NetworkPolicy).

TLS Configuration (optional, HTTP only):
- crypto/tls, MinVersion TLS 1.2, max unconstrained (TLS 1.3)
- TLS 1.2 suites: ECDHE AES-128/256-GCM, CHACHA20-POLY1305 (non-FIPS)
- Cert sources: mounted cert/key files (fsnotify hot-reload) or in-process
  self-signed RSA-4096 cert valid 10 years (--self-signed-certs)
- No client-cert (mTLS) verification

Secrets:
- No Kubernetes Secrets referenced.
- HF_TOKEN (render sidecar) - plain env value via envsubst, visible in pod spec
- TLS cert/key files (--ssl-certfile/--ssl-keyfile) - mounted files, manual or
  cert-manager (operator choice), hot-reloaded on change

FIPS / Build:
- CGO_ENABLED=0 static Go binary, distroless base, no OpenSSL, no
  strictfipsruntime -> would fail check-payload as built
- No .konflux Dockerfile, no Hermeto prefetch, no RPM lock files

Key Risks:
1. Unauthenticated POST /admin/config changes latency, failure injection and
   fake metrics at runtime.
2. Unauthenticated LoRA load/unload and sleep/wake_up endpoints.
3. HF_TOKEN in plain env in sample manifests.
4. gRPC plaintext-only; disappears silently when TLS is enabled.
5. ZMQ KV events unauthenticated/unencrypted; can be spoofed or sniffed by
   anything on the network path to the KV-cache indexer.
