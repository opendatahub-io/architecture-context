Egress (operator):
- kube-apiserver 6443/TCP HTTPS, TLS 1.2+, ServiceAccount token
  (reconciliation, SSA, TLS profile reads, TokenReview/SAR)
- No other egress. No Ingress, Route or Gateway created for the operator.

Data Flows:
1. Enable sub-component: rhods-operator -> apiserver (set toggle) ->
   watch -> operator renders /opt/manifests -> SSA apply CRDs, RBAC,
   Deployments, webhook, Kuadrant/Istio objects -> patch AIGateway status.
2. Metrics scrape: Prometheus -> 8443/TCP HTTPS Bearer -> operator ->
   TokenReview + SubjectAccessReview on apiserver.
3. MaaS removal: operator annotates maas-controller Deployment
   teardown-requested=true -> maas-controller self-teardown, sets
   teardown-completed=true -> operator GCs MaaS + ai-gateway-controller,
   deletes secret-migrate Role/RoleBinding (infra NS + secret kept).

RBAC Summary:
- ClusterRole: ai-gateway-manager-role (~76 rules, cluster-wide; union of
  all vendored sub-component ClusterRoles, required to avoid RBAC escalation
  denial)
  HIGH-RISK grants:
  - rbac.authorization.k8s.io clusterroles, clusterrolebindings, roles,
    rolebindings: create, delete, get, list, patch, update, watch
    (an unrestricted rule cancels resourceNames narrowing)
  - "" secrets: create, delete, get, list, patch, watch (cluster-wide)
  - "" serviceaccounts/token: create (resourceName grid-operator-metrics-scraper)
  - apiextensions.k8s.io customresourcedefinitions: create, list, watch, get;
    update/patch/delete for named MaaS/batch/guardrail CRDs; update/patch
    (no delete) for grid CRDs
  - admissionregistration.k8s.io validatingwebhookconfigurations: create,
    list, watch; get/update/patch/delete on maas-validating-webhook-configuration
  - security.openshift.io securitycontextconstraints nonroot-v2: use

  modelsasservices patch/update), dscinitialization (read), apps, batch,

Service Mesh Configuration:
- None for the operator itself (no sidecar, no PeerAuthentication).
- Vendored MaaS resources target maas-default-gateway in openshift-ingress
  (Kuadrant AuthPolicy, per-route TokenRateLimitPolicy; gateway-default-deny
  TRLP applied separately by deploy.sh, not in the default render).

Network Policies:
- None shipped for the operator in the platform deploy tree
  (config/network-policy is standalone dev only).
- Sub-components ship their own metrics NetworkPolicies.

Secrets:
- ai-gateway-operator-metrics-tls (kubernetes.io/tls) - metrics serving cert,
  OpenShift service-ca, auto-rotated, reloaded by controller-runtime cert watcher
- maas-db-config (Opaque, inferred) - MaaS Postgres connection, provisioned
  by MaaS/admin, rotation not determined, preserved on MaaS removal

TLS / FIPS:
- Metrics TLS from OpenShift APIServer TLS profile (Intermediate fallback,
  min TLS 1.2); RC4 and TLS 1.3 IDs filtered from explicit cipher list;
  process restarts on profile change (SecurityProfileWatcher).
- A TLS 1.0/1.1 minimum is honoured if the cluster profile requests it.
- Konflux build: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime,
  ubi9/ubi-minimal-pqc:9.8 runtime (OpenSSL present), dynamic linking.
- Upstream Dockerfile (CGO_ENABLED=0, ubi10-micro) is not FIPS-suitable and
  not used by Konflux.

Security Findings to Review:
1. Operator SA is effectively cluster-admin-equivalent (RBAC + Secret
   manipulation cluster-wide).
2. AI Grid LoadBalancer Services (9091/TCP, 7946/UDP) may be externally
   exposed on providers without internal-LB annotations; encryption/auth
   not determined.
3. Vendored manifests come from ODH refs in practice; RHDS pins still on
   rhoai-3.6. Missing RELATED_IMAGE_* leaves upstream defaults (odh-stable,
   ghcr.io/praxis-proxy/grid-operator:v0.3.0-rc.4).
