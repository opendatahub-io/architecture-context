TLS:
- Operator servers (webhooks, metrics): tls.Config from APIServer/cluster
  tlsSecurityProfile; TLS 1.0–1.3 accepted per profile; ALPN h2, http/1.1;
  APIServer watched — profile change triggers controlled restart.
- kube-rbac-proxy: flags generated from profile; TLS 1.2 floor (Intermediate
  fallback); FIPS mode drops non-FIPS ciphers and X25519/X25519MLKEM768.
- Build: CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime, ubi-minimal-pqc runtime.

RBAC Summary:
- ClusterRole aihub-manager-role  (SA aihub-controller-manager) — HIGHLY PRIVILEGED
  - customresourcedefinitions: create, get, list, patch, update, watch
  - mutating/validatingwebhookconfigurations: create, delete, get, list, patch, update, watch
  - clusterroles, clusterrolebindings, roles, rolebindings: full CRUD
  - namespaces: create, get, list, watch
  - configmaps, secrets, services, serviceaccounts, PVCs: full CRUD
  - aihubs (+status/finalizers), catalogs: CRUD
  - superset of child operator permissions (deployments, networkpolicies,
    httproutes, referencegrants, routes, imagestreams, groups,
    storageversionmigrations, modelregistries, leases, servicemonitors, templates)
- ClusterRole model-registry-operator-manager-role (SA model-registry-operator-controller-manager)
  - modelregistries CRUD; deployments, services, secrets, configmaps CRUD
  - roles, rolebindings, clusterrolebindings CRUD; groups (user.openshift.io) CRUD
  - routes, httproutes, networkpolicies, storageversionmigrations CRUD
  - tokenreviews, subjectaccessreviews create
- ClusterRole catalog-manager-role (SA catalog-controller-manager)
  - catalogs CRUD; deployments, networkpolicies, httproutes, routes, imagestreams CRUD
  - roles, rolebindings, clusterrolebindings CRUD; tokenreviews/SARs create
- Runtime (per registry): ClusterRoleBinding {name}-auth-delegator → system:auth-delegator;
  Role registry-user-{name} (get services/endpoints) bound to Group {name}-users
- Runtime (catalog): model-catalog-auth-delegator CRB; Role model-catalog bound to
  system:authenticated; Role model-catalog-admin (configmaps/secrets) bound to
  platform admin group from Auth CR

Admission Webhooks (all failurePolicy: Fail):
- mmodelregistry.opendatahub.io  — defaults; oauthProxy → kubeRBACProxy migration
- vmodelregistry.opendatahub.io  — cluster-wide name uniqueness; ns == REGISTRIES_NAMESPACE
- /convert                        — ModelRegistry v1alpha1 ↔ v1beta1
- vcatalog.aihub.opendatahub.io  — name must be "catalog", ns == REGISTRIES_NAMESPACE (CREATE)

Secrets:
- aihub-controller-manager-metrics-tls (kubernetes.io/tls) — service-ca, auto-rotate
- webhook-server-cert / catalog-webhook-service (kubernetes.io/tls) — service-ca, auto-rotate
- {registry-name}-kube-rbac-proxy, model-catalog-kube-rbac-proxy (kubernetes.io/tls) — service-ca
- {registry-name}-postgres-credentials (Opaque) — 16 random bytes crypto/rand, no rotation
- model-catalog-postgres (Opaque) — generated password, no rotation
- User DB password / SSL cert / key / CA Secrets (Opaque) — user-provided

Risks / Observations:
- AIHub SA can create CRDs, webhook configs, ClusterRoles and namespaces.
- Egress NetworkPolicies are allow-all for operators and workloads.
- Auto-provisioned PostgreSQL traffic is plaintext; user DB TLS off by default.
- On non-OpenShift clusters a ModelRegistry may run with no proxy → REST 8080 unauthenticated.
- Catalog readable by every authenticated user; registry authZ is all-or-nothing.
- All registries' DB Secrets share one namespace.
- Registry ingress NetworkPolicy admits automl-ui pods from any generated namespace.
- Operator servers honor TLS 1.0/1.1 if the cluster profile requests them.
