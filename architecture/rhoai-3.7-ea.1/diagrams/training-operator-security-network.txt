Service Mesh Configuration:
- None. Istio sidecar injection disabled on operator pod; no PeerAuthentication
  or AuthorizationPolicy.

Network Policies:
- Operator namespace: none defined by this component.
- PyTorchJob: per-job NetworkPolicy (SSA) — ingress from same-job pods and
  openshift-monitoring TCP 8080 only.
- Other five frameworks: none.

Secrets:
- kubeflow-training-operator-webhook-cert (Opaque: CA + TLS cert/key)
  - Created empty by kustomize secretGenerator; populated by cert-controller
  - Mounted read-only at /tmp/k8s-webhook-server/serving-certs
  - Auto-rotated by cert-controller; Secret reads bypass informer cache

TLS / Crypto:
- Webhook TLS: crypto/tls, min version + ciphers from OpenShift APIServer
  tlsSecurityProfile, read ONCE at startup (restart needed for changes).
  Fallback: TLS 1.2 + Intermediate ECDHE-AEAD. Modern → TLS 1.3.
  Old → TLS 1.2 with Go default ciphers. Custom may admit non-PFS TLS_RSA_* /
  CBC suites. Empty custom cipher mapping → process exits.
- FIPS: CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime, OpenSSL from UBI9.
- No InsecureSkipVerify, md5 or sha1 usage detected.

Key Security Risks:
1. /metrics on 8080/TCP is plain HTTP without authentication.
2. ClusterRole allows creating Pods, Roles (incl. pods/exec), RoleBindings and
   ServiceAccounts in ANY namespace; can update ANY ValidatingWebhookConfiguration.
3. MPIJob has no admission validation.
4. kubectl-delivery init image is a mutable :latest ghcr.io reference.
5. Only PyTorchJob gets a NetworkPolicy; inter-pod framework traffic is
   plaintext for all frameworks.
6. Single shared reconcile queue (controller-threads=1) across all tenants.
