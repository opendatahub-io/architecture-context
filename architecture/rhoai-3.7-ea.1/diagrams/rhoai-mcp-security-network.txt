rhoai-mcp - Security Network Diagram
Source: architecture/rhoai-3.7-ea.1/rhoai-mcp.md (commit 51e2343, package 0.1.1)
Two deploy-time security postures:
  [SA]   ServiceAccount-as-actor (base, openshift, odh, rhoai overlays)
  [OIDC] Multi-user OIDC (openshift-oidc, openshift-oidc-mcpserver overlays)

Authentication & Authorization:
- [SA]   /sse, /messages/, /mcp: NO authentication. Every caller acts as the
         rhoai-mcp SA with cluster-wide privileges. Main architectural risk.
- [OIDC] token-review: opaque OCP token → TokenReview; groups from users API.
- [OIDC] jwt: JWKS-verified JWT (RS256/ES256, exp/iss/aud required); must use
         impersonation strategy (user-token + jwt rejected at startup).
- [OIDC] Downstream K8s calls use the user's effective RBAC.
- /health, /.well-known/oauth-protected-resource: public.

Service Mesh Configuration:
- None. No Istio sidecar, PeerAuthentication, or AuthorizationPolicy.
- No NetworkPolicy protecting the rhoai-mcp pod in the repo.

Secrets / Trust material:
- ServiceAccount token (projected, kubernetes.io/service-account-token) -
  in-cluster K8s auth; Bearer for Model Registry 8443 and Model Catalog;
  auto-rotated by Kubernetes.
- rhoai-mcp-service-ca (ConfigMap, injected CA bundle) - trust anchor for
  service-serving certs; OpenShift service-ca operator; auto-rotated.
- User data-connection Secrets (Opaque, in user namespaces) - S3 credentials
  created by the connections tools on agent request; no rotation.
- Workflow HMAC key (RHOAI_MCP_WORKFLOW_HMAC_SECRET) - random per process by
  default; HMAC-SHA256 tokens not bound to user identity.

Known Security Gaps:
- Unauthenticated MCP endpoint in SA mode exposed via external Route.
- TLS verification disabled for in-cluster Model Registry (*.svc) calls;
  plain HTTP on 8080 preferred over kube-rbac-proxy 8443.
- Plaintext router → pod hop (edge termination); no server-side TLS.
- Single replica; no PDB/HPA; no per-user rate limiting.
