Not shipped / not launched in RHOAI (present in source only):
- Actions server            8001/TCP HTTP, no auth
- AlignScore server         5000/TCP HTTP, no auth (not built)
- Jailbreak detection       1337/TCP HTTP, no auth (removed by profile)
- Chainlit chat UI (/chat)  disabled by entrypoint
- benchmark/mock_llm_server test utility

RBAC Summary:
- ClusterRoles: none
- RoleBindings: none
- The server does not call the Kubernetes API.
  (Operator-side RBAC for creating the Deployment is out of scope.)

Authentication & Authorization:
- All server endpoints : NONE in application; enforcement must come from
                         operator-provided Route / auth proxy / NetworkPolicy
- Outbound LLM calls   : Bearer from static env key, else X-Authorization
                         mapped to Authorization (header_forwarding.py)
- /v1/models outbound  : Bearer from env key, else INBOUND Authorization
                         (server/schemas/utils.py:fetch_models)
- API scoping          : config_id regex + commonprefix path-traversal
                         guard only; not access control

Service Mesh Configuration:
- None defined in this repository.

Secrets (environment variables, provisioned by operator/user, no rotation):
- OPENAI_API_KEY / provider api_key_env_var - static LLM credentials
- AZURE_OPENAI_API_KEY                      - Azure OpenAI LLM/embeddings
- F5_GUARDRAILS_API_KEY, POLYGRAF_API_KEY   - retained third-party rail SaaS
- X-Authorization request header            - per-request LLM token (client)
- Dead in image (modules removed by GUARDRAILS_PROFILE=opensource):
  ACTIVEFENCE_API_KEY, AI_DEFENSE_API_KEY, AUTOALIGN_API_KEY,
  CLAVATA_API_KEY, CLEANLAB_API_KEY, CS_AIDR_TOKEN, FIDDLER_API_KEY,
  PANGEA_API_TOKEN, PATRONUS_API_KEY, POLICYAI_API_KEY, PAI_API_KEY

Crypto / FIPS:
- No server TLS (uvicorn plain HTTP on 0.0.0.0)
- Outbound TLS via httpx/aiohttp/requests defaults; system/certifi trust
- Crypto libs: stdlib ssl/hashlib (system OpenSSL, RHEL 9.8 base),
  cryptography 46.0.7 (transitive)
- embeddings/cache.py MD5KeyGenerator uses hashlib.md5 without
  usedforsecurity=False -> fails under FIPS mode if selected
- utils.py MD5 falls back to SHA-256 when MD5 unavailable (FIPS-tolerant)
- Base-image uv (bundled Rust crypto) removed (RHOAIENG-97373)

Key Risks for SAR:
1. No in-app authN/authZ or TLS; any caller reaching port 8000 can use any
   config_id and the instance's static LLM credentials.
2. /v1/models forwards the inbound Authorization header (possibly a user
   OpenShift token passed through an auth proxy) to the upstream provider
   when no env API key is set.
3. Rails config is executable code (config.py exec'd at startup in
   multi-config mode; actions.py loaded) - write access to the mounted
   ConfigMap/volume = code execution in the pod.
4. CORS, when enabled, defaults to origins "*" with allow_credentials=True.
5. hf_classifier allows verify_ssl=False.
6. Process-global rails cache shared across all callers of an instance;
   no NetworkPolicy defined in repo; binds 0.0.0.0.
