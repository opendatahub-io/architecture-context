credentials and no Kubernetes API access. All network activity happens in the
offline generation tooling before the image is built.

Services / Ingress / Routes:
- None defined. No HTTP or gRPC endpoints.

RBAC Summary:
- No ClusterRoles, Roles, RoleBindings or ServiceAccounts in this repo.
- Pod identity and RBAC are owned by the consuming operator
  (rhods-operator / model-registry-operator).

Authentication & Authorization:
- N/A (no inbound endpoints). Catalog data access is controlled by whichever
  pod mounts the image or volume.

Service Mesh Configuration:
- None (no network surface).

Secrets (build-time only; none in the shipped image):
- HF_TOKEN (env, .env gitignored) - HuggingFace API auth - developer/CI - no rotation
- GITHUB_TOKEN (env) - GitHub API auth for agent enrichment - developer/CI - no rotation
- QUAY_USERNAME / QUAY_PASSWORD (GitHub Actions secret) - push upstream image
  to quay.io/opendatahub - manual - no rotation
- {{ git_auth_secret }} (Tekton workspace secret) - Konflux git clone -
  managed by Konflux / Pipelines-as-Code

Crypto / FIPS:
- Shipped image: no binaries, no crypto code; OpenSSL inherited from PQC base.
- Tooling: Go stdlib crypto/sha256 (digests, name truncation); TLS via
  stdlib / containers/image. No non-FIPS crypto risks detected.

Supply-chain controls:
- Base image digest-pinned (Konflux). Upstream Dockerfile uses floating
  ubi9-micro:latest.
- Every serving-runtime image digest-pinned (tag@sha256).
- Serving-runtime images must come from registry.redhat.io/rhoai/, rhaii/,
  rhaii-early-access/ or rhaii-fast/ (validator allowlist).
- Regex rejects secret-like parameter names in generated runtimes.
- Agent fetches pinned to resolved commit SHA.
- Trust ultimately rests on git review of data/*.yaml and integrity of
  HuggingFace, GitHub and registry inputs.

Security observations:
- 3.7-ea.1 data image carries 3.6-ea.1 runtime templates
  (generator config pins rhods-operator 3.6.0-ea.1 controller images).
- sleep infinity means the container never exits; using it as an init
  container requires a command override.
- Metadata extraction resolves only linux/amd64 manifests (output is
  architecture-neutral).
