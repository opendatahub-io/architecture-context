Route, Ingress, NetworkPolicy, RBAC or Secret objects. The OGX operator creates
the Deployment, Service, Route and Secrets. Edge/ingress values below are

Build-time network (Konflux, hermetic):
- Hermeto prefetch -> packages.redhat.com RHEL AI PyPI (cpu-torch2.13-el9.8)
    443/TCP HTTPS TLS, auth: rhel-ai-private-index-auth
- Buildah pre-pull -> quay.io/aipcc/base-images/cpu-torch2.13-el9.8:latest
    (tag-based, NOT digest-pinned) and
    registry.redhat.io/rhai/modelcar-redhatai-ogx-distribution:3.0
    443/TCP HTTPS TLS, auth: pull secret
- Hermetic build (--no-index) -> push quay.io/rhoai/odh-ogx-core-rhel9
    443/TCP HTTPS TLS, auth: SA build-pipeline-odh-ogx-core-v3-7-ea-1
- Platforms: x86_64, aarch64, ppc64le, s390x

RBAC Summary:
- ClusterRoles / Roles / Bindings: NONE defined in this repo.
- The OGX server does not call the Kubernetes API.
- ServiceAccount for the pod is created by the OGX operator.

Application Authorization (distribution/config.yaml:256-280):
- server.auth.provider_config.type = ${env.AUTH_ISSUER:+oauth2_token}
  - AUTH_ISSUER unset -> server is UNAUTHENTICATED (default)
  - AUTH_ISSUER set   -> JWT bearer validated against AUTH_JWKS_URI,
                         audience AUTH_AUDIENCE (default `ogx`)
- ABAC policy:
  - read unowned resources (models, providers): everyone
  - create: any authenticated user
  - read / update / delete: resource owner only
- /metrics: no auth, open to anything that can reach the port
- Praxis (test evidence): x-tenant-id / x-user-id headers; cross-user and
  cross-tenant reads/deletes return 403/404 for files and vector stores

Service Mesh / Network Policy:
- None defined in this repo. No NetworkPolicy, PeerAuthentication or
  AuthorizationPolicy. Transport security depends on operator/platform.

Secrets (consumed as env vars or *_FILE mounted files; 18 resolved by
distribution/entrypoint.sh:35-54; read once at startup, no auto-rotation):
- POSTGRES_PASSWORD, PGVECTOR_PASSWORD           - database credentials
- VLLM_API_TOKEN, VLLM_EMBEDDING_API_TOKEN       - inference bearer tokens
- OPENAI_API_KEY, ANTHROPIC_API_KEY, AZURE_API_KEY, WATSONX_API_KEY,
  GEMINI_API_KEY, GEMINI_ACCESS_TOKEN, AWS_BEDROCK_BEARER_TOKEN
                                                 - third-party LLM credentials
- AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY       - S3 file storage
- MILVUS_TOKEN, QDRANT_API_KEY                   - vector store credentials
- BRAVE_SEARCH_API_KEY, TAVILY_SEARCH_API_KEY    - web search tools
- DOCLING_SERVE_API_KEY                          - docling-serve (dependency-only)
- rhel-ai-private-index-auth (Konflux build secret) - private index auth
Note: _FILE values are exported into the exec'd ogx process environment; the
mechanism keeps secrets out of the Pod spec, not out of process memory.
Setting both VAR and VAR_FILE is rejected at startup.

Crypto / FIPS:
- No server TLS (--insecure). Client TLS uses library defaults
  (httpx/openai/boto3) with tls_verify toggles for vLLM and JWKS.
- cryptography 50.0.2 (OpenSSL-backed), pyjwt 2.15.1, Python ssl stdlib.
- OpenSSL inherited from AIPCC RHEL 9.8 base; no explicit FIPS opt-in.

Key Risks:
1. Plain HTTP on 8321 and unauthenticated by default; security depends
   entirely on operator/platform deployment.
2. /metrics unauthenticated.
3. tls_verify for vLLM and JWKS can be disabled via env vars.
4. VLLM_API_TOKEN defaults to the literal `fake`.
5. PostgreSQL TLS not configured (driver default).
6. Base image tag-based (not digest-pinned); no RPM lockfile;
   public-repos.sh runs as root during build.
7. All users of an instance share upstream provider credentials and
   PostgreSQL tables (isolation by application filtering only).
