Services:
- payload-processor (Helm)  ClusterIP  9004/TCP → 9004  gRPC/HTTP2  TLS self-signed  no auth
- payload-processor (e2e)   NodePort   9004/TCP         gRPC        none (--secure-serving=false)
- payload-processor (e2e)   NodePort   9090/TCP (nodePort 30090)  HTTP  none (--metrics-endpoint-auth=false)
- envoy (e2e)               NodePort   8081/TCP  HTTP  test only
- vllm-* simulators (e2e)   ClusterIP  8000/TCP  HTTP  test only

RBAC Summary:
- Role <name>-<release>-configmap-reader (default, namespaced)
  - API Groups: ""   Resources: configmaps   Verbs: get, list, watch
  - Bound via RoleBinding <name>-<release> → SA <name>-<release>
- ClusterRole payload-processor-configmap-reader (multiNamespace: true)
  - API Groups: ""   Resources: configmaps (cluster-wide)   Verbs: get, list, watch
  - Bound via ClusterRoleBinding payload-processor-configmap-reader → SA <name>-<release>
- ClusterRole payload-processor-auth-reviewer (e2e deploy/)
  - API Groups: ""   Resources: configmaps   Verbs: get, list, watch
  - Bound via payload-processor-auth-reviewer-binding → SA payload-processor
- GAP: no role grants create on tokenreviews / subjectaccessreviews, which the
  default --metrics-endpoint-auth=true filter requires → scrapes likely rejected.

Service Mesh Configuration (Istio provider):
- EnvoyFilter payload-processor: ext_proc HTTP filter on target Gateway,
  failure_mode_allow: false, FULL_DUPLEX_STREAMED
- DestinationRule: TLS mode SIMPLE, insecureSkipVerify: true
- No PeerAuthentication / AuthorizationPolicy / NetworkPolicy shipped

Secrets:
- None. ext_proc TLS key/cert generated in memory at startup (RSA-4096,
  10-year validity), not persisted, regenerated on each pod restart.
- CertReloader for mounted tls.crt/tls.key exists but is unused, so
  cert-manager / service-ca certificates cannot be plugged in.

Trust / Tenancy Notes:
- Adapter→base-model mappings come from ConfigMaps labelled
  inference.llm-d.ai/ipp-managed=true; filter is application-side, so anyone
  able to label a ConfigMap in a watched namespace can influence routing.
- multiNamespace: true caches all ConfigMaps cluster-wide.

FIPS:
- Static binary, CGO_ENABLED=0, no strictfipsruntime, no OpenSSL in image
  → fails check-payload; downstream build must provide FIPS packaging.
