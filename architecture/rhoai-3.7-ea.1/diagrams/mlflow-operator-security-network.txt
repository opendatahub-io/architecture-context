Operand NetworkPolicy Egress (chart default):
- Open to ANY destination on 443, 6443, 8443, 5432, 3306, 9000, 8333, 8334/TCP

Unauthenticated Surfaces:
- Operator :8081 /healthz, /readyz (by design)

RBAC Summary:
- ClusterRole: manager-role  (SA mlflow-operator-controller-manager)
  - mlflow.opendatahub.io mlflows (+status, finalizers): full CRUD
  - components.platform.opendatahub.io mlflowoperators: get, list, watch, patch, update
  - mlflow.kubeflow.org mlflowconfigs: get, list, watch; experiments: get, list, update
  - gateway.networking.k8s.io httproutes, console.openshift.io consolelinks,
    monitoring.coreos.com servicemonitors: full CRUD
  - rbac.authorization.k8s.io clusterroles, clusterrolebindings, rolebindings:
    CRUD + bind  (ESCALATION-SENSITIVE; mitigated by resourceNames scoping)
  - core namespaces, pods, secrets: get, list, watch
  - services.platform.opendatahub.io auths: get, list, watch
- Role: manager-role (redhat-ods-applications): configmaps, PVCs, secrets, SAs,
  services, deployments, cronjobs, jobs, networkpolicies: full CRUD
- Role: leader-election-role: configmaps, leases, events
- ClusterRole: metrics-auth-role: tokenreviews, subjectaccessreviews: create
- ClusterRole: metrics-reader: nonResourceURL /metrics: get
- ClusterRole: openshift-tls-profile-reader: config.openshift.io apiservers: read
- ClusterRole: mlflow (operand, SA mlflow-sa): namespaces; secret
  mlflow-artifact-connection (every namespace); mlflowconfigs: get, list, watch
- ClusterRole: mlflow-gc (optional): namespaces, mlflowconfigs, experiments
- Aggregate: mlflow-view / mlflow-edit / mlflow-integration on mlflow.kubeflow.org
  virtual resources (experiments, registeredmodels, datasets, gateway*, mcpservers, skills)
- RoleBindings odh-group-mlflow-view / -edit in each namespace labeled
  opendatahub.io/global-mlflow-workspace → Auth CR allowedGroups / adminGroups

Admission Control:
- CEL XValidation on MLflow CRD: name must be "mlflow"; blocks SQLite + split
  serving, multi-replica on RWO, MLFLOW_SERVER_DISABLE_SECURITY_MIDDLEWARE,
  MLFLOW_SERVER_ENABLE_JOB_EXECUTION; storage access modes immutable
- ValidatingAdmissionPolicy (Warn, failurePolicy Ignore): trace rollup schedule
- No admission webhooks

Service Mesh Configuration:
- None (no Istio sidecars / PeerAuthentication); TLS is per-hop service-ca

Secrets:
- mlflow-operator-controller-manager-metrics-tls (kubernetes.io/tls) - service-ca, auto-rotate
- mlflow-tls (kubernetes.io/tls) - tracking server TLS, service-ca, auto-rotate
- mlflow-artifacts-tls (kubernetes.io/tls) - artifact server TLS, service-ca, auto-rotate
- backend/registry/read-replica store URI Secrets (Opaque) - user provided, no rotation
- mlflow-artifact-connection per namespace (Opaque) - user provided, no rotation

FIPS:
- Operator: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime, ubi9 minimal-pqc base (OpenSSL)
- Operand is the upstream Python MLflow image (outside this repo's FIPS scope)

Multi-Tenancy Risks:
- Single shared instance; tenant isolation enforced only in the MLflow runtime (SSAR)
- Shared metadata DB and default artifact store; no per-tenant network segmentation
- mlflow-sa can read mlflow-artifact-connection Secret in every namespace
