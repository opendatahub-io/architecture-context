Egress Summary:
- BFF → OpenShell gateway 8080/TCP gRPC, TLS 1.2+ (plaintext possible), Bearer per RPC
- oauth2-proxy → OIDC issuer 443/TCP (or 8443/TCP) HTTPS, OIDC client secret
- NetworkPolicy restricts ingress only; egress is unrestricted.

RBAC Summary:
- ClusterRoles: none
- Roles / RoleBindings: none
- ServiceAccount: created by chart, automountServiceAccountToken: false
- The component makes no Kubernetes API calls.
- Application authorization is enforced entirely by the OpenShell gateway.
  UI roles (platform admin / workspace admin / user) and FEATURE_* flags only
  hide UI elements and are NOT access control.

Authentication & Authorization:
- All external traffic (4180): OIDC auth code + session cookie @ oauth2-proxy
- /api/v1/* (except auth/config, healthz, readyz): bearer presence @ BFF
- Gateway gRPC: JWT validation + roles + workspace membership @ gateway
- Terminal WebSocket: as API + Origin == http(s)://Host @ BFF
- Pod ingress: NetworkPolicy port 4180 from ingress namespace only

Service Mesh Configuration:
- None (no Istio PeerAuthentication / AuthorizationPolicy).

Secrets:
- openshell-dashboard-oidc (Opaque) - OIDC client-secret, cookie-secret (optional client-id); manual; no rotation
- openshell-client-tls (Opaque/TLS, key ca.crt) - CA for verifying the gateway; gateway chart/admin; restart to rotate
- gateway.clientCertSecretName (kubernetes.io/tls, optional) - mTLS client cert/key for the gateway; manual
- authProxy.tls.secretName (kubernetes.io/tls, optional) - HTTPS on oauth2-proxy (Route reencrypt); manual / service-ca
- keycloak-tls, keycloak-admin (dev only) - dev Keycloak cert and bootstrap admin

FIPS / Crypto:
- Build: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime, dynamic linking, UBI9 OpenSSL
- Inbound TLS 1.3 min; outbound raw gRPC TLS 1.2 min; no InsecureSkipVerify
- No JWT library; tokens opaque to the BFF
- oauth2-proxy: upstream image, not digest-pinned by default, FIPS status unknown

Security Risks / Notes:
1. Relay-only trust: if the BFF port 8080 is reachable by anything other than
   oauth2-proxy (e.g. image run without LISTEN_ADDRESS=127.0.0.1), any client
   can inject a token header. Mitigated in chart by loopback bind, Service
   exposing only 4180, and NetworkPolicy.
2. Plaintext gateway URL (grpc:// or http://) sends user bearer tokens
   unencrypted; chart permits this when gateway.tls.enabled=false.
3. Upstream oauth2-proxy image (v7.15.2) not Red Hat-built and not digest-pinned.
4. Shared BFF capacity: no per-user rate limiting; 64 MiB uploads and
   long-lived WebSocket / log streams can consume shared resources.
5. WebSocket handshakes with no Origin header are allowed (non-browser clients).
