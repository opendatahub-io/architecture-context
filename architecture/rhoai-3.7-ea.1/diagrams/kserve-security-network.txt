TLS posture:
- Controller webhook/metrics servers: min version + ciphers from
  apiservers.config.openshift.io/cluster TLSSecurityProfile (honours TLSAdherence);
  Intermediate fallback; TLS 1.2 floor off-OpenShift; explicit flags override.
- FIPS-approved curve filtering; profile propagated to Python model servers via env.
- ProfileWatcher reconciles on APIServer changes.

==========================================================================================
 KEY RISKS
==========================================================================================

1. kserve-module SA is cluster-admin-equivalent (bind/escalate, SCC, webhook configs,
   CRD delete). If the module pod is compromised, the whole cluster is compromised.
2. All admission webhooks use failurePolicy: Fail, including pods CREATE. If the webhook
   server is down, labelled inference pods cannot be created anywhere in the cluster.
3. Model endpoints have no app-level auth. Isolation depends on Gateway/Kuadrant policy
   from odh-model-controller. In-cluster ISVC traffic is plaintext by default.
4. Controller NetworkPolicies are allow-all.
5. Opt-in InsecureSkipVerify: logger sink (pkg/logger/worker.go:120), kernel-cache
   registry (pkg/kernelcache/registry/transport.go:39), and Python SDK verify_ssl=False.
6. Privileged SCC for confidential bare-metal (SA coco-cc-storage).
7. Probes on 8081 and agent/qpext on 9081/9088 are unauthenticated HTTP.
