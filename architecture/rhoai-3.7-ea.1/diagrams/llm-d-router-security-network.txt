Service Mesh / Gateway Configuration:
- Istio DestinationRule <release>-epp: host <epp>.<ns>.svc.cluster.local:9002
  tls.mode SIMPLE, insecureSkipVerify: true  → encrypted but UNAUTHENTICATED hop
- HTTPRoute <release> → InferencePool backend, attached to shared parent Gateway
- No PeerAuthentication / AuthorizationPolicy / NetworkPolicy shipped by charts

Secrets:
- router.monitoring.prometheus.auth.secretName (kubernetes.io/service-account-token)
  - Bearer token for Prometheus scrape; Helm-provisioned; long-lived, no rotation
- Serving cert dir --cert-path (kubernetes.io/tls, mounted)
  - Provisioned externally (operator / cert-manager / service-ca)
  - EPP reloads with --enable-cert-reload; sidecar/coordinator use file watch
- Self-signed cert (in-memory) - RSA-4096, 10 years, no SANs, generated at startup, no rotation
- Redis URL credentials (coordinator config value), no rotation

TLS / Crypto:
- Go crypto/tls, MinVersion TLS 1.2 (configurable to 1.3, <1.2 rejected), insecure suites rejected
- Metrics listeners fixed at TLS 1.2 + default ciphers
- FIPS RISK: CGO_ENABLED=0 static pure-Go crypto, distroless/static base, no strictfipsruntime,
  no .konflux Dockerfiles on this branch → would fail check-payload; downstream must override

Key Security Findings:
1. Gateway → EPP ext-proc: TLS with skip-verify; no client auth unless --client-ca-file set
2. pd-sidecar :8000 and coordinator :8080 have no authentication
3. pd-sidecar SSRF allowlist off by default; prefill/encode targets come from request headers
4. Coordinator → gateway defaults to plaintext HTTP :80; Redis plaintext by default
5. Metrics scrape, ZMQ KV events and KV transfer between model pods are unencrypted
6. pprof enabled by default on the EPP metrics listener (behind metrics auth)
7. No NetworkPolicy shipped: ext-proc and sidecar ports reachable cluster-wide
