PostgreSQL Client TLS (pkg/postgres/client_tls.go):
- require + CA supplied   -> upgraded to verify-ca
- verify-ca               -> InsecureSkipVerify=true + custom VerifyPeerCertificate
                             (chain checked against CA, hostname NOT checked; libpq semantics)
- verify-full             -> hostname validated (used for Internal when TLS enabled)
- require without CA      -> encryption without server verification (pgx default)
- No MinVersion / CipherSuites set (Go/pgx defaults)

Authorization model for claims:
- Kubernetes RBAC on DatabaseClaim/SchemaClaim is the ONLY gate. Any principal that can
  create a claim in a namespace can obtain credentials from any matching cluster-scoped
  DatabaseProvider (selected by name or label; highest selection-priority, ties by name).

Service Mesh Configuration:
- None. No PeerAuthentication / AuthorizationPolicy. Isolation via NetworkPolicy + TLS.

Secrets:
- metrics-server-cert (kubernetes.io/tls) - metrics HTTPS cert, OpenShift service-ca,
  auto-rotated (certwatcher reload); self-signed fallback if absent
- webhook-server-cert (kubernetes.io/tls) - webhook cert, cert-manager self-signed Issuer, auto-rotated
- Internal admin Secret (Opaque, per provider) - postgres superuser password + dbname,
  generated by operator (crypto/rand), not rotated; retained on provider removal
- Internal TLS Secret (kubernetes.io/tls, per provider) - PostgreSQL server cert,
  cert-manager, auto-rotated (renewBefore)
- External admin Secret (Opaque, connectionSecretRef, any namespace) - administrator-provided, manual rotation
- Claim connection Secret (Opaque, claim namespace, annotation
  opendatahub.io/connection-type-protocol: postgres) - host, port, user, password, dbname,
  sslmode[, schema, ca.crt]; new password only when repairing lost credentials

Secret-cache hardening (RHOAIENG-96275):
- Informer label-scoped to operator-managed Secrets; all Secret reads bypass the cache.
  RBAC remains cluster-wide Secret CRUD.

Credential hygiene:
- Passwords from crypto/rand, wrapped in secret.SecretString; redacting pgx trace logger;
  SQL identifiers and literals quoted before DDL. No rotation workflow.

FIPS / Build:
- Konflux: CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime -tags strictfipsruntime,
  dynamic link, ubi9/ubi-minimal-pqc (OpenSSL), digest-pinned bases, hermetic gomod prefetch,
  x86_64 + arm64. No non-FIPS crypto detected (SHA-256 only for name suffixes).
- Dev Containerfile (CGO_ENABLED=0, ubi10/ubi-micro:latest) is NOT FIPS - local use only.

Observations / Risks:
- Webhook Service, port 9443 and NetworkPolicy rule exist with no registered handlers.
- No per-provider authorization; no per-tenant quotas or connection limits on shared PostgreSQL.
- Internal provider is single-replica, no backup/restore.
- Shared default-database DatabaseClaims share one database; isolation relies on operator-issued grants.
