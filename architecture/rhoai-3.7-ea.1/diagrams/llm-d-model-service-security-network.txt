RBAC Summary:
- ClusterRole: modelservice-manager-role (→ SA modelservice-system/modelservice-controller-manager)
  - "" configmaps, serviceaccounts: create, delete, get, list, patch, update, watch
  - "" services: create, delete, list, patch, update, watch (no get)
  - apps deployments: create, delete, get, list, patch, update, watch
  - apps deployments/scale: patch, update
  - gateway.networking.k8s.io httproutes: create, delete, get, list, patch, update, watch
  - inference.networking.x-k8s.io inferencemodels, inferencepools: full CRUD + watch
  - llm-d.ai modelservices: full CRUD + watch; /finalizers: update; /status: get, patch, update
  - rbac.authorization.k8s.io rolebindings: create, delete, get, list, patch, update, watch
- ClusterRoleBinding: modelservice-manager-epp-rolebinding → $EPP_CLUSTER_ROLE (cluster-wide)
  - Required so the controller can bind EPP SAs to that ClusterRole (escalation rule)
- ClusterRole: modelservice-metrics-auth-role — tokenreviews: create; subjectaccessreviews: create
- ClusterRole: modelservice-metrics-reader — nonResourceURL /metrics: get
- Role: modelservice-leader-election-role (modelservice-system) — configmaps/leases CRUD; events create, patch
- Aggregate roles: modelservice-admin (*), -editor (CRUD), -viewer (get, list, watch) on modelservices
- Dynamic RoleBinding: <msvc>-epp-rolebinding (tenant ns) → ClusterRole $EPP_CLUSTER_ROLE → <msvc>-epp-sa
- Effective controller permissions: manager-role ∪ $EPP_CLUSTER_ROLE, cluster-wide

Service Mesh / Network Policy:
- No service mesh configuration (no PeerAuthentication / AuthorizationPolicy).
- Optional NetworkPolicy config/network-policy: allows 8443 only from namespaces labelled
  metrics: enabled — NOT enabled by default.
- No NetworkPolicies created for tenant EPP / model-server Services (open in-cluster).

Admission Control:
- None. webhook.NewServer constructed (cmd/run.go:139) but no handlers registered.

Secrets:
- spec.modelArtifacts.authSecretName (Opaque, key HF_TOKEN) — user-provisioned; injected via
  secretKeyRef into model containers for hf:// URIs; controller never reads it; no rotation
- --pd-pull-secrets / --epp-pull-secrets (kubernetes.io/dockerconfigjson) — platform admin;
  attached to generated PD/EPP ServiceAccounts; no rotation
- metrics-server-cert (kubernetes.io/tls, optional) — cert-manager (commented out);
  certwatcher hot-reload when provided

Security Findings:
- [HIGH] Cross-namespace BaseConfig READ: spec.baseConfigMapRef.namespace honoured
  (child_resources.go:234-242); any ModelService creator can project another namespace's
  ConfigMap into their own via controller's cluster-wide configmaps get.
- [HIGH] Cross-namespace ConfigMap WRITE: BaseConfig configMaps[].namespace honoured; owner-ref
  error only logged (child_resources.go:372-381), CreateOrUpdate still runs cluster-wide.
- [MEDIUM] Controller SA highly privileged cluster-wide (RoleBindings, Deployments, ConfigMaps,
  plus $EPP_CLUSTER_ROLE); compromise affects all tenants.
- [MEDIUM] Tenant data path (Gateway→EPP 9002, Gateway→decode 8000, decode→prefill 8000/5557)
  plaintext and unauthenticated in samples.
- [MEDIUM] FIPS: CGO_ENABLED=0 static build fails check-payload; non-RH builder image
  (quay.io/projectquay/golang:1.24); runtime base ubi9/ubi:latest unpinned; no hermetic build.
- [LOW] Probes :8081 unauthenticated (by design); metrics TLS self-signed by default.
- [INFO] Cluster-wide informer cache of Deployments/Services/ConfigMaps/RoleBindings/SAs.
- [INFO] deploy/ scaffold (pods/exec granted to system:authenticated) is unrelated and unused.
