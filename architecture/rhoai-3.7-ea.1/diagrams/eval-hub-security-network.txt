Service Mesh Configuration:
- None. No PeerAuthentication or AuthorizationPolicy. Transport security is
  kube-rbac-proxy TLS plus optional native TLS on the API and MCP listeners.

Secrets:
- Per-job model reference Secret (Opaque) - rewritten creds, created by eval-hub,
  owned by Job, job lifetime, no rotation
- User model credential Secret (Opaque) - user-provided, referenced by job request
- S3 / test-data Secret (Opaque) - AWS keys for init container, user-provided
- DB password (mounted file via secrets.mappings) - operator/user, no rotation
- MLflow / eval-hub token files (projected SA token) - Kubernetes, auto-rotated
- API serving cert (kubernetes.io/tls, optional) - TLS_CERT_FILE/TLS_KEY_FILE,
  operator / service-ca, auto-rotated if service-ca

Crypto / FIPS:
- Build: CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime, dynamic OpenSSL
- Runtime base: ubi9/ubi-minimal-pqc (digest-pinned)
- TLS: min 1.2 (1.3 via TLS_MIN_VERSION), configurable ciphers/curves incl.
  PQC hybrids X25519MLKEM768, SecP256r1MLKEM768, SecP384r1MLKEM1024
- Risks: optional InsecureSkipVerify in sidecar (default false), OTLP
  exporter_insecure plaintext, X25519 selectable (not FIPS-approved)

Multi-Tenancy:
- Tenant = namespace (X-Tenant). Scopes all SQL queries and the Job namespace.
- Shared SQL DB, tenant-column filtering (application-enforced).
- Tenant-membership authorization is NOT checked by eval-hub; it relies on
  kube-rbac-proxy SAR config and operator RoleBindings.

Security Observations:
1. API security rests on kube-rbac-proxy being the only path to 127.0.0.1:8080
   and on the proxy stripping client-supplied X-Tenant / X-User headers.
2. --local mode disables identity header checks entirely.
3. Metrics listener (0.0.0.0:8081) is unauthenticated plaintext.
4. evalhub-mcp defaults to auth_type: none when run in HTTP mode.
5. Job pod egress is unrestricted (documented in docs/network-policies.md).
6. One image serves four roles, so a CVE in any binary's dependencies affects
   job pods as well as the API server.
