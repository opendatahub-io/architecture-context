RBAC Summary:
- ClusterRole: dc-controller-manager-role  (bound to dc-controller-manager)
  - "" configmaps, secrets, serviceaccounts, services: full CRUD + watch
  - apps deployments: full CRUD + watch
  - rbac.authorization.k8s.io clusterroles, clusterrolebindings: full CRUD
    (privilege-escalation-capable)
  - dataconnecthub.opendatahub.io dataconnectservices, data-connections,
    data-connection-types, data-store, flight-services: full CRUD
  - gateway.networking.k8s.io httproutes: CRUD; gateways: read
  - networking.k8s.io networkpolicies, monitoring.coreos.com servicemonitors: CRUD
  - config.openshift.io apiservers, ingresses; operator.openshift.io
    ingresscontrollers: read; route.openshift.io routes: get
  - authentication tokenreviews / authorization subjectaccessreviews: create
- ClusterRole: dc-controller-metrics-auth-role - tokenreviews, SARs: create
- ClusterRole: dc-controller-metrics-reader - nonResourceURL /metrics: get
- Role: dc-controller-leader-election-role (dc-controller-system)
- CRB dch-flight-auth-delegator → system:auth-delegator → dch-flight-service-sa
- CRB dch-kube-rbac-proxy-auth-review → tokenreviews/SAR create → dch-rest-service-sa
- CRB dch-rest-service-data-access → data-store get (cluster-wide) → dch-rest-service-sa
- RoleBinding (manual, per tenant ns) dch-rest-service-secret-access →
  secrets get/create/patch/delete → dch-rest-service-sa
- Role/RoleBinding (manual, per tenant ns, per resourceName) secrets get
  → dch-flight-service-sa
- User ClusterRoles (bound per tenant ns):
  - dch-read: data-connections, data-connection-types, data-store: get,list,watch
  - dch-read-write / dch-admin: same resources, full CRUD (admin == read-write)
  - dch-secret-export: core secrets create

Service Mesh Configuration:
- None. No Istio sidecars / PeerAuthentication. Transport security is
  per-hop TLS using OpenShift service-CA certificates; the only plaintext
  in-cluster hop is kube-rbac-proxy → rest-service over pod loopback.
- TLS profile: controller reads OpenShift APIServer TLS security profile
  and projects it into kube-rbac-proxy args and the Flight ConfigMap.
  Go side may admit non-RC4 "insecure" suites (e.g. 3DES/CBC) if listed.

Secrets:
- dch-database-config (Opaque, key secret-config.toml, optional CA) -
  PostgreSQL URL/credentials; admin-provisioned; no rotation
- rest-service-tls (kubernetes.io/tls) - kube-rbac-proxy serving cert,
  OpenShift service-CA, auto-rotated
- flight-service-tls (kubernetes.io/tls) - Flight serving cert,
  service-CA, auto-rotated
- flight-service-ca (ConfigMap) - CA bundle for REST → Flight trust,
  service-CA inject-cabundle
- Controller metrics cert (kubernetes.io/tls, OpenShift overlay) - service-CA
- Tenant connection Secrets (Opaque) - data-source credentials referenced by
  secret_ref; created by REST for inline creds or left in place on migration
- Exported Secrets (Opaque) - PUT /connections/{id}/exports/secrets/{name}
- Projected ServiceAccount tokens - REST → Flight, controller → REST bearer

Unauthenticated surfaces:
- REST /health (8443), Flight grpc.health.v1.Health (8443)
- REST and Flight /metrics on 9090/TCP plaintext, reachable from any pod
- Controller /healthz, /readyz on 8081/TCP

FIPS notes:
- Rust services use aws-lc-rs WITHOUT the fips feature (not a validated
  module); ring also present in the dependency graph
- Controller built with CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime
