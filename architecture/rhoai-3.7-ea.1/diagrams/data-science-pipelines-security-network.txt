Admission Webhooks (API server, --pipelinesStoreKubernetes):
- /webhooks/validate-pipelineversion  Validating  PipelineVersion CREATE/UPDATE
  - Parses PipelineSpec, validates name, spec immutable except displayName/tags
- /webhooks/mutate-pipelineversion    Mutating    PipelineVersion CREATE/UPDATE
  - Sets pipeline-id / pipeline labels, owner reference to parent Pipeline
- failurePolicy: Fail on both

Service Mesh / Network Policy:
- No Istio mTLS enforced by this repo (upstream Istio option: mysql AuthorizationPolicy, MLMD VirtualService)
- No NetworkPolicy in base manifests (seaweedfs only); DSPO adds policies in RHOAI

Secrets:
- mysql-secret (Opaque) - DB credentials; manifest / DSPO; no rotation
- mlpipeline-minio-artifact (Opaque) - object store keys for API server and EVERY task pod; no rotation
- kfp-api-webhook-cert (kubernetes.io/tls) - webhook TLS; cert-manager; auto-rotated
- kfp-mlflow-credentials (Opaque) - MLflow token/user/password injected into task pods; user/platform
- webhook-server-tls (kubernetes.io/tls) - upstream cache-server only; self-signed; no rotation

Crypto / FIPS:
- All 5 Konflux images: GOFIPS140=v1.0.0, -tags no_openssl (Go native FIPS 140-3 module)
- api-server: CGO_ENABLED=1 dynamic; driver, launcher, persistenceagent, scheduledworkflow: static
- Risk: static binaries conflict with classic check-payload rules (exception not recorded in repo)
- TLS: Go defaults, no MinVersion / CipherSuites; TLS off unless cert paths provided

Key Risks:
1. Authorization fully skipped when MULTIUSER=false; relies on DSPO auth proxy + NetworkPolicy.
2. Trusted-header authenticator requires the proxy to strip spoofed headers.
3. MLMD gRPC 8080 has no authentication.
4. Every task pod holds object-store credentials and a broad pipeline-runner Role.
5. Webhook falls back to plain HTTP when no certificate is mounted.
6. MLflow insecureSkipVerify is configurable and propagated to driver/launcher.
