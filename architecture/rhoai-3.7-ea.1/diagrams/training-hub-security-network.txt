TRAINING-HUB - SECURITY NETWORK DIAGRAM (RHOAI 3.7-ea.1, training-hub v0.11.2)
Source: architecture/rhoai-3.7-ea.1/training-hub.md

NOTE: training-hub is an in-process Python library + CLI (`thub`). It has NO
Kubernetes Services, Ingress, CRDs, ServiceAccounts or RBAC of its own, and it
never calls the Kubernetes API. All identity, RBAC and network policy come from
the hosting pod (Kubeflow Trainer v2 TrainJob, KFTO PyTorchJob or Workbench)
running a distributed-workloads `odh-th-torch-{cpu,cuda,rocm}-py312-rhel9` image.

TLS posture:
- training-hub configures no TLS itself. Min/max version, ciphers and CA
  validation are the defaults of requests, aiohttp and botocore (system or
  certifi trust store). No custom CA handling.

RBAC Summary:
- ClusterRoles: none
- Roles / RoleBindings: none
- ServiceAccount: none (uses hosting pod's ServiceAccount; never calls K8s API)

Service Mesh Configuration:
- None. No PeerAuthentication / AuthorizationPolicy. Inter-rank c10d/NCCL
  traffic is plaintext; protection relies on NetworkPolicy (if any) set by
  the platform.

Secrets (all consumed as pod environment variables; none auto-rotated):
- OPENAI_API_KEY - LiteLLM-routed LLM endpoints (GEPA, GRPO); "dummy" for
  local endpoints. Provisioned by user / Secret ref in TrainJob or workbench.
- WANDB_API_KEY - Weights & Biases auth; also gates ART wandb stub.
- AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY (botocore chain) - S3 checkpoint
  mirroring. Provisioned by user / data connection Secret.
- HF_TOKEN - gated Hugging Face model/dataset downloads.
- Risk: env-var credentials are visible to every process in the pod.

Code-Execution Trust Boundaries:
- CLI callable resolution: importlib.import_module, no allowlist
  (src/training_hub/cli.py:386-433)
- Callback serialization: base64 class source, 0600 file, exec() in workers
  (src/training_hub/adapters/serialize.py:92,138)
- trust_remote_code passthrough to HF loaders, default False
  (src/training_hub/algorithms/lora.py:370,
   src/training_hub/profiling/memory_estimator.py:83)

FIPS / Supply Chain:
- No direct crypto imports; transitively Python ssl (OpenSSL) from the
  consuming image. FIPS posture inherited from distributed-workloads image.
- No lock file in repo (lower-bound deps only); reproducibility enforced by
  downstream distributed-workloads image lock files.
- litellm pinned to exclude compromised 1.82.7, 1.82.8, 1.107.0.
