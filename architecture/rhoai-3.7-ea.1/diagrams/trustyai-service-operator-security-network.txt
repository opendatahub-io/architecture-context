Monitoring (scrape paths):
- Prometheus → operator 8443/TCP HTTPS, Bearer → TokenReview + SAR (/metrics get)
- Prometheus → EvalHub 8081/TCP HTTP, no auth
- Prometheus → TAS /q/metrics via 80→8080/TCP HTTP, no auth
- Module /metrics 8080/TCP HTTP, no auth (not opened by its NetworkPolicy)

RBAC Summary:
- SA trustyai-service-operator-controller-manager (cluster-wide, union of):
  - tas-manager-role:
    - trustyai.opendatahub.io trustyaiservices (+status, finalizers): full CRUD
    - core services, pods, configmaps, secrets, PVCs, serviceaccounts: full CRUD
    - apps deployments: CRUD; serving.kserve.io inferenceservices: get/list/watch/update/patch
    - rbac clusterrolebindings, roles, rolebindings: get/list/watch/create/update/delete
    - networking.istio.io destinationrules, virtualservices: full CRUD
    - routes CRUD; servicemonitors list/watch/create; networkpolicies get/list/watch/create/update
  - lmes-manager-role:
    - lmevaljobs: full CRUD; pods, configmaps, PVCs: CRUD; pods/exec: create, get
    - secrets, persistentvolumes: get/list/watch; networkpolicies: full CRUD
  - evalhub-manager-role:
    - evalhubs (+status, finalizers, proxy), evaluations, collections, providers,
      status-events: full CRUD
    - services, configmaps, serviceaccounts: CRUD; namespaces, pods, pods/log, events: read
    - roles, rolebindings, clusterrolebindings: CRUD
    - clusterroles bind (resourceNames: evalhub-model-secret, -auth-reviewer-role,
      -jobs-writer, -job-config, -hardware-profiles-reader, -mlflow-access,
      -mlflow-jobs-access, -providers-access, -collections-access)
    - batch jobs, kueue workloads: get/list/watch/patch
    - mlflow experiments: get/list/create; hardwareprofiles: get/list
  - nemo-guardrails-manager-role:
    - nemoguardrails: full CRUD; configmaps, services, secrets, serviceaccounts: full CRUD
    - deployments, routes, clusterrolebindings: full CRUD
  - tls-profile-reader: config.openshift.io apiservers get/list/watch
  - proxy-role / metrics-auth / system:auth-delegator: tokenreviews, subjectaccessreviews create
- SA trustyai-operator-module-controller-manager (MOST PRIVILEGED; superset of the above):
  - components.platform.opendatahub.io trustyais: full CRUD
  - apiextensions customresourcedefinitions: full CRUD
  - admissionregistration mutating/validating webhookconfigurations: full CRUD
  - rbac clusterroles, clusterrolebindings, roles, rolebindings: full CRUD + clusterroles bind
  - core configmaps, secrets, pods, services, SAs, PVCs: full CRUD; pods/exec; pods/log
  - read: apiservers, gateways, mcpgatewayextensions, prometheuses
- Operator-created per-instance bindings:
  - {name}-{ns}-proxy-rolebinding (TAS, CRB) → proxy-role → SA {name}-proxy
  - {name}-{ns}-auth-reviewer-crb (EvalHub, CRB) → evalhub-auth-reviewer-role → SA {name}-service
  - Tenant RoleBindings (EvalHub): jobs-writer, job-config, mlflow-*, providers/collections-access
  - NeMo auth-delegator CRB → system:auth-delegator → per-instance SA
  - evalhub-tenant-admin-binding (single-tenant mode)

Service Mesh Configuration:
- No PeerAuthentication / AuthorizationPolicy created.
- TAS (KServe RawDeployment + Istio present): DestinationRule TLS mode SIMPLE on 443;
  VirtualService rewrites port 80 → 443 for {tas}.{ns}.svc.cluster.local.

Network Policies (operator-generated):
- Operator manager: ingress 8443 (monitoring namespaces), 8081, 9443; egress allow-all.
- Module: ingress 8081 only.
- TAS / LMES / EvalHub operands: per-workload ingress peers
  (EvalHub: Route/router, Dashboard BFF, operator pod, Prometheus).

Secrets:
- trustyai-service-operator-metrics-tls (kubernetes.io/tls) - operator metrics cert, service-ca, auto-rotate
- webhook-server-cert (kubernetes.io/tls) - conversion webhook cert, service-ca, auto-rotate
- {tas}-tls, {tas}-internal (kubernetes.io/tls) - TAS proxy certs, service-ca, auto-rotate
- EvalHub / NeMo serving certs (kubernetes.io/tls) - service-ca, auto-rotate
- {tas}-db-credentials (Opaque) - DB kind/user/password/host/port/name, user-provided
- {tas}-db-ca - DB CA cert, user / controller
- EvalHub DB secret (Opaque, key db-url) - PostgreSQL DSN at /etc/evalhub/secrets, user-provided
- MLflow projected SA token - 3600s expiry, kubelet-rotated
- LMES model / HF tokens (Opaque) - user-provided, referenced via pod env

TLS / FIPS:
- All three Konflux images: CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime, ubi-minimal-pqc runtime.
- Curve preference default X25519MLKEM768 (PQC hybrid); plain X25519 dropped in FIPS mode.
- Exceptions to cluster TLS profile: NeMo kube-rbac-proxy (hardcoded TLS 1.2),
  EvalHub failure-reporter client (MinVersion TLS 1.2), module metrics (plain HTTP).

Security Observations:
1. Operator SA is cluster-wide: secrets CRUD, pods/exec, ClusterRoleBinding create/update.
2. Module SA can create CRDs, webhook configurations, ClusterRoles and bind them.
3. NeMo without enable-auth annotation: no kube-rbac-proxy, edge Route, plaintext to 8000.
4. Plaintext/unauthenticated in-cluster ports: EvalHub 8081, TAS 80→8080, NeMo 80→8000,
   module 8080.
5. TAS payload ingestion (/consumer/kserve/v2) is authorized only by NetworkPolicy.
6. EvalHub kube-rbac-proxy auth config is a subPath mount; rule changes need pod restart.
7. Operator egress is allow-all (tracked HPSTRAT-278).
8. RHOAI overlay: lmes-allow-online=false, lmes-allow-code-execution=false (base allows both).
