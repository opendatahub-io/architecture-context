Authorization Summary (application-enforced; no Kubernetes RBAC):
- POST   /api/results                 user or admin       (submit.ts:51-79)
- POST   /api/results/:runId/review   admin only          (review.ts:60-87)
- POST   /api/results/:runId/promote  authenticated; ownership/role in handler
- DELETE /api/results/:runId          owner or admin      (delete.ts:57-97)
- GET    /api/results[/:runId], export  public states to all; pending/own need
                                        owner or admin
- ALL    /api/gcs/*                   configured buckets only; writes only to
                                      results-store prefix (server.js:564-620)
- ALL    /api/giq/*                   UNRESTRICTED pass-through; ADC fallback
- *      any route, Playground Mode   everyone admin (iam.ts:97-110)
- Unauthenticated: /api/config, /api/local/*, dashboard data, agent tooling,
  avatars, SPA static files

Kubernetes RBAC:
- Not applicable. No ClusterRoles, Roles, bindings or ServiceAccounts.
- GCP access is governed by the Cloud Run service account IAM roles
  (not defined in this repo).

Service Mesh Configuration:
- None. No Istio/PeerAuthentication/AuthorizationPolicy. Hop from the Cloud Run
  front end to the container is plain HTTP inside Google's infrastructure.

Secrets:
- GITHUB_CLIENT_SECRET (+ GITHUB_CLIENT_ID) - plain Cloud Run env var via
  deploy.sh --set-env-vars (NOT Secret Manager); no rotation
- GOOGLE_API_KEY - env var injected into the SPA (client-visible); no rotation
- GCP ADC - Cloud Run SA metadata token (auto-rotated) or JSON key file via
  GOOGLE_APPLICATION_DEFAULT_CREDENTIALS (dev; no rotation)
- GCP_WORKLOAD_IDENTITY_PROVIDER, GCP_SERVICE_ACCOUNT - GitHub Actions secrets
  for keyless CI deploy (WIF)
- User GitHub access/refresh tokens - returned in redirect URL fragment, kept in
  browser storage, sent as X-Prism-Github-Token; GitHub expiry + /refresh

Crypto / FIPS:
- No server TLS (edge only); outbound TLS uses Node defaults, bundled CA store
- Node crypto only: randomBytes(16) OAuth state, randomUUID run IDs, SHA-256
  agent artifact digests; no MD5/SHA-1/RC4
- Alpine base, no FIPS provider, no Konflux / check-payload; not FIPS-capable

Notable Risks:
1. Public by default (--allow-unauthenticated); rate limit effectively unlimited
2. GIQ proxy lets anonymous callers spend the host project's quota; logs
   response snippets
3. Playground Mode is a single env var that disables all authorization
   (default on in docker-compose)
4. OAuth state generated but not verified server-side (CSRF relies on client)
5. Tokens in URL fragment; OAuth secret in plain env vars
6. Per-request GitHub + GCS validation (3+ outbound calls), exposed to GitHub
   rate limits
7. 50 MB request bodies allowed
