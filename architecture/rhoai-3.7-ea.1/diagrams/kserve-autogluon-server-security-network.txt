RBAC Summary:
- ClusterRoles: none
- Roles / RoleBindings: none
- The runtime container needs no Kubernetes API access.
- The inherited kserve-manager-role in the tree belongs to the separate
  RHOAI kserve controller component and is not shipped by this image.

Authentication & Authorization:
- All REST endpoints on :8080 (GET, POST): no in-application auth.
  Enforcement is delegated to the platform (KServe / odh-model-controller
  auth proxy or Gateway when enabled). Unauthenticated inside the pod network.
- gRPC :8081 (all RPCs): insecure port, no auth. Not exposed by the
  ClusterServingRuntime manifest.

Service Mesh / Network Policy:
- No PeerAuthentication, AuthorizationPolicy or NetworkPolicy is defined in
  this repo for the runtime. Isolation depends on platform configuration.

Secrets:
- Storage credentials (e.g. S3 data connection) (Opaque, env injection by KServe)
  - AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AZ_CLIENT_SECRET, GIT_PASSWORD
  - Provisioned by: user / RHOAI data connections; Auto-rotate: No
  - Visible as env vars in the pod
- kserve-hdfscreds (Opaque, mounted at /var/secrets/kserve-hdfscreds)
  - HDFS credentials; Provisioned by: user; Auto-rotate: No

TLS / Crypto / FIPS:
- No server-side TLS (plaintext uvicorn; gRPC add_insecure_port).
- Outbound TLS uses library defaults (boto3 / requests / azure); certifi or
  system trust store.
- OpenSSL from the AIPCC RHEL 9.8 base image; no explicit FIPS opt-in.
- Transitive cryptography==48.0.0, pyjwt==2.13.0; no direct crypto use.

Key Security Risks:
1. Model loading unpickles predictor.pkl and model artifacts. Anyone with
   write access to the model storage location can run code in the pod.
2. Inference, metrics and repository load/unload endpoints have no auth at
   the container. Exposure relies entirely on platform controls.
3. S3_VERIFY_SSL=false turns off certificate verification for S3 downloads.
4. Storage credentials are injected as plain environment variables.
