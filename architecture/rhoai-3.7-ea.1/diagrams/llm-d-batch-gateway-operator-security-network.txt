TLS Posture:
- Cluster TLS profile read from config.openshift.io/APIServer (Intermediate fallback on
  non-OpenShift or transient error); applied to operator metrics listener; forwarded to
  operand API server as apiserver.tls.{minVersion,cipherSuites,nextProtos}
  (TLS 1.2/1.3 minimum only; unsupported ciphers dropped). ALPN h2,http/1.1.
- SecurityProfileWatcher restarts the operator on profile/adherence change.

Security Observations:
1. Cluster-wide Secret get/list/watch/create/patch; the cluster-wide Secret informer caches
   every Secret in operator memory. ReferenceGrant checking is the only guard against a CR
   author copying another namespace's Secret.
2. asyncConfig.tls.insecureSkipVerify is passed straight through, so any CR author can
   disable inference-gateway certificate verification.
3. No NetworkPolicies for operand pods; operand metrics (:9090, :9091, :8081) are plain HTTP.
4. Operand API authentication is not enforced by the operator (gateway/header trust model).
5. Cluster-wide roles/rolebindings CRUD makes the operator SA a high-value identity.
6. secretWatchFilter.remove is never called, so tracked keys only grow (minor leak).
