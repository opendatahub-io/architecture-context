RBAC Summary (all bound to the gateway ServiceAccount <release>):
- ClusterRole <release> (only when openshell.clusterRbacCreate; rules vary by workspaceMode)
  - All modes:
    - node.k8s.io runtimeclasses: get
    - scheduling.k8s.io priorityclasses: get
    - authentication.k8s.io tokenreviews: create
    - core nodes: get, list, watch
    - core namespaces: get (+ list, watch in managed/operator; + create, delete in managed)
  - managed/operator:
    - agents.x-k8s.io sandboxes, sandboxes/status: create, delete, get, list, patch, update, watch
    - core pods: create, delete, get, list, patch, watch
    - core events: get, list, watch
    - core services: create, get
    - networking.k8s.io networkpolicies: create, get (+ patch, update for managed SSH ingress)
    - core configmaps (additional CA): get, create
  - managed only:
    - core secrets: create, delete
    - core serviceaccounts: create, get
- Role <release>-sandbox (shared mode, sandbox namespace)
  - agents.x-k8s.io sandboxes, sandboxes/status: create, delete, get, list, patch, update, watch
  - pods: create, delete, get, list, patch, watch | events: get, list, watch
  - services: create, get | secrets: create, delete
  - networking.k8s.io networkpolicies: create, get
- Role <release>-peer (release namespace)
  - pods: get | services (supervisor): get | secrets (<supervisor>-token): get, patch
- Role <release>-credential-secrets (credential namespace, if K8s Secrets driver enabled)
  - secrets (ALL in namespace): get, create, patch, delete   <-- use dedicated namespace
- Role <release>-workspace-secret-source (sandbox namespace)
  - secrets (named TLS/pull Secrets): get

Risk note: workspaceMode=managed grants namespace create/delete and cluster-wide
pod/sandbox CRUD plus Secret create/delete - significantly wider blast radius.

Service Mesh Configuration:
- None. No Istio/Service Mesh integration. Transport security is native rustls TLS
  (TLS 1.2/1.3, ALPN h2/http1.1, hot-reloaded certs).
- Network isolation relies on Kubernetes NetworkPolicy (requires an enforcing CNI,
  e.g. OVN-Kubernetes):
  - networkpolicy.yaml: sandbox SSH 2222 ingress from gateway pod only
  - supervisor-networkpolicy.yaml: runtime 5500 ingress from workload pods only;
    egress unrestricted

Secrets:
- openshell-server-tls (kubernetes.io/tls) - gateway server cert; certgen hook Job or
  cert-manager (8760h, renew 720h before); hot-reloaded; auto-renew only with cert-manager
- openshell-server-client-ca (Opaque, ca.crt) - mTLS client CA; no rotation (certgen)
- openshell-client-tls (kubernetes.io/tls) - client cert mounted in sandbox/supervisor pods
- <release>-jwt-keys (Opaque) - Ed25519 sandbox-JWT signing keypair; no rotation
- Credential-storage KEK (Opaque, 32 bytes) - AES-256-GCM key for provider creds in DB;
  retained via Helm lookup or existingSecret; shared across workspaces; no rotation
- <supervisor>-token (Opaque) - shared supervisor token; gateway-renewed
- Bootstrap Secrets (Opaque) - per sandbox generation, created by K8s driver
- externalDbSecret (Opaque, uri) - PostgreSQL URI; admin-provided
- Provider credentials (Opaque, SHA-256 names) - K8s Secrets driver; RotateProviderCredential
- Dashboard OIDC client secret - installer file (0600)

Crypto / FIPS:
- TLS: rustls 0.23 + aws-lc-rs (vendored, non-FIPS mode); ring 0.17.14 in dependency tree
- openshell-crypto verify_posture(require_fips=true) -> UnsupportedPosture
- Konflux fips-check-blocking: false on all four pipelines (OCPEXCEPT-75/76)
- Sandbox binary statically linked; does not read system crypto policy
- Runtime images: ubi-minimal-pqc with DEFAULT:PQ crypto policy (hardening, not FIPS)

Dev-only unsafe flags (off by default):
- server.auth.allowUnauthenticatedUsers, server.disableTls,
  oidc.dangerouslyAllowInsecureHttp, CLI/SDK --insecure (skips TLS verification)
