manifests. Exposure is decided by the deployer (for example praxis-proxy/ai or ai-gateway-operator).

RBAC Summary:
- None. Praxis does not call the Kubernetes API; no ClusterRoles, Roles or
  bindings ship in the repository.

Service Mesh Configuration:
- None shipped. Praxis acts as the gateway / sidecar data plane itself
  (ingress, egress, east/west sidecar, security gateway shapes).

Secrets:
- Listener/cluster TLS certs + keys (PEM files at config paths) - mounted by
  deployer; hot-reloaded on file change (config-reload feature)
- Credential injection values (env var or literal config) - upstream API keys;
  wrapped with secrecy/zeroize; no rotation
- Policy API keys / JWKS (config, files, fetched JWKS) - JWKS refreshed by
  Policy engine

Crypto / FIPS:
- Single rustls crypto provider: rustls-openssl (Pingora fork) over system
  libcrypto.so.3. No ring / aws-lc-rs provider; missing provider = startup fail.
- PRAXIS_REQUIRE_FIPS=truthy -> TLS config construction fails unless rustls
  reports FIPS mode.
- FIPS image (Containerfile.fips, UBI 9 minimal, OPENSSL_NO_VENDOR=1,
  features pingora,config-reload,admin-api) EXCLUDES Policy engine:
  JWT / API-key / DPoP policies absent unless policy-*-fips profile selected.
- Standard image (Containerfile, Alpine/musl) is NOT FIPS-capable and its
  default Policy bundle uses RustCrypto (not FIPS-validated).
- ring and aws-lc-rs appear in workspace Cargo.lock (test / weak deps);
  cargo auditable -Zsbom manifest + `cargo xtask fips report` verify the build.

Security Findings / Review Items:
1. Admin API (9901) has NO authentication; protection relies solely on
   loopback bind. allow_public_admin or exposing 9901 = unauthenticated
   control plane (KV store writes, log-level changes).
2. Health/metrics listener (9902) unauthenticated; /metrics exposure must be
   restricted with NetworkPolicy when bound non-loopback.
3. HTTP engine and TLS provider both come from the quixotic-plecostomus-*
   fork; security fixes depend on fork maintenance. tokio pinned ~1.53.3.
4. No NetworkPolicy, Konflux Dockerfiles, rpms.lock.yaml or Hermeto prefetch
   on this branch; cargo-auditable fetched from crates.io at build time.
5. All tenants' credentials live in one process / one YAML config; in-memory
   KV stores are shared across listeners.
