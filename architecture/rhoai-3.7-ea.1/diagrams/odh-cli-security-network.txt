RBAC Summary:
- No ClusterRoles, Roles, RoleBindings or ServiceAccounts are shipped.
- Effective privilege = invoking user's RBAC.
  - lint: broad read (get/list) across 30+ platform API groups
    (DSC/DSCI, DSPA, KServe, Ray, Kubeflow Training/Trainer, Kueue, TrustyAI,
    CodeFlare, LlamaStack/OGX, Dashboard, Kuadrant/Authorino, Gateway API,
    OLM v0/v1, OpenShift config/image). Namespace-limited users get partial results.
  - migrate / deps install: write access, typically cluster-admin, to
    Namespaces, OperatorGroups, Subscriptions, ClusterExtensions, DSC/DSCI,
    InferenceServices, Roles/RoleBindings, workload CRs; pods/exec.
- Safety controls: lint is read-only by construction (client.Reader);
  migrate/deps support --dry-run; migrate run asks for confirmation (--yes skips).

Service Mesh Configuration:
- Not applicable (no in-cluster workload).

Secrets:
- kubeconfig (file, mounted at /kubeconfig or supplied via --token)
  - Provisioned by: user; Auto-rotate: No
  - Forwarded: bearer token is sent to the TrustyAI Route without server verification

Crypto / FIPS:
- Build: CGO + strictfipsruntime, dynamic link to RHEL 9 OpenSSL (Dockerfile.konflux:38-40)
- TLS: client-go defaults for API server; custom tls.Config{MinVersion: TLS12,
  InsecureSkipVerify: true} for TrustyAI Route; no cipher suites set
- No MD5/SHA1/custom crypto found
- Build hermetic: Hermeto rpm + gomod prefetch; rpms.lock.yaml; GOTOOLCHAIN=auto caveat

Security Findings for Review:
1. TrustyAI Route client disables certificate verification while forwarding the
   user's bearer token (MITM / credential exposure).
2. Hidden MCP SSE server has no authentication on loopback; any local process can
   drive cluster-mutating tools with the user's credentials. Review before promotion.
3. kubectl flags allow --insecure-skip-tls-verify on the API server connection.
4. Hidden deps command can fetch manifests from GitHub at runtime (non-pinned input).
5. Upstream Dockerfile downloads kubectl/oc via curl (non-hermetic); Konflux image does not.
