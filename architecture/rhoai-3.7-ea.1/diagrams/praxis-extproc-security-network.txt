PROBE PATH
  [kubelet] → 50052/TCP gRPC health (plaintext, no auth)
    readiness: grpc probe, service envoy.service.ext_proc.v3.ExternalProcessor
    liveness:  tcpSocket
    SERVING only after pipeline build + FIPS requirements met; NOT_SERVING on drain

RBAC Summary:
- ClusterRole: payload-processing-metrics-auth
  - API Group: authentication.k8s.io   Resources: tokenreviews          Verbs: create
  - API Group: authorization.k8s.io    Resources: subjectaccessreviews  Verbs: create
  - Bound via ClusterRoleBinding payload-processing-metrics-auth
    → SA openshift-ingress/payload-processing
- ClusterRole: payload-processing-metrics-reader
  - Non-resource URL: /metrics         Verbs: get
  - Bound via ClusterRoleBinding payload-processing-metrics-reader
    → SA redhat-ods-monitoring/prometheus-k8s
- Note: an earlier payload-processing-reader role (cluster-scoped secrets get)
  was intentionally removed and must not be restored.

Service Mesh / Istio Configuration:
- praxis-extproc pods are NOT mesh members (Istio metadata-exchange frames
  cause HTTP/2 protocol_error), hence custom EnvoyFilter CLUSTERs.
- EnvoyFilter payload-processing (HTTP_FILTER + CLUSTER on maas-default-gateway)
  - Anchored relative to Kuadrant Wasm (4 alternative subfilter names, incl.
    misspelled extenstions.istio.io variant)
  - Removes and re-inserts Istio's EPP envoy.filters.http.ext_proc before the
    router (mirrors Istio <=1.31 rendering) - Istio/OSSM upgrade coupling risk
- DestinationRules payload-processing / payload-pre-processing: TLS SIMPLE,
  service-CA trust, SNI/SAN.
- No PeerAuthentication / AuthorizationPolicy.

Network Policy:
- Ingress 9004/TCP: only gateway pods in openshift-ingress
- Ingress 9090/TCP: monitoring namespaces only
- Ingress 50052/TCP: not allowed (kubelet probes bypass)
- Egress: DNS 53/5353, TCP 443/6443

Secrets:
- payload-processing-tls (kubernetes.io/tls) - post-auth listener cert/key,
  mounted /etc/tls/private, provisioned by OpenShift service-ca, auto-rotated;
  process reloads only on restart (Stakater Reloader annotation required)
- payload-pre-processing-tls (kubernetes.io/tls) - pre-auth listener cert/key,
  same provisioning and restart caveat
- Projected SA token (automountServiceAccountToken: true) - TokenReview/SAR calls

Crypto / FIPS:
- Listener: OpenSSL SslAcceptor mozilla_modern_v5 + TLS 1.2 re-enabled;
  TLS 1.2 ECDHE-ECDSA/RSA AES-GCM + CHACHA20-POLY1305 only; ALPN h2
- Outbound: rustls with a single OpenSSL-backed CryptoProvider; kube uses openssl-tls
- Build: OPENSSL_NO_VENDOR=1, dynamic system OpenSSL, UBI 9 minimal PQC runtime,
  features responses,aws-sigv4,store-postgres-cert-auth (policy engine excluded)
- PRAXIS_REQUIRE_FIPS runtime gate exists but is NOT set in the deploy manifests
- ring / aws-lc-rs present in Cargo.lock; verify with make fips-check / cargo xtask fips

Key Risks:
- Fail-closed + replicas 1 + no PDB: pod restart blocks inference traffic
- No client authentication on gRPC 9004 (relies on NetworkPolicy)
- Shared 8-request circuit breaker across all tenants (noisy-neighbour)
- Header strip list must stay in sync with MaaS x-maas-* header names
- Body/memory limits must be kept in step across ConfigMap, Deployment env,
  and EnvoyFilter
