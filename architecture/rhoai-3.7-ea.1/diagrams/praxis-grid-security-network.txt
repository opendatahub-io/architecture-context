RBAC Summary (ServiceAccount grid-operator unless noted):
- ClusterRole grid-operator-crd (ClusterRoleBinding)
  - grid.praxis.fast: gridnetworks, inferenceproviders, agenttoolproviders
      get, list, watch, patch  (+ create on gridnetworks)
  - grid.praxis.fast: gridsites  get, list, watch, patch, create, update, delete
  - grid.praxis.fast: */status   get, patch
- ClusterRole grid-operator-resources (RoleBinding in grid-system)
  - core secrets: get, create, patch
  - core services (grid-gateway, grid-operator-swim, grid-operator-signals): get
  - apps deployments (grid-gateway): get, patch
  - events.k8s.io events: create, patch
  - core configmaps: get, create, patch, update
  - core configmaps (grid-operator-local-records): delete
- Role grid-operator-leader-election (grid-system)
  - coordination.k8s.io leases: create; get, update (grid-operator)
  - core pods: get, list; services (signals, swim): get
  - discovery.k8s.io endpointslices: create, list, delete (VAP-restricted)
  - discovery.k8s.io endpointslices/restricted: create
  - discovery.k8s.io endpointslices (*-signals-holder, *-swim-holder): get, update
- Role grid-operator-metrics-scraper-token: serviceaccounts/token
  (grid-operator-metrics-scraper): create
- Role grid-operator-operator-config: configmaps (grid-operator-config):
  get, list, watch
- ClusterRole grid-operator-metrics-scraper → SA grid-operator-metrics-scraper:
  nonResourceURL /metrics: get

Admission Policies (failurePolicy: Fail):
- grid-operator-endpointslice-cleanup: operator SA may DELETE only
  controller-managed EndpointSlices on grid-operator-signals / grid-operator-swim
- grid-operator-protect-config: denies operator SA UPDATE of grid-operator-config

Service Mesh Configuration:
- None. No Istio, Gateway API or HTTPRoute resources are created by the operator.
- Transport security is application-level: rustls/ring (default) or system
  OpenSSL (FIPS build), client minimum TLS 1.2, EMS required, resumption off.

Secrets:
- grid-swim-key (Opaque) - 32-byte AES-256-GCM SWIM mesh key, shared across
  sites, provisioned by deployment owner, NOT auto-rotated
- grid-site-identity (kubernetes.io/tls) - site mTLS identity (signals, base
  metrics TLS); enrollment / cert-manager / operator; rotated via
  /v1alpha1/rotations
- grid-operator-metrics-tls (kubernetes.io/tls) - OpenShift service-CA,
  auto-rotated, listener hot-reloads
- Provider credential Secrets (Opaque, InferenceProvider.spec.auth.secretRef) -
  mounted only in final-hop gateway; overlays carry references, never values
- Enrollment CA / serving cert / DB Secrets - bootstrap Job or cert-manager

FIPS:
- FIPS images only for grid-operator and grid-overlay-sync (UBI9-minimal,
  dynamic libssl.so.3/libcrypto.so.3, grid_fips::verify() at startup requires
  fips_enabled=1, FIPS default properties, SHA-256 KAT).
- enrollment, grid-gateway, fleet-dashboard, mock-providers: Alpine, static
  OpenSSL/rustls - would fail check-payload as built.
- Default params.env image is the non-FIPS Alpine operator image.

Key Security Observations:
1. SWIM (7946/UDP) is exposed via LoadBalancer and open to any source; it is
   protected only by a shared mesh key. Any key holder can inject state for
   any site (origin signing exists in the swim crate but is not wired).
2. Signals (9091/TCP) is exposed via LoadBalancer but protected by mTLS with
   SPIFFE site certificates.
3. No request-time tenant-to-model authorization; access policy is site-level.
   Edge gateway must enforce caller auth.
4. All five CRDs are cluster-scoped: anyone able to create InferenceProvider /
   GridSite affects routing for the whole site.
5. fleet-dashboard has no in-app authorization (relies on oauth-proxy).
6. overlay-sync health (9091/TCP) and operator metrics (9090/TCP) are
   unauthenticated (metrics is NetworkPolicy-restricted on OpenShift only).
