Listener Summary:
  Port       Bind        App         Proto  TLS                         Auth
  8081/TCP   127.0.0.1   main app    HTTP   None (loopback)             kube-rbac-proxy (external)
  4443/TCP   0.0.0.0     main app    HTTPS  TLS (system / configured)   NONE
  8080/TCP   0.0.0.0     health_app  HTTP   None                        NONE
  (Container EXPOSE 8080 4443. No gRPC server; KServe v2 .proto used only for decoding.)

Authentication & Authorization:
- All main-app routes via 8081: Bearer token, enforced by kube-rbac-proxy sidecar (SAR)
- All main-app routes via 4443: no auth middleware; relies on network isolation
- /, /consumer/kserve/v2, /q/health* on 8080: no auth; relies on NetworkPolicy
- CORS: Starlette CORSMiddleware allow_origins=["*"], allow_credentials=True,
  all methods/headers
- Feature flags (TRUSTYAI_ENABLE_*) read at import; disabled routes return 404
- Explainers (LIME/SHAP/CF/TSSaliency/PDP) disabled by default; return 501

RBAC Summary:
- No ClusterRoles / Roles / RoleBindings defined in this repository.
- The service does not call the Kubernetes API.
- kube-rbac-proxy RBAC (tokenreviews create, subjectaccessreviews create) is
  provisioned by trustyai-service-operator.

Service Mesh Configuration:
- None defined. No PeerAuthentication / AuthorizationPolicy in repo.

NetworkPolicy:
- None in repo. Deployer (operator) must restrict 8080 and 4443
  (docs/server-tls.md: "Network exposure and plaintext exceptions must be
  evaluated by the deployer").

Secrets:
- Serving cert (kubernetes.io/tls) mounted at /etc/tls/internal/tls.crt, tls.key
    HTTPS listener on 4443; OpenShift service-ca via operator; auto-rotated,
    service restart required to reload
- DB CA (file mount) at /etc/tls/db/ca.crt - verify DB server cert; operator/user; no rotation
- DATABASE_USERNAME / QUARKUS_DATASOURCE_USERNAME (env from Secret) - DB credentials
- DATABASE_PASSWORD / QUARKUS_DATASOURCE_PASSWORD (env from Secret) - DB credentials
- TRUSTYAI_MIGRATION_SOURCE_URL / TRUSTYAI_MIGRATION_TARGET_URL (env, may embed
    credentials) - trustyai-migrate DSNs

Crypto / FIPS:
- Python stdlib ssl / hashlib backed by system OpenSSL (AIPCC EL9.8 base)
- No cryptography, PyJWT or pycryptodome
- create_default_context(Purpose.CLIENT_AUTH), OP_NO_COMPRESSION
- Python cannot set TLS 1.3 suites or multiple key-exchange groups; docs
  recommend an external terminator and removing 4443 for such TLS profiles
- MD5 for UUIDv3 metric ids (usedforsecurity=False, FIPS-safe)
- SHA-256 for namespace table tokens and migration content digests
- No explicit FIPS opt-in; relies on base image OpenSSL / system crypto policy

Migration (trustyai-migrate):
- Source: PVC HDF5/CSV or MariaDB legacy tables (3306/TCP, TLS CERT_REQUIRED if CA)
- Target: SQL DB canonical schema (asyncmy/asyncpg, 3306/5432, TLS + hostname check if CA)
