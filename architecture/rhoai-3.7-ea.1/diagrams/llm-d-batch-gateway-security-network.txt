        gc.config.reconciler.enabled)
  - API Group "":   pods          verbs: get, list, watch
  - API Group apps: statefulsets  verbs: get, list, watch
- RoleBinding: <release>-gc-pod-watcher -> gc ServiceAccount (release namespace)
- apiserver / processor ServiceAccounts: no bindings, but automount: true

Service Mesh / Gateway Policy Configuration:
- No Istio PeerAuthentication or NetworkPolicy shipped in the Helm chart
- External Gateway (batch-route): AuthPolicy (TokenReview / API key) + RateLimitPolicy
- Internal Gateway (batch-llm-route): AuthPolicy SubjectAccessReview on
  inferencepools; no TokenRateLimitPolicy

Secrets:
- batch-gateway-secrets (Opaque, global.secretName) - manual, no rotation
  keys: postgresql-url, redis-url, inference-api-key, s3-secret-access-key
  mounted read-only at /etc/.secrets, read via os.OpenInRoot
- <release>-apiserver-tls / apiserver.tls.secretName (kubernetes.io/tls) -
  API server serving cert; cert-manager (auto-rotate) or manual
- Per-gateway CA / client cert Secrets (kubernetes.io/tls / Opaque) -
  processor -> inference gateway TLS/mTLS; manual or cert-manager
- Per-model api_key_file - manual, no rotation

Security Observations:
1. No in-process authentication. Any in-cluster caller reaching Service port
   8000 can impersonate any tenant by setting X-MaaS-Username. Missing header
   falls back to the shared "default" tenant. No NetworkPolicy restricts this.
2. User Bearer tokens (passThroughHeaders: [Authorization], Helm default) are
   stored in plaintext in PostgreSQL batch tags JSONB and, in async mode, in
   Redis messages, for the life of the batch row.
3. Gateway -> apiserver hop is plaintext HTTP unless apiserver.tls.enabled.
4. Observability ports (8081/9090/9091) are unauthenticated plain HTTP;
   enabling pprof exposes profiling and cmdline data in-cluster.
5. OTLP export defaults to insecure; PostgreSQL TLS depends on sslmode.
6. tls_insecure_skip_verify per inference gateway disables cert verification.
7. Upstream images: CGO_ENABLED=0 static on distroless - would fail Konflux
   check-payload FIPS gate; downstream Konflux build config not present.
8. Tenant isolation is application-level only (tenant_id filters, t-sha256
   storage prefixes); shared DB, bucket, processor pool and API key.
