SCOPE NOTE: praxis-policy is an embedded Rust LIBRARY. It has no listener,
Service, Ingress, Route, CRD, RBAC or container image. All inbound exposure and
all outbound HTTP TLS settings belong to the host (Praxis proxy). Ports marked
"host-defined" or "configurable" are set in host or policy config.

RBAC Summary:
- None defined in this repository (no ClusterRoles, Roles, bindings or
  ServiceAccounts). Any Kubernetes RBAC belongs to the host deployment.
- Vault Kubernetes auth uses the host pod's ServiceAccount token.

Service Mesh / Network Policy:
- None defined. Network isolation is a host / platform responsibility.

Secrets (runtime, via secrets provider: env / file / Vault KV v2):
- OAuth/CIBA client credentials (env/file/Vault ref) - IdP client auth;
  provisioned by host operator; no auto-rotation
- Vault auth material (SA token / role_id + secret_id) - Vault login;
  Vault token renewed by plugin (renew-self)
- Valkey credentials (URL userinfo or config) - session store auth;
  provisioned by host operator; no auto-rotation
- OAuth cache-key secret (in-memory, random bytes) - HMAC key for token
  cache keys; generated at startup, per process
- Secret buffers zeroized; env lookup errors do not echo values

Authentication & Authorization:
- Host routes (tool/resource/prompt/LLM/HTTP): JWT or API key; enforced by
  embedded PPE; APL require(...), Cedar/CEL/OPA PDPs, Session Taint, redaction
- Upstream calls: delegated per-audience token via delegate(...) APL action

Multi-Tenancy:
- Tenant boundary: authenticated principal (sub + issuer); no namespaces
- Valkey keys use key_prefix + principal-bound session ids (shared instance)
- Decision cache keyed by SHA-256 of principal + request attributes
- Single policy document per engine; no per-tenant config separation

Cryptography / FIPS:
- Default backend: RustCrypto (sha2/hmac), NOT FIPS
- fips feature: OpenSSL SHA-256 + private DRBG; jwt-openssl-fips: OpenSSL
  RS/PS/ES verification; HS*/EdDSA refused, RSA 2048-8192, EC P-256/P-384
- Outside FIPS profile: OAuth delegation, Vault delegation, Valkey
  (rustls/ring), ordinary jwt (AWS-LC), http-hyper (ring)
- Runtime gate: crypto_capability_report().fips_profile_is_safe() and
  SHA-256 self-check in PolicyEngine::initialize()
- Build gate: make check-fips-graph rejects sha2/hmac/ring/rustls/aws-lc
- TLS (http-hyper, unused by Praxis): rustls TLS 1.2/1.3, ring ciphers,
  webpki-roots bundle (not system trust store; OpenShift service CAs fail)
- Hashes: SHA-256, HMAC-SHA256; no MD5/SHA-1

Security Observations:
- Cargo.lock contains ring, aws-lc-rs and openssl; enabling builtins selects
  non-FIPS providers. Whether RHOAI Praxis is FIPS-safe depends on host
  Cargo features.
- Correctness of enforcement depends on the host routing all traffic
  through the engine.
- Quota is a soft cap with an overrun window; pending-debit state is
  per-replica and in-process. Quota/ratelimit are experimental.
