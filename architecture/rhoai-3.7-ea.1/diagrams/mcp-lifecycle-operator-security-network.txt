RBAC Summary:
- ClusterRole: mcp-lifecycle-operator-manager-role
  (bound cluster-wide via mcp-lifecycle-operator-manager-rolebinding)
  - core: configmaps, namespaces, pods, secrets        get, list, watch
  - core: services                                     create, delete, get, list, update, watch
  - events.k8s.io: events                              create, patch
  - apiextensions.k8s.io: customresourcedefinitions    get, list, watch
  - apps: daemonsets, statefulsets                     get, list, watch
  - apps: deployments                                  create, get, list, update, watch
  - gateway.networking.k8s.io: gateways                get, list, watch
  - gateway.networking.k8s.io: httproutes              create, delete, get, list, update, watch
  - mcp.kuadrant.io: mcpgatewayextensions              get, list, watch
  - mcp.kuadrant.io: mcpserverregistrations            create, delete, get, list, update, watch
  - mcp.x-k8s.io: mcpgatewaybindings                   create, delete, get, list, patch, update, watch
  - mcp.x-k8s.io: mcpservers                           get, list, patch, update, watch
  - mcp.x-k8s.io: */status                             get, patch, update
  - mcp.x-k8s.io: */finalizers                         update
  - networking.k8s.io: networkpolicies                 create, get, list, update, watch
- ClusterRole: mcp-lifecycle-operator-metrics-auth-role (ClusterRoleBinding)
  - authentication.k8s.io tokenreviews: create
  - authorization.k8s.io subjectaccessreviews: create
- ClusterRole: mcp-lifecycle-operator-metrics-reader
  - nonResourceURL /metrics: get
- Role: mcp-lifecycle-operator-leader-election-role (ns mcp-lifecycle-operator-system)
  - configmaps, coordination.k8s.io leases: full CRUD; events: create, patch
- Aggregated user roles: mcpserver-admin-role (aggregate-to-admin),
  mcpserver-editor-role (aggregate-to-edit), mcpserver-viewer-role (aggregate-to-view)

Admission Control:
- Validating webhook vmcpserver.mcp.x-k8s.io (v1alpha1, matchPolicy Equivalent)
  - Registered only with --enable-webhook (set in kustomize default)
  - Rules: image allowlist, digest pinning, max storage mounts, required labels,
    privileged securityContext rejection (only the last is on by default)
  - Cluster-wide policy; failurePolicy Fail blocks MCPServer writes when operator is down
- Conversion webhook /convert: always registered
- No mutating webhook

Service Mesh Configuration:
- None. No PeerAuthentication / AuthorizationPolicy; isolation via NetworkPolicy.

Secrets:
- mcplo-webhook-server-cert (kubernetes.io/tls) - webhook TLS; cert-manager self-signed
  Issuer (upstream default); auto-renewed, reloaded by cert watcher
- mcplo-metrics-server-cert (kubernetes.io/tls) - metrics TLS; cert-manager self-signed
  Issuer; auto-renewed, reloaded by cert watcher
- spec.transport.tls.caBundleSecret (Opaque, user) - CA for handshake; hash tracked,
  change triggers re-verification
- imagePullSecrets / storage-mounted / envFrom Secrets (user) - passed through to MCP pods

TLS Profile:
- TLS_MIN_VERSION / TLS_CIPHER_SUITES / TLS_GROUPS env (Go defaults if unset)
- Applied to webhook + metrics servers and handshake clients (with floor)
- HTTP/2 disabled unless --enable-http2

Security Risks / Observations:
1. insecureSkipVerify on spec.transport.tls honored (warning event + log only)
2. Base ServiceMonitor uses insecureSkipVerify: true (ODH overlay injects serverName only)
3. Manager SA reads Secrets/ConfigMaps cluster-wide (get, list, watch)
4. Gateway / Kuadrant namespace allowlists empty by default → cross-tenant route
   attachment possible
5. Default NetworkPolicy posture "open" leaves operand ingress unrestricted
6. parseCipherSuites accepts tls.InsecureCipherSuites() names
7. Operator egress is allow-all in the ODH overlay (stopgap)
