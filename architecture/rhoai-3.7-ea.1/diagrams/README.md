## Diagram Descriptions

### Component Dependency Graph
Shows how platform components depend on each other. rhods-operator is the single root (302 edges) and now acts mainly as a module orchestrator. Hubs (kserve, odh-model-controller, llm-d-router, models-as-a-service, kueue-operator) are highlighted. Deprecated or offboarded components (llm-d-routing-sidecar, vllm-orchestrator-gateway image, modelexpress) are dashed. The Tech Preview AI Grid (Praxis) is purple. Useful for understanding blast radius of changes and planning upgrades.

### Platform Network Topology
Complete network architecture showing all ingress points, gateway-tier authentication chains, and egress destinations. Includes exact port numbers, protocols, encryption, and authentication mechanisms.

- **data-science-gateway** (rhods-operator): fail-closed `ext_authz` to kube-auth-proxy, authentication only. Backend hop uses an `insecureSkipVerify` DestinationRule.
- **openshift-ai-inference** (odh-gitops): Kuadrant AuthPolicy to Authorino (TokenReview + SAR), then llm-d EPP `ext_proc`.
- **maas-default-gateway** (odh-gitops or MaaS manifests): ext_proc pre/post the Kuadrant wasm, API keys, OPA subscriptions, token rate limits.

**Two formats provided**:
- **Mermaid (.mmd)**: Visual diagram with color-coded trust zones. Great for presentations and architecture discussions.
- **ASCII (.txt)**: Precise text format with no ambiguity. Required for SAR (Security Architecture Review) submissions and compliance documentation.

Both formats contain the same core information. The ASCII file additionally lists namespaces, unresolved ingress joins, unauthenticated surfaces and an RBAC summary.

### Cross-Component Workflows
One sequence diagram with three highlighted workflows: (A) dashboard login and workbench access through kube-auth-proxy and kube-rbac-proxy, (B) LLMInferenceService deployment and Authorino-authorized inference through the llm-d EPP, (C) MaaS API-key issuance and governed inference, including the ExternalModel branch.

### Platform Security Overview
Authentication stacks, gateway policies, privileged identities (RBAC-escalation mirroring), critical secrets, TLS configuration, container/FIPS posture, admission control and the observed unauthenticated or NetworkPolicy-only surfaces.

### Platform Observability
Prometheus scrape targets split into authenticated (TokenReview + SAR) and unauthenticated endpoints, health probes per component, and OTLP tracing/usage-log flows into the odh-observability stack (OTel collectors, Tempo, Loki, Perses).

**Note:** This generation of PLATFORM.md has no "Monitoring & Observability" section. This diagram was built from the component architecture documents in `architecture/rhoai-3.7-ea.1/*.md` instead. It covers about 25 key components, not all 95.

### Platform Maturity Dashboard
High-level metrics: component and CRD counts, API version distribution, gateway auth fragmentation, mTLS and FIPS status, Gateway API coverage, HA and SPOFs, disconnected and multi-arch support, and the evidence gaps in this generation.
