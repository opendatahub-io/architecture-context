Services:
- odh-model-controller-webhook-service   ClusterIP 443/TCP → 9443  HTTPS  TLS (service-ca)  admission
- odh-model-controller-metrics-service   ClusterIP 8443/TCP → 8443 HTTPS  TLS (service-ca)  TokenReview + SAR
- model-serving-api                      ClusterIP 443/TCP → 8443  HTTPS  TLS 1.2+ (hot-reloaded)  Bearer + SSAR
- model-serving-api                      ClusterIP 8080/TCP → 8080 HTTPS  TLS 1.2+  none

Admission Webhooks (all failurePolicy: Fail, port 9443):
- Mutating  core/v1 Pod CREATE (all pods; acts on RAY_USE_TLS)  - Ray TLS volumes + cert init container
- Mutating  v1beta1 InferenceService CREATE/UPDATE              - ConnectionsAPI credential injection, HardwareProfile
- Mutating  v1alpha1 InferenceGraph CREATE                       - defaulting
- Mutating  v1alpha1 + v1alpha2 LLMInferenceService CREATE/UPDATE - ConnectionsAPI; may create ServiceAccounts
- Validating v1beta1 InferenceService   - name length, protected namespace, canary ≤ 3, DRA
- Validating v1alpha1 InferenceGraph    - step serviceUrl must be name.namespace for .svc hosts
- Validating v1alpha1 + v1alpha2 LLMInferenceService - HardwareProfile DRA references
- Validating nim.opendatahub.io/v1 Account - singleton per namespace
- xKS mode: only the LLMInferenceService webhooks are registered

Secrets:
- odh-model-controller-webhook-cert (kubernetes.io/tls) - webhook TLS, service-ca (cert-manager in xKS), auto-rotated
- odh-model-controller-metrics-tls  (kubernetes.io/tls) - metrics TLS, service-ca, auto-rotated
- model-serving-api-tls             (kubernetes.io/tls) - API/metrics TLS, service-ca, hot-reloaded (fsnotify)
- Ray CA + per-pod Ray cert Secrets (kubernetes.io/tls) - self-signed RSA-4096 by controller, NO rotation
- storage-config (Opaque, per namespace) - aggregated data-connection/S3 credentials, built by SecretReconciler
- NGC API key Secret / NIM pull Secret (Opaque / dockerconfigjson, per namespace) - user / AccountReconciler, no rotation
- KEDA Prometheus auth Secret / SA token - created by controller, rotation unknown

TLS / FIPS:
- Manager: cluster APIServer TLS profile on webhook + metrics (Mozilla Intermediate fallback, TLS 1.2); fail-fast on malformed profile
- model-serving-api: TLS 1.2 min, ECDHE AES-GCM, curves X25519MLKEM768/P-256/P-384; cluster profile under StrictAllComponents
- Both binaries restart on TLS profile change (ProfileWatcher / watchTLSPolicy)
- Build: CGO_ENABLED=1 GOEXPERIMENT=strictfipsruntime, ubi-minimal-pqc runtime (OpenSSL), digest-pinned bases, hermetic gomod prefetch

Key Security Observations:
- Pod mutating webhook intercepts ALL Pod CREATEs with failurePolicy Fail: webhook availability affects cluster-wide pod scheduling
- Controller pod NetworkPolicy allows all ingress; 8081 probes are plaintext and unauthenticated
- model-serving-api /metrics (8080) and /api/v1/samples/llm-d have no authentication
- ConnectionsAPI webhooks read user-namespace Secrets with controller privileges; namespace scoping enforced in code, not RBAC
- Controller can create ClusterRoleBindings/RoleBindings (per-ISVC auth delegation, Grid RBAC) - escalation-capable SA
- Outbound NGC/nvcr.io calls matter for air-gapped installs; MR_SKIP_TLS_VERIFY can disable Model Registry cert verification
- params.env on this branch references quay.io/opendatahub/*:odh-stable and quay.io/vllm/*:latest; RHOAI operator overrides with digest-pinned images
