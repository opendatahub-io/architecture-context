RBAC Summary:
- None in repo. No ClusterRoles, Roles or bindings.
- The model server does not call the Kubernetes API.

Service Mesh / Network Policy:
- None in repo. Any mTLS, AuthorizationPolicy or NetworkPolicy comes from the
  KServe / gateway deployment layer.

Secrets:
- None referenced in repo. KServe supplies model-storage credentials at deployment.

Authentication & Authorization:
- vLLM API (8000/TCP, GET/POST): no auth by default; optional vLLM --api-key.
  Enforcement point: deployment layer (KServe / gateway).
- /health and /metrics: unauthenticated.
- NIXL KV transfer: no auth or encryption in plugin.

FIPS:
- NOT FIPS-capable: Dockerfile.konflux.gaudi:59-64 runs
  `rpm -e --nodeps openssl-fips-provider-so` ("Remove FIPS provider").
- No TLS or crypto code in vllm_gaudi; server TLS is off by default in upstream vLLM/uvicorn.
- Habana vendor binaries and public PyPI wheels are not FIPS-validated.

Build Hermeticity / Supply Chain:
- RPM: no lock file (CentOS Stream, EPEL, Habana repos added ad hoc)
- Python: no lock file (requirements.txt lower bounds only); public PyPI
- Artifacts: Habana PyTorch tarball fetched with wget; install.sh executed
- Hermeto prefetch: none; Tekton hermetic: false; linux/x86_64 only
- PROVENANCE: image clones upstream Intel vllm-gaudi v0.16.0 from GitHub instead of
  building the checked-out downstream source. Downstream patches do not reach the image.
- Not on AIPCC base image (overlay 0017 lists AIPCC Gaudi variant 1.24.1 / torch 2.11).

Multi-Tenancy:
- Tenant boundary: per-namespace InferenceService (delegated to KServe)
- One single-tenant model-server instance per InferenceService
- Gaps: unauthenticated by default; NIXL traffic unauthenticated and unencrypted
