## Purpose

**Short**: AI Grid Network (AGN) is a Rust Kubernetes operator. It federates inference providers across clusters, clouds and external APIs, and publishes routing state that Praxis AI gateways use to choose a provider for each request.

**Detailed**: praxis-grid (AGN) is a control plane, not a proxy. The `grid-operator` watches cluster-scoped `grid.praxis.fast/v1alpha1` custom resources: `GridNetwork`, `GridSite`, `InferenceProvider`, `AgentToolProvider` and `SiteInvite`. It forms a peer-to-peer membership mesh with operators at other sites using the SWIM gossip protocol (built on `foca`) over UDP/7946. Provider capabilities and load signals spread between peers as delta CRDTs. The operator scores providers using one of three strategies (`noMetrics`, `queueDepth`, `kvCachePressure`) and writes routing overlays into ConfigMaps. The `grid-overlay-sync` sidecar watches the overlay ConfigMap, validates the content-addressed envelope, and writes it atomically into a shared `emptyDir`. The Praxis AI gateway then hot-reloads that file. The operator stays out of the request path, so gateways keep serving from their last accepted snapshot while the operator is down.

The repo also holds several optional parts:
- an **enrollment** service, which is the production certificate signer that bootstraps site identity (CA, CSR signing, rotation)
- a **fleet-dashboard** hub web UI
- **mock-providers**, which simulates OpenAI, Anthropic, Bedrock and Vertex for tests
- the project-owned **grid-gateway** data-plane binary, in a separate Cargo workspace under `crates/gateway/`

Deployment is through Helm charts (`grid-operator`, `grid-enrollment`, `grid-site`, `praxis-gateway`, `grid-mock-providers`). Kustomize manifests are generated from the operator chart (`deploy/operator`, `deploy/overlays/{kind,openshift}`).

Within RHOAI, AGN is a technical preview (`docs/technical-preview-scope.md`). The deployment owner supplies the clusters, inference backends, credentials, gateways and inter-site connectivity. Provider credentials stay on the final-hop gateway as mounted Secrets. Overlays carry only Secret references, never token values.

## Architectural Analysis

**Control plane separated from the data plane.** The operator computes eligibility and scoring and publishes them as data: a routing overlay in a ConfigMap, a serving ConfigMap for `grid-gateway`, and a per-site signals endpoint. The Praxis gateways make the actual per-request choice. As a result, an operator outage degrades freshness but not availability. The overlay envelope is content-addressed and validated by overlay-sync before it is written atomically, so a gateway never loads a partial or corrupt overlay (`crates/overlay-sync/src/main.rs:3-8`).

**Peer-to-peer federation without a central hub API.** Sites find each other through SWIM seeds. Membership and provider state travel over UDP gossip encrypted with a shared AES-256-GCM mesh key, taken from `GridNetwork.spec.tls.swimKeySecretRef` (chart default `grid-swim-key`). The README notes a real trust gap: the shared mesh key does not bind a broadcast to a specific site identity. The SWIM library supports ECDSA P-256 origin signatures (`crates/swim/src/signing.rs`), but the operator does not yet wire signing and origin pins into its publication path (upstream issue #75). Any holder of the mesh key can therefore inject state for any site.

**Leader-election and Service tricks to reach peers across clusters.** Both the SWIM and signals Services in the base and OpenShift manifests are selector-less `LoadBalancer` Services with `externalTrafficPolicy: Local`. The leader writes "holder" EndpointSlices (`grid-operator-swim-holder`, `grid-operator-signals-holder`) that point at its own pod, so only the elected replica receives peer traffic. This is why the operator needs EndpointSlice `create`/`delete` rights and the OpenShift `endpointslices/restricted` virtual subresource. Those broad verbs are fenced by a ValidatingAdmissionPolicy (`grid-operator-endpointslice-cleanup`): the operator may only delete controller-managed slices on its own two Services. A second VAP (`grid-operator-protect-config`) stops the operator ServiceAccount from updating its own `grid-operator-config` ConfigMap. Using admission policy to narrow RBAC that cannot be scoped by name is a careful least-privilege pattern.

**Three separate authentication layers** (`docs/architecture/auth.md`):
1. External caller auth at the edge gateway. Not part of AGN.
2. AGN site mTLS between consumer and provider gateways, and for operator-to-operator signals on 9091. Identities are SPIFFE-style site certificates verified by a custom `GridSpiffeServerVerifier`.
3. Provider credential injection at the final-hop gateway.

Access policy is site-level, not tenant-level. The project states that request-time tenant-to-model authorization "is not yet implemented."

**Dual crypto backends selected at build time.** Default builds (Alpine/musl, `OPENSSL_STATIC=1`) use rustls on ring, RustCrypto `aes-gcm`/`sha2`, and `rcgen`. The opt-in `fips` Cargo feature (operator, overlay-sync, enrollment) routes every TLS stack, certificate key generation and signing, identity fingerprinting and SWIM AEAD/signing through dynamically linked system OpenSSL. The dedicated `Containerfile.fips` images run on a digest-pinned UBI9-minimal base, check `ldd` for `libssl.so.3` and `libcrypto.so.3` at build time, and call `grid_fips::verify()` at startup. That check requires `/proc/sys/crypto/fips_enabled=1`, FIPS default properties, and a SHA-256 known-answer test (`crates/fips/src/lib.rs`). The gossip wire format is the same for both backends, so FIPS and non-FIPS sites interoperate on one key. Only the operator and overlay-sync have FIPS images. Enrollment, gateway, fleet-dashboard and mock-providers images are Alpine with static OpenSSL or rustls.

**Risks and observations:**
- No `.konflux` Dockerfiles, Tekton pipelines, `rpms.lock.yaml` or Hermeto configuration exist on this branch. The analyzed checkout is upstream `main`, and downstream RHOAI build hardening is not visible here.
- The default `params.env` image is `ghcr.io/praxis-proxy/grid-operator:v0.3.0`, the non-FIPS Alpine image. RHOAI would have to substitute the `-fips` UBI image.
- The base and OpenShift manifests expose SWIM (UDP/7946) and signals (TCP/9091) as `LoadBalancer` Services. The OpenShift NetworkPolicy allows those ports from any source by design, so peers can reach them. Signals is protected by mTLS, but SWIM depends only on the shared mesh key.
- All five CRDs are cluster-scoped. One operator instance serves one site in one `GridNetwork` (`GRID_NETWORK=grid`). There is no in-cluster tenancy model.
- `sqlx-postgres` in the enrollment service links `sha2` and `md-5` for Postgres password authentication even in FIPS builds. This is a documented exception (`docs/fips.md`).

|--------|-------|--------|

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Site-level mTLS identity. Access policy on InferenceProvider is site-oriented. | Application | No request-time tenant-to-model authorization ("not yet implemented"). Edge gateway must enforce caller auth. |
| Data storage | No tenant data stored. Routing state lives in ConfigMaps in the operator namespace. Enrollment uses a shared Postgres. | Kubernetes / Application | Enrollment DB is shared across all sites |
| Network traffic | OpenShift NetworkPolicy restricts metrics. SWIM and signals are open to any source. | Kubernetes / Application | SWIM trusts any holder of the shared mesh key. No per-site origin binding. |
| Compute & resources | Single Deployment, PodDisruptionBudget in chart | Kubernetes | N/A |
| Configuration & secrets | Provider Secrets referenced by name/namespace and mounted only at the final-hop gateway | Kubernetes / Application | Operator holds cluster-scoped read of the CRDs and namespaced Secret create/patch |
| API scoping | Cluster-scoped CRDs, cluster-wide watches | Kubernetes RBAC | Anyone able to create InferenceProvider/GridSite affects routing for the whole site |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| SWIM gossip mesh | GridNetwork (shared key) | AES-256-GCM encryption only. Origin signing not yet wired. |
| Enrollment service + Postgres | per-site enrollment record | TokenReview + SAR, one-time tokens, per-site certificates |
| Praxis gateways (data plane) | site (consumer vs provider identities) | mTLS peer identity (`peer_identity_trust`), separate Services and credential mounts |
