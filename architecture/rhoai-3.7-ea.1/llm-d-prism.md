## Purpose

**Short**: Prism is a web dashboard and results store for llm-d inference benchmarks. It pulls benchmark data from GCS, the Google GKE Inference Quickstart (GIQ) API, S3 and local files into one interactive view, and it accepts curated benchmark submissions through a GitHub-authenticated workflow.

**Detailed**: Prism is aimed at AI platform engineers and ML engineers who need to compare inference-serving configurations (throughput, latency, cost, quality) across llm-d well-lit paths such as P/D disaggregation, prefix-cache offloading, intelligent routing and regression tracking. The React 19 / Vite frontend (`src/`) renders dashboards with Recharts. An Express server (`server/server.js`) serves the built SPA from `dist/` and acts as a Backend-for-Frontend (BFF). The server proxies GIQ (`gkerecommender.googleapis.com`) and Google Cloud Storage with the server's Application Default Credentials (ADC), so the browser never holds Google credentials.

The second responsibility is the **Results Store** (`server/results/`). Contributors submit benchmark runs (BRv0.2 benchmark-report format) to a GCS bucket under a results-store prefix. Admins then review and promote them to public visibility. A GitHub OAuth flow handles identity, and permissions are resolved from llm-d GitHub org membership plus allowlist files kept in GCS (`prism-iam/github-{admin,user}-allowlist.txt`). The server also distributes an "agent tooling" bundle: a standalone `prism-results` CLI (`cli/prism.ts` bundled to `skills/prism-results/scripts/prism.mjs`), a `SKILL.md`, `llms.txt` and `.well-known/agent.json` manifests. AI coding agents use these to submit results without cloning the repo.

In the RHOAI 3.7 EA.1 context this repo is part of the llm-d project checkout set. It is **not** a cluster-deployed RHOAI workload on this branch: there are no Kubernetes manifests, no Konflux Dockerfile, no CRDs and no operator integration. Its only production deployment target is Google Cloud Run (`deploy.sh`, `.github/workflows/deploy-cloud-run.yaml`), with the public instance at `https://prism.llm-d.ai`. Upstream CI also publishes a container image to `ghcr.io/llm-d/<project>`.

## Architectural Analysis

**Shape.** One Node.js process (`tsx server/server.js`) does three jobs: it serves the static SPA, proxies APIs (GIQ, GCS) and implements the Results Store API. State lives entirely in GCS objects (results payloads, IAM allowlists) and in client-side storage such as the browser cache, `localStorage` and URL-encoded share links. Prism has no database. Running replicas share nothing in memory, so Cloud Run scales the service horizontally (`MAX_INSTANCES=100`, `CONCURRENCY=80` in `deploy/prod.env`) and down to zero (`MIN_INSTANCES=0`).

**Identity and authorization.** Prism does not issue its own session tokens. After the OAuth callback it hands the raw GitHub access token (and refresh token) to the browser in the URL fragment (`server/oauth.ts:225-238`). The client then sends it on every privileged call in an `X-Prism-Github-Token` header. On **each** request the server re-validates the token by calling `api.github.com/user` and `/orgs/llm-d/memberships/{user}`, and it fetches both allowlist files from GCS. No caching was observed. This keeps the server stateless, but every authenticated call costs at least three outbound requests, which ties latency and availability to GitHub and GCS and exposes Prism to GitHub API rate limits. Permission is the higher of the org role (`admin` → admin, `member` → user) and the allowlist role (`server/oauth.ts:123-173`).

**Playground Mode.** `RESULTS_STORE_PLAYGROUND_MODE` (truthy values: `1`, `true`, `yes`, `on`) turns every caller into `admin` and bypasses GitHub validation (`server/iam.ts:97-110`). It is the default in `docker-compose.yml`. It is a deliberate dev convenience, but it is also a single-variable switch that disables all authorization. It must never be set on a shared deployment.

**Data-boundary enforcement in the GCS proxy.** The `/api/gcs/*` proxy only reaches buckets listed in `DEFAULT_BUCKETS` / `RESULTS_STORE_BUCKET`. Writes are allowed only under the results-store prefix of the results-store bucket, and the `prism-iam/` prefix gets special handling (`server/server.js:564-620`). Because the server's ADC identity can usually read and write the whole bucket, this application-level check is the only thing standing between users and the data. Restricting what the browser can reach is entirely Prism's job.

**Public exposure and rate limiting.** By default `deploy.sh` deploys with `--allow-unauthenticated`. The `/api` rate limiter is set to 50,000 requests per minute per IP, which the code comment describes as "effectively unlimited" (`server/server.js:59-66`), so in practice requests are not rate-limited. Request bodies may be up to 50 MB (`server/server.js:50-51`). The GIQ proxy logs response snippets and falls back to the **server's** ADC token when the caller sends no bearer token. Any anonymous caller can therefore spend the host project's GIQ quota (`server/server.js:105-187`).

**Vestigial / non-runtime artifacts.** `cmd/main.go` only prints "TODO: implement your service here", and `go.mod` declares no dependencies. Both are left over from the llm-d repo template. `tools/update_arena_scores.py` is an offline data-refresh script (`npm run update-metrics`). `nginx.conf` describes an older static-hosting variant that is no longer used by the Dockerfile. The analyzer reported this repo as a "Go, Python Application Service", but the shipped runtime is Node.js only.

**RHOAI relevance and risk.** Nothing on this branch is productized for RHOAI: there is no Konflux build, no UBI/AIPCC base image (`node:26-alpine`), no FIPS posture and no hermetic RPM lock. The Results Store also depends on GCP (GCS, GIQ, Cloud Run ADC). Running Prism on OpenShift would require a storage abstraction, a different identity provider, and Kubernetes manifests that do not exist yet. `PRISM_LOCAL_DIR` (described in the code as "a mounted PVC", `server/server.js:40-43`) is the only existing hook for a cluster-local data source.
