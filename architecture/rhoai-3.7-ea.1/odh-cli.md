## Purpose

**Short**: A client-side kubectl plugin (`kubectl odh` / `rhai-cli`) that checks RHOAI clusters for upgrade readiness, runs migrations, and helps with diagnostics.

**Detailed**: odh-cli is a Go/Cobra command-line tool that runs outside the cluster, either on an administrator's workstation or as a one-shot container with a mounted kubeconfig. It talks directly to the Kubernetes/OpenShift API server using the caller's kubeconfig credentials. The supported commands are `lint`, `migrate` and `version`. `lint` runs version-aware checks against components, dependencies, platform CRs and workloads, and reports whether an upgrade to a `--target-version` is blocked, needs attention, or is clean. `migrate` runs ordered, phased migration actions (prepare/run/verify) for the RHOAI 2.x → 3.x transition. Examples include ModelMesh/Serverless → RawDeployment KServe, the RHBOK (Kueue) migration, TrustyAI data and metrics moves, workbench auth-model upgrades, the DataSciencePipelines role update, and DSC storage-version migration.

Several more commands are compiled in but hidden while they mature: `api`, `get`, `deps`, `components`, `status`, `logs`, `completion`, `mcp`, `events` and `diagnose`. Of note, `deps` installs operator dependencies through OLM (Subscription/OperatorGroup, or OLMv1 ClusterExtension) using a manifest embedded from odh-gitops. `mcp serve` exposes the CLI's capabilities as Model Context Protocol tools over stdio, or over SSE on localhost. `diagnose` reuses the opendatahub-operator `clusterhealth` and `failureclassifier` packages.

The tool has no in-cluster footprint. It ships no CRDs, operators, Services or kustomize manifests. Its whole "architecture" is client-side: one binary, one outbound API-server connection, and the RBAC of whoever runs it.

## Architectural Analysis

**Client-only, credential-borrowing design.** All cluster access goes through `genericclioptions.ConfigFlags` (cmd/main.go:37). The tool therefore inherits every kubectl authentication mode: kubeconfig, `--token`/`--server`, client certificates, OIDC, and also `--insecure-skip-tls-verify`. It has no ServiceAccount, no RBAC manifests and no long-lived secrets of its own. The effective privilege is whatever the operator running it holds. In practice that means cluster-admin for `migrate` and `deps install`, which create Namespaces, OperatorGroups, Subscriptions and ClusterExtensions, patch InferenceServices and DSC/DSCI, and update RBAC roles.

**Read/write separation by type.** The lint framework gives checks a `client.Reader`-only `Target` (docs/lint/architecture.md), so lint is read-only by construction. Mutation happens only in `migrate` and `deps`. Both have `--dry-run`, and `migrate run` also has an interactive confirmation (`--yes` to skip). Some migrations (e.g. the RHBOK preflight) run a SelfSubjectAccessReview pre-flight to catch missing permissions before making changes (pkg/util/kube/rbac/check.go:60, pkg/migrate/actions/kueue/rhbok/rhbok_preflight.go:137).

**Broad API surface knowledge.** pkg/resources encodes GVRs for more than 30 API groups across the platform: DSC/DSCI, DSPA, KServe, Ray, Kubeflow Training/Trainer, Kueue, TrustyAI, CodeFlare, LlamaStack/OGX, Dashboard, Kuadrant/Authorino, Gateway API, OLM v0/v1, and OpenShift config/image. This makes odh-cli tightly coupled to the release schedule of every component. Each RHOAI release needs matching lint checks and migration actions, which is why the build is tied to a release branch (`3.7.0-ea.1`).

**Secondary transports.** Besides the API server, there are three other egress paths. (1) Pod exec over SPDY, used for TrustyAI data migration and tar copy (pkg/util/exec/exec.go). (2) Direct HTTPS calls to the TrustyAI service OpenShift Route, which forward the user's bearer token and **disable certificate verification** (pkg/migrate/actions/trustyai/metrics/http.go:60-63). (3) The hidden `deps` command can fetch a manifest from `raw.githubusercontent.com/opendatahub-io/odh-gitops` (pkg/deps/fetch.go:16); otherwise it uses the embedded Helm chart data in pkg/deps/data.

**MCP server.** The hidden `mcp serve` command turns the CLI into an agent tool server. The SSE transport binds only to `127.0.0.1:8080` by default (pkg/mcp/server.go:83) and has no authentication. Any local process can therefore call cluster-mutating tools using the user's kubeconfig credentials. The command is hidden today, but this is a risk to review before it is promoted.

**Container packaging.** The Konflux image is built on `ose-cli-rhel9`, so `oc`/`kubectl` come from Red Hat. The upstream Dockerfile instead downloads them with curl from dl.k8s.io and mirror.openshift.com. The Konflux image also sets the system crypto policy to `DEFAULT:PQ` (post-quantum, RHOAIENG-94192). The build is hermetic: RPM and gomod prefetch, with an `rpms.lock.yaml`.
