## Purpose

**Short**: A Kubernetes operator that deploys and manages a separate Kubeflow Pipelines v2 (Data Science Pipelines) stack in each namespace that has a `DataSciencePipelinesApplication` (DSPA) CR. It also installs the shared Argo Workflows assets for the platform.

**Detailed**: The Data Science Pipelines Operator (DSPO) runs as a single controller-manager Deployment (`data-science-pipelines-operator-controller-manager`) in the RHOAI applications namespace (`redhat-ods-applications`). Its main controller, `DSPAReconciler`, watches `DataSciencePipelinesApplication` resources (`datasciencepipelinesapplications.opendatahub.io/v1`). For each DSPA it renders Go-templated manifests from `config/internal/` with manifestival and applies them into that DSPA's namespace. The resulting stack contains:
- the KFP API server, fronted by kube-rbac-proxy sidecars
- the persistence agent
- the scheduled-workflow controller
- a namespace-scoped Argo Workflow controller
- optionally, ML Metadata (MLMD) gRPC + Envoy, MariaDB and MinIO
- per-DSPA RBAC, NetworkPolicies, OpenShift Routes and service-CA-signed TLS secrets

The operator also runs health checks against the configured database and object store, and updates DSPA status from the results.

When a DSPA uses the `kubernetes` pipeline store, the operator also deploys one shared admission webhook (`ds-pipeline-webhook`, which runs the API-server image) into its own namespace. It registers that webhook as the `pipelineversions.pipelines.kubeflow.org` mutating and validating webhook configurations, so Pipeline and PipelineVersion CRs act as the pipeline store.

In RHOAI 3.x there is also a modular-ownership path behind the flag `ENABLEAIPIPELINESMODULECONTROLLER` (`false` in `config/base/params.env`). When the flag is on, two more controllers run:
- `AIPipelinesReconciler` reconciles a cluster-scoped singleton `AIPipelines` CR (`components.platform.opendatahub.io/v1alpha1`). It owns status, monitoring objects (ServiceMonitor, PrometheusRule) and cleanup of the legacy `default-datasciencepipelines` DataSciencePipelines component.
- `AIPipelinesArgoReconciler` manages the shared Argo installation assets: CRDs, aggregate ClusterRoles, and the `argo` SA/Role/ConfigMap.

With this split, DSPO is moving from being an operand of rhods-operator to being a self-managing platform module.

## Architectural Analysis

**Operator-of-operands with template-driven rendering.** DSPO does not build Kubernetes objects in Go. Nearly every child resource is a `.yaml.tmpl` file under `config/internal/`, rendered with `DSPAParams` (`controllers/dspipeline_params.go`) and applied by manifestival with a `dsp-version` label transformer. The Dockerfile copies `config/internal` into the image (`Dockerfile.konflux:49`), so the deployment shape of every DSPA ships inside the operator image. That label is also how the operator limits what it caches. `main.go:213-301` restricts the informers for Services, ServiceAccounts, PVCs, Roles, RoleBindings and Routes to objects carrying `dsp-version`, and Pods to `component=data-science-pipelines`. ConfigMaps and Secrets are cached with their data stripped. All ConfigMap, Secret and MLflow reads go straight to the API server instead of the cache. The comment at `main.go:216-220` records the invariant this depends on: any child resource created outside manifestival would not be seen by the controller.

**Two auth planes per DSPA.** The API server pod exposes three paths:
- **8443**: kube-rbac-proxy, authenticated with a bearer token. Authorization is a SubjectAccessReview on `datasciencepipelinesapplications/api` for that specific DSPA name (`config/internal/apiserver/default/kube-rbac-proxy-config.yaml.tmpl`).
- **8445**: a second kube-rbac-proxy for `/metrics`, authorized on the `datasciencepipelinesapplications/metrics` subresource.
- **8888/8887**: the raw HTTP/gRPC ports, with no login check.

The raw ports are protected only by the per-DSPA NetworkPolicy (`config/internal/common/default/policy.yaml.tmpl`). It admits only the persistence agent, the scheduled-workflow controller, and pods labelled `pipelines.kubeflow.org/v2_component: "true"`. Because that label is the trust boundary, any pod in the namespace that carries it can reach the API server without authentication. Port 8443 is opened to all sources (port-only rule), because the OpenShift router often uses host networking. User authorization is therefore Kubernetes RBAC on the DSPA `api` subresource, granted through the aggregated `aggregate-dspa-admin-edit`/`-view` ClusterRoles. Kubeflow user identity is not involved.

**Ingress model is still OpenShift Route + kube-rbac-proxy.** No HTTPRoute or Gateway API resources are created. Each DSPA gets reencrypt Routes for the API server (`apiserver/route/route.yaml.tmpl`) and for MLMD Envoy (`ml-metadata/route/metadata-envoy.route.yaml.tmpl`). An optional edge Route for MinIO is created only when `objectStorage.enableExternalRoute` is set. The dashboard reaches the API through these Routes or the in-cluster `ml-pipeline:8443` Service.

**Possible defect.** The MLMD Envoy Route sends traffic to Service `ds-pipeline-metadata-envoy-<name>` (`metadata-envoy.route.yaml.tmpl:14`). The Service template creates `ds-pipeline-md-<name>` instead (`metadata-envoy.service.yaml.tmpl:7`). The Route is applied by default (`controllers/mlmd.go:66`), so unless another Service with that name exists, the MLMD Envoy Route has no backend. This was observed in source only and not confirmed on a live cluster.

**TLS posture follows the cluster profile.** Two places read the cluster's `APIServer` TLS profile:
- **Operator webhook/metrics servers.** At startup the operator reads `config.openshift.io/v1 APIServer` and builds `tls.Config` with `openshift/controller-runtime-common` (`tls_profile.go`). If the profile can't be read it falls back to Intermediate, and a SecurityProfileWatcher restarts the operator when the profile or adherence policy changes.
- **kube-rbac-proxy sidecars.** `controllers/tls_resolve.go` turns the profile into `--tls-min-version`/`--tls-cipher-suites` flags. It applies the configured profile only under `StrictAllComponents` adherence (other values fall back to Intermediate) and fails closed when a cipher is unsupported.

The MySQL health check is weaker. `tls=skip-verify` or `preferred` sets `InsecureSkipVerify: true`, and the default is no TLS, with only a logged warning (`controllers/database.go:140-155`).

**FIPS build approach.** The build is `CGO_ENABLED=0 GOFIPS140=v1.0.0 go build -tags no_openssl`, producing a statically linked binary. It relies on the Go native FIPS 140-3 module, not OpenSSL. The runtime base image is `ubi9/ubi-minimal-pqc`. This does not match the check-payload rule that expects dynamically linked CGO/OpenSSL. Whether Konflux has an exception or a newer check-payload policy for this cannot be determined from the repo.

**Managed pipelines are pulled over OCI by the operator.** `controllers/managed_pipelines_fetcher.go` uses `go-containerregistry` `remote.Image` with `authn.DefaultKeychain` to fetch pipeline definitions from container images. `MANAGED_PIPELINES_ALLOWED_REGISTRIES` can restrict the registries; when it is unset, every registry is allowed. This makes the operator pod a direct egress client of container registries, in addition to the Kubernetes API, the DSPA databases and the object stores it health-checks.

**Shared Argo assets vs per-namespace controllers.** Argo CRDs and aggregate ClusterRoles are cluster-wide, but each DSPA runs its own `--namespaced` workflow controller. The README warns that a cluster-scoped Argo install will conflict. `argo-cluster-role` lets the `argo` SA read only the `argo-workflows-agent-ca-certificates` secret, via `resourceNames`.

**Broad operator RBAC.** `manager-role` is very broad. It grants full CRUD on `secrets`, `pods/exec`, Roles/RoleBindings and ClusterRoles/ClusterRoleBindings cluster-wide, plus `ray.io`, `serving.kserve.io`, `workload.codeflare.dev` and `kubeflow.org` resources. Most of these exist so the operator can grant the same permissions to the `pipeline-runner` SA in each DSPA, because Kubernetes forbids granting permissions you do not hold. The operator is therefore a high-value privilege-escalation target.

**Webhook port with no handlers.** The OpenShift overlay NetworkPolicy opens port 9443 for "the admission webhook", and `main.go:261` configures a webhook server there. No webhook handler is registered in the operator process; admission is served by the separate `ds-pipeline-webhook` Deployment on 8443. With no handlers, controller-runtime does not start the 9443 server, so this is leftover configuration rather than an exposed endpoint.

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | kube-rbac-proxy SAR on the named DSPA `api` subresource; per-DSPA SAs and Roles | Kubernetes RBAC / kube-rbac-proxy | Raw ports 8888/8887 have no auth and rely on a pod label (`v2_component=true`) that any namespace user who can create pods can set |
| Data storage | Per-DSPA MariaDB + PVC (or user-supplied external DB) and per-DSPA bucket/credentials | Kubernetes / Application | External DB/S3 sharing across DSPAs is up to the user; MinIO is not production-supported |
| Network traffic | Per-DSPA NetworkPolicies (API server, MLMD, MariaDB, MinIO, workflow controller, persistence agent, scheduled workflow, driver) with ingress and egress rules | Kubernetes NetworkPolicy | Port 8443 open to all sources; external DB and S3 egress allowed by port only |
| Compute & resources | Per-component resource requests/limits from DSPA spec | Kubernetes | No ResourceQuota/LimitRange created by DSPO |
| Configuration & secrets | Per-namespace Secrets/ConfigMaps; operator reads tenant Secrets cluster-wide | Kubernetes | Operator SA has cluster-wide Secret CRUD |
| API scoping | Operator watches all namespaces (label-filtered caches); shared cluster-scoped Argo CRDs; namespaced workflow controllers | Kubernetes / Application | Shared webhook processes PipelineVersions from all namespaces with `failurePolicy: Fail`, so a webhook outage blocks every tenant |
