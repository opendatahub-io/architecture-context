## Purpose

**Short**: Python library that automatically optimizes RAG (Retrieval-Augmented Generation) templates by running hyperparameter optimization over chunking, embedding, retrieval and generation settings, then returns the best-scoring "RAG Pattern".

**Detailed**: ai4rag is the business-logic engine behind RHOAI's AutoRAG capability. A caller supplies a set of knowledge-base documents (as Docling `DoclingDocument` objects), benchmark question/answer data, a search space (chunking method/size/overlap, embedding model, foundation model, retrieval method, top-k, template ID, and so on), optimizer settings, and a vector store configuration. The `AI4RAGExperiment` orchestrator first runs a Models Pre-Selector (MPS) to narrow down candidate foundation and embedding models. It then drives a GAM-based (pyGAM) or random HPO optimizer. Each iteration indexes the corpus into a fresh vector store collection, answers the benchmark questions with a RAG template (`AgenticRAG` via LangChain tool-calling, or `SequentialRAG`), and scores the answers with evaluators (in-house LLM-as-a-judge, RAGAS, unitxt). The result is a ranked set of patterns, each with full configuration, evaluation records and agent conversations.

The library is provider-agnostic. Foundation and embedding models are reached through the stock `openai` SDK, so any OpenAI-compatible endpoint works. OpenShift AI Models-as-a-Service (MaaS) is the integration it ships helpers for. Vector stores are reached directly through vendor clients: remote Milvus/Zilliz, embedded Milvus Lite, PostgreSQL+pgvector, and Neo4j for graph-only RAG. `ai4rag.utils.data` also provides data-stage helpers: S3 document discovery and download, plus Docling-based text extraction with optional OCR (RapidOCR/ONNX Runtime) and Whisper ASR, run across a `spawn` multiprocessing pool.

On the platform, ai4rag is not deployed as a service. The `opendatahub-io/pipelines-components` repository wraps it in `@dsl.component` KFP components. Those components run inside Data Science Pipelines (Argo) pods, handle artifact I/O and Kubernetes secrets, and inject credentials as environment variables. ai4rag picks these up through `from_env()` constructors. From v0.26.0, notebook, leaderboard and starter-kit asset generation moved out of this repo into pipelines-components.

## Architectural Analysis

**Library, not workload.** The repo has no Dockerfile, no Konflux build, no kustomize manifests, no Kubernetes API usage and no listeners. Every network-facing aspect (ports, egress, credentials, RBAC) is determined by the host process, normally a KFP component pod built from pipelines-components. Therefore the architectural surface is *outbound only*: OpenAI-compatible inference (chat completions, embeddings, model listing), S3-compatible object storage, one of four vector store backends, and optionally Hugging Face Hub for pinned OCR/ASR model downloads in connected mode. In RHOAI, the image build, FIPS posture, AIPCC base image and network policy all belong to the consuming pipeline image, not to this repo.

**Pluggable abstractions around a fixed orchestration loop.** `BaseFoundationModel`, `BaseEmbeddingModel`, `BaseVectorStore`, `BaseEvaluator`, `BaseOptimizer` and `BaseEventHandler` define the extension points. `AI4RAGExperiment` composes them in a fixed sequence: pre-selection → HPO search → per-iteration index/generate/evaluate → event publishing. Two event handlers ship with the library. `LocalEventHandler` writes `pattern.json`, `evaluation_results.json` and `conversations.json` to disk. `KFPEventHandler` buffers status changes and patterns in memory so the KFP wrapper can emit them as pipeline artifacts. This keeps KFP types completely out of the library.

**Centralized transport-security policy.** `ai4rag/utils/network.py` is the single trust policy for every externally configured endpoint. Plaintext schemes (`http://`, `bolt://`, `neo4j://`, unencrypted Postgres) are accepted only for loopback or `*.cluster.local` hosts. Every other endpoint must use a verified TLS scheme. The library never falls back to unverified TLS, and Neo4j `+ssc` URIs are rejected. Private-CA support exists per backend: `MAAS_CA_BUNDLE`, plus automatic merging of DSP-mounted `SSL_CERT_DIR/ca.crt` with certifi roots; `AWS_CA_BUNDLE`; and `MILVUS_CA_CERT`, `PGVECTOR_CA_CERT` and `NEO4J_CA_CERT` as inline PEM. Inline PEMs are written to process-lifetime temp files and removed by an `atexit` hook. One consequence: the `cluster.local` exemption means in-cluster traffic to vector stores and MaaS may be plaintext unless the operator configures TLS. Encryption of that traffic then depends on the platform (for example, a service mesh), not on ai4rag.

**Shared-backend safety.** Every collection or table name must carry the `ai4rag` prefix. Names are generated with a `secrets`-based random suffix and capped at 63 characters (the Postgres identifier limit). This prevents the library from creating, reusing or dropping objects it does not own when pointed at a shared database. Combined with per-iteration collections, concurrent experiments can share one Milvus or pgvector instance without namespace collisions. However, this is an application-level guard, not access control. Isolation still relies on the credentials the pipeline supplies.

**Heavy, fast-moving dependency surface.** The core install pulls in LangChain 1.x, openai 2.x, ragas, unitxt, docling-slim, pymilvus with Milvus Lite, neo4j-graphrag, asyncpg and pgvector, scikit-learn and pyGAM. The `text-extraction` extra adds ONNX Runtime, RapidOCR and huggingface-hub. Pins are a mix of exact, compatible-release and open ranges, so reproducibility depends on `uv.lock` and on the consuming image's lock files. Recent commit history is dominated by dependency CVE bumps, which matches this risk. Disconnected installs need pre-staged Docling/RapidOCR artifacts (`DOCLING_ARTIFACTS_PATH`) and a Transformers-format Whisper model (`HF_MODEL_DIR`, supplied by an approved modelcar in AutoRAG product deployments).

**Concurrency model.** Inference fan-out uses a `ThreadPoolExecutor` bounded by `inference_max_threads` (default 10). pgvector uses asyncpg pools bound to their event loop (wrapped by `_LoopBoundPool`). Text extraction uses `spawn`-context multiprocessing so Docling/ONNX state is not shared across workers. The library has no HA or replica concept. Resilience comes from per-iteration exception handling (`FailedIterationError`) and the KFP retry semantics of the caller.
