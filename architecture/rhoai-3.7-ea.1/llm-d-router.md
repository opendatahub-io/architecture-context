## Purpose

**Short**: The llm-d Router (formerly "Inference Scheduler") is the LLM inference entry point: an Endpoint Picker (EPP) that Envoy-compatible proxies call over ext-proc to make load-, KV-cache- and priority-aware routing decisions across an InferencePool of model-server pods, plus a P/D disaggregation sidecar and a disaggregation coordinator.

**Detailed**: The core of the repository is the **Endpoint Picker (EPP)** (`cmd/epp`). A Gateway API implementation (Istio, AgentGateway, GKE) or a standalone Envoy proxy sends each inference request to the EPP over the Envoy External Processing (ext-proc) gRPC API on port 9002. The EPP runs a plugin pipeline configured by an `EndpointPickerConfig` file. The pipeline covers parsing, flow control and queuing, filters, scorers (prefix-cache, KV-cache usage, load, predicted latency), and pickers. The EPP returns the chosen endpoint to the proxy as a header or dynamic metadata. It keeps its view of the pool's pods current with namespace-scoped controller-runtime reconcilers for `Pod`, `InferencePool` (`inference.networking.k8s.io/v1`, owned by Gateway API Inference Extension), `InferenceObjective` and `InferenceModelRewrite` (`llm-d.ai`, now hosted in this repo). It also scrapes vLLM Prometheus metrics, and can optionally subscribe to vLLM KV-cache events over ZMQ.

The **pd-sidecar** (`cmd/pd-sidecar`) is an HTTP reverse proxy that runs next to a decode model server, by default listening on 8000 and forwarding to the model server on 8200. It handles Prefill/Decode (P/D) and Encode/Prefill/Decode (E/P/D) disaggregation. It calls remote prefill and encode workers first, then the local decoder, and coordinates KV-cache and embedding transfer through connectors (NIXL, shared storage, SGLang, Mooncake, MoRI-IO). The **coordinator** (`cmd/coordinator`) is a newer, standalone alternative. It is an OpenAI-compatible HTTP server on 8080 that runs a configurable pipeline of steps (async-broker, render, encode, prefill, decode) against the Inference Gateway. Its async-broker step can hand requests to `llm-d-async` through Redis.

In RHOAI this component is the request-scheduling layer of llm-d distributed inference, which KServe's LLMInferenceService integration deploys. Images and Kubernetes objects are not created by this repo at runtime. The repo ships Helm charts (`llm-d-router-gateway`, `llm-d-router-standalone`, and the `routerlib` library) and CRDs that a platform operator or user installs.

## Architectural Analysis

**Data-plane callout, not a proxy.** The EPP never carries inference payloads to model servers itself. It answers ext-proc callouts (`FULL_DUPLEX_STREAMED` body mode is the only supported mode, per README) with a destination endpoint, so the proxy (Envoy/Istio gateway) remains the L7 data plane. This keeps the EPP horizontally scalable via active-passive leader election (`--ha-enable-leader-election`, Lease in the release namespace) or, in "priority routing", a StatefulSet with a headless Service so Envoy can health-check each replica individually. A non-leader can still populate its datastore (`PopulateNonLeaderDatastore`) for fast failover.

**Pluggable scheduling framework.** Almost all routing intelligence lives under `pkg/epp/framework/plugins/` (request handling, data producers, data layer sources, flow control, scorers/pickers, screeners). Plugins are wired declaratively by an `EndpointPickerConfig` document (`apix/config/v1`, `v1alpha1`) passed via `--config-file`/`--config-text`. The analyzer counts this as an `llm-d.ai` "CRD", but it is a file-format schema with `+kubebuilder:object:root=true` only, and no CRD manifest exists in `config/crd/bases/`. Feature gates and `--allow-experimental-plugins` let operators turn on alpha behavior. Some plugins make outbound calls: a vLLM HTTP tokenizer, the latency-predictor training and prediction servers (`TRAINING_SERVER_URL`/`PREDICTION_SERVER_URL`), Redis/ristretto/LRU caches for the KV-block index, and ZMQ subscribers to model-server KV events on port 5557. Each one widens the EPP's egress surface only when you enable it.

**API consolidation from GIE.** `InferenceObjective` and `InferenceModelRewrite` moved from `sigs.k8s.io/gateway-api-inference-extension` into `llm-d.ai`. The EPP uses discovery (`pkg/epp/server/controller_config.go`) to find out which group/version is served (llm-d.ai v1, v1alpha2, or the legacy GIE group) and degrades gracefully when a CRD is absent. Code comments warn that serving two versions at once without apiserver conversion prunes fields across versions, so migrate objects instead of dual-writing them. `InferencePool` remains an external GIE dependency.

**Namespace-scoped by construction.** The controller-runtime cache is restricted to the pool namespace for Pods, InferenceObjectives and InferenceModelRewrites. The InferencePool cache is further field-selected to the single named pool (`pkg/epp/server/controller_manager.go:92-130`). The Helm charts match this with namespace `Role`s only. The single ClusterRole is optional and exists only for TokenReview/SubjectAccessReview to protect `/metrics`. One EPP instance serves exactly one InferencePool.

**TLS-by-default with weak defaults for verification.** The EPP, sidecar and coordinator all default to `--secure-serving=true`, TLS ≥1.2, and Go `crypto/tls` default ciphers. When no `--cert-path` is given, each generates a 10-year self-signed RSA-4096 certificate with no SANs (`internal/tls/tls.go:58`). As a result, the gateway chart's Istio `DestinationRule` sets `tls.mode: SIMPLE` with `insecureSkipVerify: true` (`config/charts/llm-d-router-gateway/templates/istio.yaml:13-14`). The gateway→EPP hop is encrypted but unauthenticated unless an operator provides certificates and `--client-ca-file` (mTLS). The sidecar likewise supports per-stage `--tls-insecure-skip-verify` for prefill/encode/decode hops, and the coordinator's default gateway address is plain `http://inference-gateway:80`.

**FIPS risk.** Every runtime Dockerfile builds with `CGO_ENABLED=0` (static, pure-Go crypto) onto `gcr.io/distroless/static:nonroot` by default, and this branch has no `.konflux` Dockerfiles. As built here, the images would fail a check-payload FIPS gate. The RHOAI downstream build must override the base image and build flags.

**SSRF surface in the sidecar.** The sidecar takes prefill and encode target hosts from request headers set by the EPP. An InferencePool allowlist (`--enable-ssrf-protection`, which watches the pool and its pods via a client-go dynamic client, `pkg/sidecar/proxy/allowlist.go:94-121`) limits forwarding to pool members, but it is off by default. Deployments that expose the sidecar port to untrusted callers should enable it.

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Per-release ServiceAccount with namespace Roles | Kubernetes | Inference endpoints (ext-proc, sidecar, coordinator) do not authenticate end users; gateway handles that |
| Data storage | In-memory datastore per EPP; optional Redis for async/KV index | Application | A shared Redis would need per-tenant queue routing (`routes` by model/tenant) |
| Network traffic | None shipped (no NetworkPolicy) | — | ext-proc and sidecar ports reachable cluster-wide unless platform adds policies |
| Compute & resources | Flow control / fairness IDs and priority from InferenceObjective | Application | Fairness is within a pool, not across pools |
| Configuration & secrets | Per-namespace ConfigMap/Secrets via Helm | Kubernetes | — |
| API scoping | Namespace-scoped caches; InferencePool cache field-selected by name | Kubernetes / controller-runtime | Optional ClusterRole limited to TokenReview/SAR |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| Model server pool (InferencePool) | Pool / namespace | EPP flow control, priority and fairness |
| Redis (async broker, optional) | Queue per route (model, tenant) | Application routing config |
| Shared Gateway | HTTPRoute per release | Gateway API route matching |
