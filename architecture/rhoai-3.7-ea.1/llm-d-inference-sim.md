## Purpose

**Short**: A lightweight, GPU-free simulator that imitates the vLLM (and, experimentally, SGLang) inference server's OpenAI-compatible HTTP API, vLLM gRPC engine API, Prometheus metrics and KV-cache events, so that llm-d routing, scheduling and observability components can be developed and tested without real models.

**Detailed**: `llm-d-inference-sim` is one Go binary (`cmd/llm-d-inference-sim`). It listens on one TCP port (default 8000) and acts as a stand-in for a vLLM model server. It serves the OpenAI-compatible APIs (`/v1/chat/completions`, `/v1/completions`, `/v1/responses`, `/v1/embeddings`, `/v1/models`), the Anthropic-style `/v1/messages` API, vllm-omni style multimodal outputs (`/v1/audio/speech`, `/v1/images/generations`), and vLLM-specific control endpoints: LoRA load/unload, sleep/wake, render/derender, `/inference/v1/generate`, and the Mooncake `/query` bootstrap endpoint. It does not run a model. Responses are synthesised in "echo" mode (the prompt is returned) or "random" mode (pre-defined sentences or an optional SQLite dataset). Timing follows configurable latency models: time-to-first-token, inter-token latency, prefill and KV-transfer costs, load factors, and named latency profiles. This gives deterministic, cheap and reproducible behaviour for infrastructure tests.

The simulator also reproduces the signals llm-d's control plane depends on. It exports vLLM-compatible Prometheus metrics at `/metrics`, including injectable "fake" metrics. It keeps a simulated prefix KV cache and publishes vLLM-format KV-cache events over ZeroMQ, with an optional ZMQ ROUTER replay endpoint. Both are consumed by the llm-d router / KV-cache-aware scheduler. It can emulate the prefill/decode pods of disaggregated serving, data-parallel ranks (port + rank), failure injection and startup delays. A runtime `/admin/config` API lets tests change latency, failure-injection and fake-metric settings without a restart. Tokenization uses either a built-in simulated tokenizer or an external vLLM "render" service (`vllm launch render`). The sample manifests run that service as a native sidecar on `localhost:8082`.

In RHOAI 3.7 EA.1 the component belongs to the llm-d stack as a test and development utility, not a production inference runtime. It is useful to Distributed Inference / llm-d integration (router, EPP, KV-cache indexer) for CI and demos on clusters without GPUs. The repo also ships `dataset-tool`, a CLI that builds response datasets from HuggingFace, and a small Python ZMQ listener for debugging KV events.

## Architectural Analysis

**Engine-pluggable transport over a shared core.** The code splits into a shared communication/simulation core (`pkg/communication`, `pkg/simulator`, `pkg/endpoint`) and engine "personalities" (`pkg/engine/vllm`, `pkg/engine/sglang`) chosen at startup through `--engine` or an environment variable (`pkg/engine/registry.go`, `cmd/llm-d-inference-sim/main.go`). The `Transport` interface (`pkg/communication/communication.go:77-107`) lets each engine add its own HTTP routes (`BindHTTP`), optionally a gRPC service (`BindGRPC`), engine-specific error envelopes, and response decorations. vLLM adds 17 extra routes and the `VllmEngine` gRPC service. SGLang adds nothing and has no gRPC surface; the binary logs it as experimental and not production-ready. Both engines share flag parsing, configuration validation and the request queue/worker model, so the simulator follows upstream API changes per engine without forking the core.

**Single-port HTTP + gRPC multiplexing.** HTTP (fasthttp + fasthttprouter) and gRPC (`google.golang.org/grpc`) share one plain `tcp4` listener, split by `cmux`: an HTTP/2 preface goes to gRPC and everything else to fasthttp (`pkg/communication/communication.go:123-153`). gRPC server reflection is on (`pkg/communication/grpc.go:133`). The gRPC server is created with no transport credentials. When TLS is enabled (`--ssl-certfile/--ssl-keyfile` or `--self-signed-certs`), only the fasthttp server calls `ServeTLS`. A TLS ClientHello never matches cmux's HTTP/2 matcher, so with TLS on, gRPC in practice becomes unreachable instead of being encrypted. In data-parallel mode, `simulator.Start` runs one simulator per rank, each on `port + rank` (`pkg/common/config.go:834-839`).

**Graceful lifecycle.** Shutdown on SIGTERM/SIGINT (`cmd/signals`) sets a `stopping` flag that rejects new requests. In-flight requests drain for up to 30 s, then HTTP and gRPC stop in a fixed order to avoid a cmux race (`pkg/communication/communication.go:178-200`). `/health/ready` reflects a configurable `--startup-duration`, so model-load delays can be simulated against Kubernetes readiness probes.

**Emulated control-plane signals.** Two ZMQ paths matter for KV-cache-aware routing. (1) A PUB socket publishes msgpack KV events. It binds on wildcard endpoints and dials otherwise, the same heuristic vLLM uses; the default is `tcp://127.0.0.1:5557` (`pkg/common/publisher.go:70-110`, `pkg/engine/vllm/defaults.go:34`). (2) An optional ROUTER replay socket returns buffered event batches on request (`pkg/kvcache/kv_events_replayer.go:134`). Block hashing and event types come from the upstream `github.com/llm-d/llm-d-router` library (`pkg/kvcache/kv_cache.go:31`, `pkg/engine/vllm/kvevents.go:22`). This ties the simulator's wire format to the router version it is tested against (v0.11.0 in `go.mod`). ZMQ traffic is unauthenticated and unencrypted (`go-zeromq/zmq4` with no CURVE).

**Externalised tokenization.** When `--render-url` is set, tokenization calls the vLLM render service over plain HTTP using a default `http.Client` with per-request timeouts (`pkg/tokenizer/render_client.go:51,130`). The kustomize and Helm samples run `vllm/vllm-openai-cpu` as a native init-container sidecar on port 8082. That sidecar, not the simulator, downloads tokenizer files from HuggingFace and may need `HF_TOKEN`. The sample manifests put `HF_TOKEN` in plain env values instead of a Secret reference (`deploy/deployments.yaml:25-27`, `manifests/deployment.yaml:25-27`).

**Risks and observations.**
- **Unauthenticated admin surface.** `POST /admin/config` (`pkg/communication/http.go:106,1257-1266`) changes failure-injection rate/types, latencies, image emission and fake metrics at runtime, with no authentication. The same applies to `/v1/load_lora_adapter`, `/sleep` and `/wake_up`. That is acceptable for a test tool, but the Service should never be exposed outside a trusted test namespace.
- **No Konflux/downstream build artefacts on this branch.** The only Dockerfile builds a static (`CGO_ENABLED=0`) binary on `gcr.io/distroless/static:nonroot`. A commented-out UBI-micro line remains (`Dockerfile:22-25`). There are no `.konflux` Dockerfiles, no RPM/artifact lock files and no FIPS build flags. A downstream RHOAI build would have to supply all of these, or the image would fail check-payload.
- **Python helper image.** `Dockerfile.zmq` installs `pyzmq` and `msgpack` from public PyPI on `python:3.15-slim`. It is a debugging aid, not part of the serving path, and is not built with AIPCC.
- **Analyzer gaps corrected here.** The analyzer reported gRPC as empty and missed `/v1/responses`, `/v1/messages` and `/v1/messages/count_tokens`, which are registered through constants (`pkg/communication/http.go:86-88`). This document includes them.
- **Argument note.** The pipeline passed `--component-name=claude-opus-5-5`, which appears to be a pipeline argument error. The component is named here after the repository (`llm-d-inference-sim`).
