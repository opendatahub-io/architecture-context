## Purpose

**Short**: A controller-runtime module operator that deploys, reconciles, and garbage-collects the MCP Lifecycle Operator (the operand that manages `MCPServer` resources) on behalf of the ODH/RHOAI platform operator.

**Detailed**: The MCP Lifecycle Module Operator follows the ODH modular-architecture pattern (v2 of the "Onboarding Guide for ODH Operator Modules"). The platform operator (opendatahub-operator / rhods-operator) installs this module and creates a single cluster-scoped `MCPLifecycleOperator` custom resource named `default` (`components.platform.opendatahub.io/v1alpha1`). The module reconciles that CR. When `spec.managementState: Managed`, it renders the vendored operand manifests embedded in the binary, applies them with Server-Side Apply, removes stale resources, and reports readiness. When `Removed`, it deletes every resource it owns.

The module contains no MCP business logic. The operand, `mcp-lifecycle-operator` (a fork of `kubernetes-sigs/mcp-lifecycle-operator` in opendatahub-io), owns the `MCPServer` (`mcp.x-k8s.io` v1alpha1 → v1beta1) and `MCPGatewayBinding` APIs. It runs the conversion and validating webhooks for those APIs and creates the per-server workloads, Services, HTTPRoutes, and NetworkPolicies. The module adapts the operand to the platform. It injects the platform-supplied operand image (`RELATED_IMAGE_ODH_MCP_LIFECYCLE_OPERATOR_IMAGE`) and rewrites the namespace to `SYSTEM_NAMESPACE`. It projects the cluster TLS security profile (OpenShift `APIServer`) into operand env vars and forces the operand's NetworkPolicy posture to `restricted`.

The module also handles three operand lifecycle concerns beyond plain deployment. It discovers Kuadrant `MCPGatewayExtension`s and their Gateway listeners and publishes them in its status. It gates the platform-version handshake on MCPServer conversion-webhook health. It drives a `StorageVersionMigration` that rewrites stored `MCPServer` objects to v1beta1.

## Architectural Analysis

**Two-tier operator pattern.** This repository produces one binary (`/manager`), but it places two controllers in the cluster:
- The **module operator** (`mcp-lifecycle-module-operator-controller-manager`, from `config/`), deployed by the platform.
- The **operand** (`mcp-lifecycle-operator-controller-manager`), which the module creates at runtime from `internal/controller/resources/mcp-lifecycle-operator.yaml`.

That vendored YAML (~5.8k lines) is the kustomize rendering of `config/manifests/mcp-lifecycle-operator/overlays/odh`. It is synced from one operand source commit by `tools/source-update` (`make update-operand-manifests`, also run as a daily GitHub Action). `operand-image.json` pins the operand image digest (`quay.io/opendatahub/odh-mcp-lifecycle-operator@sha256:1c7230f1…`, source commit `afd44b9`), and `go.mod` replaces `kubernetes-sigs/mcp-lifecycle-operator` with the same opendatahub-io commit. Upgrading the operand therefore requires a new module build: the module image, manifests, and operand version are released together.

**Rendering pipeline.** `KustomizeProvider.Manifests` (internal/manifests/kustomize.go:51-81) loads the embedded YAML into manifestival and applies these transforms in order:
1. Inject the `platform.opendatahub.io/part-of: mcplifecycleoperator` label.
2. Inject the namespace (`SYSTEM_NAMESPACE`, default `mcp-lifecycle-operator-system`).
3. Rewrite cert-manager `inject-ca-from` annotations and Certificate `dnsNames` to the target namespace.
4. Replace the operand image.
5. Inject `TLS_MIN_VERSION` / `TLS_CIPHER_SUITES` / `TLS_GROUPS` / `PROPAGATE_TLS_ENV_VARS`.
6. Add `--network-policy-default-posture=restricted`.

Resources are applied with the odh-platform-utilities `deploy.Deployer` in SSA mode (field owner `mcplifecycleoperator`, ordered apply, cached). The part-of label drives three things: watch predicates, the label-filtered cache for ClusterRole/ClusterRoleBinding, and garbage collection. If the operand later stops emitting a resource, the module deletes it on the next reconcile.

**Cache and memory discipline.** The manager cache is scoped to `SYSTEM_NAMESPACE` for namespaced types. Cluster-scoped RBAC is label-filtered. CRDs are cached cluster-wide, but `stripCRDSchema` drops their OpenAPI schemas because the gateway CRDs carry no managed label and cannot be label-filtered (cmd/main.go:72-101, 140-158). A documented trap follows from this: any future code that needs a CRD's schema or conversion detail must use an uncached reader. Managed fields are also stripped, and `GOMEMLIMIT` is set in both Deployments.

**Dynamic, optional dependencies.** The module never requires Kuadrant or Gateway API:
- `discoverMCPGateways` checks whether the `mcpgatewayextensions.mcp.kuadrant.io` CRD exists, lists extensions through the dynamic client, and resolves each target Gateway's listeners (gateway_discovery.go:88-150).
- `tryRegisterGatewayWatches` registers dynamic-informer watches once each CRD appears (`sync.Once`), triggered by a CRD watch predicate (mcplifecycleoperator_reconciler.go:731-746).
- The `config.openshift.io/APIServer` watch is registered only on OpenShift.

When discovery fails, the module logs the error and keeps the previous `status.availableMCPGateways` rather than failing the reconcile.

**Upgrade safety for the v1beta1 API promotion.** The operand's `MCPServer` CRD serves v1alpha1 (`storage: false`) and v1beta1 (`storage: true`) through a cert-manager-backed conversion webhook (`/convert`). The module protects the upgrade in three ways:
1. **Conversion gate**: it advances `status.distribution`, which the platform operator uses as the "current version" handshake, only after a paginated cluster-wide LIST of MCPServers at v1beta1 succeeds. That LIST forces conversion of every stored object. Pages are 500 items, with at most 3 restarts on HTTP 410.
2. **Durable marker**: it records the `MCPServerConversionVerified` condition so steady-state reconciles skip the LIST.
3. **Storage migration**: it creates the `mcpservers-v1beta1` StorageVersionMigration. On OpenShift this is served by the kube-storage-version-migrator; elsewhere the condition reports Pending. The migration retries at most 5 times, 1 minute apart, and is excluded from the aggregate Ready condition (storage_migration.go:37-75).

**Platform contract surface.** The platform passes configuration through environment variables only (`SYSTEM_NAMESPACE`, `OPERATOR_VERSION`, `RELATED_IMAGE_*`), plus the optional ConfigMap `odh-mcplifecycleoperator-config` in the pod namespace, which carries `distribution.name` / `distribution.version` / `platformVersion`. A missing ConfigMap means "Standalone". The CR spec deliberately holds only `managementState`. Status reports `phase`, the conditions `Ready`, `ProvisioningSucceeded`, `Degraded`, `MCPLifecycleOperatorAvailable`, `MCPServerConversionVerified`, and `MCPServerStorageMigrated`, plus `releases` (operand `v0.1.0` from `component_metadata.yaml`), `distribution`, and `availableMCPGateways`.

**Risks and observations.**
- **Privilege superset.** The module's ClusterRole must be a superset of every permission the operand holds, because Kubernetes RBAC escalation prevention applies to the ClusterRoles the module creates. It therefore has cluster-wide create/delete on ClusterRoles/ClusterRoleBindings, CRDs, ValidatingWebhookConfigurations, Deployments, NetworkPolicies, HTTPRoutes, `mcpserverregistrations`, and full CRUD plus `deletecollection` on `mcpservers`, and cluster-wide read of Secrets and Pods. A compromise of the module SA is effectively cluster-admin-equivalent through RBAC creation.
- **Stopgap egress.** The ODH overlay adds allow-all egress to the operand NetworkPolicy and marks it STOPGAP until upstream least-privilege egress (DNS + apiserver + mcp-server) is vendored. A kustomize `test` op makes the build fail if the base policy changes (overlays/odh/kustomization.yaml).
- **Self-signed webhook PKI.** Operand webhook and metrics TLS rely on a cert-manager self-signed `Issuer`, so cert-manager is a hard runtime prerequisite for the operand.
- **TLS profile reload.** A change to the cluster TLS profile or adherence policy makes the module cancel its manager context so its process restarts and reloads metrics TLS (cmd/main.go:219-237). The operand picks up new values through a re-rendered Deployment, which causes a rollout.
