## Purpose

**Short**: Kubernetes operator that offers a declarative `MCPServer` API to deploy, verify, network-isolate, and optionally expose Model Context Protocol (MCP) servers through Gateway API or Kuadrant MCP gateways.

**Detailed**: mcp-lifecycle-operator is a Kubernetes SIGs project (`kubernetes-sigs/mcp-lifecycle-operator`) that RHOAI ships downstream as `quay.io/rhoai/odh-mcp-lifecycle-operator-rhel9`. Users create an `MCPServer` (`mcp.x-k8s.io/v1beta1`, the storage version; `v1alpha1` is still served through a conversion webhook). The operator works in one of two modes. In **managed mode** it builds a `Deployment`, a `Service`, and a `NetworkPolicy` from a container image source, server config (port, path, args, env, ConfigMap/Secret/EmptyDir storage mounts), and runtime settings (replicas, strategy, security contexts, probes, resources). In **bring-your-own (BYO) mode** it points `workloadRef`/`serviceRef` at existing Deployments, StatefulSets, DaemonSets, or Services that it does not own.

Once the workload is available, the operator performs a real **MCP protocol handshake** using `modelcontextprotocol/go-sdk`, with optional TLS, a CA bundle Secret, or `insecureSkipVerify`. It copies server info and capabilities (tools, resources, prompts, logging, completions) into `status`, and only publishes `status.address` after the server is `Verified`. An endpoint that answers with an HTTP auth error is still marked Verified, with reason `AuthSkipped`.

If an MCPServer sets `spec.gateway`, the operator creates an owned `MCPGatewayBinding` (`v1alpha1`). Pluggable gateway providers then reconcile that binding. The `httproute` provider creates Gateway API `HTTPRoute`s against a Gateway named in a tenant ConfigMap. The `kuadrant` provider creates `mcp.kuadrant.io` `MCPServerRegistration`s using `MCPGatewayExtension` routing config. Each provider only starts once its CRDs exist in the cluster; a `CustomResourceDefinition` watcher starts it later if they are installed after the operator. Within RHOAI, the opendatahub-operator turns the component on or off through the DataScienceCluster `mcplifecycleoperator` component, which the repo's disruptive tests toggle.

## Architectural Analysis

**Single-binary operator with layered controllers.** `cmd/main.go` starts one controller-runtime manager. It hosts the `MCPServerReconciler`, a log-level ConfigMap reconciler (`cmd/loglevel.go`, which changes log verbosity at runtime from the `mcp-lifecycle-operator-config` ConfigMap), the gateway provider reconcilers (`httproute`, `kuadrant`), and the CRD watcher that starts providers lazily. It also serves the v1alpha1 validating webhook and the v1alpha1↔v1beta1 conversion webhook. Providers register through an `init()`-style registry (`internal/controller/providers/registry.go`), so the core MCPServer controller never takes a hard dependency on Gateway API or Kuadrant CRDs. The operator still runs on clusters without those CRDs, but gateway exposure stays inactive there.

**Verification gates publication.** The design hinges on the `Verified` condition. `status.address` and `ServerReady` are only published after a successful MCP `initialize` handshake from the operator pod to the MCP Service, over HTTP or HTTPS. The operator therefore needs network reachability to every operand. This is why the restricted NetworkPolicy posture (`--network-policy-default-posture=restricted`) has to admit the operator's own pod labels (`networkpolicy_operator_peer.go`) and the gateway peers (`networkpolicy_gateway_peer.go`). If it doesn't, servers never become Ready. The default posture is `open`, and the operator logs a startup warning about it. A handshake is reused while generation, URL, and CA-bundle hash are unchanged, which avoids re-dialing on every reconcile.

**Security posture is secure-by-default in parts and opt-in in others.**
- Secure by default: HTTP/2 is disabled on webhook and metrics servers (Rapid Reset CVEs); metrics use SecureServing with TokenReview/SubjectAccessReview; `--disallow-privileged-security-context=true`; Pod informer cache is label-filtered to `mcp.x-k8s.io` managed pods and stripped of spec/annotations to bound memory and data exposure (`internal/controller/cache.go`).
- Opt-in in the binary, but enabled by the kustomize default: the validating admission webhook (`--enable-webhook`). Without it, image allowlist, digest pinning, max storage mounts, required labels, and securityContext policy are **not** enforced. A `PolicyEnforced=False` condition reports this per MCPServer. Even with the webhook enabled, no policy applies until `--image-allowlist`, `--require-image-digest`, etc. are set; only the privileged-securityContext rule is on by default.
- Tenant-controlled indirection: gateway ConfigMaps (`spec.gateway.configRef`) name the target Gateway namespace or Kuadrant extension namespace. Without `--httproute-allowed-gateway-namespaces` / `--kuadrant-allowed-extension-namespaces`, a tenant can attach routes to another tenant's Gateway. Both allowlists are empty (unrestricted) by default.

**TLS profile propagation.** TLS settings come from the `TLS_MIN_VERSION`, `TLS_CIPHER_SUITES`, and `TLS_GROUPS` env vars (`cmd/tlsconfig.go`). The operator applies them to its own webhook and metrics servers and to handshake clients through a floor (`applyTLSProfileWithFloor`). With `PROPAGATE_TLS_ENV_VARS=true` it also injects them into managed MCP server containers. This matches how the platform distributes the OpenShift cluster TLS profile. Cipher parsing accepts names from `tls.InsecureCipherSuites()`, so an operator-supplied profile could enable weak suites. In strict FIPS runtime mode, Go/OpenSSL still rejects non-approved suites.

**Downstream deltas are thin.** The RHOAI fork adds `Dockerfile.konflux` (FIPS build with `GOEXPERIMENT=strictfipsruntime` and `CGO_ENABLED=1`, and a `DEFAULT:PQ` crypto policy staged from a separate ubi-minimal layer), `Makefile-ocp.mk`, the `config/overlays/odh` overlay, `rpms.lock.yaml`, and Tekton pipelines. The ODH overlay narrows metrics ingress to the `openshift-monitoring` and `openshift-user-workload-monitoring` namespaces. It also adds a **stopgap allow-all egress** for the operator pod, guarded by a JSON-patch `test` op that fails the build once upstream least-privilege egress lands.

**Risks and observations.**
1. `insecureSkipVerify` on `spec.transport.tls` is honored, guarded only by a warning event and log (`mcpserver_controller_tls.go:56-62`).
2. The base ServiceMonitor uses `insecureSkipVerify: true`. The ODH overlay only injects `serverName`.
3. Certificates in the upstream kustomize default come from a cert-manager self-signed `Issuer`. In RHOAI, the opendatahub-operator deploys the component and may provide certificates differently; that is not verifiable from this repo.
4. The manager ClusterRole can read Secrets cluster-wide (`get, list, watch`) so it can resolve CA bundles and validate storage mounts. That is a broad privilege for a multi-tenant operator.

### Tenant Model

| Aspect | Value | Source |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Namespace RBAC via aggregated admin/edit/view roles; operator uses a single cluster-wide SA | Kubernetes | Operator SA can read Secrets/ConfigMaps in all namespaces; resolution of `caBundleSecret`/ConfigMaps is scoped to the MCPServer namespace in code |
| Data storage | Per-MCPServer storage mounts (ConfigMap/Secret/EmptyDir) in the tenant namespace; optional `--max-storage-mounts` | Kubernetes / webhook | No PVC support; limits only enforced when webhook rule configured |
| Network traffic | Per-MCPServer NetworkPolicy with `ingressFrom`/`egressTo`/`dnsEgressPeer`; default posture `open` or `restricted` | Kubernetes (CNI) | Default `open` posture leaves ingress unrestricted; unconfigured egress unmanaged |
| Compute & resources | `spec.runtime.resources`; privileged securityContext rejection | Kubernetes / webhook | No ResourceQuota management; relies on namespace quotas |
| Configuration & secrets | Per-namespace Secrets/ConfigMaps referenced by name | Kubernetes / Application | Gateway config ConfigMap names cross-namespace Gateway/extension; allowlists empty by default |
| API scoping | Cluster-wide watches; Pod cache filtered to operator-managed label | Application | Cross-tenant HTTPRoute attachment possible without `--httproute-allowed-gateway-namespaces` |

| Gateway (Gateway API / Kuadrant MCP gateway) | Gateway namespace / hostname | Optional namespace allowlists; Gateway `allowedRoutes` policy |
