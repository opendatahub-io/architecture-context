## Purpose

**Short**: A lightweight Go HTTP reverse proxy that runs beside a vLLM decode server and orchestrates disaggregated prefill/decode (P/D) inference by first sending each completion request to a remote prefill pod and then forwarding it, with KV-transfer metadata, to the local decoder.

**Detailed**: In llm-d disaggregated serving, the Endpoint Picker (EPP / inference scheduler) selects both a decode pod and a prefill pod for each request. The request is routed through the Gateway to the decode pod, where it lands first on this sidecar (default port 8000). The EPP communicates its prefill choice via the `x-prefiller-host-port` HTTP header (legacy: `x-prefiller-url`). For `POST /v1/chat/completions` and `POST /v1/completions`, the sidecar rewrites the body for a prefill-only pass (`max_tokens=1`, streaming disabled, `kv_transfer_params.do_remote_decode=true` for NIXL v2), sends it to the prefill pod, extracts the returned `kv_transfer_params`, then restores the client's original streaming/token settings and forwards the request to the co-located vLLM on `localhost:<vllm-port>` (default 8001). vLLM's KV connector (NIXL) then pulls the KV cache from the prefiller out-of-band. All other paths, and completion requests without a prefill header, pass straight through to the local decoder.

The sidecar supports three P/D connector protocols: `nixlv2` (default and recommended), and the deprecated `nixl` (v1) and `lmcache`. It optionally provides SSRF protection: when `-enable-ssrf-protection` is set, it watches one named `InferencePool` (`inference.networking.x-k8s.io/v1alpha2`) and the pods matching its selector, and rejects prefill targets whose host/IP is not a current pool member with HTTP 403.

**Deprecation**: The README states that this repository is deprecated and will be archived. The code moved to `llm-d/llm-d-inference-scheduler` under `cmd/pd_sidecar` and `pkg/sidecar` (README.md:3-7). This checkout is a frozen snapshot of the upstream `llm-d` org repo. In RHOAI, the routing sidecar is injected into decode pods by KServe's `LLMInferenceService` controller through the `config-llm-decode-template` presets (overlay 0011). The image RHOAI actually ships is built from the successor repository, not from this one.

## Architectural Analysis

**Design: stateless per-request orchestrator in the data path.** The sidecar holds no persistent state. Each P/D request is handled synchronously in two stages inside one HTTP handler: a blocking prefill call whose response is fully buffered in a `bufferedResponseWriter`, followed by a streaming pass-through to the decoder via `httputil.ReverseProxy`. Prefill reverse-proxy handlers are cached in a 16-entry LRU keyed by host:port (proxy.go:114, 281-316). The server deliberately sets no Read/Write timeouts, because LLM inference can take a very long time. It sets only `ReadHeaderTimeout=30s`, `IdleTimeout=300s`, and `MaxHeaderBytes=1MiB` (proxy.go:169-175). Because the full request body is read into memory and re-marshalled twice (once for prefill, once for decode), memory use grows with prompt size. No request-size limit is set.

**Trust model: the prefill target comes from a request header.** The sidecar sends traffic to whatever host the `x-prefiller-host-port` header names. That header is a built-in SSRF vector. By default (`-enable-ssrf-protection=false`), every target is allowed for backward compatibility (allowlist.go:176-180). This means any client that can reach the sidecar port directly, bypassing the EPP, can make the decode pod send arbitrary POST bodies to any reachable host. The optional allowlist closes this gap with Kubernetes-backed membership: it allows pod IPs and pod names of the selected `InferencePool` members, but not ports (allowlist.go:374-386). So any port on an allowed pod is reachable. Two other details matter:

- The allowlist waits only for the InferencePool informer to sync, not the pod informers (allowlist.go:144). Requests that arrive right after startup may get 403 until the pod cache fills.
- Header values that start with a scheme (e.g. `http://host:port`) fail `net.SplitHostPort` and are compared verbatim (allowlist.go:194-205). This fails closed (403) when SSRF protection is on.

**TLS posture: TLS by default on ingress, plaintext by default on egress.** `-secure-proxy` defaults to `true`, so the listener serves HTTPS (proxy.go:178-202, 220-224). It uses certificates from `-cert-path/tls.{crt,key}` if given. Otherwise it generates an in-memory self-signed RSA-4096 certificate valid for 10 years (tls.go:33-72). Certificates are loaded once at startup with no reload. This matches overlay 0011, which says KServe's workload DestinationRule falls back to `InsecureSkipVerify=true` in P/D mode because "the routing sidecar doesn't yet support watching and auto-reloading certificates". Egress to the prefiller and the decoder is plain HTTP unless `-prefiller-use-tls` / `-decoder-use-tls` are set. When TLS is used, certificate verification can be turned off per hop with `-*-tls-insecure-skip-verify`.

**Connector abstraction.** The connector is chosen once at construction through a function-pointer switch (proxy.go:130-139). Differences between connectors:

- NIXL v2 injects a `kv_transfer_params` object and forwards the prefiller's returned params to the decoder (connector_nixlv2.go:72-155).
- NIXL v1 sets the top-level `do_remote_decode` field instead.
- LMCache only clamps `max_tokens=1` on the prefill and replays the original body to the decoder unchanged (connector_lmcache.go:50-88).

Both NIXL paths add a time-based UUIDv1 `x-request-id` so the prefill and decode legs can be correlated in vLLM.

**Robustness observations (source-level):**
- `main.go` logs but does not return when `proxy.NewProxy` fails. The local variable `proxy` (which shadows the package) is then nil, and `proxy.Start(ctx)` would panic with a nil dereference. The realistic trigger is SSRF protection enabled without in-cluster/kubeconfig credentials (main.go:102-108, allowlist.go:75-88).
- Invalid configuration (bad `-connector`, missing pool namespace/name) is logged via `logger.Info` and the process exits with code 0 (main.go:56-75). A sidecar with `restartPolicy: Always` would then restart-loop silently.
- The LRU cache lookup uses the raw header value, but insertion uses the value after trimming `http://` (proxy.go:282 vs 288/313). Legacy-prefixed headers therefore never hit the cache, so a new reverse proxy (and `http.Transport`) is built for every request.
- README documents the `-connector` default as `nixl`, but the code default is `nixlv2` (main.go:33).

**Repository manifests are scaffolding, not the production deployment.** The `deploy/` kustomization is a generic llm-d project template: a StatefulSet using SA `operator-controller-manager`, a ClusterIP Service on 8080, an edge-terminated OpenShift Route, and a `pods/exec` Role bound to `system:authenticated`. It is internally inconsistent:
- The Service selector `app: ${PROJECT_NAME}-service` does not match the pod label `app: ${PROJECT_NAME}-statefulset`.
- Port 8080 does not match the binary's default listener on 8000.
- An edge Route sends plaintext to a backend that serves TLS by default.

It does not reflect how the sidecar is deployed in RHOAI. The realistic topology is shown in `test/config/nixl/qwen-decoder-pod.yaml`: an init container with `restartPolicy: Always` (a native sidecar) on port 8000, fronting vLLM on 8200 in the same pod. The `ssrf-allowlist-rbac-role.yaml` (pods + inferencepools get/list/watch) is not referenced by the kustomization.

**Supply chain.** The only Dockerfile is upstream-style. It has no Konflux variant and no `.konflux` suffix, builds with `CGO_ENABLED=0` (statically linked pure-Go crypto), and uses unpinned `quay.io/projectquay/golang:1.24` and `ubi9/ubi-micro:latest` base images. As built here, the image would fail the Konflux check-payload FIPS gate. Any RHOAI-shipped image must come from a downstream build of the successor repository.
