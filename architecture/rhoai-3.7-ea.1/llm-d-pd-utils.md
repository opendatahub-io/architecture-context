## Purpose

**Short**: A toolkit of Claude Code Agentic Skills, Python test runners, and NIXL benchmark manifests for validating GPU topology, RDMA/TCP networking, and KV-cache transfer performance in llm-d prefill/decode (P/D) disaggregated deployments.

**Detailed**: llm-d-pd-utils is a support repository for llm-d operators, not a runtime component of the inference data path. It packages two Agentic Skills (`SKILL.md` slash commands for AI coding agents). `/llm-d-preflight-checks` adds a diagnostics script to the start of llm-d model-server pods, just before `vllm serve`. `/llm-d-networking-tests` drives a set of Python scripts that use `kubectl` to find llm-d inference pods by label and run perftest (`ib_*_bw/lat`), iperf3, NCCL/RCCL `all_reduce_perf`, and nixlbench between every pod pair. It then reports bandwidth and latency matrices with outlier flagging and matplotlib plots.

The preflight script (`llm-d-preflight-checks.py`) is the only piece meant to run inside production pods. It is mounted from a ConfigMap and runs as `python3 /preflight/llm-d-preflight-checks.py && vllm serve ...`. It collects environment variables, `nvidia-smi`/`rocm-smi` topology, `lscpu`, and `lspci`. In `pause` mode (`LLMD_PREFLIGHT_CHECKS=pause`) it starts a plain-HTTP server on the vLLM port (default 8000, or `VLLM_INFERENCE_PORT`). The server answers Kubernetes health probes and holds back vLLM startup, so the GPU memory and network stay free for testing. When an operator calls `/exit`, vLLM continues starting.

The repo also includes an older NIXL benchmarking setup: a CUDA 12.5/Ubuntu 24.04 `Dockerfile` that builds MLNX OFED user-space libraries, gdrcopy, UCX v1.18.0, and NIXL 0.1.1, plus a `benchmark.py` that measures NIXL READ/WRITE throughput between two pods. Bare `Pod`/`Service` manifests deploy the benchmark pods (`deployment/nixl_*.yaml`, run by `benchmarks/benchmark_deployment.sh` with `oc`). There are also host-level and non-root NIXL installer scripts. None of this is wired into the RHOAI operator. It is used manually or by an agent on demand.

## Architectural Analysis

**Tooling, not a platform service.** No controller, CRD, operator, or long-lived workload is defined. Every action starts from an operator's workstation through `kubectl exec`, `kubectl debug`, `oc apply`, or optional SSH (`--ssh-hosts`). The scripts therefore run with whatever kubeconfig identity the user has. No ServiceAccount, Role, or ClusterRole is shipped. The user needs `pods/exec`, `pods/ephemeralcontainers`, `pods` get/list, and (for the preflight skill) the rights to create ConfigMaps and patch Deployments in the target namespace.

**Preflight gate pattern.** The preflight design changes the model-server container entrypoint, so the vLLM process only starts after `&&` succeeds. Pause mode reuses the vLLM port so that existing liveness/readiness probes stay green. The handler returns 200 for *any* path (catch-all) and serves `/info`. `/info` includes **every environment variable in the pod** (`os.environ`), which can contain HF tokens, S3 credentials, or other secrets injected into the vLLM container. The server binds `""` (all interfaces), has no auth, and serves plain HTTP. While paused, anyone who can reach the pod IP on port 8000 can read those values and can call `/exit`. The intended access path is `kubectl exec ... curl localhost`, but nothing restricts the server to localhost. This is the most significant security observation in the repo. Note: the docstring and design doc say `/exit` takes GET/POST, but only `do_GET` is implemented (`llm-d-preflight-checks.py:117`). A POST, as described in `docs/preflight-checks-design.md`, would get a 501.

**Mutating test harness.** With `--install-deps`, the networking scripts install software inside running inference pods. This includes apt/dnf/pip packages, curl downloads of `.deb`s, and source builds of perftest, protobuf v21.12, gRPC v1.46.7, etcd-cpp-apiv3, gdrcopy 2.5, UCX 1.18.0, NIXL, OpenMPI, and nccl-tests from GitHub. None of the downloads are checksum-verified. The NCCL/RCCL runner creates an unencrypted RSA-2048 SSH key in the first pod, appends the public key to `authorized_keys` on every pod (including `/root/.ssh`), starts sshd on port 22, and sets `StrictHostKeyChecking=no` for `mpirun`. nixlbench starts an ad-hoc etcd v3.5.21 on plain HTTP 2379/2380 in a pod as its rendezvous service. These changes leave the pods different from their image-defined state. Operators should restart test pods before serving production traffic.

**Repo hygiene and drift.** The `Makefile`, `.golangci.yml`, `hooks/pre-commit`, `.github/workflows/ci-pr-checks.yaml` (Go setup with `go.sum` cache), and `Dockerfile copy` (a kubebuilder `manager` build) all refer to a Go operator (`cmd/main.go`, `api/`, `internal/`, `go.mod`) that does not exist in the repo. They are leftover kubebuilder scaffolding. `Dockerfile copy` cannot build. The real `Dockerfile` pulls `nvcr.io/nvidia/cuda:12.5.1-devel-ubuntu24.04`, a non-Red Hat base, and pins nothing by digest. There is no `.konflux` Dockerfile, no Tekton pipeline, and no lock file. The release workflow publishes to `ghcr.io/llm-d/llm-d-pd-utils`, not quay.io/Red Hat registries. The benchmark manifests use `quay.io/llm-d/llm-d-model-service-dev:latest`. For RHOAI 3.7 EA1 this repo is best seen as an *upstream diagnostic companion* to llm-d (llm-d-inference-scheduler, llm-d routing sidecar, vLLM P/D with NIXL connector), not as a shipped product image.

**Hardware coupling.** The scripts handle both NVIDIA (NVLink/NVSwitch, `nvidia.com/gpu`, `nvidia.com/roce_gdr`) and AMD (Infinity Fabric, `rocm-smi`, RCCL). RoCE benchmark pods need the Multus `multi-nic-network` NetworkAttachmentDefinition and the `IPC_LOCK` capability. The non-RoCE manifests pin nodes to `NVIDIA-A100-SXM4-80GB`.

**Intent**: An optional gate before vLLM starts in llm-d model-server pods. It lets operators inspect the environment and run network tests with full GPU memory available before vLLM loads the model.
