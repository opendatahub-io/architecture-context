RBAC Summary:
- No RBAC resources. NeMo Guardrails is a stateless service with no
  Kubernetes API access requirements.

Service Mesh Configuration:
- No PeerAuthentication or AuthorizationPolicy resources defined.
- Ingress and network policies are expected to be managed by the
  platform operator (RHOAI dashboard or Istio service mesh).

Authentication & Authorization:
- No application-level auth gate on the NeMo Guardrails server itself.
- Bearer token forwarding: X-Authorization header mapped to Authorization
  for outbound LLM requests. Inbound Authorization header is NEVER forwarded
  (intentional security boundary in header_forwarding.py).
- Relies entirely on platform-level network policies and ingress auth.

FIPS Compliance:
- Python runtime; no Go build flags applicable.
- cryptography==46.0.7 delegates to system OpenSSL for FIPS compliance.
- hashlib uses MD5 for cache keys with SHA-256 fallback (FIPS-tolerant).
- TLS: HTTPTLSConfig with verify=True default; custom CA bundle and mTLS supported.

Build & Container:
- Base: AIPCC CPU base image (UBI9, x86_64 + aarch64)
- Multi-stage build with 6 modelcar images for offline ML inference
- Runs as UID 1001 (non-root)
- Offline mode enforced (HF_HUB_OFFLINE=1, TRANSFORMERS_OFFLINE=1)
- No outbound model downloads from within the cluster
