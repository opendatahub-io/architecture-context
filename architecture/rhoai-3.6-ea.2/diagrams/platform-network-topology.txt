NAMESPACES:
- redhat-ods-operator:       Meta-operator (rhods-operator)
- redhat-ods-applications:   All platform operators, controllers, dashboard, API servers
- openshift-ingress:         Gateway infrastructure (data-science-gateway, kube-auth-proxy, praxis-extproc)
- redhat-ods-monitoring:     Prometheus, ServiceMonitors, PodMonitors
- {user-namespaces}:         User workloads (InferenceServices, Notebooks, Pipelines, RayClusters)
- ai-tenants:                MaaS tenant isolation (AITenant CRs)
- odh-ai-gateway-infra:      MaaS infrastructure (maas-api, PostgreSQL)
- rh-ai-gateway (XKS only): Gateway resources on non-OpenShift clusters

GATEWAY ARCHITECTURE:
- data-science-gateway:      Primary platform ingress (Dashboard, Registry, Notebooks, Workbenches)
                             Auth: ext_authz → kube-auth-proxy (OIDC/OAuth) → Lua token forwarding
- maas-default-gateway:      MaaS model inference ingress
                             Auth: praxis-extproc BBR → Kuadrant/Authorino → praxis-extproc IPP
- LLM serving Gateway:       Per-LLMInferenceService (on demand)
                             Auth: Kuadrant AuthPolicy per service
- OpenShift Routes (legacy): Dashboard redirect, observability proxies, model-registry (non-GW)

SERVICE MESH CONFIGURATION:
- Istio revision: openshift-gateway (OCP), default (XKS)
- DestinationRules: Self-signed TLS validation for kube-auth-proxy, praxis-extproc
- EnvoyFilters: ext_authz (data-science-gateway), ExtProc (maas-default-gateway), per-GW (LLM serving)
- VirtualServices (legacy): data-science-pipelines, model-registry, trustyai

RBAC HIGHLIGHTS (Most Privileged):
- kueue-operator:            34 mutating + 36 validating webhooks
- kserve:                    8 mutating + 21 validating + 1 conversion webhook
- odh-model-controller:      10 mutating + 6 validating webhooks (cross-component pod mutation)
- rhods-operator:            Full cluster-scoped CRD lifecycle (DataScienceCluster, DSCInitialization)

CROSS-COMPONENT WEBHOOK TARGETS:
- odh-model-controller mutates KServe Pods and InferenceService/LLMInferenceService CRs
- odh-observability mutates PodMonitor/ServiceMonitor from kserve, kuberay, pipelines
- rhods-operator validates Dashboard HardwareProfile CRs
