RBAC Summary:
- RBAC roles are NOT defined in this repository
- RBAC is configured by the TrustyAI Service Operator deployment
- kube-rbac-proxy performs SubjectAccessReview for API authorization
- eval-hub trusts proxy-set X-User/X-Tenant headers without validation

Authentication & Authorization:
- /api/v1/** routes: X-User + X-Tenant headers required (cluster mode)
  - Headers set by kube-rbac-proxy after Bearer token validation
  - Bypassed in local/development mode (--local flag)
- /api/v1/health: Unauthenticated (probe-friendly)
- /docs, /openapi.yaml: Unauthenticated
- /metrics (port 8081): Unauthenticated, separate port avoids proxy

Multi-Tenancy:
- Tenant boundary: per-namespace (X-Tenant header = namespace name)
- Deployment model: multi-tenant (single instance, multiple tenants)
- Data isolation: Row-level filtering by tenant column in SQL storage
- Provider isolation: System providers visible to all; tenant-created scoped

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Runtime: /proc/sys/crypto/fips_enabled check rejects InsecureSkipVerify
- TLS: MinVersion 1.2, MaxVersion 1.3 on all servers and clients
- Base image: ubi9/ubi-minimal-pqc (post-quantum cryptography variant)
- No non-FIPS crypto risks detected (no MD5, RC4, custom RNG)

Secrets:
- MLflow token: Read from file path (mlflow.token_path config)
- Database credentials: Read from secrets directory (secrets.dir config)
- ServiceAccount token: Kubernetes projected volume (standard mount)
- No secrets defined in this repository; all externally provisioned
