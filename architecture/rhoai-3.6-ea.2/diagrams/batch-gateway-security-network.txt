  - API Group: "" (core)
    - Resources: pods
    - Verbs: get, list, watch
  - API Group: apps
    - Resources: statefulsets
    - Verbs: get, list, watch
- No ClusterRoles defined

Role Binding:
- {release}-batch-gateway-gc-pod-watcher → SA: {release}-batch-gateway-gc

Authentication Model:
- External clients: Authenticated/authorized by Kuadrant/Authorino gateway
- Batch Gateway: Trusts X-MaaS-Username header from gateway (no internal auth)
- Tenant isolation: Application-enforced via tenant ID in all DB queries
- GC to K8s API: ServiceAccount token (automatic in-cluster)
- Observability endpoints: No authentication (separate ports, cluster-internal)

Secrets:
- batch-gateway-secrets (Opaque) - Redis URL, PostgreSQL URL, inference API key,
  S3 secret access key. Provisioned manually. No auto-rotation.
- {release}-batch-gateway-apiserver-tls (kubernetes.io/tls) - TLS cert/key for
  API server. Provisioned by cert-manager (optional) or manually. Auto-rotates
  when cert-manager is enabled.

Pod Security Hardening:
- All pods: non-root user, read-only root filesystem
- All Linux capabilities dropped
- Seccomp profile enabled
- Secrets mounted read-only via projected volumes
- Path traversal prevention via os.OpenInRoot()

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Base image: registry.redhat.io/ubi9/ubi-minimal-pqc (digest-pinned)
- Crypto: stdlib crypto/tls + crypto/x509 (FIPS via OpenSSL with strictfipsruntime)
- TLS: Configurable TLS 1.2+ minimum, configurable cipher suites
- Risk: InsecureSkipVerify available as config option but disabled by default

Multi-Tenancy:
- Tenant identity: X-MaaS-Username header (configurable)
- Isolation: Application-enforced (all DB queries scoped by tenant ID)
- Risk: No network-level or compute-level tenant isolation
- Risk: If gateway misconfigured/bypassed, no internal auth enforcement
