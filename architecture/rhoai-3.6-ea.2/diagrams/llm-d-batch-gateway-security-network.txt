Secrets:
- batch-gateway-secrets (Opaque)
  - Keys: postgresql-url, redis-url, inference-api-key, s3-secret-access-key
  - Provisioned by: Manual (kubectl create secret)
  - Auto-rotate: No
- {apiserver-fullname}-tls (kubernetes.io/tls)
  - Purpose: TLS certificate and key for API server
  - Provisioned by: cert-manager (optional) or manual
  - Auto-rotate: Yes (if cert-manager)

Authentication & Authorization:
- /v1/batches, /v1/files: No built-in auth
  - Tenant ID extracted from X-MaaS-Username header
  - External enforcement expected (gateway-level auth, Envoy ext_authz)
  - LastHeaderValue helper takes LAST header to work with Envoy ext_authz append pattern
- /health, /ready, /metrics: No authentication (separate observability port)
- Kubernetes API: ServiceAccount token (in-cluster, automatic)
- llm-d inference gateway: Optional Bearer token or mTLS client certificate

TLS Configuration:
- API server: Optional TLS 1.2+ with configurable cipher suites and ALPN
- Inference client: Optional TLS 1.2+ with custom CA and mTLS support
- InsecureSkipVerify: Available but defaults to false (testing only)
- No hardcoded weak ciphers; uses Go's tls.CipherSuites() (excludes insecure)

Multi-Tenancy:
- Tenant boundary: HTTP header (X-MaaS-Username)
- No per-tenant resource limits
- Shared PostgreSQL with tenant column filtering (no RLS)
- Shared Redis priority queue across all tenants
- Shared inference gateway across all tenants
- Risk: Misconfigured gateway could allow tenant spoofing via header injection
