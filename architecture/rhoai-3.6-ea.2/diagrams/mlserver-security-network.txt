RBAC Summary:
- MLServer does not define its own RBAC resources
- RBAC is managed by KServe and the platform
- kube-rbac-proxy enforces OpenShift OAuth/ServiceAccount token validation per pod

Service Mesh Configuration:
- Istio sidecar injection on InferenceService pods
- PeerAuthentication: STRICT (mTLS for all pod-to-pod communication)
- No application-level network policies (delegated to platform)

Authentication & Authorization:
- All REST endpoints (/v2/*): kube-rbac-proxy sidecar, OpenShift OAuth token
- All gRPC services (inference.*): kube-rbac-proxy sidecar, OpenShift OAuth token
- /metrics (8082/TCP): No authentication (Prometheus in-cluster scraping)

Security Controls:
- Trusted Runtimes Allowlist: /etc/mlserver/trusted-runtimes.json (baked into image at build time)
  - CPU variant: mlserver_sklearn.SKLearnModel, mlserver_xgboost.XGBoostModel,
                 mlserver_lightgbm.LightGBMModel, mlserver_onnx.OnnxModel
  - CUDA variant: mlserver_onnx.OnnxModel
- Production mode blocks: custom environments (tarball/path), wildcard CORS, sys.path injection
- Container runs as USER 1000 (non-root)

Secrets:
- No application-level secrets defined
- Model artifacts accessed via volume mount (/mnt/models)
- Auth tokens managed by kube-rbac-proxy sidecar (platform-provisioned)

Crypto Notes:
- No application-level TLS (gRPC: add_insecure_port, REST: plain HTTP uvicorn)
- hashlib.sha256 used for environment tarball checksums (FIPS-compliant)
- OTLP exporter uses insecure=True (no TLS for trace export)
- Transport security fully delegated to Istio mTLS and kube-rbac-proxy TLS
