RBAC Summary:
- No RBAC manifests in this repository
- RBAC is managed by the deploying operator (ogx-operator)
- ServiceMonitor uses label selector: app.kubernetes.io/managed-by: ogx-operator

Authentication & Authorization:
- OAuth2 JWT (conditional on AUTH_ISSUER environment variable)
- When AUTH_ISSUER is set:
  - JWKS-based key discovery (AUTH_JWKS_URI)
  - Audience validation (AUTH_AUDIENCE, default: "ogx")
  - TLS verification configurable (AUTH_VERIFY_TLS, default: true)
  - Custom CA bundle via AUTH_TLS_CAFILE
- Access Policy (owner-based resource isolation):
  - Read unowned/system resources: all users (authenticated or not)
  - Create resources: authenticated users only
  - Read/Update/Delete own resources: resource owner only
- When AUTH_ISSUER is NOT set: all API access is unauthenticated

Secrets (18 supported with _FILE variants for Kubernetes secret file mounting):
- VLLM_API_TOKEN (Opaque) - vLLM inference auth
- VLLM_EMBEDDING_API_TOKEN (Opaque) - vLLM embedding auth
- POSTGRES_PASSWORD (Opaque / file-mounted) - PostgreSQL auth
- OPENAI_API_KEY (Opaque) - OpenAI provider auth
- ANTHROPIC_API_KEY (Opaque) - Anthropic provider auth
- AZURE_OPENAI_API_KEY (Opaque) - Azure OpenAI provider auth
- BRAVE_SEARCH_API_KEY (Opaque) - Brave search tool auth
- TAVILY_SEARCH_API_KEY (Opaque) - Tavily search tool auth
- QDRANT_API_KEY (Opaque) - Qdrant vector DB auth
- (additional provider API keys as per distribution/entrypoint.sh)
- rhel-ai-private-index-auth (Opaque) - RHAI package index auth (build-time only)
- git_auth_secret (Opaque) - Git auth for Tekton pipeline (build-time only)
- Auto-Rotate: No (manual provisioning)

Secret File Resolution Pattern:
- For each supported secret, a _FILE suffix env var can be set
- e.g., POSTGRES_PASSWORD_FILE=/run/secrets/pg-password
- Entrypoint reads file content into the base env var
- Reduces exposure through /proc/1/environ

Multi-Tenancy Notes:
- Tenant boundary: per-user (via OAuth2 JWT identity)
- Data isolation: Application-level owner filtering (NOT database-level)
- Shared PostgreSQL tables with owner field filtering
- No per-tenant network isolation or resource quotas
- Provider credentials (API keys) shared across all users
