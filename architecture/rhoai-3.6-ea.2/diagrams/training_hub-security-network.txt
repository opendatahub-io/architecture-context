RBAC Summary:
- Training Hub does NOT define any RBAC roles or bindings
- RBAC is delegated to the orchestrating platform (Kubeflow, Trainer Operator)
- Pod ServiceAccount and permissions are managed by the platform

Secrets (Environment Variables):
- OPENAI_API_KEY (Bearer token) - LLM API calls for GEPA, not persisted by Training Hub
- WANDB_API_KEY (Bearer token) - W&B experiment tracking, optional
- AWS_ACCESS_KEY_ID (IAM credential) - S3 checkpoint storage, optional
- AWS_SECRET_ACCESS_KEY (IAM credential) - S3 checkpoint storage, optional
- AWS_ENDPOINT_URL_S3 (URL) - Custom S3 endpoint, optional
- HF_TOKEN (Bearer token) - HuggingFace Hub access, optional
- TRAINING_HUB_CHECKPOINT_UPLOAD_URI (URI) - Set by Training Hub at runtime for torchrun workers

Security Notes:
- No inbound network services (library, not a server)
- All TLS delegated to underlying HTTP clients (requests, aiohttp, litellm, fsspec)
- No direct cryptographic operations; FIPS compliance inherited from container base image
- litellm versions 1.82.7-1.82.8 excluded due to TeamPCP supply chain attack
- _resolve_dotted_path in CLI imports arbitrary modules via importlib — YAML config is a trust boundary
- checkpoint_manager._is_safe_remote_name validates remote names against path traversal
- Callbacks serialized via inspect.getsource — no closure captures allowed across torchrun boundary

Multi-Tenancy:
- Single-tenant: each training job runs as isolated process/pod
- Tenant isolation delegated to platform (namespace RBAC, ResourceQuota, NetworkPolicy)
