Authentication Flow:
  REST API path:
    Client → Bearer Token → odh-gateway → kube-rbac-proxy
    kube-rbac-proxy → TokenReview (validates token)
    kube-rbac-proxy → SAR (X-Tenant-Id → namespace scope)
    kube-rbac-proxy → rest-service (X-Remote-User, X-Tenant-Id headers)

  Flight gRPC path:
    Client → Bearer Token → flight-service AuthLayer
    AuthLayer → TokenReview (validates token)
    AuthLayer → SAR (X-Tenant-Id → namespace scope)
    AuthLayer → FlightService handler

Multi-Tenancy:
- Tenant boundary: per-namespace (X-Tenant-Id header → Kubernetes namespace)
- Data isolation: Shared PostgreSQL with row-level tenant_id filtering (application-enforced)
- No database-level isolation; compromised pod has access to all tenants' metadata
- No per-tenant resource quotas on shared services
