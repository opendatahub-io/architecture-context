NetworkPolicy Summary:
- maas-authorino-networkpolicy:
  - Allows: Authorino → maas-api (internal callback for API key validation)
- maas-gateway-networkpolicy:
  - Allows: Gateway → maas-api (forwarded API requests)
- maas-deployment-ns-networkpolicy:
  - Allows: Controller namespace → maas-api (management traffic)
- cleanup-ingress-networkpolicy:
  - Allows: CronJob → maas-api (internal cleanup endpoint)

RBAC Summary:
- ClusterRole: maas-controller-role
  - ServiceAccount: maas-controller
  - Scope: Cluster-wide (manages resources across tenant namespaces,
            gateway namespace, infrastructure namespace)
  - Key permissions:
    - maas.opendatahub.io/* : Full CRUD on all MaaS CRDs
    - gateway.networking.k8s.io/gateways,httproutes : Full CRUD

FIPS Compliance:
- All three services built with GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Runtime base: UBI 9 (ubi-minimal-pqc for API/controller, ubi-minimal for discovery)
- TLS: OpenShift TLS Security Profile integration (Intermediate default, TLS 1.2 min)
- Crypto: stdlib crypto/tls via OpenSSL through strictfipsruntime
- JWT: golang-jwt (delegates to stdlib crypto)

Security-Critical Dependencies:
- Kuadrant 1.4.2+ required for Authorization header stripping
- Authorino prevents credential forwarding to model backends
- Client-supplied X-MaaS-* headers are rejected at AuthPolicy level
