INGRESS:
  Not applicable — PPE is a library, not a network service.
  The host process (e.g., Praxis proxy) handles all inbound connections.
  PPE is invoked via in-process function calls.

AUTHENTICATION & AUTHORIZATION:
  PPE authenticates callers of mediated operations, not callers of PPE itself.

  Identity Resolution:
  - JWT identity: verified tokens via identity/jwt plugin
    → RS256/RS384/RS512, ES256/ES384, EdDSA, HS256/HS384/HS512
    → Issuer, audience, expiration, not-before validated
    → JWKS keys fetched from IdP at runtime
  - API-Key identity: SHA-256 indexed lookup via identity/api-key plugin
  - Workload SVID: caller workload identity

  Identity Slots (per request):
  - subject: end-user identity
  - client: calling application identity
  - caller_workload: infrastructure-level identity

  Authorization:
  - APL (Authorization Policy Language) rules per route
  - Three PDP backends: Cedar, CEL, OPA (semantically equivalent via diff tests)
  - Route matching: entity name (tool, resource, prompt, llm, http)
  - Missing route: implicit deny (unidentified_request) — fail-safe

  Assertion Pipeline:
  - Client-supplied target headers removed before trusted values rendered
  - Secret headers redacted in plugin and audit views

CRYPTO:
  TLS:
  - Library: rustls 0.23 with ring provider
  - Minimum version: TLS 1.2 (retained for enterprise IdP compatibility)
  - Trust store: WebPKI roots (webpki-roots crate), no system trust store
  - No custom cipher suites (rustls defaults)

  JWT:
  - Library: jsonwebtoken v11 with aws-lc-rs backend
  - Chosen to avoid RUSTSEC-2023-0071 (rsa crate)
  - Algorithms: RS256/RS384/RS512, ES256/ES384, EdDSA, HS256/HS384/HS512

  Content Integrity:
  - sha2 0.11 for HMAC-SHA256 content provenance digests
  - hmac 0.13 for keyed digests (audit, OAuth cache)
  - getrandom 0.4 for per-process HMAC secret generation

  Credential Handling:
  - All secret material wrapped in Zeroizing<String>
  - Inline literals refused unless allow_insecure_literal: true

  FIPS Status:
  - ring is NOT a FIPS-validated provider
  - aws-lc-rs supports FIPS mode but activation depends on host build config
  - PPE is a library — FIPS compliance depends on host build environment

BUILD HERMETICITY:
  - Cargo.lock pins all transitive dependencies
  - deny.toml: crates.io registry only (allow-git = [])
  - cargo deny: advisories, licenses, bans, sources
  - No Dockerfile (library crate, published to crates.io)
