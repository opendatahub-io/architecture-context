RBAC Summary:
- No default ClusterRoles or ClusterRoleBindings created by default
- RBAC is opt-in via Helm chart values (namespace_rbac, cluster_rbac, extraRules)
- ServiceAccount created by Helm chart (serviceAccount.create: true)
- Authorization enforced at application level by mlflow-kubernetes-plugins
  - Per-request Kubernetes bearer token validation
  - Workspace isolation via X-MLFLOW-WORKSPACE header (mapped to K8s namespace)

Network Policy:
- NetworkPolicy available via Helm chart (disabled by default)
- Without NetworkPolicy: any pod in the cluster can reach MLflow on port 5000
- Recommendation: Enable NetworkPolicy to restrict ingress to authorized clients

Secrets:
- OPENAI_API_KEY (env var) - OpenAI API access (AI Gateway, when enabled)
- ANTHROPIC_API_KEY (env var) - Anthropic API access (AI Gateway, when enabled)
- AWS_SECRET_ACCESS_KEY (env var) - AWS S3/Bedrock credentials
- AWS_SESSION_TOKEN (env var) - AWS temporary session credentials
- AZURE_STORAGE_SAS_TOKEN (env var) - Azure Blob SAS token
- JUPYTERHUB_API_TOKEN (env var) - JupyterHub API access
- DATABRICKS_TOKEN (env var) - Databricks workspace authentication
- DATABRICKS_PASSWORD (env var) - Databricks basic auth
- mlflow-tls (kubernetes.io/tls) - TLS certificate for HTTPS, cert-manager, rotation configurable
- Additional LLM provider keys (Cohere, Mistral, TogetherAI, Groq, DeepSeek, xAI, OpenRouter) when AI Gateway enabled

FIPS Compliance:
- Base image: UBI9-minimal-pqc (post-quantum-cryptography variant)
- Python crypto: Uses system OpenSSL via cryptography >=43.0.0 (FIPS-validated on RHEL)
- Risk: hashlib.md5 used for dataset fingerprinting (non-security); may error in strict FIPS mode
- TLS: Delegates to Python ssl module (system OpenSSL)

Multi-Tenancy:
- Tenant boundary: Kubernetes namespace = MLflow workspace
- Model: Single server, multiple workspaces
- Isolation: Application-enforced query scoping (not K8s namespace isolation of data)
- Gap: Shared database; LLM provider API keys shared across tenants
