RBAC Summary:
- No RBAC manifests defined in repository
- Component relies on ServiceAccount configured by eval-hub and KFP
- Kubernetes API access: GET ConfigMaps, GET/LIST Secrets
  (managed by eval-hub service, not this component)

Secrets Summary:
- model-auth (Kubernetes Secret, volume-mounted)
  Purpose: API keys for TARGET, JUDGE, ATTACKER, EVALUATOR, SDG, TRANSLATION roles
  Provisioned by: User / Operator
  Auto-Rotate: No

- Data Connection Secret (Kubernetes Secret, env injection)
  Fields: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_S3_ENDPOINT,
          AWS_S3_BUCKET, AWS_DEFAULT_REGION
  Provisioned by: User / Operator
  Auto-Rotate: No

- API_KEY (Environment variable)
  Purpose: Generic fallback API key for model authentication
  Auto-Rotate: No

- KFP_AUTH_TOKEN (Environment variable)
  Purpose: Kubeflow Pipelines authentication token
  Auto-Rotate: No

Security Controls:
- API key redaction: All API keys are redacted from config files before
  upload to S3 or OCI storage (pipeline_steps.py)
- TLS verification: Configurable per-connection (KFP_VERIFY_SSL,
  KFP_SSL_CA_CERT); defaults to enabled
- Pod-internal communication: eval-hub sidecar uses localhost HTTP only
- AutomountServiceAccountToken=false: Supported in evalhub ≥ 0.4.4
  (sidecar proxy model)
- No NetworkPolicy: Relies on cluster-level network isolation

FIPS Compliance:
- Base image: AIPCC CPU base (RHEL 9.8 with system OpenSSL)
- No direct cryptographic operations in source code
- Crypto delegated to: cryptography==50.0.1, pyjwt==2.14.0, boto3, grpcio
- Risk: ~200 transitive dependencies must use system OpenSSL for FIPS
- Hermetic build: Hermeto prefetch from RHAI index (FIPS-compatible builds)
