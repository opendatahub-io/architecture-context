RBAC Summary:
- OVMS does not define its own RBAC resources
- RBAC is managed by KServe and the platform operator
- No ClusterRoles, Roles, or RoleBindings defined

Secrets:
- API key file (Opaque) - Bearer token auth for REST API, manual provisioning, no auto-rotate
- HF token (Opaque) - HuggingFace Hub auth for model downloads, manual provisioning, no auto-rotate
- mTLS certificates (kubernetes.io/tls) - Mutual TLS for nginx-mtls-auth sidecar, manual/cert-manager

Authentication Summary:
- REST /v3/* (OpenAI-compatible): Bearer token (optional, --api_key_file or API_KEY env)
- REST /v1/* (TFS): Bearer token (optional)
- REST /v2/* (KServe): Health probes bypass auth; inference endpoints use optional Bearer
- REST /metrics: Unauthenticated (always accessible)
- gRPC services: No authentication (InsecureServerCredentials)

FIPS Notes:
- gRPC uses InsecureServerCredentials — no TLS on gRPC transport
- HTTP server (Drogon) does not configure TLS — relies on external infrastructure
- Uses OpenSSL MD5 for file checksumming (non-FIPS hash, non-security use)
- Base image is UBI 9 minimal PQC (post-quantum cryptography variant)
- Outbound HTTPS uses system CA bundle with CURLOPT_SSL_OPTIONS

Security Considerations:
- No server-side TLS: both HTTP and gRPC transports are plaintext
- Must rely on service mesh (Istio), network policies, or nginx-mtls-auth sidecar
- API key auth is optional and single-key (not per-tenant)
- gRPC has zero authentication — network-level isolation required
- Runs as non-root user ovms (UID 5000)
