RBAC Summary:
  No Kubernetes RBAC roles — Praxis AI runs as a standalone service,
  not a Kubernetes operator.

Authentication & Authorization:
  - Proxy listener: Configurable per filter chain
    - Bearer token injection (credential_inject filter)
    - mTLS peer identity trust (peer_identity_trust filter)
    - Basic Auth (basic_auth filter)
    - Azure AD token acquisition (azure_ad filter)
    - GCP Application Default Credentials (gcp_adc filter)
    - AWS SigV4 signing (aws_sigv4_sign filter)
    - Identity header guard (strips client-supplied internal headers)
  - Admin API: No auth — bound to loopback (127.0.0.1:9901)

Secrets:
  - Provider API keys (Opaque) — upstream provider auth, operator-managed
  - TLS certificates (kubernetes.io/tls) — listener TLS, cert-manager/manual, hot-reload
  - PostgreSQL credentials (Opaque) — response store auth, manual

FIPS Compliance:
  - FIPS 140-3 build on UBI 9 (CMVP #4857)
  - All crypto via system OpenSSL (openssl-fips-provider-so)
  - PRAXIS_REQUIRE_FIPS=1 enforces FIPS at startup
  - FIPS build strips non-OpenSSL features (policy-engine, store-postgres,
    store-sqlite, conversations, compact, mcp-tools)
  - cargo-auditable embeds crate SBOM for Red Hat scanner compatibility

Multi-Tenancy:
  - Tenant boundary: Per-filter-chain config; per-user via state_owner filter
  - Data isolation: Row-level in PostgreSQL via StateOwner identity
  - Network isolation: Per-listener and per-chain routing
  - Risk: Single database with row-level isolation, not schema-per-tenant
  - Risk: Header-based scoping relies on identity_header_guard filter
