RBAC Summary:
- No RBAC manifests defined in repository
- RBAC expected to be managed by deploying operator

Service Mesh Configuration:
- No NetworkPolicy or AuthorizationPolicy defined in repository
- mTLS to orchestrator is optional, auto-detected from certificate presence
- Service mesh expected to provide ingress and network policies externally

Secrets:
- /etc/tls/private/tls.crt (File mount - TLS cert) - Client cert for mTLS, provisioned by service mesh / cert-manager
- /etc/tls/private/tls.key (File mount - TLS key) - Private key for mTLS, provisioned by service mesh / cert-manager
- /etc/tls/ca/service-ca.crt (File mount - CA cert) - Custom CA trust, provisioned by OpenShift service CA

Authentication Notes:
- Gateway performs NO local authentication or authorization
- Authorization header is forwarded transparently to orchestrator
- x-forwarded-* headers are forwarded transparently
- All auth enforcement is delegated to upstream (orchestrator / platform)

FIPS Notes:
- Rust binary dynamically links against system OpenSSL
- Base image: ubi9/ubi-minimal-pqc (post-quantum cryptography variant, digest-pinned)
- TLS cipher suites and protocol versions inherited from system crypto-policies (RHEL 9 defaults)
- No explicit FIPS mode validation in application code
