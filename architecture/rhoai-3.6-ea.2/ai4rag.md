## Purpose

**Short**: Provider-agnostic optimization engine that initializes RAG templates with optimal hyperparameters, supporting multiple vector store backends and LLM providers via the OpenAI SDK.

**Detailed**: ai4rag is an IBM-developed Python library that automates the optimization of Retrieval-Augmented Generation (RAG) pipelines. Given a set of documents, benchmark questions, and a search space of RAG configuration parameters (chunking strategy, embedding model, retrieval settings), ai4rag runs hyperparameter optimization using Generalized Additive Models (GAMs) to find the configuration that maximizes evaluation metrics such as answer correctness, faithfulness, and context correctness.

The library is provider-agnostic: it reaches foundation and embedding models through the standard OpenAI Python SDK, making it compatible with any OpenAI-compatible endpoint including OpenShift AI Models-as-a-Service (MaaS), vLLM, TGI, and Ollama. Vector storage is handled through pluggable backends including remote Milvus, embedded Milvus Lite, PostgreSQL/pgvector, and Neo4j for graph-based retrieval. Document processing uses docling for structure-aware chunking.

In addition to the core optimization library, ai4rag bundles an agentic RAG starter kit -- a FastAPI service template that exposes an OpenAI-compatible `/v1/responses` API backed by a LangChain agent with query rewriting and multi-step retrieval capabilities. This starter kit can be deployed as a standalone service on OpenShift via OpenShell sandboxes.

## Architectural Analysis

ai4rag's architecture follows a clean separation between experiment orchestration and RAG pipeline components. The `AI4RAGExperiment` class serves as the top-level orchestrator, driving the GAM-based hyperparameter optimizer through a search space of RAG configurations. Each trial instantiates a complete RAG pipeline -- chunking strategy, embedding model, vector store, retriever, and RAG template -- evaluates it against benchmark data using Unitxt/RAGAS metrics, and feeds the score back to the optimizer.

A deliberate design decision is the strict URL trust policy implemented in `ai4rag.utils.network`. The `ensure_safe_url()` function enforces HTTPS for any endpoint outside localhost or `*.cluster.local`, with no option to disable certificate verification. This policy is applied uniformly across all external connections: MaaS, S3, Milvus, Neo4j, and pgvector. Custom CA bundles are supported everywhere, but there is no "skip verification" escape hatch. The recent removal of the unverified-TLS fallback in v0.21.0 (commit 120e455) strengthened this posture.

The agentic RAG starter kit (`assets_generator/starter_kit_templates/agentic_rag/`) is both a bundled template that ai4rag generates as an output artifact (after optimization finds optimal parameters) and an independently deployable FastAPI service. The starter kit includes its own `auth_wrapper.py` that authenticates requests via K8s TokenReview API, but the core `main.py` FastAPI app has no built-in authentication -- the auth layer is designed to be composed on top as ASGI middleware.

The vector store abstraction uses frozen dataclasses with `from_env()` constructors and explicit provider discriminators (`"milvus"`, `"milvus_lite"`, `"pgvector"`, `"neo4j"`), ensuring connection credentials stay in environment variables and never leak into generated artifacts like pattern notebooks. The explicit separation between `MilvusConfig` (remote server) and `MilvusLiteConfig` (embedded local) prevents a common footgun where a misconfigured server URI silently falls back to a throwaway local database.
