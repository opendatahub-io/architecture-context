## Purpose

**Short**: A module operator that manages the lifecycle of the MCP Lifecycle Operator as a deployable component within the ODH/RHOAI platform.

**Detailed**: The mcp-lifecycle-module-operator follows the ODH modular architecture pattern for integrating optional platform components. The ODH platform operator creates a cluster-scoped `MCPLifecycleOperator` custom resource (singleton named `default`), and this module operator watches that CR and reconciles it by deploying (or tearing down) the MCP Lifecycle Operator operand into the platform namespace.

The reconciliation loop renders pre-embedded kustomize manifests for the operand, applies them via Server-Side Apply (SSA), performs garbage collection of stale resources, and monitors operand Deployment readiness. It propagates the cluster's TLS profile (fetched from the OpenShift APIServer CR, or Intermediate defaults on non-OpenShift clusters) into the operand as environment variables. The CR's `managementState` field (`Managed` or `Removed`) governs whether the operand is deployed or deleted.

The module operator itself exposes no user-facing APIs or services; its sole function is lifecycle management of the operand. The operand — the MCP Lifecycle Operator — is the component that actually manages `MCPServer` resources (the Model Context Protocol server abstraction).

## Architectural Analysis

This operator implements a two-tier deployment pattern characteristic of the ODH modular architecture. The module operator is a thin lifecycle wrapper: it embeds pre-rendered kustomize manifests for the operand (stored in `internal/controller/resources/mcp-lifecycle-operator.yaml`), transforms them at runtime (namespace injection, image replacement, TLS env var injection, platform labels), and applies them using the `odh-platform-utilities` SSA deployer. This design means the module operator never directly manages MCPServer resources itself — that responsibility belongs entirely to the deployed operand.

A notable design choice is the label-scoped cache configuration. Cluster-scoped resources (ClusterRole, ClusterRoleBinding, CRD) are filtered by the `platform.opendatahub.io/part-of: mcplifecycleoperator` label in the informer cache, avoiding the cost of caching every such object across the cluster. Namespace-scoped resources are limited to the operator's own namespace via `DefaultNamespaces`. This is a resource-conscious approach appropriate for a component that only manages a small, well-defined set of resources.

The TLS configuration handling is dynamic: on OpenShift clusters, it reads the cluster-wide APIServer TLS profile (supporting Custom, Old, Intermediate, and Modern profiles), converts OpenSSL cipher suite names to IANA names via `library-go`, and injects the result as environment variables (`TLS_MIN_VERSION`, `TLS_CIPHER_SUITES`, `TLS_GROUPS`, `PROPAGATE_TLS_ENV_VARS`) into the operand's Deployment. On non-OpenShift clusters, it falls back to the Intermediate profile (TLS 1.2+). This ensures the operand inherits the cluster's crypto policy without the module operator needing to understand the operand's internal TLS implementation.

Metrics are explicitly disabled on the module operator itself (`Metrics.BindAddress: "0"`), delegating metrics exposure to the operand, which binds a metrics service on port 8443 with TokenReview/SubjectAccessReview authentication.
