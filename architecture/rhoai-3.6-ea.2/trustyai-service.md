## Purpose

**Short**: Python-based REST service providing real-time AI model fairness monitoring, drift detection, and explainability metrics for KServe-served models on OpenShift AI.

**Detailed**: TrustyAI Service is a FastAPI-based responsible AI platform service that consumes inference data from KServe and ModelMesh inference servers, stores it in either PVC-backed HDF5 files or MariaDB, and computes fairness and drift metrics on a configurable schedule. Computed metrics are published to Prometheus for monitoring and alerting.

The service exposes a comprehensive REST API organized into five functional groups: inference data consumption (KServe v2 and CloudEvent payloads), fairness metrics (Statistical Parity Difference, Disparate Impact Ratio), drift detection (Kolmogorov-Smirnov, Jensen-Shannon divergence, Maximum Mean Discrepancy, Compare Means, and streaming KS tests), model explainability (LIME, SHAP, counterfactuals, PDP — disabled by default), and service metadata/health management. Endpoints are gated by a feature flag system (`TRUSTYAI_ENABLE_*` environment variables) allowing selective activation.

The architecture uses a dual-port Hypercorn ASGI server design: a loopback-only HTTP port (8081) behind kube-rbac-proxy for authenticated access, an optional direct HTTPS port (4443) with TLS certificate support, and a separate health port (8080) for Kubernetes probes and KServe consumer endpoints. TLS configuration honors the system crypto policy through a custom `PolicyAwareConfig` that delegates cipher and version selection to the operating system rather than hardcoding them.

## Architectural Analysis

TrustyAI Service represents a complete rewrite from its Java/Quarkus predecessor into a Python-native implementation built on the FastAPI/Hypercorn stack. This transition brings the service's scientific computing capabilities into Python's ecosystem (scikit-learn, scipy, numpy, pandas, polars) where they are most naturally expressed, while maintaining wire-format compatibility with the existing KServe v2 inference protocol.

The dual-port architecture is a deliberate security pattern: the main API port (8081) binds to loopback only, requiring kube-rbac-proxy as an authentication sidecar to reach it from the network. This separation means the service itself carries no authentication middleware — all auth enforcement is delegated to the proxy. The health port (8080) binds to all interfaces for kubelet probe access and also serves as the KServe consumer ingress, accepting both flat ModelMesh payloads and CloudEvent-wrapped inference logs.

The storage abstraction layer (`StorageInterface`) cleanly separates the service from its persistence backend. PVC storage uses HDF5 via h5py for columnar inference data, while MariaDB support is gated behind an optional dependency (`pip install trustyai-service[mariadb]`). The MariaDB backend includes TLS support with CA certificate validation when `DATABASE_TLS_CA_CERT` is set, and a migration subsystem (`PVCToDBMigrator`) for transitioning from PVC to database storage. Database credentials are sourced from environment variables, supporting both direct (`DATABASE_*`) and operator-style (`QUARKUS_DATASOURCE_*`) naming for backward compatibility with the Java predecessor.

The Prometheus scheduling system runs as an asyncio background task, periodically computing all registered metric requests and publishing results via `prometheus-client`. This pattern avoids per-request computation overhead by amortizing expensive statistical calculations across a configurable interval (default 30 seconds, ISO-8601 duration supported).

A notable design choice is the `PolicyAwareConfig` TLS wrapper that creates SSL contexts using Python's `ssl.create_default_context()` instead of Hypercorn's built-in defaults, which hardcode cipher lists and TLS versions. This ensures the service automatically honors the cluster's `update-crypto-policies` configuration (Old, Intermediate, Modern, Custom profiles) and FIPS crypto policy without requiring application-level configuration changes.
