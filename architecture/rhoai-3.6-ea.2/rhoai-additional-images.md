## Purpose

**Short**: Maintains digest-pinned RHOAI container image references that must be available for disconnected mirroring but are not referenced directly by platform manifests.

**Detailed**: rhoai-additional-images is a data-only repository that maintains a curated YAML list of digest-pinned container image references (`rhoai-disconnected-images.yaml`). These images are required for fully-functional RHOAI deployments in air-gapped/disconnected environments but are not referenced by the standard RHOAI operator manifests or kustomize overlays.

The image list spans several RHOAI subsystems: FMS HF Tuning (fine-tuning), Ray (distributed compute with CUDA and ROCm accelerator variants), training runtime images (CPU/CUDA/ROCm), notebook workbench images (Jupyter, Code Server, TrustYAI, LLM Compressor variants), and data science pipeline runtime images. The repository tracks both current (N-1) and deprecated (N-x) image versions across multiple Python versions (py311, py312) and accelerator backends (CPU, CUDA, ROCm).

This repository produces no deployable artifacts itself. Its value is as a declarative inventory consumed by image mirroring tooling (such as `oc mirror` or Quay mirror registries) to ensure completeness of disconnected installations.

## Architectural Analysis

The repository is a release and supply-chain input for disconnected RHOAI installations. Its architecture is intentionally declarative: a single YAML list maps image identities to immutable digests, and comments provide human-readable tag/version context that is not encoded in the digest reference itself.

The catalog spans multiple accelerator families (CPU, NVIDIA CUDA with variants cu121/cu128/cu129, and AMD ROCm with variants rocm61/rocm64) across notebooks, pipelines, and training runtimes. All 47 images are pinned by SHA256 digest rather than floating tags, ensuring reproducible mirroring.

The repository carries a generational structure: images are grouped by RHOAI release version (3.4, 3.5/2025-1, 2025-2) with explicit lifecycle annotations (N-1 as "additional", N-x as "deprecated"). This tiered retention means disconnected environments can access workbench images from prior releases during upgrade transitions, which is critical for user notebook continuity.

The image registries span two domains: `quay.io/modh/` (upstream community images for Ray and FMS HF tuning) and `registry.redhat.io/rhoai/` (productized Red Hat images for notebooks, pipelines, and training runtimes). This dual-registry pattern means disconnected mirroring must target both registries. Because the repository has no lockfile, image-signature policy, or deployment manifest, digest pinning provides reproducibility of referenced content but does not by itself establish provenance, vulnerability status, or FIPS compliance of the referenced images.
