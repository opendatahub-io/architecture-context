## Purpose

**Short**: Kubernetes operator that provides a declarative API to deploy, manage, and safely roll out Model Context Protocol (MCP) servers with production-grade lifecycle automation.

**Detailed**: The mcp-lifecycle-operator is a Kubernetes-native operator originating from the kubernetes-sigs community (SIG-sponsored) that manages the full lifecycle of MCP servers. Given an `MCPServer` custom resource, the operator provisions a complete runtime stack: a Deployment running the user-specified MCP server container image, a Service with configurable session affinity for stateful or stateless MCP servers, and a NetworkPolicy restricting ingress to the MCP server's port. The operator performs an active MCP protocol handshake against deployed servers to verify they speak the MCP protocol, recording discovered capabilities (tools, resources, prompts, logging, completions) in the CR status.

The operator supports TLS-secured operator-to-server communication with custom CA bundles, environment-driven TLS profile configuration (minimum TLS version, cipher suites) that can be propagated to managed server containers, and config-hash-based rolling updates when referenced ConfigMaps or Secrets change. RBAC aggregation roles (admin/editor/viewer) integrate with the Kubernetes built-in role hierarchy, giving namespace administrators immediate access to MCPServer resources.

## Architectural Analysis

The mcp-lifecycle-operator follows a clean single-controller design built on controller-runtime v0.24.1 and Kubernetes API v0.36.2. The `MCPServerReconciler` is the sole controller, watching `MCPServer` CRs as its primary resource and owning three child resource types: Deployment, Service, and NetworkPolicy. It also watches ConfigMap and Secret metadata via secondary informers with field indexes, enabling config-hash-based rolling updates when referenced configuration data changes without requiring a spec change.

The reconciliation loop has a well-defined pipeline: validation → deployment reconciliation → service reconciliation → network policy reconciliation → MCP handshake verification. Each phase emits dedicated Prometheus metrics (`mcpserver_reconcile_phase_duration_seconds`) and failure counters, providing operational visibility. The handshake phase uses the official `modelcontextprotocol/go-sdk` (v1.6.1) to perform a real MCP initialize handshake against the deployed server, verifying protocol compliance and extracting server identity and capabilities into the CR status. This handshake includes exponential backoff (10s → 2min, max 10 retries) and treats HTTP 401/403 as reachable (the server exists but requires auth).

Ownership validation prevents the operator from silently overwriting resources managed by other controllers while supporting orphan adoption for seamless MCPServer recreation. The operator uses server-side apply (SSA) with field ownership for status updates, following current best practices for multi-actor status management.

A notable design decision is the TLS profile propagation feature: the operator reads `TLS_MIN_VERSION` and `TLS_CIPHER_SUITES` from its own environment, validates them against Go's known cipher suite registry, and optionally injects these as environment variables into managed MCP server containers via the `PROPAGATE_TLS_ENV_VARS` flag. This enables consistent TLS policy across the operator and its managed workloads without coupling MCP server implementations to a specific TLS configuration mechanism.
