## Purpose

**Short**: OpenShift operator that deploys, configures, and lifecycle-manages the Kueue workload queueing system for fair-share scheduling and resource quota management of batch and AI/ML jobs.

**Detailed**: The kueue-operator is an OpenShift-native operator that manages the upstream Kueue project as an operand on OpenShift clusters. Kueue is a Kubernetes-native job queueing system that implements fair-share scheduling, preemption policies, and resource quota management across batch workloads, AI/ML training jobs, and other compute-intensive tasks.

The operator follows a two-tier architecture: the operator pod (`openshift-kueue-operator`) watches a singleton `Kueue` custom resource and reconciles the operand deployment (`kueue-controller-manager`) along with all supporting infrastructure — CRDs, RBAC, webhook configurations, certificates, network policies, and monitoring resources. The operator dynamically configures which workload integrations (Job, RayJob, PyTorchJob, etc.) are enabled based on the CR spec, and applies an opt-in namespace model via the `kueue.openshift.io/managed=true` label for webhook enforcement.

The component depends on cert-manager for TLS certificate provisioning (webhook and metrics serving certificates) and integrates with Prometheus for metrics collection. It supports a broad set of workload frameworks including Kubernetes Jobs, JobSets, Kubeflow training operators (PyTorch, TensorFlow, MPI, XGBoost, Paddle), Ray (clusters and jobs), CodeFlare AppWrappers, and LeaderWorkerSets.

## Architectural Analysis

The kueue-operator exhibits a clean separation between the operator control plane and operand data plane. The operator itself is built on the `openshift/library-go` controller framework rather than the more common Operator SDK or controller-runtime pattern, which gives it access to OpenShift-specific machinery for managing operand lifecycle, log-level control, and resource application with caching.

The reconciliation logic in `TargetConfigReconciler` is monolithic — a single `sync()` method manages all operand resources in sequence: cert-manager issuers/certificates, ConfigMaps, ServiceAccounts, Roles, RoleBindings, ClusterRoles, ClusterRoleBindings, CRDs, the operand Deployment, Services, webhooks, network policies, and monitoring resources. All operand manifests are embedded via Go `bindata` rather than sourced from the filesystem, ensuring the operator binary is self-contained.

A notable design decision is the opt-in webhook model. Unlike upstream Kueue which intercepts all matching resources cluster-wide, the OpenShift operator applies a namespace selector (`kueue.openshift.io/managed=true`) to all non-cluster-scoped webhooks. This prevents interference with system namespaces and gives cluster administrators explicit control over which namespaces Kueue manages. The operator dynamically filters the webhook configurations based on which integration frameworks are enabled in the CR spec.

The operator manages cert-manager Certificate CRs for both webhook serving and metrics TLS, with explicit CA injection annotations on webhook configurations. This creates a hard dependency on cert-manager — the `sync()` function actively checks for cert-manager API availability and fails if not found.

The operand image reference is passed via the `RELATED_IMAGE_OPERAND_IMAGE` environment variable on the operator deployment, following OLM conventions for disconnected environments. The operator deployment runs with 2 replicas and `system-cluster-critical` priority, while the operand runs with 1 replica.
