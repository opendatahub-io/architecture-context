## Purpose

**Short**: A Kubernetes module operator that manages AI Gateway sub-components (Models as a Service, Batch Gateway, AI Gateway Controller) for the OpenDataHub/RHOAI platform.

**Detailed**: ai-gateway-operator is a module operator that runs under opendatahub-operator's modular architecture. Rather than directly implementing inference or gateway logic, it acts as an orchestrator that deploys and manages three vendored sub-component bundles via kustomize: the **maas-controller** (Models as a Service), the **batch-gateway-operator** (LLM-d batch inference), and the **ai-gateway-controller** (gateway routing with praxis-extproc). Each sub-component's lifecycle is controlled through the cluster-scoped `AIGateway` custom resource's `spec.batchGateway.managementState` and `spec.modelsAsAService.managementState` fields, which accept `Managed` or `Removed` values.

The operator implements a sophisticated teardown protocol for the MaaS sub-component: when transitioning from Managed to Removed, it annotates the maas-controller Deployment with a teardown-requested signal, then keeps the manifests installed until maas-controller self-reports teardown completion via a separate annotation. This graceful shutdown window ensures tenant resources are cleaned up before the controller is removed. The operator also manages a cross-namespace RBAC setup for secret migration between the applications namespace and an infrastructure namespace, supporting database credential portability across MaaS lifecycle transitions.

## Architectural Analysis

ai-gateway-operator follows the ODH modular operator pattern, importing `opendatahub-operator/v2` packages for its reconciler framework, action pipeline, kustomize rendering, garbage collection, and status reporting. The reconciler is built using a declarative action chain: initialize → ensureInfraSecretMigrationRBAC → upgradeIfNeeded → releases → kustomize render → annotateResource → migrateSelector → deploy → deployments status → reportSubModuleStatus → overWriteCondition → reportStatus → GC.

A key design decision is the consolidation of three formerly independent operators into a single module operator. The vendored manifest bundles (under `config/manifests/`) are fetched via `make get-manifests` from pinned upstream commits, making ai-gateway-operator the single deployment vehicle. Image references flow through `RELATED_IMAGE_*` environment variables (OLM disconnected-install pattern) mapped to kustomize `params.env` substitutions.

The TLS configuration is notable: the operator reads the cluster's OpenShift TLS profile via `config.openshift.io/APIServer` and adherence policy, then applies the resulting cipher configuration to its metrics server. A `SecurityProfileWatcher` triggers a graceful restart when the cluster TLS profile changes, ensuring the operator always serves metrics with the cluster-mandated cipher suite. On non-OpenShift clusters, it falls back to the Intermediate profile.

The platform upgrade handshake is bidirectional: the platform operator writes `platformVersion` to a ConfigMap (`odh-aigateway-config`), and after successful reconciliation the module echoes that version into `status.releases` so the platform can verify alignment. A `withPreservedPlatformRelease` wrapper prevents failed reconcile passes from wiping the handshake entry.
