## Purpose

**Short**: High-performance model inference server built on OpenVINO, serving AI models via REST and gRPC with OpenAI-compatible, KServe, and TensorFlow Serving APIs.

**Detailed**: OpenVINO Model Server (OVMS) is a C++-based inference serving system developed by Intel that hosts machine learning models and exposes them over standard network protocols. It supports multiple model frameworks including OpenVINO IR, ONNX, TensorFlow, PaddlePaddle, and PyTorch, and provides inference through three API families: OpenAI-compatible generative APIs (chat completions, responses, embeddings, rerank, image generation, audio), KServe v2 inference protocol, and TensorFlow Serving v1. The server is optimized for deployment on Intel architectures and supports both CPU and GPU acceleration.

Within RHOAI, OVMS functions as a KServe-compatible serving runtime that can be deployed via ServingRuntime/ClusterServingRuntime custom resources. It integrates with the KServe model serving stack to provide model inference as part of the OpenShift AI platform. The server includes features for continuous batching of LLM requests, DAG pipeline scheduling, MediaPipe graph execution, model management with versioning, and Prometheus-compatible metrics. It supports model storage from local filesystems, cloud object storage (Azure, S3, GCS), and HuggingFace Hub.

## Architectural Analysis

OVMS follows a modular server architecture built around a central `Server` class that orchestrates several independently initialized modules: `GRPCServerModule`, `HTTPServerModule`, `ServableManagerModule`, `MetricModule`, and optional `PythonInterpreterModule`. Each module has its own lifecycle (start/shutdown) and the server coordinates their initialization order.

The HTTP layer uses the Drogon web framework with separate thread pools for unary and streaming workloads. Streaming endpoints (completions, responses, audio transcriptions) are dispatched to a dedicated MediaPipe thread pool to avoid blocking Drogon's internal listener threads. The gRPC layer uses standard gRPC C++ with `InsecureServerCredentials` — the server itself does not implement TLS, relying on external infrastructure (service mesh, nginx sidecar) for transport encryption. An nginx-mTLS sidecar pattern is provided in `extras/nginx-mtls-auth/` for deployments requiring mutual TLS.

The generative AI stack is organized around MediaPipe graph-based calculators. Each inference modality (text generation, embeddings, rerank, image generation, speech-to-text, text-to-speech) is implemented as a MediaPipe calculator that processes requests through a graph pipeline. The text generation pipeline uses OpenVINO GenAI's continuous batching for efficient LLM inference. The server supports OpenAI-compatible API key authentication via the `--api_key_file` flag or `API_KEY` environment variable, enforced through Bearer token validation on the HTTP handler.

The build system uses Bazel for the core C++ server with CMake for OpenVINO/OpenCV/Azure SDK dependencies. The Konflux Dockerfile is a complex multi-stage build that can either build OpenVINO from source (`ov_use_binary=0`) or use a pre-built binary package, then compiles the OVMS server and creates a minimal release image based on UBI 9 minimal PQC.
