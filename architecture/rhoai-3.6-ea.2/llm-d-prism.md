## Purpose

**Short**: Prism is an interactive performance-analysis dashboard for distributed AI inference systems that unifies benchmark data from cloud storage, public repositories, and local experiments into a single analysis experience.

**Detailed**: Prism helps AI Platform Engineers and ML Engineers choose, configure, and optimize inference infrastructure by consolidating benchmark data from disparate sources—Google Cloud Storage (GCS), Google Inference Quality API (GIQ), AWS S3, Google Drive/Sheets, and locally-uploaded reports—into an interactive web dashboard. The application uses a Backend-for-Frontend (BFF) architecture with a Node.js/Express backend that proxies requests to cloud APIs (injecting Application Default Credentials) and a React 19 frontend built with Vite that presents scatter charts, comparison dashboards, regression analysis, prefix-cache offloading analysis, and prefill/decode disaggregation views.

The platform includes a "Results Store" subsystem: a full CRUD lifecycle for benchmark submissions backed by GCS objects with custom metadata contexts. Users authenticate via GitHub OAuth, and an IAM layer (GCS-backed allowlists plus GitHub organization membership) gates write/review/promote operations. A "Playground Mode" bypass enables unauthenticated local development. The primary production deployment target is Google Cloud Run, deployed via GitHub Actions with Workload Identity Federation.

## Architectural Analysis

Prism's architecture is a classic single-process BFF: one Express server simultaneously serves the compiled React SPA assets and exposes `/api/*` endpoints that proxy authenticated requests to Google Cloud Storage, Google's GKE Recommender API (GIQ), and manage the Results Store lifecycle. The multi-stage Dockerfile separates development (live-reload via `npm run dev`), build (Vite compilation), and production (Express serving built assets) concerns cleanly.

The authentication model layers three identity sources: GitHub OAuth tokens (resolved via the GitHub API), `llm-d` GitHub organization membership roles, and GCS-backed allowlists (`prism-iam/github-admin-allowlist.txt` and `prism-iam/github-user-allowlist.txt`). The highest permission from any source wins. This is pragmatic but means the IAM boundary depends entirely on GCS bucket ACLs and GitHub token validation—there is no independent identity provider or session store.

The GCS proxy (`/api/gcs/*`) implements fine-grained authorization: read operations filter results-store items by ownership and approval state; write operations are restricted to the configured results-store prefix and to admin users; IAM allowlist files are protected from modification. The Results Store workflow follows a state machine (`staged → submitted_pending_processing → submitted_pending_review → public/promoted/rejected/unlisted`) with server-generated UUIDs replacing client-supplied IDs to prevent collisions.

The Go `cmd/main.go` is a placeholder stub (`TODO: implement your service here`) with an empty `internal/` package. The `go.mod` declares `go 1.24.0` but there are no Go dependencies or meaningful Go code. The Python code (`tools/update_arena_scores.py`) is a dev-time script that scrapes LMSYS Arena leaderboard scores and writes them to a static JSON file; it is not part of the runtime application.

A notable architectural gap is that the production Dockerfile does not include a Konflux variant, and there are no kustomize manifests, lock files (no `package-lock.json` in the commit, only referenced in `.gitignore`), or Kubernetes deployment resources in the repository. The sole deployment mechanism is `deploy.sh` targeting Google Cloud Run, which limits portability to OpenShift/Kubernetes environments without additional packaging work.
