## Purpose

**Short**: End-to-end benchmarking automation for LLM inference on the llm-d stack, providing declarative lifecycle management across standup, execution, analysis, and teardown phases.

**Detailed**: llm-d-benchmark is a comprehensive benchmarking framework for evaluating LLM inference performance on the llm-d stack. It provides a single CLI (`llmdbenchmark`) that orchestrates the full lifecycle of benchmark experiments: infrastructure standup (deploying vLLM, routing, and supporting services), workload execution via pluggable harnesses (inference-perf, guidellm, vllm-benchmark, aiperf, lm-eval, inferencemax), post-run analysis and reporting, and teardown of deployed resources.

The tool supports multiple deployment styles (standalone, modelservice, Fast Model Actuation, kustomize) across multiple cloud environments (GKE, CoreWeave, OpenShift) and accelerator types (NVIDIA GPU, CPU, s390x). Configuration is driven by a declarative merge chain: base defaults, specification templates (Jinja2), scenarios, and CLI overrides, producing a deterministic workspace that captures all rendered manifests and results. Built-in Design of Experiments (DoE) support automates parameter sweeps across infrastructure and workload dimensions.

A companion sub-component, `llm-d-stack-discovery`, provides Kubernetes cluster introspection — given an OpenAI-compatible endpoint URL, it traces the full request path (Route/Gateway → HTTPRoute → InferencePool → vLLM Pods) and produces a structured configuration snapshot in multiple output formats including the Benchmark Report v0.2 schema.

## Architectural Analysis

The repository follows a pipeline architecture with well-separated phases. The core `llmdbenchmark` CLI parses specifications through a Jinja2-based template engine, resolving cluster-specific values (accelerator labels, version pins) via runtime introspection. Each phase (standup, smoketest, run, teardown) decomposes into numbered steps executed by a step-executor framework, enabling predictable ordering and dry-run previews.

The harness image (`build/Dockerfile`) bundles multiple benchmark harnesses (inference-perf, vllm-benchmark, guidellm, aiperf, lm-eval, inferencemax) into a single container deployed as a StatefulSet. The harness pod is the execution environment for all benchmark workloads; it receives configuration through environment variables and rendered workspace files. The entry-point script (`llm-d-benchmark.sh`) dispatches to the selected harness, runs load generation with retry logic, and executes post-run analysis.

Results storage is abstracted through a `StorageClient` interface with two backends: direct GCS access via `google-cloud-storage` and a fallback proxy client (`GCSProxyClient`) that routes through a Prism proxy at `prism.llm-d.ai`. This dual-path design allows result upload from environments without direct GCS credentials.

A notable architectural pattern is the multi-model support: the `multi-model-optimized-baseline` scenario deploys N model stacks behind a single shared Gateway, each with its own EPP + InferencePool + Deployment, behind one HTTPRoute with N backendRefs. This enables comparative benchmarking across models under identical infrastructure conditions.

The `benchmark-report` sub-package defines a standard data format (Benchmark Report v0.2) for LLM inference benchmark results, with Pydantic schemas, validators, and converters. This enables structured comparison across runs and environments.

The security surface is minimal — the benchmark tool requires cluster admin privileges for infra installation but can operate with namespace-level admin for workload deployment. RBAC is scoped to `pods/exec` on the benchmark StatefulSet pod, granted to all authenticated users, which represents a broad access pattern suitable for development and CI but not production multi-tenant clusters.
