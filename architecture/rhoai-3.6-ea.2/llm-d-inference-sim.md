## Purpose

**Short**: Lightweight inference server simulator that mimics vLLM and SGLang API surfaces for GPU-free development, testing, and benchmarking of LLM infrastructure.

**Detailed**: llm-d-inference-sim is a configurable simulator designed as a drop-in replacement for real LLM inference servers (vLLM and SGLang). It exposes OpenAI-compatible HTTP endpoints and vLLM-compatible gRPC services on the same port using connection multiplexing (cmux), enabling developers to test routing, scheduling, KV cache locality, and control-plane logic without requiring GPU resources or running actual models.

The simulator implements a pluggable engine architecture where each engine backend (vLLM, SGLang) supplies its own HTTP routes, gRPC service registration, error framing, metrics, and KV event wire format. The core simulation engine handles response generation (echo or random mode), latency modeling (TTFT, inter-token latency, load-dependent scaling, disaggregated prefill), LoRA adapter lifecycle management, tokenization (HuggingFace or simulated), and failure injection. KV cache events are published over ZMQ using msgpack serialization, matching the real vLLM event format consumed by the llm-d-router for cache-aware scheduling.

The project is a multi-vendor open-source effort under the llm-d organization, designed to accelerate infrastructure development across the llm-d ecosystem. It is used for integration testing with the llm-d-router, EPP (Endpoint Picker), and other llm-d control-plane components.

## Architectural Analysis

The simulator's architecture separates transport, engine-specific behavior, and core simulation logic into distinct layers. The `pkg/communication` package owns the HTTP and gRPC servers and uses cmux to multiplex both protocols on a single TCP listener. The `pkg/engine` package defines the `Engine` interface, and concrete implementations in `pkg/engine/vllm` and `pkg/engine/sglang` supply engine-specific routes, gRPC services, error framing, metrics adapters, and KV event encoders. This design allows the same simulator binary to simulate different inference backends via a `--engine` flag.

The request processing pipeline flows from the transport layer through a shared `Processor` interface into the simulator core (`pkg/simulator`), which manages a worker queue, applies latency calculations, generates responses using the configured mode (echo or random), and emits per-token results on a channel. The transport layer consumes this channel to produce either streamed SSE responses or buffered JSON bodies.

KV cache simulation is a notable subsystem: `pkg/kvcache` maintains a block cache that tracks simulated memory usage and emits engine-independent events. The engine's `EventEncoder` serializes these events into the target engine's wire format (msgpack), and a `Publisher` (`pkg/common/publisher.go`) sends them over ZMQ PUB sockets. This mirrors real vLLM's KV event publishing and allows the llm-d-router to exercise its cache-aware scheduling logic against simulated data.

TLS is optional and well-structured: when enabled, the server configures a minimum of TLS 1.2 with an explicit AEAD-only cipher suite list and supports automatic certificate reloading via filesystem watching (`pkg/common/certs.go`). The TLS implementation follows the pattern used in the Gateway API Inference Extension project.

A secondary Python container image (`Dockerfile.zmq`) provides a standalone ZMQ listener for debugging KV cache events. A separate Go CLI tool (`cmd/dataset-tool`) creates and manages SQLite-backed response datasets for the simulator's random mode.

_The simulator is built as a statically linked Go binary without CGO, using the distroless base image. This means it uses Go's pure-Go crypto implementation rather than OpenSSL. While TLS configuration is well-structured (TLS 1.2+, AEAD-only ciphers), the static binary would not pass the Konflux check-payload FIPS gate which requires dynamic linking and OpenSSL. This is architecturally appropriate for a testing/simulation tool that does not run in production inference paths. No Konflux Dockerfiles exist on this branch._
