## Purpose

**Short**: KServe provides a Kubernetes-native model serving platform that manages the lifecycle of inference services, including model deployment, autoscaling, request routing, and local model caching across heterogeneous accelerator hardware.

**Detailed**: KServe is the core model serving component of Red Hat OpenShift AI, implementing a declarative API for deploying and managing machine learning models on Kubernetes. It operates through multiple coordinated controllers: the primary InferenceService controller manages model deployment via pluggable serving runtimes (vLLM, OpenVINO, MLServer, HuggingFace, etc.), while the LLMInferenceService controller provides a higher-level abstraction optimized for large language models with features like Gateway API integration, KEDA-based autoscaling, and multi-node inference via LeaderWorkerSets.

The component follows a fork-based development model from the upstream kserve/kserve project, using Go build tags (`//go:build distro`) to cleanly separate ODH/OpenShift-specific behavior from upstream code. The kserve-module controller acts as the lifecycle operator, deploying and configuring the other controllers and their associated resources (CRDs, webhooks, RBAC, serving runtimes, NetworkPolicies) based on the platform's Kserve CR. The platform ships a comprehensive catalog of ClusterServingRuntime definitions covering multiple accelerators (NVIDIA CUDA, AMD ROCm, Intel Gaudi, IBM Spyre) and CPU variants.

A Python SDK and storage library complement the Go controllers, providing a model server framework (FastAPI/gRPC-based), client library, and storage initialization layer that supports S3, GCS, Azure Blob, HDFS, OCI registries, and HuggingFace Hub as model sources.

## Architectural Analysis

KServe's architecture is defined by a layered controller hierarchy. At the top, the kserve-module controller (deployed as a separate binary from `cmd/kserve-module`) acts as a meta-operator: it watches the `Kserve` CR from `components.platform.opendatahub.io` and deploys or removes the subordinate controllers and their prerequisites. This includes installing CRDs, webhook configurations, RBAC roles, cert-manager Certificates, NetworkPolicies, and the full catalog of ClusterServingRuntime definitions from prefetched manifests.

Beneath this, four primary controllers run as separate Deployments, each with its own binary and service account:

1. **kserve-controller-manager** (`cmd/manager`): Reconciles InferenceService, InferenceGraph, and TrainedModel CRs, managing the full lifecycle from storage initialization to autoscaling (HPA/KEDA/Knative) and ingress (Istio VirtualService, Gateway API HTTPRoute, OpenShift Routes, or plain Kubernetes Ingress). A pod-mutating webhook injects storage initializer containers into model server pods.

2. **llmisvc-controller** (`cmd/llmisvc`): Reconciles LLMInferenceService and LLMInferenceServiceConfig, a v1alpha2 API surface designed for LLM workloads. It integrates with Gateway API inference extensions (InferencePool, InferenceModel), supports multi-node inference via LeaderWorkerSets, and manages DestinationRules for self-signed TLS between components and the service mesh.

3. **localmodel-controller** (`cmd/localmodel`): Reconciles LocalModelCache and LocalModelNamespaceCache, managing pre-caching of models to node-local storage via PersistentVolumes and download Jobs.

4. **localmodelnode-agent** (`cmd/localmodelnode`): Runs as a DaemonSet, reconciling LocalModelNode resources to manage per-node model cache state and download Jobs.

The TLS posture is notably well-engineered. The `pkg/tls/distro/` package reads the OpenShift cluster's TLS security profile from `apiservers.config.openshift.io/cluster` at startup and dynamically configures cipher suites and minimum TLS versions. A `ProfileWatcher` controller continuously monitors the APIServer CR for changes, allowing TLS settings to be updated without restarts. The fallback for non-OpenShift clusters is hardened Intermediate defaults (TLS 1.2, ECDHE AEAD ciphers). All Go binaries are built with `GOEXPERIMENT=strictfipsruntime` and `CGO_ENABLED=1` on UBI 9 minimal-pqc base images.

The distro build-tag pattern (`//go:build distro` / `//go:build !distro`) is a key architectural feature that enables clean upstream/downstream separation. ODH-specific logic lives in `*_odh.go` companion files that implement hook functions; `*_default.go` files provide no-op fallbacks. This enables the downstream to carry OpenShift Route creation, custom RBAC generation, Gateway API integration specifics, and platform detection without modifying upstream code.

Webhook coverage is extensive: 16+ admission webhooks (both validating and mutating) cover InferenceService, LLMInferenceService, LLMInferenceServiceConfig, InferenceGraph, ServingRuntime, ClusterServingRuntime, TrainedModel, LocalModelCache, LocalModelNamespaceCache, and pod mutation. CRD conversion webhooks support the v1alpha1-to-v1alpha2 migration path for LLMInferenceService and LLMInferenceServiceConfig.

## Multi-Tenancy

### Tenant Model

| Aspect | Value | Source |
|--------|-------|--------|
| **Tenant boundary** | per-namespace | CRD scope: all serving.kserve.io resources are Namespaced |
| **Deployment model** | multi-tenant (single controller set serves all namespaces) | cmd/manager, cmd/llmisvc -- cluster-scoped watches with namespace-filtered reconciliation |
| **Tenant identifier** | namespace name | Inferred from CRD scope and controller namespace watches |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Per-namespace RBAC for CRD operations; kube-rbac-proxy for metrics; ServiceAccount per controller | Kubernetes RBAC | Python model servers have no built-in authentication; rely on platform ingress (Gateway API / Istio) for tenant isolation at the network level |
| Data storage | Per-namespace PVCs for LocalModelCache; model credentials in per-namespace Secrets | Kubernetes | ClusterStorageContainer and ClusterServingRuntime are cluster-scoped, shared across tenants |
| Network traffic | NetworkPolicy per namespace (created by kserve-module via ODH overlay); AuthorizationPolicy via Istio (platform-level) | Kubernetes / Istio | NetworkPolicies are optional; depends on ODH overlay being applied |
| Compute & resources | Per-InferenceService resource requests/limits; no built-in ResourceQuota enforcement | Kubernetes (user-configured) | No automatic per-tenant resource quotas; relies on platform-level enforcement |
| Configuration & secrets | Per-namespace Secrets for model credentials; ConfigMap-based inference configuration | Kubernetes | inferenceservice-config ConfigMap is shared across all namespaces in the controller namespace |
| API scoping | Namespace-scoped watches for InferenceService, LLMInferenceService; cluster-scoped watches for ClusterServingRuntime, Nodes | Kubernetes / Application | Controllers use cluster-wide watches filtered by namespace; LocalModelCache watches cross-namespace InferenceService references |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| Controller managers | Cluster-wide (single instance per controller) | Namespace-scoped reconciliation; RBAC on CRDs |
| ClusterServingRuntime catalog | Cluster-wide | Read-only for tenants; managed by kserve-module |
| Webhook server | Cluster-wide | Kubernetes admission authorization |
