## Purpose

**Short**: IBM Spyre accelerator-optimized vLLM inference serving runtime image for RHOAI, providing OpenAI-compatible HTTP and TGIS-compatible gRPC APIs.

**Detailed**: vllm-spyre is a thin container image wrapper that extends the pre-built RHAIIS (Red Hat AI Inference Service) `vllm-spyre-rhel9` product image with RHOAI-specific environment variables, runtime configuration, and container labels. The base image (`registry.redhat.io/rhaiis/vllm-spyre-rhel9`) contains the full vLLM inference engine compiled with IBM Spyre accelerator support, including the `vllm_tgis_adapter` module that provides a TGIS-compatible gRPC interface alongside the standard vLLM OpenAI-compatible HTTP API.

This repository does not contain application source code. All inference logic, Python dependencies, and accelerator support are inherited from the RHAIIS base image, which is itself built from the AIPCC (AI Platform Core Components) IBM Spyre base image. The repository's role is to customize the runtime configuration for RHOAI deployments — setting ports, disabling speculative decoding logprob suppression for hosted model compatibility, and applying RHOAI product labeling.

The component is deployed as a KServe `ServingRuntime` container in RHOAI, where it serves LLM inference requests using IBM Spyre hardware accelerators. It exposes an HTTP API on port 8000 (OpenAI-compatible) and a gRPC API on port 8033 (TGIS-compatible).

## Architectural Analysis

This repository represents a minimal "thin wrapper" pattern for producing RHOAI-specific container images. The entire vLLM inference engine, IBM Spyre accelerator support, Python runtime, and all dependencies are inherited from the RHAIIS product base image (`registry.redhat.io/rhaiis/vllm-spyre-rhel9:3.2.2`). The repository's sole contribution is a 24-line Dockerfile that customizes environment variables, sets the container entrypoint, and applies RHOAI product labels. This is a deliberate architectural choice: the RHAIIS team owns the full build of the inference runtime, and downstream teams (RHOAI) layer only deployment-specific configuration on top.

The entrypoint `python3 -m vllm_tgis_adapter --uvicorn-log-level=warning` launches the vLLM TGIS adapter, which wraps the vLLM engine to provide both an OpenAI-compatible HTTP API (port 8000) and a TGIS-compatible gRPC API (port 8033). The `DISABLE_LOGPROBS_DURING_SPEC_DECODING=false` environment variable overrides vLLM's default optimization that suppresses logprobs during speculative decoding — this ensures consistent API behavior for users of hosted models that may internally use speculative decoding. The container runs as non-root user 2000.

A notable aspect of this repository's history is the transition from a full-source-build model to the thin-wrapper model. The `rhoai-2.22` branch (cut June 2025) contains the entire vLLM source tree (2,583+ files) with a multi-stage Dockerfile (`Dockerfile.spyre.ubi`) that builds from `quay.io/ibm-aiu/base` with explicit `pip install` and `uv pip install` commands, clones Foundation Model Stack repositories, and compiles vLLM from source. The current `main` branch (September 2025) has been reduced to just the Dockerfile wrapper, README, and LICENSE. This evolution reflects the maturation of the RHAIIS product pipeline: once RHAIIS began publishing production-quality base images, downstream repositories no longer needed to duplicate the full build process.

The provenance chain for this component spans three tiers: upstream `vllm-project/vllm`, midstream `neuralmagic/nm-vllm` (synced via the `midstream-cuda-v0.9.1.0` branch), and downstream `red-hat-data-services/vllm-spyre`. The sync from NeuralMagic midstream to Red Hat downstream appears to be manual (no sync workflows detected). The NeuralMagic midstream adds optimizations and enterprise patches on top of the upstream vLLM codebase.
