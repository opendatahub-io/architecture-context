## Purpose

**Short**: Caikit NLP is a Python library providing Natural Language Processing capabilities (text generation, embeddings, reranking, classification) built on top of the Caikit AI framework, serving as a runtime extension for NLP model serving in RHOAI.

**Detailed**: Caikit NLP (`caikit_nlp`) implements the Caikit framework's "task" and "module" pattern to provide a comprehensive set of NLP capabilities. It defines task interfaces (TextGenerationTask, EmbeddingTask, RerankTask, etc.) and implements multiple modules that fulfill these tasks using different backends — local PyTorch inference via HuggingFace Transformers, or remote inference via gRPC to Text Generation Inference Server (TGIS).

The library supports both training and inference workflows. For training, it provides prompt tuning (including multi-task prompt tuning via PEFT) and full fine-tuning of causal language models and sequence-to-sequence models. For inference, it supports text generation (with streaming), text embeddings via sentence-transformers, semantic similarity, reranking (both bi-encoder and cross-encoder), sequence classification, token classification, and tokenization.

In the RHOAI platform, caikit-nlp is packaged as a container image and used as a runtime library by the Caikit serving runtime. It is loaded by setting `RUNTIME_LIBRARY=caikit_nlp` and running `python -m caikit.runtime`, which exposes the library's modules via HTTP (port 8080) and gRPC (port 8085) endpoints. The library integrates tightly with the caikit-tgis-backend for offloading generation to remote TGIS instances.

## Data Flows

- **Inference path (text generation):** Client → caikit runtime (gRPC/HTTP) → TextGenerationTGIS module → TGISGenerationClient → TGIS server (gRPC). The caikit runtime receives inference requests, routes them to the appropriate loaded module, which delegates to TGIS via `generation_pb2.BatchedGenerationRequest` (unary) or `generation_pb2.SingleGenerationRequest` (streaming). TGIS returns `GeneratedTextResult` or streamed `GeneratedTextStreamResult`.
- **Inference path (embedding):** Client → caikit runtime (gRPC/HTTP) → EmbeddingModule → sentence-transformers (local). Embedding inference runs locally using sentence-transformers models with configurable batch size, device, and optimization (IPEX, autocast, pt2_compile).
- **Training path:** Client → caikit runtime → PeftPromptTuning module → local GPU (torch/accelerate/peft). PEFT prompt tuning trains locally using PyTorch with configurable torchrun elastic launch (master_addr/master_port for multi-GPU).
- **Model loading:** caikit runtime → module.load() → local filesystem or TGIS backend registration. TextGenerationTGIS loads "remote" models by registering the model name with TGISBackend; TextGeneration loads HuggingFace models from disk.

## Architectural Analysis

Caikit NLP follows a clean module/task architecture inherited from the Caikit framework. Each NLP capability is defined as a "task" (an interface) and implemented by one or more "modules" (concrete implementations). This separation allows the same task interface to be fulfilled by different backends — for example, `TextGenerationTask` can be served by `PeftPromptTuning` (local PyTorch), `PeftPromptTuningTGIS` (remote via gRPC), `TextGeneration` (local fine-tuned model), or `TextGenerationTGIS` (remote fine-tuned model). The TGIS-backed modules use `@module(backend_type=TGISBackend.backend_type, base_module=LocalModule)` to transparently proxy inference to a remote TGIS instance, making the local/remote distinction invisible to callers.

The embedding module (`EmbeddingModule`) stands out architecturally because it implements seven distinct tasks (Embedding, Embeddings, SentenceSimilarity, SentenceSimilarities, Rerank, Reranks, Tokenization) in a single class. This is a design choice that consolidates all vector-based operations under one model load, avoiding redundant model loading. The `CrossEncoderModule` provides an alternative reranking implementation using cross-attention rather than bi-encoder similarity. Both modules implement thread-safe tokenizer caching (per-thread tokenizer copies via `deepcopy`) to avoid "Already borrowed" errors from concurrent tokenizer access — a practical solution for multi-threaded serving.

The TGIS integration is notable for its error handling sophistication. The `TGISGenerationClient` in `tgis_utils.py` maps all gRPC status codes to Caikit-native exception types (lines 72-88), providing consistent error semantics regardless of whether inference is local or remote. The client also handles prompt cache management — loading and unloading prompt vectors to/from TGIS backends — which is essential for the prompt tuning workflow where soft prompts must be registered with the inference server before queries can use them.

The library's training capabilities support distributed training via `torch.distributed.launcher.api.elastic_launch` for fine-tuning and via HuggingFace `Accelerator` for PEFT prompt tuning. The `torch_run.py` toolkit module auto-detects GPU count and configures single-node elastic launch with gloo or nccl backends. Training data limits are configurable per-module and per-model via `training_data_limit` in the config, providing a safety valve against unbounded resource consumption during training.

From a security standpoint, the library is conservative by default: `allow_downloads` defaults to `false` (preventing arbitrary model downloads from HuggingFace), and `trust_remote_code` defaults to `false` for sentence-transformers models. However, the Dockerfile uses `registry.access.redhat.com/ubi9/ubi-minimal:latest` rather than AIPCC base images, meaning Python packages (including PyTorch with its accelerator-specific binaries) are installed from public PyPI rather than Red Hat's secure Python Package Index. The Tekton pipelines explicitly set `hermetic: false`, and no dependency lock files exist on this branch — the build is fully non-hermetic. For a production RHOAI component, migration to AIPCC base images and Hermeto-based hermetic builds would significantly strengthen the supply chain posture.

## Architectural Analysis

caikit-nlp follows the caikit module library pattern: it provides domain-specific AI modules (NLP in this case) that plug into the caikit runtime framework. The library does not run as a standalone process—the caikit runtime discovers and loads its modules, then auto-generates gRPC and HTTP API endpoints from the registered task types. This means the serving infrastructure (ports, TLS, authentication, health checking) is entirely controlled by the caikit runtime configuration, not by caikit-nlp itself.

The text generation architecture uses a split between local and remote inference. The `TextGeneration` module runs transformers models locally for training and inference, while `TextGenerationTGIS` delegates inference to a remote TGIS server via gRPC through the `caikit-tgis-backend` library. This split enables the same module interface to serve both fine-tuning workflows (which need local GPU access) and production inference (which uses optimized TGIS serving). The `PeftPromptTuning` and `PeftPromptTuningTGIS` modules mirror this pattern for PEFT prompt tuning, with the TGIS variant supporting inference against remotely-hosted models with trained prompt prefixes.

The embedding modules (`EmbeddingModule`, `CrossEncoderModule`) run entirely locally using sentence-transformers. The config.yml provides embedding-specific tuning options: trust_remote_code, retry count, batch size, implicit truncation error handling, PyTorch compile optimization, IPEX integration, autocast (bfloat16), and device selection. This configurability reflects deployment across CPU, CUDA GPU, and Intel XPU environments.

A notable security posture is the `allow_downloads: false` default in config.yml, which prevents the library from downloading model artifacts from arbitrary URLs at runtime. This forces models to be pre-provisioned on disk or served via TGIS, aligning with air-gapped and supply-chain-secured deployment patterns common in RHOAI.
