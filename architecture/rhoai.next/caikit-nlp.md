## Purpose

**Short**: Caikit-NLP is a Python library that provides Natural Language Processing capabilities (text generation, embeddings, reranking, classification) as modules within the Caikit AI runtime framework.

**Detailed**: Caikit-NLP implements the "task" and "module" abstraction pattern from the Caikit framework to expose NLP capabilities. Each task defines an interface for an NLP problem (text generation, embedding, reranking, sentence similarity, text/token classification, tokenization), and each module provides a concrete implementation. The library supports both local model inference via PyTorch/HuggingFace Transformers and remote inference through the TGIS (Text Generation Inference Server) backend over gRPC.

The library is not a standalone service. It is loaded as a plugin library by the Caikit runtime (`python -m caikit.runtime`), which auto-discovers the registered modules and exposes them through HTTP (port 8080) and gRPC (port 8085) endpoints. This architecture separates NLP domain logic from serving infrastructure — caikit-nlp owns the model loading, inference, and training logic, while the caikit runtime owns the server lifecycle, request routing, and protocol handling.

A key capability is parameter-efficient fine-tuning (PEFT), particularly prompt tuning and multi-task prompt tuning. These approaches train lightweight prompt vectors rather than modifying base model weights, enabling multiple tuned prompts to share a single base model at inference time. The TGIS backend modules (`PeftPromptTuningTGIS`, `TextGenerationTGIS`) delegate heavy generation workloads to a separate TGIS server, communicating over gRPC with configurable TLS.

## Architectural Analysis

Caikit-NLP follows a plugin-library architecture where all NLP logic is encapsulated in Caikit modules that register themselves against Caikit task interfaces. The library has no main entry point of its own — the Dockerfile CMD is bare `python`, and the actual serving is started via `python -m caikit.runtime` with `RUNTIME_LIBRARY=caikit_nlp` set as an environment variable. This means the serving surface (ports, protocols, authentication) is entirely controlled by the Caikit runtime, not by this library.

The TGIS integration is architecturally significant. Modules like `PeftPromptTuningTGIS` and `TextGenerationTGIS` use the `caikit-tgis-backend` library to connect to an external TGIS server over gRPC. The connection supports TLS with configurable CA certificates, client certificates, and client keys. The `TGISAutoFinder` in `model_management` enables automatic discovery of TGIS endpoints. This creates a runtime dependency on an external inference server for generation workloads, while embedding and reranking modules run locally using `sentence-transformers`.

The configuration system uses `alchemy-config`, supporting both YAML files and environment variables. Configuration controls model loading behavior, TGIS connection parameters, embedding optimization flags (IPEX, PyTorch compile, autocast), and training limits. The `allow_downloads` flag defaults to `false` for security, requiring explicit opt-in to download models from external sources like HuggingFace Hub.

The build pipeline is minimal — a multi-stage Dockerfile on UBI9 minimal that builds a wheel with tox and installs it via pip. No lock files exist on this branch for either Python dependencies or RPM packages, creating a significant supply chain hermeticity gap. The Tekton pipeline references Cachi2 prefetch capabilities, but the Dockerfile.konflux does not source `cachi2.env`, so hermetic builds are not enforced at the container build level.
