## Purpose

**Short**: Python SDK that simplifies the lifecycle management of Ray clusters and Ray jobs on Kubernetes, integrating with Kueue for quota-aware scheduling and KubeRay for cluster orchestration.

**Detailed**: CodeFlare SDK provides a high-level Python interface for data scientists and ML engineers to request, configure, and manage distributed computing resources on OpenShift via Ray. The `Codeflare` class is the single entrypoint: it authenticates to Kubernetes via kube-authkit, then exposes `cf.clusters` and `cf.jobs` handlers for creating Ray clusters and submitting Ray jobs respectively. Both paths consume the same `ClusterConfiguration` dataclass, ensuring a single way to describe a cluster across the SDK.

The SDK is not deployed as a long-running service. It runs client-side — in Jupyter notebooks, developer workstations, or CI pipelines — and creates Kubernetes custom resources (RayCluster, RayJob CRs) via the KubeRay operator. It integrates with Kueue for workload queuing and priority scheduling, OpenShift Routes and Kubernetes Gateway API for dashboard access, and generates TLS certificates locally for secure Ray client connections. A vendored KubeRay Python client handles the low-level CR interactions.

The SDK also ships a test container image (`images/tests/Dockerfile`) used for end-to-end testing on OpenShift clusters, but this is not a production deployment artifact.

## Architectural Analysis

CodeFlare SDK follows a layered architecture with strict import boundaries enforced by import-linter in CI. The foundation layer (`common/`) provides authentication, Kueue integration, utility functions, and TLS certificate generation. The feature layers (`ray/cluster/` and `ray/rayjobs/`) build on this foundation, with `ray/cluster/` managing RayCluster CR lifecycle and `ray/rayjobs/` managing RayJob CR lifecycle. Only the `ray/rayjobs/` layer may import from the vendored KubeRay client — all other layers use SDK wrappers.

A notable architectural pattern is client isolation (RHOAIENG-98754): each `Codeflare` instance owns its Kubernetes API client, and objects created through it are bound to that client via a `ContextVar`. This prevents a second `Codeflare` instance from silently redirecting the first instance's operations to a different cluster. The `@_bound_to_api_client` decorator and `_use_api_client` context manager propagate the correct client through the call chain without requiring explicit parameter threading.

The SDK's ingress discovery is multi-strategy: it checks OpenShift Routes (`route.openshift.io`), Kubernetes Gateway API HTTPRoutes (`gateway.networking.k8s.io`), and RHOAI's `GatewayConfig` CR (`services.platform.opendatahub.io`) to find Ray dashboard URLs, making it portable across deployment topologies.

`ClusterConfiguration.__post_init__` is not idempotent — it merges accelerator resource mappings and validates the result — so the codebase uses `copy.copy()` rather than `dataclasses.replace()` when modifying a configured instance. This is a deliberate design choice but a recurring source of subtle bugs if not followed.

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Per-user Kubernetes credentials via kube-authkit | Kubernetes API server | SDK trusts whatever RBAC the user has; no SDK-level authorization |
| Data storage | Per-namespace RayCluster/RayJob CRs; per-cluster TLS certs in user-private dirs | Kubernetes / Filesystem | TLS cert directory (~/.local/share/codeflare/tls/) uses 0700 permissions |
| Network traffic | Delegated to Kubernetes/OpenShift network policies | Kubernetes / Platform | No SDK-level network isolation |
| Compute & resources | Delegated to Kueue (LocalQueue, ClusterQueue, ResourceFlavor) | Kueue / Kubernetes | SDK validates queue existence but does not enforce quotas |
| Configuration & secrets | Per-namespace Secrets for CA certs | Kubernetes | Module-level client fallback (`set_api_client`) can cross instances if not using `Codeflare` entrypoint |
| API scoping | Namespace-scoped watches for clusters, jobs, queues, routes | Kubernetes / Application | `list_all_clusters` and similar APIs scope to a single namespace |
