## Purpose

**Short**: MLServer is an open-source Python inference server that serves machine learning models via REST and gRPC interfaces compliant with the V2 Inference Protocol (KFServing dataplane).

**Detailed**: MLServer is a multi-model inference server originally created by Seldon Technologies and forked into the Red Hat OpenShift AI ecosystem. It provides a standardized way to serve machine learning models through dual-protocol endpoints (REST via FastAPI/uvicorn and gRPC via grpc.aio), both implementing the KFServing V2 Dataplane specification. The server supports multi-model serving (multiple models within a single process), parallel inference via worker pools, adaptive request batching, and a plugin-based runtime architecture that allows different ML framework backends (scikit-learn, XGBoost, LightGBM, ONNX, MLflow, HuggingFace, CatBoost, Alibi, and Spark MLlib) to be loaded dynamically.

In the RHOAI platform, MLServer operates as a KServe-managed serving runtime container. When deployed in production mode, a trusted-runtimes allowlist baked into the container image at build time restricts which model implementation classes can be loaded, preventing arbitrary code execution via user-supplied model configurations. The server exposes a Prometheus metrics endpoint on a dedicated port, supports OpenTelemetry tracing export, and can optionally consume/produce Kafka messages for asynchronous inference. Authentication is platform-delegated to a kube-rbac-proxy sidecar injected by KServe.

## Architectural Analysis

MLServer's architecture follows a clean separation between its transport layer, business logic, and pluggable ML runtimes. The core `MLServer` class orchestrates four concurrent servers -- REST (FastAPI on uvicorn), gRPC (grpc.aio), Metrics (dedicated uvicorn instance), and optionally Kafka -- all running within a single asyncio event loop. The DataPlane handler mediates between transport endpoints and a MultiModelRegistry that manages model lifecycle (load/reload/unload) with configurable hooks for batching and parallel inference pools.

The runtime security model is a notable architectural decision. The Konflux Dockerfiles generate a `/etc/mlserver/trusted-runtimes.json` artifact at build time, containing a whitelist of allowed Python import paths for model implementations. At runtime, this allowlist is enforced at three points: during model settings validation (initial parse), at the `implementation` property access (lazy import), and through the `ModelParameters` validator (which blocks custom `environment_path` and `environment_tarball` in production mode). This defense-in-depth approach prevents code injection through model-settings.json files. When the allowlist file is absent (development mode), all model implementations are allowed and dynamic loading from model folders is supported.

The gRPC server uses `add_insecure_port` exclusively -- there is no application-level TLS. Similarly, the REST server runs plain HTTP via uvicorn without TLS configuration. All encryption and authentication is delegated to the platform layer: KServe injects a kube-rbac-proxy sidecar that terminates TLS and validates OpenShift OAuth/ServiceAccount tokens before forwarding to MLServer's ports. The OTLP tracing exporter also connects without TLS (`insecure=True`), which assumes the collector is colocated or within a trusted network boundary.

The multi-model design uses a registry pattern where each model is an instance of an `MLModel` subclass. Models can be loaded from a repository (filesystem directory scan), dynamically via the Model Repository API (load/unload/index endpoints), and configured for adaptive batching with `max_batch_size` and `max_batch_time` parameters. The parallel inference feature uses a pool of worker processes for CPU-bound inference workloads.

CORS settings include a production-mode validator that rejects wildcard origins when the trusted-runtimes allowlist is present, preventing overly permissive cross-origin configurations in deployed images.
