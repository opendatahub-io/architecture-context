## Purpose

**Short**: A lightweight, GPU-free inference simulator that mimics vLLM and SGLang behavior for infrastructure testing, routing validation, and control-plane development.

**Detailed**: llm-d-inference-sim is a configurable simulator that acts as a drop-in replacement for real LLM inference engines. It exposes the full OpenAI-compatible HTTP surface (chat completions, text completions, embeddings, responses, messages), a vLLM-compatible gRPC interface, and engine-specific management endpoints (LoRA adapter loading, sleep/wake lifecycle, Mooncake bootstrap query). The simulator models realistic latency behavior including configurable time-to-first-token, inter-token latency with jitter, and load-dependent delay scaling, allowing infrastructure teams to validate routing, scheduling, and observability without GPU resources.

The simulator supports a pluggable engine backend architecture with vLLM and SGLang engines, each supplying its own HTTP routes, gRPC surface, error framing, metrics, and KV-event wire format. A block-level KV cache simulation publishes cache events over ZMQ using msgpack-encoded batches, enabling testing of KV-cache-aware routing and prefill/decode disaggregation. Response content can be generated in echo mode (loopback), random mode (probabilistic histograms), or from SQLite-backed HuggingFace datasets. The simulator also provides Prometheus metrics mirroring vLLM's standard metric set.

## Architectural Analysis

The simulator is structured around a clean engine abstraction that separates the generic simulation core from engine-specific transport and metrics concerns. The `Engine` interface (`pkg/engine/engine.go`) defines a contract covering defaults, CLI flags, configuration validation, HTTP/gRPC binding, error framing, metrics adapters, and KV-event encoding. Two implementations -- vLLM (`pkg/engine/vllm/`) and SGLang (`pkg/engine/sglang/`) -- are registered in a name-keyed registry; the active engine is selected at startup via the `--engine` flag or `SIM_ENGINE` environment variable.

The communication layer (`pkg/communication/`) uses `cmux` to multiplex HTTP and gRPC on a single TCP port. HTTP is served via `fasthttp` with `fasthttprouter` for high-performance request handling; the gRPC surface uses the standard `google.golang.org/grpc` server. The vLLM engine registers a protobuf-defined `VllmEngine` gRPC service with Generate, Embed, HealthCheck, Abort, and model/server info RPCs; the SGLang engine has no gRPC surface. TLS is optional, supporting either file-based certificates with hot-reload via filesystem watcher or auto-generated self-signed certificates.

Request processing flows through a shared pipeline: the communication layer unmarshals and validates requests, the simulator core (`pkg/simulator/`) manages a worker queue that applies latency simulation (TTFT, ITL, load scaling), selects response content (echo, random, or dataset-sourced), and emits token-by-token results through a channel. KV cache events are tracked by `pkg/kvcache/`, encoded by the active engine's `EventEncoder`, batched, and published over ZMQ via `pkg/common/publisher.go`. Each engine encodes its own wire format (vLLM uses msgpack-tagged unions matching the upstream Python publisher; SGLang uses its own variant).

The build produces a statically linked Go binary (`CGO_ENABLED=0`) on a `distroless/static` base image. This design choice prioritizes minimal image size and attack surface over FIPS compliance -- the absence of CGO and OpenSSL means the binary cannot pass Konflux `check-payload` FIPS validation. No Konflux Dockerfiles exist in this repository. A separate ZMQ listener utility (`Dockerfile.zmq`) provides a Python-based diagnostic tool for observing KV cache events.

_The simulator is built with CGO_ENABLED=0 on a distroless/static base image containing no system libraries. This means all cryptographic operations use Go's pure-Go crypto implementation, which is not FIPS-validated. The binary would not pass Konflux check-payload validation. This is architecturally appropriate for a testing simulator that is not intended for production workloads, but it should not be deployed in FIPS-mandated environments._
