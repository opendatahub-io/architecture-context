## Purpose

**Short**: Intelligent inference traffic router that delivers LLM load-aware and prefix-cache-aware routing via an Endpoint Picker (EPP) integrated with Envoy ext-proc, complemented by a coordinator for disaggregated inference pipelines and a sidecar proxy for multi-stage request orchestration.

**Detailed**: The llm-d Router is the entry point for inference traffic in the llm-d stack. Its core is the Endpoint Picker (EPP), a gRPC service that implements the Envoy External Processing (ext-proc) protocol. On each incoming request, Envoy calls out to the EPP, which evaluates real-time signals — KV-cache locality, queue depth, model load, and priority — to select the optimal backend pod from an InferencePool. The EPP is driven by an EndpointPickerConfig CRD that declares plugins (filters, scorers), scheduling profiles, data-layer sources, and feature gates, making the routing logic extensible without code changes.

Beyond single-shot routing, the repository hosts two additional deployable components. The Coordinator is an HTTP server that orchestrates disaggregated inference pipelines — E/P/D (Encode/Prefill/Decode) and P/D (Prefill/Decode) — by chaining configurable steps (replace-media-urls, render, encode, prefill, decode, async-broker) that each call back through the Inference Gateway. The PD-Sidecar runs alongside model-serving pods (typically decode workers) as a reverse proxy that intercepts inference requests and routes them through prefill and encode workers before returning the streamed response to the caller, coordinating KV-cache and embedding transfers across the disaggregated stages.

Two custom resource APIs complement the EPP: InferenceObjective defines per-request scheduling priorities and pool targeting, while InferenceModelRewrite enables model-name rewriting for A/B testing and canary rollouts. Both CRDs are namespaced and reconciled by dedicated controllers within the EPP process.

## Architectural Analysis

The llm-d Router follows a plugin-oriented architecture where routing behavior is defined declaratively through the EndpointPickerConfig CRD rather than compiled in. The EPP process embeds a controller-runtime manager that watches InferencePool, InferenceObjective, InferenceModelRewrite, and Pod resources, maintaining an in-memory datastore of pool state. When Envoy calls the ext-proc gRPC service, the EPP evaluates the request through a pipeline of filter and scorer plugins configured per scheduling profile, then returns routing headers that Envoy uses for upstream selection.

The coordinator introduces a pipeline pattern where each step (media download, tokenization, encode fan-out, prefill, decode) is a self-contained unit that can be enabled, reordered, or configured independently via YAML. The coordinator supports multiple KV-transfer protocols (NIXL RDMA, shared storage, SGLang bootstrap) selected per-step, and its gateway client pools HTTP connections to the Inference Gateway for high-throughput multimodal workloads.

The sidecar proxy pattern decouples disaggregation orchestration from the model server itself. The sidecar intercepts requests on a local port, fans out prefill and encode calls to their respective workers, collects transfer descriptors, and then proxies the final decode call to the co-located model server. Each upstream connection (prefill, encode, decode) has independent TLS configuration, including per-stage InsecureSkipVerify controls.

Data-layer plugins within the EPP scrape metrics (Prometheus, DCGM) and model metadata directly from model-serving pods. These HTTP data sources default to InsecureSkipVerify=true for the pod-scraping transport, which is documented as an operator-supplied configuration choice. The ZMQ subscriber on port 5557 receives KV-cache event notifications for prefix-cache-aware routing decisions.

Redis is used by the async-broker step for queue-based asynchronous inference serving, with per-tenant quota classification and tiered objective assignment. The coordinator async-broker exposes GET/DELETE /v1/requests/{id} endpoints for polling and cancelling queued requests.
