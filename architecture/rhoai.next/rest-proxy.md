## Purpose

**Short**: A reverse-proxy sidecar that translates KServe V2 REST inference requests into gRPC calls for ModelMesh Serving backends.

**Detailed**: rest-proxy is a lightweight Go service built on the gRPC-Gateway library. It accepts HTTP/REST requests conforming to the KServe V2 Predict Protocol and translates them into the equivalent gRPC V2 Predict Protocol calls, forwarding them to a co-located gRPC inference server (typically a ModelMesh Serving instance on localhost). This enables clients that only speak REST to interact with inference servers that only expose gRPC endpoints.

The proxy handles custom JSON marshaling and unmarshaling of tensor data, supporting all KServe V2 tensor types (BOOL, INT8–INT64, UINT8–UINT64, FP32, FP64, BYTES) and both structured tensor contents and raw binary representations. It runs as a sidecar container alongside the inference server, with the gRPC endpoint defaulting to `localhost:8033` and the REST listener defaulting to port `8008`. TLS can optionally be configured for both the outbound gRPC connection and the inbound HTTP listener.

## Architectural Analysis

rest-proxy is architecturally simple by design: a single Go binary acting as a protocol bridge between REST and gRPC. The entire application logic resides in four Go source files under `proxy/`, with generated gRPC-Gateway stubs in `gen/`. The proto definition (`grpc_predict_v2.proto`) comes from the KServe/Kubeflow ecosystem and defines the V2 inference protocol.

A significant design characteristic is the custom JSON marshaler (`CustomJSONPb`) that intercepts both request deserialization and response serialization. On the request path, it translates the KServe REST tensor format (with nested arrays, base64 strings, and typed data) into protobuf `InferTensorContents`. On the response path, it converts protobuf `RawOutputContents` byte arrays back into typed tensor data. This custom marshaling is performance-critical since inference payloads can be large (configurable up to 16 MB by default via `REST_PROXY_GRPC_MAX_MSG_SIZE_BYTES`).

The proxy has no persistent state, no CRDs, no RBAC requirements, and no kustomize manifests of its own. Its deployment is managed entirely by ModelMesh Serving, which injects it as a sidecar container via the `restProxy.image` configuration in the `model-serving-config` ConfigMap. This means the proxy's lifecycle, scaling, and network exposure are all delegated to the parent ModelMesh deployment.

TLS configuration is dual-layered: the gRPC client connection to the inference backend can use TLS (controlled by `REST_PROXY_USE_TLS`), and the inbound HTTP listener can separately serve over HTTPS when `MM_TLS_KEY_CERT_PATH` and `MM_TLS_PRIVATE_KEY_PATH` are set. However, neither connection enforces a minimum TLS version or restricts cipher suites — both rely on Go's `crypto/tls` defaults via the FIPS-enabled runtime.
