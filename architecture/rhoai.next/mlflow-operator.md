## Purpose

**Short**: Kubernetes operator that automates the deployment, lifecycle management, and upgrade orchestration of MLflow tracking and artifact servers on OpenShift and Kubernetes.

**Detailed**: The mlflow-operator provides a declarative API for deploying MLflow instances through three Custom Resources (`MLflow`, `MLflowOperator`, `MLflowConfig`). The primary `MLflow` CR triggers the operator to render embedded Helm charts into full Kubernetes workloads — a tracking Deployment, optional dedicated artifact-server Deployment, garbage-collection and trace-archival CronJobs, Services, NetworkPolicies, RBAC resources, and Gateway API HTTPRoutes. The operator manages the complete lifecycle: database migration orchestration (scale-down, one-shot Job, rollout), secret rotation via pod-template annotation rollouts, TLS certificate provisioning through OpenShift service-ca, and multi-workspace RBAC distribution through namespace-scoped RoleBindings.

The `MLflowOperator` CR (gated behind `ENABLE_MLFLOW_OPERATOR_MODULE_CONTROLLER`) provides the ODH/RHOAI platform handoff path, allowing the opendatahub-operator to project gateway configuration and status aggregation into the mlflow-operator's lifecycle. The `MLflowConfig` CR enables per-namespace artifact storage overrides so workspaces can direct experiments to separate S3 buckets or storage backends. The operator supports two deployment modes: RHOAI (targeting `redhat-ods-applications`) and ODH (targeting `opendatahub`), with platform-aware TLS profile adherence fetched from `apiservers.config.openshift.io/cluster`.

## Architectural Analysis

The mlflow-operator follows a three-controller architecture where each controller has a clearly scoped domain. The **MLflowReconciler** is the primary controller, reconciling `MLflow` CRs by rendering the vendored Helm chart with computed values, managing owned resources (Deployments, Services, ServiceAccounts, PVCs, Jobs, CronJobs, HTTPRoutes, ConsoleLinks, ServiceMonitors), and orchestrating database migrations with zero-downtime scale-down/scale-up sequences. The **MLflowOperatorReconciler** handles the ODH/RHOAI module handoff, watching the cluster-scoped `MLflowOperator` singleton to project platform configuration and aggregate component status. The **NamespaceRBACReconciler** watches labeled namespaces and the platform `Auth` CR to distribute `mlflow-view` and `mlflow-edit` RoleBindings across workspaces.

The Helm-rendered approach is notable: the operator embeds a full Helm chart (`charts/mlflow/`) and uses the Helm Go SDK to template resources at reconcile time, making the same chart deployable standalone via `helm install` or operator-managed. This dual-path design means the chart must remain self-contained while the operator adds lifecycle orchestration on top.

The split artifact-server topology is a key architectural decision. When `artifactsServer.enabled` is set, the operator creates two independent Deployments sharing the same metadata store and credentials but serving different traffic through separate Gateway API HTTPRoutes (`/mlflow` for tracking, `/mlflow-artifacts` for artifact operations). HTTPRoute path rewrites map legacy tracking-relative artifact URLs to the dedicated server, preserving backward compatibility with existing experiment metadata. This topology isolates artifact I/O from tracking queries at the cost of doubling the metadata-store connection count.

The operator's cache configuration is carefully scoped: label selectors restrict watches to `app: mlflow` resources, field selectors restrict shared RBAC watches to exact resource names (`mlflow`, `mlflow-gc`), and a separate dedicated cache instance handles the singleton GC RBAC objects to avoid widening the manager cache's per-GVK selector limitations. This design keeps RBAC permissions tight (`resourceNames`-scoped) while still enabling watch-based reconciliation.

TLS configuration follows OpenShift's platform crypto policy. At startup, the operator fetches the cluster TLS profile from `apiservers.config.openshift.io/cluster`, applies it via `openshift/controller-runtime-common`, and registers a `SecurityProfileWatcher` that triggers a graceful restart when the profile changes. The managed MLflow server uses in-process TLS termination via uvicorn with `UVICORN_SSL_CIPHERS=PROFILE=SYSTEM` unless overridden, aligning with FIPS-compatible cipher selection.
