RBAC Summary:
- No ClusterRoles or RoleBindings defined
- TGIS runs as a plain workload without Kubernetes API access
- No ServiceAccount-specific RBAC requirements

Secrets:
- No secrets directly referenced in manifests
- TLS certificates provided via environment variables:
  - TLS_CERT_PATH: Server TLS certificate
  - TLS_KEY_PATH: Server TLS private key
  - TLS_CLIENT_CA_CERT_PATH: Client CA cert for mTLS
- Certificates mounted from consuming deployment (e.g., KServe InferenceService)

Network Policies:
- No NetworkPolicy defined in manifests
- Relies on platform-level network isolation

FIPS Compliance Gaps:
- Rust router uses rustls + ring crate (NOT FIPS-validated)
- Rust binaries linked against Debian OpenSSL (not RHEL FIPS-validated OpenSSL)
- Python shards use Unix sockets (no TLS needed)
- In production: TLS typically terminated upstream by KServe/Istio

Multi-Tenancy:
- Single-tenant: one TGIS instance serves exactly one model
- Multi-tenancy achieved at platform level via separate deployments
- No per-request authentication within TGIS itself
