RBAC Summary:
- fms-hf-tuning does NOT define any ClusterRoles, Roles, or RoleBindings
- RBAC is fully delegated to the Kubeflow Training Operator (KFTO)
- The service account used by training pods is configured in the PyTorchJob spec
- KFTO's service account manages pod creation, deletion, and status updates

Secrets:
- No secrets are created or managed by fms-hf-tuning itself
- Secrets are mounted into the pod by the PyTorchJob spec:
  - HF_TOKEN: HuggingFace Hub authentication (Bearer Token)
  - Tracker credentials: API keys for Aim/MLflow/ClearML (optional)
  - Model registry credentials: If using private model registries

Network Policy:
- fms-hf-tuning does NOT define any NetworkPolicy resources
- No inbound Services, Ingress, or Routes are created
- Only outbound HTTPS connections (HuggingFace Hub, trackers) and
  intra-cluster NCCL traffic (29500/TCP, plaintext)
- Network isolation depends on cluster-level NetworkPolicy configuration

FIPS Compliance:
- Python application; no Go binaries or custom crypto
- TLS handled by system OpenSSL on UBI9 base image
- FIPS compliance inherited from UBI9's OpenSSL configuration
- No direct use of cryptographic primitives in application code
- Previous CVE fix: removed unsafe pickle deserialization (CWE-502)

Container Image Security:
- Base: registry.access.redhat.com/ubi9/ubi:latest
- Multi-stage build strips system Python and dnf from release image
- Python runtime runs from user-local install (/home/tuning/.local/)
- CUDA 12.1 development toolkit included
- No lock files on main branch (version ranges in pyproject.toml)
