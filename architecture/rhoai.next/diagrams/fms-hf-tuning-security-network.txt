SECURITY NOTES:

⚠️  Inter-pod NCCL/Gloo Communication (29500/TCP):
  - PyTorch distributed training uses plaintext TCP for gradient synchronization
  - No encryption or authentication between worker pods
  - Mitigated by: NetworkPolicy restricting 29500/TCP to PyTorchJob pods only
  - Risk: Gradient data could be intercepted within the cluster network

⚠️  No RBAC Defined by Component:
  - fms-hf-tuning does not define its own RBAC
  - Relies on ServiceAccount configured in PyTorchJob spec
  - RBAC is managed by the Kubeflow Training Operator
  - Recommendation: Ensure least-privilege ServiceAccount is used

RBAC Summary:
  - No ClusterRoles or Roles defined by this component
  - ServiceAccount is inherited from PyTorchJob spec
  - Kubeflow Training Operator manages pod creation RBAC

Secrets:
  - No secrets defined by this component
  - HF Token: typically provided via env var (HF_TOKEN) or mounted K8s Secret
  - Tracker API keys: provided via env vars in PyTorchJob spec
  - Recommendation: Use K8s Secrets (not env vars) for credentials

FIPS Compliance:
  - UBI 9 base image provides FIPS-mode OpenSSL
  - No direct crypto operations in application code
  - Python requests/urllib3 delegates to system OpenSSL
  - NVCR variant (nvcr.io/nvidia/pytorch) may NOT be FIPS-compliant ⚠️

Build Hermeticity:
  - No lock files (no requirements.txt lock, no uv.lock, no poetry.lock)
  - No Hermeto/cachi2 prefetch configured
  - pyproject.toml uses version ranges (not pinned)
  - Builds are NOT fully hermetic on main branch ⚠️
