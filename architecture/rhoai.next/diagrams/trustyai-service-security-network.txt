Kubernetes Services:
- trustyai-service (HTTP): ClusterIP, 8080/TCP → 8080, HTTP, Internal
- trustyai-service (HTTPS): ClusterIP, 4443/TCP → 4443, HTTPS TLS 1.2+, Internal

Secrets:
- TLS certificate (kubernetes.io/tls) — HTTPS listener on port 4443
  Provisioned by: TrustyAI Operator / cert-manager, Auto-Rotate: Yes
- MariaDB credentials (Opaque) — DATABASE_USERNAME, DATABASE_PASSWORD
  Provisioned by: TrustyAI Operator, Auto-Rotate: No
- MariaDB TLS CA (Opaque) — DATABASE_TLS_CA_CERT at /etc/tls/db/ca.crt
  Provisioned by: Platform provisioning, Auto-Rotate: No

Authentication & Authorization:
- kube-rbac-proxy sidecar: Proxies 8443→8080, enforces Kubernetes RBAC
  via SubjectAccessReview before forwarding requests
- HTTPS listener (4443): TLS client certificate validation
- LM eval subprocess: Environment variable allowlist sanitization
  (blocks LD_PRELOAD, PYTHONPATH, PATH, proxy vars)

RBAC:
- Managed by TrustyAI Operator (no RBAC manifests in service repo)
- ServiceAccount: operator-provisioned per namespace

FIPS Compliance:
- System crypto policy: FIPS (set via update-crypto-policies --set FIPS)
- Python cryptography library: Binds to OpenSSL, respects FIPS constraints
- MD5 usage: hashlib.md5(usedforsecurity=False) — non-cryptographic UUID only
- TLS: Hypercorn ssl_version=2 (TLS 1.2+)

Multi-Tenancy:
- Tenant boundary: per-model (model_id)
- Data isolation: Application-level dataset naming (no tenant-level access control)
- Compute isolation: No per-model resource limits
- Risk: Any authenticated caller can access any model's data within namespace
