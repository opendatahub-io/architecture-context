NetworkPolicy (when enabled via Helm chart):
- Egress allowed:
  - DNS: 53, 5353 (TCP/UDP)
  - HTTPS: 443, 6443 (TCP)
  - PostgreSQL: 5432 (TCP)
  - MySQL: 3306 (TCP)
  - S3/MinIO: 9000, 8333, 8334 (TCP)

RBAC Summary:
- ServiceAccount: Configurable (Helm chart)
- ClusterRole/Role: Dynamically configured via extraRules in values.yaml
  - No default RBAC rules created
  - kubernetes-auth plugin requires:
    - API Groups: ""
    - Resources: namespaces
    - Verbs: list (for workspace enumeration)
    - API Groups: authentication.k8s.io
    - Resources: tokenreviews
    - Verbs: create (for user authentication)

Secrets:
- mlflow-tls (kubernetes.io/tls) - TLS certificate/key for HTTPS, manual/cert-manager, depends on provisioner
- mlflow-db-secret (Opaque) - Database connection URI, manual, no auto-rotation
- MLFLOW_CRYPTO_KEK_PASSPHRASE (env var) - Key Encryption Key for AES-GCM encryption of gateway secrets, manual rotation via `mlflow crypto rotate-kek`

Authentication Flow:
1. Client sends request with kubernetes-auth token (ServiceAccount token)
2. MLflow server calls Kubernetes TokenReview API to validate token
3. Workspace resolved from URL path prefix (/workspaces/{name}/...) or X-Mlflow-Workspace header
4. All queries scoped to active workspace via SQLAlchemy middleware
5. Auth cache (configurable TTL) may allow stale permissions briefly after changes

FIPS Compliance:
- Python application uses system OpenSSL via `cryptography` package (cffi-based)
- UBI9-minimal base image provides FIPS-validated OpenSSL
- No non-FIPS crypto detected (hashlib.sha256 used for data integrity only)
- TLS configuration via uvicorn --ssl-keyfile/--ssl-certfile (no hardcoded cipher suites)
