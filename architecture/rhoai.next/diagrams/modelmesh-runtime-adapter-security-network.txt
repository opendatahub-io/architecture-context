Secrets:
- Storage config secrets (Opaque) — mounted at /storage-config
  - S3: access_key_id, secret_access_key, endpoint_url, region, bucket, default_bucket
  - GCS: service_account (JSON with private_key + client_email)
  - Azure: connection_string or (client_id + client_secret + tenant_id + container_name + storage_account)
  - HTTP: Optional custom headers, optional CA cert, optional client cert + key
  - Provisioned by: User / modelmesh-serving controller
  - Auto-Rotate: No

Authentication & Authorization:
- puller gRPC (8084/TCP): No auth — relies on pod-level network isolation
- adapter gRPC (8085/TCP): No auth — loopback only, never exposed outside pod
- Cloud storage egress: Per-provider credentials from mounted secrets
- No Kubernetes RBAC roles (sidecar does not interact with K8s API directly)

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, -tags strictfipsruntime
- Linking: Dynamic (CGO_ENABLED=1 for OpenSSL)
- Base image: UBI 9 minimal (OpenSSL included)
- No non-FIPS crypto detected (no MD5, RC4, or DES usage)
- TLS: Cloud storage SDKs use stdlib crypto/tls (FIPS-compliant via OpenSSL at runtime)

Network Policy Notes:
- All puller ↔ adapter ↔ runtime communication is localhost (loopback)
- No Kubernetes Services are defined (pod-internal only)
- External egress required to cloud storage endpoints on 443/TCP
- ModelMesh communicates with puller on 8084/TCP within cluster network
