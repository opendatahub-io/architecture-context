RBAC Summary:
- No Kubernetes RBAC roles — this is a sidecar container that does not
  interact with the Kubernetes API server.
- Pod-level security relies on the parent ModelMesh Serving deployment's
  RBAC, NetworkPolicies, and ServiceAccount configuration.

Secrets:
- storage-config (Opaque) - Cloud storage credentials mounted at /storage-config/
  Contains per-provider JSON files with:
  - S3: access_key_id, secret_access_key, endpoint_url, region, bucket
  - GCS: private_key, client_email, project_id, bucket
  - Azure: connection_string or client_id + client_secret + tenant_id
  - HTTP: custom headers, optional certificate + client_certificate + client_key
  Provisioned by: User / ModelMesh controller
  Auto-Rotation: No

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Go crypto: crypto/tls, crypto/x509 (FIPS-compliant via strictfipsruntime)
- Python crypto: System OpenSSL (via UBI 9 minimal)
- No non-FIPS crypto detected (no MD5, RC4, DES, custom RNG)
- TLS Config: Go defaults with strictfipsruntime (FIPS-approved cipher suites)
- Custom CA bundle support from storage-config JSON
- mTLS client certificates supported for HTTP storage provider

Network Security Notes:
- ALL internal communication is plaintext (gRPC/HTTP on localhost)
- This is acceptable: all processes share the pod's network namespace
- No cross-node traffic occurs between adapter components
- External storage communication uses TLS 1.2+ with per-provider auth
- Pod compromise grants access to all model data and storage credentials
- ModelMesh Serving manages network policies at the pod boundary
