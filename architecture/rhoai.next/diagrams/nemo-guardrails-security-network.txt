RBAC Summary:
- No Kubernetes RBAC resources (stateless application-level service, not an operator)

Secrets:
- LLM API Keys (Opaque) - API keys for upstream LLM providers
  (OPENAI_API_KEY, etc.) - Manual provisioning, no auto-rotation

Authentication Summary:
- /v1/chat/completions (POST): Header passthrough (Authorization forwarded to upstream LLM)
- /v1/checks (POST): Header passthrough
- /v1/models (GET): Header passthrough
- /v1/health, /healthz (GET): No auth (public health endpoints)
- No built-in auth enforcement — relies on platform ingress (kube-rbac-proxy or similar)

TLS/Crypto Notes:
- Server listens on plaintext HTTP/8000 (TLS handled externally by platform ingress)
- Outbound TLS via httpx/aiohttp using system OpenSSL (RHEL 9.6 UBI)
- CA bundle: /etc/ssl/certs/ca-certificates.crt (REQUESTS_CA_BUNDLE, SSL_CERT_FILE env vars)
- cryptography==46.0.7 (OpenSSL backend, FIPS-compatible)
- hashlib.md5 used for non-cryptographic cache keys (FIPS fallback in utils.py)
- MD5KeyGenerator in embeddings/cache.py lacks FIPS fallback (SHA256KeyGenerator available)

Multi-Tenancy:
- Per-config-id tenant isolation (directory-based configuration)
- Path traversal protection (rejects ".." and "/" in config_id)
- No per-tenant auth enforcement at guardrails layer
- Thread IDs are caller-provided (no tenant-scoped access control)
- Shared embedding model instance across tenants (thread-safe via async)

Build Hermeticity:
- Hermetic build: Yes (Tekton pipeline with hermetic: "true")

- All 879 pip packages SHA256-hash-pinned in requirements.txt
- ML models pinned in artifacts.lock.yaml (16 artifacts with SHA256)
