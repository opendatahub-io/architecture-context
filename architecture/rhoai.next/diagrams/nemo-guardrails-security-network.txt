RBAC Summary:
- No Kubernetes RBAC resources — standalone containerized service
- No ClusterRoles, Roles, or RoleBindings defined
- No ServiceAccount with elevated privileges required

Authentication Summary:
- Server-level: NONE — no built-in authentication or authorization
- External enforcement required: kube-rbac-proxy sidecar, Istio AuthorizationPolicy,
  or Kubernetes NetworkPolicy
- Header forwarding: X-Authorization remapped to Authorization for upstream LLM calls
- Input validation: Path traversal prevention for config IDs, minimum thread ID length,
  request header sanitization (strips infrastructure prefixes)

Secrets:
- LLM API keys (Opaque, env vars) — OPENAI_API_KEY, ANTHROPIC_API_KEY,
  AZURE_OPENAI_API_KEY, COHERE_API_KEY, GOOGLE_API_KEY
  Provisioned by: Manual / external secret management
  Auto-Rotate: No
  Note: Never persisted to disk; injected via env vars or forwarded from request headers

FIPS Compliance:
- OpenSSL: Inherited from RHEL 9.6 base image (AIPCC CPU base)
- TLS: System OpenSSL enforces FIPS-approved ciphers when host is in FIPS mode
- Crypto fallback: MD5 → SHA256 when MD5 unavailable (FIPS mode)
- Certificate trust: System trust store (REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt)
- Non-FIPS crypto: MD5 used for non-cryptographic content hashing and embedding cache keys only

Build Hermeticity:
- Konflux build: Fully hermetic ("hermetic": "true")
- Python deps: Prefetched via Hermeto pip handler (requirements.txt with hashes)
- ML models: Prefetched via Hermeto generic handler (artifacts.lock.yaml with SHA256)
- No runtime network access to PyPI or HuggingFace Hub
