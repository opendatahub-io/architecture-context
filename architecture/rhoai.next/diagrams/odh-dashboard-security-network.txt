SA Token Isolation:
- odh-dashboard SA: Full K8s API permissions (shell + kube-rbac-proxy)
  - automountServiceAccountToken: disabled, uses projected volume
- odh-dashboard-modules SA: Restricted permissions (BFF modules only)
  - Separate projected volume mount per BFF container
  - Limited blast radius if compromised

Secrets:
- dashboard-proxy-tls (kubernetes.io/tls) - TLS cert for kube-rbac-proxy,
  provisioned by OpenShift service-ca, auto-rotated
- gen-ai-proxy-tls (kubernetes.io/tls) - TLS cert for gen-ai standalone,
  provisioned by OpenShift service-ca, auto-rotated
- odh-dashboard-modules-token (kubernetes.io/service-account-token) -
  SA token for BFF modules, provisioned by Kubernetes, auto-rotated
- genai-pgvector-credentials (Opaque) - PostgreSQL credentials for
  pgvector auto-provisioning, provisioned by gen-ai BFF, NOT auto-rotated

Authentication Flow:
1. User authenticates via OAuth → obtains token
2. Token sent in Authorization header to Gateway
3. Gateway forwards to kube-rbac-proxy (8443/TCP TLS)
4. kube-rbac-proxy validates token, injects identity headers
5. Backend receives x-forwarded-access-token for upstream calls
6. BFF modules receive forwarded token for domain-specific API calls
7. K8s API calls use user's identity for RBAC enforcement

FIPS Compliance:
- Go BFFs: CGO_ENABLED=1, -tags strictfipsruntime, dynamic linking
- TLS 1.3 minimum for Go BFF HTTPS listeners
- All base images: UBI9 (FIPS-validated OpenSSL)
- esbuild Go binaries removed from node_modules for check-payload compliance

Network Policy (Sidecar Mode):
- Single NetworkPolicy opens ports 8043-8843 + broad egress
- Less granular than standalone mode

Network Policy (Standalone Mode):
- Per-module NetworkPolicy with precise egress rules
- Example: gen-ai allows egress only to MaaS (8243), MLflow (8343),
  K8s API (6443), DNS, and external HTTPS (443)
