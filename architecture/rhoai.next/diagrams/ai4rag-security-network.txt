Secrets Summary:
- OGX API Key (API Key) - Authentication to OGX server
  • Provisioned by: User (via OgxClient constructor or environment variable)
  • Auto-rotate: No
- AWS_ACCESS_KEY_ID (AWS Credential) - S3 storage authentication
  • Provisioned by: Environment variable or Kubernetes Secret
  • Auto-rotate: No
- AWS_SECRET_ACCESS_KEY (AWS Credential) - S3 storage authentication
  • Provisioned by: Environment variable or Kubernetes Secret
  • Auto-rotate: No
- AWS_S3_ENDPOINT (Endpoint URL) - S3-compatible endpoint address
  • Provisioned by: Environment variable or Kubernetes Secret
  • Auto-rotate: No

RBAC Summary:
- No Kubernetes RBAC — ai4rag is a Python library, not a Kubernetes operator.
- RBAC is the responsibility of the consuming workload.

Crypto Summary:
- hashlib.sha256: Used for deterministic chunk ID generation (NOT cryptographic security)
- httpx TLS: Default TLS for OGX Server connections
- boto3 TLS: Default TLS for S3 connections
- ⚠ SSL verify=False fallback: create_ogx_client() silently downgrades to unverified TLS
  on self-signed certificates. Potential MITM risk in production deployments.

Authentication Summary:
| Endpoint              | Methods                    | Auth Mechanism              | Enforcement Point |
|-----------------------|----------------------------|-----------------------------|-------------------|
| OGX Server            | REST (POST, GET, DELETE)   | API Key (Bearer Token)      | OGX Server        |
| S3-compatible storage | REST (GET, PUT, DELETE)    | AWS IAM (Access Key+Secret) | S3 endpoint       |

FIPS Compliance:
- ai4rag is a Python library (no container image, no Go binary)
- FIPS build-time validation is the responsibility of the consuming container
- hashlib.sha256 usage is for chunk IDs (not security-critical)
- SSL verify=False fallback is a non-FIPS concern for production
