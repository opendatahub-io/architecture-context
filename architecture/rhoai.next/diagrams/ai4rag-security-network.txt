RBAC Summary:
─────────────
No Kubernetes RBAC defined. The library runs as a Python import within the
caller's process and inherits whatever service account permissions the caller
has (e.g., a KFP pipeline runner's ServiceAccount).

Credentials / Secrets:
──────────────────────
All credentials are passed via environment variables:

  | Variable              | Purpose                              | Provisioned By    |
  |-----------------------|--------------------------------------|-------------------|
  | OGX_CLIENT_BASE_URL   | OGX server endpoint URL              | User / KFP        |
  | API_KEY               | OGX API authentication key           | User / KFP        |
  | AWS_ACCESS_KEY_ID     | S3 authentication                    | User / KFP        |
  | AWS_SECRET_ACCESS_KEY | S3 authentication                    | User / KFP        |
  | AWS_S3_ENDPOINT       | S3-compatible storage endpoint       | User / KFP        |

  Note: No auto-rotation. Credentials are not managed by the library.
  All invocations in the same process share the same environment variables.

Security Concerns:
──────────────────
1. SSL VERIFICATION FALLBACK (HIGH):
   Both OGX client and S3 client silently retry with verify=False on SSL
   certificate errors. This bypasses certificate validation and enables
   potential man-in-the-middle attacks. No mechanism exists to disable
   this fallback or enforce strict TLS.

2. SHARED CREDENTIALS (MEDIUM):
   All library invocations within the same process share environment
   variables. No per-experiment credential isolation.

3. NO CIPHER SUITE RESTRICTIONS (LOW):
   No explicit cipher suite configuration. Relies on system defaults
   from httpx and boto3/botocore (which delegate to system OpenSSL).

4. ORPHANED VECTOR STORE COLLECTIONS (LOW):
   Per-experiment OGX vector store collections are not automatically
   cleaned up. Orphaned collections may accumulate with residual data.
