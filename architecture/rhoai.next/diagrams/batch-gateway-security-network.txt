Multi-Tenancy:
- Tenant boundary: X-MaaS-Username header (injected by upstream gateway)
- Data isolation: Application-level query scoping by tenant ID
- Risk: No per-tenant resource quotas; shared PostgreSQL/Redis/S3 instances
- Risk: API is fully open if deployed without upstream auth gateway

Authentication Flow:
1. Client authenticates to upstream gateway (Kuadrant/Authorino)
2. Gateway validates credentials (API key, SA token, or OpenShift token)
3. Gateway injects tenant ID via X-MaaS-Username header
4. API Server extracts tenant ID from header (defaults to "default" if absent)
5. All database queries scoped to extracted tenant ID
6. Cross-tenant access returns 404
