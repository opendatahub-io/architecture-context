RBAC Summary:
- No Kubernetes RBAC — batch-gateway does not interact with the Kubernetes API.
  All components connect only to external databases and inference endpoints.

Secrets:
- batch-gateway-secrets (Opaque) — Manual provisioning, no auto-rotation
  Contains: redis-url, postgresql-url, inference-api-key, s3-secret-access-key
- {release}-batch-gateway-apiserver-tls (kubernetes.io/tls) — cert-manager (optional) or manual
  Contains: TLS certificate and key for apiserver HTTPS
  Rotation: Yes (if cert-manager), otherwise manual

Authentication Model:
- Tenant identity via X-MaaS-Username header (configurable)
- NO API key or JWT validation in the apiserver itself
- Relies on upstream proxy for authentication (e.g., Envoy ext_authz, kube-rbac-proxy)
- Authorization header is captured and forwarded to inference backends
- Tenant isolation: database queries filtered by tenant_id → mismatched tenant returns 404

FIPS Compliance:
- All three binaries: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1
- Base image: UBI 9 ubi-minimal (provides OpenSSL for FIPS crypto at runtime)
- TLS: MinVersion=TLS 1.2, configurable InsecureSkipVerify for testing
- Custom CA bundle support (TLSCACertFile), mTLS client certs (TLSClientCertFile/Key)
- No weak crypto: No MD5, RC4, DES, or weak ciphers detected

Security Headers (Apiserver):
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY
- Content-Security-Policy: default-src 'none'
- Referrer-Policy: no-referrer

Critical Security Note:
- The apiserver MUST NEVER be exposed directly without an authenticating proxy.
  It performs no authentication — tenant identity is trusted from headers.
