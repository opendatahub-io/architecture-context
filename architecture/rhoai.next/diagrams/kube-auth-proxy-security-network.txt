RBAC Summary:
- ClusterRole: (not bundled - managed by deploying operator)
  - API Groups: authentication.k8s.io
  - Resources: tokenreviews
  - Verbs: create
  Note: The deploying operator (e.g., odh-notebook-controller,
        rhods-operator) must grant this permission when K8s token
        validation is enabled.

Authentication Chain (ordered):
1. Kubernetes TokenReview (Bearer token with K8s SA token)
2. JWT/OAuth token validation
3. Basic Auth (htpasswd)
4. Stored session (cookie)
Note: Ordering is security-significant. K8s TokenReview runs first,
      allowing service account tokens to bypass provider-specific auth.

Secrets:
- kube-auth-proxy-secret (Opaque) - Cookie encryption secret (32-byte
  base64), provisioned by operator, no auto-rotation
- ServiceAccount token (kubernetes.io/service-account-token) - OAuth client
  secret for OpenShift provider; bearer token for K8s API calls, auto-rotated
  (bound token)

FIPS Compliance:
- Build: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime
- Runtime: UBI 9 ubi-minimal-pqc base image with OpenSSL
- TLS: crypto/tls with FIPS-compliant OpenSSL backend at runtime
- Non-FIPS risks: SHA-256 for non-security cache keys (acceptable)

Envoy ext_authz Integration:
- Endpoint: /oauth2/auth
- Response: 202 Accepted (authenticated) or 401/403 (unauthenticated)
- Purpose: Compatible with Gateway API-based ingress architecture
