RBAC Summary:
- MLServer does NOT define Kubernetes RBAC resources
- Runs as non-root container (UID 1000) within KServe pods
- ServiceAccount: Managed by KServe (per InferenceService)
- No ClusterRoles, no ClusterRoleBindings

Service Mesh Configuration:
- MLServer does not configure service mesh directly
- TLS/mTLS enforced by KServe platform ingress layer
- Pod-level network policies managed by KServe/platform operator

Secrets:
- MLServer does NOT define or consume Kubernetes Secrets
- TLS certificates: Managed by KServe/platform (cert-manager)
- Model storage credentials: Mounted by KServe init containers
- No direct secret references in MLServer code

Application Security Controls:
- Trusted Runtimes Allowlist:
  - File: /etc/mlserver/trusted-runtimes.json
  - Generated at build time from TRUSTED_RUNTIMES build arg
  - Enforced at: ModelSettings parsing + implementation property access
  - Prevents: Arbitrary code execution from user model-settings.json
- CORS Policy (production mode):
  - Wildcard origins (*): FORBIDDEN
  - Regex patterns: FORBIDDEN
  - Only explicit origin strings allowed
- Custom Environments (production mode):
  - environment_tarball: BLOCKED
  - environment_path: BLOCKED
  - Prevents sys.path manipulation

FIPS Compliance:
- Python service — inherits crypto from RHEL 9.6 AIPCC base image
- OpenSSL: FIPS-capable (inherited from UBI base)
- No TLS termination in MLServer (delegated to platform)
- Non-FIPS risk: batch_processing.py ssl_context=False (loopback only)
- No explicit crypto library imports

Container Security:
- Base images: quay.io/aipcc/base-images/cpu:3.5 (CPU)
                quay.io/aipcc/base-images/cuda-12.9-el9.6:3.5 (CUDA)
- User: UID 1000 (non-root)
- Build: Konflux hermetic builds with pip hash verification
- Lock files: Poetry (11 lock files), requirements-cpu.txt, requirements-cuda.txt
