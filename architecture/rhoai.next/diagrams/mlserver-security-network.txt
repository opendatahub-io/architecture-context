RBAC Summary:
- MLServer defines NO Kubernetes RBAC resources
- Runs as unprivileged container (UID 1000)
- Pod RBAC managed by KServe service account
- API access gated by kube-rbac-proxy sidecar (RHOAI 3.x)

Authentication & Authorization:
- All /v2/* endpoints: No application-level auth
  Enforcement: kube-rbac-proxy sidecar (RHOAI 3.x) performs SubjectAccessReview
- /metrics (8082): No auth, restricted by NetworkPolicy
- Trusted Runtimes: Image-baked allowlist restricts loadable model implementations
- CORS: Wildcard origins ('*') rejected in PRODUCTION mode
- Custom environments: environment_tarball and environment_path disabled in PRODUCTION

Secrets:
- No Kubernetes secrets directly managed by MLServer
- Model storage credentials injected via KServe storage credential mechanism
- TLS certificates managed by kube-rbac-proxy sidecar

FIPS Compliance:
- Python service (no Go binaries, no GOEXPERIMENT=strictfipsruntime)
- OpenSSL provided by AIPCC/UBI base image
- No direct crypto library usage
- OpenTelemetry exporter uses insecure=True (plaintext gRPC, expected for in-cluster)
- No non-FIPS crypto risks detected (no MD5, RC4, DES, custom crypto)

Build Security:
- Konflux hermetic builds (hermetic: true in Tekton pipelines)
- Python deps pinned with SHA256 hashes (requirements-cpu.txt, requirements-cuda.txt)
- Dependencies resolved against RHEL AI Python Package Index (Red Hat-approved packages)
- AIPCC base images: quay.io/aipcc/base-images/cpu:3.5, cuda-12.9-el9.6:3.5
