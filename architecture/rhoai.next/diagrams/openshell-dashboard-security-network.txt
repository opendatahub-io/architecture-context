RBAC Summary:
- No Kubernetes RBAC roles — BFF is a user-space HTTP server
- Does not access the Kubernetes API
- All authorization delegated to OpenShell gateway
- Gateway enforces workspace-level RBAC per bearer token

Authentication Architecture:
- Auth Proxy (oauth2-proxy / kube-auth-proxy):
  - Handles OIDC/OAuth2 authentication flows
  - Manages browser sessions and CSRF protection
  - Injects bearer token via x-forwarded-access-token header
  - Injects username via x-auth-request-user header
- BFF Token Relay:
  - Extracts token from: proxy header → Authorization header → 401
  - Never validates tokens — pure relay
  - AUTH_DISABLED flag for development only
- OpenShell Gateway:
  - Validates JWT against OIDC IdP's JWKS endpoint
  - Enforces workspace membership and RBAC

Multi-Tenancy:
- Tenant boundary: per-workspace (delegated to gateway)
- Deployment model: single-instance multi-tenant
- Tenant identifier: workspace name (URL path parameter)
- BFF does NOT independently verify workspace membership

Secrets:
- TLS_CERT_FILE / TLS_KEY_FILE (file mount) — Inbound BFF HTTPS cert, manual/cert-manager, no auto-rotate
- GATEWAY_CA_CERT (file mount) — CA cert for gateway TLS verification, manual, no auto-rotate
- GATEWAY_CLIENT_CERT / GATEWAY_CLIENT_KEY (file mount) — mTLS client cert for gateway, manual, no auto-rotate

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1 (dynamic linking with OpenSSL)
- Base images: Digest-pinned UBI 9 (nodejs-22, go-toolset:1.26, ubi-minimal:9.8)
- Inbound TLS: crypto/tls with MinVersion TLS 1.3
- Outbound TLS: crypto/tls with MinVersion TLS 1.2 (raw exec client)
- No non-FIPS crypto risks detected

Security Risks:
- BFF trusts proxy-injected header — must be network-isolated to prevent header spoofing
- If BFF port (8080) is directly exposed, any client can present arbitrary bearer tokens
- BFF does not independently verify workspace membership (delegated to gateway)
