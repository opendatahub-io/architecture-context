RBAC Summary:
  No RBAC roles or bindings — no Kubernetes manifests in repository.
  Deployment, RBAC, and network policies are managed by the deploying
  operator (e.g., TrustyAI operator or guardrails orchestrator operator).

Service Mesh Configuration:
  No service mesh configuration in repository.
  Transport security (mTLS) is expected to be provided by the platform
  service mesh (e.g., Istio / OpenShift Service Mesh).

Secrets:
  No secrets consumed or referenced by the application.

Authentication & Authorization:
  No authentication or authorization at the application level.
  All access control relies on platform-level enforcement:
  - Kubernetes NetworkPolicy to restrict pod-to-pod access
  - Service mesh mTLS for transport encryption
  - Service mesh AuthorizationPolicy for caller identity verification

Security Notes:
  - Regex patterns are compiled per-request (no caching)
  - The `regex` crate uses finite automaton matching (ReDoS resistant)
  - Pattern compilation overhead exists but catastrophic backtracking is prevented
  - No cryptographic operations performed by the application
  - compat-openssl11 installed in image for system library compatibility only
  - No Konflux Dockerfile exists; standard Dockerfile uses Debian builder + UBI 9 release
