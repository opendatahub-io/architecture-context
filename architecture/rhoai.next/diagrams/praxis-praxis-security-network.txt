FIPS Compliance:
- Crypto Provider: System OpenSSL exclusively (no aws-lc-rs, no ring at runtime)
- FIPS Enforcement: PRAXIS_REQUIRE_FIPS env var checks:
  1. Kernel FIPS flag (/proc/sys/crypto/fips_enabled)
  2. Provider's self-reported FIPS status
  → Refuses to start if either check fails
- FIPS Build: UBI 9 base, excludes policy engine (ppe depends on aws-lc-rs/sha2/hmac)
- Validation: `cargo xtask fips report` checks binary against FIPS-denied crate list
- cargo-auditable: Embeds crate manifest for Red Hat scanner in FIPS image

Secrets:
- TLS certificates (File-based PEM) - Server TLS termination
  Provisioned by: Operator / cert-manager / certbot
  Auto-rotate: Yes (hot-reload via filesystem watcher)
- TLS private keys (File-based PEM) - Server TLS key
  Provisioned by: Operator / cert-manager / certbot
  Auto-rotate: Yes (hot-reload)
- Client CA certificates (File-based PEM) - mTLS client verification
  Provisioned by: Operator
  Auto-rotate: No (requires config reload)
- Cluster TLS client certs (File-based PEM) - mTLS to upstream servers
  Provisioned by: Operator
  Auto-rotate: No (requires config reload)

Reserved Header Security:
- Prefixes: x-praxis-*, x-ext-protocol-*, x-ext-agent-*
- Client requests with these headers: Rejected with HTTP 400
- Upstream responses with these headers: Stripped before forwarding to client
- Purpose: Unspoofable metadata channel for internal filter communication
  (e.g., json_body_field promotes model name to x-praxis-guard-model)
