================================================================================
SERVICE MESH CONFIGURATION
================================================================================

Mode: MIXED (not platform-wide STRICT)
- Istio STRICT mTLS: model-registry, models-as-a-service
- Istio PERMISSIVE mTLS: caikit-tgis-serving
- SPIFFE mTLS: agents-operator AuthBridge (separate trust domain)
- Component-level TLS elsewhere (kube-rbac-proxy, service-serving certs)

PeerAuthentication:
- Namespace-scoped for model-registry, MaaS
- Not mesh-wide enforcement

AuthorizationPolicy:
- model-registry (service-to-service access control)
- models-as-a-service (service-to-service access control)

Certificate Sources:
- OpenShift service-serving certificates (automatic, annotation-based)
- cert-manager (agents-operator, modelmesh, kserve, llm-d, workbenches)
- Self-signed (operator-managed)

TLS Security Profile:
- Aligned with cluster-wide OpenShift TLS profile for:
  rhods-operator, trustyai-service-operator, model-registry-operator,
  workbenches-operator, feast-operator, odh-model-controller, kuberay,
  spark-operator, trainer
