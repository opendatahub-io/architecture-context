MULTI-TENANCY:
- Tenant boundary: per-namespace (X-Tenant header maps to namespace)
- Deployment model: multi-tenant; single EvalHub serves multiple tenants
- Data isolation: SQL row-level filtering via WithTenant() / WithOwner()
- No database-level row security or schema separation
- K8s Job pods run in tenant namespaces
- Per-namespace secrets for model auth, MLflow tokens, OCI credentials

SECRETS:
- model-auth (Opaque) - Model endpoint credentials; User/Operator provisioned; No auto-rotate
- mlflow-token (Opaque) - MLflow bearer token; Operator/Manual; No auto-rotate
- oci-credentials (dockerconfigjson) - OCI registry auth; User/Operator; No auto-rotate
- test-data-s3 (Opaque) - AWS credentials for S3; User/Manual; No auto-rotate
- TLS certs (kubernetes.io/tls) - Server TLS cert+key; cert-manager/Manual; Depends on provisioner
- service-ca (ConfigMap) - OpenShift service CA bundle; Service CA Operator; Yes (auto)

RBAC:
- RBAC manifests managed by TrustyAI Service Operator (not in eval-hub repo)
- K8s runtime requires: create/get/delete Jobs, ConfigMaps, Secrets
- Permissions granted via operator's ServiceAccount

FIPS COMPLIANCE:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, dynamic linking
- TLS: MinVersion 1.2, MaxVersion 1.3; InsecureSkipVerify rejected in FIPS mode
- Crypto: stdlib crypto/tls (FIPS via OpenSSL under strictfipsruntime)
- No non-FIPS crypto (MD5/RC4/DES) detected in codebase

AUTHENTICATION FLOW:
- External → kube-rbac-proxy: OAuth/Bearer Token → validated → X-Tenant + X-User injected
- EvalHub validates: X-Tenant required in cluster mode; X-User required in cluster mode
- Sidecar → EvalHub: K8s SA Token (projected, 5-min cache)
- Sidecar → MLflow: File-based Bearer Token (from mounted secret, 5-min cache)
- Sidecar → OCI: Docker config.json + challenge-response token exchange
- Sidecar → Model: Ref token resolution (api-key:ref → secret lookup) / SA Token fallback
