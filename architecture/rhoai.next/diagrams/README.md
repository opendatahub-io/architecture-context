## How to Use

### Mermaid Diagrams (.mmd files)
- **In GitHub/GitLab**: Paste into markdown with ` ```mermaid ` code blocks
- **Render to PNG locally**:
   ```bash
   PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome mmdc -i diagram.mmd -o diagram.png -s 3
   ```
- **Online viewer**: Paste contents at https://mermaid.live

### ASCII Diagrams (.txt files)
- View in any text editor
- Include directly in security documentation
- Perfect for SAR (Security Architecture Review) submissions

## Diagram Descriptions

### Component Dependency Graph
Shows how platform components depend on each other. Central components are highlighted:
- **KServe** (17 reverse dependencies) — gravitational center of the serving stack
- **rhods-operator** (15 reverse dependencies) — platform control plane
- **Kueue** (8 reverse dependencies) — shared job scheduling fabric
- **kube-rbac-proxy** (8 reverse dependencies) — standard auth sidecar

Color scheme: gray (platform operator), blue (core serving), green (data science), purple (LLM/GenAI), red (MaaS gateway), orange (gateway infrastructure).

### Platform Network Topology
Complete network architecture showing all ingress points, namespace isolation, service mesh communication, and egress destinations. Includes exact port numbers, protocols, encryption, and authentication mechanisms.

**Two formats provided**:
- **Mermaid (.mmd)**: Visual diagram with color-coded trust zones (External, Ingress, Operator NS, Platform NS, MaaS NS, User NS, Mesh, Egress). Great for presentations and architecture discussions.
- **ASCII (.txt)**: Precise text format with no ambiguity. Includes full authentication summary (7 patterns), RBAC summary (808 roles), and network policy inventory (32 policies). Required for SAR (Security Architecture Review) submissions and compliance documentation.

Both formats contain the same information — use Mermaid for visual clarity, ASCII for security reviews.

### Cross-Component Workflows
Five sequence diagrams showing end-to-end workflows:
1. **LLM Model Deployment and Serving** — Dashboard → KServe → vLLM → EPP → Envoy → Client
2. **Multi-Tenant Model Access (MaaS)** — Admin → maas-controller → payload-processing → Authorino → KServe
3. **Data Science Pipeline Execution** — Dashboard → DSP → Argo → MLMD → Model Registry → KServe
4. **Distributed Training with Job Scheduling** — Dashboard → Training Operator → Kueue → K8s Scheduler → Workers
5. **Model Fairness and Evaluation** — Dashboard → TrustyAI → lm-evaluation-harness → Model Registry

### Platform Security Overview
Visual representation of the platform's defense-in-depth security architecture:
- **7 authentication mechanisms** (kube-rbac-proxy, OAuth2/OIDC, Kuadrant AuthPolicy, API Key SHA-256, mTLS, Bearer SA, SA token isolation)
- **Top privileged ClusterRoles** (highlighted in red)
- **Critical secrets** (credential secrets in yellow, TLS certs in light yellow)
- **TLS configuration** per component type (blue)
- **Container security** patterns: 70% non-root, 38% UBI, 4% distroless (green)
- **32 NetworkPolicies** across 12 components
- **Service mesh security** (MIXED mTLS mode, not mesh-wide STRICT)

### Platform Observability
Maps all monitoring and observability endpoints:
- **Prometheus scrape targets**: 12+ component metrics endpoints (most via kube-rbac-proxy on :8443)
- **Health probes**: Liveness/readiness for 10+ components (standard :8081 healthz/readyz pattern)
- **Distributed tracing**: Tempo backend + OpenTelemetry Collector (auto-instrumentation) + Perses dashboards
- **Key metrics categories**: Inference (latency, KV cache), Training (GPU utilization, Kueue wait), Platform (reconciliation), Gateway (per-tenant rate)

### Platform Maturity Dashboard
High-level metrics organized by domain:
- **Component Statistics**: 87 total (31 operators, 31 services, 7 SDKs, 12 image repos, 517 Dockerfiles)
- **Security Posture**: MIXED mTLS, 7 auth patterns, 70% non-root, 808 RBAC roles
- **API Surface**: 175 CRDs, 91 gRPC services, 583 HTTP endpoints, 175 ClusterIP services
- **Deployment Readiness**: Leader election HA, disconnected support, 4 CPU architectures, OCP v4.16-v4.19
- **Ingress Migration**: 26 OpenShift Routes → 21 HTTPRoutes (Gateway API transition in progress)
- **API Maturity**: DSC v1→v2, InferencePool v1alpha2→v1, MaaS namespace migration
