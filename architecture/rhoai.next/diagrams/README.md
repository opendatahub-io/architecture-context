## How to Use


- **Online viewer**: Paste content at https://mermaid.live

## Diagram Descriptions

### Component Dependency Graph
Shows how platform components depend on each other across the three-tier operator hierarchy (rhods-operator → module operators → workload operators). Central components (KServe, odh-dashboard, rhods-operator) are highlighted. Groups include: Platform Control Plane, AI/ML Serving Stack, AI Gateway, Data Science Workflows, Model Management, Workbenches, Distributed Training, Trust & Safety, Agent Infrastructure, and Platform Services.

### Platform Network Topology
Complete network architecture showing all ingress points (Gateway API with Envoy, HTTPRoutes), inter-namespace communication, service mesh configuration (MIXED mTLS), and egress destinations. Covers 6 namespace groups: redhat-ods-operator, redhat-ods-applications, redhat-ai-gateway-infra, istio-system/knative-serving, user namespaces, and redhat-ods-monitoring.

**Two formats provided**:
- **Mermaid (.mmd)**: Visual diagram with color-coded trust zones. Great for presentations and architecture discussions.
- **ASCII (.txt)**: Precise text format with exact ports, protocols, TLS versions, auth mechanisms, and ServiceAccount details. Required for SAR (Security Architecture Review) submissions and compliance documentation.

Both formats contain the same information — use Mermaid for visual clarity, ASCII for security reviews.

### Cross-Component Workflows
Sequence diagrams showing three major end-to-end workflows:
1. **LLM Model Serving** — Client request through Gateway API → Kuadrant AuthPolicy → llm-d EPP (scoring plugins) → vLLM inference pod → streaming response
2. **Notebook Workbench Lifecycle** — Dashboard UI → webhook validation → Kubeflow controller → ODH controller (sidecar injection, HTTPRoute, ambient config for DSPO/MLflow/Feast) → kube-rbac-proxy auth → notebook session
3. **Model Registration and Deployment** — Model Registry API → PostgreSQL persistence → KServe InferenceService with model-registry:// URI → storage initializer → TrustyAI explainability patching

### Platform Security Overview
Visual representation of the platform's defense-in-depth security architecture:
- **7 authentication mechanisms**: kube-rbac-proxy (15+ components), Kuadrant/Authorino, kube-auth-proxy OAuth2/OIDC, K8s SA tokens, OAuth proxy, SPIFFE/mTLS, Istio AuthorizationPolicy
- **RBAC landscape**: 913 roles across 37 operators, 187 CRDs across 41 API groups
- **Container security**: UBI9-minimal (64), distroless (20), FIPS-compliant builds, non-root, Konflux/Tekton hermetic builds
- **FIPS compliance gaps**: Rust components (ring/rustls), CGO_ENABLED=0 modules, Token Broker
- **TLS risks**: InsecureSkipVerify in DSPO/Feast, NoVerifier in fms-guardrails-orchestrator
- **Service mesh**: MIXED mTLS (STRICT for model-registry/MaaS, PERMISSIVE for caikit-tgis), 37 NetworkPolicies

### Platform Observability
Maps all monitoring and observability infrastructure:
- **Prometheus**: 26+ scrape targets, most via kube-rbac-proxy on port 8443, ServiceMonitor/PodMonitor discovery
- **Multi-tenant isolation**: prom-label-proxy for namespace-scoped queries, Thanos Querier for federation
- **Distributed tracing**: OpenTelemetry Collector → Tempo, instrumented in KServe, DS Pipelines, llm-d, vLLM
- **Dashboarding**: Perses platform dashboards, MetricsDashboard CRs per InferenceService
- **Conditional deployment warning**: Observability stack varies by cluster — each component conditionally deployed based on CRD availability (MonitoringStack, Tempo, OpenTelemetryCollector, Perses)
- **Health probes**: Liveness and readiness endpoints for all operators (typically :8081 healthz/readyz)

### Platform Maturity Dashboard
High-level metrics about platform health and readiness:
- 96 components, 37 operators, 554 container images, 285 services, 630 API endpoints, 110 gRPC definitions
- MIXED mTLS enforcement, 7 authentication patterns, 913 RBAC roles
- CRD API maturity: v1 stable for core, v1beta1 for serving, v1alpha1/v1alpha2 for newer features
- Deployment: leader election HA, RELATED_IMAGE disconnected support, Gateway API migration in progress
- Multi-arch: amd64 (full), arm64 (partial), ppc64le/s390x (limited)
