Cross-Namespace Secret Resolution:
- Mechanism: Gateway API ReferenceGrant
- Operator lists ReferenceGrants in target namespace
- Validates that batch.llm-d.ai/LLMBatchGateway from CR namespace is permitted
- Copies permitted Secret to CR namespace as {gw-name}-credentials
- secretRef is immutable after first copy (prevents credential-swapping attacks)

Secrets:
- {gw-name}-credentials (Opaque) - Cross-namespace copy of source secret, re-synced on change
- spec.secretRef.name (Opaque) - Runtime credentials (DB URL, S3 keys, inference API key)
- spec.tls.secretName (kubernetes.io/tls) - TLS cert/key for API server (cert-manager or manual)

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, UBI 9 base
- TLS: Delegated to managed components via Helm values
- Gap: AsyncTLSSpec.InsecureSkipVerify not blocked at CRD level (sync mode blocks it)

Network Isolation Gaps:
- No NetworkPolicy created by operator for managed workloads
- No network isolation between batch gateway instances in different namespaces
- Operator metrics endpoint (8443/TCP) has no encryption or authentication
- Health probes (8081/TCP) are plaintext HTTP
