RBAC Summary:
- OVMS does NOT define RBAC resources
- Runs as unprivileged container (UID 5000)
- Does not interact with the Kubernetes API
- RBAC is managed by KServe / RHOAI operator for the enclosing pod

Authentication Summary:
- /v3/* endpoints: Bearer Token (optional, validated against --api_key_file or API_KEY env)
- /v1/*, /v2/* endpoints: No application-level authentication
- /metrics: No authentication
- Platform-level auth handled by Gateway API / kube-rbac-proxy (external to OVMS)

Secrets:
- api-key (Opaque) — API key for v3 endpoint auth — Manual provisioning — No auto-rotate
- hf-token (Opaque) — HuggingFace auth token — Manual (HF_TOKEN env) — No auto-rotate
- aws-credentials (Opaque) — AWS S3 access — Manual (AWS SDK env vars) — No auto-rotate
- gcs-credentials (Opaque) — GCS access — Manual (ADC / GOOGLE_APPLICATION_CREDENTIALS) — No auto-rotate
- azure-credentials (Opaque) — Azure storage — Manual (AZURE_STORAGE_CONNECTION_STRING) — No auto-rotate

Crypto Notes:
- No native TLS on gRPC or REST endpoints (plaintext; TLS termination external)
- Outbound TLS via system OpenSSL (UBI 9 base image)
- Uses OpenSSL MD5 for file integrity checksums (not cryptographic use)
- C++ binary — not subject to Go-specific FIPS checks (check-payload)
- Dynamic linking against system OpenSSL from UBI 9

Container Security:
- Base image: registry.access.redhat.com/ubi9/ubi-minimal:9.8
- Runs as UID 5000 (non-root)
- No Kubernetes API interaction
- No CRDs defined or managed
