RBAC Summary:
- OVMS does not define its own RBAC resources
- RBAC is managed by KServe for InferenceService pods
- KServe creates ServiceAccount per InferenceService

Security Context (from ServingRuntime definitions):
- runAsNonRoot: true (UID 5000)
- capabilities: drop ALL
- allowPrivilegeEscalation: false

Authentication & Authorization:
- REST endpoints: Optional Bearer token via --api_key_file or API_KEY env var
  - Single shared key for all callers (no per-user auth)
  - Health probes (/v2/health/*) and /metrics: always unauthenticated
- gRPC endpoints: No authentication (InsecureServerCredentials)
  - Relies on platform-level mTLS (Istio/Service Mesh)
- Optional nginx-mtls-auth sidecar for mTLS when no service mesh

Secrets:
- Model storage credentials: Injected by platform (KServe storage initializer or env vars)
- API key: Mounted via --api_key_file or set as API_KEY env var
- HuggingFace token: HF_TOKEN env var (optional)
- No auto-rotation managed by OVMS

Crypto Concerns:
- MD5 used for filesystem model file checksums (openssl/md5.h)
  - Not security-sensitive (integrity, not authentication)
  - May trigger failures in strict FIPS 140-2/3 enforcement mode
- Base image: ubi9/ubi-minimal-pqc (post-quantum cryptography variant)
- Outbound TLS uses system OpenSSL and CA trust store
