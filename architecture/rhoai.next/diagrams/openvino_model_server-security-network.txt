RBAC Summary:
  OVMS does not define its own RBAC resources. RBAC is managed by:
  - KServe: Manages pod creation and service account for InferenceService
  - RHOAI Operator: Creates kube-rbac-proxy sidecar for auth enforcement
  - Platform: NetworkPolicies (if configured by operator)

Secrets:
  - Cloud storage credentials injected via environment variables by KServe:
    - AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY (S3)
    - AZURE_STORAGE_CONNECTION_STRING (Azure)
    - GCP service account JSON (GCS)
    - HF_TOKEN (HuggingFace)
  - OVMS does not define or manage Secrets directly

TLS Configuration:
  - gRPC: InsecureServerCredentials() — no TLS
  - HTTP: Drogon with no SSL config — no TLS
  - TLS delegated to platform ingress layer (Routes, Gateway, kube-rbac-proxy)
  - Crypto: OpenSSL MD5 for model file checksums (non-security, cache keys only)
  - Certificate handling: libgit2 uses system trust store for HF Hub

Container Security:
  - Runs as non-root user: ovms (UID 5000)
  - No privilege escalation allowed
  - All Linux capabilities dropped
  - Base image: UBI 9 Minimal
  - SSRF protection: allowed_media_domains whitelist for VLM image URLs
  - Path traversal protection: allowed_local_media_path restriction

FIPS Compliance:
  - C++ binary (not Go — check-payload primarily validates Go binaries)
  - Dynamically links system OpenSSL from UBI 9 (FIPS-validated module)
  - No TLS termination in application
  - MD5 usage: OpenSSL MD5 for model file caching (not security-sensitive)
