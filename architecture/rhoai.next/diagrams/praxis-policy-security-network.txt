RBAC Summary:
- N/A. PPE is an embeddable Rust library, not a Kubernetes workload.
- Authorization is enforced internally via policy decision points (Cedar/CEL/OPA)
  operating on verified identity attributes from JWT/API-key plugins.

Secrets:
- IdP client credentials (oauth/client_secret) - Token exchange, operator-provisioned
- API keys (SHA-256 digest) - Identity verification, operator-managed, never stored plaintext
- Vault token (string) - Vault KV v2 auth, lazy renewal on read
- Valkey password (string) - Session store auth, operator-managed
- HMAC secret (32 bytes, getrandom) - Per-process OAuth cache-key derivation, ephemeral

Crypto Stack:
- TLS: rustls 0.23 with ring provider (not FIPS-validated)
  - Explicit ring selection (no process-wide default, avoids races with host)
  - TLS 1.2 + 1.3 (1.2 kept for enterprise IdP compatibility)
  - WebPKI root certificates from Mozilla (webpki-roots crate)
- JWT: jsonwebtoken 11 with aws_lc_rs backend
  - Avoids RUSTSEC-2023-0071 (Marvin timing sidechannel in pure-Rust rsa)
- Hashing: SHA-256 (sha2 0.11) for API-key index, cache keys, session keys
- HMAC: hmac 0.13 (HMAC-SHA256 for OAuth cache-key derivation)
- RNG: getrandom 0.4 for HMAC secret generation
- Memory: zeroize 1.9 for secure erasure of secret material

Supply Chain:
- Cargo.lock pins all transitive dependencies
- cargo-deny enforces: advisory checks, license allow-list (Apache-2.0, MIT, BSD, MPL-2.0),
  no git dependencies, crates.io only, duplicate version warnings
- OPA (regorus): restricted builtins - no http.send, no net, no opa.runtime, no jsonschema
