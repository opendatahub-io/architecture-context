Application-Level Auth Summary:
- Auth Middleware: JWT/OAuth2/Custom bearer token validation (OPTIONAL)
- Access Control: Cedar-like permit/forbid rules with resource ownership
- Rate Limiting: Per-client quotas (100/day anonymous, 1000/day authenticated)
- Unauthenticated endpoints: /v1/health, /v1/version, /v1/inspect/routes

Multi-Tenancy:
- Deployment: Multi-tenant (single server, multiple users)
- Tenant ID: JWT claims (sub) + user attributes
- Data isolation: Application-level (shared KV/SQL store, resource ownership tracking)
- Compute isolation: None (all tenants share inference providers)
- Network isolation: None (no NetworkPolicy or Istio AuthorizationPolicy)

FIPS Compliance Gaps:
- python-jose uses pure Python RSA/ECDSA (NOT FIPS-validated)
- Base image is python:3.12-slim (NOT UBI) — fails check-payload
- No Konflux Dockerfiles on this branch
- No OLM FIPS annotation

Secrets:
- No Kubernetes Secrets defined (provider API keys are environment/config-level)
- Provider credentials: API keys for cloud services, DB passwords
- JWT signing keys: Retrieved from JWKS endpoint (not stored locally)
