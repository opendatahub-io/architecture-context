TLS Configuration:
- Server TLS enabled via config.runtime.tls settings
- Supports TLS and mTLS (client cert verification)
- Uses Python ssl module (grpc.ssl_server_credentials for gRPC)
- Relies on system OpenSSL (FIPS from container base image)
- Certificate sources: file path or inline PEM

Secrets:
- runtime.tls.server.key (TLS private key) - gRPC/HTTP server TLS, cert-manager, no auto-rotate
- runtime.tls.server.cert (TLS certificate) - gRPC/HTTP server TLS, cert-manager, no auto-rotate
- runtime.tls.client.cert (TLS CA cert) - Client cert verification (mTLS), manual, no auto-rotate
- runtime.trace.tls.ca (TLS CA cert) - OTel exporter TLS, manual, no auto-rotate
- runtime.trace.tls.client_key (TLS private key) - OTel exporter mTLS, manual, no auto-rotate
- runtime.trace.tls.client_cert (TLS certificate) - OTel exporter mTLS, manual, no auto-rotate

RBAC Summary:
- N/A — Caikit is a library. RBAC is defined by consuming deployments.
- No ClusterRoles, Roles, or RoleBindings defined.

Authentication & Authorization:
- No application-level auth built into Caikit
- TLS/mTLS provides transport encryption only
- Auth enforcement delegated to platform layer:
  - KServe InferenceService configuration
  - kube-rbac-proxy sidecar
  - Istio service mesh policies
  - OpenShift Route authentication

FIPS Compliance:
- Pure Python library — no compiled binaries
- Crypto delegated to system OpenSSL via grpcio and Python ssl module
- FIPS compliance inherited from container base image (UBI with OpenSSL)
- reversible_hasher.py explicitly non-cryptographic (ID generation only)
