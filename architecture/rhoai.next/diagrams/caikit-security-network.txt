 CAIKIT SECURITY NETWORK DIAGRAM
 Component: Caikit Runtime Framework (Python Library)
 Distribution: RHOAI
================================================================================

NOTE: Caikit is a pure Python library with NO built-in authentication or
authorization. All auth is delegated to the platform layer (KServe, ModelMesh,
Istio, kube-rbac-proxy, OAuth proxy, Gateway API). Caikit's TLS/mTLS support
is purely for transport-level encryption.

================================================================================
 TLS CONFIGURATION
================================================================================

Server TLS (gRPC + HTTP):
  Config key: runtime.tls.server
  - server.key:  TLS private key (file path or inline)
  - server.cert: TLS certificate (file path or inline)
  - client.cert: Client CA certificate for mTLS validation
  Source: caikit/runtime/grpc_server.py:199-231,
          caikit/runtime/http_server/http_server.py:219-228

mTLS Mode:
  - gRPC: grpc.ssl_server_credentials with require_client_auth=True
  - HTTP: uvicorn ssl_cert_reqs=CERT_REQUIRED
  - Both validate client certificates against configured CA

Trace TLS (OTLP exporter):
  Config key: runtime.trace.tls
  - ca:          OTLP collector server CA certificate
  - client_key:  mTLS client private key
  - client_cert: mTLS client certificate

================================================================================
 RBAC SUMMARY
================================================================================

Caikit is a pure Python library and does NOT define any Kubernetes RBAC
resources (ClusterRoles, RoleBindings, ServiceAccounts). All RBAC is managed
by the deploying operator:
  - KServe: Manages ServiceAccounts and RoleBindings for InferenceService pods
  - ModelMesh: Manages ServiceAccounts for ServingRuntime pods
  - Platform: kube-rbac-proxy sidecar enforces Kubernetes RBAC on API access

================================================================================
 AUTHENTICATION & AUTHORIZATION
================================================================================

| Endpoint            | Auth Mechanism     | Enforcement Point                            |
|---------------------|--------------------|----------------------------------------------|
| All HTTP endpoints  | None (delegated)   | Platform (kube-rbac-proxy / OAuth / Gateway)  |
| All gRPC services   | None (delegated)   | Platform (ModelMesh / KServe / Istio)          |
| gRPC (mTLS mode)    | mTLS client cert   | grpc.ssl_server_credentials (require_client)   |
| HTTP (mTLS mode)    | mTLS client cert   | uvicorn ssl_cert_reqs=CERT_REQUIRED            |

SECURITY NOTE: Any deployment of caikit without platform-level auth enforcement
exposes inference and management APIs without protection.

================================================================================
 FIPS COMPLIANCE
================================================================================

- Pure Python library: no compiled binaries
- TLS uses Python ssl module → system OpenSSL
- FIPS posture depends on consuming container image (UBI + FIPS kernel)
- No custom cipher suites, no MD5/RC4, no non-FIPS crypto detected
- No explicit FIPS opt-in needed at application level for Python
