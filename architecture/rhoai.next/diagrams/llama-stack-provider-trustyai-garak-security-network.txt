Credential Resolution Chain (5-step fallback):
  1. In-cluster SA token (ServiceAccountTokenVolumeProjection)
  2. KFP_AUTH_TOKEN environment variable
  3. Sidecar proxy model (evalhub >= 0.4.4)
  4. model-auth secret volume mount
  5. kubeconfig fallback (~/.kube/config)

API Key Resolution Chain (per-model, 13-step):
  Resolves keys for: target, sdg, judge, attacker, evaluator models
  Sources: model-auth secret → API_KEY env → OPENAICOMPATIBLE_API_KEY env
  Security: Keys redacted (__FROM_ENV__ placeholder) before persisting
  to S3 or OCI registries

Secrets Summary:
  - model-auth (Opaque, volume mount) - API keys for all model endpoints
  - Data Connection secret (Opaque, envFrom) - AWS S3 credentials
  - API_KEY (env var) - Generic API key fallback
  - KFP_AUTH_TOKEN (env var) - KFP authentication token
  - OPENAICOMPATIBLE_API_KEY (env var) - OpenAI-compatible API key
  - AWS_SECRET_ACCESS_KEY (env var) - S3 secret access key

RBAC:
  - No RBAC manifests in this repository
  - Runs under ServiceAccount provided by eval-hub
  - RBAC configured by trustyai-service-operator
  - Required permissions: read Secrets, read ConfigMaps

FIPS Compliance:
  - Python package, no Go binaries (no CGO_ENABLED flags)
  - Uses system OpenSSL via AIPCC base image (UBI 9.8)
  - cryptography==50.0.1 (uses OpenSSL backend)
  - Risk: Conditional verify_ssl=False when CA cert file absent
    (evalhub/garak_adapter.py:896, fallback-of-last-resort)

Multi-Tenancy:
  - Per-job isolation (one adapter instance per evaluation)
  - S3 isolation by key prefix: evalhub-garak-kfp/{job-id}/
  - No NetworkPolicy defined by component
