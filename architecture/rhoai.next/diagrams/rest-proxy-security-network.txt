RBAC Summary:
  No RBAC resources. The rest-proxy does not interact with the Kubernetes API.
  It runs as a sidecar container and has no ServiceAccount-level API permissions.

Secrets:
  No secrets are defined by this component.
  TLS certificate/key paths are injected via environment variables by the
  deploying operator (ModelMesh Serving):
    - MM_TLS_KEY_CERT_PATH       → Server-side TLS certificate path
    - MM_TLS_PRIVATE_KEY_PATH    → Server-side TLS private key path
    - REST_PROXY_USE_TLS         → Enable TLS for upstream gRPC connection
    - REST_PROXY_SKIP_VERIFY     → Disable certificate verification (⚠ dev only)

Authentication & Authorization:
  The rest-proxy does NOT implement its own auth. Auth is enforced by:
    1. Istio service mesh (mTLS between pods)
    2. kube-rbac-proxy sidecar (if deployed alongside)
    3. Platform Gateway / Route (external ingress AuthN)

FIPS Compliance:
  - Build: CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime, -tags strictfipsruntime
  - Crypto: OpenSSL-backed via ubi9/ubi-minimal base image
  - TLS: stdlib crypto/tls (FIPS-validated via OpenSSL at runtime)
  - Risk: InsecureSkipVerify configurable via REST_PROXY_SKIP_VERIFY env var
    (disables cert verification, NOT a FIPS algorithm issue)

Network Exposure:
  - No Kubernetes Service defined (shares ModelMesh pod network)
  - No Ingress resources (accessed through ModelMesh Service)
  - Egress: localhost:8033/TCP only (co-located gRPC server)
  - No external network egress
