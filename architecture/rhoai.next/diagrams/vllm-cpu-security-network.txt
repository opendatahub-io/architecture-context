RBAC Summary:
- No Kubernetes RBAC resources defined
- vllm-cpu runs as non-privileged container (UID 2000, GID 0)
- Does not interact with Kubernetes API server

Application-Level Authentication:
- AuthenticationMiddleware (ASGI middleware)
  - Guarded prefixes: /v1/*, /v2/*, /inference/*
  - Mechanism: Bearer token (VLLM_API_KEY env var or --api-key flag)
  - Comparison: SHA-256 hash, constant-time (secrets.compare_digest)
  - Exemptions: OPTIONS requests, all non-prefixed paths

Service Mesh Context:
- vllm-cpu relies on platform-level encryption (Istio mTLS STRICT)
- In-mesh communication encrypted at pod level via sidecar proxy
- gRPC insecure port gap mitigated by mesh-level mTLS

Secrets:
- VLLM_API_KEY (env var) - API authentication token, no auto-rotation
- S3_ACCESS_KEY_ID (env var) - S3 storage access key, no auto-rotation
- S3_SECRET_ACCESS_KEY (env var) - S3 storage secret key, no auto-rotation
- HF_TOKEN (env var) - Hugging Face Hub authentication, no auto-rotation
- MODELSCOPE_API_TOKEN (env var) - ModelScope registry auth, no auto-rotation

FIPS Compliance Notes:
- Python project (no Go binaries) - N/A for build-time FIPS flags
- Uses Python stdlib ssl module (SSLContext) - relies on system OpenSSL
- hashlib.sha256 for token comparison (FIPS-safe)
- blake3 used for content hashing (non-crypto, not FIPS-validated)
- gRPC server lacks TLS (gap for FIPS transport requirements)
- UBI 9 base provides FIPS-validated OpenSSL
