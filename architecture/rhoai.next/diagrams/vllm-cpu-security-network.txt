RBAC Summary:
- No RBAC — vllm-cpu is a container image, not an operator
- RBAC is managed by KServe/rhods-operator at the platform level

Secrets:
- HF_TOKEN (env var) - HuggingFace Hub auth for model download, user-provisioned, no auto-rotate
- VLLM_API_KEY (env var) - API key auth for HTTP endpoints, user/platform-provisioned, no auto-rotate
- EXA_API_KEY (env var) - Exa web search API auth (demo tools), user-provisioned, no auto-rotate
- ssl_certfile / ssl_keyfile (file mount) - TLS cert and key for HTTPS, cert-manager/manual, auto-refresh via enable_ssl_refresh
- ssl_ca_certs (file mount) - CA certificate chain for client cert validation, manual, no auto-rotate

Authentication & Authorization:
- /v1/* endpoints: Optional Bearer Token auth (if VLLM_API_KEY is set, all requests must include matching Authorization header)
- /health, /ping: Always public (no auth)
- gRPC VllmEngine: ⚠ No authentication on gRPC server (security concern for internal-only access)
- Render/derender endpoints: No auth required

FIPS Compliance:
- Python-based service (no Go binaries, no GOEXPERIMENT=strictfipsruntime)
- OpenSSL from UBI 9 base image provides FIPS-capable crypto
- hashlib.md5 used with usedforsecurity=False (non-cryptographic, FIPS-safe)
- TLS configuration delegates to Python ssl module defaults (FIPS-aware on UBI 9)
- No RC4, DES, or deprecated ciphers detected

Container Security:
- Runs as non-root user (UID 2000)
- Base image: registry.access.redhat.com/ubi9/ubi-minimal:9.6
- Does NOT use AIPCC base images
- Build: Non-hermetic (hermetic: false in Tekton pipeline)
- Architectures: s390x, ppc64le
