RBAC Summary:
- No RBAC -- this is a containerized service, not an operator.
- No ClusterRoles, Roles, or RoleBindings.
- Pod runs under default ServiceAccount unless configured by KServe.

Authentication Summary:
- HTTP API (8000/TCP):
  - Optional Bearer Token via --api-key or VLLM_API_KEY env var
  - AuthenticationMiddleware rejects requests if token invalid
  - Bypassed if no API key configured
  - Health/readiness probes (/health, /ready, /readyz) always unauthenticated
- gRPC (50051/TCP):
  - NO authentication
  - NO TLS (insecure_port binding)
  - Relies on network-level pod isolation

Secrets:
- HF_TOKEN (env var) - HuggingFace Hub auth - User/platform provisioned - No auto-rotate
- VLLM_API_KEY (env var) - API server auth key - User/platform provisioned - No auto-rotate
- S3_ACCESS_KEY_ID (env var) - S3 access key for tensorizer - User provisioned - No auto-rotate
- S3_SECRET_ACCESS_KEY (env var) - S3 secret key for tensorizer - User provisioned - No auto-rotate
- SSL cert/key files (filesystem) - TLS encryption - cert-manager - Auto-refresh (--enable-ssl-refresh)

FIPS Compliance:
- Python ssl module delegates to system OpenSSL (UBI9 base image)
- TLS operations use FIPS-validated crypto when host is in FIPS mode
- blake3 used for content hashing (cache keys) - NOT FIPS-validated
  (sha256 alternative available via VLLM_MM_HASHER_ALGORITHM)
- gRPC server uses insecure_port (no TLS) - TLS at ingress layer

Build Hermeticity:
- Tekton pipeline: hermetic=false
- Python deps: NOT locked (version ranges in requirements/*.txt)
- Rust deps: Locked (Cargo.lock present)
- No AIPCC base images (raw UBI9-minimal)
- Supply chain risk: non-deterministic Python dependency resolution

Multi-Architecture:
- x86_64: bf16/fp16/fp32, Intel extensions, OpenTelemetry, numba
- ppc64le: bf16/fp32 only, custom PyTorch build, no Intel extensions
- s390x: bf16/fp32 only, custom PyTorch build, no OTel, no numba
