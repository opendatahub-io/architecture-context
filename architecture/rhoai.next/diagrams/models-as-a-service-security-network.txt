  - apps: deployments → full CRUD

  - networking.k8s.io: networkpolicies → get/list/watch/create/delete/patch
  - monitoring.coreos.com: servicemonitors, podmonitors → get/list/watch/create/delete/patch
  - 12+ additional API groups (see architecture doc for complete list)

- ClusterRoleBinding: maas-controller-rolebinding → maas-controller SA (opendatahub ns)
- Per-tenant Roles: aitenant-{name}-tenant-admin, aitenant-{name}-object-admin

Admission Webhooks:
- vaitenant.kb.io (validating): AITenant namespace + gateway uniqueness enforcement (failurePolicy: Fail)
- vmaasauthpolicy.kb.io (validating): Namespace initialization check (failurePolicy: Fail)
- vmaassubscription.kb.io (validating): Namespace initialization check (failurePolicy: Fail)

Secrets:
- maas-db-config (Opaque) - PostgreSQL connection URL, manual provisioning, no auto-rotate
- maas-controller-webhook-cert (kubernetes.io/tls) - Webhook TLS, OpenShift serving-cert or cert-manager, auto-rotated
- Gateway TLS secret (kubernetes.io/tls) - Gateway listener TLS, manual or cert-manager
- credentialRef secrets (Opaque) - External model provider API keys (api-key field), manual, no auto-rotate

Multi-Tenancy Isolation:
- Auth: Per-tenant Kuadrant AuthPolicy at dedicated Gateway; per-model subject matching
- Data: Shared PostgreSQL with mandatory tenant column filter (application-enforced)
- Network: NetworkPolicy for internal endpoints; dedicated Gateway per AITenant
- Compute: Separate maas-api Deployment per tenant (no per-tenant ResourceQuota)
- Config: Per-namespace MaasTenantConfig singleton; namespace-scoped secrets

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, dynamic linking
- Runtime: stdlib crypto/tls via OpenSSL (UBI9), SHA-256 for key hashing, crypto/rand for key generation
- No non-FIPS crypto detected (no MD5, RC4, DES, custom RNG)
