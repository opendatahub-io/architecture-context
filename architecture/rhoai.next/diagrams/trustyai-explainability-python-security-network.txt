RBAC Summary:
  The library itself does not define any RBAC resources (ClusterRoles,
  RoleBindings, etc.). When using the optional [api] extra, it requires
  the caller to have:
  - read access to OpenShift Routes (route.openshift.io/v1)
  - The caller's Bearer token must authorize access to TrustyAI Service
    and Thanos Querier endpoints.

Secrets:
  The library does not create or manage Kubernetes secrets.
  - Bearer Token: Passed as a constructor parameter to
    TrustyAIMetricsService. Not persisted by the library.
  - Risk: Token may appear in notebook cell output or logs if not
    handled carefully by the user.

Security Concerns:
  1. verify=False option: TrustyAIMetricsService constructor accepts a
     `verify` parameter that defaults to True but can be set to False,
     disabling SSL certificate verification. This should be documented
     as a security risk.
  2. Token management: Bearer tokens are the user's responsibility.
     The library does not enforce token rotation or secure storage.
  3. SNAPSHOT JAR: The bundled Java JAR uses a 999-SNAPSHOT version,
     indicating it is not a release-quality artifact. Supply chain
     provenance for this artifact is limited.
  4. Dependency version divergence: requirements.txt and pyproject.toml
     specify different versions of JPype1 and pyarrow, creating
     potential for unexpected behavior.

FIPS Compliance:
  - Pure Python library -- no compiled binaries or direct crypto usage.
  - TLS delegated to Python `requests` library using system OpenSSL.
  - FIPS compliance depends on the host environment (e.g., UBI-based
    Jupyter notebook image with FIPS-enabled OpenSSL).
  - No non-FIPS cryptographic operations detected in the library.
