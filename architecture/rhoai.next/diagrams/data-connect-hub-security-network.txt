RBAC Summary:
- ClusterRole: dc-controller-manager-role
  - API Groups: core, apps, authentication.k8s.io, authorization.k8s.io,
                 config.openshift.io, dataconnecthub.opendatahub.io,
                 gateway.networking.k8s.io, monitoring.coreos.com,
                 networking.k8s.io, rbac.authorization.k8s.io
  - Resources: configmaps, secrets, serviceaccounts, services, deployments,
               tokenreviews, subjectaccessreviews, apiservers, ingresses,
               dataconnectservices, gateways, httproutes, servicemonitors,
               networkpolicies, clusterroles, clusterrolebindings
  - Verbs: full CRUD + watch

- ClusterRole: kube-rbac-proxy-auth-review
  - Purpose: REST API auth enforcement
  - Resources: tokenreviews, subjectaccessreviews
  - Verbs: create

- ClusterRole: dch-flight-service-read / read-write / admin
  - Purpose: Data access RBAC for flight service clients
  - Resources: data-connections, data-connection-types, data-store

Secrets:
- rest-service-tls (kubernetes.io/tls) - TLS cert for kube-rbac-proxy,
    provisioned by OpenShift service-serving-cert-signer, auto-rotate: Yes
- flight-service-tls (kubernetes.io/tls) - TLS cert for flight gRPC server,
    provisioned by OpenShift service-serving-cert-signer, auto-rotate: Yes
- dch-database-config (Opaque) - PostgreSQL connection URL and credentials,
    provisioned manually, auto-rotate: No

Multi-Tenancy:
- Boundary: per-namespace (namespace name = tenant ID)
- Model: multi-tenant (single deployment serves all namespaces)
- Identifier: X-Tenant-Id HTTP header mapped to Kubernetes namespace
- Data isolation: Application-enforced (pg-meta-store tenant_id column filter)
- ⚠ No database-level row security policies
- ⚠ Shared database credentials across all tenants
- ⚠ No per-tenant compute resource isolation

Security Considerations:
1. ⚠ NetworkPolicies are allow-all (placeholder)
2. ⚠ CORS is allow-any-origin on rest-service
3. ⚠ Auth asymmetry: REST uses sidecar (kube-rbac-proxy), Flight uses
   application-level AuthLayer — a bug in AuthLayer could bypass isolation
4. ⚠ ring crypto provider in Cargo.lock (not FIPS-validated) but not selected
5. ⚠ Application-enforced tenant data isolation (no DB row-level security)
