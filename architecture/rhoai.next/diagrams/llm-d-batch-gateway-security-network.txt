Secrets:
- batch-gateway-secrets (Opaque) - Redis URL, PostgreSQL URL, S3 secret key, inference API key
  - Provisioned by: Manual / external
  - Auto-rotate: No
- {release}-apiserver-tls (kubernetes.io/tls) - API server TLS certificate and key
  - Provisioned by: cert-manager or manual
  - Auto-rotate: Yes (cert-manager) / No (manual)

Multi-Tenancy:
- Tenant boundary: per-user (header-based tenant ID via X-MaaS-Username)
- Deployment model: multi-tenant (shared service instances, tenant-scoped data)
- Data isolation: All DB queries filter by TenantID; cross-tenant returns 404
- File isolation: SHA256-hashed tenant folders (t-<hash>) in shared S3 bucket
- No NetworkPolicy defined in Helm chart
- No per-tenant ResourceQuota or LimitRange

Pod Hardening (all components):
- RunAsUser: 65532 (nonroot)
- ReadOnlyRootFilesystem: true
- AllowPrivilegeEscalation: false
- Capabilities: ALL dropped
- SeccompProfile: RuntimeDefault

RBAC Summary:
- No Kubernetes RBAC required (components do not interact with Kubernetes API)
- ServiceAccounts created per component by Helm chart but no Roles/RoleBindings defined

TLS Configuration:
- crypto/tls with MinVersion=tls.VersionTLS12
- Custom CA bundle support, mTLS client certs, system trust store fallback
- InsecureSkipVerify available but disabled by default (testing only)
- No third-party crypto libraries (stdlib crypto/tls only)

FIPS Compliance:
- Upstream: CGO_ENABLED=0, distroless base (would fail check-payload)
- Downstream: Expected to use UBI base, CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime
