RBAC Summary:
- No RBAC roles defined by this component
- RBAC is defined by odh-notebook-controller which deploys these images
- kube-rbac-proxy sidecar enforces per-user Notebook CR access control
- Runtime images use ServiceAccount tokens mounted by KFP/Elyra

Authentication Architecture:
- Workbench images have NO built-in authentication
- kube-rbac-proxy sidecar is injected by odh-notebook-controller into every workbench Pod
- The sidecar intercepts all incoming traffic on port 8443/TCP
- Validates Bearer Token / OIDC before proxying to workbench on localhost
- Per-user isolation: each Notebook CR creates a dedicated Pod

FIPS Compliance:
- UBI9 base images provide FIPS-compliant OpenSSL
- mongocli compiled with CGO_ENABLED=1 -tags strictfipsruntime
- check-payload FIPS validation in CI
- CUDA/ROCm vendor libraries: NOT FIPS-certified (vendor limitation)
- Build hermeticity: Non-hermetic (hermetic: "false" in Tekton pipeline)

Secrets:
- No secrets defined by these images
- Secret injection handled by notebook controller at Pod creation time
- Runtime images receive credentials via Pod environment / mounted secrets

Multi-Tenancy:
- Tenant boundary: per-user (one workbench Pod per user)
- Per-user PVC for data storage
- Network isolation depends on platform-level NetworkPolicy (none in this repo)
- No resource limits in image manifests (relies on namespace ResourceQuota)
