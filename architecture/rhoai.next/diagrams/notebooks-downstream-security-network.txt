RBAC Summary:
- These are container images, not operators. No RBAC roles defined.
- RBAC is managed by odh-notebook-controller which deploys the workbenches.
- kube-rbac-proxy sidecar enforces per-user access to Notebook CRs.

Authentication & Authorization:
- JupyterLab (8888/TCP): Bearer token / OIDC via kube-rbac-proxy sidecar
- Code Server (8787/TCP): Bearer token / OIDC via kube-rbac-proxy sidecar
- RStudio Server (8787/TCP): Bearer token / OIDC via kube-rbac-proxy sidecar
- Runtime containers: ServiceAccount token (no user-facing auth)
- No authentication implemented within container images themselves.

Secrets:
- No secrets defined by these images.
- Secret injection handled by odh-notebook-controller at Pod creation time.
- Build-time: Registry credentials for quay.io push (managed by Konflux).

FIPS Compliance:
- Images use UBI9 base (inherits FIPS-compliant OpenSSL)
- mongocli compiled with: CGO_ENABLED=1 -tags strictfipsruntime
- check-payload FIPS validation in GitHub Actions CI
- CUDA/ROCm vendor libraries: NOT FIPS-certified (vendor limitation)

Build Hermeticity:
- Python deps: Locked via 26 Pipfile.lock files (micropipenv)
- Go deps: Locked via go.sum (buildinputs, check-payload tools)
- RPM packages: NOT locked on main branch
- Hermeto/cachi2 prefetch: NOT configured
- Builds are NOT network-isolated (hermetic: "false")

Multi-Tenancy:
- Tenant boundary: per-user (each user gets own workbench Pod)
- Isolation: kube-rbac-proxy sidecar + per-user PVC
- No NetworkPolicy defined in this repo (relies on platform-level policy)
- ServiceAccount token mounted in Pod (cluster access risk)
