Secret Management:
- 18 environment variables with _FILE suffix support for file-mounted secrets
- _FILE variants: ANTHROPIC_API_KEY, AWS_ACCESS_KEY_ID, AWS_BEDROCK_BEARER_TOKEN,
  AWS_SECRET_ACCESS_KEY, AZURE_API_KEY, BRAVE_SEARCH_API_KEY, DOCLING_SERVE_API_KEY,
  GEMINI_ACCESS_TOKEN, GEMINI_API_KEY, MILVUS_TOKEN, OPENAI_API_KEY, PGVECTOR_PASSWORD,
  POSTGRES_PASSWORD, QDRANT_API_KEY, TAVILY_SEARCH_API_KEY, VLLM_API_TOKEN,
  VLLM_EMBEDDING_API_TOKEN, WATSONX_API_KEY
- entrypoint.sh reads from file at startup, avoids /proc/1/environ exposure
- Secrets provisioned by: Manual / External Secrets Operator

Authentication & Authorization:
- OAuth2 JWT validation when AUTH_ISSUER is set (optional)
- JWKS-based key verification (recheck period: AUTH_JWKS_RECHECK_PERIOD, default 3600s)
- Access policy: Owner-based (read unowned resources: all; create: authenticated; manage own: owner only)
- /v1/health and /metrics: Always unauthenticated

RBAC:
- No Kubernetes RBAC defined by this component
- RBAC managed by ogx-operator (separate component)

FIPS Compliance:
- Python application — no Go binaries
- FIPS inherited from AIPCC UBI 9.8 base image (FIPS-validated OpenSSL)
- Python ssl module and cryptography package use system OpenSSL
- TLS verification defaults to true for all providers (configurable per-provider)

Multi-Tenancy:
- Application-enforced tenant isolation (owner-based access control)
- Shared PostgreSQL, inference providers, and vector store backends
- Cross-user isolation verified by Praxis integration tests
- Soft isolation boundary — depends on application correctness
