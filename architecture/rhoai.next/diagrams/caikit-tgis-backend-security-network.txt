TLS/mTLS Configuration:
- CA certificate:     File path (ca_cert_file) loaded via open(path, "rb")
- Client certificate: File path (client_cert_file) for mTLS
- Client key:         File path (client_key_file) for mTLS
- Enforcement:        mTLS requires BOTH client cert AND client key
- Validation:         File existence checked at configuration time
- Rotation:           NOT supported -- certs read once at channel creation
- Implementation:     grpc.ssl_channel_credentials() (tgis_connection.py:270-281)

RBAC Summary:
- No RBAC roles or bindings -- library component with no direct
  Kubernetes API interactions. RBAC is the responsibility of the
  hosting serving runtime.

Secrets:
- CA certificate (ca_cert_file)      -- File path, provisioned externally
- Client certificate (client_cert_file) -- File path, provisioned externally
- Client key (client_key_file)        -- File path, provisioned externally
- TLS materials are passed as file paths via configuration
- The consuming serving runtime mounts Kubernetes Secrets as volumes

FIPS Compliance:
- Python library -- no compiled binary
- TLS delegated to grpcio's OpenSSL binding
- FIPS compliance depends on the hosting container image's OpenSSL
- No direct use of non-FIPS crypto (hashlib, pycryptodome, etc.)

Multi-Tenancy:
- Tenant boundary: per-model (model_id)
- Local mode: single-model only (single-tenant)
- Remote mode: multi-model via _model_connections dict
- All models share TLS credentials from base connection config
- No per-model auth differentiation
