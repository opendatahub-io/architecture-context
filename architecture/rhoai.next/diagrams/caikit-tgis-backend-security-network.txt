TLS Configuration:
- grpc.ssl_channel_credentials() with:
  - root_certificates: CA cert file (ca_cert_file)
  - private_key: Client key file (client_key_file) -- optional, for mTLS
  - certificate_chain: Client cert file (client_cert_file) -- optional, for mTLS
- Certificate validation: Strict (file existence checked at config time)
- mTLS enforcement: Both client cert AND client key required together
- Certificate rotation: NOT supported (files read once at channel creation)
- Implementation: tgis_connection.py:270-281, 308-323

Secrets (file-path based, not Kubernetes Secrets):
- ca_cert_file (file path) - TLS CA certificate for TGIS server validation
  - Provisioned by: External (manual/cert-manager)
  - Mounted by: Consuming serving runtime
- client_cert_file (file path) - mTLS client certificate
  - Provisioned by: External (manual/cert-manager)
  - Mounted by: Consuming serving runtime
- client_key_file (file path) - mTLS client private key
  - Provisioned by: External (manual/cert-manager)
  - Mounted by: Consuming serving runtime

RBAC Summary:
- No RBAC roles or bindings -- library component with no direct Kubernetes API interactions

FIPS Compliance:
- TLS delegated to grpcio (OpenSSL binding)
- FIPS compliance depends on consuming container image's OpenSSL
- No non-FIPS crypto detected (no hashlib, pycryptodome usage)

Multi-Tenancy:
- Tenant boundary: per-model (model_id)
- Local mode: Single-tenant only (one model at a time)
- Remote mode: Per-model connections via remote_models dict
- All models on same backend share TLS credentials
- Prompt artifacts: per-model subdirectories, no filesystem-level isolation
