FIPS Compliance Summary:
  Standard build:
  - Image: Alpine 3.24, dynamic linking against system OpenSSL
  - TLS: rustls with OpenSSL crypto provider (not aws-lc-rs)
  - Crypto: SHA-256, HMAC-SHA256 via OpenSSL EVP API
  - Non-FIPS risks: sha2, hmac, md-5 via sqlx (PostgreSQL SCRAM auth)

  FIPS build:
  - Image: UBI 9 (pinned by digest, signature-verified)
  - Enforcement: PRAXIS_REQUIRE_FIPS refuses startup if non-FIPS filters present
  - Feature gates: Excludes store backends (sqlx sha2), rate limiting, ext_proc
  - Crypto: All routed through system OpenSSL FIPS provider
  - Audit: cargo-auditable + SBOM, check-payload scanner with --fail-on-warnings

Multi-Tenancy:
  - Boundary: StateOwner (tenant_id, issuer, subject)
  - Constructor: StateOwner::from_trusted_parts (validated, max 1024 bytes/component)
  - Store isolation: Every query owner-scoped, get_response returns None for wrong owner
  - Rate limiting: Per-tenant via token_rate_limit filter (experimental, Valkey)
  - Network isolation: Delegated to platform (NetworkPolicy, AuthorizationPolicy)

Secrets:
  - TLS certificates (key/cert files) — Listener TLS termination, operator/cert-manager, file watcher rotation
  - Upstream credentials (YAML config / projected) — Backend auth tokens, operator/credential_inject
  - PostgreSQL credentials (connection URL / TLS certs) — Database auth, operator-provisioned

Sensitive Data Handling:
  - secrecy crate wraps sensitive values (prevents accidental logging)
  - zeroize crate provides secure memory zeroing for key material
  - Credentials are per-route via credential_inject (security-class filter)

Container Security:
  - Standard: Non-root user "praxis", exposed ports 8080 + 9901
  - FIPS: UID 1001, 4-stage build, signature-verified base image
