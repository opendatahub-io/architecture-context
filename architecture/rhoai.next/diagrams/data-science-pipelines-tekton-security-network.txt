Authentication & Authorization:
- API Server gRPC: Bearer token via unary interceptor → Kubernetes TokenReview
  (validates user identity) + SubjectAccessReview (checks authorization)
  Enforcement: Multi-user mode only; single-user mode has no user-level auth
- MinIO: Istio AuthorizationPolicy — ALLOW principals: ml-pipeline, ml-pipeline-ui
- MySQL: Istio AuthorizationPolicy — ALLOW 7 specific service account principals

Service Mesh Configuration:
- Istio mTLS: Enforced in multi-user mode via sidecar injection
- VirtualService: ml-pipeline-ui exposed via kubeflow-gateway
- AuthorizationPolicies: Per-service access control for MySQL and MinIO
- Single-user mode: No Istio, no network-level isolation

Secrets:
- webhook-server-tls (kubernetes.io/tls) — TLS cert for cache webhook,
  provisioned by cache-deployer job or cert-manager, NO auto-rotation

Security Observations:
- grpc.WithInsecure() used for internal localhost gRPC-to-HTTP proxy
  (traffic stays in-process; external TLS expected via service mesh)
- Cache server SHA-256 usage is for cache key derivation (non-security-critical)
- No FIPS build flags; FIPS compliance relies on UBI8 runtime + service mesh
- Shared MySQL database — no row-level tenant isolation
