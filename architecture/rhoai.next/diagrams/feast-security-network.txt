Authentication & Authorization:
- Feature Server: Bearer token (OIDC JWT / K8s SA token / None)
  - 8 permission actions: CREATE, DESCRIBE, UPDATE, DELETE, READ_ONLINE, READ_OFFLINE, WRITE_ONLINE, WRITE_OFFLINE
  - Enforced per-resource by SecurityManager → permission policies in Feast registry
- Operator-to-Registry: Intra-communication JWT (HS256, empty key) bypasses permission framework
  - WARNING: InsecureSkipVerify: true for intra-cluster TLS connections
- Operator Metrics: ServiceAccount token auth via controller-runtime authn/authz filter

Secrets:
- feast-{name}-{service}-tls (kubernetes.io/tls) - Service TLS certs, OpenShift auto-provisioned
- (user-provided) (Opaque) - Online/offline/registry store credentials, user-managed
- (user-provided) (Opaque) - OIDC client credentials (client_id, client_secret), user-managed
- (user-provided) (Opaque) - OpenLineage API key, user-managed

FIPS Compliance:
- Operator (Go): GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, dynamic linking
- Feature Server (Python): Inherits FIPS from OpenSSL in UBI 9 base
- TLS: MinVersion TLS 1.2, curve preferences P256 + X25519MLKEM768
- Risk: X25519MLKEM768 (post-quantum) may not be FIPS-approved
- Risk: InsecureSkipVerify: true for intra-cluster registry client
