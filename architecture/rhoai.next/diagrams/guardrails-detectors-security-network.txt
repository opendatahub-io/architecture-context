RBAC Summary:
- No RBAC defined. Detectors are application-level microservices, not Kubernetes operators.
- RBAC for KServe InferenceServices is managed by KServe.
- Example user-one-view RoleBinding exists in reference manifests (not production).

Authentication & Authorization:
- /api/v1/text/contents (POST): Istio mTLS + platform auth
  Enforcement: Istio sidecar (sidecar.istio.io/inject: true)
  Policy: security.opendatahub.io/enable-auth: true on ISVC
- /api/v1/text/generation (POST): Istio mTLS + detector_id header
  Enforcement: Istio sidecar
- /health, /metrics (GET): Unauthenticated

Service Mesh Configuration:
- Istio sidecar injection: sidecar.istio.io/inject: true (annotation on ISVCs)
- mTLS: Enforced by Istio service mesh for inter-service communication
- Platform auth: security.opendatahub.io/enable-auth: true (HF and LLM Judge ISVCs)

Secrets:
- aws-connection-minio-data-connection-guardrails-guardian (Opaque)
  Contents: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_S3_ENDPOINT, AWS_S3_BUCKET
  Provisioned: Manual (example manifest)
  Auto-Rotate: No

FIPS Compliance:
- Python services inherit FIPS from RHEL 9.6 base image OpenSSL
- No third-party crypto libraries; uses stdlib ssl module
- Optional SSL via ssl_ca_certs in config.yaml (ssl.CERT_REQUIRED)
- Custom detector code undergoes AST static analysis to block dangerous imports/calls
- No non-FIPS crypto risks detected (no MD5, RC4, non-FIPS ciphers)

Security Notes:
- Built-in detector custom code sandbox: blocks os, subprocess, sys, shutil imports
  and eval, exec, open, compile, input function calls via AST analysis
- LLM Judge detector has NO Konflux Dockerfile (productization gap)
  Uses generic ubi9/python-312:latest without AIPCC base image integration
- HuggingFace Konflux Dockerfile lacks hash-pinned requirements for HF extras
