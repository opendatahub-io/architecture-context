RBAC Summary:
- No RBAC resources — standalone HTTP service with no Kubernetes API interactions
- No ClusterRoles, Roles, or RoleBindings defined
- No ServiceAccount-specific permissions required

Secrets:
- TLS cert (/etc/tls/private/tls.crt) - kubernetes.io/tls - Client certificate for mTLS
  Provisioned by: Cluster CA / cert-manager (external)
  Auto-Rotate: Unknown
- TLS key (/etc/tls/private/tls.key) - kubernetes.io/tls - Private key for mTLS identity
  Provisioned by: Cluster CA / cert-manager (external)
  Auto-Rotate: Unknown
- CA cert (/etc/tls/ca/service-ca.crt) - Opaque - Custom CA certificate for orchestrator trust
  Provisioned by: OpenShift service-ca operator (external)
  Auto-Rotate: Unknown

NOTE: All TLS secrets are OPTIONAL. When absent, gateway connects via plaintext HTTP.

Authentication & Authorization:
- Gateway does NOT enforce authentication
- Authorization header is forwarded as-is to orchestrator
- x-forwarded-* headers are forwarded to backend
- Auth enforcement delegated to FMS Guardrails Orchestrator and/or upstream infra

FIPS Compliance:
- Rust binary (not Go — check-payload gate not directly applicable)
- Links against openssl-libs from UBI9 (OpenSSL 3.0.x with FIPS provider)
- native-tls crate delegates to system OpenSSL
- FIPS-validated crypto available when system OpenSSL FIPS provider is enabled
- WARNING: danger_accept_invalid_hostnames(true) for localhost (dev only)

Build Hermeticity:
- Cargo.lock: Present (cargo)
- rpms.lock.yaml: Present (rpm-lockfile-prototype)
- Hermeto prefetch: Configured in Konflux PipelineRun (cargo + RPM)
- Architectures: x86_64, arm64, ppc64le, s390x

Security Concerns:
- Container runs as root (no USER directive in Dockerfile)
- No health/readiness endpoints
