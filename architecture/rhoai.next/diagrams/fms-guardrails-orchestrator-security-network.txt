RBAC Summary:
- No ClusterRoles defined (pure service, not a Kubernetes operator)
- No RoleBindings defined
- Runs as a standalone service container

Secrets:
- TLS server cert/key (kubernetes.io/tls)
  Purpose: Server TLS for guardrails endpoint
  Provisioned: Manual (TLS_CERT_PATH, TLS_KEY_PATH env vars)
  Auto-Rotate: No

- TLS client CA cert (Opaque)
  Purpose: mTLS client certificate verification
  Provisioned: Manual (TLS_CLIENT_CA_CERT_PATH env var)
  Auto-Rotate: No

- Per-service TLS certs (kubernetes.io/tls)
  Purpose: Client TLS for outbound gRPC/HTTP connections
  Provisioned: Manual (config.yaml tls section per service)
  Auto-Rotate: No

- API token(s) (Opaque)
  Purpose: Bearer token auth for HTTP backends (detector, OpenAI)
  Provisioned: Manual (api_token in config, resolved from env var)
  Auto-Rotate: No

Authentication & Authorization:
- /api/v*/* (guardrails): mTLS optional via rustls WebPkiClientVerifier
- /health, /info: Open access (separate server on port 8034)
- Outbound to detectors: Bearer token optional (api_token from env)
- Outbound to OpenAI: Bearer token optional (api_token from env)
- Outbound to gRPC services: mTLS optional (client cert + CA from config.yaml)
- Header passthrough: X-Forwarded-Access-Token rewritten to Authorization: Bearer
  (controlled by rewrite_forwarded_access_header config)

FIPS Compliance Concerns:
- Uses rustls with ring crypto backend (NOT OpenSSL)
- ring is NOT FIPS-certified in Rust context
- NoVerifier struct allows disabling cert verification (insecure=true)
  WARNING: Must not be enabled in production
- Unlike Go binaries, cannot use GOEXPERIMENT=strictfipsruntime
