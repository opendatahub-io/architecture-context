  and does not interact with the Kubernetes API.

- TLS server cert/key (kubernetes.io/tls) — Server TLS for guardrails endpoint (port 8033)
  Provisioned by: Platform operator / cert-manager
- TLS client CA cert (Opaque) — Client CA certificate for mTLS verification
  Provisioned by: Platform operator
- API tokens (Opaque, env var) — Bearer tokens for downstream detector/generation services
  Provisioned by: Platform operator
- Downstream TLS certs (Opaque) — Client certificates for mTLS to downstream services
  Provisioned by: Platform operator

FIPS Compliance Warning:
- The application uses rustls with the ring crypto provider
- ring is NOT a FIPS 140-2/3 validated cryptographic module
- Despite UBI 9 PQC base image providing system OpenSSL,
  the application explicitly installs ring as the default TLS provider
  (src/main.rs:30 — rustls::crypto::ring::default_provider().install_default())
- This makes the component non-FIPS-compliant at the application crypto layer
- check-payload may pass (validates build artifacts, not runtime crypto)

Multi-Tenancy:
- Stateless request proxy — no tenant boundary
- Single shared instance per deployment
- No per-request authorization — trusts platform for caller authentication
- All API endpoints serve all callers equally
- Tenant isolation must be enforced externally (ingress proxy, service mesh)

Container Security:
- Base image: registry.redhat.io/ubi9/ubi-minimal-pqc (digest-pinned)
- Non-root user: orchestr8 (UID 1001, GID 0)
- Multi-arch: amd64, ppc64le, s390x
- Build hermeticity: Hermeto prefetch for cargo + rpm dependencies
