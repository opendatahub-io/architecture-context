RBAC Summary:
- No RBAC defined — the autogluon server is a passive inference container
- Does NOT interact with the Kubernetes API
- RBAC for the pod's service account is managed by the KServe operator

Secrets:
- storage-credentials (Opaque) — S3/GCS/Azure credentials for model download
  - Provisioned by: User / platform operator
  - Mounted by: KServe operator into InferenceService pod
  - Auto-Rotate: No
  - Accessed via: Standard SDK credential chains (boto3, google-cloud-storage, azure-identity)

Authentication & Authorization:
- Enforcement point: kube-rbac-proxy sidecar (port 8443/TCP)
- Mechanism: Bearer token validation against platform RBAC policy
- The autogluon server itself has NO authentication
- All inference endpoints are protected by the sidecar proxy

FIPS Compliance:
- Python application — no Go binaries, no custom TLS
- Crypto: cryptography>=48.0.0 (transitive) linked against RHEL OpenSSL
- TLS: Delegated entirely to platform (kube-rbac-proxy, service mesh)
- Certificate trust: System trust store via RHEL ca-certificates
- No non-FIPS crypto risks detected

Container Security:
- Runs as non-root (arbitrary UID on OpenShift)
- No privilege escalation
- Read-only root filesystem (writable: /tmp, $HOME)
- runtime_paths.py handles chdir to writable directory for OpenShift
- No hostNetwork, no hostPID, no hostIPC
