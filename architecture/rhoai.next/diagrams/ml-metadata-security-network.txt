RBAC Summary:
- No Kubernetes RBAC defined by this component (standalone gRPC server)
- RBAC is managed by the deploying operator (DSP controller / rhods-operator)

Service Mesh Configuration:
- No service mesh configuration defined by this component
- Network isolation relies on Kubernetes NetworkPolicy deployed by platform operator

Secrets:
- DB credentials (Opaque) - MySQL/PostgreSQL username and password
  Provisioned by: Platform operator (DSP controller)
  Auto-Rotate: No

- TLS server key/cert (kubernetes.io/tls) - gRPC server TLS termination
  Provisioned by: Platform operator or cert-manager
  Auto-Rotate: Operator-dependent

- TLS client CA (Opaque) - Client certificate verification for mTLS
  Provisioned by: Platform operator
  Auto-Rotate: No

- MySQL SSL options (Opaque) - cert, key, ca for MySQL TLS
  Provisioned by: Platform operator
  Auto-Rotate: No

- PostgreSQL SSL options (Opaque) - sslcert, sslkey, sslrootcert for PostgreSQL TLS
  Provisioned by: Platform operator
  Auto-Rotate: No

Authentication & Authorization:
- Endpoint: gRPC MetadataStoreService (all RPCs)
- Mechanism: Optional mTLS (client_verify flag in SSLConfig)
- Enforcement: gRPC server credentials (BoringSSL)
- Policy: If client_verify=true, requires valid client certificate;
  otherwise no auth at application level
- WARNING: No application-level authorization. All authenticated clients
  have full read/write access to all metadata.

FIPS Compliance Notes:
- Crypto library: BoringSSL (Google's OpenSSL fork) linked via Bazel
- FIPS risk: BoringSSL is FIPS-capable but no evidence of FIPS module
  activation in build config. Uses upstream BoringSSL, not Red Hat OpenSSL.
- Build: C++ binary (not Go), no GOEXPERIMENT/strictfipsruntime applicable
- Base image: UBI9 (registry.access.redhat.com/ubi9/ubi)

Multi-Tenancy Warning:
- Tenant boundary: per-database instance (single-tenant per server)
- No per-user or per-namespace authorization within the metadata store
- All pipeline metadata co-located in shared database tables
- Isolation depends on platform operator deploying separate MLMD instances
  per DSPA and restricting access via NetworkPolicy
