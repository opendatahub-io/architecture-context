RBAC Summary:
- No RBAC resources defined by the component
- The server runs as a standalone gRPC binary without Kubernetes API access
- Pod-level RBAC (ServiceAccount, Roles) managed by the deploying operator
  (Data Science Pipelines Operator)

Authentication & Authorization:
- gRPC endpoint: No auth by default
- Optional mTLS: SSLConfig with client_verify=true enables client certificate
  verification via gRPC C++ SslServerCredentials
- No per-user or per-tenant authorization within the application
- All authenticated clients have full read/write access to all metadata entities

Secrets (managed by deploying operator):
- Database credentials (Opaque) - MySQL/PostgreSQL username and password
  - Provisioned by: Deploying operator
  - Auto-rotate: No
- SSL certificates (kubernetes.io/tls) - Optional gRPC TLS and/or database SSL
  - Provisioned by: Deploying operator / cert-manager
  - Auto-rotate: Depends on provisioner

FIPS Compliance Notes:
- gRPC transport uses BoringSSL (statically linked via Bazel), NOT system OpenSSL
- BoringSSL operates outside the kernel FIPS module
- Runtime base image: ubi9-minimal-pqc (post-quantum cryptography variant)
- Hermetic builds: false (Tekton pipeline config)
- No rpms.lock.yaml or Hermeto prefetch

Multi-Tenancy:
- Single-tenant: one server instance per database
- No row-level or schema-level tenant isolation
- No per-client quotas or resource limits
