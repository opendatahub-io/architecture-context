Application Authorization Summary:
- Authentication: GitHub OAuth (read:user scope)
- Role Resolution: GitHub org membership + GCS-hosted IAM allowlists
- Roles: admin (full access), user (submit + own data), none (public only)
- Rate Limiting: 50,000 req/min per IP (express-rate-limit)
- Path Traversal: Relative path validation on /api/local/file/* endpoints
- Playground Mode: RESULTS_STORE_PLAYGROUND_MODE=1 bypasses all auth (dev only)

Multi-Tenancy:
- Tenant Boundary: Per-user (GitHub identity)
- Deployment Model: Single shared instance (multi-tenant)
- Data Isolation: GCS object metadata (submission_state, github_user) — application-layer filtering
- Risk: No bucket-level isolation; GCS credential leak would expose all data

Secrets:
- GITHUB_CLIENT_ID (env var) — OAuth App client ID, manual provisioning, no auto-rotate
- GITHUB_CLIENT_SECRET (env var) — OAuth App client secret, manual provisioning, no auto-rotate
- GOOGLE_API_KEY (env var) — Google Drive/Sheets API key, manual provisioning, no auto-rotate
- GOOGLE_APPLICATION_DEFAULT_CREDENTIALS (mounted JSON) — GCS/GIQ SA credentials, WIF auto-rotate

FIPS Compliance:
- Not applicable — Node.js web application on Alpine, no FIPS build signals
- TLS termination handled by Google Cloud Run (Google-managed certificates)
- Application listens on plain HTTP; no explicit TLS configuration
- Python offline tool disables SSL cert verification (not deployed)
