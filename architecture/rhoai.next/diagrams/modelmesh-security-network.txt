RBAC Summary:
  ModelMesh does not define RBAC resources. RBAC is managed by the
  modelmesh-controller. The ModelMesh process itself does not interact
  with the Kubernetes API.

Secrets:
  - model-mesh-tls-secret (kubernetes.io/tls)
    Purpose: TLS certificate and key for gRPC server and inter-instance comm
    Provisioned By: Manual or cert-manager (via kustomize secretGenerator)
    Auto-Rotate: No

  - model-mesh-icd-etcd (Opaque)
    Purpose: etcd connection configuration (JSON with endpoints, TLS settings)
    Provisioned By: Manual / platform operator
    Auto-Rotate: No

Authentication & Authorization:
  - mmesh.ModelMesh gRPC (8033/TCP):
    Auth: TLS (server-auth or mTLS, configurable)
    Enforcement: gRPC server TLS handler
    Policy: Transport-level only; no application-level auth

  - Internal Thrift (8080/TCP):
    Auth: TLS with optional client-auth (MM_INTRACLUSTER_CLIENTAUTH)
    Enforcement: LiteLinks SSL handler
    Policy: Client certificate validation when enabled

  - Prometheus metrics (2112/TCP):
    Auth: None
    Policy: Unauthenticated; relies on NetworkPolicy for access control

  - Health probes (8089/TCP):
    Auth: None
    Policy: Unauthenticated; internal-only

FIPS Compliance Gaps:
  - Java FIPS explicitly disabled (-Dcom.redhat.fips=false) in start.sh
  - SunPKCS11 provider replaced with NSS but FIPS flag prevents enforcement
  - BouncyCastle used for self-signed Prometheus TLS cert generation
  - Truststore uses hardcoded password ("watson15qa")
  - This is an architecturally significant FIPS gap

NetworkPolicy:
  - Defined in config/base/networkpolicy.yaml
  - Controls access to metrics endpoint (2112/TCP)
