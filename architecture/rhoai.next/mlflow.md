## Purpose

**Short**: MLflow is an open-source ML lifecycle management platform providing experiment tracking, model registry, artifact storage, AI gateway, and MCP server registry capabilities, deployed as a Python web service on RHOAI.

**Detailed**: MLflow is a comprehensive machine learning lifecycle platform originally created by Databricks and maintained under the Linux Foundation. The Red Hat Data Services fork customizes upstream MLflow for deployment on Red Hat OpenShift AI (RHOAI), adding Kubernetes-native authentication (service account token and namespace-based workspace mapping), PatternFly UI theming, module federation for embedded use within the RHOAI dashboard, and Konflux-based hermetic container builds using the AIPCC Python package index.

The server exposes a dual-framework architecture: a Flask application providing the core MLflow tracking and model registry APIs (protobuf-defined), wrapped by a FastAPI application that adds the AI Gateway (multi-provider LLM endpoint management with OpenAI/Anthropic/Gemini passthrough), OpenTelemetry trace ingestion, MCP (Model Context Protocol) server registry, job execution engine, and workspace-based multi-tenancy. The Helm chart packages MLflow for Kubernetes deployment with configurable TLS, NetworkPolicy, Prometheus metrics, RBAC, and persistent storage.

MLflow supports multiple backend stores (PostgreSQL, MySQL, SQLite) for experiment metadata, pluggable artifact repositories (S3, GCS, Azure Blob, local filesystem), and an extensible authentication framework. The workspace feature provides logical multi-tenancy by mapping Kubernetes namespaces to MLflow workspaces, enabling per-tenant isolation of experiments, models, and artifacts within a shared server instance.

## Architectural Analysis

MLflow's architecture in the RHOAI context represents a sophisticated fork management strategy. The Red Hat fork tracks upstream MLflow (currently at v3.14.0) through periodic rebases, maintaining a set of clearly annotated cherry-picks prefixed with `keep:` or `drop:` to distinguish downstream-only patches from upstream backports. The fork adds three main categories of customization: (1) Kubernetes-native authentication via service account tokens mapped to workspaces, (2) UI theming with PatternFly and module federation support for embedding in the RHOAI dashboard, and (3) Konflux-based hermetic builds using the AIPCC Python package index.

The dual-framework architecture (FastAPI wrapping Flask via WSGIMiddleware) is an intentional migration strategy. The core MLflow APIs remain on Flask for backward compatibility, while new features (AI Gateway, MCP Registry, OTel ingestion, job execution) are built as native FastAPI routers mounted ahead of the Flask catch-all. This allows incremental migration without breaking the extensive upstream test suite. The `_EfficientWSGIMiddleware` class patches a known O(n^2) body buffering issue in Starlette's deprecated WSGIMiddleware.

The workspace feature is architecturally significant for RHOAI. It provides logical multi-tenancy within a single MLflow instance by mapping Kubernetes namespaces to MLflow workspaces. The `kubernetes-namespaced` auth provider reads the pod's service account token and namespace, injecting them as `Authorization` and `X-MLFLOW-WORKSPACE` headers. The server resolves workspaces via a pluggable store (SQL or Kubernetes-backed), ensuring experiments, models, and artifacts are isolated per tenant. Workspace names follow Kubernetes DNS-1123 naming conventions (lowercase alphanumeric with hyphens, 2-63 characters), reinforcing the namespace-to-workspace mapping.

The secrets management system uses AES-GCM-256 encryption with PBKDF2-derived keys, supporting key rotation via a versioned Key Encryption Key (KEK). This is critical for storing LLM provider API keys used by the AI Gateway feature. The KEK passphrase is injected as an environment variable and never exposed through the CLI, ensuring it remains a server-admin-only secret. The rotation workflow is atomic and idempotent, designed for zero-downtime key rotation.

The Helm chart reflects production-readiness with security-by-default patterns: `runAsNonRoot`, `readOnlyRootFilesystem`, `seccompProfile: RuntimeDefault`, dropped capabilities, and an optional NetworkPolicy with explicit egress rules limiting outbound traffic to DNS, HTTPS, Kubernetes API, databases, and S3. The `automountServiceAccountToken: false` default indicates that MLflow does not require Kubernetes API access by default -- it is opt-in when workspace features are enabled.
