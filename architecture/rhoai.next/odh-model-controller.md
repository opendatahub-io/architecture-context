## Purpose

**Short**: Kubernetes operator and REST API server that manages the lifecycle, networking, authentication, monitoring, and credential injection for KServe-based model serving workloads on the Red Hat OpenShift AI platform.

**Detailed**: The odh-model-controller is a controller-runtime based Kubernetes operator that automates operational tasks for machine learning model deployment on OpenShift AI. It watches KServe InferenceService, LLMInferenceService, ServingRuntime, and InferenceGraph CRDs, and reconciles supporting resources including OpenShift Routes, Gateway API HTTPRoutes, Kuadrant AuthPolicies, Istio EnvoyFilters, Prometheus ServiceMonitors, KEDA TriggerAuthentications, and data connection Secrets.

The controller provides admission webhooks that intercept Pod creation (for Ray TLS injection), InferenceService and LLMInferenceService mutations (for ConnectionsAPI credential injection and HardwareProfile scheduling), and InferenceGraph validation (for service URL namespace isolation). It also manages NVIDIA NIM integration through a dedicated Account CRD and controller that handles NGC API key validation, model catalog synchronization, and pull secret generation.

A companion REST API server (`model-serving-api`) provides a gateway discovery endpoint that enables the RHOAI dashboard to enumerate available Gateway API gateways for LLM inference routing. This server enforces per-request RBAC via Kubernetes SelfSubjectAccessReview and serves over mandatory TLS with FIPS-compliant cipher suites.

## Architectural Analysis

The odh-model-controller follows a hub-and-spoke architecture where a single operator binary hosts multiple independent controllers, each responsible for a distinct aspect of model serving lifecycle. The InferenceService controller is the most complex, orchestrating seven sub-reconcilers (route, RBAC, metrics service, ServiceMonitor, dashboard ConfigMap, KEDA, and Model Registry) through a delta-processing pipeline that compares desired state against actual state before making changes. This design avoids unnecessary API server writes and enables clean separation of concerns.

The controller exhibits a deliberate migration pattern from RHOAI 2.x (OpenShift Routes + oauth-proxy) to 3.x (Gateway API HTTPRoutes + Kuadrant AuthPolicy). The InferenceService controller still creates OpenShift Routes for backward compatibility, while the newer LLMInferenceService controller exclusively uses Gateway API patterns. The Gateway bootstrap controller creates EnvoyFilter CRs for TLS configuration between the Envoy data plane and Authorino, demonstrating tight integration with the Istio service mesh control plane. The separation of gateway-level auth (EnvoyFilter + AuthPolicy on Gateway) from service-level auth (AuthPolicy on HTTPRoute) is a clean architectural boundary.

The admission webhook system handles three cross-cutting concerns transparently: ConnectionsAPI credential injection (S3/URI/OCI), HardwareProfile resource scheduling (CPU/memory/accelerator + node affinity + Kueue labels), and Ray TLS certificate injection for multi-node serving runtimes. These mutations happen at admission time rather than in reconcile loops, ensuring that pods are created with correct configuration from the start. The webhook detects connection changes between old and new objects during UPDATE operations and performs surgical cleanup/replacement, avoiding stale credential leaks.

The model-serving-api server is architecturally notable for its information-hiding approach to RBAC: when a user lacks permission to create LLMInferenceServices in a namespace, the gateway discovery endpoint returns an empty list rather than a 403 error, preventing information leakage about gateway infrastructure. The server also implements a per-request bearer token passthrough pattern, creating ephemeral Kubernetes clients that inherit the caller's identity, ensuring that all authorization decisions are made at the Kubernetes API level rather than in the application.

The NIM Account controller demonstrates an external API integration pattern with defensive design: 24-hour refresh intervals for both validation and config, air-gapped mode support via DSC detection, singleton-per-namespace enforcement via validating webhook, and graceful resource cleanup on API key invalidation. The controller creates OpenShift Templates (not just raw resources), enabling users to instantiate NIM ServingRuntimes through the OpenShift template mechanism.
