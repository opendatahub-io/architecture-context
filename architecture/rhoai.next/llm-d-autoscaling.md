## Purpose

**Short**: Provides KEDA autoscaling blueprints and an evaluation test bed for llm-d inference deployments, plus a deprecated GPU-aware Kubernetes controller (WVA) staged for removal.

**Detailed**: llm-d-autoscaling serves a dual role. Its **active, current function** is to supply recommended KEDA-based autoscaling strategies — ScaledObject configurations, Prometheus metric triggers (queue depth, KV-cache utilization), and scaling behaviors for prefill/decode disaggregated topologies — along with a benchmark test bed that exercises these strategies against real or simulated GPU backends. The repository provides scenario blueprints under `benchmark/config/scenarios/` (guides for production, staging for experiments) and drives load via the llm-d-benchmark harness to compare strategies on evidence.

Its **legacy function** is the Workload-Variant-Autoscaler (WVA), a custom Go controller-runtime based Kubernetes controller that implemented GPU-aware saturation scaling, Kalman-filter-based prediction, scale-from-zero, and multi-model GPU rebalancing. The WVA code is frozen in the `legacy/` directory, staged for removal. The last supported release is v0.9.0 on the `release-0.9` branch; all new autoscaling work targets KEDA-native approaches.

## Architectural Analysis

The repository represents a transition in llm-d's autoscaling architecture from a bespoke controller to a KEDA-native approach. The WVA controller in `legacy/` is a sophisticated piece of infrastructure — it runs a saturation engine that queries Prometheus for vLLM metrics (KV-cache utilization, queue length, throughput), applies a configurable analyzer pipeline (V1 percentage-based or V2 token/capacity-based), and patches Deployment or LeaderWorkerSet replicas via a DirectActuator. It conditionally discovers KEDA ScaledObjects and HPAs via annotation-based indexing, and supports an experimental Coordinator loop with a GPU rebalance plugin that redistributes replica budgets across models under GPU contention using ResourceQuota-based caps.

The decision to deprecate WVA in favor of KEDA reflects a "use the platform" philosophy: KEDA reads the same Prometheus metrics and drives HPA-managed scaling without a custom controller in the path. The repository retains the evaluation test bed to validate that KEDA-native strategies match or exceed WVA's scaling quality. The benchmark harness deploys scenarios (e.g., prefill/decode disaggregation), drives inference load, and captures replicas, trigger values, latency, and throughput for comparison.

A notable architectural detail is the WVA's conditional CRD support: it probes for KEDA ScaledObject and LeaderWorkerSet CRDs at startup and auto-restarts (via a CRD watcher) when they appear later. It also supports both cluster-scoped and namespace-scoped deployment modes, with label-selective ConfigMap caching to reduce memory footprint in cluster-scoped mode. The Prometheus client supports full mTLS with configurable CA certificates, and the OpenShift overlay integrates with service-ca for automated certificate rotation and Thanos Querier as the metrics source.
