# ADR-0012: Linting and CI Infrastructure

## Status

Accepted

## Date

2026-05-06

## Context

External contributors began submitting overlays via PRs (CodeFlare, KServe, Model Runtimes, AIPCC teams). Without automated quality gates, malformed overlays, lint violations, and accidental modifications to generated architecture files could merge unchecked. The codebase also had accumulated lint issues in both Python and Go code.

## Decision

Add comprehensive linting and CI infrastructure:

**Linters:**
- `ruff` for Python (rules E, F, W, I; target Python 3.13)
- `golangci-lint` for Go (errcheck, govet, staticcheck, unused)
- `lint_overlays.py` for overlay YAML frontmatter validation
- `lint_platforms.py` for platforms.yaml schema validation
- `lint_architecture_docs.py` for generated doc template compliance
- Unicode safety check to detect skills/context poisoning in PRs

**CI (GitHub Actions):**
- Lint and build on PRs and main branch pushes
- Block PRs that modify autogenerated `architecture/` directory (must be regenerated via pipeline)
- Schema validation for platforms.yaml

**Make targets:** `make lint` (all), `make lint-python`, `make lint-go`

## Consequences

Positive:
- External overlay contributions are validated automatically
- Generated architecture files are protected from accidental manual edits
- Consistent code quality across Python and Go codebases
- Unicode safety check prevents prompt injection via skill/context files

Negative:
- CI adds friction to the contribution workflow (contributors must pass lint checks)
- Multiple linting scripts to maintain alongside the main codebase
