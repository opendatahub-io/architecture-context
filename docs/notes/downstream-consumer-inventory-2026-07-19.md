# Downstream Consumer Inventory

**Date**: 2026-07-19
**Source**: Manual survey of `tmp/skill-repos/` checkouts

Four downstream repos consume architecture-context data generated by this project.
This document records how each fetches, consumes, and falls back when the data is
unavailable, based on a code-level survey of their current main branches.

## Fetch Mechanism

All three active consumers use a divergent copy of
`scripts/fetch-architecture-context.sh`. Each performs a sparse git checkout of
`https://github.com/opendatahub-io/architecture-context`, discovers the latest
`rhoai-*` version directory via the GitHub contents API, and clones that version
into `.context/architecture-context/`. The `.context/` directory is gitignored in
every repo.

### Script Feature Matrix

| Feature | epic-code-gen | rfe-creator | strat-creator | epic-creator |
|---------|:---:|:---:|:---:|:---:|
| Script exists | No | Yes | Yes | Yes |
| Sparse checkout includes `overlays/` | — | Yes | Yes | No |
| Local-path override argument | — | No | Yes | No |
| Writes `LATEST_VERSION` marker | — | Yes | No | No |
| Handles existing symlink | — | No | Yes | No |
| Skip env var | — | `RFE_SKIP_BOOTSTRAP` | `RFE_SKIP_BOOTSTRAP` | `EPIC_SKIP_BOOTSTRAP` |

The scripts have drifted independently. Fixes or improvements in one copy do not
propagate to the others.

## Consumer Profiles

### rfe-creator

**Role**: RFE feasibility review, architecture review, and strategy refinement.

**Skills that consume architecture-context**:
- `rfe-feasibility-review` — primary consumer
- `architecture-review`
- `feasibility-review`

**Access pattern**:
1. Read `.context/architecture-context/LATEST_VERSION` to get the version string.
2. Read `.context/architecture-context/architecture/<version>/PLATFORM.md` to
   identify which components an RFE touches.
3. Read relevant per-component `{component}.md` files for structured detail.
4. Glob `overlays/*.md` excluding `README.md`, parse YAML frontmatter for
   `status: active`, `release`, and `affects` fields.
5. Read `## Fact` and `## Impact on Strategies` sections from matched overlays.
6. Overlays take precedence over generated docs when they conflict.

**Fallback**: If `LATEST_VERSION` or `PLATFORM.md` reads fail, skills assess
feasibility from RFE content alone and note that architecture context was
unavailable. The `architecture-review` skill skips entirely with a message.

**Fetch trigger**: `rfe.review` skill Step 1.5, run in parallel with
`bootstrap-assess-rfe`. The `rfe-creator.update-deps` skill forces a fresh fetch
by deleting the existing directory.

### strat-creator

**Role**: Strategy review, refinement, feasibility assessment, and architecture
review.

**Skills that consume architecture-context**:
- `strategy-refine` — heaviest consumer
- `strategy-architecture-review`
- `strategy-feasibility-review`
- `strategy-review` (orchestrator, passes context to scorer agent)

**Access pattern**:
1. Glob for `rhoai-*` directories under
   `.context/architecture-context/architecture/` (no `LATEST_VERSION` marker).
2. Read `PLATFORM.md` and per-component docs.
3. Read `overlays/*.md` with the same frontmatter filtering as rfe-creator.
4. The `strategy-refine` skill defines a 4-level priority chain for context
   sources: Staff Engineer Input > Overlays > Removed RFE Context >
   Architecture Context.

**Fallback**: Skills note unavailability and proceed with RFE content alone. The
`strategy-architecture-review` skill skips with a message.

**Inconsistency**: `strategy-feasibility-review` does not read overlays, while
`strategy-refine` does. A strategy could be refined with overlay corrections but
reviewed without them.

**Fetch trigger**: `strategy-review` skill Step 2, with optional
`--architecture-context <path>` argument for local overrides.

### epic-creator

**Role**: Epic decomposition into implementation work items.

**Skills that consume architecture-context**:
- `epic-decompose` and its decompose agent

**Access pattern**:
1. Check whether a component architecture file exists at
   `.context/architecture-context/architecture/<version>/{component}.md`.
2. File existence = "component is in the platform."
3. Missing file triggers creation of provisioning epics or investigation epics.

**Does not read**: PLATFORM.md, overlays, or any structured content from
component files. Only performs file-existence checks.

**Note**: The sparse checkout does not include `overlays/`, so this consumer
cannot benefit from overlay corrections even if it were extended to read them.

**Fetch trigger**: `epic-decompose` skill Step 3 ("Bootstrap"), retried once on
failure; pipeline stops if retry also fails.

### epic-code-gen

**Role**: Code generation from epics with architecture review.

**Current state**: The CLAUDE.md documents `bash scripts/fetch-architecture-context.sh`
but the script does not exist in the repo. The `.context/` directory is gitignored
and cleaned by the Makefile, suggesting infrastructure is in place but the actual
fetch mechanism was never implemented.

**Skills do not reference architecture-context**: The `epic-codegen` SKILL.md and
`architecture-reviewer` agent review target-repo conventions, not platform
architecture data.

## What Consumers Do Not Use

None of the four repos reference or use:

- **arch-query CLI** — the purpose-built query tool designed for these consumers
- **component-map.json** — the structured component inventory
- **GENERATED_ARCHITECTURE.md** — the in-repo generated files (they read the
  collected/organized files under `architecture/`)
- **Diagrams** — no `.mmd`, `.png`, `.dsl`, or `.txt` diagram files are read
- **arch-analyzer** output directly — they consume only the final Markdown

## Observations

1. **Script drift is the primary maintenance risk.** Three independent copies of
   the fetch script with different feature sets. When the upstream repo URL,
   directory layout, or API changes, each copy must be updated separately.

2. **Overlay adoption is incomplete.** epic-creator's sparse checkout excludes
   `overlays/`, and strat-creator's `strategy-feasibility-review` skill does not
   read overlays even though they are fetched. Overlay corrections may not reach
   all decision points.

3. **Version discovery is inconsistent.** rfe-creator writes a `LATEST_VERSION`
   marker file and reads it deterministically. strat-creator and epic-creator
   glob for `rhoai-*` directories, which is slower and requires the skill to
   sort/select the latest version itself.

4. **Full-document reads are expensive.** Both rfe-creator and strat-creator read
   entire 300+ line component Markdown files to extract small sets of facts. This
   is the exact pattern arch-query was designed to replace.

5. **Graceful degradation varies.** Some skills skip silently, some note
   unavailability explicitly, and some stop the pipeline. There is no consistent
   contract for what happens when architecture data is missing.

6. **No consumer validates data freshness.** No skill checks the `Generated On`
   date in component docs or compares it against the current RHOAI version. Stale
   data is consumed without warning.
